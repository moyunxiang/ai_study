语言模型的规模定律

Scaling Laws for Neural Language Models
2020.01论文主干Kaplan, McCandlish, Henighan, Brown, Chess, Child, Gray, Radford, Wu, Amodei · OpenAI / Johns Hopkins来源已核对
arXiv ↗ar5iv全文 ↗在交互版中打开（演化树、学习进度）

问题

GPT-2之后大家都觉得“模型越大越好”，但大到多少、该花多少钱在参数上、多少在数据上，没人能事先算出来，训练一个大模型只能靠试。

方法

训练几百个从768到15亿参数不等的Transformer语言模型，发现测试损失与参数量、数据量、算力各自呈幂律关系，并且几个规律能拼成一个公式，从而推算给定算力下最优的模型大小。

影响

把“砸多少算力能换多少效果”变成可以用小实验提前估算的问题；四个月后的GPT-3论文用8个尺寸检验了它的幂律、并参考它选批大小和学习率，用小模型拟合曲线、外推大模型此后成为常见做法。

背景

到2019年，GPT-2已显示语言模型做大会更好，《AI and Compute》：算力每3.4个月翻倍统计出顶尖AI训练用的算力每3.4个月翻一番。更早的深度学习规模可预测（百度，2017）已在翻译、语言模型、图像、语音上观察到误差随数据量按幂律下降，探索语言模型的极限也显示更大的LSTM语言模型能把困惑度明显降下来。

但这些观察零散：各自固定了别的因素，没有回答一个实际问题——手里有固定的算力预算，应该训练多大的模型、读多少数据、训练多久？模型形状（层数还是宽度）重不重要？多大才会过拟合？答不出这些，就只能凭经验押注，而训练一个大模型的代价很高。

方法

作者在WebText2（GPT-2所用WebText的扩充版，约96GB文本）上训练了大量从左到右的Transformer语言模型，统一用BPE子词切分切词，测量测试集上的交叉熵损失L（单位nats，见交叉熵）。变动的因素有：非嵌入参数量N（768到15亿）、数据量D（2200万到230亿token）、模型形状、上下文长度、批大小、训练步数。

三条幂律（见幂律与规模定律）。只受其中一个因素限制时：

L(N) = (N_c / N)^α_N，α_N ≈ 0.076

L(D) = (D_c / D)^α_D，α_D ≈ 0.095

L(C_min) = (C_c / C_min)^α_C，α_C ≈ 0.050

指数很小，意思是收益来得慢但很稳定：参数翻倍，损失乘以2^−0.076 ≈ 0.95，即下降约5%。在双对数坐标下这些都是直线，某些趋势跨越七个数量级以上。作为直观例子，把N=15亿代入第一条公式（N_c ≈ 8.8×10^13）得约2.30 nats，N=1.5亿得约2.74 nats。

计算量的估算。训练算力近似为C ≈ 6·N·B·S（B为批大小，S为步数，见参数量、计算量与显存）：每个token前向约2N次浮点运算，反向约4N次。

参数与数据的联合公式：

L(N, D) = [(N_c/N)^(α_N/α_D) + D_c/D]^α_D

它描述了过拟合：只加大N而不加D，收益会递减。避免过拟合大致需要D与N^0.74同比例增长——模型扩大8倍，数据只需扩大约5倍。

最优分配。综合以上，在固定算力下最省的做法是：N ∝ C^0.73，而数据只需D ∝ C^0.27。算力每涨10倍，模型应涨约5倍，读的数据只涨约2倍；而且应该训练一个很大的模型，并在远未收敛时就停下。

结果

几个经验结论：

  • 形状几乎不重要。在相当大的范围内，固定总参数量，改层数、宽度、头数，损失变化很小；决定性能的主要是规模。
  • 大模型更省数据。达到同一损失，大模型需要的训练步数和样本数都更少。
  • 迁移可预测。在其他分布的文本上测试，损失与WebText2上的损失只差一个大致恒定的偏移。
  • LSTM对比。相同参数量下，LSTM对上下文开头的token与Transformer一样好，但对靠后的token明显不如，说明Transformer更能利用长上下文。
  • 最优批大小也近似是损失的幂函数。

论文还指出公式本身存在矛盾：按最优分配推下去，在约10^4 PF-天、10^12参数附近，L(C_min)和L(D)两条趋势会相交，届时预测必然失效——自然语言的熵不为零，损失不可能无限下降。

后来的发展

四个月后的GPT-3把参数推到1750亿。GPT-3论文写明，训练8个尺寸可以用来检验本文的幂律假设，批大小和学习率的选择也参考了本文；结果显示损失与训练算力的幂律关系再延伸两个数量级后只有轻微（如果有的话）偏离。此后，用小模型拟合曲线、外推大模型的表现成为常见做法。

两年后Chinchilla修正了最关键的结论：它用了更多不同训练长度的模型，得出参数和数据应同比例增长，当时的大模型普遍“训练不足”。Chinchilla论文给出的原因有两条：本文所有模型共用固定的训练token数和学习率调度，中途读出的损失偏高，低估了用较少数据训练的效果，进而得出“模型应比数据增长更快”；另外本文的模型多数较小（很多不到1亿参数）。再往后，计入推理成本的规模定律把推理成本计入，数据受限的规模定律研究数据用完需要重复时怎么办，测试时计算扩展和OpenAI o1推理模型则把规模定律的思路从训练算力扩展到推理时的算力。

容易误解的地方

  • 规模定律预测的是预训练损失，不是某项具体能力。损失平滑下降，不代表每个下游任务的分数也平滑上升（见涌现能力的争论）。
  • N ∝ C^0.73这个分配比例后来被Chinchilla修正为参数与数据大致同比例增长，规划训练时不宜再直接套用；用幂律从小模型外推的思路仍被广泛使用。
  • N_c、D_c等常数依赖词表和切词方式，没有物理意义；能跨设置比较的是指数。
  • N特指非嵌入参数。把嵌入层算进去，小模型上的规律会变得不干净。

局限与后续

  • 算出的最优分配让模型增长远快于数据（N∝C^0.73、D∝C^0.27），后来Chinchilla的实验显示这低估了数据的作用，按它训练出的模型普遍训练不足。
    后来针对它的工作　Chinchilla
  • 只预测平均交叉熵损失，无法预测某项具体能力（算术、推理）在多大规模出现或达到什么水平。
    后来针对它的工作　涌现是幻象吗
  • 只考虑训练算力，没有计入模型部署后的推理成本；对要服务海量请求的模型，更小、多训的模型反而更划算。
    后来针对它的工作　计入推理成本的规模定律 LLaMA
  • 假设有取之不尽的不重复数据，没有回答数据用完、必须重复训练时规律会怎样变化。
    后来针对它的工作　数据受限的规模定律
  • 只研究训练时花多少算力，没有考虑推理时让模型多想一会儿能换来多少性能。

读懂它需要的概念

语言模型 交叉熵 幂律与规模定律 参数量、计算量与显存 泛化与过拟合 批大小、步数与轮数 学习率与学习率调度

本篇术语

  • 幂律　形如y = a·x^(−k)的关系。在双对数坐标下是一条直线，斜率为−k，所以可以用小规模的点画线、外推到大规模。
  • 非嵌入参数　除去词嵌入矩阵和位置嵌入之外的参数，也就是各层注意力和前馈网络的参数。
  • PF-天　算力单位：每秒10^15次浮点运算持续一天，约8.64×10^19次运算。
  • 计算最优　在算力预算固定的前提下，选择使最终损失最低的模型大小和数据量组合。

怎么学

先懂交叉熵、参数量、计算量与显存和对数坐标图。读原文第1.1–1.2节（结论汇总和公式1.1–1.8）、图1和第6节（最优分配与那个矛盾）。然后紧接着读Chinchilla，看最优分配是怎么被修正的。动手：用nanoGPT在同一份数据上训练5个宽度不同的小模型，在双对数坐标上画出损失-参数曲线，拟合出你自己的α_N。
