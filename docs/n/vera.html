VeRA共享随机矩阵适配

VeRA: Vector-based Random Matrix Adaptation
2023.10论文延伸ICLR 2024Dawid J. Kopiczko, Tijmen Blankevoort, Yuki M. Asano · 阿姆斯特丹大学, 高通AI研究院待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

LoRA已把可训练参数降到千分之一级别，但要给成千上万个用户或任务各存一份适配器时，存储和加载开销仍然可观，模型越大越明显。

方法

所有层共用一对随机初始化后冻结的低秩矩阵A和B，每层只学习两个很小的缩放向量，分别缩放B的输出维度和A的秩维度。

影响

把参数高效微调的可训练参数再压低一个数量级以上，同时性能与LoRA相当，被Hugging Face PEFT库收录，是“更省参数的LoRA变体”这一支的代表。

方法

LoRA给每个权重W加上一个低秩更新 ΔW = BA，每层都有自己的A、B要训练和存储。有研究发现，随机初始化并冻结的投影本身已经有相当的表达能力，真正需要学习的可能只是怎样缩放它们。

VeRA据此把更新写成 ΔW = Λ_b B Λ_d A：A（r×n）和B（m×r）用随机数初始化后冻结，并且所有层共享同一对（只需存一个随机种子就能重新生成）；每层只训练两个向量——长度为r的d（构成对角矩阵Λ_d，缩放秩维度）和长度为m的b（构成Λ_b，缩放输出维度）。由于A、B不用训练也不用逐层存储，VeRA可以把秩r取得比LoRA大得多，而可训练参数仍然极少。初始化时b取0，使训练开始时 ΔW = 0，与LoRA的做法一致。

摘要报告：可训练参数相比LoRA显著减少而性能相当，在GLUE、E2E、图像分类任务上验证，并用于7B和13B语言模型的指令微调。

局限与后续

  • 表达能力受限于共享的随机子空间，在需要大幅改变模型行为的任务上可能不如LoRA；更大的秩也增加了前向计算量。
    本站还没有记录针对它的后续工作（不代表没有人解决）
