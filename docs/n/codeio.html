CodeI/O代码输入输出推理

CodeI/O: Condensing Reasoning Patterns via Code Input-Output Prediction
2025.02论文延伸ICML 2025Junlong Li, Daya Guo, Dejian Yang, Runxin Xu, Yu Wu, Junxian He · 香港科技大学 / DeepSeek待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

提升推理的训练数据大多集中在数学和代码生成，逻辑、科学、常识等其他推理任务的数据稀疏又零散，很难系统地练。

方法

把大量真实代码改写成“给定代码和输入，用自然语言一步步推出输出”（或反过来由输出推输入）的预测题，让模型从代码里学到通用的推理套路，而不必学写代码本身。

影响

说明代码里蕴含的规划、搜索、分解等推理模式可以被“浓缩”成通用推理训练数据，在符号、科学、逻辑、数学、常识推理上都带来一致提升，是推理数据构造方面的代表工作。

方法

代码本身就是推理过程的精确记录：一个函数里有条件判断、循环、状态更新、递归分解。CodeI/O的做法是：

  • 从各种来源收集有实际语境的代码（而不只是竞赛题），整理成带测试输入的可执行函数；
  • 把它们转成两类预测题：给定代码和输入，预测输出；给定代码和输出，预测一个能产生该输出的输入；
  • 要求模型用自然语言思维链写出推理过程，再给出答案。这样学到的是逻辑流程规划、状态空间搜索、决策树遍历、模块化分解这类通用推理原语，而与具体编程语言的语法解耦，同时保持过程的严谨。

每个预测都可以验证：预测输出可以直接和真实输出比对，预测输入可以重新执行代码检查。利用这一点，作者对答错的样本让模型根据执行反馈多轮修订思维链，得到质量更高的CodeI/O++数据。

实验显示，用CodeI/O数据训练后，模型在符号、科学、逻辑、数学与数值、常识等多类推理任务上都一致提升，CodeI/O++进一步提高。这与PAL/PoT程序辅助推理“让代码替模型算”的方向相反：这里是让模型学会像代码那样想。

局限与后续

  • 推理过程由更强的模型生成，再经执行结果筛选，数据质量与覆盖面依赖教师模型与代码来源。

它建立在什么之上

  • 使用
    思维链CoT2022.01 · 推理·智能体
    训练目标是用自然语言思维链推出代码的输出或输入。
  • 竞争
    PAL/PoT程序辅助推理2022.11 · 推理·智能体
    PAL让模型写代码交给解释器执行，CodeI/O反过来让模型在脑中“执行”代码来学推理。
  • 延续
    CRUXEval代码执行推理2024.01 · 数据·评测
    CRUXEval用代码输入输出预测来评测推理，CodeI/O把同一任务形式大规模用作训练数据。
  • 使用
    DeepSeek-Coder2024.01 · LLM
    实验中使用的底座模型之一来自DeepSeek-Coder等开源代码模型系列。
