Codex

Evaluating Large Language Models Trained on Code
2021.07论文重要Mark Chen, Jerry Tworek, Heewoo Jun, Qiming Yuan, Henrique Ponde de Oliveira Pinto, Jared Kaplan, Harri Edwards, Yuri Burda et al. · OpenAI待核对
arXiv ↗HumanEval代码与评测框架 ↗在交互版中打开（演化树、学习进度）

问题

GPT-3能写一点代码，但在“按文档字符串写出能跑通单元测试的函数”这件事上几乎是0分；而且当时评价代码生成用BLEU，和代码对不对关系不大。

方法

把GPT模型在159GB的GitHub Python代码上继续训练，得到Codex；同时手写164道带单元测试的题目HumanEval，用“采样k次至少一次通过测试”的pass@k衡量功能正确性。

影响

120亿参数的Codex单次采样解出28.8%的题，GPT-3是0%；它的生产版本驱动了GitHub Copilot，HumanEval和pass@k成为此后代码模型的标准评测。

背景

GPT-3证明了大模型靠提示就能做很多任务，人们也注意到它偶尔能从注释写出简单的Python。但这种能力很弱，也没有好的衡量办法：代码生成论文大多沿用翻译的BLEU（数和参考答案有多少词重合），而两段代码字面上很像，一段能跑一段报错，BLEU分不出来。另一方面，GitHub上有海量公开代码，正好是语言模型最擅长吃的那种无标注序列。问题是：专门在代码上训练的GPT，能不能真的写出正确的程序？

方法

数据。2020年5月从5400万个公开GitHub仓库收集了179GB、单文件小于1MB的Python文件，过滤掉自动生成、行太长、字母数字占比太低的文件，剩下159GB。

训练。从GPT-3系列的权重出发继续做下一个词预测（最大120亿参数）。作者发现从预训练权重出发并没有让最终效果更好（可能因为代码数据本身够大），但收敛更快。分词沿用GPT-3的BPE子词切分，额外加了一组表示不同长度连续空格的token，因为缩进是代码里最浪费token的部分，这样同一段代码少用约30%的token。

评测：HumanEval与pass@k。手写164道题，每题给出函数签名和文档字符串，平均配7.7个单元测试。模型续写函数体，跑通全部测试才算对。对每题采样n=200次，数出通过的c次，用无偏估计 pass@k = E[1 − C(n−c, k) / C(n, k)] 估计“随机挑k个样本至少一个正确”的概率。直接用 1 − (1 − p̂)^k 会系统性低估。

Codex-S。再从编程竞赛网站和带持续集成的仓库里收集“独立且正确实现”的函数，做一次有监督微调，格式更贴近HumanEval。

结果

单次采样（温度0.8下的pass@1）：Codex-12B解出28.8%，3亿参数的Codex 13.2%，60亿参数的GPT-J-6B 11.4%，GPT系列都接近0%；Codex-S达到37.7%。每题采样100次时，只要其中有一个能过测试就算对，Codex-S覆盖77.5%的题；如果不能跑测试、只按平均对数概率挑一个，也有44.5%。作者还造了由“转小写”“删掉每第三个字符”等积木串起来的合成题，每多串一步，通过率下降到原来的约1/2到1/3。

后来的发展

Codex的生产版本是GitHub Copilot的底座，也作为API开放。它确立了两件事：代码是大模型最有商业价值的能力之一；“多采样再用测试筛选”是提升代码正确率的有效手段，AlphaCode把它推到竞赛级。开源方向随后出现CodeGen、InCoder代码补全、StarCoder、Code Llama。HumanEval一直用到今天，但因为题少、测试弱、容易被训练数据污染，后来有了HumanEval+ / EvalPlus、LiveCodeBench，以及面向真实仓库的SWE-bench。

读懂它需要的概念

语言模型 自回归生成 预训练与微调 解码：贪心、束搜索、温度与top-p 分词与token 基准、排行榜与SOTA

本篇术语

  • pass@k　对一道题生成k个程序，只要有一个通过全部单元测试就算解出；对所有题取平均。k越大，越接近“允许多试几次”的场景。
  • 单元测试　一小段自动检查代码的程序，例如断言 add(2,3)==5。用它判对错比对照参考答案的字面相似度可靠得多。
  • 功能正确性　只看程序在输入上的行为是否符合要求，不在乎写法是否和参考答案一样。

怎么学

先懂自回归生成和解码：贪心、束搜索、温度与top-p里的温度采样。读原文第2节（HumanEval与pass@k估计，附录A的推导）和第3节（数据与训练）。动手：克隆human-eval仓库，用任意开源代码模型对20道题各采样10次，自己实现pass@k的无偏估计，并与 1−(1−p̂)^k 的结果对比。
