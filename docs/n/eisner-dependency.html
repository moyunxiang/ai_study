Eisner依存分析算法

Three New Probabilistic Models for Dependency Parsing: An Exploration
1996.08论文重要COLING 1996Jason M. Eisner · 宾夕法尼亚大学待核对
ACL Anthology ↗arXiv ↗在交互版中打开（演化树、学习进度）

问题

带词汇信息的句法分析若沿用CKY，每个短语还要记住它的中心词，复杂度从O(n³)涨到O(n⁵)，依存分析也缺一个精确又快的动态规划解码算法。

方法

改记「中心词在两端」的片段：把一棵依存树拆成左右两半各自生长，完整片段与未完整片段交替拼接，在O(n³)时间内精确找出得分最高的投射依存树；再给出三种给弧打分的概率模型。

影响

这个O(n³)算法成了图式（graph-based）依存分析的标准解码器，MSTParser、双仿射分析器等的投射版本都用它；论文提出的生成式模型C也是后来词汇化依存模型的起点。

背景

依存句法把一句话表示成一棵树：每个词恰好有一个中心词（head），例如「吃」是「我」和「苹果」的中心词。到90年代中期，统计句法分析发现「词汇化」很重要——同一个介词短语该挂在动词上还是名词上，要看具体是哪几个词。但用CKY句法分析算法做词汇化的概率上下文无关文法PCFG时，每个片段除了起止位置i、j，还要记一个中心词位置h，组合两个片段时又要枚举分割点和另一个中心词，复杂度变成O(n⁵)，40个词的句子就慢得难以接受。

方法

Eisner的关键观察是：在投射（弧互不交叉）的依存树里，一个词的左侧依存和右侧依存是互相独立生长的，因此不必让中心词处于片段中间，只需记录「中心词在左端」或「在右端」的片段。定义两类表项：

  • 完整片段 C[i][j]：中心词在一端（比如i），从i到j的词都已经找齐了自己的依存；
  • 未完整片段 I[i][j]：刚刚连上弧 i→j，但j朝向i那一侧的依存还没收完。

递推只有两条（以向右为例，s(i,j)是弧 i→j 的得分）：I[i][j] = max_{i≤k<j} ( C→[i][k] + C←[k+1][j] ) + s(i,j)；C→[i][j] = max_{i<k≤j} ( I→[i][k] + C→[k][j] )。表项共O(n²)个，每个只枚举一个分割点k，总复杂度O(n³)，而且得到的是精确最优解。只要总分能拆成各条弧的分数之和（后来称为「一阶」或「弧分解」模型），这个算法都适用。

在这个解码框架上，论文比较了三种给依存树定概率的方式：模型A让每对词互相「争夺」修饰关系（词汇亲和），模型B把每个词看成随机挑选修饰对象的标注问题，模型C是生成式模型——从中心词出发，依次生成左右两侧的依存词。论文在《华尔街日报》树库转换出的依存数据上做了初步实验，模型C表现最好。

后来的发展

十年后MSTParser与MIRA把弧打分换成判别式训练，投射情形仍用Eisner算法解码，非投射情形改用最大生成树；双仿射依存分析等神经图式分析器同样只换了打分函数。后来的高阶图式模型都在它的表项上扩展：McDonald与Pereira（2006）加入相邻兄弟弧的二阶模型仍是O(n³)，Koo与Collins（2010）的三阶模型升到O(n⁴)。它和转移式依存分析代表了依存分析的两大路线：图式全局精确解码与转移式线性时间贪心分析。

局限与后续

  • 只能输出投射树（弧不交叉），而德语、捷克语等语言里非投射结构并不少见。
    后来针对它的工作　MSTParser与MIRA
  • 要求总分是各条弧得分之和，无法利用兄弟弧、祖孙弧等更大范围的结构特征；加入这些特征复杂度就要上升。

本篇术语

  • 依存句法　用词与词之间带方向的「中心词→依存词」关系表示句子结构，整句构成一棵以核心动词为根的树。
  • 投射性　把依存弧画在句子上方时，所有弧互不交叉。英语绝大多数句子满足，有些语言不满足。
  • 弧分解　整棵树的得分等于每条依存弧单独得分之和，这是Eisner算法能精确求解的前提。

怎么学

先弄懂CKY句法分析算法的片段递推 → 读原文第2节的算法图示，在纸上对一个5个词的句子手推完整片段和未完整片段 → 动手：实现Eisner算法，用随机弧分数测试它与暴力枚举所有投射树的结果一致。
