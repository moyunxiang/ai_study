CodeAct代码即行动

Executable Code Actions Elicit Better LLM Agents
2024.02论文延伸ICML 2024Xingyao Wang, Yangyi Chen, Lifan Yuan, Yizhe Zhang, Yunzhu Li, Hao Peng, Heng Ji · UIUC / Apple待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

智能体的行动通常是JSON或固定格式的文本，只能调用预先定义好的工具，很难把几个工具组合起来或写循环、条件判断。

方法

把行动统一成可执行的Python代码，用解释器执行，并根据执行结果多轮修改。

影响

“代码即行动”成为智能体的常见设计，后来的OpenHands等采用，也影响了函数调用之外的工具使用方式。

方法

CodeAct让模型在每一步直接写一段Python：可以调用任何已有的库，用变量保存中间结果，用循环和条件把多个操作串联成一步；解释器运行后，输出和报错作为观察返回，模型据此改代码或继续下一步（类似ReAct的循环，但行动是代码，和PAL/PoT程序辅助推理用代码做计算也相通）。论文在API-Bank和自建基准上比较了17个LLM，称CodeAct比JSON或文本动作格式成功率最高高出20%。

团队还收集了7千条多轮CodeAct交互的指令数据集CodeActInstruct，用来微调Llama2和Mistral，得到CodeActAgent：能用现有库完成复杂任务（如模型训练）并自主调试，同时不损害通用能力。

局限与后续

  • 让模型执行任意代码有安全风险，需要沙箱，并要防止破坏性操作。
    后来针对它的工作　OpenHands/OpenDevin
  • 小模型生成的代码质量不稳定，调试多轮会增加延迟和成本。
    本站还没有记录针对它的后续工作（不代表没有人解决）
