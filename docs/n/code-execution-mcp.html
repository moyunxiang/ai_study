用代码调用工具

Code execution with MCP: Building more efficient agents
2025.11思想延伸Anthropic待核对
Anthropic ↗在交互版中打开（演化树、学习进度）

问题

MCP客户端通常把所有工具定义一次性塞进上下文，工具上百上千时光读定义就要数十万token，中间结果又要在模型里转手。

方法

不让模型直接逐个调用工具，而是把MCP服务器呈现为代码接口，让智能体写代码按需调用，数据在执行环境里处理，只把结果带回上下文。

影响

官方称这样可把上下文开销最多降低98.7%，并推动了按需加载工具的设计。

方法

Anthropic在2025年11月4日发文。问题有两个：一是工具定义过载，大多数客户端把所有工具定义预先放进上下文，连接数千工具的智能体要在读请求之前先处理几十万token；二是中间结果也占token，比如把一份长文档从一个工具读出再写进另一个工具，内容要穿过模型两次。

解决办法是让智能体写代码：把MCP服务器当作代码里的API，智能体只在需要时去查看需要的那几个工具的定义，调用并在代码里对大数据做过滤、聚合，只把小结果打印出来。官方给出的案例称上下文开销最多减少98.7%（来自其摘要说明）。这和CodeAct代码即行动用代码代替固定工具调用格式的想法一脉相承。

局限与后续

  • 让模型执行任意代码需要沙箱、资源限制和审计，部署复杂度比直接调用工具高。
