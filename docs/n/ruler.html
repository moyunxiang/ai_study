RULER长上下文

RULER: What's the Real Context Size of Your Long-Context Language Models?
2024.04数据集延伸COLM 2024Hsieh, Sun, Kriman, Acharya, Rekesh, Jia, Zhang, Ginsburg · NVIDIA待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

大海捞针测试几乎被所有长上下文模型刷满，但它只检验检索一个事实，不能说明真实的上下文能力。

方法

合成基准，在检索基础上加入多针、多跳追踪和聚合等任务，长度和难度都可调。

影响

推动「声称的上下文长度」与「有效上下文长度」的区分，成为长上下文评测的常用基准。

方法

RULER包含13个代表性任务，扩展了普通NIAH：多种类型和数量的针，以及两类新任务——多跳追踪和聚合——考察超出「查找」的行为。作者评测了17个长上下文模型：虽然在原版NIAH上近乎满分，但随长度增加几乎都出现明显下降；这些模型都声称支持32K以上，但只有一半在32K长度上保持令人满意的表现。对声称支持200K的Yi-34B分析显示，随长度和任务复杂度增加仍有很大空间。

局限与后续

  • 任务是合成的，与真实长文档问答仍有差距。

它建立在什么之上

  • 改进
    ALiBi线性偏置位置2021.08 · LLM
    实验集中在语言模型困惑度和13亿参数以内的模型，外推能力在下游任务和更大模型上是否成立没有验证。
  • 改进
    位置插值扩上下文2023.06 · LLM
    窗口扩大了，但模型是否真正利用了中间位置的信息没有检验，只测了困惑度和口令检索这类简单任务。
  • 改进
    迷失在中间2023.07 · LLM
    任务以单条信息检索为主，没有测需要综合多处信息、多步推理的长上下文能力。
  • 改进
    YaRN2023.08 · LLM
    只用困惑度和口令检索验证，没有检验长文中的多跳推理和信息综合。
  • 使用
    Gemini 1.5与百万上下文2024.02 · LLM
    评测对象涵盖声称支持超长上下文的新一代模型，其宣传的长上下文能力是它质疑的对象。
  • 改进
    大海捞针测试2023.11 · 数据·评测
    在单针检索之上加入多针、多跳和聚合，揭示被它掩盖的退化。
  • 改进
    LongRoPE2024.02 · LLM
    2048K窗口是外推出来的，在这么长的输入上真正能用多少信息（而不只是困惑度不爆）需要另外检验。
  • 改进
    Jamba混合架构2024.03 · LLM
    Mamba层仍然压缩历史，在超长输入里精确检索细节的能力需要用专门的评测检验。
  • 改进
    零一万物Yi2024.03 · LLM
    200K窗口主要用大海捞针测试验证，更复杂的长文推理没有系统评估。
  • 改进
    Infini-attention2024.04 · LLM
    固定大小的压缩记忆是有损的，需要精确回忆的内容可能丢失；论文的验证以passkey和摘要为主。
