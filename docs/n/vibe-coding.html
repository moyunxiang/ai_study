Vibe Coding

2025.02思想延伸Andrej Karpathy 提出 · 概念待核对
维基百科 ↗在交互版中打开（演化树、学习进度）

问题

AI写代码越来越可靠后，一部分人开始不再逐行阅读，只是描述需求、运行、再提反馈，这种做法需要一个名字。

方法

Karpathy在2025年2月把它叫作vibe coding：完全跟着感觉走，忘记代码本身的存在。

影响

词汇迅速进入大众，成为AI时代软件开发风格和争议的代名词，并被Collins选为2025年度词汇。

方法

维基百科记载，这个词由Andrej Karpathy在2025年2月提出：开发者用自然语言向LLM描述项目，由模型自动生成代码，可能在没有仔细审查的情况下接受结果，靠运行效果和后续提示来引导修改。Karpathy的描述是「完全屈服于氛围，拥抱指数增长，忘掉代码的存在」（原文大意）。

支持者认为它让没有受过训练的人也能做出软件；批评者指出缺乏问责、难以维护，并增加安全漏洞风险。Merriam-Webster在2025年3月把它列为流行俚语，Collins词典将其选为2025年年度词汇。《纽约时报》记者Kevin Roose用它做了几个「给自己用的软件」，同时指出结果常常有限且容易出错。

后来的发展

这个词对应的工具是Cursor AI编辑器、Claude Code与终端编码智能体这类智能体；与之对应的反方是更谨慎的「AI辅助软件工程」。关于它是否真的提升效率的实证，可见METR开发者效率实验。
