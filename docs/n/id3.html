ID3/C4.5决策树

Induction of Decision Trees
1986.03论文重要Machine Learning 1(1), 1986J. Ross Quinlan · 悉尼大学待核对
Machine Learning期刊（DOI） ↗Wikipedia: ID3 algorithm ↗Wikipedia: C4.5 algorithm ↗在交互版中打开（演化树、学习进度）

问题

专家系统的规则要靠人一条条写，知识获取成了瓶颈；能不能直接从带标签的例子里归纳出一棵可读的决策树？

方法

每一步选那个能让类别“最不混乱”的属性来分叉，用信息论里的熵下降量（信息增益）作为挑选标准，自顶向下递归建树。

影响

ID3和它的后继C4.5成为机器学习教材里决策树的标准讲法，与统计学界的决策树CART并列为两条源头路线。

背景

1980年代前期，专家系统的商业化在医疗、地质等领域展示了用规则做决策的能力，但这些规则要由知识工程师采访专家后手写，耗时又难维护，被称为“知识获取瓶颈”。机器学习界因此关心一个问题：给定一批已经标好类别的例子（每个例子是若干属性的取值），能否自动归纳出一套分类规则？

同一时期，统计学家Breiman等人在1984年出版了决策树CART，从回归和统计检验的角度做树模型；Quinlan则从人工智能和信息论出发，独立走出了另一条路。1986年这篇发表在新创刊的Machine Learning第一卷上的论文，总结了他自1979年前后开始做的ID3系统。

方法

ID3处理的是离散属性的分类问题。设当前节点上的样本集合为S，类别分布为p₁…p_k，它的熵是 H(S) = −Σ p_i log₂ p_i：样本全属一类时为0，各类均匀混在一起时最大。用属性A把S按取值切成若干子集S_v后，信息增益定义为 Gain(S, A) = H(S) − Σ_v (|S_v|/|S|)·H(S_v)，即“知道A之后，类别的不确定性减少了多少”。

ID3在每个节点挑信息增益最大的属性来分叉，对每个子集递归重复，直到子集纯净或没有属性可用。例如判断“今天适不适合打网球”，若“天气”一个属性就能把大部分样本分开，它就会被放在根节点。论文还讨论了样本带噪声或属性缺失时的处理办法，并指出信息增益偏爱取值很多的属性（比如“日期”这种几乎每个样本一个值的属性），给出了两种修正思路的比较。

Quinlan在1993年的专著中把ID3发展为C4.5：用增益率（信息增益除以属性自身的熵）纠正对多值属性的偏好，支持连续属性（找阈值切分）和缺失值，并加入基于错误估计的剪枝，还能把树转成if-then规则集。

后来的发展

ID3/C4.5与决策树CART一起构成了决策树的两大源头：今天的教材通常用ID3讲信息增益、用C4.5讲增益率、用CART讲基尼系数和二叉切分。C4.5在2008年的一份“数据挖掘十大算法”评选里名列第一（来源为一般了解，未在本次核对）。

后来的集成方法大多以树为部件：Bagging与随机森林把许多棵深树平均起来降低方差，AdaBoost与集成学习和梯度提升机GBM把许多棵浅树串起来降低偏差，XGBoost、LightGBM把这条路做成了工程系统。现在实际使用的库（如scikit-learn）基本实现的是CART式二叉树，但信息增益（熵）作为切分准则仍是常用选项之一。

容易误解的地方

  • 信息增益和基尼系数在大多数数据上选出的切分很接近，二者之争在实践中没有想象的重要。
  • 单棵ID3树不剪枝时很容易过拟合，现在几乎没人直接用单棵树做最终模型，而是用它的集成版本。

局限与后续

  • 单棵树的方差很大：训练数据稍有变化，根节点的选择就可能改变，整棵树随之不同。
    后来针对它的工作　Bagging 随机森林
  • 原始ID3只处理离散属性、没有剪枝，在噪声数据上会长出过深的树。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 每次只按一个属性做轴对齐的切分，表达平滑或斜向的决策边界需要很多层。

读懂它需要的概念

决策树 信息量与熵 监督学习 准确率、精确率、召回率与F1

本篇术语

  • 信息增益　按某个属性切分前后，类别熵减少的量；减少得越多，这个属性越能区分类别。
  • 增益率　C4.5的改进准则：信息增益除以属性取值分布本身的熵，用来惩罚取值很多的属性。

怎么学

先弄懂熵的定义，再在纸上用十几条“打网球”样本手算一遍信息增益；然后读原文的ID3算法一节，最后用scikit-learn的决策树把criterion设成entropy跑一遍并画出树。
