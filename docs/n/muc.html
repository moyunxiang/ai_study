MUC信息抽取评测

1987事件延伸DARPA · 多家美国研究机构待核对
Wikipedia ↗在交互版中打开（演化树、学习进度）

问题

信息抽取（从新闻里抽出谁、何时、何地做了什么）各家系统做法不同，输出格式各异，无法比较。

方法

由DARPA出资，让多个团队在同一批文本上、按统一规定的填表格式竞争，并采用查准率和查全率打分。

影响

它把共同任务评测引入NLP，催生了命名实体识别、共指消解等任务的定义和评测标准。

方法

MUC（Message Understanding Conference）是DARPA出资发起的一系列评测会议，目的是推动信息抽取方法。它沿用DARPA共同任务框架的共同任务思路：许多团队同时参赛、互相竞争，因此必须先规定统一的评测标准，查准率和查全率（见Cranfield实验与查准查全率）就是这样被引入语言处理的。

具体任务是填表：只有第一届可以自选输出格式，从第二届起，评测方规定输出的表格，每个主题给定若干字段，系统要从文本里填出事件的原因、施事者、时间、地点、后果等，字段数逐届增多。到第六届（MUC-6），新增了命名实体识别（把文中所有人名、地名、机构名、时间和数量标出来）和共指消解两个任务。

今天常见的NER评测，如CoNLL（见CoNLL-2003命名实体），直接继承了这一任务定义。

局限与后续

  • 填表任务依赖人工设计的模板，换一个领域（比如从军事新闻换到公司并购）就要重写，难以泛化。
    后来针对它的工作　CoNLL-2003命名实体 OntoNotes
  • 系统主要靠手写规则和浅层模式，对语言变化的覆盖有限。
    后来针对它的工作　BERT

它建立在什么之上

  • 使用
    DARPA共同任务框架1987 · 数据·评测
    沿用DARPA共同任务框架：统一数据、统一指标、各队同台竞赛。

后来的相关工作

  • 改进
    BERT2018.10 · LLM
    系统主要靠手写规则和浅层模式，对语言变化的覆盖有限。
  • 竞争
    TREC文本检索评测1992.11 · 数据·评测
    同属DARPA TIPSTER体系下的文本评测：MUC评信息抽取，TREC评检索，前者偏结构化理解，后者偏排序，后来检索式问答把两条线汇合。
  • 使用
    Penn Treebank1993 · 数据·评测
    把MUC-3信息抽取评测的消息文本纳入标注，供抽取系统研究句法。
  • 延续
    CoNLL-2003命名实体2003.06 · 数据·评测
    延续MUC的命名实体任务，但改成多语言、统一的列格式，并面向机器学习方法而不是手写规则。
  • 改进
    OntoNotes2006.06 · 数据·评测
    填表任务依赖人工设计的模板，换一个领域（比如从军事新闻换到公司并购）就要重写，难以泛化。

  • 信息抽取　从自由文本中抽取结构化信息（谁在何时何地做了什么）的任务。

怎么学

读一段新闻，自己手工填一张MUC式的事件表；再看CoNLL-2003如何把任务简化为逐词标注。
