ToolkenGPT工具词元

ToolkenGPT: Augmenting Frozen Language Models with Massive Tools via Tool Embeddings
2023.05论文延伸NeurIPS 2023Shibo Hao, Tianyang Liu, Zhen Wang, Zhiting Hu · 加州大学圣地亚哥分校待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

让模型用工具有两条路：微调（如Toolformer）成本高、工具集一固定就不能加；上下文示例不用训练，但上下文装不下几个示例，工具一多就几乎失效。

方法

把每个工具当成一个新词元（toolken），只给它学一个嵌入向量、模型本体冻结；模型生成时一旦「说出」某个工具词元，就切换到填参数模式调用工具，再把结果写回文本。

影响

可以随时增加任意多的工具，每加一个只多一行嵌入；在数值计算、知识问答和具身规划上超过ReAct和上下文学习，工具数到上百时优势更明显，是「工具检索/工具表示」方向常被引用的早期方法。

方法

语言模型输出层本来对每个词有一个向量，用来算下一个词的概率。ToolkenGPT在这个词表后面追加若干行，每行对应一个工具，例如 <add>、<multiply>、<求某人出生地>。

推理时分两种模式：

  • 推理模式：模型照常一个词一个词地写，工具词元与普通词一起参与竞争；
  • 工具模式：一旦预测出某个工具词元，就换用该工具的少量示例提示模型补全参数，例如 <multiply>(3.5, 12)，执行后把结果42插回原文，回到推理模式继续写。

训练时只更新这几行新嵌入，梯度不经过模型本体，所以便宜，也可以用大量演示数据来学，而不受上下文长度限制。训练数据来自已有标注（GSM8K的算式）、ChatGPT合成的例子或领域内监督数据。

实验在冻结的LLaMA 13B/33B上进行：FuncQA单跳题（13个工具）上准确率0.73，ReAct为0.57；VirtualHome具身规划成功率0.68，上下文学习为0.20；在KAMEL知识问答上，工具数增加到上百个时上下文学习明显下降，而ToolkenGPT保持最好。

局限与后续

  • 每个工具都要有演示数据来训练嵌入，新工具不能零样本直接使用；而且要访问模型的输出层，闭源API模型用不了。
    后来针对它的工作　ToolLLM与ToolBench
  • 填参数仍靠上下文示例，复杂参数和多工具组合的正确率有限。

怎么学

先读Toolformer和ReAct → 读原文第3节toolken的定义和两种模式 → 动手：给一个小模型的词表加两个工具词元，只训练这两行输出嵌入，看它能否在合适位置预测出工具。
