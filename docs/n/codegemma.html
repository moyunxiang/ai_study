CodeGemma

CodeGemma: Open Code Models Based on Gemma
2024.06论文延伸arXiv 2024CodeGemma Team（Heri Zhao, Jeffrey Hui, Joshua Howland, Nam Nguyen 等） · Google待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

IDE里的代码补全需要又快又会“填中间”的小模型，而对话式编程助手又需要保留自然语言和数学能力，一个模型很难兼顾。

方法

在Gemma基础上继续用大量代码做预训练，发布擅长中间填充的2B补全模型和兼顾自然语言的7B预训练/指令模型。

影响

Google第一批开放权重的代码模型，2B版本面向低延迟补全，7B版本在代码能力上与同期开源模型持平。

背景

Code Llama、StarCoder、DeepSeek-Coder等开源代码模型已经把中间填充FIM（中间填充）训练变成标配。Google在2024年2月开放了Gemma，但通用模型直接用于补全时速度和填空能力都不够理想。

方法

CodeGemma以Gemma的2B和7B为起点继续预训练，主要用代码数据，混入一部分数学和自然语言数据以免通用能力退化：

  • FIM训练：以较高比例把文件切成前缀-后缀-中间三段，让模型学会根据上下文填中间，支持PSM与SPM两种拼接顺序；
  • 多文件打包：按仓库内的依赖关系把相关文件拼在一起训练，让模型看到跨文件的上下文；
  • 三个变体：CodeGemma 2B（面向快速补全与填充）、7B预训练版、7B指令微调版（面向对话式编程和数学推理）。

结果

摘要报告：7B预训练和指令版在自然语言理解上表现稳健，数学推理出色，代码能力与其他开源模型相当；2B模型是面向延迟敏感场景的最先进代码补全模型。

后来的发展

后来Google的开源代码能力主要并入Gemma 2、Gemma 3等通用模型；CodeGemma是Gemma家族向专用领域扩展的第一步，之后还有RecurrentGemma、PaliGemma等变体。

局限与后续

  • 7B规模在复杂代码生成和仓库级任务上明显落后于同期的大型代码模型和闭源模型。

怎么学

先读中间填充FIM理解中间填充；读CodeGemma第2节的数据与FIM设置；动手：用2B模型在编辑器中做一次中间填充补全，比较PSM与SPM格式。
