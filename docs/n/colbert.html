ColBERT后期交互

ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT
2020.04论文重要SIGIR 2020Omar Khattab, Matei Zaharia · Stanford University待核对
arXiv ↗GitHub: stanford-futuredata/ColBERT ↗在交互版中打开（演化树、学习进度）

问题

BERT重排序效果大幅领先，但每个查询要把查询和上千篇文档逐对送进BERT，一次查询要十几秒GPU时间，没法直接用于检索。

方法

查询和文档各自用BERT编码成一组词向量，文档向量离线算好存起来；在线只算查询，再对每个查询词取它与文档词向量的最大相似度并求和（MaxSim）。

影响

把BERT级别的排序质量降到几十毫秒的成本，开创了“多向量/后期交互”这一检索路线，介于单向量稠密检索和逐对交叉编码之间。

背景

2019年BERT重排序证明：把查询和文档拼在一起送进BERT打分，MS MARCO上的MRR@10能从BM25的16.7提高到35左右。代价是每个“查询-文档对”都要完整跑一遍BERT，重排BM25给出的前1000篇，单个查询在V100上要约10.7秒。

另一条路是把查询和文档各压成一个向量再算内积（同月的稠密检索DPR就是这样），文档向量可以提前算好，但整段话被压进一个向量，细粒度的词级匹配信息丢掉了。问题是：能不能既提前算文档，又保留词级别的交互？

方法

独立编码。查询前加特殊标记[Q]，补足到32个token，不足的位置填[mask]（作者称为“查询扩充”，让模型在这些位置学出可能的扩展词）；文档前加[D]。两边各过一遍BERT，每个token的输出再经过一个线性层降到128维并做L2归一化。于是查询变成32个向量E_q，文档变成几十到上百个向量E_d。

后期交互（MaxSim）。打分只在两组向量算好之后才发生：

S(q, d) = Σ_i max_j (E_q,i · E_d,j)

对每个查询词，在文档里找最像它的那个词，取相似度，再把所有查询词的分数加起来。比如查询“苹果 股价”，“苹果”会匹配到文档里的“Apple”，“股价”匹配到“市值”，两者分别取最大再相加。

两种用法。一是重排序：文档向量从磁盘读出，只需编码查询加做MaxSim。二是端到端检索：把全部文档的词向量放进FAISS向量检索，每个查询向量先近邻搜出候选文档，再对候选做精确MaxSim。

结果

MS MARCO重排序（开发集）MRR@10为34.9，接近BERT-base的36.0，好于所有非BERT方法；重排延迟61毫秒，比BERT-base快170多倍，FLOPs少约1.39万倍。端到端检索时MRR@10为36.0，Recall@1000达96.8%，而BM25只有85.7%。880万段落的索引在4块GPU上约3小时建完。

后来的发展

ColBERT之后，“一个文本一个向量”和“逐对交叉编码”之间多了一个中间选项。作者团队后来做了压缩索引、蒸馏训练的ColBERTv2和更快的检索引擎，并把它作为检索器用进了DSPy等系统。多向量的思路也被用到图文检索上。工业界最常用的仍是单向量嵌入（OpenAI文本嵌入、BGE嵌入模型）加交叉编码重排，ColBERT主要用在对精度要求高、能承受较大索引的场景。

容易误解的地方

  • ColBERT不是又一个单向量稠密检索器：它每个token都存一个向量，索引大小与语料token数成正比，比DPR大得多。
  • “快170倍”是相对逐对BERT重排而言；端到端检索延迟约458毫秒，仍比BM25慢。

局限与后续

  • 每个文档token都要存一个128维向量，索引体积比单向量检索大一个数量级以上，内存和磁盘成本高。

  • 竞争
    稠密检索DPR2020.04 · 推理·智能体 待核对
    同月发表的稠密检索：DPR一段话一个向量，便宜但丢掉词级匹配；ColBERT每词一个向量，更准但索引更大。
  • 使用
    BERT2018.10 · LLM
    查询编码器和文档编码器都是BERT-base，只在输出后加一个降维线性层。
  • 延续
    BM251994 · NLP
    重排模式下处理BM25的前1000篇；端到端模式下Recall@1000从BM25的85.7%提到96.8%。
  • 使用
    FAISS向量检索2017.02 · 推理·智能体
    端到端检索时用FAISS对全部文档词向量做近似近邻搜索，找出候选文档。
  • 改进
    Sentence-BERT2019.08 · NLP
    两句话各自压成一个向量，丢掉了词与词之间的细粒度交互，精度低于交叉编码器（STS基准86.10对88.77）。
  • 改进
    DSSM深度语义匹配2013.10 · NLP

    BERT重排序2019.01 · 推理·智能体
    保留BERT的上下文表示，但把逐对交互推迟到编码之后，解决了BERT重排每个查询要十几秒的成本问题。

读懂它需要的概念

预训练与微调 嵌入向量 内积与余弦相似度 检索与向量数据库 Transformer层的结构

本篇术语

  • 后期交互　查询和文档先各自独立编码，最后才用便宜的运算（这里是MaxSim）让两者交互。区别于把两者拼在一起送进模型的“早期交互”。
  • MRR@10　平均倒数排名：第一个相关结果排第k位得1/k分，前10里没有就得0分，再对所有查询取平均。
  • 多向量检索　一个文档用一组向量（每个token一个）表示，而不是一个向量。

怎么学

先弄懂检索与向量数据库里的稠密检索和内积与余弦相似度，再读原文第3节（尤其3.1的late interaction示意图和MaxSim公式）和表1、表2。动手：用HuggingFace的BERT对几个查询和段落取每个token的输出，手写MaxSim打分，与取[CLS]单向量的内积打分做对比。
