几分钟学会走路

Learning to Walk in Minutes Using Massively Parallel Deep Reinforcement Learning
2021.09论文重要CoRL 2021Nikita Rudin, David Hoeller, Philipp Reist, Marco Hutter · ETH Zürich / NVIDIA待核对
arXiv ↗legged_gym开源代码 ↗在交互版中打开（演化树、学习进度）

问题

足式机器人的RL策略在CPU仿真上训练要几十到上百小时，研究者改一次奖励就要等好几天，迭代极慢。

方法

在Isaac Gym里把物理仿真和PPO训练都放到同一块GPU上，同时模拟几千台机器人；相应地重调批大小等超参数，修正超时处理的细节，并设计一个像游戏闯关一样的地形课程。

影响

ANYmal在平地上的行走策略4分钟内训练完，复杂地形20分钟，比此前快几个数量级；开源的legged_gym成为之后几年足式和人形机器人RL的标准起点。

背景

足式机器人强化学习和ANYmal复杂地形行走证明了“仿真里用RL训练、零样本迁移到真机”在足式机器人上可行，但训练成本很高：论文列举的此前在台阶上行走的工作，分别要82小时、88小时、120小时的训练。原因是传统物理引擎（如MuJoCo物理仿真、RaiSim）跑在CPU上，想要大量并行就得像Dactyl灵巧手那样调动几千个CPU核，数据在CPU和GPU之间来回搬运也很费时间。

2021年NVIDIA发布了Isaac Gym大规模并行仿真：物理仿真直接在GPU上算，观测、奖励都以张量形式留在显存里，单卡就能同时模拟几千个环境。问题是，标准的RL算法和超参数都是为几个到几十个并行环境设计的，直接把几千个机器人塞进去未必能学得好、学得快。

方法

全部在GPU上。仿真、观测计算、奖励计算和PPO的更新都在同一块GPU上，数据不出显存。

重调超参数（见批大小、步数与轮数）。PPO每次更新前要用当前策略采一批数据，批大小 B = 机器人数 × 每台采的步数。机器人多了，每台只需采很少的步数；但论文发现每台少于25步（0.5秒仿真时间）时学不好。小批量（mini-batch）取到几万个样本，比常规做法大得多。实验表明2048–4096台机器人、批大小约10万到20万是最佳折中。

修正超时。每个回合最长20秒，到时间就重置。很多PPO实现把“超时重置”和“摔倒失败”同样当作回合结束、未来价值记为0，这会让价值估计出错。论文在超时的情况下用价值网络自己的预测来补上未来回报（自举，见时序差分与自举）。

游戏式课程。所有地形（平地、斜坡、随机粗糙、离散障碍、台阶）按难度分级，拼在同一张大地图上。机器人走出当前地块，下次就升一级（台阶高度从5厘米逐步加到20厘米，坡度从0°到25°）；走不到目标距离的一半就降一级。这比ANYmal复杂地形行走用粒子滤波的课程简单得多，也不用调参。

结果

在单块工作站GPU上，ANYmal平地行走策略不到4分钟训练完成，崎岖地形（含台阶）约20分钟，而此前同类工作需要几十到上百小时。策略部署到真实ANYmal C上，验证了sim2real仍然成立。

后来的发展

开源的legged_gym几乎成了足式RL的默认代码库：四足跑酷、人形机器人RL行走等大量工作都在它的基础上改。GPU并行仿真也从此成为机器人RL的主流基础设施，后续发展为Orbit / Isaac Lab，以及ManiSkill3、Genesis物理引擎等新一代仿真器。“几分钟一次实验”让研究者可以快速试奖励、试结构，也为Eureka奖励设计这类用大模型自动写奖励、反复试错的方法提供了条件。

读懂它需要的概念

策略梯度 Actor-Critic与优势函数 批大小、步数与轮数 时序差分与自举 仿真到现实的差距 CPU、GPU与并行计算

本篇术语

  • GPU并行仿真　把成千上万个仿真环境同时放到一块GPU上计算物理，状态以张量形式保存在显存中，直接供神经网络读取。
  • 超时自举（time-out bootstrapping）　回合因时间到了被强行截断时，未来回报并不是0，应该用价值网络的估计补上，否则价值函数会学偏。
  • 地形课程　训练时从简单地形开始，按机器人表现逐步加难，避免一开始就太难导致什么也学不会。

怎么学

先补PPO和优势估计 → 读原文第2节（GPU上的PPO修改与超时处理）和第3节（课程） → 动手：克隆legged_gym，在一块消费级GPU上训练ANYmal平地行走，改机器人数量观察训练时间和最终奖励的变化。
