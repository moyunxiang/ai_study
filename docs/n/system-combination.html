翻译系统融合

Combining Outputs from Multiple Machine Translation Systems
2007.04论文延伸NAACL-HLT 2007Antti-Veikko Rosti, Necip Fazil Ayan, Bing Xiang, Spyros Matsoukas, Richard Schwartz, Bonnie Dorr · BBN Technologies、马里兰大学待核对
ACL Anthology ↗在交互版中打开（演化树、学习进度）

问题

短语式、层次式、句法式等不同翻译系统准确率差不多，但各自出错的地方不同；只挑一个系统的输出，就浪费了其他系统在别处译对的部分。

方法

借鉴语音识别里的混淆网络投票，在句子、短语、词三个层面融合多个系统的输出：选最好的整句、重组各系统的短语，或把各系统译文对齐成一张混淆网络后逐位置投票。

影响

词级混淆网络融合成为NIST、GALE等评测里各大团队的标配，常能在最好的单系统之上再提高数个BLEU点；“多系统输出对齐后投票”的思路也延续到后来神经翻译的集成与重排序中。

背景

2000年代中期，统计翻译有多条并行路线：短语统计机器翻译、层次短语翻译Hiero层次短语、基于句法的系统等，它们用的语言学知识差别很大，最终BLEU却相近。语音识别早在1997年就用ROVER把多个识别器的输出对齐后投票，混淆网络与共识解码（Mangu等，2000）又给出了按位置求共识的解码方法。翻译的难点在于不同系统的译文词序不同，不能像语音那样简单按时间对齐。

方法

论文比较三种层次的融合：

  • 句子级：把各系统的N-best候选合并，用系统得分、语言模型等特征重新打分，选出一整句。
  • 短语级：利用各系统给出的目标—源短语对齐，把所有系统用到的短语收集成新的短语表，重新解码一次。
  • 词级：选一个系统的译文作“骨架”，把其他系统的译文用TER（翻译编辑率）式的编辑距离对齐到骨架上，允许词移位；对齐结果构成一张混淆网络，每个位置是若干备选词（含空词），各系统按权重投票，再结合语言模型找出得分最高的路径。

词级方法的关键在于对齐时允许整段移位，从而容忍不同系统的词序差异；投票权重和语言模型权重在开发集上调。

结果

在NIST MT05和GALE 2006试运行新闻组数据这两个开发测试集上，词级融合带来的提升最稳健，三种方法全部组合时效果最好（原文摘要结论）。

后来的发展

此后几年，基于混淆网络的词级融合被不断改进（增量对齐、多骨架、联合解码等），WMT专门设立过系统融合任务。它的局限也很明显：需要维护多个完整系统、融合本身要调参。神经翻译时代，单个模型的集成（多个检查点平均概率）和最小贝叶斯风险解码MBR式的候选重排取代了这种跨架构的输出融合，但“用多个假设的共识选答案”的思想延续到了后来的MBR解码与大模型的多次采样投票。

本篇术语

  • 混淆网络　一串位置，每个位置列出若干候选词及其权重（可含空词），路径上依次各选一个词就得到一句话。
  • TER　翻译编辑率：把一个译文改成另一个所需的插入、删除、替换和整段移位次数，常用来对齐不同系统的输出。
  • 骨架　词级融合中选作对齐基准的那一个系统译文，其他译文都对齐到它上面。

怎么学

先读混淆网络与共识解码了解语音里的共识解码 → 读本文第4节词级融合 → 动手：拿三个不同翻译系统对同一句的输出，手工用编辑距离对齐成混淆网络，按多数投票得到融合译文。
