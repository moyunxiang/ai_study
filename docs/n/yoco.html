YOCO只缓存一次

You Only Cache Once: Decoder-Decoder Architectures for Language Models
2024.05论文延伸NeurIPS 2024 OralYutao Sun, Li Dong, Yi Zhu, Shaohan Huang, Wenhui Wang, Shuming Ma, Quanlu Zhang, Jianyong Wang, Furu Wei · 微软研究院、清华大学待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

仅解码器Transformer每一层都要保存自己的KV缓存，上下文一长，显存和预填充时间都随层数和长度一起暴涨。

方法

把模型拆成上下两半：下半部分用高效注意力生成一份全局KV缓存，上半部分所有层通过交叉注意力共用这份缓存。

影响

在保留全局注意力能力的同时，把推理显存、预填充延迟和吞吐改善了数量级，并扩展到百万token上下文。

背景

标准Transformer解码时，L层各存一份键值，缓存大小正比于 L × n × d。分组查询注意力GQA、多查询注意力MQA在头之间共享键值，只能省一个常数倍；RetNet等线性模型状态恒定，但牺牲了对任意位置的精确检索。

方法

YOCO由两段堆叠：

  • 自解码器（self-decoder）：前一半层用滑动窗口注意力或门控保留（gated retention）这类内存恒定的机制，处理整个输入，最后输出一份全局的 K, V。
  • 交叉解码器（cross-decoder）：后一半层不再自己算键值，而是用交叉注意力去读这一份共享缓存。

整体仍是因果的、从外部看与仅解码器模型一样，但全局KV只缓存一次，缓存从 L 份降到约1份。另一个好处是预填充可以“提前退出”：输入文本只需跑完自解码器就能得到全部缓存，交叉解码器只在生成新token时才需要运行，因此长提示的预填充大幅提速，而最终输出不变。

结果

摘要报告：在扩大模型规模和训练token数的多种设置下，YOCO与Transformer相比表现有竞争力；扩展到100万token上下文时大海捞针检索接近满分；推理显存、预填充延迟和吞吐在各种长度和规模下都改善了数量级。

后来的发展

它是“跨层共享KV”路线的代表之一，入选NeurIPS 2024口头报告，与跨层注意力CLA等方法一起推动了缓存压缩的架构设计；后续的混合注意力模型也常借鉴“少数全局层加大量高效层”的分工。

局限与后续

  • 交叉解码器所有层读同一份KV，表达上弱于每层独立的键值，需要更大的模型或数据来弥补。

它建立在什么之上

  • 改进
    Transformer2017.06 · LLM
    解决每层各存KV导致缓存随层数线性增长的问题。
  • 竞争
    分组查询注意力GQA2023.05 · LLM
    GQA在头之间共享KV，YOCO在层之间共享KV，两者都为压缩缓存。
  • 使用
    Longformer滑窗注意力2020.04 · LLM
    自解码器可用滑动窗口注意力处理局部上下文。
  • 使用
    RetNet2023.07 · LLM
    自解码器可采用同团队RetNet的门控保留机制来保持恒定内存。

读懂它需要的概念

KV缓存 自注意力与多头注意力 编码器-解码器 上下文窗口 显存、内存带宽与“内存墙”

本篇术语

  • 预填充（prefill）　生成前先把整段提示一次性跑过模型、建好KV缓存的阶段，长提示时它决定首个token的等待时间。

怎么学

先弄懂KV缓存和交叉注意力；读YOCO第2节架构图；动手：估算一个32层模型在128K上下文下普通缓存与YOCO缓存的显存差。
