GLUE / SuperGLUE

GLUE: A Multi-Task Benchmark and Analysis Platform for Natural Language Understanding
2018.04数据集重要ICLR 2019（GLUE）；NeurIPS 2019（SuperGLUE）Alex Wang, Amanpreet Singh, Julian Michael, Felix Hill, Omer Levy, Samuel R. Bowman · 纽约大学 / 华盛顿大学 / DeepMind待核对
arXiv（GLUE） ↗arXiv（SuperGLUE） ↗GLUE官网 ↗在交互版中打开（演化树、学习进度）

问题

NLP模型各自在单个数据集上刷分，无法回答“一个模型的语言理解能力是否通用”；小数据任务上也看不出迁移学习的价值。

方法

把九个现有的英语句子理解任务打包成一个基准，测试集答案不公开，统一在线评分，取各任务的宏平均作为一个总分。

影响

成为2018–2019年预训练模型的主战场：GPT-1、BERT、XLNet、RoBERTa、T5都以刷新GLUE总分为卖点；一年多就被超越人类基线，随即推出更难的SuperGLUE。

背景

2018年前，NLP研究基本是一个任务一个模型：情感分析、复述判断、推理各有各的数据集和专用架构。SQuAD、MultiNLI这样的大数据集推动了单项进步，但一个在SQuAD上很强的模型换到别的任务上往往要从头设计。

与此同时，CoVe上下文词向量、ELMo表明在大规模文本上预训练的表示可以提升多个下游任务。要衡量“通用性”，需要一个同时包含大小不同、领域不同任务的统一考场，而且测试答案要藏起来，防止各家在测试集上反复调参。

方法

GLUE包括九个英语任务，分三组：

  • 单句：CoLA（句子是否合乎语法）、SST-2（电影评论情感）。
  • 相似与复述：MRPC、QQP（两句是否同义）、STS-B（两句相似度打1–5分）。
  • 推理：MNLI、QNLI（由SQuAD改造：句子是否回答了问题）、RTE（来自RTE文本蕴含挑战）、WNLI（由Winograd模式挑战改造）。

其中RTE、WNLI、MRPC训练集只有几千条甚至几百条，单独训练几乎学不会，逼着模型把在大任务或预训练中学到的知识迁移过来。每个任务按各自的常用指标打分，多指标的先平均，九个任务再做不加权的基准、排行榜与SOTA宏平均，得到GLUE分数。测试集标签由组织方私有，提交预测到gluebenchmark.com才能看到成绩。

另有一个由专家手写的诊断集，按词汇语义、谓词论元结构、逻辑（否定、量词、单调性）、常识四大类标注语言现象，用来分析模型具体错在哪里。

2019年推出的SuperGLUE沿用同样的形式，换成八个更难的任务（BoolQ、CB、COPA、MultiRC、ReCoRD、RTE、WiC、WSC），每个任务都估计了人类成绩，并剔除了对机器基线已经太容易的任务。

结果

论文里最好的基线是多任务训练的BiLSTM加ELMo加注意力，GLUE分数70.0。半年内GPT-1达到72.8，BERT达到80.2。到2019年7月，XLNet以88.4超过了人类基线87.1。SuperGLUE上BERT为69.0，人类估计为89.8；2021年1月DeBERTa解耦注意力单模型89.9、集成90.3，又超过了人类。

后来的发展

GLUE让“预训练加微调，在一组任务上看总分”成为评价语言模型的标准范式，也让排行榜驱动研究的问题浮出水面：标注伪影指出的数据捷径同样存在于其中的NLI任务，排行榜批判批评单一总分忽略了效率和鲁棒性。

大模型时代，评测重心转向知识和推理更难的MMLU、任务数量更多的BIG-bench和多维度的HELM；跨语言则有XNLI、XTREME跨语言基准。今天GLUE基本只用于小模型和教学。

容易误解的地方

  • “超过人类基线”不代表理解语言超过人：人类基线来自少量众包工人的估计，而模型可能利用了数据里的表面线索。
  • 图上的id“superglue”是视觉里的特征匹配网络，与这里的SuperGLUE基准无关。

局限与后续

  • 题目难度很快被预训练模型追上，GLUE一年多、SuperGLUE不到两年就超过人类基线，失去区分度。
    后来针对它的工作　MMLU BIG-bench
  • 只有英语，无法衡量跨语言迁移。
    后来针对它的工作　XNLI XTREME跨语言基准
  • 测试集固定不变，长期反复提交容易过拟合，其中的NLI任务还带有标注伪影。
    后来针对它的工作　Dynabench动态基准 对抗式NLI
  • 只看一个准确率总分，不考虑模型大小、速度、鲁棒性和公平性。

它建立在什么之上

  • 改进
    困惑度Perplexity1977 · 数据·评测
    困惑度的改进与下游任务效果并不总是一致，降低困惑度未必降低词错误率或提高翻译、问答质量。
  • 使用
    SQuAD2016.06 · 数据·评测
    QNLI任务由SQuAD改造：判断上下文中的某个句子是否包含问题的答案。
  • 使用
    ELMo2018.02 · LLM
    论文最强基线用ELMo预训练表示，多任务训练拿到70.0分。
  • 改进
    Senseval / SemEval1998.09 · 数据·评测
    评测针对孤立的词义任务，难以说明对整体语言理解有多大帮助。
  • 使用
    RTE文本蕴含挑战2005 · 数据·评测
    把PASCAL RTE历届挑战的数据合并为一个小数据推理任务。
  • 使用
    Winograd模式挑战2012.06 · 数据·评测
    把Winograd代词消解题改写成句对推理的WNLI，后来SuperGLUE又以原始形式收入WSC。
  • 改进
    bAbI2015.02 · 数据·评测
    任务是模板生成的合成数据，语言简单规整，模型可以靠记住模板得高分，不能代表真实阅读理解。
  • 使用
    MultiNLI2017.04 · 数据·评测
    MultiNLI是GLUE中训练数据最多的任务，也是检验推理能力的核心。
  • 使用
    CoVe上下文词向量2017.08 · NLP
    CoVe是论文评测的另一种预训练表示基线，GLUE上效果不如ELMo。

读懂它需要的概念

基准、排行榜与SOTA 预训练与微调 迁移学习 准确率、精确率、召回率与F1 训练集、验证集与测试集

本篇术语

  • 宏平均　先在每个任务上单独算分，再把各任务分数直接平均，不按数据量加权，所以小任务和大任务对总分贡献一样大。
  • 诊断集　专门构造的小测试集，每题标注它考的是哪种语言现象（如双重否定），用来定位模型的短板，不计入总分。

怎么学

先懂预训练与微调与基准、排行榜与SOTA。读GLUE原文第3节（九个任务）和表1，再读SuperGLUE第3节的选题原则。动手：用Hugging Face的datasets加载glue/rte，微调一个小BERT，体会只有约2500条训练数据时预训练有多重要。
