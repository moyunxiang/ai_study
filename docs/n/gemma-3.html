Gemma 3

Gemma 3 Technical Report
2025.03论文延伸arXiv 2025Gemma Team · Google DeepMind待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

小型开源模型要支持长上下文，KV缓存的显存会随长度暴涨，在单卡上跑不起来。

方法

把局部滑动窗口注意力层和全局注意力层按更高比例交错，并加入视觉能力，参数规模1B到27B。

影响

表明27B级开源模型靠架构和蒸馏就能逼近上一代旗舰闭源模型，并把上下文推到至少128K。

方法

Gemma 3是Google的开源小模型系列，规模1到27B参数，在Gemma 2基础上增加了图像理解、更多语言覆盖和至少128K token的上下文。

最主要的结构改动是针对长上下文的参数量、计算量与显存（显存）问题：推理时每层都要保存过去所有token的键和值（KV缓存），上下文越长越占显存。Gemma 3提高了“局部注意力层”与“全局注意力层”的比例，局部层只看一小段窗口，窗口跨度也刻意取得很短，这样大部分层的缓存不随长度增长。训练上使用知识蒸馏，并设计了新的后训练配方来提升数学、对话、指令遵循和多语言能力。

技术报告称Gemma3-4B-IT可与Gemma2-27B-IT竞争，Gemma3-27B-IT在各基准上与Gemini-1.5-Pro相当。

局限与后续

  • 局部/全局注意力的比例是手工设定的，局部窗口之外的信息只能靠少数全局层传递，超长文档上的精细检索仍受限。
