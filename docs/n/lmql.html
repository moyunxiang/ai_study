LMQL语言模型查询语言

Prompting Is Programming: A Query Language for Large Language Models
2022.12论文延伸PLDI 2023Luca Beurer-Kellner, Marc Fischer, Martin Vechev · 苏黎世联邦理工学院（ETH Zürich）待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

高级提示方法需要语言模型与用户、外部工具多轮交互，还要约束输出格式；要做到这些，往往得写复杂的、针对特定任务和模型的临时代码，而且多余的生成浪费调用开销。

方法

提出“语言模型编程”的概念和查询语言LMQL：把文本提示与脚本控制流、对输出的约束写在一起，解码时把约束编译成逐token的掩码，只生成合法的输出。

影响

是约束解码与“提示即程序”这一方向的早期代表，与Guidance、约束解码Outlines、SGLang与RadixAttention的前端语言一起推动了结构化生成工具的出现。

方法

一个LMQL查询看起来像带占位符的Python：提示文本中嵌入变量（如[ANSWER]），后面跟where子句写约束，例如长度上限、必须是某个列表中的选项、必须是整数、遇到某个字符就停。还可以用循环和条件语句根据前面生成的内容决定下一步提示。

关键实现是“部分求值”的约束解码：在生成每个token前，运行时判断哪些候选token会导致约束被违反（或注定违反），把它们的概率置零，只在合法集合里采样或贪心选择；一旦变量满足终止条件就提前停止生成。这样既保证输出格式正确，又减少了不必要的模型调用。论文报告：在多种提示方法上，LMQL能以更少的代码实现，同时因减少调用与生成token，在使用付费API时显著降低计算或费用（摘要给出的数字是节省26%–85%），且下游任务准确率保持或提高。

局限与后续

  • 基于token掩码的约束依赖能访问模型的逐token概率，对只提供文本接口的闭源API支持受限。

读懂它需要的概念

怎么学

先了解逐token解码与采样；读论文第3节语言设计与第4节约束解码的部分求值；动手用LMQL写一个只允许输出“是/否”的分类查询。
