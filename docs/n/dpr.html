稠密检索DPR

Dense Passage Retrieval for Open-Domain Question Answering
2020.04论文延伸EMNLP 2020Vladimir Karpukhin, Barlas Oğuz, Sewon Min, Patrick Lewis, Ledell Wu, Sergey Edunov, Danqi Chen, Wen-tau Yih · Facebook AI / Princeton / UW来源已核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

开放域问答要先从百万段维基文本里找证据，主流是TF-IDF/BM25词匹配，问法和原文用词不同就找不到。

方法

用两个BERT分别把问题和段落编码成向量，用内积衡量相关，只靠少量问答对训练，就能做稠密向量检索。

影响

在五个开放域问答集中的四个上，top-20检索准确率明显超过BM25（SQuAD除外）；之后被RAG直接用作检索器。

方法

结构是双编码器：问题编码器和段落编码器各是一个BERT，相关度为两个向量的内积。训练用对比损失：每个问题配一个正确段落，负样本取同批次里别的问题的正确段落（批内负样本），再加一个BM25取到的难负样本，让正确段落得分高于其余。段落向量可离线算好建索引，查询时只需编码问题再做近邻搜索。

摘要称在多个开放域问答集上，top-20段落检索准确率比Lucene-BM25高9%到19%（绝对值），并带动端到端问答刷新当时最佳；例如Natural Questions上78.4对59.1。例外是SQuAD（63.2对68.8），作者解释为它的问题是标注者看着段落写的、与原文用词重合度高，且只来自500多篇维基百科文章。只用1000条训练样本时，DPR就已超过BM25。

后来的发展

检索增强生成RAG直接用DPR作检索器；之后的Contriever无监督检索、OpenAI文本嵌入、BGE嵌入模型等嵌入检索模型都沿用双编码器加对比学习的路线。

局限与后续

  • 依赖标注的问答对来训练；后来的Contriever论文（2021）指出，这类稠密检索器迁移到没有训练数据的新应用时常常不如BM25。

它建立在什么之上

  • 使用
    BERT2018.10 · LLM 已核对
    问题和段落的两个编码器都由BERT初始化。
  • 改进
    DrQA开放域问答2017.03 · NLP 已核对
    DrQA式流水线用TF-IDF找段落，问法与原文用词不同时容易找不到；DPR改用学习到的稠密向量，在多数数据集上明显改善了检索准确率（原文对比的稀疏基线是BM25，并借用了DrQA的维基百科预处理代码）。
  • 改进
    IDF与TF-IDF1972.01 · NLP
    只看字面是否相同：查询写“汽车”、文档写“轿车”就完全匹配不上（词汇不匹配问题）。
  • 改进
    向量空间模型1975.11 · NLP
    每个词是独立且互相正交的维度，“汽车”和“轿车”的相似度为0，查询和文档用词不同就搜不到。
  • 改进
    BM251994 · NLP
    仍然只认字面相同的词，查询与文档用词不同（同义词、改写）就检索不到。
  • 改进
    FAISS向量检索2017.02 · 推理·智能体
    它只负责“在向量里找近邻”，检索质量完全取决于向量本身是否表达了语义；当时还没有好用的文本检索向量。
  • 改进
    PageRank与Google搜索1998.04 · NLP
    对链接农场等作弊手段敏感，且对所有查询给同一个全局重要度，不能反映用户意图。
  • 改进
    基于Freebase的语义解析问答2013.10 · NLP
    依赖Freebase等结构化知识库，知识库没有的事实无法回答。
  • 改进
    HotpotQA多跳问答2018.09 · 数据·评测
    训练和评测都假设给定了候选段落，与真实检索设置有差距。
  • 改进
    BERT重排序2019.01 · 推理·智能体
    交叉编码器对每个候选都要完整前向一次，推理成本高，只能重排几十到几百条，召回阶段仍受BM25限制。

后来的相关工作

  • 使用
    检索增强生成RAG2020.05 · 推理·智能体 已核对
    检索器和2100万段维基百科的向量索引直接用DPR初始化，再联合微调查询编码器。
  • 延续
    Contriever无监督检索2021.12 · 推理·智能体 已核对
    保留双编码器，但去掉对标注问答对的依赖，改用无监督对比预训练。
  • 改进
    HyDE假设文档检索2022.12 · 推理·智能体 已核对
    依赖标注的问答对来训练；后来的Contriever论文（2021）指出，这类稠密检索器迁移到没有训练数据的新应用时常常不如BM25。
  • 竞争
    ColBERT后期交互2020.04 · 推理·智能体 待核对
    同月发表的稠密检索：DPR一段话一个向量，便宜但丢掉词级匹配；ColBERT每词一个向量，更准但索引更大。
  • 改进
    SPLADE学习式稀疏检索2021.07 · 推理·智能体 待核对
    单个向量压缩整段文本，细粒度词匹配信息丢失；作者在附录中也提到它可能没有足够容量表示罕见的关键短语。
  • 使用
    FiD融合解码2020.07 · 推理·智能体
    用DPR取回的段落作为输入。
  • 竞争
    BEIR零样本检索2021.04 · 数据·评测
    把稠密检索DPR与BM25等放在同一基准下比较，发现稠密方法零样本常不如BM25。
