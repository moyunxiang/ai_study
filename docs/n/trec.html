TREC文本检索评测

1992.11事件重要TREC-1，NIST Special Publication 500-207（1992年11月会议）Donna Harman等 · NIST（DARPA TIPSTER计划资助）待核对
TREC-1总览（Harman） ↗Wikipedia: Text Retrieval Conference ↗TREC官网 ↗在交互版中打开（演化树、学习进度）

问题

检索研究几十年来只有Cranfield这种上千篇文档的小测试集，各组各用各的数据，结论无法累积，也不知道方法到了真实规模的全文库上还灵不灵。

方法

NIST每年发布约2GB真实新闻全文和一批由真实用户写的检索需求，各队提交排序结果；把所有队的前几名结果合并成“池”，由人工评判相关性，统一打分后开会交流。

影响

TREC把检索评测从千篇级推到百万篇级，确立了“池化+人工评判”的大规模评测方法，并从文档检索扩展出问答、网页、对话等几十个赛道，一直办到今天。

背景

Cranfield实验与查准查全率实验确立了“文档集+查询+相关性标注+查准查全率”的评测范式，但它的测试集只有1400篇文档、225个查询。之后几十年，SMART系统的向量空间模型和IDF与TF-IDF等方法都在这种小集合上开发。

Harman在TREC-1总览里点出两个缺失。第一，虽然有些组用了相同的集合，但没有人组织大家用同样的数据、同样的评测方式横向比较；Karen Sparck Jones 1981年就抱怨，二十年的检索实验缺乏积累，后一个实验没能建在前一个之上。第二，没有接近真实规模的测试集：小集合上的结论未必适用于大规模全文检索，像短语索引、自动同义词表这类直觉上有用的技术，在小集合上反复验证都不显著。与此同时，DARPA在语言技术上推行DARPA共同任务框架式的统一评测，正需要一个检索方向的展示平台。

方法

数据。直接沿用DARPA TIPSTER项目的测试集：训练和测试两套文档各约1GB，压缩后刻在CD-ROM上发给参赛者，内容是报纸、通讯社稿件、杂志和期刊的全文。

主题（topic）。不是给一行关键词，而是由真实检索用户写的“需求说明”：标题、描述，以及什么样的文档算相关的明确标准。出题人先在样本文档上试检索，只保留命中大约25到100篇的主题，使难度有宽有窄。TREC-1共有训练和测试两批各50个主题。

两类任务。ad hoc：用新主题检索已有文档库，像在图书馆查资料；routing：用已知主题过滤新到达的文档流。

池化评判。文档有上百万篇，不可能每个主题都全部人工看一遍。做法是：每个参赛系统对每个主题提交排名前200的文档，把所有系统的结果合并去重，组成这个主题的“池”，评判员只看池里的文档，池外的一律视为不相关。每个主题由同一位评判员负责，保证标准一致。最后按查准率、查全率及其平均值统一打分，年底开会交流。

结果

TREC-1共有25个参赛系统。池化的效果比预想的好：在ad hoc任务里，33组提交结果按前200名合并，理论上每个主题最多6600篇不同文档，实际不同的约有2400篇，说明各系统找到的文档差别很大，合并后能覆盖更多相关文档。实际只评判各系统的前100名，平均每个主题评了约1462篇，最多的主题2893篇、最少611篇。维基百科引用的2010年一项经济评估估计，没有TREC的话，1999–2009年间美国网民用搜索引擎要多花多达31.5亿小时。

后来的发展

TREC前几届的激烈比较推动了BM25的定型（伦敦城市大学Okapi组在TREC-2、TREC-3的比较中逐步调出这个排序公式），此后二十多年它都是检索的默认基线。TREC每年增开新赛道：1999年起的问答赛道是开放域问答研究的重要起点，后来IBM Watson赢得Jeopardy!的DeepQA也建立在这一传统上；网页、跨语言、视频（TRECVID）、医学等赛道把同样的方法推广到别处。2019年起的深度学习赛道改用MS MARCO的数据（880万段落、50万条训练查询），第一年15个组提交的75个结果里，深度学习方法明显胜过传统检索方法。池化评判和“主题+相关性判断”的格式也被BEIR零样本检索等后来的检索基准沿用。

容易误解的地方

  • 池化意味着池外文档默认不相关。一个与所有参赛系统都不同的新方法，如果找到了池外的相关文档，反而会被判错，所以用旧的TREC集合评估全新类型的模型时要小心。
  • TREC的相关性大多是二元的，且由单个评判员定义，不同评判员之间本来就存在分歧。

局限与后续

  • 每年只有约50个主题，人工评判成本很高，相关性标注的总量远不足以训练需要大量样本的神经排序模型。

  • 池化评判依赖当年参赛系统的结果，对后来出现的、找到池外相关文档的新方法存在系统性偏差。

它建立在什么之上

  • 使用
    IDF与TF-IDF1972.01 · NLP
    TF-IDF加权是参赛系统最常用的打分基础，TREC上的比较推动了对它的系统改进。
  • 使用
    向量空间模型1975.11 · NLP
    SMART等向量空间检索系统是早期TREC参赛的主力基线。
  • 延续
    DARPA共同任务框架1987 · 数据·评测
    把DARPA共同任务的组织方式用到检索：统一数据、NIST统一打分、定期公开交流。
  • 改进
    Cranfield实验与查准查全率1962 · 数据·评测
    Cranfield集合只有1400篇文档、225个查询；TREC用约2GB全文和池化评判把检索评测推到真实规模。
  • 竞争
    MUC信息抽取评测1987 · 数据·评测
    同属DARPA TIPSTER体系下的文本评测：MUC评信息抽取，TREC评检索，前者偏结构化理解，后者偏排序，后来检索式问答把两条线汇合。

后来的相关工作

  • 使用
    BM251994 · NLP
    在TREC的大规模、长度差异巨大的文档集上开发和调参，正是这些数据暴露了词频与长度的问题。
  • 延续
    ROUGE2004.07 · 数据·评测
    NIST的DUC沿用TREC的统一评测方式组织摘要评测，ROUGE成为其中的自动打分工具。
  • 延续
    Netflix Prize2006.10 · 数据·评测
    延续TREC式“发布数据、隐藏答案、统一打分”的公开评测，但对任何人开放并加上百万美元奖金，参与规模大了几个数量级。
  • 延续
    MS MARCO2016.11 · 数据·评测
    延续TREC的检索评测传统，但用真实搜索日志提供了数十万条带标注的训练查询，足以训练神经排序模型。
  • 改进
    PageRank与Google搜索1998.04 · NLP
    早期文档集是新闻和期刊文本，没有网页的超链接结构和噪声，与网络搜索的真实环境有差距。
  • 改进
    BEIR零样本检索2021.04 · 数据·评测
    每个集合只代表一个领域，在一个TREC集合上调好的方法换到别的领域常常失效。

读懂它需要的概念

基准、排行榜与SOTA 准确率、精确率、召回率与F1 检索与向量数据库 训练集、验证集与测试集

本篇术语

  • 池化（pooling）　把所有参赛系统对一个查询排在前面的结果合并去重，只对这部分文档做人工相关性评判，以此近似完整标注。
  • ad hoc与routing　ad hoc是固定文档库、来了新查询就检索；routing是固定查询（用户兴趣）、来了新文档就判断是否推送。
  • 平均查准率（AP）　沿排名往下走，每遇到一篇相关文档就记下此刻的查准率，再对所有相关文档取平均；对多个查询再平均即MAP。

怎么学

先补准确率、精确率、召回率与F1里的查准率与查全率。然后读Harman的TREC-1总览第2.3节（池化）和第3.3节（主题），再用开源的trec_eval工具在一个小的TREC格式数据（例如BEIR里的小集合）上自己算一次MAP。
