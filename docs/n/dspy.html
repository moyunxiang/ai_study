DSPy

DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines
2023.10论文重要ICLR 2024Omar Khattab, Arnav Singhvi, Paridhi Maheshwari, Zhiyuan Zhang, Keshav Santhanam, Heather Miller, Matei Zaharia, Christopher Potts et al. · Stanford University / UC Berkeley 等待核对
arXiv ↗GitHub: stanfordnlp/dspy ↗在交互版中打开（演化树、学习进度）

问题

LLM应用通常由好几次模型调用串成流水线，每一步都靠人反复试出来的长提示模板；换个模型或改一步流程，所有提示都得重调。

方法

把提示换成可“编译”的程序：开发者只用签名声明每一步的输入输出（如question -> answer），由优化器在少量训练样本上运行整条流水线，自动挑出能让指标变好的示范样例，填进各步提示或用来微调小模型。

影响

把“提示工程”变成类似训练神经网络的过程：写模块、定指标、编译。GPT-3.5和Llama2-13b-chat上自动编译的流水线比普通少样本提示高出25%和65%以上，DSPy也成为最常用的提示优化框架之一。

背景

2023年，LangChain等框架让开发者把检索、推理、工具调用组合成多步流水线，但每一步的提示仍是手写的字符串模板，往往几百字、靠试错得来。模板与具体模型强绑定：从GPT-3.5换到开源模型，效果可能大幅下降。自动提示工程APE和OPRO以LLM为优化器已经尝试让模型自动生成提示，但它们优化的是单个提示，不处理多步流水线中“每一步该怎么提示、各步怎样配合”的问题。作者的出发点是：深度学习早就不手写特征，而是声明层、定义损失、交给优化器——提示能不能也这样？

方法

签名（signature）。声明一步要做的变换，而不是写提示。比如dspy.Predict(“question -> answer”)就是一个完整的问答程序，字段名本身表达语义；DSPy负责把它展开成具体提示并解析输出。

模块（module）。把常见提示技巧做成可复用、带参数的模块：Predict、ChainOfThought（先写推理，见思维链CoT）、ReAct（见ReAct）、多条推理链比较等，以及Retrieve检索模块（支持ColBERTv2等检索器）。模块可以像PyTorch层一样用普通Python控制流组合，例如“检索→带推理地回答”的RAG程序只有几行。

编译器与优化器（论文称teleprompter）。输入是程序、少量训练样本（可以只有问题和最终答案）和一个评价指标（如答案精确匹配）。最常用的BootstrapFewShot在训练样本上实际运行整个程序，记录每个模块的输入输出轨迹；凡是最终通过指标检验的轨迹，就把其中各模块的输入输出当作该模块的示范样例，自动填进提示。这与STaR自举推理“只保留答对的推理”同一思路，只是推广到了多个模块。还有随机搜索示范组合、集成多个编译结果，以及BootstrapFinetune——用大模型产生的轨迹去微调T5-Large这样的小模型。

结果

GSM8K（表1）：GPT-3.5直接回答测试集准确率25.2%，用ChainOfThought模块编译后72.9%，再集成达到81.6%（开发集88.3%）；Llama2-13b-chat从9.4%提到最高46.9%。论文总结为：靠编译正确的模块，不同模型从4–20%提升到49–88%。HotPotQA多跳问答（表2，用ColBERTv2检索维基百科摘要）：GPT-3.5的多跳程序经自举后测试集答案EM 39.6，集成后45.6，少样本基线为31.5。每次编译通常只需几分钟到几十分钟，最多运行程序几千次。

后来的发展

DSPy让“提示优化”成为一个独立方向。2024年6月作者团队发表MIPRO（arXiv 2406.11695），同时优化多步程序的指令文字和示范样例；框架本身也常被用来把同一流水线迁移到不同模型上。它和OPRO以LLM为优化器一起推动人们把提示看作可以用数据和指标优化的参数，而不是手艺；2025年的智能体上下文工程ACE则把这种思路扩展到智能体不断演化的上下文。

容易误解的地方

  • DSPy不训练大模型的权重（除非用BootstrapFinetune微调小模型）；“编译”主要是在挑选和组合提示里的示范样例。
  • 效果依赖评价指标：指标写得不对，优化器会找到投机取巧但无用的样例。

    ColBERT后期交互2020.04 · 推理·智能体

    STaR自举推理2022.03 · 推理·智能体
    沿用STaR“运行、只保留通过检验的轨迹作为训练数据”的自举思想，推广到多个模块组成的程序。
  • 改进
    LangChain2022.10 · 推理·智能体
    LangChain式流水线依赖手写提示模板，换模型就要重调；DSPy用签名和编译器自动生成各步提示。
  • 改进
    自动提示工程APE2022.11 · 推理·智能体
    APE让模型为单个任务自动搜索指令；DSPy把自动优化推广到多步流水线，优化的是每个模块的示范样例。
  • 改进
    OPRO以LLM为优化器2023.09 · 推理·智能体
    优化出的提示往往只对特定模型和任务有效，换模型需重新搜索，也缺乏理论保证。

读懂它需要的概念

上下文学习与提示 零样本与少样本 检索与向量数据库 智能体循环 超参数与调参

本篇术语

  • 签名（signature）　用“输入字段 -> 输出字段”的形式声明一步LLM调用要做什么，例如“context, question -> answer”，不写具体提示词。
  • teleprompter / 优化器　DSPy中负责“编译”的组件：在训练样本上运行程序，根据指标挑选示范样例或生成微调数据。
  • 示范样例（demonstration）　放在提示里的输入输出示例，即少样本提示中的“样本”。

怎么学

先熟悉上下文学习与提示和检索增强生成RAG的基本流程。读原文第3节（签名与模块）和第4节（编译），再看表1理解不同编译策略的差别。动手：按官方教程用DSPy写一个“检索→ChainOfThought回答”的程序，准备20条问答样本，比较编译前后在验证集上的准确率，并打印编译后实际生成的提示看看它选了哪些样例。
