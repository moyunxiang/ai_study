Toolformer

Toolformer: Language Models Can Teach Themselves to Use Tools
2023.02论文延伸NeurIPS 2023Timo Schick, Jane Dwivedi-Yu, Roberto Dessì, Roberta Raileanu, Maria Lomeli, Luke Zettlemoyer, Nicola Cancedda, Thomas Scialom · Meta AI / UPF待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

语言模型在算术、查事实这类简单事情上反而不如小工具，此前的工具调用需要大量人工标注或固定任务设置。

方法

让模型自己决定在文本的哪里插入API调用，只留下对后续预测真正有帮助的调用，再在这些数据上微调。

影响

提出自监督的工具学习方案，只需每种工具几个示范，不损失原有语言建模能力。

方法

做法分三步：先用少量示例提示模型，在一般文本的许多位置标出可能的API调用（如计算器、问答系统、两种搜索引擎、翻译、日历）；真正执行这些调用，拿到结果；然后比较「带调用结果」与「不带」时后续词的损失，只保留使损失降低足够多的调用；最后在保留下来的文本上继续微调。

摘要称微调后的模型能决定调用哪个API、何时调用、传什么参数，以及如何把结果融入后续预测，零样本表现在多项任务上明显提升，并常与大得多的模型相当。

后来的发展

同类思想成为后来的函数调用成为标准接口与ChatGPT插件的基础；Gorilla API调用、ToolLLM与ToolBench则面向更大规模的真实API。

局限与后续

  • 每次调用独立，不能链式使用多个工具，也无法根据中间结果再决定下一步。

  • 对工具的使用只在监督信号来自损失降低时有效，难处理多轮交互。

  • 改进
    TALM工具增强2022.05 · 推理·智能体
    沿袭自举式工具使用思路，但改成自监督、用语言建模损失筛选调用。

后来的相关工作

  • 延续
    函数调用成为标准接口2023.06 · 推理·智能体 待核对
    同样把“何时调用、怎么填参数”训练进模型，但工具由开发者在每次请求中任意定义，而不是固定几个。
  • 竞争
    ChatGPT插件2023.03 · 推理·智能体
    Toolformer把调用API的能力训练进模型；插件不改模型，只在提示里提供接口说明，依赖模型的通用理解能力。
  • 延续
    ChemCrow2023.04 · 科学
    把工具使用从通用API（计算器、搜索）推向专业化学工具链。
  • 竞争
    Coscientist2023.04 · 科学
    同样让语言模型使用工具，但Toolformer是自监督训练调用API，Coscientist是靠提示编排。
  • 延续
    Gorilla API调用2023.05 · 推理·智能体
    同样教模型调用外部工具，但把对象从少数简单工具扩展到成千上万个带复杂参数的真实API，并加入检索。
  • 改进
    ToolLLM与ToolBench2023.07 · 推理·智能体
    对工具的使用只在监督信号来自损失降低时有效，难处理多轮交互。
