IMPALA与V-trace

IMPALA: Scalable Distributed Deep-RL with Importance Weighted Actor-Learner Architectures
2018.02论文重要ICML 2018Espeholt, Soyer, Munos, Simonyan, Mnih, Ward, Doron, Firoiu et al. · DeepMind待核对
arXiv ↗ar5iv全文 ↗在交互版中打开（演化树、学习进度）

问题

A3C把采样和学习绑在同一批CPU线程上，吞吐量上不去、用不好GPU；如果让采样者和学习者分开跑，采样用的策略就比正在学的策略旧，产生偏差。

方法

大量actor只负责用旧参数跑环境、把整段轨迹发给中心GPU学习者；学习者用V-trace——一种截断的重要性采样修正——抵消“数据来自旧策略”造成的偏差。

影响

单个智能体达到每秒25万帧的吞吐，在30个3D任务上同时训练一个网络；分布式actor-learner+V-trace成为DeepMind此后大规模RL（AlphaStar、XLand等）的标准底座。

背景

A3C让很多CPU线程各自跑环境、各自算梯度，再异步更新共享参数。这比DQN快，但每个线程都要算梯度，难以利用GPU批量计算；想把规模做大，瓶颈在通信和计算方式上。更早的Gorila分布式DQN把DQN分布式化，但依赖回放和值函数，扩展到更复杂的策略网络时同样笨重。

直觉上的改法是“分工”：成百上千个便宜的actor只跑环境，一个（或几个）GPU学习者专心批量训练。代价是：actor手里的参数总是落后几步，它们收集的数据来自旧策略μ，而学习者要更新的是新策略π。直接当作on-policy数据用（见on-policy与off-policy），梯度是有偏的，规模越大偏得越厉害。

方法

架构。每个actor拿最近一次同步的参数跑n步（如20步），把这段轨迹连同每步动作在μ下的概率发到队列；学习者把很多段轨迹拼成大批量，在GPU上一次前向反向，并把新参数广播回去。actor从不算梯度。

V-trace目标。对状态x_s，价值目标是

v_s = V(x_s) + Σ_{t=s}^{s+n−1} γ^{t−s} (c_s⋯c_{t−1}) δ_t

其中δ_t = ρ_t (r_t + γV(x_{t+1}) − V(x_t))是带权重的TD误差（见时序差分与自举），权重是被截断的重要性比率（见重要性采样）：ρ_t = min(ρ̄, π(a_t|x_t)/μ(a_t|x_t))，c_i = min(c̄, π/μ)。

  • 当数据恰好是on-policy（π=μ）时，所有比率为1，v_s就是普通的n步回报。
  • 截断c̄控制收敛速度和方差，避免比率连乘爆炸，思路来自Retrace离策略修正；截断ρ̄决定收敛到哪个价值函数——介于π和μ之间。

策略梯度用ρ_s ∇log π(a_s|x_s) (r_s + γv_{s+1} − V(x_s))，即带修正的优势（见Actor-Critic与优势函数），再加熵正则。

结果

多机配置下吞吐达每秒25万帧，论文称比单机A3C快30倍以上。DMLab-30（30个3D任务、一个网络同时学）上，平均人类标准化得分：A3C深网络23.8%，IMPALA深网络46.5%，再加基于种群的训练PBT调超参数到49.4%。Atari-57上每个游戏单独训练的深网络IMPALA中位数191.8%，高于A3C的117.9%；但一个网络同时学57个游戏时只有59.7%。

后来的发展

V-trace和actor-learner分离成了DeepMind大规模RL的默认配方：夺旗：种群训练的第一人称多人游戏、AlphaStar、XLand开放式学习都在此基础上训练；同年的Ape-X、R2D2则在值函数一侧做了同样的“采样与学习分离”。后续SEED RL把推理也集中到学习者，进一步提高吞吐。IMPALA论文里的深层残差卷积网络（常称IMPALA CNN）也成了Procgen泛化基准等基准的常用网络。

它建立在什么之上

  • 改进
    策略梯度定理1999 · RL 已核对
    梯度要在当前策略的状态分布上估计，数据只能同策略采集，旧经验无法直接复用。
  • 改进
    广义优势估计GAE2015.06 · RL
    仍是on-policy方法，数据用一次就扔，双足行走要相当于1–2周真实时间的模拟经验。
  • 改进
    Gorila分布式DQN2015.07 · RL
    同样是采样与学习分离的分布式架构，但面向actor-critic、在GPU上批量学习，规模和效率更高。
  • 改进
    A3C2016.02 · RL
    把A3C中“每个线程既采样又算梯度”拆成actor与GPU学习者，解决吞吐和GPU利用率问题，单机即快一个量级。
  • 延续
    Retrace离策略修正2016.06 · RL
    沿用Retrace对重要性比率做截断连乘的思路，把它从Q函数改写为状态价值V，并用于策略梯度。
  • 改进
    ACER2016.11 · RL
    回放中的旧样本偏离当前策略过远时仍会引起不稳定。
  • 使用
    基于种群的训练PBT2017.11 · RL
    在DMLab-30上用基于种群的训练调整超参数，得分从46.5%提到49.4%。
  • 竞争
    Ape-X2018.03 · RL
    几乎同时期的分布式方案：Ape-X走值函数+优先回放路线，IMPALA走策略梯度+离策略修正路线，两者分别成为两类方法的分布式标准。

读懂它需要的概念

Actor-Critic与优势函数 on-policy与off-policy 重要性采样 时序差分与自举 分布式训练：数据并行与模型并行

本篇术语

  • actor / learner　actor只负责与环境交互、产生数据；learner只负责用数据更新网络。两者分开后可以各自扩展到不同数量的机器。
  • 策略滞后　actor使用的参数比learner当前参数旧几次更新，导致数据分布与要学的策略不一致。
  • 人类标准化得分　(智能体得分 − 随机得分)/(人类得分 − 随机得分)，100%表示达到人类水平。

怎么学

先补Actor-Critic与优势函数和重要性采样，读A3C的讲解。然后读原文第3节（架构）和第4节V-trace的定义与两条性质。动手：在CleanRL或TorchBeast里跑IMPALA，把ρ̄、c̄改成很大或很小，观察训练稳定性的变化。
