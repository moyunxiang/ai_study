Browser Use

2024.11系统延伸Browser Use 团队 · Browser Use待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

要让大模型操作网页，需要把浏览器的状态变成模型能读的文字，再把模型的决定变成点击和输入；每个团队都在重复做这一层。

方法

开源库：把浏览器交给任意LLM，模型通过程序控制真实浏览器完成任务。

影响

成为开源浏览器智能体的事实标准之一，被大量项目当作基础组件。

方法

Browser Use是一个开源的浏览器智能体库（Python和TypeScript）：给它一个任务，模型在真实浏览器里完成。按项目现在的说明，它的做法是让模型写Python代码，在一个持续运行的REPL中调用浏览器控制助手和Chrome DevTools协议（CDP）来操作页面，结果再回传给模型，循环到任务完成；官方称这就是整个智能体：模型、REPL和CDP。它可以接任意LLM，本地或在其云服务上运行，MIT许可。

早期版本更偏向把页面元素编号后交给模型选择，具体实现随版本变化较大，这里只依据现在的说明（早期细节未核对）。

后来的发展

它与OmniParser的截图解析、Operator与浏览器智能体的视觉智能体是同一问题的不同解法：Browser Use偏向读页面结构和代码控制。后来浏览器厂商也推出内置智能体，如AI浏览器Comet与Atlas。

局限与后续

  • 网页改版、验证码、登录和反爬会让自动化脆弱，需要人工兜底。
