Codestral代码模型

Codestral
2024.05模型延伸Mistral AI待核对
官方博客 ↗在交互版中打开（演化树、学习进度）

问题

2024年上半年的开放代码模型要么较小（StarCoder2、DeepSeek-Coder等）上下文只有4K–16K，要么需要更高的硬件配置；IDE里的代码补全既要质量高，又要延迟低、能看到较长的项目上下文。

方法

推出Mistral的第一个专用代码模型：22B参数、开放权重，在80多种编程语言上训练，上下文窗口32K，同时支持指令对话和中间填充（FIM）补全，并为IDE插件提供专用的API端点。

影响

以22B的规模在性能—延迟上树立了新的平衡点，在长距离的仓库级补全评测RepoBench上超过当时其他代码模型；它也让Mistral的代码能力进入主流IDE插件生态，此后的Mistral大模型都借鉴了它的代码数据经验。

背景

Code Llama、DeepSeek-Coder和StarCoder2与Stack v2是当时主要的开放代码模型，它们普遍支持中间填充FIM（根据光标前后的代码补全中间部分），但上下文多在4K到16K之间。仓库级补全（RepoBench仓库级补全）需要看到其他文件里的定义，短上下文成为瓶颈。Mistral此前的Mistral 7B和Mixtral 8x7B是通用模型，代码只是其能力的一部分。

方法

模型：22B参数的稠密模型，开放权重，以新的Mistral AI非生产许可证发布：研究与测试可免费使用，商业使用需另行申请许可。

数据：训练数据覆盖80多种编程语言，既包括Python、Java、C、C++、JavaScript、Bash等主流语言，也包括Swift、Fortran等较小众的语言。

能力：支持补全函数、编写测试，以及用中间填充机制补全任意不完整代码；32K的上下文窗口（对比竞品的4K、8K或16K）使它能利用更多项目内容。

接入方式：除了常规API，还提供专用端点codestral.mistral.ai，面向IDE插件中的指令和FIM调用，按个人API密钥管理，测试期免费8周。

评测：Python上用HumanEval pass@1、MBPP（sanitised）pass@1、CRUXEval输出预测、RepoBench完全匹配；SQL用Spider；另在C++、Bash、Java、PHP、TypeScript、C#六种语言上测HumanEval；FIM用Python、JavaScript、Java的HumanEval填空版，与DeepSeek Coder 33B比较。

结果

官方称，作为22B模型，Codestral在代码生成的性能—延迟空间上树立了新标准；凭借32K上下文，在仓库级长距离补全评测RepoBench上超过所有其他被比较的模型。各基准的具体分数见博客中的图表，此处不逐项引用。

后来的发展

Mistral随后发布了基于Mamba的Codestral Mamba、后续版本的Codestral以及面向智能体编码的Devstral，并把代码能力并入Mistral Large 2等通用模型；Codestral也被Continue、Tabnine等IDE插件集成。

本篇术语

  • 中间填充（FIM）　给出光标前和光标后的代码，让模型生成中间缺的部分；IDE补全最常用的方式。
  • 仓库级补全　补全时需要参考同一项目中其他文件里的函数和类定义，上下文越长越有利。

怎么学

先读中间填充FIM和Code Llama；读官方博客的评测部分；动手：用开放权重的Codestral在一个多文件项目里做FIM补全，比较只给当前文件与附上相关文件两种上下文的效果。
