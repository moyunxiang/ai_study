并行智能体团队

Building a C compiler with parallel Claudes
2026.02思想延伸Nicholas Carlini · Anthropic Safeguards团队待核对
Anthropic ↗在交互版中打开（演化树、学习进度）

问题

单个智能体一次只能做一件事，规模一大就慢；且做完一块就停下来等人，没法长时间自主推进。

方法

同时跑多个Claude实例在共享代码库上并行工作，靠测试和文件锁协调，不需要人时时介入。

影响

用约2000次会话、2万美元API费用，让16个智能体从零写出可编译Linux内核的C编译器，给出并行智能体的成本、做法与天花板。

方法

Anthropic在2026年2月5日发文，作者称这种监督方式为“agent teams”。底层仍是Ralph循环式的无限循环：一个任务做完立刻领下一个。并行靠一套极简的协议：建一个裸git仓库，每个智能体一个Docker容器，各自克隆工作副本，做完推回上游；为避免两个智能体同时做同一件事，智能体通过往current_tasks目录写一个文本文件来“加锁”，冲突时git的同步机制迫使后来者换任务；合并冲突频繁，但Claude能自己解决。

文章给出的结果：16个智能体，将近2000次Claude Code会话，2万美元API费用，产出10万行的Rust编译器，可在x86、ARM和RISC-V上构建Linux 6.9。作者的重点是如何设计让智能体不跑偏的测试，以及这种做法的上限。这些数字来自作者自述。

局限与后续

  • 没有人监督时，质量完全靠测试套件兜底，测试写得不好智能体就会朝错误方向勤奋地工作。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 成本高（本例约2万美元），且任务必须能拆成互不依赖的块，耦合紧的任务难以并行。
    本站还没有记录针对它的后续工作（不代表没有人解决）
