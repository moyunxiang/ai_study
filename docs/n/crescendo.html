Crescendo多轮越狱

Great, Now Write an Article About That: The Crescendo Multi-Turn LLM Jailbreak Attack
2024.04论文延伸Mark Russinovich, Ahmed Salem, Ronen Eldan · Microsoft待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

已有越狱多是单轮：一次塞入精心构造的提示或乱码后缀，容易被输入过滤识别。

方法

多轮渐进：先问无害的相关问题，再引用模型自己的回答一步步升级，直到它写出原本会拒绝的内容。

影响

让多轮越狱成为红队和防御评测的标准项目，说明只看单条输入的防御不够。

方法

名字取自音乐的“渐强”。攻击者不直接提出有害请求，而是先问一个一般性问题（比如某样东西的历史），再说“就你刚才提到的写篇文章”，每一轮都借模型已经说过的话往前推一点。每一步单看都不明显越界，模型又倾向于与自己先前的输出保持一致，最终会产出原本拒绝的内容。

作者在ChatGPT、Gemini Pro与Ultra、Llama-2 70B、Llama-3 70B Chat和Anthropic的聊天模型上测试，各任务都有很高的成功率。他们还做了自动化工具Crescendomation：用一个攻击模型带反馈和回退地推进对话。在AdvBench子集上，它比其他越狱方法在GPT-4上的成功率高29–61%，在Gemini-Pro上高49–71%，也能越狱多模态模型。

与它同月发表的多样本越狱在单条长提示里伪造大量对话，Crescendo则是真实的多轮交互，两者都利用了长上下文中模型会顺着前文走的倾向。

局限与后续

  • 防御需要审视整段对话而非单条输入，论文没有给出有效的防御方案。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 延续
    DAN越狱提示2022.12 · 安全·可解释
    从单条角色扮演提示推进到跨多轮逐步升级的越狱。
  • 竞争
    自动化越狱攻击GCG2023.07 · 安全·可解释
    GCG优化不可读的后缀，Crescendo只用自然、看似无害的对话。
  • 竞争
    PAIR黑盒越狱2023.10 · 安全·可解释
    PAIR用攻击模型迭代改写单条提示，Crescendomation用攻击模型推进多轮对话。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。
