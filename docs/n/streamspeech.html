StreamSpeech同声翻译

StreamSpeech: Simultaneous Speech-to-Speech Translation with Multi-task Learning
2024.06论文延伸ACL 2024Shaolei Zhang, Qingkai Fang, Shoutao Guo, Zhengrui Ma, Min Zhang, Yang Feng · 中国科学院计算技术研究所待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

同声传译式的语音到语音翻译要一边听一边说，不仅要翻得对，还要有一个「策略」决定何时开口；以往系统要么只做离线翻译，要么把识别、翻译、合成和读写策略拼成复杂级联。

方法

在一个两遍式直接语音翻译模型里，用多任务学习同时训练识别和翻译的CTC辅助任务，让模型从CTC的对齐中自己判断「已经听够了，可以输出这部分译文了」。

影响

StreamSpeech是开源的端到端同声语音翻译代表工作之一，在CVSS基准上同时刷新离线和同声两种设定的结果，并能在翻译过程中给出识别和文字翻译的中间结果；常被后续同传系统作为基线。

方法

直接语音到语音翻译的两遍式模型（UnitY两段式语音翻译）先生成目标语言文字，再生成目标语音的离散单元（见离散单元语音翻译S2UT）。要把它改成同声传译，需要一个读写策略：每接收一段源语音，决定是继续「读」（听）还是「写」（输出译文）。传统做法是固定等待k个词（wait-k）或另训一个策略模块。

StreamSpeech把策略学习融进多任务学习：分块的流式编码器处理源语音，在上面接两个CTC解码器，分别做源语言识别和目标语言文字翻译。CTC的输出天然带有对齐信息——它会告诉你目前听到的语音已经对应了多少个源词、多少个目标词。推理时，当CTC预测的目标词数增加，模型就输出相应的文字翻译，再经过非自回归的文本到单元模块生成语音单元，最后由单元声码器合成语音。这样一个模型同时完成离线/同声的识别、语音到文字翻译和语音到语音翻译，所谓All-in-One。

摘要称，在CVSS基准上StreamSpeech在离线和同声语音到语音翻译两项任务上都达到当时最好的水平，同时能在同传过程中给出高质量的中间结果（识别或翻译文字）。

它建立在什么之上

  • 使用
    CTC2006 · 语音
    用识别和翻译两个CTC解码器的对齐结果来决定何时输出译文。
  • 改进
    SimulST同声语音翻译2020.11 · 语音
    只输出文字译文，没有直接生成译语语音；同声语音到语音翻译要等后续工作。
  • 使用
    离散单元语音翻译S2UT2021.07 · 语音
    目标语音以离散单元表示，再由单元声码器合成。
  • 延续
    UnitY两段式语音翻译2022.12 · 语音
    沿用UnitY的两遍式结构（先文字后语音单元），把它改造为可流式的同声翻译模型。
  • 改进
    PolyVoice语言模型语音翻译2023.06 · 语音
    两个语言模型串联，延迟较高，不能做同声传译。
  • 竞争
    Seamless流式表现力翻译2023.12 · 语音
    SeamlessStreaming用专门训练的单调注意力策略做流式翻译；StreamSpeech把策略并入多任务学习，模型更小、完全开源。
