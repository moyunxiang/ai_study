Lean证明助手

2013系统重要2013年发布；Lean 3于2017年、Lean 4于2021年发布Leonardo de Moura 主导，后有Sebastian Ullrich等 · Microsoft Research（后为Amazon Web Services与Lean FRO）待核对
维基百科：Lean ↗Lean官网 ↗在交互版中打开（演化树、学习进度）

问题

已有的证明助手（Coq、Isabelle等）要么学习曲线陡峭，要么不便扩展自动化；数学家与程序员都想要一个既能写形式证明、又能当通用编程语言的工具。

方法

基于带归纳类型的构造演算，设计一种既是证明助手又是函数式编程语言的系统，并让它的自动化（策略、宏）本身也用Lean写，使用户能扩展系统。

影响

成为当前形式数学和AI定理证明最主流的平台：Lean数学库mathlib、GPT-f之后的几乎所有AI证明系统（如LeanDojo、AlphaProof达到IMO银牌）都以它为环境。

背景

证明助手让用户用形式语言写出定理和证明，由一个很小的“内核”逐步检验，保证没有逻辑漏洞。早期的成功如四色定理形式化证明，使用的是Coq。但这些系统对普通数学家不友好，自动化弱，写一个简单引理也常需要大量手工步骤。Lean的目标是兼顾两端：理论基础稳固（依赖类型论），同时对用户友好，并能让自动化被灵活定制。

方法

基础：据维基百科，Lean基于带归纳类型的构造演算（与Coq相同的基础类型论），是严格、纯函数式、依赖类型的语言。

版本演进：2013年发布，早期的Lean 1和2是实验性的，包含基于同伦类型论的功能，后来被放弃。Lean 3于2017年1月发布，是第一个比较稳定的版本，主要用C++实现。2021年发布的Lean 4是一次重新实现，能生成C代码再编译，使高效的领域特定自动化成为可能；其前端等关键部分由Lean自身实现，用户无需改C++就能修改；它还带有卫生宏系统，以及改进的类型类解析和内存管理。Lean 4与Lean 3不向后兼容。

使用方式：用户用策略语言一步步把目标化为子目标，直到全部被内核接受；也可以写成项（term）。因为语言本身又是编程语言，同一个系统里可以写算法并证明它的正确性。

机构：2023年成立非营利的Lean FRO，目标是提高可扩展性和易用性，并实现证明自动化。

结果

据维基百科，2025年Lean的四位开发者获得了ACM SIGPLAN编程语言软件奖，嘉奖词称其对数学、硬件与软件验证以及AI有重大影响。具体的使用规模（如定理数量、用户数）本次没有在一手资料核对，所以不引用。

后来的发展

Lean的两个特点使它成为AI研究的天然平台：（1）验证是确定性的，对或错由内核判定，可以用作强化学习的奖励；（2）有Lean数学库mathlib这样的大规模数学库提供数据和目标。因此，从GPT-f之后的语言模型证明器，到2024年的AlphaProof达到IMO银牌在国际数学奥林匹克竞赛题上达到银牌水平，都以Lean为工作环境。

容易误解的地方

  • Lean证明助手本身不是AI，它只检验证明；AI系统是在它之上生成证明候选。
  • 形式化的陈述是否忠实于数学家想表达的命题，需要人检查；内核只保证“证明对于这个陈述是对的”。

局限与后续

  • 把一个数学陈述正确地写成形式语言本身就费时费力，也是AI形式化系统的瓶颈（“自动形式化”）。
    后来针对它的工作　Draft-Sketch-Prove AlphaProof达到IMO银牌
  • 证明助手的自动化依然有限，许多对人来说显然的步骤在Lean里要手写，使得形式化论文的代价很高。
    后来针对它的工作　LeanDojo DeepSeek-Prover Seed-Prover
  • Lean 3到Lean 4不向后兼容，已有库和工具要整体迁移，造成社区一段时间的割裂。

读懂它需要的概念

命题逻辑、谓词逻辑与符号推理 图、树与搜索

本篇术语

  • 依赖类型　类型可以依赖具体的值，例如“长度为n的列表”是一个依赖于n的类型；它使命题和证明可以用类型和程序来表达。
  • 策略（tactic）　对当前证明目标施加的一条命令，如rewrite、simp，把目标改写成更简单的子目标。

怎么学

先玩Lean的入门教程“Natural Number Game”。读Lean官方文档的Theorem Proving in Lean 4。动手：在Lean 4里证明自然数加法交换律，再用mathlib证明一个简单的不等式。
