TFX生产机器学习平台

TFX: A TensorFlow-Based Production-Scale Machine Learning Platform
2017.08论文延伸KDD 2017Denis Baylor, Eric Breck, Heng-Tze Cheng, Noah Fiedel, Chuan Yu Foo, Zakaria Haque, Salem Haykal, Mustafa Ispir et al. · Google待核对
ACM ↗官网 ↗在交互版中打开（演化树、学习进度）

问题

生产中的机器学习远不止训练：每个团队都要自己拼数据接入、数据校验、特征变换、训练、评估、上线的流程，重复造轮子，数据出错还会悄悄把模型带坏。

方法

把这些步骤做成一套共享的、可组合的组件，以TensorFlow为核心，加上数据分析与验证、模型评估与验证、上线服务，形成一个端到端的生产机器学习平台。

影响

把“机器学习系统的技术债”从问题陈述推进到平台实践，数据验证、模型验证、训练与服务一致性等做法成为MLOps的标准环节；Kubeflow Pipelines等后来的平台都有类似组件划分。

方法

机器学习系统的技术债指出机器学习代码只是系统里很小的一块，周围的数据收集、特征处理、配置、监控才是大头。TFX是谷歌给出的平台化回答，论文发表于KDD 2017，作者二十余人均来自谷歌。

平台由一组组件串成流水线：数据接入后先做数据分析与验证——自动推断数据的模式（每个特征的类型、取值范围、是否允许缺失），新一批数据违反模式时报警，防止上游数据出错静悄悄地污染模型；然后是特征变换，训练用TensorFlow；训练后做模型评估与验证，新模型在关键指标和数据切片上不比旧模型差才允许上线；最后交给TensorFlow Serving提供在线推理，同时保证训练和服务用的是同一套特征变换代码，避免两边不一致。各组件共享配置与元数据，支持持续训练（新数据到来时从上次的状态热启动）。

论文报告了在Google Play应用商店上的部署经验，后来各组件以TensorFlow Data Validation、TensorFlow Transform、TensorFlow Model Analysis等名字开源。

局限与后续
