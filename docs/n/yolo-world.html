YOLO-World

YOLO-World: Real-Time Open-Vocabulary Object Detection
2024.01论文延伸CVPR 2024Tianheng Cheng, Lin Song, Yixiao Ge, Wenyu Liu, Xinggang Wang, Ying Shan · 华中科技大学 / 腾讯ARC实验室待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

YOLO只能检测训练时预设的类别；而OWL-ViT、GLIP等开放词表检测器依赖重型模型，速度慢。

方法

在YOLO上加入视觉-语言建模：用可重参数化的视觉-语言路径聚合网络RepVL-PAN融合文本和图像，并用区域-文本对比损失预训练。

影响

把开放词表检测带进实时场景，提出「先提示后检测」的使用方式。

方法

Ultralytics YOLO系列式检测器的分类头是固定类别。YOLO-World把类别换成文字：用CLIP的文本编码器把类别名或短语编码成向量，检测头输出的区域特征与这些文本向量做相似度，类别就可随时更换。

两个关键设计：一是RepVL-PAN，在YOLO的特征金字塔融合中加入文本引导的分支，让图像特征和文本特征相互作用，部署时可以把文本部分重参数化进权重，不增加推理开销；二是区域-文本对比损失，在大规模检测、定位和图文数据上预训练。

摘要称，在LVIS上零样本达到35.4 AP，V100上52.0 FPS，兼顾精度和速度，微调后在下游检测和开放词表实例分割上也表现突出。

局限与后续

  • 文本与视觉的交互主要在特征融合层，对长句、复杂属性描述的理解不如大型视觉语言模型。

  • 在与预训练分布差别大的真实数据集上，开放词表能力仍会退化，需要针对目标域微调。

它建立在什么之上

  • 使用
    CLIP2021.01 · 多模态
    用CLIP文本编码器把类别名编码成向量。
  • 改进
    Grounding DINO2023.03 · 多模态
    Swin-L骨干加多层跨模态注意力，推理慢，难以实时运行。
  • 延续
    Ultralytics YOLO系列2020.06 · 视觉
    在YOLO骨架上加入文本分支，把固定类别头换成可输入文字的检测。
  • 改进
    ViLD开放词表检测2021.04 · 视觉
    依赖两阶段检测器和先裁剪区域再送老师的过程，推理和训练都较慢。
  • 竞争
    GLIP2021.12 · 多模态
    同样把检测与语言对齐，区别是GLIP追求精度、模型重，YOLO-World追求实时。
  • 改进
    OWL-ViT2022.05 · 视觉
    检测阶段的框标注数据规模仍远小于图文对，罕见类别上的定位精度明显落后于常见类别。
  • 改进
    YOLOv10免NMS2024.05 · 视觉
    只做封闭类别检测，不能按文字描述检测新类别。
