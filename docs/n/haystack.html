Haystack检索问答框架

2019.11系统延伸deepset待核对
GitHub ↗官网 ↗在交互版中打开（演化树、学习进度）

问题

在大模型之前，要做一个“在自己的文档库里检索并回答问题”的系统，需要把文档解析、检索器、阅读理解模型串起来，每个团队都在重复造轮子。

方法

开源一个用可组合“管线”搭建检索问答系统的Python框架：文档存储、检索器、阅读器或生成器都是可替换的组件，按图连接起来即可。

影响

是最早一批开源的神经检索问答框架之一，从BERT时代的抽取式问答一路演进为RAG和智能体编排框架，至今仍是主流的生产级RAG框架之一。

方法

Haystack由德国公司deepset开发，GitHub仓库创建于2019-11。早期版本围绕“检索器—阅读器”的问答流水线：先用BM25或稠密检索DPR这类检索器从Elasticsearch等文档库里找出相关段落，再用在SQuAD上微调的BERT类抽取式模型从段落中圈出答案，结构上沿袭DrQA开放域问答。

大模型出现后，它把“阅读器”换成生成式大模型，成为构建检索增强生成RAG系统的框架。2024年的Haystack 2.0重写了架构，核心是管线：

  • 每个组件声明自己的输入输出（如文档转换器、切块器、嵌入器、检索器、提示构造器、生成器）；
  • 组件按有向图连接，可以有分支、循环和路由，便于实现查询改写、混合检索、自我纠错等流程；
  • 在此之上支持带工具调用的智能体工作流。

README强调对检索、路由、记忆和生成的“显式控制”，以及透明、可审计的流程，这是它与追求快速原型的LangChain在设计取向上的主要区别。

局限与后续

  • 管线需要显式定义每个组件和连接，搭复杂流程时代码量和配置较多，快速试验不如更高层的框架方便。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 框架只负责编排，检索质量、切块策略、生成是否忠于文档等核心问题仍取决于所选模型和参数。

  • 使用
    BM251994 · NLP

  • 使用
    SQuAD2016.06 · 数据·评测
    早期阅读器多是在SQuAD上微调的抽取式问答模型。
  • 延续
    DrQA开放域问答2017.03 · NLP
    沿用DrQA“先检索段落、再阅读理解”的开放域问答结构，并做成可替换组件的通用框架。
