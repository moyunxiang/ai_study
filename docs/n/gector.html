GECToR标注式语法纠错

GECToR -- Grammatical Error Correction: Tag, Not Rewrite
2020.05论文延伸BEA Workshop 2020Kostiantyn Omelianchuk, Vitaliy Atrasevych, Artem Chernodub, Oleksandr Skurzhanskyi · Grammarly待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

语法纠错（GEC）主流做法是把它当成「错句→正句」的机器翻译，用Transformer编码器-解码器逐词重写整句，推理慢，而且大部分词其实不需要改。

方法

不重写，而是给每个词打一个编辑标签：保留、删除、在后面插入某词、替换为某词，或做名词单复数、动词时态之类的「语法变换」。用预训练Transformer编码器做序列标注，反复标注几轮直到不再修改。

影响

在当时的标准测试集上达到最好或接近最好的F0.5，推理比seq2seq纠错系统快到10倍；「标注式纠错」成为工业纠错系统常用的路线之一。

背景

语法纠错的标准评测是CoNLL-2014共享任务和BEA-2019共享任务，指标是更看重精确率的F0.5。2018年以后最好的系统都是神经机器翻译式的Seq2Seq：把带错的句子「翻译」成正确的句子，并用回译式的人造错句数据预训练。问题在于纠错时九成以上的词应原样保留，逐词生成既浪费又容易改出新错误，解码速度也满足不了实时写作助手的需要。

方法

编辑标签。 作者为每个源token定义一个目标操作：$KEEP、$DELETE、$APPEND_w（在后面加词w）、$REPLACE_w（换成w），以及约30种针对英语的g变换，如改大小写、合并两个词、名词单复数转换、动词形式转换（$VERB_FORM_VB_VBZ 把原形变第三人称单数）。训练前把（错句，正句）对齐，自动推出每个词的标签，常见词表约5000个标签。

模型。 一个预训练编码器（BERT、RoBERTa或XLNet）加两个线性头：一个预测编辑标签，一个判断整句是否有错。

迭代纠正。 一次标注只做局部修改，所以把修改后的句子再送回模型，最多几轮，直到预测全是 $KEEP。推理时还加了两个超参数：给 $KEEP 的置信度加偏置、句级错误概率低于阈值就不改，用来在精确率和召回率之间调节。

训练分三阶段：先在900万对人造错句上预训练，再在真实学习者语料上微调，最后在少量高质量（含无错句）数据上微调。

结果

摘要报告：最好的单模型/集成在CoNLL-2014测试集上F0.5为65.3/66.5，在BEA-2019测试集上为72.4/73.6；推理速度最高可达基于Transformer的seq2seq纠错系统的10倍。

后来的发展

GECToR之后，标注式与生成式纠错长期并存：工业界看重它的速度和可解释的编辑操作，学术界在其上改进标签集、多语言化。大语言模型出现后，直接提示LLM改写成了新的强基线，但LLM倾向于过度改写、F0.5偏低，标注式方法仍常用于需要「最小改动」的场景。

  • 使用
    回译2015.11 · NLP
    预训练阶段使用人工合成的错句-正句对，与回译造数据的思路一致。
  • 使用
    RoBERTa2019.07 · LLM
    用RoBERTa、BERT、XLNet等预训练编码器做序列标注骨干，其中RoBERTa与XLNet效果最好。

    BiLSTM-CRF序列标注2015.08 · NLP
    把语法纠错改写成逐词序列标注问题，沿用序列标注的建模方式。

读懂它需要的概念

预训练与微调 Transformer层的结构 Softmax与logits 准确率、精确率、召回率与F1 数据增强

本篇术语

  • 语法纠错（GEC）　自动找出并改正句子中的语法、拼写、搭配等错误，输出修改后的句子。常用CoNLL-2014和BEA-2019评测。
  • F0.5　F值的一种，β=0.5时精确率的权重是召回率的两倍；纠错中「改错了」比「漏改」更伤害用户，所以偏重精确率。

怎么学

先了解序列标注和Seq2Seq → 读原文第3节标签设计和第4节三阶段训练 → 动手：用开源GECToR模型纠正几句带错的英文，观察每一轮迭代给出的编辑标签。
