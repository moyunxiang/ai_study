云端异步编码智能体

Introducing Codex
2025.05系统重要OpenAI待核对
官方公告 ↗在交互版中打开（演化树、学习进度）

问题

终端里的编码智能体需要人守在旁边逐步确认，一次只能做一件事；把任务交出去后人还得等它在自己电脑上跑完。

方法

把智能体搬到云端：每个任务在一个预装好代码仓库的隔离容器里独立运行，可同时派出多个，完成后附带终端日志和测试结果作为证据，人像审同事的PR一样审结果。

影响

确立了“异步委派、并行执行、审阅合并”的编码智能体工作方式，同月Google和GitHub也推出了异步编码智能体；配套的AGENTS.md后来成为跨厂商的项目说明标准。

背景

2025年2月的Claude Code与终端编码智能体和4月的Codex CLI把智能体放进开发者的终端，它们与人“结对”工作：人看着它改、随时批准或打断。这种方式交互性好，但人的注意力成了瓶颈。更早的Devin在2024年就提出了在云端独立完成任务的“AI软件工程师”，但实际效果争议很大。研究上，SWE-agent已证明在受控环境里给模型合适的命令接口，它就能独立修复真实仓库的问题。

方法

2025年5月16日，OpenAI以研究预览发布ChatGPT中的Codex。

模型：codex-1，官方称是为软件工程优化的o3版本，在多种环境的真实编码任务上用强化学习训练，目标是生成贴近人类风格和PR习惯的代码、严格遵循指令，并反复运行测试直到通过。

执行方式：用户在ChatGPT侧边栏输入任务点“Code”（或点“Ask”提问）。每个任务在独立的云端容器中处理，容器预装用户的仓库，智能体可以读写文件、运行测试、linter和类型检查器，通常耗时1到30分钟。完成后它在容器内提交修改，并在报告中引用终端日志和测试输出作为证据；用户审阅后可要求修改、开GitHub PR或拉到本地。

安全设计：首发配置下，任务执行期间禁止联网，智能体只能接触用户的仓库和设置脚本预装的依赖。

AGENTS.md：仓库中类似README的文本文件，告诉智能体如何浏览代码、用哪些命令测试、遵守哪些项目规范；codex-1的系统提示规定要运行AGENTS.md里提到的全部测试。

同时发布的codex-mini是o4-mini的变体，作为Codex CLI的默认模型。

结果

官方称codex-1在编码评测和内部基准上即使没有AGENTS.md也表现很强，且比o3产生更干净、可直接审阅的补丁（SWE-bench Verified测试排除了23个在内部基础设施上无法运行的样本）。OpenAI工程师主要用它处理重构、重命名、写测试等边界清楚的重复任务；官方建议同时给多个智能体分配范围明确的任务。官方承认的局限：不能输入图片、执行中途无法纠正方向、远程委派比交互编辑耗时更长。

后来的发展

云端异步编码智能体在2025年5月迅速成为一个品类，Google的Jules、GitHub Copilot的编码智能体在同月发布。OpenAI随后把Codex的云端、CLI、IDE扩展合并成一个产品，推出长时程模型并引入上下文压缩（Codex-Max与上下文压缩），2026年的Codex app多智能体指挥台把它做成同时指挥多个智能体的桌面应用。AGENTS.md在2025年8月成为多家工具共同支持的格式，并于12月随智能体AI基金会AAIF移交Linux基金会。

读懂它需要的概念

智能体循环 工具调用 推理token与测试时计算 策略梯度

本篇术语

  • 异步委派　把任务交给智能体后人去做别的事，智能体完成后再回来审阅结果，而不是实时盯着它操作。
  • AGENTS.md　放在代码仓库里给智能体看的说明文件：怎么构建、怎么测试、有哪些约定。与给人看的README互补。
  • GPT-5-Codex　2025年9月15日发布的GPT-5变体，专门针对Codex里的智能体编码（搭项目、调试、大规模重构、代码审查）训练，会按任务复杂度自动调整思考时长；成为云端任务和代码审查的默认模型，9月23日起也可通过Responses API调用。

怎么学

先读SWE-agent和Claude Code与终端编码智能体理解本地编码智能体，再读官方公告的How Codex works和附录里的系统提示，看它如何规定提交方式和AGENTS.md。动手：为自己的项目写一份AGENTS.md，分别交给本地和云端编码智能体同一个小任务，比较交互方式和结果。
