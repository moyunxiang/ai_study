深度混合MoD

Mixture-of-Depths: Dynamically allocating compute in transformer-based language models
2024.04论文延伸David Raposo, Sam Ritter, Blake Richards, Timothy Lillicrap, Peter Conway Humphreys, Adam Santoro · Google DeepMind / McGill大学 / Mila待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

Transformer给每个token分配完全相同的计算量，可“的”“了”这样的词和关键推理步骤显然不需要一样多的算力。

方法

每一层用一个路由器只挑出top-k个token走注意力和MLP，其余token经残差直接跳过这一层；k事先固定，计算图是静态的。

影响

把MoE“按token路由”的思想从宽度搬到深度，成为后来递归混合MoR、零计算专家等“自适应计算”设计的直接参照。

方法

稀疏MoE大模型这类MoE让每个token只用一部分专家，节省的是“宽度”上的计算；Universal Transformer等自适应计算时间的方法想让不同token计算不同层数，但计算量不可预测、难以高效实现。

MoD的做法：在某些层前放一个打分路由器，序列里得分最高的k个token进入这一层的自注意力和MLP，其余token什么都不做、沿残差连接直接传到下一层。因为k是预先定好的（论文发现每隔一层放一个、容量只取12.5%的设置最好），每层张量形状固定，可以用静态计算图高效实现；但哪些token被选中是由内容决定的，所以计算在token和深度两个维度上都是动态分配的。

论文报告：在同等训练FLOPs和训练时间下，MoD模型能追平基线性能，而每次前向只需一部分FLOPs，采样时每步可以快50%以上。top-k选择在自回归采样时会用到未来token的信息，作者用一个辅助损失或一个小MLP预测器（预测某个token是否会进入top-k，准确率97%以上）来解决这个因果性问题，评测时性能损失很小。

局限与后续

  • top-k路由在训练时依赖整段序列，自回归推理时需要额外的预测器近似，增加了实现复杂度。
    后来针对它的工作　递归混合MoR
  • 只在较小规模上验证，与MoE、KV缓存和大规模推理框架怎样结合没有给出成熟方案。
    后来针对它的工作　美团LongCat-Flash

它建立在什么之上

  • 使用
    稀疏门控MoE层2017.01 · LLM
    沿用稀疏门控的top-k路由机制。
  • 改进
    Universal Transformer2018.07 · LLM
    自适应计算时间计算量不可预测；MoD用固定容量的top-k路由让总计算量可预测。
  • 延续
    稀疏MoE大模型2021.01 · LLM
    把MoE式的按token路由从选专家改成选“算不算这一层”。

后来的相关工作

  • 改进
    递归混合MoR2025.07 · LLM
    把MoD的按token跳层推广为按token决定递归次数，并据此只缓存活跃token的KV。
  • 延续
    美团LongCat-Flash2025.09 · LLM
    与MoD让token跳层的思路相通，LongCat把“可以不算”做成MoE里的一类专家。
