蒙特卡洛树搜索UCT

Bandit Based Monte-Carlo Planning
2006论文重要ECML 2006Levente Kocsis, Csaba Szepesvári · 匈牙利科学院计算机与自动化研究所（SZTAKI）待核对
论文PDF ↗Wikipedia：Monte Carlo tree search ↗在交互版中打开（演化树、学习进度）

问题

围棋这类分支数巨大、又写不出好评估函数的博弈，Alpha-Beta搜索几乎无能为力；用随机模拟估值的蒙特卡洛搜索开始在围棋里见效，但它在树中怎么分配模拟次数全靠启发式，没有任何收敛保证。

方法

UCT（UCB applied to Trees）：把搜索树的每个节点都当成一个多臂老虎机，用UCB1决定下一次模拟往哪个子节点走——既偏向目前胜率高的着法，也照顾试得少的着法；模拟到底后把结果沿路径回传更新平均值。

影响

第一个有理论保证的蒙特卡洛树搜索：采样足够多时选错最优动作的概率趋于0。它迅速成为计算机围棋的核心算法，十年后AlphaGo和AlphaZero的搜索部分正是在它的基础上加入神经网络。

背景

香农：计算机下棋以来的棋类程序靠“评估函数 + Alpha-Beta剪枝分析搜索”。这在国际象棋上很成功（深蓝战胜卡斯帕罗夫），在围棋上却失效：19×19的棋盘开局就有361个落点，分支数远大于国际象棋，而且局面好坏很难写成一个评估函数。

另一条路是蒙特卡洛评估：从某局面开始让双方随机落子到终局，重复很多次，用胜率当作这个局面的分数。2006年前后它在围棋上开始有竞争力（Crazy Stone与蒙特卡洛围棋）。剩下的问题是：每次模拟该从哪条分支走下去？均匀分配太浪费，按经验偏向好着法又可能过早放弃真正的好棋——这正是UCB1解决的探索与利用问题，只不过现在每个节点都有一个。

方法

UCT属于基于rollout的蒙特卡洛规划（见博弈树搜索：minimax与MCTS、蒙特卡洛采样）：从根节点反复模拟完整的一局（或截断到一定深度），每次模拟把途经的“状态-动作”的访问次数和平均回报记在树上。一次模拟分几步：

  • 选择：在已建的树中，每个节点按UCB1选子节点：a* = argmax_a [Q(s,a) + 2C_p √(ln N(s) / N(s,a))]，Q是平均回报，N(s)是节点访问次数，N(s,a)是该动作被选次数；
  • 扩展与模拟：走出已建的树后，用随机（或简单）策略一直走到终局；
  • 回传：把这局的结果沿路径加到每个节点的平均值上。

下完足够多次模拟后，根节点选平均回报最高的动作。对双人博弈，在对手节点上取相反符号（negamax形式）。

难点在理论：下层节点的选择在不断变化，上层节点看到的回报序列不再独立同分布，原版UCB1的证明不成立。论文先把UCB1的遗憾界推广到回报“漂移”但收敛的非平稳情形，再按树的深度归纳，得到定理6：在深度为D、回报在[0,1]内的有限时域MDP中，把加成项乘以D后，根节点价值估计的偏差为O(log n / n)，选错最优动作的概率随模拟次数以多项式速度趋于0。

结果

随机博弈树（P-game，200棵树各跑200次）：UCT与Alpha-Beta大约在同样数量的叶节点内收敛到正确着法；若允许少量失误，UCT更快；均匀采样的纯蒙特卡洛则停留在明显的失误率上。所需迭代次数大致按B^{D/2}增长（B为分支数、D为深度），与Alpha-Beta相当。“帆船”随机最短路问题中，达到同样误差UCT所需的模拟次数显著少于ARTDP和PG-ID，因此能解更大的问题。

后来的发展

MoGo把UCT与围棋棋形知识结合，蒙特卡洛树搜索从此主导计算机围棋。AlphaGo用策略网络给出先验、价值网络代替随机模拟，选择公式变为PUCT；AlphaGo Zero、AlphaZero完全去掉了随机模拟；MuZero连规则模型也改为学出来。在大语言模型时代，RAP推理即规划、LATS智能体树搜索等工作又把MCTS用于推理和智能体的规划。

容易误解的地方

  • 常说的“选择、扩展、模拟、回传”四步是后来通用的描述方式；UCT论文的核心贡献是在选择这一步用UCB1并证明一致性。
  • UCT的理论保证是渐近的，实际棋力很大程度取决于模拟策略的质量，这正是后来加入棋形知识和神经网络的原因。

局限与后续

  • 随机模拟下的棋与真实对局差别很大，估值噪声大，围棋里需要海量模拟才能下好。

它建立在什么之上

  • 改进
    香农：计算机下棋1950 · RL
    香农的Type B选择性搜索要靠人工规则决定算哪些变化；UCT用统计置信上界自动把计算集中到有希望的分支。
  • 改进
    TD-Gammon1995 · RL
    只做1–2步浅层搜索，残局仍有技术性错误；学到的评估没有和更深的搜索结合。
  • 使用
    UCB12002 · RL
    树中每个节点的动作选择就是一个UCB1老虎机，论文把其遗憾界推广到回报会漂移的情形。
  • 竞争
    Alpha-Beta剪枝分析1975 · RL
    实验直接对比：在随机博弈树上UCT与Alpha-Beta收敛所需叶节点数相当，但UCT可随时停止、给出近似答案，也不需要评估函数。
  • 改进
    实时动态规划RTDP1995.01 · RL
    仍是表格方法，需要能对每个访问到的状态做完整的期望备份（知道或学会转移概率），状态空间连续或巨大时无法直接用。
  • 改进
    深蓝战胜卡斯帕罗夫1997.05 · RL
    围棋分支因子太大，同样的暴力搜索无法奏效。
  • 改进
    稀疏采样在线规划2002.11 · RL
    每个节点对所有动作均匀采样，树大小随深度指数增长，理论上需要的样本数在实践中大到无法使用。
  • 竞争
    Crazy Stone与蒙特卡洛围棋2006 · RL
    同年Coulom的蒙特卡洛树搜索用启发式规则分配模拟并逐步从平均值过渡到极小极大；UCT给出有理论保证的选择规则，随后被围棋程序普遍采用。

读懂它需要的概念

博弈树搜索：minimax与MCTS 探索与利用 蒙特卡洛采样 马尔可夫决策过程 图、树与搜索

本篇术语

  • rollout（模拟）　从某个状态出发，按某个简单策略一直走到终局或截断深度，用得到的回报作为这个状态价值的一个随机样本。
  • 失误率（failure rate）　论文的评价指标：在给定计算量下停止搜索时，选到的不是最优动作的频率。
  • P-game　一种人工生成的随机极小极大博弈树，叶节点的胜负由路径上随机值之和决定，用来测试搜索算法。

怎么学

先懂UCB1和博弈树搜索：minimax与MCTS里的极小极大。读原文第2节（算法与定理6）和第3.1节实验。动手：用Python为井字棋或四子棋实现UCT（每个节点记访问次数和胜率），对比纯随机模拟和UCT在相同模拟次数下的胜率；再读AlphaGo论文的搜索部分，看PUCT改了哪里。
