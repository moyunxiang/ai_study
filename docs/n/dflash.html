DFlash块扩散草稿

DFlash: Block Diffusion for Flash Speculative Decoding
2026.02论文延伸ICML 2026Jian Chen, Yesheng Liang, Zhijian Liu · 加州大学圣地亚哥分校待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

推测解码的草稿器本身也是逐词自回归生成，草稿越长越慢；扩散语言模型能并行出词，但单独使用时质量不如自回归模型。

方法

只让扩散模型当草稿器：一个小型块扩散模型一次前向就猜出整块16个词，并读取目标模型的中间特征来提高命中率，最后仍由目标模型逐一验证。

影响

官方称在多种模型和任务上无损加速超过6倍，比EAGLE-3高最多2.5倍；是把扩散语言模型用来加速自回归模型的代表做法之一。

方法

推测解码的验证保证输出与目标模型完全一致，所以草稿器可以用任何方法生成，只要猜得准、猜得快。DFlash的草稿器是一个块扩散BD3-LM式的小模型（Qwen3上只有5层）：给定已确认的前文，它把接下来一整块位置都设为掩码，一次前向同时填出这一块的所有词，而不是像EAGLE-3推测解码那样一个一个猜。

为了让小模型猜得准，DFlash从目标模型均匀选取5层的隐藏特征，拼接压缩后注入草稿器每一层的Key和Value里，相当于草稿器直接“看到”目标模型对上下文的理解。草稿器与目标模型共用词嵌入和输出头（冻结），只训练中间几层。

结果

论文表1：Qwen3-8B、关闭思考、温度0时，DFlash平均加速4.86倍、每轮平均接受6.49个词；EAGLE-3（草稿16）为1.76倍、2.96个词。在SGLang中单张B200、并发1时，Qwen3-8B在Math500上吞吐从230升到1175 token/s（5.1倍），并发32时降到2.8倍。

局限与后续

  • 并发升高后加速比明显下降（并发1为5.1倍，并发32为2.8倍），高负载服务中优势收窄。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 每个目标模型要单独训练草稿器，训练依赖目标模型自己生成的约80万条回答。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    推测解码2022.11 · 系统·效率
    沿用推测解码的验证流程，因此输出与目标模型逐词解码一致。
  • 延续
    EAGLE特征级推测解码2024.01 · 系统·效率
    继承EAGLE系列读取目标模型特征的思路，但注入到草稿器每层的KV中而不只是输入。
  • 改进
    EAGLE-3推测解码2025.03 · 系统·效率
    EAGLE-3草稿器仍逐词自回归，DFlash用块扩散一次前向出整块草稿，并作为主要对比基线。
  • 使用
    块扩散BD3-LM2025.03 · LLM
    草稿器采用块扩散的生成方式：块内并行去掩码，块间按顺序推进。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

自回归生成 掩码建模 扩散：前向加噪与反向去噪 KV缓存 吞吐、延迟与批处理

怎么学

先读推测解码、EAGLE-3推测解码和块扩散BD3-LM → 读论文第3节草稿器结构与训练 → 用官方仓库的SGLang示例测不同并发下的加速比。
