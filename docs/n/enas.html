ENAS参数共享架构搜索

Efficient Neural Architecture Search via Parameter Sharing
2018.02论文延伸ICML 2018Hieu Pham, Melody Y. Guan, Barret Zoph, Quoc V. Le, Jeff Dean · Google Brain / 卡内基梅隆大学 / 斯坦福大学待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

神经架构搜索NAS每评估一个候选架构都要从头训练一个子网络，搜索一次要花成百上千个GPU天，只有极少数机构负担得起。

方法

把所有候选架构看成一张大计算图里的子图，让它们共享同一套权重；控制器每次挑一个子图，只训练共享权重，不再从头训练每个子网络。

影响

把架构搜索的成本降低了约三个数量级，“权重共享的一次性超网络”成为随后DARTS可微架构搜索等高效NAS方法的共同基础。

方法

原始的神经架构搜索NAS用一个RNN控制器生成架构描述，每个架构都要训练到收敛才能拿到验证集精度作为强化学习的奖励，这是开销的主要来源。ENAS的做法是先定义一张包含所有可能操作和连接的大有向无环图，任何一个候选架构都是这张图的一个子图。所有子图共享图里的参数。

训练时交替进行两步：一是固定控制器，采样子图，用普通的交叉熵损失训练共享参数；二是固定共享参数，用策略梯度（REINFORCE策略梯度）更新控制器，奖励是所选子图在验证集上的表现。因为子网络不用从头训练，每次评估几乎是免费的。

摘要报告：ENAS比此前所有自动设计模型的方法用的GPU小时都少得多，比标准NAS便宜约1000倍；在Penn Treebank上发现的循环单元取得测试困惑度55.8，是当时不做后处理的方法中最好的；在CIFAR-10上发现的架构测试误差2.89%，与NASNet的2.65%相当。

局限与后续

  • 共享权重下子网络的排名与它们单独训练时的真实排名可能不一致，搜索结果的可靠性受到质疑。

本篇术语

  • 权重共享（超网络）　把所有候选架构嵌在一张大网络里，各架构使用其中对应部分的同一套参数，评估某个架构时直接取出子网络。
