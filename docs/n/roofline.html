Roofline性能模型

Roofline: An Insightful Visual Performance Model for Multicore Architectures
2009.04论文重要Communications of the ACM 52(4)，2009年4月（技术报告UCB/EECS-2008-134，2008年10月）Samuel Williams, Andrew Waterman, David A. Patterson · UC伯克利 Parallel Computing Laboratory待核对
CACM（DOI） ↗伯克利技术报告PDF ↗Wikipedia：Roofline model ↗在交互版中打开（演化树、学习进度）

问题

多核处理器五花八门，程序跑得慢时很难判断是算力不够还是内存带宽不够，也不知道该先做哪种优化。

方法

用一张对数坐标图回答：横轴是每从DRAM读1字节做多少次浮点运算（运算强度），可达性能等于峰值算力与“带宽×运算强度”中较小的那个，图形像一个屋顶。

影响

成为判断程序“卡在计算还是卡在内存”的标准工具。到了大模型时代，它直接解释了为什么逐token生成的推理受限于显存带宽而不是算力。

背景

2005年后处理器转向多核（Dennard缩放终结与并行转向），但多核没有统一的设计套路：有的用少量复杂核心，有的用大量简单核心，IBM Cell甚至用显式管理的本地存储代替缓存。同一个程序在不同芯片上的瓶颈完全不同。更早的内存墙只用平均延迟推算了内存与处理器的差距，回答不了“我这个程序到底卡在哪”。作者认为片外内存带宽常常是最紧的资源，所以模型要把处理器性能和片外内存流量联系起来。

方法

运算强度：每传输1字节DRAM数据所做的浮点运算次数（FLOP/字节），字节按经过缓存过滤后真正到达主存的流量计。

屋顶公式：

可达性能 = min(峰值浮点性能, 峰值内存带宽 × 运算强度)

在对数坐标上，前一项是水平线，后一项是45度斜线，两线交点叫脊点。程序的运算强度落在脊点左边就受限于带宽，右边就受限于算力。

一个AI例子：用FP16权重做矩阵乘向量，每个权重2字节、只做一次乘加（2次运算），运算强度约1 FLOP/字节，远在今天GPU的脊点左边，所以大模型逐个生成token时主要在等显存。一次同时处理B个请求，同一权重被用B次，运算强度约变成B倍——这就是推理要做批处理的原因。

天花板：屋顶下再画几条线，表示不用SIMD、乘加不平衡、不做预取时的上限，它们的顺序提示了优化的顺序。

结果

以双路2.2GHz AMD Opteron X2为例：峰值双精度17.6 GFLOPS，实测带宽15GB/s；乘加不平衡时降到8.8 GFLOPS，不做软件预取时带宽只有11GB/s。四核Opteron X4内存通道不变、峰值算力高四倍多，脊点从1.0右移到4.4，运算强度低于1的程序换新芯片几乎不会变快。作者还在Intel Xeon、Sun T2+和IBM Cell上分析了稀疏矩阵乘向量（运算强度0.17–0.25）、三维FFT（1.09–1.64）等四个内核。

后来的发展

2017年Google TPU论文用Roofline分析线上负载，发现多数受限于内存带宽；2024年的AI与内存墙用它说明解码器Transformer逐词生成落在带宽受限区。FlashAttention用分块减少显存读写、vLLM与PagedAttention等推理系统把多个请求拼批，本质都是提高运算强度。硬件上，HBM高带宽内存抬高了斜线，Tensor Core（V100与Tensor Core）抬高了水平线，使脊点进一步右移，“喂饱算力”更难。

容易误解的地方

  • 屋顶给出的是上界，程序达不到屋顶很正常；它告诉你差距在哪一侧，而不是保证能达到。
  • 运算强度不是程序固定不变的属性：缓存大小、分块方式、批大小都会改变它。同一个矩阵乘，分块做得好坏可以让运算强度相差十几倍。

局限与后续

  • 只考虑一层内存（DRAM）和峰值算力，没有刻画片上多级缓存、延迟以及芯片间互连带宽，对多卡和集群训练的通信瓶颈说明不了问题。

    内存墙1995.03 · 硬件
    内存墙只给出延迟差距的趋势推算；Roofline把带宽和算力放进同一张图，能判断具体程序卡在哪一边。

    Dennard缩放终结与并行转向2005 · 硬件
    并行转向带来了设计各异的多核芯片，正是为了在这些芯片之间做比较和指导优化，作者提出了这个模型。

读懂它需要的概念

显存、内存带宽与“内存墙” 参数量、计算量与显存 矩阵乘法与线性变换 CPU、GPU与并行计算 吞吐、延迟与批处理

本篇术语

  • 运算强度　每从主存搬1字节数据所做的运算次数，单位FLOP/字节。数值越高，越不容易被内存带宽拖住。
  • 脊点　屋顶上斜线与水平线的交点，其横坐标等于峰值算力除以峰值带宽，是跑满这台机器所需的最低运算强度。
  • 天花板（ceiling）　屋顶下方表示缺少某种优化时的性能上限的线，例如不用SIMD指令或不做预取时能达到的最高性能。

怎么学

先读显存、内存带宽与“内存墙”和参数量、计算量与显存。然后读技术报告第3–4节（只有几页）和图1、图2。动手：查一款你能用的GPU的峰值算力和显存带宽，算出脊点；再估算矩阵乘向量和N×N矩阵乘的运算强度，把它们画在同一张对数坐标图上，看看N多大时矩阵乘才进入算力受限区。最后读AI与内存墙，用这张图解释大模型推理为什么要做批处理。
