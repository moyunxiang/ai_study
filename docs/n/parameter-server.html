参数服务器

Scaling Distributed Machine Learning with the Parameter Server
2014.10论文重要OSDI 2014李沐（Mu Li）, David G. Andersen, Jun Woo Park, Alexander J. Smola, Amr Ahmed, Vanja Josifovski, James Long, Eugene J. Shekita, Bor-Yiing Su · 卡内基梅隆大学 / 百度 / Google待核对
OSDI 2014论文PDF ↗在交互版中打开（演化树、学习进度）

问题

工业界的机器学习任务有上千亿样本、上百亿参数，所有机器都要频繁读写共享参数；MapReduce式框架每轮都要全体同步，网络带宽和等待最慢的机器成为瓶颈，机器出故障还会拖垮整个任务。

方法

把参数放在一组服务器节点上，以分片的键值向量形式管理；计算节点按键的范围批量地推（push）梯度、拉（pull）参数，并允许用户在“完全同步”和“完全异步”之间选择一致性模型。

影响

把DistBelief等内部系统里的参数服务器做成通用、开源、可容错的组件；这一架构被MXNet等框架采用，是2014—2017年大规模机器学习的主流范式。

背景

DistBelief与Downpour SGD展示了用参数服务器训练大模型的可行性，但它是Google内部、专为神经网络设计的系统。工业界更多的任务是广告点击预测、主题模型这类稀疏模型：训练数据在1TB到1PB之间，参数在10⁹到10¹²个之间。论文指出共享参数带来三个难题：访问参数需要巨大的网络带宽；很多机器学习算法本质上是串行的，每轮之间的同步屏障会让机器空等；在云环境里机器随时可能故障或被抢占。

基于MapReduce的迭代框架（以及Spark）每轮都要全局同步、靠粗粒度快照恢复故障，这些都阻碍了大规模训练。

方法

系统分成服务器组和工作节点组。服务器保存全局参数，工作节点各自持有一部分训练数据，计算局部梯度。

  • 参数是有序的键值向量：参数看作（特征编号，数值）对，但不是一个键一个键地传，而是按键的范围批量push和pull。对稀疏模型，每个工作节点只需要与自己数据中出现过的特征相关的那部分参数：论文实验中100个工作节点时每个只需全部参数的7.8%，1万个节点时只需0.15%。
  • 灵活的一致性：每次push/pull是一个异步任务，用户可以给任务加依赖。顺序一致＝每轮都等上一轮完成；最终一致＝完全不等；有界延迟＝最多允许落后τ轮。τ是在“机器空等”和“过时参数拖慢收敛”之间的旋钮。
  • 通信压缩：键的集合在训练中不变，收发双方缓存键列表只传值；大量值为0时压缩；用户还可以设过滤器，不发送太小的梯度。
  • 容错：参数用一致性哈希分配到服务器上并在相邻节点复制；用向量时钟（按键范围记录时间戳）保证故障和网络分区后行为明确，论文称可在1秒内恢复非灾难性故障而不打断计算。

结果

在一个1700亿样本、650亿个唯一特征（未压缩636TB）的广告点击预测数据集上，用1000台机器（800台工作节点、200台服务器）训练稀疏逻辑回归。与某大型互联网公司的两个专用系统相比：专用系统的工作节点在同步屏障处空闲32%和53%，参数服务器把空闲降到2%以下，总时间减半；实现同样功能只需约300行代码，而专用系统都超过1万行。有界延迟实验中，τ=0时工作节点空闲50%，τ=16时降到1.7%，但收敛所需的迭代数随τ增加，τ=8是最佳折中。

后来的发展

这篇论文描述的是“第三代”参数服务器，同月的Project Adam也走类似路线。它的push/pull接口被李沐参与创建的MXNet采用，TensorFlow早期的分布式训练也以参数服务器为默认模式。

深度学习转向GPU后，模型变成稠密参数、每步都要同步全部梯度，参数服务器的带宽集中在少数服务器上成了瓶颈，同步的Ring All-Reduce和Horovod逐渐取代它；但在超大规模稀疏的推荐和广告模型（巨大的嵌入表）中，参数服务器架构至今仍在使用。

容易误解的地方

  • 参数服务器不等于异步训练：它同时支持顺序一致（同步）和有界延迟，异步只是可选项。
  • 论文的优势主要体现在稀疏模型上——每个工作节点只碰到一小部分参数；对每步都要更新全部参数的稠密神经网络，收益要小得多。

  • 改进
    DistBelief与Downpour SGD2012.12 · 系统·效率
    把DistBelief里专为神经网络设计的参数服务器，推广成支持多种算法、可配置一致性和容错的通用开源组件。
  • 改进
    MapReduce2004.12 · 系统·效率
    解决迭代式MapReduce每轮全局同步、靠粗粒度快照恢复的问题：用异步任务与有界延迟减少空等，用复制与向量时钟实现细粒度容错。
  • 竞争
    Spark2010.06 · 系统·效率
    Spark等基于迭代map/reduce的框架同样面向大规模机器学习，但同步粒度粗；参数服务器专门针对共享参数的高频读写。
  • 改进
    Hogwild!并行SGD2011 · 系统·效率
    Hogwild!在单机上证明了稀疏问题的无锁异步更新可行；参数服务器把这种放松一致性的思想做到上千台机器。
  • 竞争
    Project Adam2014.10 · 系统·效率
    同期微软的参数服务器式深度学习系统，侧重深度网络；本文侧重通用性、稀疏模型和容错。

读懂它需要的概念

分布式训练：数据并行与模型并行 随机梯度下降与小批量 逻辑回归 正则化与权重衰减 吞吐、延迟与批处理

本篇术语

  • push / pull　工作节点向服务器发送梯度或更新（push），以及从服务器取回最新参数（pull）的两个基本操作。
  • 有界延迟（bounded delay）　一致性模型：允许一个工作节点在落后最慢节点不超过τ轮的情况下继续计算，τ=0即完全同步。
  • 向量时钟　分布式系统中记录每个节点所见事件先后的时间戳机制；本文按参数键的范围记录，节省空间。

怎么学

先读DistBelief与Downpour SGD理解参数服务器的起源，再读本文第3节（push/pull、一致性模型）和第5.1节实验。动手：用Python多进程实现一个有界延迟的参数服务器，训练稀疏逻辑回归，比较τ=0、4、16时的空闲时间与收敛曲线，复现论文图13的趋势。
