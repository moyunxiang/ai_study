Megatron-LM模型并行

Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism
2019.09论文延伸arXiv 2019Mohammad Shoeybi, Mostofa Patwary, Raul Puri 等 · NVIDIA待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

单块GPU放不下数十亿参数的Transformer，已有的模型并行方案需要重写模型或专门编译器。

方法

把每层的矩阵乘按列或按行切到多块GPU上，每个Transformer层只需前向和反向各两次allreduce，几行PyTorch代码即可实现。

影响

层内张量并行成为之后所有大模型训练的标准组件之一。

方法

每个Transformer层有两大块：多头自注意力和前馈网络（MLP）。Megatron把MLP第一个矩阵按列切到几块GPU，各自独立算出激活，第二个矩阵按行切，这样中间不用通信，只在两个矩阵乘之后做一次allreduce求和。注意力则按头分到各GPU，每个头独立计算，再用同样方式处理输出投影。

因此每层前向只有两次通信，反向两次。论文称无需新编译器或重写框架，只需在原生PyTorch里插入几个通信操作。训练的8.3B参数GPT-2式模型用到512块GPU，持续15.1 PetaFLOPs，相对单卡基线（39 TeraFLOPs）扩展效率76%；在WikiText103上困惑度10.8（此前最优15.8），LAMBADA准确率66.5%（此前63.2%）；3.9B的BERT式模型在RACE上90.9%（此前89.4%）。

局限与后续

  • 只切层内，模型更大时通信跨机很贵，需要与流水线、数据并行组合。

  • 每张卡仍要存全部优化器状态，显存冗余。
    后来针对它的工作　ZeRO与DeepSpeed

它建立在什么之上

  • 改进
    CUDA2006.11 · 硬件 待核对
    编程模型只描述一块GPU内部的并行；多卡、多机之间如何切分模型和同步梯度要用户自己解决。
  • 改进
    TensorFlow2015.11 · 系统·效率 待核对
    只做张量级别的切分放置，单个巨型模型如何在数百个设备间自动高效地切分，仍需用户手工设计。
  • 使用
    PyTorch2017.01 · 系统·效率 待核对
    在原生PyTorch中实现，不依赖新编译器。
  • 使用
    GPT-22019.02 · LLM
    用GPT-2结构训练8.3B参数的大模型，并在多项基准上验证。
  • 改进
    GTX 580：AlexNet的显卡2010.11 · 硬件
    显存只有1.5GB或3GB，AlexNet这样的网络都要拆到两块卡上，研究者只能手工决定哪些层在哪块卡上、在哪里交换数据。
  • 改进
    参数服务器2014.10 · 系统·效率
    模型参数仍按完整副本放在每个工作节点上计算，单个模型大到一块设备放不下时无能为力。
  • 改进
    V100与Tensor Core2017.05 · 硬件
    单卡显存只有几十GB，几十亿参数以上的模型放不进一张卡，需要另行发明模型切分方法。
  • 改进
    GPipe流水线并行2018.11 · 系统·效率
    只能按层切分，单层的参数或计算本身超过一个设备时无能为力。
  • 改进
    Ring All-Reduce2017.02 · 系统·效率
    仍是同步数据并行，每张卡必须放得下完整模型，模型变大后不再适用。
  • 改进
    Horovod2018.02 · 系统·效率
    仍是同步数据并行，模型要放得进单卡显存。
  • 竞争
    Mesh-TensorFlow张量切分2018.11 · 系统·效率
    同样做张量切分，Mesh-TensorFlow用声明式语言和TPU网格，Megatron用手写的GPU与PyTorch方案，后者在GPU社区被广泛采用。

读懂它需要的概念

分布式训练：数据并行与模型并行 矩阵乘法与线性变换 Transformer层的结构 互连：从芯片到机柜到集群

怎么学

在纸上把一个两层MLP按列、行切成2份，验证拼起来与原结果一致且只需一次求和。
