CCNet

CCNet: Extracting High Quality Monolingual Datasets from Web Crawl Data
2019.11数据集延伸Wenzek, Lachaux, Conneau, Chaudhary, Guzmán, Joulin, Grave · Facebook AI Research待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

Common Crawl与网络规模文本是免费的海量网页，但夹杂着重复页面、模板文字和低质量内容，直接拿来预训练效果差，各语言也没有现成的干净语料。

方法

建立一条自动流水线：先去重、再用fastText识别语言，最后用一个在维基百科上训练的语言模型给文档打分，只留下接近维基质量的部分。

影响

给出了从原始网页抽取各语言高质量语料的标准配方，后来XLM-R、LLaMA等模型的数据处理都沿用了它的思路。

方法

流水线依次做三件事。第一，按段落去重，去掉网页里反复出现的页眉页脚等模板文字。第二，用fastText的语言识别模型判断每个文档的语言。第三，针对每种语言在维基百科上训练一个语言模型，用困惑度（见困惑度）给每篇文档评分，困惑度低（更像维基百科）的保留，高的丢弃，按分位数把文档分成头、中、尾几档。

这样就能在Common Crawl上批量产出几十种语言的单语语料，且不需要人工标注，成本主要是计算。

局限与后续

  • 质量标准是「像维基百科」，会系统性地偏向正式、百科式文风，丢掉口语、方言和小众话题。
    后来针对它的工作　RefinedWeb FineWeb / FineWeb-Edu
  • 质量判断只靠一个在维基百科上训练的打分模型，论文并未系统比较不同过滤方式对下游模型的影响。
    后来针对它的工作　FineWeb / FineWeb-Edu Dolma开放语料

怎么学

先了解Common Crawl与网络规模文本的数据格式，读原文第3节流水线；用开源的cc_net代码在一小片Common Crawl上跑一遍，看每一步丢掉多少文本。
