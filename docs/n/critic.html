CRITIC借工具自我纠错

CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing
2023.05论文延伸ICLR 2024Zhibin Gou, Zhihong Shao, Yeyun Gong, Yelong Shen, Yujiu Yang, Nan Duan, Weizhu Chen · 清华大学 / 微软待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

模型会编造事实、写出有错的代码；只靠自己回头检查，往往看不出错在哪。人会查搜索引擎、跑一遍代码来核对，模型能否也这样？

方法

先生成初始答案，再调用合适的外部工具（搜索引擎、Python解释器、毒性检测API）检查它，把工具给出的证据写成批评意见，据此修改答案，循环几轮。

影响

不训练、只改提示，就让ChatGPT在三个问答任务上F1平均提高7.7、在三个数学任务上提高7.0个百分点、毒性概率下降79.2%；并指出模型自我验证不可靠，外部反馈才是关键。

方法

CRITIC是一个「验证—修正」循环：

  • 生成：模型照常回答问题或写程序；
  • 验证：根据任务选工具。事实问答时让模型针对答案写搜索查询，用搜索结果判断答案是否有据；数学题让模型写成Python程序，把解释器的报错和运行结果当作反馈；降低有害输出时调用Perspective API拿到毒性分数；
  • 修正：模型读取「原答案 + 工具反馈 + 自己写的批评」，生成修改后的答案；直到工具不再发现问题或到达轮数上限。

整个过程用少样本示例教模型怎么调用工具、怎么写批评，不需要训练。实验覆盖ChatGPT、text-davinci-003和LLaMA-2（7B/13B/70B），在AmbigNQ、TriviaQA、HotpotQA、GSM8K等任务上超过思维链CoT、自洽性采样和不借助工具的自我修正。论文的消融显示，把工具换成模型自己评判时提升大多消失——这一结论后来被自我纠错的局限在推理任务上进一步证实。

局限与后续

  • 要为每类任务人工设计调用哪种工具、怎么把工具输出变成反馈；工具本身出错（搜索结果不准）时也会误导修改。
    本站还没有记录针对它的后续工作（不代表没有人解决）

怎么学

先读Self-Refine自我改进和ReAct → 读原文第3节框架和第4节三类任务的实现 → 动手：给模型10道数学题，先让它直接作答，再让它写成Python并根据运行结果修改，比较正确率。
