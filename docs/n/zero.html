ZeRO与DeepSpeed

ZeRO: Memory Optimizations Toward Training Trillion Parameter Models
2019.10论文延伸SC 2020Samyam Rajbhandari, Jeff Rasley, Olatunji Ruwase, Yuxiong He · Microsoft待核对
arXiv ↗DeepSpeed ↗在交互版中打开（演化树、学习进度）

问题

数据并行里每张卡都保存完整的参数、梯度和优化器状态，大量冗余；模型并行虽省显存，但通信多、扩展差。

方法

ZeRO把优化器状态、梯度、参数依次切分到各数据并行卡上，用时再通信取回，消除冗余，同时保持数据并行的便利。

影响

显著降低每卡显存，使训练百亿级以上模型成为可能，是DeepSpeed与PyTorch FSDP的基础。

方法

以Adam混合精度训练为例，一份参数还需要FP32副本、动量和方差，这些状态加起来比参数本身占更多显存，而数据并行的每张卡都完整存一份。ZeRO分三个阶段：切分优化器状态；再切分梯度；再切分参数本身，每张卡只保留自己负责的一片，计算某层时临时收集其余分片。这样每卡显存随卡数减少，而通信量与普通数据并行大致同量级。

摘要称其分析显示可扩展到超过1万亿参数；实验在400块GPU上训练超过100B参数的模型，吞吐15 petaflops；相对此前可训练模型规模提升8倍、性能提升10倍；不用模型并行也可训练最大13B的模型，超过Megatron-LM模型并行的8.3B和T5的11B；并用它构建了17B的Turing-NLG。

它建立在什么之上

  • 改进
    PyTorch2017.01 · 系统·效率 待核对
    初版只提供基本的多进程与通信原语，模型大到单卡放不下时的模型并行和参数切分需要用户自己实现。
  • 竞争
    参数服务器2014.10 · 系统·效率
    同样想突破单卡容纳极限，参数服务器集中存参数，ZeRO把状态分片到各计算卡。
  • 改进
    V100与Tensor Core2017.05 · 硬件
    单卡显存只有几十GB，几十亿参数以上的模型放不进一张卡，需要另行发明模型切分方法。
  • 改进
    学习率预热与大批量SGD2017.06 · 基础
    依赖256块GPU和高速网络，梯度同步的通信开销随规模上升，需要专门的通信与显存优化。
  • 改进
    GPipe流水线并行2018.11 · 系统·效率
    只能按层切分，单层的参数或计算本身超过一个设备时无能为力。
  • 改进
    Hugging Face Transformers2018.11 · 系统·效率
    为可读性设计的逐模型实现不包含大规模分布式训练所需的切分与显存优化，训练数十亿参数以上的模型要依赖外部工具。
  • 改进
    梯度检查点2016.04 · 系统·效率
    只减少激活内存，参数、梯度与优化器状态的内存仍需另外处理。
  • 改进
    Ring All-Reduce2017.02 · 系统·效率
    仍是同步数据并行，每张卡必须放得下完整模型，模型变大后不再适用。
  • 改进
    Horovod2018.02 · 系统·效率
    仍是同步数据并行，模型要放得进单卡显存。
  • 改进
    Megatron-LM模型并行2019.09 · 系统·效率
    Megatron的张量并行仍让数据并行组内冗余存储，ZeRO用分片消除冗余，可与之组合。

后来的相关工作

  • 使用
    OPT-175B2022.05 · LLM
    全分片数据并行与ZeRO同属把参数和优化器状态切分到所有卡上的做法。
  • 使用
    BLOOM2022.07 · LLM
    用ZeRO第一阶段切分优化器状态，以便在384张卡上放下176B模型的训练状态。
  • 使用
    Hugging Face Accelerate2021.03 · 系统·效率
    以配置方式接入DeepSpeed ZeRO，以及后来的PyTorch FSDP。
  • 竞争
    Megatron 3D并行2021.04 · 系统·效率
    ZeRO靠切分优化器状态省显存，本文靠多维并行省显存，两者后来常被组合使用。
  • 延续
    ZeRO-Infinity异构卸载2021.04 · 系统·效率
    在ZeRO三阶段切分的基础上，把被切分的状态进一步卸载到CPU内存和NVMe。
  • 使用
    MT-NLG 530B2022.01 · LLM
    使用DeepSpeed的ZeRO优化器分片降低内存占用。
  • 延续
    PyTorch FSDP2023.04 · 系统·效率
    把ZeRO的分片思想落成PyTorch原生实现并补上工程细节。
  • 使用
    DeepSpeed-Ulysses序列并行2023.09 · 系统·效率
    作为DeepSpeed的一部分，与ZeRO的参数/优化器状态切分一起使用，以同时支持大模型和长序列。
  • 使用
    FP8-LM八比特训练2023.10 · 系统·效率
    在ZeRO式的切分优化器状态上使用FP8，进一步减少分布式训练的显存与通信。
  • 使用
    OpenRLHF训练框架2024.05 · 系统·效率
    训练阶段用DeepSpeed ZeRO切分大模型的参数、梯度与优化器状态。
