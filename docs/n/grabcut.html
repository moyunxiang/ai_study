GrabCut框选抠图

GrabCut: Interactive Foreground Extraction Using Iterated Graph Cuts
2004.08论文延伸SIGGRAPH 2004（ACM TOG）Carsten Rother, Vladimir Kolmogorov, Andrew Blake · 微软剑桥研究院待核对
维基百科 ↗DOI（重印版） ↗在交互版中打开（演化树、学习进度）

问题

Graph Cuts图割分割式交互分割要求用户在前景和背景上分别涂抹种子，颜色模型只用种子统计一次，复杂图像要来回修改很多次。

方法

用户只需在物体外画一个框：框外一定是背景，框内先当作“可能是前景”；用高斯混合模型描述前景和背景的颜色，交替执行“用当前分割重估颜色模型”和“用图割重新分割”，直到收敛。

影响

把交互式抠图简化到“画一个框”，成为最广为人知的经典分割算法之一，OpenCV从2.1版起内置实现；“框作为提示”的交互方式也延续到了Segment Anything等可提示分割模型。

方法

GrabCut在Graph Cuts图割分割的能量上做了三处扩展：

  • 颜色模型用GMM：前景和背景各用一个含K个分量（论文常用5个）的高斯混合模型描述彩色分布，比灰度直方图更能刻画复杂的颜色。
  • 迭代优化：初始时框外像素标为背景，框内标为“未知”并暂当前景。然后反复执行：①把每个像素分配给对应GMM中最可能的那个高斯分量；②用分配结果重新估计GMM参数；③用图割求解新的前景/背景分割。这个过程类似EM算法算法，每一步都使能量不增，因此会收敛。
  • 不完全标注与边界抠图：用户只需给出框，必要时再补几笔修正误分的区域；分割完成后再对边缘做一道“边界抠图”，估计半透明的过渡带，使头发等细边缘更自然。

维基百科概括为：从用户指定的边界框开始，用GMM估计目标与背景的颜色分布，以此构造像素标签上的马尔可夫随机场，用图割优化，再重复这两步直到收敛；用户可以指出误分区域后重新优化。

局限与后续

  • 只依赖颜色和局部边缘，前景与背景颜色相近时（如迷彩、阴影）会分错。
    后来针对它的工作　Segment Anything
  • 每张图都要用户画框并迭代优化，无法自动识别物体类别。
    后来针对它的工作　Mask R-CNN

读懂它需要的概念

高斯分布 EM算法 图、树与搜索 图像作为张量

本篇术语

  • 高斯混合模型（GMM）　用若干个高斯分布加权相加来描述一个复杂的概率分布，这里用来描述前景或背景的颜色。
  • 马尔可夫随机场　一种图模型，每个像素的标签只与相邻像素直接相关，常用来表达“相邻像素倾向于同类”。

怎么学

先读Boykov–Jolly图割理解能量与构图，再看GrabCut论文第3节迭代过程；用OpenCV的cv2.grabCut画框分割一张人像，观察迭代次数和补笔对结果的影响。
