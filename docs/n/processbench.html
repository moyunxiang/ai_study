ProcessBench推理找错

ProcessBench: Identifying Process Errors in Mathematical Reasoning
2024.12数据集延伸ACL 2025Chujie Zheng, Zhenru Zhang, Beichen Zhang, Runji Lin, Keming Lu, Bowen Yu, Dayiheng Liu, Jingren Zhou, Junyang Lin · 阿里巴巴Qwen团队待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

过程奖励模型（PRM）要给推理的每一步打分，但大家通常只用它在Best-of-N选答案时的最终准确率间接评价它，并不直接检验它能否找出推理过程中错在哪一步。

方法

收集3400道以竞赛和奥赛难度为主的数学题的逐步解答，由人类专家标注最早出错的那一步；模型要么指出这一步，要么判断全部正确。

影响

成为评测PRM和“批评模型”逐步纠错能力的标准基准，揭示了很多开源PRM在比GSM8K、MATH更难的题目上泛化很差。

方法

背景。过程监督与过程奖励模型发布了PRM800K，证明逐步监督比只看最终答案更有效；Math-Shepherd自动过程监督等工作用自动方法生成步级标签训练PRM。评价这些PRM的常用办法是：让策略模型采样N个解答，用PRM挑出得分最高的那个，看最终答对率。这个指标混入了策略模型的能力，而且答案对了不代表过程对，PRM可能只是学会了猜答案。

怎么构造。题目来自GSM8K、MATH竞赛数学以及OlympiadBench奥赛题、Omni-MATH奥赛数学等竞赛与奥赛级数据，后两者占大头。作者用多个开源模型生成逐步解答，统一重新切分步骤后，由人类专家逐步检查，标出最早出错的那一步的编号；如果整个过程都正确，标为没有错误。最终得到3400个测试样本，错误样本和正确样本都有。

怎么评。被测模型拿到题目和逐步解答，输出最早错误步骤的编号，或输出“全部正确”。分别计算在错误样本上和正确样本上的准确率，取二者的调和平均（F1）作为总分，这样既惩罚漏报错误，也惩罚把正确过程误判为错误。

两类被测模型。一类是PRM，取第一个得分低于阈值的步骤为预测；另一类是批评模型，即直接提示通用大模型逐步审查解答。

发现。摘要报告两点：现有PRM一般无法泛化到GSM8K和MATH之外更难的数学题，表现不如提示式的批评模型，也不如作者直接在PRM800K上微调得到的PRM；最好的开源模型QwQ开源推理模型-32B-Preview的批评能力可与GPT-4o相当，但仍落后于专门做推理的o1-mini。

局限与后续

  • 只标注“最早一个错误”，不评后续步骤和错误类型；只覆盖数学，代码和其他领域的过程评测仍缺少同类基准。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 延续
    过程监督与过程奖励模型2023.05 · 推理·智能体
    PRM800K提供了步级训练数据，ProcessBench提供了直接检验步级判断能力的测试集，并发现直接在PRM800K上微调的PRM泛化更好。
  • 改进
    Math-Shepherd自动过程监督2023.12 · 推理·智能体
    Math-Shepherd等用自动步级标签训练的PRM只用Best-of-N间接评价，ProcessBench直接测它们找错的能力，发现在难题上泛化差。
  • 使用
    Omni-MATH奥赛数学2024.10 · 数据·评测
    以Omni-MATH、OlympiadBench等奥赛级题目为主要题源。
  • 使用
    QwQ开源推理模型2024.11 · 推理·智能体
    QwQ-32B-Preview作为批评模型被评测，是表现最好的开源模型。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

本篇术语

  • 过程奖励模型　对推理过程的每一步分别打分的模型，用来判断推理在哪一步出了问题，而不只看最终答案。
  • 批评模型　用提示让通用大模型扮演审稿人，逐步检查一份解答并指出错误。

怎么学

先读过程监督与过程奖励模型了解过程监督；读ProcessBench原文的数据统计表和PRM与批评模型的对比表；动手找一份有错的数学解答，分别让一个PRM和一个通用模型指出第一个错误步骤。
