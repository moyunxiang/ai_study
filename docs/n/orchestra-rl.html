OrchestraRL智能体群编排

OrchestraRL: Learning to Orchestrate LLM Agent Swarms with Entropy-Aware Communication Control
2026论文延伸NeurIPS 2026（poster）Runze Fan, Shiyi Jiang, Junsheng Wang, Shuangjun Xie, Xiaodan Li, Yong Li待核对
NeurIPS 2026 ↗在交互版中打开（演化树、学习进度）

问题

用强模型搭的多智能体系统，智能体数量从2个加到8个时成绩常常停滞甚至下降；在算力相同的条件下，只改智能体之间的通信方式就能让结果差约5个百分点。

方法

在冻结的LLM之上训练两层控制器：宏观编排器根据群体输出的分歧程度选择通信模式和拓扑，每个智能体的微观协调器决定和谁说话、什么时候说。

影响

把「智能体群该怎样通信」本身当作要用强化学习学的策略，并报告智能体越多、相对随机广播的优势越大，是2026年swarm RL讨论中的代表工作之一。

方法

论文的出发点是一个对照实验：在SWE-bench Verified上用8个以Claude Opus 4.5为底座的智能体、预算相同，只改变通信策略，解决率相差5.1个百分点，说明多智能体系统的瓶颈常在协调而不在单个模型。

OrchestraRL不动底层LLM的权重，只训练一层控制器。宏观编排器读取群体的上下文熵H(t)——用各智能体输出嵌入的分散程度来衡量大家意见有多不一致——据此选择通信模式和拓扑（例如分散探索还是集中汇总）。微观协调器每个智能体一个，决定这个智能体把消息发给谁、什么时候发言。两层都用REINFORCE策略梯度加一个学出来的价值基线训练。

据会议页摘要：智能体数为2时与最强基线持平，为4和8时在SWE-bench Verified、GPQA Diamond、LiveCodeBench v6、SimpleQA四个基准上都取得最好成绩，且差距随数量增大；8个智能体时SWE-bench Verified解决率85.5%，随机广播协调为80.4%。学到的策略呈现出聚类探索、星形汇总、流水线推理等可解释的通信模式。

怎么学
