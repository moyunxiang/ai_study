DeepSeek-Coder-V2

DeepSeek-Coder-V2: Breaking the Barrier of Closed-Source Models in Code Intelligence
2024.06论文延伸arXiv 2024DeepSeek-AI, Qihao Zhu, Daya Guo, Zhihong Shao 等 · DeepSeek-AI待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

开源代码模型与GPT-4 Turbo这类闭源模型在代码和数学上仍有明显差距。

方法

从DeepSeek-V2与MLA的一个中间检查点出发，用额外6万亿token继续预训练，得到MoE代码模型。

影响

报告称在代码和数学基准上超过GPT-4 Turbo、Claude 3 Opus和Gemini 1.5 Pro，是当时最强的开源代码模型。

方法

DeepSeek-Coder-V2不是从零训练：它以DeepSeek-V2的一个中间检查点为起点，继续在代码和数学数据上训练了6万亿token，既大幅提升代码和数学推理，又保留通用语言能力。底座是混合专家架构，因此推理成本比同等能力的稠密模型低。

与DeepSeek-Coder相比，支持的编程语言从86种增加到338种，上下文从16K扩到128K。官方称在标准基准上，它在代码和数学任务上超过GPT-4 Turbo、Claude 3 Opus和Gemini 1.5 Pro。

局限与后续

  • 基准成绩是官方报告，且HumanEval等函数级基准已接近饱和，仓库级真实任务上的差距没有充分体现。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • MoE总参数很大，本地部署门槛高。

先读DeepSeek-V2与MLA的MoE结构；读本文继续预训练的数据配比一节；动手：比较从零训练与继续预训练在同样token预算下的差别（思考实验即可）。
