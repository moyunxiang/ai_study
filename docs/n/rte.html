RTE文本蕴含挑战

The PASCAL Recognising Textual Entailment Challenge
2005数据集延伸Ido Dagan, Oren Glickman, Bernardo Magnini · PASCAL网络待核对
Springer ↗Wikipedia ↗在交互版中打开（演化树、学习进度）

问题

问答、摘要、信息抽取等应用都需要判断「一句话能否推出另一句话」，但这个能力没有统一的任务和测试集。

方法

给定一段文本和一个假设，要求判断假设是否能从文本合理推出，集中成一个通用的二分类评测。

影响

它把自然语言推理定义成一个独立任务，后来SNLI、MultiNLI以及GLUE中的推理任务都沿着它发展。

方法

RTE（Recognising Textual Entailment）由欧洲PASCAL卓越网络于2005年组织。任务是：给出一段文本t和一个假设h，判断读者读了t之后，是否通常会认为h为真。这不同于严格的逻辑蕴含，而是接近人的日常推断，所以用的是「典型情况下」的宽松标准。例子：文本说「帮助穷人，上帝会奖赏你」，假设说「给穷人钱会有好结果」，则成立；假设说「给穷人钱没有后果」，则矛盾。

第一届挑战吸引了17个团队提交，说明这个通用任务引起了研究界的注意。此后每年继续办，RTE成了GLUE基准中的一个子任务（见GLUE / SuperGLUE）。组织者的想法是：许多应用（问答、检索、摘要、翻译评测）背后都隐含着同样的语义推断，一个共同任务可以统一评测它们。

它的数据量很小（只有几百到上千对），后来SNLI用众包把规模提高了几个数量级。

局限与后续

  • 每年的数据只有几百对，不够训练数据驱动的模型，系统多靠手写规则和浅层特征。
    后来针对它的工作　SNLI MultiNLI
  • 「大概率成立」的标准主观，不同标注者的判断并不总是一致。
    后来针对它的工作　SNLI HellaSwag

它建立在什么之上

    PASCAL VOC2005 · 数据·评测
    同属PASCAL网络的挑战赛模式：公开数据、统一评测、年度竞赛，只是任务从图像换成文本。

后来的相关工作

  • 改进
    SNLI2015.08 · 数据·评测
    RTE每届只有几百到几千对句子，SNLI把规模扩大到57万对，足以训练神经网络。
  • 使用
    GLUE / SuperGLUE2018.04 · 数据·评测
    把PASCAL RTE历届挑战的数据合并为一个小数据推理任务。
  • 改进
    MultiNLI2017.04 · 数据·评测
    每年的数据只有几百对，不够训练数据驱动的模型，系统多靠手写规则和浅层特征。
  • 改进
