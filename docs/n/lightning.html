PyTorch Lightning

2019.03系统延伸William Falcon · Lightning AI待核对
维基 ↗在交互版中打开（演化树、学习进度）

问题

原生PyTorch的训练循环里，模型定义、数据、设备管理、分布式、日志混在一起，每个项目都在重复写，也容易出错。

方法

PyTorch Lightning把研究代码（模型、损失、优化器）和工程代码（循环、多卡、混合精度、日志）分开，后者由框架统一处理。

影响

成为PyTorch上最常用的训练封装之一，换设备和并行策略只需改参数。

方法

用户继承一个LightningModule，写好training_step（一个批次的损失）、configure_optimizers等方法；循环、梯度清零、设备迁移、混合精度、多卡与多机训练、检查点和日志都交给Trainer处理。切换到多GPU或TPU只需改Trainer的参数，不必改模型代码。

维基记载作者为William Falcon，首个版本发布于2019年5月31日，目标是「把研究与工程解耦」，使实验更易读、更易复现。它与fastai走的是相近的路：给PyTorch提供上层训练抽象，区别在Lightning更强调不隐藏PyTorch代码。

局限与后续

  • 封装之下行为较隐式，复杂定制（如非标准训练循环）要覆盖钩子。

它建立在什么之上

  • 延续
    PyTorch2017.01 · 系统·效率
    在PyTorch之上封装训练循环与分布式细节。
  • 竞争
    fastai2018.10 · 系统·效率
    同为PyTorch上的训练封装，Lightning更少隐藏原生代码，fastai的高层API更强。

读懂它需要的概念

分布式训练：数据并行与模型并行 批大小、步数与轮数 梯度下降

怎么学

把一个手写的训练循环改写成LightningModule加Trainer，再切换到多GPU。
