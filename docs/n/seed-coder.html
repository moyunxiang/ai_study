Seed-Coder模型筛数据

Seed-Coder: Let the Code Model Curate Data for Itself
2025.06论文延伸ByteDance Seed（Yuyu Zhang, Jing Su, Yifan Sun, Chenguang Xi, Xia Xiao, Shen Zheng et al.） · 字节跳动Seed待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

开源LLM的代码预训练数据大多靠人工：为每种编程语言手写过滤规则，或用人工标注训练质量分类器。这种做法难以扩展到许多语言，带有主观偏差，维护成本也高。

方法

用“以模型为中心”的数据流水线：主要让LLM给代码数据打分和过滤，尽量减少人工参与；在此基础上训练8B的基础、指令和推理三种代码模型，推理版用长思维链强化学习提升多步代码推理。

影响

在同规模开源模型中取得最好成绩，部分任务超过大得多的模型，说明“让代码模型自己筛代码数据”是可扩展的替代方案，标题就概括了这一点。

方法

背景：StarCoder2与Stack v2和OpenCoder开放食谱等开源代码模型的数据流程依赖大量手写规则：每种语言单独设计过滤启发式（如注释比例、行长度），或者像FineWeb / FineWeb-Edu的教育质量分类器那样用人工或模型标注训练一个打分器。规则越多、语言越多，越难维护，而且规则体现的是设计者的主观偏好。

以模型为中心的数据流水线：Seed-Coder把质量判断交给LLM。核心做法是用一个LLM对代码文件按可读性、模块化、清晰度、可复用性等维度打分，再把打分结果蒸馏到一个较小的打分模型上，以便对海量代码做筛选；这样一个打分器就能覆盖所有编程语言，不必逐语言写规则。数据来源包括GitHub代码文件、提交记录（commit）和与代码相关的网页，按各自的特点处理。

三种模型（都是8B）：

  • 基础模型：在筛选后的数据上预训练，支持补全和中间填空；
  • 指令模型：在基础模型上做监督微调和偏好优化；
  • 推理模型：用长思维链（LongCoT）强化学习训练，提升多步的代码推理，例如竞赛编程题，做法与DeepSeek-R1一类推理模型相近。

结果（摘要）：在代码生成、代码补全、代码编辑、代码推理和软件工程任务上，Seed-Coder在同规模开源模型中达到最好水平，甚至超过一些大得多的模型。

后来的发展

“用LLM打分代替手写规则”的代码数据流水线被后续开源代码与通用模型的数据工作借鉴；它也是字节Seed团队较早公开技术细节的开源模型之一。

局限与后续

  • 数据质量完全由LLM打分决定，打分模型自身的偏好（例如偏爱某种风格或语言）会被放大进训练数据，作者的方法难以发现这种偏差。

  • 只有8B一个规模，更大规模下“模型筛数据”的收益是否保持没有验证。

它建立在什么之上

  • 使用
    DeepSeek-R12025.01 · 推理·智能体
    推理版采用长思维链强化学习，与R1一类推理模型的训练思路相同。
  • 延续
    FineWeb / FineWeb-Edu2024.06 · 数据·评测
    FineWeb-Edu用模型打分筛选教育质量网页，Seed-Coder把模型打分扩展为代码数据的主要过滤手段。
  • 竞争
    Qwen2.5-Coder2024.09 · LLM
    同规模的主要对照，摘要称Seed-Coder在同规模开源模型中最好。
  • 改进
    OpenCoder开放食谱2024.11 · LLM
    OpenCoder等依赖为代码手工设计的过滤规则，Seed-Coder改用LLM打分，减少人工规则。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

预训练与微调 指令微调与对话模板 知识蒸馏 推理token与测试时计算 人类反馈强化学习

本篇术语

  • 以模型为中心的数据流水线　主要由大模型而不是人工规则来判断数据质量、决定保留哪些训练数据。
  • 长思维链强化学习　让模型生成很长的推理过程再给答案，用答案是否正确作为奖励做强化学习，提升多步推理能力。

怎么学

先读FineWeb / FineWeb-Edu的模型打分过滤和OpenCoder开放食谱的规则式清洗；读本文数据流水线一节和各任务评测表；动手：用一个开源LLM按“可读性、模块化”给几十个代码文件打分，看高分和低分文件分别是什么样子。
