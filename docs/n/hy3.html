腾讯混元Hy3

Hy3
2026.07模型延伸腾讯混元（Tencent Hy Team）待核对
Hugging Face模型卡 ↗在交互版中打开（演化树、学习进度）

问题

公开基准分数高的开放模型，在真实产品里常因工具调用不稳定、输出格式出错、幻觉多而难以落地。

方法

2950亿总参数、210亿激活的MoE，在Hy3 Preview之后根据50多个产品的反馈扩大后训练和强化学习，专门修复工具调用稳定性和幻觉问题。

影响

官方称性能超过同规模模型、可与参数多2–5倍的开源旗舰竞争；270位专家的盲评得分2.67/4，高于GLM-5.1的2.51/4；以Apache 2.0开源。

背景

腾讯在2024年开源了腾讯混元Hunyuan-Large（389B总参数的MoE），之后混元系列主要在腾讯内部产品中迭代。2026年，开放模型竞争的重点从基准分转向“在产品里是否可靠”：工具调用、格式约束、跨脚手架的一致性和幻觉率。

方法

据官方模型卡，Hy3为MoE架构：总参数2950亿、激活210亿，另有38亿参数的1层多token预测（MTP）层；80层主干，64个注意力头的分组查询注意力GQA（8个KV头、头维128），隐藏维4096，192个专家每token激活8个，上下文256K，词表约12万。

训练上，在4月底发布Hy3 Preview后，团队收集了50多个产品的反馈，提升后训练数据的质量与多样性并扩大RL训练规模。产品可靠性方面重点修复了：工具调用和输出格式的稳定性（在CodeBuddy、Cline、KiloCode等不同脚手架上SWE-Bench Verified准确率差异控制在4%以内）；知识与反幻觉（按“有依据才答、无证据就说明、不混淆来源、不编造数据”的原则清洗数据并加训练约束）。

结果

官方模型卡报告：Hy3超过同规模模型，可与参数多2–5倍的旗舰开源模型竞争；在270位专家用自身工作任务做的盲评中得2.67/4，高于GLM-5.1的2.51/4，前端开发、数据与存储、CI/CD任务优势最明显；内部真实场景评测中幻觉率从12.5%降到5.4%。模型以Apache 2.0许可开源。

后来的发展

2026年11月腾讯又在Hugging Face发布了Hy4与Hy4-flash；Hy3代表了国内大厂把“产品反馈驱动的后训练”作为开放模型主要卖点的做法。
