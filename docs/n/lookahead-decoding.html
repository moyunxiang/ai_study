Lookahead前瞻解码

Break the Sequential Dependency of LLM Inference Using Lookahead Decoding
2024.02论文延伸ICML 2024Yichao Fu, Peter Bailis, Ion Stoica, Hao Zhang · 加州大学圣地亚哥分校, 加州大学伯克利分校等待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

推测解码要先找一个和目标模型匹配的小草稿模型，或者额外训练草稿头，换一个模型就得重新准备，也不容易推广。

方法

不要草稿模型：让大模型自己用Jacobi迭代并行地猜未来好几个位置的词，从猜测轨迹里收集n-gram放进池子，同一次前向里再验证池中候选，猜对几个就一次接受几个。

影响

无需辅助模型、输出与原模型完全一致的并行解码代表方法，常与Medusa、EAGLE并列比较，后续的Jacobi/一致性解码工作沿着它继续推进。

方法

自回归解码每步只出一个词，GPU算力大量闲置，瓶颈在显存带宽。推测解码用小模型先猜、大模型一次验证，效果好但依赖合适的草稿模型。

Lookahead Decoding的出发点是Jacobi迭代：把未来n个位置先随便填上词，让模型同时为这n个位置各预测一次，用新预测替换旧值，反复迭代，直到不再变化。单纯的Jacobi解码很少能一次猜对多个词，但迭代过程中会冒出很多正确的片段。于是每次前向同时做两件事：前瞻分支，在一个2D窗口里沿多个位置继续Jacobi迭代，把产生的n-gram存进n-gram池；验证分支，从池里挑出以当前最后一个词开头的候选n-gram，和分块并行解码一样用一次前向检查它们，接受最长的正确前缀。两者用特殊的注意力掩码合并进同一次前向，可以与FlashAttention兼容。

论文指出，它用每步增加的log(FLOPs)换取总解码步数的减少。摘要报告：在MT-bench上解码最多加速1.8倍，在多GPU强扩展的代码补全任务上最多4倍。
