JAX

JAX: Composable Transformations of Python+NumPy Programs
2018.12系统延伸James Bradbury, Roy Frostig, Peter Hawkins, Matthew Johnson 等 · Google待核对
GitHub ↗维基 ↗在交互版中打开（演化树、学习进度）

问题

研究者喜欢写NumPy，但NumPy不能自动求导，也不能在GPU/TPU上高效运行，要么换框架要么手写梯度。

方法

JAX保留NumPy接口，在其上提供可组合的函数变换：求梯度、JIT编译、自动向量化和多设备并行。

影响

成为谷歌内外大规模研究的常用底座，不少大模型训练代码基于它。

方法

JAX最初基于autograd：给NumPy求导的自动求导，再接上XLA编译器编译器。维基称其结合了改造版的autograd与OpenXLA，设计上尽量贴近NumPy的结构和用法。

核心理念是函数变换可嵌套组合：对一个纯函数，grad返回它的梯度函数，jit把它编译成XLA程序，vmap自动加上批维度，pmap把它分到多个设备。它们可以任意叠加，例如对一个函数先求梯度、再用vmap得到逐样本梯度。要求函数是纯函数（无副作用），随机数也要显式传入密钥。这与Theano与自动微分的符号图和PyTorch的命令式风格都不同。

局限与后续

  • 纯函数式风格对新手不友好，状态管理（如随机数、参数）要显式处理。

它建立在什么之上

  • 改进
    TensorFlow2015.11 · 系统·效率 待核对
    静态图加Session的编程模型抽象层次多、报错难以定位，带条件分支和循环的动态模型要用专门的控制流算子编写，研究效率低。
  • 竞争
    PyTorch2017.01 · 系统·效率 待核对
    同一时期的另一种研究框架路线：命令式PyTorch与函数变换式JAX。
  • 改进
    NumPy与SciPy2006.10 · 系统·效率
    只在CPU上运行，无法利用GPU做大规模并行计算。
  • 竞争
    Theano与自动微分2010.06 · 系统·效率
    同样把数值程序编译到加速器，但JAX从普通Python函数出发而不是构建符号图。
  • 改进
    Chainer与Define-by-Run2015.06 · 系统·效率
    每一步运算都要经过Python解释器调度，小算子多时开销显著，也无法做跨算子的全局优化。
  • 改进
    TPU v2/v3与TPU Pod2017.05 · 硬件
    只能通过TensorFlow和Google Cloud使用，研究社区主流的PyTorch代码不能直接跑。
  • 改进
    autograd：给NumPy求导2015 · 系统·效率
    沿用autograd对Python与NumPy代码的自动求导，并让它可组合、可编译。
  • 改进
    自动微分综述2015.02 · 系统·效率
    综述写于动态图框架普及之前，对GPU上的大规模张量程序、编译器层面的求导（如对整段Python程序求导）只能简略讨论；这些后来由JAX、PyTorch 2等框架补上。
