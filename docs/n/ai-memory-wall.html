AI与内存墙

AI and Memory Wall
2024.03论文延伸arXiv 2024Gholami, Yao, Kim, Hooper, Mahoney, Keutzer · UC Berkeley待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

大家都在谈算力不够，但真正限制大模型服务速度的可能是把数据从内存搬到计算单元的速度。

方法

用20年的硬件数据证明：服务器峰值算力每两年增长3.0倍，而DRAM带宽只增1.6倍、互连带宽只增1.4倍；解码器Transformer的推理尤其被内存带宽卡住。

影响

把内存墙这一老问题带入大模型时代，成为解释HBM、H200、推理专用芯片热潮的常被引用的论文。

方法

论文指出：过去20年服务器硬件峰值FLOPS每两年增长3.0倍，远超DRAM（1.6倍每两年）和互连（1.4倍每两年）带宽的增速，这种剪刀差让内存而不是算力成为AI应用，尤其是服务阶段的主要瓶颈。作者分析了编码器和解码器Transformer，说明解码器（逐词生成）每生成一个词都要读一遍权重，运算强度很低，在Roofline性能模型模型上落在内存带宽受限的区域，所以带宽成了决定速度的因素。

他们呼吁从模型结构、训练和部署三方面重新设计来缓解内存限制，例如更小的模型、量化和更高的运算强度。
