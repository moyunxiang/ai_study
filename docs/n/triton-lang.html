Triton GPU编程语言

Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations
2019.06论文重要MAPL 2019Philippe Tillet, H. T. Kung, David Cox · 哈佛大学 / IBM（后由OpenAI维护）待核对
论文（ACM） ↗OpenAI Triton 1.0博客 ↗官方教程 ↗在交互版中打开（演化树、学习进度）

问题

研究者的新算子用不上cuBLAS、cuDNN这类厂商库，自己写CUDA又要手工处理访存合并、共享内存和线程调度，写得慢、跑得也常常不快。

方法

把编程单位从“单个线程”提高到“一块数据（tile）”：程序员描述每个程序实例处理哪块矩阵，访存合并、共享内存管理、块内调度交给编译器自动完成。

影响

成为写自定义GPU内核的主流高层语言；PyTorch 2的编译器默认生成Triton代码，大量注意力、量化、融合内核都先用它实现。

背景

深度学习框架的每个算子背后都是一个GPU内核。常见算子（矩阵乘、卷积）由NVIDIA的cuBLAS、cuDNN手工优化到接近硬件峰值；但研究者一旦想要一个库里没有的算子，比如新的卷积变体或把几步运算融合成一个内核，就只能自己写CUDA。CUDA采用SIMT模型（每个线程跑同一段代码处理一个元素），程序员得自己保证全局内存访问合并成大块事务、把要重用的数据搬进共享内存并避免bank冲突、安排线程块和warp的分工——这正是专家和新手性能差几倍的地方。

另一条路是编译器：Halide：算法与调度分离和TVM深度学习编译器把“算什么”和“怎么调度”分开，Tensor Comprehensions、PlaidML用多面体方法自动生成循环。论文指出它们在常见矩阵乘上仍明显慢于cuBLAS，原因是这些系统以标量循环为单位做变换，难以表达GPU上真正高效的分块结构。

方法

Triton的核心抽象是tile：形状在编译期确定的多维数组。论文给了三层：

  • Triton-C：类C语言，可以直接声明float tile[16,16]这样的块变量，对整块做加载、加法、点积、广播和带掩码的条件运算；程序以SPMD方式运行，每个实例通过自己的编号决定处理矩阵的哪一块。
  • Triton-IR：基于LLVM的中间表示，把tile作为一等类型，便于做块级别的分析和变换。
  • Triton-JIT：一组与硬件无关和与硬件相关的块级优化（自动访存合并、共享内存分配与同步、利用张量指令等），最后生成LLVM-IR再到GPU代码，并带一个自动调优器搜索块大小等元参数。

例子：写矩阵乘C = A·B时，程序员只写“第(m, n)个实例负责C的一个128×128块，沿K方向每次取A和B各一块做点积累加”，而线程怎么分工、数据什么时候进共享内存由编译器决定。2021年OpenAI发布的Triton 1.0把前端换成Python装饰器函数，这就是今天大家用的形式。

结果

论文在GTX 1070上与cuBLAS 10.0、Auto-TVM、Tensor Comprehensions、PlaidML比较：Triton生成的矩阵乘与cuBLAS相当，在循环网络和Transformer的矩阵乘形状上比其他DSL快至多3倍；用它重写cuDNN的IMPLICIT_GEMM卷积没有性能损失，还高效实现了shift-conv这样的新算子。OpenAI的1.0博客称，用不到25行代码就能写出与cuBLAS性能相当的FP16矩阵乘，研究员写出的内核比等价的Torch实现快至多2倍。

后来的发展

作者加入OpenAI后，Triton从研究原型变成工业级工具。PyTorch 2与torch.compile的TorchInductor把模型图自动编译成Triton内核；Unsloth等微调加速库、许多注意力和量化内核也用它编写，FlashAttention系列在CUDA之外同样有Triton版本。它证明了“块级编程+编译器”可以逼近手写CUDA，2025年NVIDIA也在CUDA里推出了类似的块编程模型（CUDA Tile与cuTile）。

局限与后续

  • 编译器只负责一个程序实例内部的优化，跨SM的分块策略、同步仍要程序员自己决定，性能还依赖自动调优搜到合适的块大小。
    后来针对它的工作　PyTorch 2与torch.compile
  • 抽象越高，越难及时用上新硬件特性：Hopper的异步拷贝与warp专门化、Blackwell的新张量核心接口出现后，最快的内核仍先用CUDA/CUTLASS手写。
    后来针对它的工作　CUDA Tile与cuTile
  • 论文版本只面向NVIDIA GPU，其他加速器的后端需要另外实现。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 改进
    CUDA2006.11 · 硬件 待核对
    CUDA的SIMT模型要求手工处理访存合并、共享内存和线程调度；Triton把这些交给编译器，研究者只写块级逻辑。
  • 改进
    PyTorch2017.01 · 系统·效率 待核对
    PyTorch本身不帮你写高性能GPU内核，注意力等新算子要么拼接多个现有算子（慢、费显存），要么手写CUDA。
  • 改进
    BLAS线性代数接口1979.09 · 系统·效率
    接口按单个稠密矩阵设计，不支持批量小矩阵、稀疏、低精度（FP16/INT8）以及把激活函数等运算融合进矩阵乘法，这些都是深度学习的需求。
  • 改进
    Roofline性能模型2009.04 · 硬件
    只做诊断：它能指出程序受限于带宽，但提高运算强度要靠对每个内核手工重写数据访问方式（分块、算子融合）。
  • 竞争
    TVM深度学习编译器2018.02 · 系统·效率
    TVM从循环和调度原语出发自动生成内核，Triton以tile为一等公民，论文实验中矩阵乘比Auto-TVM更接近cuBLAS；之后高性能自定义内核更多选择Triton。
  • 改进
    体系结构的新黄金时代2018.06 · 硬件
    每种DSA都要配一套编译器和软件栈，生态碎片化；文章提出了问题，但如何让一份模型代码高效跑在多种芯片上当时没有成熟答案。
  • 改进
    Halide：算法与调度分离2013.06 · 系统·效率
    继承“算法与调度分离”的编译器思路，但把调度单位从标量循环换成GPU上的数据块。
  • 竞争
    cuDNN2014.09 · 硬件
    厂商库只覆盖常见算子；Triton用通用编译器重写了cuDNN的IMPLICIT_GEMM卷积且不掉性能，说明不必为每个新算子等厂商。
  • 竞争
    CUTLASS2017.12 · 系统·效率
    同样把矩阵乘拆成分块层次，CUTLASS用C++模板由专家组合，Triton用编译器自动完成，门槛更低但对新硬件特性的跟进更慢。

读懂它需要的概念

CPU、GPU与并行计算 矩阵乘法与线性变换 显存、内存带宽与“内存墙” 参数量、计算量与显存

本篇术语

  • GPU内核（kernel）　在GPU上并行执行的一个函数。框架里的每个算子，例如矩阵乘或softmax，最终都对应一个或几个内核。
  • tile（块）　一小块形状固定的多维数据，比如矩阵的一个128×128子块。Triton程序以块为单位读写和计算。
  • 访存合并　让一组相邻线程访问相邻的内存地址，硬件就能把它们合成一次大的内存事务，带宽利用率高得多。
  • SIMT　单指令多线程：CUDA的执行模型，大量线程执行同一段代码，每个线程处理不同数据。

怎么学

先了解CPU、GPU与并行计算里GPU的线程、共享内存和显存层次，以及显存、内存带宽与“内存墙”为何常常是瓶颈。然后跟着官方教程依次写向量加法、融合softmax、矩阵乘三个内核（这正是Triton 1.0博客的例子）。最后对照论文第3节的Triton-C与第5节的优化遍，理解编译器替你做了哪些事。
