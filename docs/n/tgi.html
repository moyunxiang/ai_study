TGI文本生成推理服务

2022.10系统延伸Hugging Face待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

开源大模型越来越多，但把它们部署成稳定、高吞吐、支持流式输出的在线服务，需要自己拼接批处理、张量并行和量化等工程。

方法

提供一个用Rust、Python和gRPC写成的现成文本生成服务器：内置连续批处理、张量并行、流式输出和多种量化后端，用Docker一条命令即可启动。

影响

曾为Hugging Face的HuggingChat、推理API和Inference Endpoints提供服务，是2023年前后最常用的开源LLM服务方案之一；2025年起官方宣布进入维护模式，推荐转用vLLM、SGLang等引擎。

方法

TGI的结构分两层：Rust写的路由层负责接收HTTP请求、排队和调度，把请求动态拼成批次；Python写的模型服务进程（可多卡分片）通过gRPC接收批次并执行前向计算。调度采用Orca连续批处理式的连续批处理：每生成一个token就可以让新请求加入、让已完成的请求退出，而不必等整批结束。它为常见模型架构提供了优化实现，集成了FlashAttention、分页注意力、张量并行，以及GPTQ训练后量化、AWQ激活感知量化、bitsandbytes等量化格式，并提供token流式输出、停止词、引导式（结构化）生成等接口。

项目仓库于2022年10月创建。其README目前写明已进入维护模式，只接受小修复与文档改进，并说明TGI推动了“推理引擎直接依赖transformers模型架构”的做法，这一做法已被下游的vLLM、SGLang等引擎采用。
