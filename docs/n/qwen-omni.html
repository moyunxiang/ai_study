Qwen2.5-Omni

Qwen2.5-Omni Technical Report
2025.03论文延伸Jin Xu, Zhifang Guo, Jinzheng He, Hangrui Hu, Ting He et al. · Alibaba Qwen团队待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

GPT-4o全模态实时模型式的全模态模型要同时接收文字、图像、音频、视频，并且边想边说，开源社区缺少端到端、流式的方案。

方法

提出Thinker-Talker架构：Thinker是负责生成文字的大语言模型，Talker是双轨自回归模型，直接利用Thinker的隐状态生成语音词元；再用TMRoPE对齐音频和视频的时间。

影响

为开源端到端语音交互全模态模型提供了一套可复现的架构，Qwen3-Omni沿用它。

方法

Qwen2.5-Omni要解决三个问题。第一，输入要流式：音频和视觉编码器都采用分块处理。第二，音视频要对齐：把音频和视频按时间交错排列，并提出TMRoPE（时间对齐的多模态位置编码），让同一时刻的画面和声音落在对应位置。第三，文字和语音要同时输出又不互相干扰：Thinker像普通大语言模型一样产生文字，Talker直接读取Thinker的隐藏表示，产生离散的音频词元。两部分端到端训练和推理。

局限与后续

  • 语音输出仍受限于Talker的离散语音词元，延迟和韵律控制不足，也未在全模态上做到不弱于单模态模型。

它建立在什么之上

  • 竞争
    GPT-4o全模态实时模型2024.05 · 多模态 已核对
    同样追求实时的音视频输入与语音输出，但以开源权重和公开架构的方式实现。
  • 改进
    Uni-MoE多模态专家2024.05 · 多模态
    只做理解，输出仍是文字，不能像全模态对话模型那样直接生成语音。
  • 改进
    video-SALMONN音视频2024.06 · 多模态
    只能理解、输出文字，不能像全模态对话模型那样以语音实时回应。
  • 改进
    VideoLLM-online流式2024.06 · 多模态
    只输出文本，不能像真人助手那样同时听、说语音。
  • 改进
    VITA开源全模态2024.08 · 多模态
    语音输出依赖独立的语音合成，不是端到端地生成语音，延迟和自然度不及GPT-4o。
  • 使用
    Qwen2-VL与开源VLM2024.09 · 多模态
    视觉理解部分建立在Qwen2-VL一系的视觉编码和语言主干之上。
  • 改进
    Baichuan-Omni开源全模态2024.10 · 多模态
    只能理解音频、输出文字，不能像GPT-4o那样直接生成语音，也没有端到端的全双工语音对话。
  • 改进
    Mini-Omni2视听语音助手2024.10 · 多模态
    模型规模很小，视觉理解和推理能力与大模型差距明显，主要价值在于完整功能形态的开源复现。
  • 改进
    Pixtral 12B2024.10 · 多模态
    只处理图像和文本，不含视频与音频。
  • 改进
    Lyra语音中心全模态2024.12 · 多模态
    依赖拼接现成的视觉语言模型和语音编码器，各模态的能力上限受这些部件限制，并非原生全模态训练。
  • 改进
    MiniCPM-o 2.6全模态2025.01 · 多模态
    宣称的「GPT-4o级」来自开发方自选的评测，实时交互的延迟、稳定性和长时间对话能力缺少统一的独立评测。
