SciCode科研代码

SciCode: A Research Coding Benchmark Curated by Scientists

问题

模型在许多难题上已超过普通人，高质量、贴近真实的评测越来越难做；代码基准多是通用编程题，考不到科研里“懂物理化学再写数值程序”的能力。

方法

请16个自然科学子领域的科学家出80道真实科研计算问题，每题拆成若干子问题（共338个），给出可选的背景说明、标准解答和测试用例。

影响

发布时最好的Claude 3.5 Sonnet在最贴近真实的设置下只能解出4.6%的主问题，给“模型能否当科研助手写计算程序”提供了一把难度足够的尺子。

方法

SciCode的题目由数学、物理、化学、生物、材料科学等16个子领域的科学家和AI研究者共同整理，来源是他们自己研究中真实需要写的计算程序。每道主问题天然可以拆成几个子问题，每个子问题同时涉及三件事：回忆相关的科学知识、推理出算法、写出代码。全部80道主问题拆成338个子问题。

评测时可以选择是否提供科学背景说明；每个子问题都有科学家标注的标准解答和测试用例，用测试判对错。只有一道主问题的所有子问题都做对，才算解出这道主问题。

据摘要，被测模型中最好的Claude 3.5 Sonnet在最贴近真实的设置（不给背景说明）下只解出4.6%的主问题。与HumanEval这类通用函数题相比，SciCode考的是专业知识与编程的结合，也和GPQA一样由领域专家出题。

局限与后续

  • 题目只有80道主问题，统计波动大，公开后也难避免进入训练数据。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 延续
    GPQA2023.11 · 数据·评测
    延续“请领域专家出难题”的思路，从选择题转到需要写可运行代码的科研任务。
  • 使用
    Claude 3.5 Sonnet2024.06 · LLM
    发布时表现最好的被测模型，主问题解出率4.6%。
  • 延续
    HumanEval2021.07 · 数据·评测
    同样用测试用例判断生成代码对错，但题目从通用短函数换成科研计算，并拆成多步子问题。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

基准、排行榜与SOTA 语言模型 数据泄漏与基准污染

怎么学

先读HumanEval了解用测试判分的方式；再看SciCode项目页上的示例题，体会一道主问题如何拆成子问题；动手让一个开源模型做一道题，比较给与不给背景说明时的差别。
