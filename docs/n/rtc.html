实时动作分块RTC

Real-Time Execution of Action Chunking Flow Policies
2025.06论文延伸Kevin Black, Manuel Y. Galliker, Sergey Levine · Physical Intelligence、UC Berkeley待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

VLA推理延迟高，动作分块虽保证了时间一致，但执行完一块再算下一块会停顿，或在块边界处出现跳变和抖动。

方法

推理时一边执行当前块、一边生成下一块，把确定会执行的动作「冻结」，其余部分用扩散或流匹配的修补（inpainting）来补全。

影响

无需重新训练，就能让任意扩散或流匹配VLA在高延迟下平滑、异步地运行。

方法

动作分块（见动作表示：离散token、连续动作与动作块，来自ALOHA与ACT）让策略每次输出一段动作，但π0这类大模型生成一块要几百毫秒，同步执行会在块之间停顿；若直接异步，新旧块在边界处不一致又会出现抖动。

RTC（实时分块）的做法是纯推理期算法：生成下一块时，已经确定要执行的那几步动作被冻结为条件，其余动作用图像修补式的引导去生成，使新块平滑接上旧块。作者提出了包含12个高动态任务的Kinetix仿真基准，并在6个真机双臂任务上测试；论文称RTC对推理延迟尤其鲁棒，显著提高任务吞吐量，甚至在较大延迟下完成点燃火柴这类精细任务。

局限与后续

  • 只适用于扩散或流匹配类策略，且需要额外的修补引导计算。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 只解决执行层的延迟，模型本身的推理成本和规模问题仍在。

它建立在什么之上

  • 改进
    π02024.10 · 具身·世界模型 已核对
    为π0等流匹配VLA提供无需重训的异步执行方法。
  • 改进
    Diffusion Policy2023.03 · 具身·世界模型
    每次出动作都要去噪10到100步，推理延迟比单次前向的策略高得多，限制了控制频率。
  • 改进
    ALOHA与ACT2023.04 · 具身·世界模型
    在动作分块基础上解决块边界不一致和延迟问题。
  • 改进
    Hugging Face LeRobot2024.05 · 具身·世界模型
    库本身不做量化、图编译等底层推理优化，大模型在廉价硬件上实时运行仍困难。
  • 改进
    FAST动作分词与π0-FAST2025.01 · 具身·世界模型
    自回归解码慢：π0-FAST在4090上每个动作块约需750毫秒，而流匹配版π0约100毫秒，不适合需要快速反应的场景。
  • 改进
    TinyVLA2024.09 · 具身·世界模型
    扩散头需要多步去噪，实时控制的延迟问题仍在。
  • 改进
    RDT-1B2024.10 · 具身·世界模型
    1.2B的扩散模型推理需要多步去噪，实时双臂控制的延迟较高。
  • 改进
    CogACT2024.11 · 具身·世界模型
    扩散动作头需要多步去噪，推理速度不及直接回归的方案。
