Code as Policies

Code as Policies: Language Model Programs for Embodied Control
2022.09论文重要ICRA 2023Jacky Liang, Wenlong Huang, Fei Xia, Peng Xu, Karol Hausman, Brian Ichter, Pete Florence, Andy Zeng · Robotics at Google待核对
arXiv ↗项目主页（代码与演示） ↗在交互版中打开（演化树、学习进度）

问题

SayCan让语言模型从固定技能库里挑技能，只能“按顺序调用现成动作”；“把方块排成一条对角线”“再快一点”这类需要几何计算、循环判断或具体数值的指令，挑技能是表达不了的。

方法

让会写代码的大语言模型（Codex）根据几条示例，把自然语言指令直接写成Python策略程序：调用感知接口拿物体坐标，用循环、条件和NumPy做计算，再调用控制接口执行；遇到没定义的函数就让模型递归地再写出来。

影响

不需要任何机器人数据训练，就能在桌面操作、白板绘图、移动机器人等多个平台上执行新指令；在仿真中对没见过的指令和属性远超用3万条示范训练的CLIPort，开启了“用代码作为机器人接口”的路线。

背景

SayCan把大语言模型接到了机器人上：语言模型从几百个预训练技能中挑出下一步，价值函数保证选中的技能在当前场景能做到。但这种方式的表达力受限于技能库——语言模型只能输出“下一个技能的名字”。

很多指令其实需要计算：“在红碗和绿碗之间放一个方块”要求中点，“再快一点”要把速度调到合理值，这些没法用一串技能名拼出来。另一方面，Codex已经证明大语言模型能根据注释写出可运行的Python程序。程序天然有变量、循环、条件和数学库，正好能表达这些逻辑。

方法

语言模型程序（LMP）。给语言模型一段提示：开头是几行导入语句和可用接口的提示（感知接口如 get_obj_pos(name)、get_obj_names()，控制接口如 put_first_on_second(a, b)），后面是若干“注释写指令、下面写代码”的示例（见上下文学习与提示）。新指令以注释形式加在末尾，模型续写出代码，直接执行。

例如指令“把方块堆在最左边的碗里”，模型会写：取所有碗的坐标 → 用 min(..., key=x坐标) 找最左边的碗 → 循环把每个方块放上去。感知接口背后接的是开放词汇检测器（如ViLD、MDETR），控制接口背后可以是CLIPort这样的拿放原语，也可以是速度或轨迹指令（见工具调用）。

分层代码生成。如果生成的代码调用了一个还不存在的函数，比如 get_blocks_in_a_line()，就把这个函数名和用法作为新的提示交给模型，让它递归地把函数写出来，直到所有函数都有定义。这让模型能写出更长、更复杂的程序，类似把思维链CoT的逐步拆解用函数调用的形式表达。

模型还会把“快一点”这类模糊说法按上下文换成具体数值。

结果

实验主要使用code-davinci-002，温度为0。仿真桌面任务中，与用3万条示范训练的多任务CLIPort相比：见过的属性和指令下的长程任务，CaP成功率97.2%，CLIPort 78.8%；属性和指令都没见过时，CaP 80.0%，CLIPort为0。空间几何推理上，写代码的准确率98%，用自然语言思维链为58%。分层生成把HumanEval通过率提到39.8%，在自建的RoboCodeGen上也优于不分层的写法，并且模型越大越好。

后来的发展

“让大模型写调用感知和控制接口的程序”成为LLM驱动机器人的重要路线：VoxPoser让语言模型写代码生成三维价值地图来指导轨迹，Eureka奖励设计让语言模型写奖励函数代码训练灵巧手。后来的RT-2与VLA等VLA模型则走了相反的路，直接从数据里学底层动作。

读懂它需要的概念

语言模型 上下文学习与提示 工具调用 解码：贪心、束搜索、温度与top-p 分类、检测、分割

本篇术语

  • 语言模型程序（LMP）　由语言模型生成、可直接执行的程序；在这里它本身就是机器人的策略，负责把感知结果变成控制指令。
  • 分层代码生成　模型先写高层函数，遇到未定义的子函数再让模型单独写出它，逐层递归，直到程序完整。
  • 开放词汇检测　能按任意文字描述（而不只是固定类别表）在图像中找出物体的检测模型。

怎么学

先读SayCan和Codex → 读原文第III节（LMP与分层代码生成）和表III、表IV → 动手：用任一开源代码模型和项目提供的桌面仿真Colab，写几条新指令，观察生成的代码和失败案例。
