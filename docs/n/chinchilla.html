Chinchilla

Training Compute-Optimal Large Language Models
2022.03论文重要NeurIPS 2022Jordan Hoffmann, Sebastian Borgeaud, Arthur Mensch, Elena Buchatskaya, Trevor Cai, Eliza Rutherford, Diego de Las Casas, Lisa Anne Hendricks et al. · DeepMind待核对
arXiv ↗Chinchilla复现与修正 ↗在交互版中打开（演化树、学习进度）

问题

按照2020年的规模定律，算力增加时应主要加参数、数据只少量增加，于是GPT-3、Gopher、MT-NLG都是一两千亿以上参数却只训练约3000亿token。这种分配是否最优，没人认真检验过。

方法

训练400多个从7000万到160亿参数、数据量从50亿到5000亿token的模型，用三种方法估计“给定算力时最优的参数量和数据量”；三种方法都得出：两者应按相同比例增长。

影响

按此训练的700亿参数Chinchilla用了与2800亿Gopher相同的算力、4倍的数据，在几乎所有任务上都更好，MMLU达67.5%；“约20个token对应1个参数”成为此后训练大模型的基本参照。

背景

语言模型的规模定律（Kaplan等，2020）发现语言模型的损失随参数量N、数据量D按幂律下降（见幂律与规模定律），并据此建议算力增加时主要加参数：最优参数量 N_opt ∝ C^0.73，最优数据量 D_opt ∝ C^0.27（算力翻10倍，参数约翻5倍，数据不到翻2倍）。业界照此行事：GPT-3（175B）、Jurassic-1（178B）、Gopher（280B）都只训练了约3000亿token，MT-NLG 530B（530B）只有2700亿token。

但Kaplan的实验有一个问题：所有模型用同一个固定长度的学习率衰减计划，训练中途的损失并不是“按这么多数据训练到底”时能达到的损失，数据的作用因此被低估；而且大部分模型不到1亿参数。

方法

训练前先统一一个关键设置：余弦学习率衰减的周期长度与该次训练的token总数匹配。在此基础上用三种互相独立的方法估计最优配比，训练成本按常用近似 C ≈ 6·N·D 计算（见参数量、计算量与显存）。

方法一：训练曲线包络。固定一组模型尺寸（70M到10B以上），每个按4种不同的训练长度训练，在每个算力点上取所有曲线中最低的损失，再看最低点对应的N和D。

方法二：等算力曲线（IsoFLOP）。选9个固定的算力预算，每个预算下训练不同大小的模型（模型越大，能分到的token越少），损失对模型大小呈U形，用抛物线找谷底，得到该预算下的最优N。

方法三：参数化拟合。把所有实验的最终损失拟合成

L(N, D) = E + A / N^α + B / D^β

E是数据本身的不可约熵，第二项是模型容量不够带来的损失，第三项是数据不够带来的损失。拟合结果约为 E = 1.69, α = 0.34, β = 0.28，在 6ND = C 的约束下解析求最优点。

三种方法给出 N_opt ∝ C^a 中 a 分别为0.50、0.49、0.46，即参数和数据应大致同比增长。按方法一的表格：70B模型应训练1.4万亿token，175B模型约3.7万亿，即每个参数约20个token。

验证。用Gopher的训练算力训练一个70B模型Chinchilla，在1.4万亿token的MassiveText上（数据与Gopher相同，配比略调），并把优化器换成AdamW。

结果

Chinchilla（70B）在大量下游任务上全面超过Gopher（280B）、GPT-3（175B）、Jurassic-1（178B）和MT-NLG（530B）。MMLU五样本平均67.5%，比Gopher高7个多百分点。由于参数只有Gopher的四分之一，推理和微调的成本也低得多。按其估计，当时的大模型普遍“参数过多、训练不足”：用Gopher的算力，最优模型应在400亿到700亿参数之间。

后来的发展

这篇论文直接改变了大模型的训练方式。LLaMA进一步把较小的模型训练到远超“20倍”的token数，因为部署时推理成本占大头；计入推理成本的规模定律把推理成本写进了规模定律。当高质量数据开始不够用时，数据受限的规模定律研究了重复训练多轮的收益，数据会用完吗估计了人类文本何时耗尽。2024年Chinchilla复现与修正重新拟合发现，原文方法三的参数估计有误，修正后与方法一、二一致。今天“Chinchilla最优”仍是讨论训练预算的基准，但实际模型的训练token数大多远超20倍参数。

容易误解的地方

  • “每个参数20个token”是训练算力最优，不是部署最优：如果模型要被大量调用，训练一个更小的模型、喂更多数据通常更划算。
  • 结论依赖“数据不重复、不超过一轮”的假设，以及特定数据集MassiveText。

局限与后续

  • 只优化训练算力，没有考虑推理成本；对需要大规模部署的模型，比最优更小、训练更久的模型更合算。
    后来针对它的工作　LLaMA 计入推理成本的规模定律
  • 假设数据无限、每条只用一次；按此配比，下一代模型需要数万亿乃至更多高质量token，数据很快会成为瓶颈。
    后来针对它的工作　数据受限的规模定律 数据会用完吗
  • 方法三的参数化拟合与另外两种方法不一致，且原始实验数据没有公开，难以检验。
    后来针对它的工作　Chinchilla复现与修正
  • 只用损失衡量“好坏”，数据的质量差异没有进入公式；同样多的token，质量不同，效果可以差很多。

读懂它需要的概念

幂律与规模定律 参数量、计算量与显存 学习率与学习率调度 语言模型 泛化与过拟合 损失函数

本篇术语

  • 计算最优　在固定训练算力下，选择让最终损失最低的参数量和数据量组合。
  • IsoFLOP曲线　算力固定时，把不同大小模型训练到头的最终损失画成一条曲线；曲线的谷底就是这个预算下的最优模型大小。
  • 6ND　训练一个N参数模型、看D个token大约需要的浮点运算数：前向每个参数每个token约2次，反向约4次。

怎么学

先懂幂律与规模定律和参数量、计算量与显存，读语言模型的规模定律了解Kaplan的结论。读原文第3节的三种方法和表2、表3，附录D的推导。动手：用论文的 L(N,D) = 1.69 + 406.4/N^0.34 + 410.7/D^0.28 和 C = 6ND，写几行代码算出给定算力下的最优N和D，并与表3对照；再看Chinchilla复现与修正修正后的系数有何不同。
