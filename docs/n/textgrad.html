TextGrad文本梯度

TextGrad: Automatic "Differentiation" via Text
2024.06论文延伸Nature 2025Mert Yuksekgonul, Federico Bianchi, Joseph Boen, Sheng Liu, Zhi Huang, Carlos Guestrin, James Zou · 斯坦福大学 / Chan Zuckerberg Biohub待核对
arXiv ↗Nature版 ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

由多个LLM、工具和代码拼成的复合AI系统越来越常见，但其中的提示、代码、答案都是文字，没法求导，只能靠专家手工反复调。

方法

把系统写成计算图，让LLM对输出给出文字批评当作“梯度”，再沿计算图逐层往回传给每个上游变量，最后让LLM按批评改写变量，接口仿照PyTorch。

影响

把“LLM反馈改写提示”推广成一个通用的优化框架，可优化提示、代码、答案乃至分子结构，附带开源库，论文后来发表于Nature。

方法

神经网络能被方便地训练，靠的是自动微分与计算图：写好前向计算，框架自动算梯度。TextGrad把这套抽象搬到文字上。系统里每个需要优化的东西（一段提示、一份代码、一个答案）都是一个变量，LLM调用和工具调用是图上的运算；损失也是文字，例如让一个评估LLM判断“这段代码哪里会出错”。

反向传播时，TextGrad对每一步运算问LLM：“已知下游得到了这样的批评，上游这个变量该怎么改？”得到的文字建议就是该变量的文本梯度，链条上的每一环都这样逐级生成。优化器“文本梯度下降”再把变量和它收到的所有建议交给LLM，产出改写后的新版本。与OPRO以LLM为优化器只看历史得分、DSPy主要挑示例和指令不同，TextGrad传递的是逐个变量的具体批评，所以不只能优化提示，也能在测试时直接优化某一道题的答案或代码。

论文给出的结果：不改框架设置，GPT-4o在GPQA上的零样本准确率从51%提到55%；LeetCode-Hard代码题的解答获得20%的相对提升；还展示了提示优化、类药小分子设计和放疗计划优化。

局限与后续

  • 每一步“求梯度”和“更新”都要调用强LLM，计算图越深调用越多，成本远高于普通提示；批评的质量取决于评估LLM本身，评估者看不出的错误就优化不掉。

  • “文本梯度”只是比喻，没有数值梯度那样的链式法则和收敛保证；反馈在长链条上逐级转述时可能失真，改写也可能来回振荡。

它建立在什么之上

  • 竞争
    DSPy2023.10 · 推理·智能体
    两者都优化多模块LLM程序：DSPy主要靠挑选示例和搜索指令，TextGrad靠沿计算图回传逐个变量的文字批评。
  • 竞争
    AutoPrompt梯度搜提示2020.10 · 推理·智能体
    AutoPrompt用模型内部的真实梯度搜索离散提示，需要白盒访问；TextGrad只用LLM生成的文字“梯度”，可用于闭源API。
  • 延续
    自动提示工程APE2022.11 · 推理·智能体
    APE让LLM生成并筛选候选指令；TextGrad把这种黑盒提示优化推广为可组合的、对任意文字变量的迭代改写。
  • 延续
    Reflexion2023.03 · 推理·智能体
    Reflexion用语言反思改进智能体的下一次尝试；TextGrad把语言反馈系统化为沿计算图传播、逐变量更新的过程。
  • 延续
    OPRO以LLM为优化器2023.09 · 推理·智能体
    同样把LLM当优化器，但输入从“历史提示及其得分”变成针对每个变量的具体文字反馈。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

自动微分与计算图 反向传播 梯度下降 上下文学习与提示 损失函数

本篇术语

  • 复合AI系统　由多个LLM调用、检索、代码执行等组件串联起来完成任务的系统，而不是单个模型一次回答。
  • 文本梯度　LLM针对某个变量写出的改进建议，例如“这个提示没要求检查单位”，在TextGrad里扮演梯度的角色。

怎么学

先补自动微分与计算图和反向传播，再读OPRO以LLM为优化器和DSPy → 读原文第2节的框架抽象和提示优化实验 → 动手：用官方库对一个解数学题的系统提示做几轮文本梯度下降，打印每轮的批评和改写后的提示。
