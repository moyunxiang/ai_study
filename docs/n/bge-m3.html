BGE-M3多功能嵌入

M3-Embedding: Multi-Linguality, Multi-Functionality, Multi-Granularity Text Embeddings Through Self-Knowledge Distillation
2024.02论文延伸Findings of ACL 2024Jianlv Chen, Shitao Xiao, Peitian Zhang, Kun Luo, Defu Lian, Zheng Liu · 北京智源人工智能研究院（BAAI） / 中国科学技术大学待核对
arXiv ↗ACL Anthology ↗Hugging Face ↗在交互版中打开（演化树、学习进度）

问题

多语言、长文档检索要分别用不同模型；稠密向量、稀疏词权重、多向量后期交互三种检索方式各有长处，却要训练和部署三个模型。

方法

一个编码器同时输出稠密向量、每个词的稀疏权重和每个token的向量，三种分数加权相加当“老师”，再反过来蒸馏每一种检索方式。

影响

开源后成为多语言RAG里最常用的嵌入模型之一，“一个模型同时给稠密和稀疏检索结果”的混合检索做法也随之普及。

方法

BGE嵌入模型主要面向中英文、短文本。M3指三个“多”：100多种语言、三种检索功能、最长8192 token的输入。

一个模型三种分数。底座是扩展到8192位置的XLM-RoBERTa。稠密检索用归一化后的[CLS]向量做内积；稀疏检索为每个token学一个非负权重（重复出现的词取最大值），查询与文档共有词的权重相乘求和，类似SPLADE学习式稀疏检索；多向量检索把所有token的输出投影后做ColBERT后期交互式的后期交互。最终排序可以用三者的加权和。

自知识蒸馏。三种分数的加权和比任何单一分数都准，于是把它当教师信号，让每种检索方式的分数分布去拟合它，再与普通对比学习损失平均。训练数据包括约12亿对无监督文本对（194种语言）和多语言标注数据。

结果。MIRACL多语言检索上，三者合用的平均nDCG@10为71.5，仅稠密为69.2，mE5-large为66.6，BM25为31.9。在长文档MLDR上，单用稠密只有52.5、低于BM25的53.6，稀疏为62.2，合用为65.0，说明长文档里词匹配信号仍然重要。

局限与后续

  • 多向量模式要为每个token存一个向量，索引体积和检索开销比单向量大得多，实际部署多数只用稠密或稠密加稀疏。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 长文档上单靠稠密向量仍不如BM25，长文本被压缩成一个向量时信息损失明显。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 竞争
    BM251994 · NLP
    在长文档检索上，单用稠密向量不如BM25，加入学习式稀疏分数后才超过它。
  • 使用
    ColBERT后期交互2020.04 · 推理·智能体
    多向量检索部分采用ColBERT的逐token后期交互打分。
  • 延续
    SPLADE学习式稀疏检索2021.07 · 推理·智能体
    沿用SPLADE用神经网络学习词权重做稀疏检索的思路，但与稠密、多向量共享一个编码器联合训练。
  • 竞争
    E5文本嵌入2022.12 · LLM
    以多语言E5（mE5-large）为主要开源对照，MIRACL上平均nDCG@10高出约5个点。
  • 延续
    BGE嵌入模型2023.09 · 推理·智能体
    同一团队的BGE系列从中英文短文本扩展到100多种语言、8192长度，并加入稀疏与多向量输出。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

嵌入向量 对比学习 知识蒸馏 检索与向量数据库 自注意力与多头注意力

怎么学

先读ColBERT后期交互和SPLADE学习式稀疏检索，弄清三种检索方式的区别 → 读原文第3节（三种打分与自知识蒸馏）和MLDR长文档表 → 动手：用开源模型对同一批文档分别取稠密、稀疏、合用分数，比较召回率差异。
