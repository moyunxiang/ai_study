BabyAGI任务驱动智能体

Task-driven Autonomous Agent Utilizing GPT-4, Pinecone, and LangChain for Diverse Applications
2023.03系统延伸Yohei Nakajima（个人项目）待核对
原始文章 ↗原始仓库存档 ↗在交互版中打开（演化树、学习进度）

问题

ChatGPT一问一答，要完成一个大目标得由人不断拆任务、追问；能不能只给一个目标，让模型自己列任务、做任务、再根据结果想下一步？

方法

用一个无限循环和一张任务队列：执行智能体完成队首任务，结果存进向量数据库作为记忆；任务创建智能体据结果生成新任务；排序智能体重新排列队列，如此往复。

影响

与AutoGPT同在2023年3–4月出现，用一个很短的Python脚本把「目标→任务列表→执行→再规划」的循环演示出来，成为早期自主智能体的两个代表之一，也暴露了这类系统容易跑偏、无限循环的问题。

方法

2023年3月28日，Yohei Nakajima发布了一篇由GPT-4根据代码撰写的说明文章《Task-driven Autonomous Agent Utilizing GPT-4, Pinecone, and LangChain for Diverse Applications》，随后在4月初开源精简版脚本，取名BabyAGI。

脚本的主循环只有四步：

  • 从任务列表取出第一个任务；
  • 执行智能体：把总目标、当前任务和从向量库取回的相关历史结果放进提示，调用OpenAI API完成任务；
  • 把结果做嵌入，存入向量数据库（最初用Pinecone，后来支持Chroma、Weaviate），供之后检索；
  • 任务创建智能体根据目标和刚才的结果提出新任务，排序智能体把整个任务列表重新排序，然后回到第一步。

三个「智能体」其实是同一个模型的三种提示，体现了把LLM当作规划器和执行器循环调用的想法。它和AutoGPT与自主智能体热潮一起让「自主智能体」成为2023年的热门话题；《LLM Powered Autonomous Agents》把这类系统归纳为规划、记忆、工具使用三个组成部分。原仓库于2024年9月归档，作者另起了一个「自我构建」的新版BabyAGI框架。

局限与后续

  • 没有可靠的停止条件和进度检查，常常不断生成新任务、在无关方向上打转，持续运行还会快速消耗API费用。
    后来针对它的工作　《Building Effective Agents》
  • 只会调用语言模型本身，早期版本不能真正上网、运行代码或操作文件，「完成任务」多半只是生成文字。
    后来针对它的工作　函数调用成为标准接口
