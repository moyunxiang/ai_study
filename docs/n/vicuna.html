Vicuna与ShareGPT

Vicuna: An Open-Source Chatbot Impressing GPT-4 with 90%* ChatGPT Quality
2023.03系统重要LMSYS博客 2023-03-30LMSYS（Wei-Lin Chiang, Zhuohan Li, Zi Lin, Ying Sheng, Zhanghao Wu, Hao Zhang, Lianmin Zheng, Siyuan Zhuang et al.） · UC Berkeley / CMU / Stanford / UC San Diego / MBZUAI待核对
LMSYS博客 ↗FastChat代码 ↗后续评测论文MT-Bench ↗在交互版中打开（演化树、学习进度）

问题

ChatGPT的训练细节和数据不公开；开源界的Alpaca只用5.2万条单轮、模板化的合成指令，回答短而浅，也没有可靠的办法评估聊天机器人。

方法

收集用户在ShareGPT网站上自愿分享的约7万段真实ChatGPT多轮对话，在LLaMA-13B上微调，只在助手回复上算损失；评测时让GPT-4当裁判给两个模型的回答打分。

影响

花约300美元训练出当时最受欢迎的开源聊天模型，并引出了“用强模型当评委”的评测方法，直接催生了MT-Bench和Chatbot Arena。

背景

2023年3月，LLaMA的权重在网上流传，斯坦福随即发布Alpaca与廉价指令微调：按Self-Instruct的流程用text-davinci-003生成5.2万条指令数据，微调LLaMA-7B。Alpaca证明了“几百美元做出一个能听指令的模型”，但数据是单轮的、风格单一，最大长度只有512个token，回答往往简短。

与此同时，ChatGPT发布的用户在ShareGPT等网站上分享自己的对话记录。这些是真实用户提出的、多轮的、往往很长的问题，配上ChatGPT的完整回答——恰好是开源界最缺的数据。另一个难题是评测：聊天回答没有标准答案，传统基准测不出谁更好用，请人评又贵又慢。

方法

数据。从ShareGPT收集约7万段对话，把网页HTML转回Markdown，过滤不当和低质量样本，并把超长对话切成能放进上下文的片段。

训练。在Alpaca训练脚本基础上改进：

  • 最大上下文从512扩到2048，以容纳多轮长对话；
  • 多轮对话整段输入，但只对助手（ChatGPT）说的部分计算损失，用户的话只作为条件；
  • 用梯度检查点和FlashAttention缓解显存压力；用PyTorch FSDP在8张A100上训练一天。借助SkyPilot使用云上的廉价抢占式实例，官方称13B模型的训练成本从约1000美元降到约300美元，7B从500美元降到约140美元。

评测。作者写了80道题，分8类（费米估算、角色扮演、编程数学等，每类10题）。每题把两个模型的回答放进同一个提示，让GPT-4比较打分。

结果

按GPT-4裁判的打分，Vicuna-13B达到ChatGPT和Bard质量的90%以上，在90%以上的题目上胜过LLaMA和Alpaca。博客自己在标题的星号里注明这是“有趣但不科学的评测”，并承认GPT-4不擅长评判编程和数学题。官方列出的局限包括推理和数学差、事实准确性和安全性没有专门优化。

后来的发展

Vicuna的评测想法被LMSYS系统化：LLM-as-a-Judge与MT-Bench用80道多轮难题和GPT-4评分，研究了裁判的位置偏差、啰嗦偏差等问题；Chatbot Arena让真实用户对匿名模型两两投票、算Elo评分与两两比较，成为之后几年最受关注的排行榜之一。Vicuna在线演示和Chatbot Arena也是伯克利同期开发的推理引擎vLLM与PagedAttention最早的部署场景。

不久，模仿闭源模型的假象指出：模仿ChatGPT对话的模型主要学到了风格，在模仿数据没覆盖的任务上几乎没有缩小与ChatGPT的能力差距，而人类评审很容易被流畅的风格骗过。ShareGPT类对话数据后来被整理成ShareGPT与LMSYS-Chat-1M。

容易误解的地方

  • “90%的ChatGPT质量”只来自80道题上GPT-4的主观打分，作者自己声明不严谨，不能理解为能力达到ChatGPT的九成。
  • Vicuna本质上是对ChatGPT输出的蒸馏（见知识蒸馏），它的上限受限于LLaMA基座的知识，学到的主要是回答的格式和语气。

局限与后续

  • 评测只有80道题、靠GPT-4单次判断，存在位置偏差和偏爱长回答等问题，结论不可靠。

  • 使用
    ChatGPT发布2022.11 · LLM
    训练数据就是用户分享的ChatGPT对话，相当于蒸馏ChatGPT的回答风格。
  • 使用
    GPT-42023.03 · LLM
    用GPT-4作为裁判比较两个模型的回答，开启了“LLM当评委”的做法。
  • 改进
    OPT-175B2022.05 · LLM
    只是预训练模型：不会遵循指令，容易重复和编造，生成有毒内容的比例高于GPT-3和PaLM。
  • 使用
    FlashAttention2022.05 · 系统·效率
    用FlashAttention和梯度检查点降低2048长度训练的显存占用。
  • 改进
    BLOOM2022.07 · LLM
    只是预训练基座模型，没有经过对话和偏好对齐，直接用作助手时回答质量差；BLOOMZ只做了多任务指令微调。
  • 使用
    LLaMA2023.02 · LLM
    以LLaMA-13B为基座做全参数微调。
  • 改进
    OPT-IML指令元学习2022.12 · LLM
    评测以学术NLP任务为主，模型并不擅长开放式对话和复杂指令遵循；其基座OPT本身能力有限，绝对表现被同期的Flan-T5等超过。
  • 改进
    Flan Collection指令数据2023.01 · LLM
    任务多来自学术NLP数据集，回答偏短、格式化，和真实用户开放式对话的需求差距大，单靠它训练出的模型聊天能力有限。
  • 改进
    Alpaca与廉价指令微调2023.03 · LLM
    用真实用户的多轮长对话代替Alpaca的5.2万条单轮合成指令，上下文从512扩到2048，回答更详细、结构更好。

读懂它需要的概念

指令微调与对话模板 预训练与微调 知识蒸馏 上下文窗口 基准、排行榜与SOTA Elo评分与两两比较

本篇术语

  • ShareGPT　一个让用户一键分享自己ChatGPT对话记录的网站和浏览器插件，2023年成为开源对话数据的主要来源。
  • LLM-as-a-judge　让一个强大的语言模型阅读问题和候选回答，判断哪个更好或打分，用来代替昂贵的人工评测。
  • 抢占式实例　云服务商以大幅折扣出租的闲置GPU，可能随时被收回，需要训练程序能断点续训。

怎么学

先了解Alpaca与廉价指令微调和指令微调与对话模板。读Vicuna博客的Training和Evaluation两节，再读LLM-as-a-Judge与MT-Bench论文第3节对裁判偏差的分析。动手：用FastChat的对话模板处理几段多轮对话，写出“只在助手回复上计算损失”的标签掩码。
