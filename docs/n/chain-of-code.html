代码链CoC

Chain of Code: Reasoning with a Language Model-Augmented Code Emulator
2023.12论文延伸Chengshu Li, Jacky Liang, Andy Zeng, Xinyun Chen, Karol Hausman, Dorsa Sadigh, Sergey Levine, Li Fei-Fei et al. · 斯坦福大学 / Google DeepMind / UC伯克利待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

让模型写程序再交给解释器执行，算术和逻辑很准，但遇到“判断这句话是不是讽刺”这类语义子任务，根本写不出可执行的函数，整段程序就跑不起来。

方法

让模型照常写代码，解释器逐行执行；某一行执行失败（比如调用了未定义的is_sarcastic函数），就交给LM假装成解释器，直接写出这一行运行后的变量值，再接着往下跑。

影响

在BIG-Bench Hard上达到84%，比思维链高12个点，超过人类评分者平均的68%，把“用代码推理”从纯计算题扩展到计算与语义混合的题。

方法

以论文中的例子说明：问题是“这篇文章里有几处讽刺”。模型写出伪代码：answer = 0，然后对每句话answer += is_sarcastic(句子)，最后输出answer。Python解释器逐行用try/except执行，并维护一份共享的程序状态（各变量当前的值）。第一行能执行，正常更新状态；is_sarcastic没有定义，执行报错，这时把问题、之前的代码和状态交给LM，让它充当LMulator（LM模拟的解释器），直接给出这一行执行后的状态，比如判断这句是讽刺、answer加1；然后再交还给解释器继续执行，直到answer被赋值。

这样，能精确计算的部分交给真解释器，说不清规则的语义判断交给模型，两者在同一段程序里交替进行，模型写代码时也不必担心每个函数都能真正实现。相比之下，PAL/PoT程序辅助推理要求整段代码都能执行，思维链CoT则全部用自然语言推理、计算容易出错。

在BIG-Bench Hard上（text-davinci-003，单任务示例）：直接回答55%、思维链72%、Chain of Code 84%，人类评分者平均68%；换用PaLM 2-S*时，三者分别为49%、61%、78%。作者还在一台机械臂上测试了七个抓取放置任务，如按饮食禁忌分拣物品。

局限与后续

  • LMulator写出的变量值没有任何校验，模型模拟错了，后续计算会照样沿用错误的状态；哪些行交给模型、哪些交给解释器，完全取决于代码能否执行。

  • 使用
    BIG-Bench Hard2022.10 · 数据·评测

  • 改进
    PAL/PoT程序辅助推理2022.11 · 推理·智能体
    PAL要求程序整段可执行，遇到语义子任务就失效；CoC让LM在执行失败的行上模拟解释器，补上了这一块。
  • 竞争
    Faithful CoT忠实思维链2023.01 · 推理·智能体
    Faithful CoT把问题完整翻译成符号程序交给求解器；CoC允许代码中混有只能由LM判断的部分，覆盖面更广但不保证忠实。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

本篇术语

  • LMulator　由语言模型扮演的“解释器”：遇到不能真正执行的代码行时，由模型直接写出这一行执行后变量应有的值。
  • 程序状态　程序运行到某一行时所有变量的当前取值，CoC在解释器和LM之间来回传递它。

怎么学
