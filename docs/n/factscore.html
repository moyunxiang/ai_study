FActScore原子事实评分

FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation
2023.05论文延伸EMNLP 2023Sewon Min, Kalpesh Krishna, Xinxi Lyu, Mike Lewis, Wen-tau Yih, Pang Wei Koh, Mohit Iyyer, Luke Zettlemoyer et al. · 华盛顿大学 / 马萨诸塞大学阿默斯特分校 / Meta AI / 艾伦人工智能研究所待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

大模型写的长文往往真假混杂，给整段打“对/错”太粗；请人逐句核查又贵又慢，长文生成的事实性缺少可靠又可扩展的评测方法。

方法

把一段生成拆成一条条原子事实（只含一个信息点的短句），逐条判断能否被可靠知识源（如维基百科）支持，以被支持的比例作为FActScore；并训练检索加大模型的自动估计器代替人工。

影响

成为长文事实性评测的标准做法，“拆原子事实再逐条核验”的思路被SAFE/LongFact、VeriScore等后续工作沿用，也常用来评测减少幻觉的方法。

方法

问题。TruthfulQA等基准考短答案，而用户常让模型写人物介绍、报告这类长文，其中既有正确信息也有编造。整段判对错丢失太多信息，人工逐句核查又非常昂贵。

FActScore的定义。先把生成文本拆成原子事实，例如“他1970年出生于纽约，是一名作家”拆成“他1970年出生”“他出生于纽约”“他是作家”三条；再逐条判断是否被知识源支持；被支持事实的比例就是得分，衡量的是事实精确率。作者以人物传记为任务、英文维基百科为知识源，请人对InstructGPT、ChatGPT和带检索的PerplexityAI的生成做了大规模人工评估，例如ChatGPT只有58%。

自动估计。人工评估成本高，作者构建了用检索加强大语言模型逐条核验的自动估计器，与人工FActScore的误差小于2%。用它评测了13个新模型的6,500条生成（若人工评估需约2.6万美元），发现GPT-4和ChatGPT比公开模型更符合事实，Vicuna和Alpaca是公开模型中较好的。

局限与后续

  • 只衡量精确率，不惩罚漏掉重要事实；依赖单一知识源，维基百科没有记载的事实会被误判为不支持；拆分原子事实本身也依赖模型，粒度不同分数会变。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    检索增强生成RAG2020.05 · 推理·智能体
    自动估计器先从维基百科检索相关段落，再让大模型判断每条事实是否被支持。
  • 使用
    InstructGPT与RLHF2022.03 · LLM
    InstructGPT、ChatGPT等是人工评估的主要对象。
  • 延续
    FEVER事实核查2018.03 · 数据·评测
    延续以维基百科为证据判断声明是否被支持的做法，把声明换成模型生成中拆出的原子事实。
  • 改进
    ELI5长篇问答2019.07 · 数据·评测
    参考答案来自论坛用户，质量和准确性参差不齐；用ROUGE对比参考答案很难判断长回答的好坏。
  • 延续
    TruthfulQA2021.09 · 数据·评测
    从短答案的真实性评测扩展到长文生成的逐条事实核验。
  • 改进
    HaluEval幻觉识别2023.05 · 数据·评测
    幻觉样本由ChatGPT生成，带有它特有的语言风格，模型可能靠风格而非事实判断；识别式评测也不等于衡量模型自己生成时的幻觉率。

读懂它需要的概念

幻觉 检索与向量数据库 文本生成的自动指标

本篇术语

  • 原子事实　只表达一个信息点的简短陈述，是逐条核验真假的最小单位。
  • 事实精确率　生成内容中正确事实所占的比例，不考虑漏写了多少事实。

怎么学

先读TruthfulQA和FEVER事实核查。读FActScore原文第3节的定义和人工评估流程；动手让一个模型写一段人物介绍，自己拆成原子事实并对照维基百科算得分。
