XLA编译器

2017.03系统延伸Google TensorFlow团队待核对
OpenXLA（维基） ↗在交互版中打开（演化树、学习进度）

问题

TensorFlow把网络拆成一个个小算子，每个算子单独启动一个GPU/TPU内核，中间结果反复读写显存，大量时间花在搬数据而非计算。

方法

XLA是一个线性代数编译器：把计算图整体拿下来，做算子融合和内存优化，生成针对目标硬件的机器码。

影响

后来成为JAX和TPU的默认后端，并发展为OpenXLA生态（含StableHLO等）。

方法

XLA即Accelerated Linear Algebra。它接收一张计算图，不再逐个算子执行，而是把相邻算子融合成一个内核：例如把逐元素的加法、激活函数合并，让中间结果留在寄存器或片上缓存，不必写回显存。这样减少内核启动次数与显存读写，也使针对形状的专门优化成为可能。

维基百科称它是OpenXLA项目的开源机器学习编译器，目标硬件包括x86-64、ARM64、NVIDIA/AMD/Intel GPU和Google TPU，组件有PJRT运行时接口、StableHLO可移植算子集和Shardy多设备并行系统。它的早期版本与TensorFlow一同使用，之后被JAX直接依赖。

局限与后续

  • 编译需要形状静态已知，形状变化会触发重新编译，首次运行有延迟。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 编译器自身难以扩展到新硬件和新前端，各框架各写一套中间表示。

它建立在什么之上

  • 改进
    TensorFlow2015.11 · 系统·效率 待核对
    为TensorFlow计算图增加整图编译与算子融合，减少内核启动和显存往返。
  • 改进
    NumPy与SciPy2006.10 · 系统·效率
    每个运算立即执行并生成临时数组，a*b + c这类表达式无法融合成一次循环，内存带宽被反复浪费。

后来的相关工作

  • 使用
    TPU v2/v3与TPU Pod2017.05 · 硬件
    TPU程序由XLA编译器从TensorFlow计算图编译生成。
  • 竞争
    TVM深度学习编译器2018.02 · 系统·效率
    XLA是TensorFlow的JIT编译器，主要服务自家后端；TVM面向多框架、多硬件，并在Titan X上的实验中快于TensorFlow XLA。
  • 使用
    体系结构的新黄金时代2018.06 · 硬件
    以XLA把TensorFlow编译到GPU和TPU为例，说明DSL加编译器如何让软件在多种DSA之间移植。
  • 竞争
    PyTorch 2与torch.compile2023.03 · 系统·效率
    XLA要求整图可追踪，适合JAX/TensorFlow的函数式写法；PyTorch 2允许断图回退到Python，以灵活性换取部分优化空间。
  • 延续
    MLIR2020.02 · 系统·效率
    把XLA式的单一中间表示扩展为可自定义的多层方言体系。

怎么学
