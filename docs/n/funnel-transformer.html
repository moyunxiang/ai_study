Funnel-Transformer漏斗压缩

Funnel-Transformer: Filtering out Sequential Redundancy for Efficient Language Processing
2020.06论文延伸NeurIPS 2020Zihang Dai, Guokun Lai, Yiming Yang, Quoc V. Le · CMU、Google Brain待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

BERT类编码器在每一层都保留与输入等长的词级表示，可很多任务（分类、句子匹配）最后只要一个向量；在所有层都保持全长度，计算上有大量冗余。

方法

像卷积网络逐层降低图像分辨率那样，让编码器分几段、每段之后把序列长度池化减半，越往上越短、越省算力；把省下的计算量再投入更深或更宽的模型。需要词级输出时，用一个小解码器把压缩后的表示还原到全长。

影响

第一次系统地在预训练语言模型里压缩序列长度，在相同或更少计算下于文本分类、语言理解、阅读理解上超过标准Transformer；“沿长度压缩”的思路后来被沙漏式Transformer、字节级模型的分层压缩等工作继承。

背景

BERT、XLNet、ELECTRA替换词检测等预训练编码器的计算量与层数、宽度和序列长度成正比，提升能力通常靠加深加宽，代价是更高的预训练成本。计算机视觉里，卷积网络早就通过下采样逐层减少空间分辨率、增加通道，在同样算力下做得更深；语言模型却一直保持全长度。

方法

漏斗编码器：把编码器分成若干块（如三块，每块若干层）。每块结束时，对隐藏序列沿长度做步长为2的平均池化，长度减半。池化只作用在注意力的查询上：下一块第一层的查询是池化后的短序列，键和值仍是池化前的全长序列，这样压缩时还能从全部信息里汇总（作者称为“只池化查询”）。之后各层都在短序列上运算。

计算再投资：由于后面的块长度只有1/2、1/4，同样的计算量可以放更多层。作者在与BERT相同或更少的FLOPs下，构造了更深的漏斗模型（例如B6-6-6表示三块各6层）。

解码器还原：掩码语言建模或ELECTRA式的替换词检测需要每个词都有输出。作者把最后一块的短序列按倍数重复上采样回全长，加上第一块（全长度）的输出作为残差，再经过两层Transformer得到每个词的表示。下游只需要句子级表示的任务可以直接丢掉解码器。

预训练：分别用掩码语言模型和ELECTRA目标预训练，与相应的标准Transformer在相同计算下对比。

结果

在相当或更少的FLOPs下，Funnel-Transformer在多种序列级预测任务上超过标准Transformer，包括文本分类、语言理解（GLUE）和阅读理解。

后来的发展

后来的分层与压缩式架构（沙漏Transformer、字节级模型的分块合并、长文档编码器）都把“沿长度下采样”作为重要设计；但在仅解码器的大语言模型时代，由于每个位置都要生成，长度压缩主要在编码器和字节级模型中使用。

局限与后续

  • 池化是固定步长的，不管哪些位置更重要；需要逐词输出的任务还要额外的解码器，收益随之缩小。

它建立在什么之上

  • 延续
    Transformer2017.06 · LLM
    在标准Transformer编码器中加入沿序列长度的池化。
  • 改进
    BERT2018.10 · LLM
    BERT每层保持全长度表示存在冗余；漏斗结构逐段压缩长度，把省下的计算换成更深的模型。
  • 使用
    ELECTRA替换词检测2020.03 · LLM
    除了掩码语言模型，也用ELECTRA的替换词检测目标预训练并对比。
  • 竞争
    XLNet2019.06 · LLM
    同一作者群体此前的XLNet改预训练目标，Funnel改架构效率。

读懂它需要的概念

Transformer层的结构 自注意力与多头注意力 卷积层、池化与感受野 掩码建模 参数量、计算量与显存

本篇术语

  • 序列池化　把相邻的若干个词的向量合并（如取平均）成一个，使序列变短，就像图像下采样。
  • 只池化查询　压缩时只缩短注意力的查询，键和值仍用压缩前的完整序列，保证压缩后的每个位置能看到全部信息。

怎么学

先懂BERT和卷积网络的下采样；读本文第2节漏斗结构与解码器的示意图；动手：在一个小BERT中间插入一次步长2的平均池化，比较分类任务的精度与计算量。
