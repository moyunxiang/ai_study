TRADE对话状态追踪

Transferable Multi-Domain State Generator for Task-Oriented Dialogue Systems
2019.05论文延伸ACL 2019Chien-Sheng Wu, Andrea Madotto, Ehsan Hosseini-Asl, Caiming Xiong, Richard Socher, Pascale Fung · 香港科技大学、Salesforce Research待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

对话状态追踪通常把每个槽位当成在预先给定的取值表（本体）上做分类，可餐馆名、出发时间这类取值多得无法穷举；MultiWOZ这样的多领域数据有30个（领域，槽位）对和4500多个取值，各领域分开建模又无法共享知识、难以迁移到新领域。

方法

不做分类而是生成：一个在所有领域间共享的编码器读入最近几轮对话，状态生成器以（领域，槽位）的嵌入为起点，用软门控的指针-生成器解码出取值——既可以从词表生成，也可以从对话历史里复制；另有一个三分类的槽位门判断这个槽位是否被提到（需要取值、无、不在乎）。

影响

在MultiWOZ五个领域上取得48.62%的联合目标准确率，为当时最好；在零样本设置下某个未见领域达到60.58%，少样本适应时借助持续学习方法不遗忘旧领域。生成式、不依赖本体的状态追踪随后成为多领域任务型对话的主流做法。

方法

任务。对话状态是一组（领域，槽位，取值）三元组，例如用户先订便宜的市中心餐馆、再找附近景点、最后叫出租车，状态就要逐轮累积：Restaurant(price=cheap, area=centre)、Attraction(area=centre)……其中景点的area可能要从前面讲餐馆的话里推出来（多轮映射）。

结构。对话编码器：把最近l轮的用户话语和系统回复拼成一个序列，用双向GRU编码成H_t。状态生成器：对每个（领域，槽位）对j，用领域嵌入与槽位嵌入之和作为GRU解码器的第一个输入，逐词生成取值。第k步的隐状态h_jk一方面投影到词表得到P_vocab = softmax(E·h_jk)，另一方面对对话历史做注意力得到P_history = softmax(H_t·h_jk)；两者按一个可学习的生成概率p_gen加权：P_final = p_gen·P_vocab + (1−p_gen)·P_history，这就是指针-生成器摘要式的软门控复制。作者解释说，按位置复制不适用，因为正确取值不一定原样出现在话语中；硬门控复制又需要额外监督。槽位门：用第一步的上下文向量做一个三分类（ptr/none/dontcare），只有预测为ptr时才采用生成的取值。由于所有参数在领域间共享，新领域的槽位（如出租车的出发时间）可以借用其他领域学到的「时间」表达。

迁移实验。零样本：训练时完全不见某个领域，测试时直接追踪它的槽位；少样本：用少量新领域数据微调，并比较普通微调、弹性权重巩固（EWC）和梯度情景记忆（GEM）等持续学习方法，看是否会遗忘原有领域。

局限与后续

  • 每一轮都要对全部30个（领域，槽位）对各解码一次，且每次都重新读入对话历史，推理开销随槽位数线性增长。

它建立在什么之上

  • 使用
    RNN编码器-解码器与GRU2014.06 · NLP
    编码器和状态生成器都使用GRU。
  • 使用
    EWC弹性权重巩固2016.12 · 基础
    少样本适应新领域时用弹性权重巩固防止遗忘旧领域。
  • 使用
    指针-生成器摘要2017.04 · NLP
    状态生成器采用软门控的指针-生成器，在生成与从对话历史复制之间按概率混合。
  • 改进
    POMDP对话管理2007.04 · NLP
    观察模型、用户模型和奖励都要人工设计或从少量数据估计，换一个领域就要重新搭建。
  • 延续
    复制机制CopyNet2016.03 · NLP
    沿用序列到序列模型中的复制思想，用来输出不在预定义取值表里的槽位值。
  • 延续
    端到端任务型对话系统2016.04 · NLP
    Wen等的系统用逐槽位的分类式信念追踪器、只针对单一领域；TRADE改为生成式追踪，并在多领域间共享参数。
  • 改进
    神经信念追踪NBT2016.06 · NLP
    需要对每个候选槽值对逐个打分，槽值数很多（如餐馆名、时间）时开销大，也无法处理本体里没有的值。

读懂它需要的概念

编码器-解码器 注意力机制 循环网络与隐状态 Softmax与logits 持续学习与灾难性遗忘 零样本与少样本

本篇术语

  • 联合目标准确率　对话状态追踪的主要指标：一轮中所有（领域，槽位，取值）都预测正确才算对。
  • 本体　任务型对话中预先定义好的领域、槽位及每个槽位所有可能取值的清单。
  • 槽位门　TRADE中判断某个槽位在当前对话里是否被提到、是否用户表示无所谓的三分类器。

怎么学

先读端到端任务型对话系统和指针-生成器摘要的讲解 → 读原文第2节三个模块和第4节零样本、少样本实验 → 动手：用开源代码在MultiWOZ上去掉出租车领域训练，再测试出租车领域的零样本联合准确率。
