ROS机器人操作系统

ROS: an open-source Robot Operating System
2009.05系统重要ICRA 2009 Workshop on Open Source SoftwareMorgan Quigley, Brian Gerkey, Ken Conley, Josh Faust, Tully Foote, Jeremy Leibs, Eric Berger, Rob Wheeler, Andrew Ng · Stanford / Willow Garage / USC待核对

问题

每个实验室都为自己的机器人从驱动到规划重写一整套软件，硬件各异、代码无法复用；做规划的人不懂视觉，做视觉的人不懂硬件，集成成本吞掉了研究时间。

方法

做一个跨机器、跨语言的通信层：每个功能是一个独立进程（节点），通过有类型的消息在“话题”上发布/订阅，或用“服务”请求/应答；消息格式用极简的描述文件自动生成各语言代码。

影响

成为学术界和不少企业机器人软件的事实标准，形成了驱动、导航、SLAM、可视化、仿真等大量可复用的开源软件包，“装个ROS包就能跑”大幅降低了做机器人研究的门槛。

背景

据维基百科，ROS的前身始于斯坦福：Salisbury实验室的博士生Eric Berger和Keenan Wyrobek在做个人机器人项目时发现，同事们总被机器人学的“多面性”拖住——擅长软件的不懂硬件，做路径规划的不会视觉。他们借鉴了Morgan Quigley为斯坦福STAIR机器人写的switchyard系统，想做一个“其他人可以在上面继续搭建”的基础平台。2007年1月成立的Willow Garage邀请他们加入，2007年11月7日ROS的第一次代码提交上传到SourceForge。

此前已有Player、CARMEN等机器人软件框架，各自为特定目的设计；论文指出，依赖中心服务器的设计在机载电脑与外部工作站组成的异构网络里不好用。

方法

论文把设计目标概括为五条：点对点、基于工具、多语言、“薄”、自由开源。

通信模型。系统由许多进程（节点）组成，可分布在多台主机上。节点之间传递消息，即严格类型化的数据结构，可以嵌套。一个节点把消息发布到某个命名的话题（topic），所有订阅该话题的节点都会收到；一个话题可有多个发布者和订阅者，发布者不需要知道谁在听。需要一问一答时用服务（service）：一个名字加一对请求/响应消息类型。一个名为master的名字服务只负责让节点互相找到，数据直接在节点之间点对点传输。

多语言。消息用一种极简的接口描述语言定义，例如点云消息只有三行：Header header、Point32[] pts、ChannelFloat32[] chan。代码生成器把它自动展开成137行C++、96行Python、81行Lisp和99行Octave代码，并自动处理序列化。论文写作时已有400多种消息类型。

工具与软件包。核心尽量小，日志、可视化、绘图等都做成独立工具；消息流可以录制到磁盘（bag文件）再回放，方便离线调试算法。软件按“包”组织：一个目录加一个声明依赖的XML文件。ROS直接复用已有开源项目，如Player的驱动与导航、OpenCV视觉库的视觉算法、OpenRAVE的规划算法。

结果

维基百科记录：2008年12月PR2实现连续两天、π公里的连续导航；2010年1月发布ROS 1.0，2010年3月2日发布第一个正式发行版Box Turtle；Willow Garage向11家机构赠送了Willow Garage PR2机器人；2011年ROS仓库数超过100个，2012年首届ROSCon召开，第一款运行ROS的商用机器人Baxter发布，同年12月ROS已在七大洲运行。2013年开源机器人基金会（OSRF）接管维护。

后来的发展

ROS把机器人软件变成了“乐高”：导航栈、建图（包含《概率机器人》中的粒子滤波定位等算法）、机械臂运动规划、仿真接口都有现成的包，研究者可以只替换自己关心的那一块。大量数据集和学习系统都以ROS的bag格式采集数据。

它的局限后来推动了ROS 2的重写：原版不是实时系统，依赖单一master、缺乏安全机制。深度学习时代，以模型和数据为中心的工具链（如Hugging Face LeRobot和Open X-Embodiment统一的数据格式）在ROS之外兴起，但底层驱动和传感器接口仍大多走ROS。

局限与后续

  • 不是实时操作系统，消息传输延迟不确定，硬实时的底层控制仍需在ROS之外实现；依赖单一master，也没有内建的安全认证。

读懂它需要的概念

图、树与搜索 状态、观测与动作 控制回路与控制频率

本篇术语

  • 发布/订阅（pub/sub）　一种通信方式：发送方把消息发到一个命名的频道（话题），所有订阅该频道的接收方都会收到，双方不需要知道对方是谁。
  • 中间件　介于操作系统和应用程序之间的软件层，负责进程间通信、数据格式转换等通用功能。ROS名字里有“操作系统”，实际是中间件。
  • bag文件　ROS录制的消息流文件，可以按原时间顺序回放，相当于机器人传感器数据的“录像带”，是离线调试和制作数据集的常用方式。

怎么学

读原论文第2节（五条设计目标）和第3节（节点、消息、话题、服务）。然后按官方ROS 2教程写一个发布者和一个订阅者节点，用命令行工具查看话题图；再录一个bag文件并回放。体会“话题”如何让替换某个模块（比如换一个定位算法）不影响其他模块。
