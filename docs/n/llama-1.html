LLaMA

LLaMA: Open and Efficient Foundation Language Models
2023.02论文重要arXiv 2023Hugo Touvron, Thibaut Lavril, Gautier Izacard, Xavier Martinet, Marie-Anne Lachaux, Timothée Lacroix, Baptiste Rozière, Naman Goyal et al. · Meta AI待核对
arXiv ↗Meta官方发布 ↗在交互版中打开（演化树、学习进度）

问题

最强的语言模型都是千亿参数、用私有数据训练、权重不公开；按Chinchilla的“算力最优”配方训练的模型，推理时依然又大又贵。

方法

不追求训练算力最优，而是追求推理成本最低：用只含公开数据的1.0–1.4万亿token，把7B–65B的“小”模型训练得远超常规时长，并把权重开放给研究者。

影响

13B模型在多数基准上超过175B的GPT-3，一张GPU就能跑；权重流出后迅速成为整个开源大模型生态的底座，Alpaca、Vicuna、llama.cpp都建立在它上面。

背景

2022年的大模型竞赛主要比参数量：GPT-3175B、Gopher280B、PaLM540B，都用不公开的数据训练，外界拿不到权重。公开权重的OPT-175B和BLOOM规模相当，但效果明显落后。

Chinchilla指出，给定训练算力，参数量和训练token应同比例增加，大约每个参数20个token。但这个“最优”只针对训练成本。模型训练一次，却要被调用无数次，推理成本取决于参数量。按Chinchilla的建议，10B模型训练200B个token就够；LLaMA作者发现7B模型训练到1T个token后效果仍在提升——在小模型上多花训练算力，换来的是更便宜的推理。

方法

数据只用公开来源。约1.4T个token：网页CommonCrawl占67%，C4占15%，GitHub、维基百科、书籍各4.5%，arXiv 2.5%，StackExchange 2%。大部分token只看一遍，维基百科和书籍约看两遍。分词用SentencePiece实现的分词与token（BPE），把数字拆成单个数位。

结构。在标准解码器Transformer上采用当时各家验证过的三处改进：

  • 归一化放在每个子层之前（Pre-LN Transformer），并用更省计算的RMSNorm；
  • 前馈层的ReLU换成GLU变体与SwiGLU；
  • 去掉绝对位置嵌入，每层对Q、K施加旋转位置编码RoPE旋转。

规模与训练。四个尺寸：6.7B、13B、32.5B、65.2B。前两个训练1.0T个token，后两个1.4T。用AdamW和余弦学习率衰减，并用高效的因果注意力实现和手写反向传播减少显存与计算。65B模型在2048张A100 80GB上每卡每秒约处理380个token，1.4T个token约需21天。上下文长度2048。

结果

LLaMA-13B在常识推理、问答等多数基准上超过GPT-3（175B），参数只有后者的约1/10。65B与Chinchilla-70B、PaLM-540B相当：MMLU五样本准确率63.4%，高于GPT-3的43.9%，低于Chinchilla的67.5%和PaLM-540B的69.3%。代码题HumanEval pass@1为23.7%，与PaLM-62B相当。只用少量指令数据微调后，MMLU升到68.9%。

后来的发展

Meta最初只按个案审批向研究者发放权重、限非商业用途，但一周多后权重就在网上流出（2023年3月初多家媒体报道）。此后几周内，斯坦福用它微调出Alpaca与廉价指令微调，随后有Vicuna与ShareGPT，llama.cpp与本地推理让它在笔记本上运行，QLoRA让单卡可以微调65B。Meta于7月发布可商用的Llama 2。“公开数据＋RMSNorm＋SwiGLU＋RoPE＋超长训练”的配方成了之后几乎所有开源模型的默认设计。

容易误解的地方

  • LLaMA并没有推翻Chinchilla：Chinchilla回答的是“给定训练算力怎样最省”，LLaMA回答的是“考虑推理成本时怎样最省”，两者优化的目标不同。
  • 初版LLaMA不是开源许可证，权重是按申请发放、限非商业研究使用的；广泛流传是因为泄露。

它建立在什么之上

  • 改进
    GPT-32020.05 · LLM 已核对
    13B模型在多数基准上超过175B的GPT-3，且权重可获得、单卡可运行。
  • 改进
    语言模型的规模定律2020.01 · LLM 待核对
    只考虑训练算力，没有计入模型部署后的推理成本；对要服务海量请求的模型，更小、多训的模型反而更划算。
  • 改进
    AdamW2017.11 · 基础
    实验只覆盖CIFAR-10和ImageNet32x32两类图像分类，在语言模型等任务上是否同样有效当时没有验证。
  • 使用
    Pre-LN Transformer2020.02 · LLM
    把归一化放在子层之前以稳定训练，沿用GPT-3的做法。
  • 使用
    GLU变体与SwiGLU2020.02 · 基础
    前馈层用SwiGLU激活，沿用PaLM的选择。
  • 使用
    旋转位置编码RoPE2021.04 · LLM
    用RoPE代替绝对位置嵌入，使其成为之后开源模型的标准位置编码。
  • 改进
    Chinchilla2022.03 · LLM
    沿用“多给数据”的思路，但把目标从训练算力最优改成推理成本最优，小模型训练到远超Chinchilla建议的token数。
  • 改进
    PaLM2022.04 · LLM
    5400亿参数只训练7800亿token，按同期Chinchilla的结论远未达到计算最优，推理成本也极高。
  • 改进
    OPT-175B2022.05 · LLM
    1750亿参数只训练了约1800亿token，远未达到计算最优，同等算力可以训出更强的小模型。
  • 改进
    涌现能力2022.06 · LLM
    以算力或参数为横轴，忽略了数据质量和训练方法；更好的数据能让小模型提前获得同样的能力。
  • 竞争
    BLOOM2022.07 · LLM
    BLOOM走“大而多语言”路线，只训练了366B个token；LLaMA走“小而训练充分”路线并胜出。
  • 改进
    GPT-J-6B2021.06 · LLM
    规模只有6B，能力明显弱于GPT-3 175B，没有经过指令或对齐训练。
  • 改进
    MT-NLG 530B2022.01 · LLM
    训练需要数千块GPU的专用集群，复现门槛极高，也没有开放权重。
  • 改进
    GPT-NeoX-20B2022.04 · LLM
    模型规模和数据量按旧的缩放规律设定，后来Chinchilla表明训练token数偏少。
  • 改进
    UL2混合去噪2022.05 · LLM
    之后的主流大模型选择了更简单的纯解码器加自回归，没有采纳混合去噪。
  • 改进
    nanoGPT2022.12 · 系统·效率
    只是教学级实现，缺少现代技巧（长上下文、RoPE、GQA等）。

读懂它需要的概念

语言模型 Transformer层的结构 幂律与规模定律 参数量、计算量与显存 分词与token 位置编码 训练与推理的算力差别

本篇术语

  • 推理预算　模型部署后每次调用所需的计算和显存。参数越少推理越便宜，所以宁愿训练时多花算力，把小模型训得更好。
  • 权重泄露　本应受控发放的模型参数文件被人公开传播。LLaMA权重在发布后不到两周就在网上流传。

怎么学

先读Chinchilla理解训练算力最优，再读本文第2节（数据表1、结构改动、训练效率）和表2、表9。动手：在nanoGPT上依次把LayerNorm换成RMSNorm、GELU换成SwiGLU、位置嵌入换成RoPE，每次比较同样步数下的验证损失。
