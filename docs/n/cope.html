CoPE上下文位置编码

Contextual Position Encoding: Learning to Count What's Important
2024.05论文延伸Olga Golovneva, Tianlu Wang, Jason Weston, Sainbayar Sukhbaatar · Meta FAIR待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

现有位置编码都按词元个数计算位置，模型能注意“第i个词元”，却没法直接注意“第i个句子”“第i个名词”；而词元数与句子、单词的对应关系随内容变化，计数类和选择性复制类任务因此常常失败。

方法

让位置本身取决于上下文：对每个查询，模型用一个门控判断前面每个词元是否“值得计数”，位置等于从该词元到当前词元之间门控值的累加；位置可以是小数，用相邻两个整数位置的嵌入插值得到位置向量，再加进注意力打分。

影响

把“数什么”交给模型学习，同一套机制可以按词元、按单词、按句子甚至按特定类别计位置，在选择性复制、计数和Flip-Flop等标准位置编码失败的任务上解决问题，并改善语言建模和代码建模的困惑度，是位置编码研究中常被引用的新思路。

背景

Transformer的注意力本身不区分顺序，需要位置编码。绝对位置编码给第几个词元一个向量；相对位置表示、旋转位置编码RoPE、ALiBi线性偏置位置改用两个词元之间的词元距离。这些方法都以“词元个数”为单位。当任务需要“回到上一个句子的开头”或“数一数出现了几个某类词”时，模型只能间接地从内容中推断，而训练分布外的句长又会让这种推断失效。

方法

门控：对查询位置i和它之前的每个位置j，计算 g_ij = σ(q_iᵀ k_j) σ是sigmoid，结果在0到1之间。g_ij接近1表示“j这个词元要计数”，接近0表示跳过。门控用的就是注意力里的查询和键，所以不同的注意力头可以学会数不同的东西，例如一个头只在句号处计数，从而以句子为单位。

上下文位置：j相对于i的位置定义为 p_ij = Σ_{k=j..i} g_ik 即从j到i之间被计数的词元个数。若所有门控都为1，就退化为普通的相对位置。

小数位置的嵌入：p_ij一般不是整数，不能直接查表。CoPE为整数位置0…T各学一个嵌入向量e[p]，对小数位置用相邻两个整数的嵌入线性插值 e[p_ij] = (p_ij − ⌊p_ij⌋)·e[⌈p_ij⌉] + (1 − p_ij + ⌊p_ij⌋)·e[⌊p_ij⌋] 实现上先算q_iᵀe[p]对所有整数p的值再插值，降低开销。

加入注意力：注意力打分变为 a_ij = softmax(q_iᵀ k_j + q_iᵀ e[p_ij])，其余计算不变。

结果

CoPE能解决选择性复制、计数和Flip-Flop等任务，而常用的位置编码在这些任务上失败；在语言建模（维基百科文本）和代码建模任务上，CoPE改善了困惑度。

后来的发展

CoPE代表了“位置应由内容决定”的一类思路，后来关于可学习、数据相关的位置编码和长度泛化的研究常把它作为对照；它也说明了计数类失败在一定程度上源于位置编码，而不只是模型容量。

局限与后续

  • 每个查询都要对前面所有位置算门控并累加，计算和显存开销高于RoPE，难以直接用于高效注意力内核和超长上下文。

它建立在什么之上

  • 延续
    Transformer2017.06 · LLM
    改写注意力打分中的位置项，其余结构不变。
  • 竞争
    旋转位置编码RoPE2021.04 · LLM
    RoPE按词元距离旋转向量；CoPE按上下文决定的计数距离给位置，更通用但更贵。
  • 竞争
    ALiBi线性偏置位置2021.08 · LLM
    ALiBi按词元距离线性减分，同样只能以词元为单位。
  • 延续
    相对位置表示2018.03 · LLM
    保留相对位置的形式，但把“距离”从词元个数换成门控加权的计数。

读懂它需要的概念

位置编码 自注意力与多头注意力 查询、键与值（Q/K/V） 门控机制 嵌入向量

本篇术语

  • Flip-Flop任务　序列中交替出现写入、忽略和读取指令，模型需在读取时给出最近一次写入的值；用来测试模型能否精确追踪状态。
  • 选择性复制　从混有干扰词的序列中只按顺序复制出特定的词，需要按内容而非按位置计数。

怎么学

先读旋转位置编码RoPE和相对位置表示；读本文第3节门控、累加和插值三个公式；动手：在一个“数前面出现了几个某字母”的合成任务上，比较RoPE和CoPE的小模型。
