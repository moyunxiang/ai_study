《Deep RL that Matters》复现性批评

Deep Reinforcement Learning that Matters
2017.09论文重要AAAI 2018Henderson, Islam, Bachman, Pineau, Precup, Meger · 麦吉尔大学 / Microsoft Maluuba待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

深度RL论文数量激增，但同一算法在不同论文里的数字差别巨大：随机种子、网络结构、奖励缩放、代码库的差异往往没有报告，“超过SOTA”是否真实无从判断。

方法

系统地做对照实验，把TRPO、PPO、DDPG、ACKTR的结果拆解到每个“外部因素”上，量化它们对结论的影响，并引入自助法置信区间、显著性检验和功效分析来规范评测与报告。

影响

让“多种子、报告置信区间、公开代码与超参数”成为深度RL的基本要求，直接推动了统计悬崖边的深度RL评测等更严格的评测方法和CleanRL单文件实现式的透明实现。

背景

2015–2017年，TRPO、DDPG、PPO等连续控制算法几乎都在MuJoCo的同一批任务上比较（见基准、排行榜与SOTA），新论文常声称比基线高出一截。但强化学习的训练过程本身随机性极大：网络初始化、环境随机性、探索噪声都会让同一份代码每次跑出不同的曲线。许多论文只跑3个甚至更少的种子，有时只报告其中最好的几次，基线也常常是作者自己重新实现、未必调好的版本。作者想回答：这些因素到底能让结果相差多少？

方法

实验主要用OpenAI Baselines（OpenAI Baselines与A2C）中的TRPO、PPO、DDPG、ACKTR，在Hopper和HalfCheetah等MuJoCo任务上，一次只改变一个因素：

  • 网络结构与激活函数：策略和价值网络在(64,64)、(100,50,25)、(400,300)等结构与tanh、ReLU、Leaky ReLU之间组合。
  • 奖励缩放：把奖励乘以不同系数，看DDPG（加与不加LayerNorm）的表现变化。
  • 随机种子：同一超参数跑10次，只改种子，随机分成两组各5次，分别取平均。
  • 环境：同一算法在不同任务上的排名是否一致。
  • 代码库：比较TRPO的原始代码、rllab版、Baselines版，以及DDPG的三个开源实现。

然后讨论评测指标：只报最大回报、或只报平均回报而不给波动范围，都会误导。论文建议用自助法（bootstrap，有放回地重采样估计置信区间，见方差、种子与统计显著性）、t检验、KS检验，以及用功效分析估计需要多少次试验。

结果

结论几乎在每个维度上都是“影响很大”。网络结构和激活函数能让同一算法的最终分数成倍变化，且最佳选择因算法和环境而异。最醒目的是种子实验：同样的代码和超参数跑10次、随机分成两组各5次取平均，在HalfCheetah上两条平均曲线就能显著不同（两样本t检验t=−9.09，p=0.0016），足以“证明”一个并不存在的改进。不同代码库实现的同一算法，在200万样本后的最终表现差异也很大，而这些实现差异在原论文中通常没有写出。算法排名也随环境改变，没有一个算法在所有任务上都最好。

后来的发展

这篇论文之后，报告更多随机种子、置信区间和完整超参数逐渐成为深度RL论文的常规做法。后续工作把它的方法论推进了一步：PPO的实现细节之争细查PPO的代码层面优化，发现它们才是PPO胜过TRPO的主要原因；统计悬崖边的深度RL评测针对Atari等基准提出用分层自助法置信区间、四分位均值和表现分布来汇总少量种子的结果；CleanRL单文件实现则用单文件实现让每个细节都可见。

读懂它需要的概念

方差、种子与统计显著性 基准、排行榜与SOTA 超参数与调参 基线与消融实验 策略梯度

本篇术语

  • 随机种子　决定程序里所有“随机”数值序列的初始值。换一个种子，网络初始化、探索噪声、环境随机性都会变。
  • 自助法（bootstrap）　从已有的少量结果中有放回地反复重采样，估计平均值的置信区间，不需要假设结果服从正态分布。
  • 功效分析　估计要跑多少次实验，才能以足够大的概率检测出某个大小的真实差异。

怎么学

先补方差、种子与统计显著性和基线与消融实验。读原文“Random Seeds and Trials”和“Reporting Evaluation Metrics”两节。动手：用同一份PPO代码在HalfCheetah上跑10个种子，随机分成两组各5个画平均曲线，亲手复现“同一算法两组结果显著不同”，再用rliable库计算四分位均值的置信区间。
