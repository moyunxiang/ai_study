CUDA

2006.11系统主干2006年11月8日发布；2007年2月16日开发包公开测试版Ian Buck, John Nickolls 等 · NVIDIA来源已核对
NVIDIA新闻稿（2006-11-08，存档） ↗NVIDIA新闻稿：CUDA SDK公开测试版（2007-02-16，存档） ↗Nickolls等：Scalable Parallel Programming with CUDA（ACM Queue 2008） ↗CUDA Programming Guide ↗在交互版中打开（演化树、学习进度）

问题

GPU已有数百GFLOPS的算力，但要用它做通用计算，只能通过OpenGL/DirectX把数据伪装成纹理、把算法写成像素着色器，线程间不能通信，普通程序员用不了。

方法

给GPU配一套C语言扩展和编译器：程序员写一个“对单个元素做什么”的内核函数，按网格—线程块—线程三级结构一次启动成千上万个线程，块内线程可以共享片上内存并同步。

影响

GPU从图形卡变成通用并行计算机。2009–2012年的几项深度学习工作用CUDA在GPU上获得几十倍提速，训练了当时少见的大网络；此后主流深度学习框架的GPU后端都以CUDA为主，它也常被认为是NVIDIA最难被替代的优势。

背景

Dennard缩放终结与并行转向以后，CPU单核不再自动变快，额外的晶体管只能变成更多并行单元。GPU天然就是这样的芯片：GeForce 256：第一块GPU起GPU承担几何计算，GeForce 3可编程着色器让着色器可以编程，算力很快超过CPU。

但这时的“GPGPU”（用GPU做通用计算）非常别扭。想算两个数组相加，要把数组存成纹理图片，画一个覆盖整个屏幕的矩形，让像素着色器对每个像素读两张纹理、写出结果。每个着色器程序只能写自己那个像素，不能随意写内存的其他位置，线程之间也无法交换中间结果。斯坦福的BrookGPU与GPGPU用“流”和“内核”的抽象把图形细节藏了起来，但底下仍要翻译成图形API，受着色器的种种限制。

Brook的作者Ian Buck 2004年加入NVIDIA，与负责GPU计算架构的John Nickolls一起把这套思路改造成CUDA，并且和同时设计的GeForce 8800/G80芯片一起做：硬件直接支持通用线程、共享内存和同步，不再经过图形管线。

方法

内核与线程编号。CUDA是C的一组扩展。程序员用 __global__ 声明一个内核函数，描述一个线程要做的事，再用 kernel<<<网格大小, 块大小>>>(参数) 一次启动大量线程。每个线程用内置变量算出自己负责哪一个元素：

i = blockIdx.x × blockDim.x + threadIdx.x

例如两个长度为100万的数组相加，每块256个线程、共3907块，每个线程只做 c[i] = a[i] + b[i] 一件事。

三级层次。线程组成线程块，线程块组成网格。同一块内的线程运行在同一个SM（流多处理器）上，可以读写一块很快的共享内存（G80上每个SM 16KB），并用 __syncthreads() 屏障同步；不同块之间互不依赖，可以按任意顺序执行。正因为块彼此独立，同一个程序放到SM多或少的GPU上都能运行，SM越多跑得越快，这就是CUDA所说的“可扩展”。

硬件如何执行。SM把线程按32个一组（warp）调度，同一warp执行同一条指令、处理不同数据，NVIDIA称之为SIMT（单指令多线程）。某个warp在等显存时，SM立即换另一个warp执行，所以一个SM上同时驻留几百个线程（计算能力1.0最多768个）来掩盖显存延迟。

内存层次。寄存器（每线程私有）→ 共享内存（块内共享，片上）→ 全局显存（所有线程可见，容量大但慢）→ 主机内存（要用 cudaMemcpy 经PCIe显式拷贝）。写快程序的关键是减少对全局显存的访问。以矩阵乘为例：每个线程块把A、B各一个16×16的小块读进共享内存，块内每个数被重复使用16次，全局显存的读取量大约降到原来的1/16——这就是后来Roofline性能模型模型里“提高运算强度”的具体做法。

结果

NVIDIA在2006年11月8日发布CUDA，首发于搭载GeForce 8800/G80的GeForce 8800，称其为“业界第一个面向GPU的C编译器开发环境”，宣称一些问题可以比传统方法快到100倍（官方称）。2007年2月16日，开发包和C编译器以公开测试版提供给所有开发者，支持Windows XP和Linux。

对AI最关键的数字来自后来的研究者：2009年GPU训练深度网络基于CUDA编程模型在一块GTX 280上训练深度信念网络，大模型上比双核CPU实现快最多70倍，一个1亿参数的四层网络从几周缩短到一天左右；2012年AlexNet用两块GTX 580：AlexNet的显卡和自己写的GPU卷积代码（cuda-convnet），在5到6天内训完6000万参数的网络，在ILSVRC-2012上取得第一。2026年11月在SC26上纪念CUDA二十周年时，NVIDIA称有超过1100万开发者基于CUDA开发（据IT Brief Asia、Jon Peddie Research报道）。

后来的发展

CUDA之上很快长出一层层软件：2014年的cuDNN把卷积等神经网络算子封装成库，Caffe、Theano与自动微分、TensorFlow、PyTorch都通过它调用GPU；CUTLASS提供可组合的矩阵乘模板；Triton GPU编程语言让研究者用Python写出接近手写CUDA性能的内核；FlashAttention则是“用共享内存分块减少显存读写”这一CUDA基本功在注意力上的应用。2025年NVIDIA又推出了以分块为单位编程的CUDA Tile与cuTile。

硬件也围绕这套模型演进：Tesla计算卡与Fermi把GPU卖进超算和数据中心，V100与Tensor Core加入专做矩阵乘的Tensor Core，NVLink与NVSwitch和HBM高带宽内存补上了多卡通信和显存带宽。竞争者推出了AMD的ROCm（Radeon Instinct与ROCm）、谷歌的Google TPU加XLA编译器，但大量现成代码、库和开发者经验都建立在CUDA上，这种积累常被认为是NVIDIA在AI芯片上长期领先的主要原因之一。

容易误解的地方

  • CUDA不只是一种语言，而是一整套平台：编译器、驱动、运行时、数学库和调试工具。
  • “CUDA核心”是NVIDIA对GPU里标量运算单元的营销叫法，它不能像CPU核心那样独立运行不同的程序。
  • GPU只对能拆成大量相同小任务的计算有优势；分支多、前后强依赖的串行代码放到GPU上反而更慢，还要付出PCIe拷贝的代价。

读懂它需要的概念

CPU、GPU与并行计算 显存、内存带宽与“内存墙” 矩阵乘法与线性变换 吞吐、延迟与批处理 浮点精度：FP32、FP16、BF16、INT8

本篇术语

  • 内核（kernel）　在GPU上被成千上万个线程同时执行的函数。每个线程执行同一份代码，用自己的线程编号决定处理哪部分数据。
  • 线程块与网格　线程块是一组可以共享片上内存、互相同步的线程；网格是一次内核启动中所有线程块的集合，块与块之间互不依赖。
  • 共享内存　每个SM上一小块由程序员显式读写的高速存储，速度接近寄存器，供同一线程块的线程交换和复用数据。
  • SIMT　单指令多线程：32个线程组成一个warp，同一时刻执行同一条指令、处理各自的数据；如果线程走了不同的分支，硬件要把两条分支依次执行。

怎么学

先读CPU、GPU与并行计算和显存、内存带宽与“内存墙”，再读GeForce 8800/G80了解硬件。然后读CUDA C++ Programming Guide的“Programming Model”一章，弄清网格、线程块、线程和三类内存。动手：先写一个向量加法内核并与CPU版本比时间（注意把拷贝时间单独计入），再写矩阵乘的朴素版和共享内存分块版，用不同矩阵大小测速，最后对照Roofline性能模型解释两者为什么差那么多。没有NVIDIA显卡可以用Google Colab的免费GPU。
