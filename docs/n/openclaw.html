OpenClaw个人智能体

2025.11系统重要Peter Steinberger及开源社区 · 后由OpenClaw Foundation维护待核对
GitHub ↗Introducing OpenClaw（改名公告） ↗TechCrunch：Clawdbot/Moltbot是什么 ↗维基百科 ↗在交互版中打开（演化树、学习进度）

问题

编码智能体已经能在终端里自主干活，但普通人的日常事务——邮件、日历、消息、订票——仍要自己打开一个个应用；大厂助手又把数据放在别人的服务器上。

方法

在自己的电脑上常驻一个智能体网关，从WhatsApp、Telegram等聊天软件里接收指令，接任意大模型，用Markdown文件存记忆、用SKILL.md技能教它用工具，直接在本机执行命令。

影响

一个人的周末项目两个多月拿到二十多万GitHub星，把“替你办事的个人智能体”推成大众话题，同时把智能体权限过大、提示注入的风险暴露在大量普通用户面前。

背景

到2025年下半年，Claude Code与终端编码智能体这类终端智能体已经证明：给大模型一个shell和文件读写权限，它能连续几十分钟自主完成复杂任务；Agent Skills又提供了一种用文件夹给智能体“装技能”的格式。但这些工具面向写代码的人，要坐在电脑前开终端。面向普通人的助手——Siri、ChatGPT agent——要么能力有限，要么运行在厂商的云端虚拟机里，接触不到你本机的文件和账号。

奥地利开发者Peter Steinberger自称“Claude上瘾者”，2025年11月把自己用来“管理数字生活”的私人助手Clawd开源，最初叫Warelay（WhatsApp Relay）。

方法

OpenClaw是一个跑在用户自己机器（笔记本、家庭服务器或VPS）上的开源程序，结构可以分成四块：

  • 网关：一个常驻的后台进程，统一接管WhatsApp、Telegram、Slack、Discord、iMessage等聊天渠道。你在手机上给它发消息，就像给一个助理发微信。
  • 可换的模型：后端接Claude、GPT、DeepSeek、Kimi或本地模型，甚至可以直接复用本机已登录的Claude Code。
  • 记忆是文件：长期记忆写在工作区的MEMORY.md、每日笔记等Markdown文件里，每次新会话开头读入；模型“只记得写进磁盘的东西”，用户可以直接打开编辑。
  • 技能与工具：沿用SKILL.md格式，每个技能是一个目录，写明什么时候、怎样调用某个工具；社区技能可从ClawHub安装。后来也支持连接模型上下文协议MCP服务器。工具默认直接在主机上执行，除非用户自己配置沙箱。

它还能定时主动做事（早期叫heartbeat，读HEARTBEAT.md里的待办），不必等用户开口。

结果

TechCrunch报道，到2026年1月27日已有超过4.42万GitHub星，社交媒体热度甚至让Cloudflare股价盘前上涨14%；两天后作者称已超过10万星、一周内200万访客。到3月2日为24.7万星、4.77万个fork。因Anthropic商标投诉，1月27日改名Moltbot，三天后定名OpenClaw；同期出现了供智能体发帖的社交网站Moltbook。腾讯、智谱等中国公司推出了基于它的服务。2月14日Steinberger宣布加入OpenAI，项目移交给非营利基金会。

后来的发展

它让“常驻、主动、能动你本机一切的个人智能体”成为各家竞相跟进的方向，2026年1月12日Anthropic推出的Claude Cowork同样把编码智能体的能力交给非程序员，但只开放用户指定的文件夹，并在隔离的Linux虚拟机里执行。它同时成了智能体安全问题的公开案例：维基百科援引的报道称，思科测试的一个第三方技能会在用户不知情时外传数据，2026年3月中国限制国企和政府机关使用。2026年4月，Anthropic不再允许Claude订阅额度用于OpenClaw等第三方harness，理由是这类工具占用过多算力。

容易误解的地方

  • OpenClaw本身不是模型，而是一个harness（智能体外壳）：能力取决于接的是哪个大模型。
  • “本地运行”只说明程序和数据在你的机器上，提示词仍会发给所选的模型服务商。
  • 作者自己在改名公告里写明：提示注入仍是全行业未解决的问题。

局限与后续

  • 同时拥有私人数据、读取不可信消息、对外发送和执行命令的能力，正是“致命三要素”；任何人给你发一条带恶意指令的消息都可能操纵它，而工具默认直接在主机上运行。

  • 社区技能市场缺乏审核，第三方技能可以夹带数据外传和提示注入，用户很难自己判断一个技能是否安全。

  • 竞争
    ChatGPT agent2025.07 · 推理·智能体
    ChatGPT agent在厂商云端的虚拟电脑里替用户办事；OpenClaw反其道而行，开源、跑在用户自己的机器上、可换任意模型，代价是安全责任落在用户身上。
  • 延续
    MemGPT2023.10 · 推理·智能体
    同样让智能体自己管理长期记忆，但把记忆做成用户可读可改的Markdown文件，而非数据库里的隐藏状态。
  • 竞争
    智能体的“致命三要素”2025.06 · 安全·可解释

读懂它需要的概念

智能体循环 工具调用 提示注入 上下文窗口

本篇术语

  • harness（智能体外壳）　包在大模型外面、负责循环调用模型、执行工具、管理记忆和权限的程序。同一个模型放进不同harness，表现可以差很多。
  • 网关（Gateway）　OpenClaw里常驻后台的进程，统一连接各个聊天渠道、管理会话和工具调用，用户的所有入口都通过它。

怎么学

先读Claude Code与终端编码智能体和Agent Skills，理解终端智能体和技能格式。然后读OpenClaw仓库README和文档里的Gateway architecture、Memory overview两页，再读智能体的“致命三要素”。动手：在一台隔离的虚拟机里装上它，只接一个测试聊天账号，写一个简单的SKILL.md，观察它如何决定调用技能、又如何把记忆写进MEMORY.md。
