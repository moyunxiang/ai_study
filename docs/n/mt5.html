mT5

mT5: A massively multilingual pre-trained text-to-text transformer
2020.10论文延伸NAACL 2021Linting Xue, Noah Constant, Adam Roberts, Mihir Kale, Rami Al-Rfou, Aditya Siddhant, Aditya Barua, Colin Raffel · Google Research待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

T5的文本到文本框架只用英语数据训练，其他语言要么没有预训练模型，要么得为每种语言各训一个。

方法

把T5的预训练搬到覆盖101种语言的Common Crawl新语料上，得到一个多语言的文本到文本模型。

影响

成为多语言生成与理解的通用开源基线，在多个多语言基准上达到当时最好的成绩。

方法

mT5几乎复刻T5：同样的编码器-解码器、同样的「把所有任务写成文本输入、文本输出」的格式，区别在于训练语料来自新建的Common Crawl多语言数据（mC4），共101种语言，并相应调整了词表和训练设置。

多语言生成模型的一个特有问题是零样本场景下的「意外翻译」：模型被要求用某种语言作答，却自己把答案（部分）翻译成了另一种语言。作者提出一种简单技巧来缓解它。

官方摘要称，mT5在许多多语言基准上取得当时最佳。后来稀疏MoE大模型在101种语言上与mT5-Base做了比较。

局限与后续

  • 多语言共享参数，容量被分摊，高资源语言会拖低低资源语言的表现。
    后来针对它的工作　NLLB两百种语言翻译
  • 语料质量和各语言数据量差距大，真正的低资源语言覆盖仍有限。
    后来针对它的工作　NLLB两百种语言翻译

它建立在什么之上

  • 延续
    T52019.10 · LLM 已核对
    把T5的文本到文本预训练扩展到101种语言。
  • 竞争
    XLM-R2019.11 · LLM
    XLM-R是多语言的编码器式模型，擅长理解；mT5保留编码器-解码器，可以直接生成。
  • 改进
    跨语言预训练XLM2019.01 · LLM
    编码器式的预训练模型不能直接用于生成，需要翻译时仍要另外接解码器。
  • 改进
    mBART多语言去噪预训练2020.01 · LLM
    在资源最丰富的语言对上预训练几乎没有收益；覆盖语言只有25种，语言之间争夺模型容量的问题在更多语言时会更严重。
  • 改进
    XTREME跨语言基准2020.03 · 数据·评测
    设定偏重英语到其他语言的零样本迁移，对真正使用目标语言训练数据的情形覆盖不足。
  • 改进
    清源CPM2020.12 · LLM
    训练数据只有中文，多语言和跨语言能力没有覆盖。

后来的相关工作

  • 改进
    NLLB两百种语言翻译2022.07 · NLP
    多语言共享参数，容量被分摊，高资源语言会拖低低资源语言的表现。
  • 延续
    ByT5字节级模型2021.05 · LLM
    在mT5相同的多语言设置上，把子词词表换成字节，免去词表和分词器。
  • 延续
    BLOOMZ/mT0与xP32022.11 · LLM
    对mT5做同样的微调，得到mT0。

读懂它需要的概念

编码器-解码器 预训练与微调 分词与token 迁移学习 文本生成的自动指标
