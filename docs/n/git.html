GIT生成式图文

GIT: A Generative Image-to-text Transformer for Vision and Language
2022.05论文延伸TMLR 2022Jianfeng Wang, Zhengyuan Yang, Xiaowei Hu, Linjie Li, Kevin Lin, Zhe Gan, Zicheng Liu, Ce Liu, Lijuan Wang · Microsoft待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

当时的视觉-语言模型结构复杂：编码器、融合层、解码器层层叠加，还常依赖外部的检测器、标签器和OCR。

方法

只留一个图像编码器加一个文本解码器，所有任务都当成“看图生成文字”，用单一的语言建模损失训练，再把数据和模型做大。

影响

说明极简的“编码器+解码器+下一词预测”配方在规模足够时就能拿下大量描述和问答基准，这种结构正是后来多模态大模型的基本形态。

方法

2022年前后的视觉-语言模型常有好几个模块：单模态编码器、多模态融合编码器、解码器，预训练要同时用掩码语言建模、图文匹配等多个目标；要读懂图中文字，还要先跑一个OCR系统把文字识别出来喂给模型。

GIT把结构简化到只剩两块：一个用对比学习预训练过的图像编码器，把图像变成一串特征；一个Transformer文本解码器，把图像特征放在序列开头作为前缀，然后逐词预测文字，训练目标只有语言建模（下一词预测）这一项。图像描述直接生成，视觉问答把问题当作前缀、生成答案；视频则把多帧的特征拼起来。作者把预训练图文数据和模型规模一起放大，并提出用生成类别名的方式做图像分类和场景文字识别。它与SimVLM、CoCa同属“生成式预训练”路线，但更加精简。

论文表1报告，GIT在大量描述和问答基准上刷新最好成绩，例如COCO描述CIDEr 148.8，TextCaps上CIDEr 138.2，首次超过人类的125.5；更大的GIT2进一步提高。模型不借助外部OCR就能读出图中文字，靠的是大规模数据和图像编码器本身。

局限与后续

  • 文本解码器规模有限且从头训练，没有大语言模型的知识和推理能力，难以处理需要常识或多步推理的开放问题。

它建立在什么之上

  • 使用
    CLIP2021.01 · 多模态
    图像编码器采用对比学习预训练得到的视觉模型。
  • 改进
    M²网状记忆描述2019.12 · 多模态
    视觉输入仍是离线检测器提取的区域特征，检测器的类别和质量决定了模型能“看见”什么。
  • 延续
    SimVLM2021.08 · 多模态
    同样用单一生成式目标做视觉-语言预训练，GIT进一步去掉编码器-解码器之间的复杂融合结构。
  • 使用
    Florence2021.11 · 多模态
    同属微软团队；论文引言把Florence列为大规模图文对比预训练的代表，GIT的图像编码器就来自这类对比预训练模型。
  • 竞争
    CoCa2022.05 · 多模态
    同期的生成式图文基础模型；CoCa同时保留对比损失，GIT只用语言建模损失。

本篇术语

  • TextCaps　要求描述中准确写出图中文字（如招牌、商品标签）的图像描述数据集，用来考察模型读字的能力。

怎么学

先了解图像描述的评测指标CIDEr，再读GIT原文表1和第2节的模型结构，体会“编码器输出当前缀+下一词预测”的写法；对照读BLIP-2，看接入大语言模型之后这一结构如何演变。
