FLASK细粒度技能评测

FLASK: Fine-grained Language Model Evaluation based on Alignment Skill Sets
2023.07数据集延伸ICLR 2024Seonghyeon Ye, Doyoung Kim, Sungdong Kim, Hyeonbin Hwang, Seungone Kim, Yongrae Jo, James Thorne, Juho Kim, Minjoon Seo · KAIST等待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

评测聊天模型时，通常只给一个总体偏好分或胜率，看不出模型到底是推理差、知识错还是没按用户要求做，也难以解释两个模型差在哪。

方法

把“回答得好不好”拆成一组对齐技能（逻辑正确性、事实性、完整性、可读性等），每道题先标出它需要哪几项技能，再由人或模型逐项打分。

影响

把细粒度、按评分细则打分的思路带进LLM评测，同一团队随后的Prometheus系列开源评审模型直接沿用了这种按细则打分的形式。

方法

背景。LLM-as-a-Judge与MT-Bench和Chatbot Arena给出的是总分或胜率，Alpaca与廉价指令微调式评测只问“哪个回答更好”。这种粗粒度评分不考虑每条指令需要的能力组合：一道数学题主要考逻辑正确，一个写作请求主要考可读性和遵循要求，把它们混成一个分数会掩盖差别，也让不同评审者的打分更难一致。

做法。FLASK定义了一组对齐技能，按大类分为逻辑思维、背景知识、问题处理和用户对齐。评测集从多个现有数据集收集指令，为每条指令标注它涉及的技能、所属领域和难度。评分时，评审者（人类或GPT-4这类模型）只对这条指令相关的几项技能分别打1–5分，并给出理由。这样同一个模型可以画出一张技能雷达图，也可以按领域和难度切片比较。

发现。作者报告：细粒度评分能更完整地反映模型表现，并提高评测的可靠性；基于模型的评分与人工评分高度相关。比较开源和闭源模型时，开源模型在逻辑思维和背景知识上与闭源模型差距更明显。

本篇术语

  • 评分细则　写明每个分数档次对应什么表现的打分说明（rubric），让不同评审者按同一标准打分。

怎么学

先读LLM-as-a-Judge与MT-Bench了解LLM裁判；读FLASK原文的技能定义表和人工—模型评分相关性分析；动手选几条指令，按FLASK的技能清单为两个模型的回答各打一遍分，看分项结论和总分结论是否一致。
