Donut无OCR文档理解

OCR-free Document Understanding Transformer
2021.11论文延伸ECCV 2022Kim, Hong, Yim, Nam, Park, Yim, Hwang, Yun, Han, Park · NAVER待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

文档理解先用OCR读字、再用模型理解，OCR计算昂贵、对语言和版面不灵活，错误还会传递到后续。

方法

用一个Transformer直接读文档图像，生成结构化文字（如JSON），预训练时先学「读字」，完全不依赖外部OCR。

影响

开创了OCR-free文档理解路线，是后来Pix2Struct等视觉文档模型的先声。

方法

Donut（文档理解Transformer）是图像编码器加文字解码器的结构：编码器用Swin Transformer把整页文档图像编码成特征，解码器用BART风格的Transformer逐字生成输出，如一串类似JSON的标记，里面有字段名和值。预训练任务很简单：给一张含文字的图像，让模型把文字按阅读顺序读出来（相当于一个预训练的「读字」能力），之后在具体任务上微调，把输出改成目标结构。

作者在摘要中指出OCR方法的三个痛点：计算成本高、对语言或文档类型不灵活、OCR错误向后传播；Donut用一个端到端模型去除了这些环节。

局限与后续

  • 端到端读字对小字、高分辨率页面成本高。
    后来针对它的工作　Pix2Struct截图解析
  • 没有OCR时，对没见过的语言或字体仍需重新预训练。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 改进
    TextVQA2019.04 · 数据·评测
    答案依赖外部OCR的质量，OCR认错字，后面再强的推理也无济于事。
  • 使用
    BART2019.10 · LLM
    用BART类解码器生成文字。
  • 竞争
    LayoutLM文档理解2019.12 · 多模态
    同为文档理解：LayoutLM依赖OCR输出加版式坐标，Donut完全去掉OCR。
  • 改进
    DocVQA2020.07 · 数据·评测
    早期基线依赖外部OCR再接阅读理解，OCR错误会向后传播，版面信息利用不足。
  • 使用
    Swin Transformer2021.03 · 视觉
    用Swin作图像编码器。

后来的相关工作

  • 改进
    Pix2Struct截图解析2022.10 · 多模态
    沿用OCR-free的图像到文字范式，但预训练目标换成网页截图解析。
  • 延续
    Nougat学术文档2023.08 · 多模态
    在Donut的免OCR框架上专攻科学文档，输出公式友好的标记语言。
