标签平滑

Rethinking the Inception Architecture for Computer Vision
2015.12论文延伸CVPR 2016Szegedy, Vanhoucke, Ioffe, Shlens, Wojna · Google待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

用one-hot标签和交叉熵训练时，模型会把正确类别的logit推向无穷大，产生过度自信，容易过拟合并削弱泛化。

方法

把硬标签换成软标签：正确类别拿到1−ε，剩下的概率均匀分给其他类别，使网络不再追求无限大的logit。

影响

这个只有一行的正则化技巧成了分类、翻译、语音等任务的通用配置，Transformer等模型也沿用。

方法

这篇论文的主体是改进GoogLeNet / Inception的Inception结构，即Inception v3：把大卷积分解成小卷积、不对称卷积，并在辅助分类器上做正则。其中一节提出标签平滑正则（LSR）。

设类别数为K，真实类别为y，原来的目标分布是one-hot，q(k)=1 if k=y else 0。平滑后改写为q′(k) = (1−ε)·q(k) + ε/K，即把一小部分概率ε均匀分给所有类别，再对它计算交叉熵。这样让最优logit差变成有限值，限制了模型的过度自信，也让输出分布更接近“较宽的”分布。

论文称，把它与分解卷积等手段结合，单模型单帧评估在ILSVRC 2012验证集上达到21.2% top-1和5.6% top-5错误，计算量约50亿次乘加、参数不到2500万；四模型集成加多裁剪评估达到3.5% top-5验证错误。这些数字来自整个Inception-v3方案，并不全部来自标签平滑。

局限与后续

  • 平滑强度ε和“均匀分给所有类”的做法是手工设定的，没有区分哪些类别更相近，同时会让输出概率偏小，对依赖精确置信度的任务可能有副作用。
    本站还没有记录针对它的后续工作（不代表没有人解决）
