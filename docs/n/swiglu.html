GLU变体与SwiGLU

GLU Variants Improve Transformer
2020.02论文重要Noam Shazeer · Google待核对
arXiv ↗GLU原始论文（门控卷积语言模型） ↗PaLM论文（大规模采用SwiGLU） ↗在交互版中打开（演化树、学习进度）

问题

Transformer每层的前馈网络一直是“线性—ReLU—线性”，有人把ReLU换成GELU或Swish，但收益很小，没人系统试过把门控结构放进前馈层。

方法

把第一层线性变换换成两路投影相乘：一路过激活函数当“门”，另一路保持线性，FFN = (Swish(xW) ⊗ xV)·W₂，并把隐藏维度缩到2/3以保持参数量不变。

影响

同参数、同计算量下，T5预训练的困惑度和GLUE等下游分数都更好；PaLM、LLaMA随后采用，SwiGLU成为大语言模型前馈层的默认写法。

背景

Transformer的每一层由注意力和逐位置前馈网络（FFN）组成（见Transformer层的结构）。FFN把每个位置的向量先放大到4倍宽，过一个激活函数，再投影回来：FFN(x) = max(0, xW₁)·W₂。FFN占了模型大约三分之二的参数，但它的激活函数几年里基本没变，GELU和Swish/SiLU只带来很小的改进。

另一条线索来自门控卷积语言模型GLU：Dauphin等人2016年提出门控线性单元GLU，GLU(x) = σ(xW) ⊗ xV，即两个线性投影逐元素相乘，其中一个先过sigmoid（见门控机制）。它在卷积语言模型里效果很好，但还没有人把它放进Transformer的FFN。

方法

一族门控前馈层。论文把GLU里的sigmoid换成别的函数，定义了一组变体（均不加偏置）：

FFN_GLU = (σ(xW) ⊗ xV)·W₂ FFN_ReGLU = (max(0, xW) ⊗ xV)·W₂ FFN_GEGLU = (GELU(xW) ⊗ xV)·W₂ FFN_SwiGLU = (Swish(xW) ⊗ xV)·W₂，其中Swish(z) = z·σ(z) FFN_Bilinear = (xW ⊗ xV)·W₂（干脆不用激活）

直观理解：xV是“内容”，激活后的xW是逐元素的“开关”，决定内容的每一维放行多少。与ReLU只能按自身正负截断不同，这里的开关由输入的另一个投影决定。

公平对比。门控版有W、V、W₂三个矩阵，原版只有两个。为了参数量和计算量相同，隐藏宽度d_ff乘以2/3：T5-base里原版d_ff=3072，门控版改为2048。

结果

在T5-base设置（编码器、解码器各12层，d_model=768）上，用C4做片段填空预训练524,288步，留出集对数困惑度：ReLU 1.677，GELU 1.679，Swish 1.683，GLU 1.663，GEGLU 1.633，SwiGLU 1.636。微调到GLUE开发集后平均分ReLU为83.80，SwiGLU为84.36，ReGLU为84.67。作者说明微调结果噪声较大，只各跑了一次。

后来的发展

PaLM原文写明FFN采用SwiGLU，理由正是这篇论文显示它“显著提升质量”，代价是三次矩阵乘法；LLaMA也把ReLU换成SwiGLU，隐藏维度用(2/3)·4d。此后大部分开放大模型沿用这一结构，Mixtral 8x7B等MoE模型的每个专家也是一个这样的门控前馈网络。门控注意力则把门控思路搬到注意力输出上。

容易误解的地方

  • SwiGLU是一种前馈层结构，不是单个激活函数；它比原版多一个权重矩阵，比较时必须把隐藏宽度缩小才公平。
  • 作者在结论里明说“不解释为什么有效”，把成功归于“神的眷顾”；后来的流行主要来自大模型上的实践，而非理论。
  • 各变体之间差距很小，GEGLU在困惑度上与SwiGLU几乎相同。

读懂它需要的概念

Transformer层的结构 门控机制 神经元与激活函数 矩阵乘法与线性变换 参数量、计算量与显存

本篇术语

  • 前馈层（FFN）　Transformer每层里对每个位置单独做的两层全连接网络，先升维再降维。
  • 门控线性单元（GLU）　两个线性投影逐元素相乘，其中一个先经过sigmoid等函数，起到按维度开关信息的作用。
  • 逐元素乘积（⊗）　两个同样长度的向量对应位置相乘，结果仍是同样长度的向量。

怎么学

先补Transformer层的结构和门控机制，看懂原版FFN。原文只有4页，读第2节的公式(4)–(6)和表1。动手：在nanoGPT里把MLP改成SwiGLU（三个无偏置线性层，隐藏宽度取原来的2/3），在小数据上对比验证损失。
