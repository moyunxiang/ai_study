PaLI

PaLI: A Jointly-Scaled Multilingual Language-Image Model
2022.09论文延伸ICLR 2023Chen, Wang, Changpinyo, Piergiovanni, Padlewski, Salz, Goodman, Grycner, Mustafa, Beyer, Kolesnikov, Puigcerver 等 · Google待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

视觉语言模型的视觉部分通常比语言部分小得多，且多只支持英文，缺少像大语言模型那样的统一文本接口。

方法

把大的预训练编码器-解码器语言模型与大的ViT接在一起，联合放大两边，所有任务统一成「图加文字到文字」，并覆盖多种语言。

影响

说明视觉和语言两端要联合扩展，把ViT扩到40亿参数带来额外收益，是后续PaLI-X、PaliGemma的起点。

方法

PaLI（Pathways语言与图像模型）的结构是：一个Vision Transformer把图像变成一串视觉token，作为输入送入预训练的编码器-解码器语言模型（mT5），模型输出文字。因此不论是描述、问答还是OCR类任务，接口都是「图加提示文字，输出文字」，并且可以使用多种语言。

关键发现是联合扩展：现有的文字Transformer比视觉Transformer大得多，作者训练了一个40亿参数的ViT-e来量化更大视觉模型的收益，并发现它确实改善。摘要还提到，训练数据来自一个包含100多种语言的图文数据集，在多种视觉、语言、多模态任务上取得当时最好的成绩。

局限与后续

  • 训练与数据不公开，复现代价高。

  • 每个任务仍需微调，没有对话和遵循指令的能力。

它建立在什么之上

  • 使用
    Vision Transformer2020.10 · 视觉
    用大规模ViT作视觉编码器，并把它放大到40亿参数。
  • 使用
    T52019.10 · LLM
    用T5家族（mT5）的编码器-解码器作语言端。
  • 延续
    SimVLM2021.08 · 多模态
    沿袭图加文字到文字的生成式预训练。
  • 改进
    Florence2021.11 · 多模态
    每个下游任务仍需要单独接头和微调，不是统一接口。
  • 改进
    OFA统一序列模型2022.02 · 多模态
    生成式的统一接口带来较慢的推理，对检测等任务不如专用检测器精确。

后来的相关工作

  • 使用
    RT-2与VLA2023.07 · 具身·世界模型 已核对
    主力模型建立在PaLI的放大版PaLI-X（5B/55B）上，利用它给1000以内整数都单独设token的特点表示动作。
  • 竞争
    GPT-4V2023.09 · 多模态 已核对
    GPT-4博客中的对照之一：PaLI-17B在VQAv2上经微调达84.3%，高于GPT-4零样本的77.2%；TextVQA上PaLI-17B为71.8%，低于GPT-4零样本的78.0%。
  • 改进
    LLaVA2023.04 · 多模态
    每个任务仍需微调，没有对话和遵循指令的能力。
  • 延续
    SpatialVLM2024.01 · 多模态
    在PaLI类视觉语言模型上加入大规模空间推理数据。
  • 改进
    PaliGemma2024.07 · 多模态
    沿用PaLI把所有视觉语言任务统一成图像加文本到文本的做法，但换成开放的Gemma-2B。
