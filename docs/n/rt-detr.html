RT-DETR实时DETR

DETRs Beat YOLOs on Real-time Object Detection
2023.04论文延伸CVPR 2024Yian Zhao, Wenyu Lv, Shangliang Xu, Jinman Wei, Guanzhong Wang, Qingqing Dang, Yi Liu, Jie Chen · 百度 / 北京大学待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

YOLO系列的速度和精度都被后处理NMS拖累；DETR类检测器虽不需要NMS，但计算量太大，没法实时。

方法

设计高效混合编码器，把同尺度内的交互和跨尺度融合拆开做，再用不确定性最小的查询初始化解码器，成为第一个实时的端到端检测器。

影响

让DETR路线首次在实时检测上与YOLO正面竞争，后来的RF-DETR等继续沿这条路线。

方法

论文先指出：YOLO需要NMS（非极大值抑制，去掉重叠的重复框），其耗时和阈值敏感会同时损伤速度与精度。DETR一类模型靠集合预测天然免掉NMS，但多尺度特征上的注意力太贵。

RT-DETR分两步构建。第一步，效率：设计高效混合编码器，把尺度内交互（同一层特征图内的注意力）和跨尺度融合（不同层之间的卷积融合）解耦，不再对所有尺度的所有token做全局注意力，从而省出大量计算。第二步，精度：引入不确定性最小的查询选择，挑选分类与定位置信度一致性更好的编码器特征作为解码器初始查询。另外，通过调整解码器层数，可以在不重新训练的前提下调节推理速度，适应不同场景。

局限与后续

  • 训练仍需要较长的迭代，且依赖预训练骨干，对小数据集的收敛不如YOLO稳定。
    后来针对它的工作　RF-DETR
  • 精度和延迟的搭配仍靠人工设计，没有针对具体硬件自动搜索。
    后来针对它的工作　RF-DETR

它建立在什么之上

  • 改进
    Focal Loss与RetinaNet2017.08 · 视觉
    最好的配置每秒约5帧，远达不到YOLO那样的实时速度。
  • 改进
    DETR2020.05 · 视觉
    推理速度和部署友好度不如YOLO系列，难以用在实时场景。
  • 竞争
    Ultralytics YOLO系列2020.06 · 视觉
    同为实时检测，路线分歧在于YOLO依赖NMS后处理而RT-DETR端到端免NMS。
  • 改进
    Deformable DETR2020.10 · 视觉
    可变形采样的内存访问不规则，实现和硬件效率不如规整的稠密算子。
  • 改进
    DINO（检测）2022.03 · 视觉
    沿用DINO的去噪训练和查询选择思路，但把编码器改成轻量的混合结构。
  • 改进
    OWL-ViT2022.05 · 视觉
    每次检测都要跑完整的大ViT，速度不适合实时场景。
  • 改进
    YOLOv72022.07 · 视觉
    仍依赖非极大值抑制（NMS）后处理，带来额外延迟和需调的阈值。

后来的相关工作

  • 延续
    D-FINE2024.10 · 视觉
    在RT-DETR的实时DETR框架上改造回归头和训练目标。
  • 竞争
    YOLOv122025.02 · 视觉
    RT-DETR把DETR做成实时，YOLOv12把注意力放进YOLO，两条路线争夺同一速度-精度区间。
  • 延续
    RF-DETR2025.11 · 视觉
    沿用实时DETR路线，增加权重共享NAS以适配不同数据集与延迟。
