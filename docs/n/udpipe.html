UDPipe多语言流水线

UDPipe: Trainable Pipeline for Processing CoNLL-U Files Performing Tokenization, Morphological Analysis, POS Tagging and Parsing
2016.05系统延伸LREC 2016Milan Straka, Jan Hajič, Jana Straková · 布拉格查理大学待核对
ACL Anthology ↗官网 ↗在交互版中打开（演化树、学习进度）

问题

Universal Dependencies（UD）提供了几十种语言统一规范的树库，但要真正用它们处理原始文本，还得为每种语言分别拼凑分词器、词形还原器、词性标注器和句法分析器，格式和接口各不相同。

方法

做一条可训练的端到端流水线：从原始文本出发，依次完成分句与分词、形态分析（词形还原、词性、形态特征）和依存分析，全部读写UD的CoNLL-U格式，并直接在每个UD树库上训练出现成模型。

影响

UDPipe为UD的所有树库提供了预训练模型，是CoNLL 2017、2018多语言UD分析共享任务的官方基线；它让「对一种小语种文本做基础句法分析」变成下载一个模型就能完成的事。

背景

Universal Dependencies（2014年起）统一了多语言的词性、形态特征和依存关系标注，CoNLL-U成为通用格式。已有工具如Stanford CoreNLP、MaltParser转移式依存分析器覆盖的语言有限，或者只做其中一步；从原始文本开始的分词（尤其是带缩合词的语言，如西班牙语del=de+el）往往被忽略，评测时假设已有金标准分词。

方法

分句与分词：把分句和分词联合建模为逐字符的标注问题，用双向GRU预测每个字符后是否是词边界、句边界，并处理多词token（一个书面token对应多个句法词）。

形态分析：词形还原与词性、形态特征标注用MorphoDiTa的平均感知机方法，基于词尾猜测规则处理未登录词。

依存分析：使用Parsito——一个转移式依存分析器，用小型前馈神经网络（类似神经网络依存分析）选择动作，支持投射与非投射的转移系统，并可配合动态预言训练。

输入输出：所有步骤都读写CoNLL-U，可以单独使用其中任何一步；提供命令行、C++库和Python、Java等语言绑定，以及在线服务。后续的UDPipe 2（2018年起）换成基于BiLSTM和预训练上下文嵌入的模型，精度更高。

结果

论文对当时UD 1.2版的各个树库分别训练并报告了分词、标注和分析的准确率；具体数字未核对。

后来的发展

UDPipe被CoNLL 2017/2018共享任务用作官方基线和预处理工具。Stanford的Stanza多语言工具包走了同样的路线（覆盖全部UD语言、从原始文本开始的完整流水线），并改用神经模型；UDPipe 2也在CoNLL 2018中取得前列成绩。语言学研究者常用它为小语种语料做自动标注。

局限与后续

  • 第一版的形态分析和句法分析是浅层模型，精度明显低于后来基于BiLSTM和预训练模型的系统。
    后来针对它的工作　Stanza多语言工具包
  • 各步骤串成流水线，分词或词性错误会传给句法分析，彼此不能互相纠正。

读懂它需要的概念

分词与token 循环网络与隐状态 监督学习

本篇术语

  • CoNLL-U　Universal Dependencies使用的纯文本格式：每行一个词，十列分别记录词形、词元、词性、形态特征、中心词编号、依存关系等。
  • 多词token　书面上是一个词、句法上要拆成几个词的情况，例如法语du=de+le、西班牙语del=de+el。

怎么学

先了解Universal Dependencies的标注体系 → 浏览UDPipe文档中的模型列表与CoNLL-U格式说明 → 动手：用UDPipe在线服务或Python绑定分析一段非英语文本，检查分词、词形还原和依存关系。
