Google ADK智能体开发套件

Agent Development Kit: Making it easy to build multi-agent applications
2025.04系统延伸Google待核对
官方博客 ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

要把多个智能体组合成可上线的系统，开发者需要自己处理分工委派、工具接入、评测、流式交互和部署，现有框架往往只覆盖其中一两环。

方法

开源一套代码优先的智能体开发框架，覆盖构建、交互、评测、部署整个生命周期，原生支持多智能体层级组合，也是Google自家产品里的智能体所用的同一框架。

影响

与同月发布的A2A协议一起构成Google的智能体开发栈，很快有了Python、Java、Go、TypeScript等多语言版本，成为主流智能体框架之一。

方法

ADK在2025年4月9日的Google Cloud NEXT大会上发布（GitHub仓库创建于2025-04-01）。官方博客说明它就是驱动Google Agentspace和客户互动套件里智能体的那套框架，开源出来供外部开发者使用。主要设计：

  • 多智能体为先：把多个专门的智能体按层级组合，上层负责协调和委派，下层各管一摊；
  • 模型不绑定：针对Gemini优化，但也能通过Vertex AI模型库或LiteLLM接入Anthropic、Meta、Mistral等厂商的模型；
  • 工具生态：内置搜索、代码执行等工具，支持模型上下文协议MCP工具、接入LangChain和LlamaIndex的工具，还能把LangGraph、CrewAI等框架做成的智能体当作工具调用；
  • 双向音视频流，以及内置的评测和部署支持。

后来的ADK 2.0加入基于图的工作流运行时（路由、分支汇合、循环、重试、人在回路）和结构化的智能体间任务委派接口。它与Agent2Agent协议协议分工：ADK用来搭一个系统内部的智能体，A2A用来让不同厂商、不同框架的智能体互相通信。

局限与后续

  • 虽然宣称模型不绑定，但许多高级功能（流式音视频、部署）与Gemini和Google Cloud结合最紧，换平台时能用的部分会减少。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 多智能体层级本身会带来上下文传递失真、错误层层累积等问题，框架并不能自动解决多智能体系统的可靠性。
