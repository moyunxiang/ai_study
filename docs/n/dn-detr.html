DN-DETR查询去噪

DN-DETR: Accelerate DETR Training by Introducing Query DeNoising
2022.03论文延伸CVPR 2022Feng Li, Hao Zhang, Shilong Liu, Jian Guo, Lionel M. Ni, Lei Zhang · 香港科技大学 / IDEA研究院 / 清华大学待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

DETR要训练500个epoch才收敛，比Faster R-CNN慢一个数量级；之前的改进多从注意力结构入手，对“为什么慢”缺少解释。

方法

指出慢的一个重要原因是训练早期二分图匹配不稳定，同一个查询在相邻迭代被分配给不同物体；于是额外把加了噪声的真值框喂进解码器，让模型直接学“把噪声框还原成真值框”，这部分不需要匹配。

影响

查询去噪几乎成了DETR系检测器的标配训练技巧，紧随其后的DINO（检测）在它的基础上加入对比去噪，首次让DETR类方法登顶COCO。

方法

DETR用匈牙利算法把N个预测与真值做一对一匹配再算损失。训练初期预测很乱，一个查询这一步匹配到猫、下一步可能匹配到狗，优化目标前后不一致，学得很慢。

DN-DETR在正常的匹配分支之外加了一个去噪分支：

  • 取每个真值框，给中心点和宽高加随机扰动（框噪声），把类别标签以一定概率随机翻成别的类（标签噪声），编码成额外的解码器查询；
  • 这些去噪查询“天生”知道自己对应哪个真值，直接用重建损失（框的L1与GIoU、类别分类）训练，绕开了匹配；
  • 用注意力掩码隔开：匹配查询看不到去噪查询，避免真值信息泄露；不同组的去噪查询之间也互相看不见。

去噪分支只在训练时存在，推理时去掉，不增加推理成本。方法基于把查询表示成锚框的DAB-DETR实现，作者称只要几十行代码就能加到任何DETR类方法上。摘要报告：同等设置下提升1.9 AP，ResNet-50骨干训练12个和50个epoch分别得到43.4和48.6 AP，是当时DETR类方法里最好的；与基线相比用一半的训练轮数达到相当的精度。

后来的发展

DINO（检测）在此基础上加入正负样本对比去噪和混合查询选择；Mask DINO、RT-DETR实时DETR、D-FINE、RF-DETR等后续DETR系检测器普遍保留了去噪训练。

读懂它需要的概念

自注意力与多头注意力 编码器-解码器 IoU与mAP 损失函数

本篇术语

  • 二分图匹配　把N个预测和若干真值一对一配对、使总代价最小的问题，DETR用匈牙利算法求解。
  • 去噪查询　由加了扰动的真值框和标签构造的解码器输入，训练模型把它们还原成真值。

怎么学

先读DETR的匈牙利匹配损失，再读DN-DETR第3节的“匹配不稳定”分析和第4节的去噪分支与注意力掩码；在开源代码里把去噪组数设为0和非0各训几轮，对比早期损失曲线。
