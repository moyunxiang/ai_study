多token预测MTP

Better & Faster Large Language Models via Multi-token Prediction
2024.04论文延伸ICML 2024Fabian Gloeckle, Badr Youbi Idrissi, Baptiste Rozière, David Lopez-Paz, Gabriel Synnaeve · Meta FAIR待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

标准的下一token预测只看眼前一个词，训练信号偏局部，模型也难以在推理时一次出多个token。

方法

在共享主干上接n个独立的输出头，每个位置同时预测后面n个token，作为辅助训练任务。

影响

在代码任务上提高样本效率，并使4-token预测的模型推理可达最高3倍加速；这个思路后来被DeepSeek-V3采用。

方法

做法很简单：模型主干和平常一样产生每个位置的隐表示，再接n个独立的输出头，第i个头预测位置之后第i个token。训练损失是n个头的交叉熵之和。推理时可以只用第一个头像平常那样生成，也可以把额外的头用于推测解码式的并行起草，所以不需要另外的草稿模型。

摘要称：训练时间没有额外开销；规模越大收益越明显；13B参数模型在HumanEval上多解决12%的题目，在MBPP上多17%；用4-token预测的模型，即使在大批量下，推理也最高快3倍。小型算法任务的实验还显示它有利于归纳头和算法推理的形成。

局限与后续

  • 收益主要在代码等生成类基准，自然语言通用基准上提升不明显；最优的n也随任务而变。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 额外的输出头增加参数和显存，且各头独立预测未来token，并不显式建模它们之间的依赖。
    后来针对它的工作　DeepSeek-V3

它建立在什么之上

  • 延续
    Transformer2017.06 · LLM
    在标准Transformer解码器上加多个预测头，训练目标从一个token扩展为n个。
  • 使用
    推测解码2022.11 · 系统·效率
    额外的预测头可直接当作推测解码的草稿来源，获得推理加速。

后来的相关工作

  • 使用
    DeepSeek-V32024.12 · LLM 已核对
    受其启发加入深度为1的多token预测训练目标，但改为顺序预测、保留完整因果链，并可将该模块用于推测解码。
  • 竞争
    连续自回归CALM2025.10 · LLM
    MTP一次预测多个离散token；CALM把多个token压成一个连续向量再预测，彻底离开离散词表。
  • 使用
    Nemotron 3混合Mamba2025.12 · LLM
    Super和Ultra加入MTP层加速生成。

怎么学

先会自回归生成训练目标；读原文第2节方法与第3节的n选择；动手：在小型Transformer上加一个额外的头预测t+2位置，对比下游表现。
