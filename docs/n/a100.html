A100

2020.05硬件重要GTC 2020（2020年5月14日发布）NVIDIA来源已核对
NVIDIA新闻稿 ↗A100架构白皮书 ↗维基百科：Ampere架构 ↗在交互版中打开（演化树、学习进度）

问题

V100的Tensor Core只吃FP16，训练要靠损失缩放防下溢，老的FP32代码不改就用不上；显存和带宽也跟不上GPT-3这一代模型。

方法

第三代Tensor Core加入TF32和BF16两种与FP32数值范围相同的格式，FP32代码不改即可走Tensor Core；配40GB HBM2、1555GB/s带宽、600GB/s NVLink，另加2:4结构化稀疏和一卡切7份的MIG。

影响

2020–2023年大模型训练最常见的硬件之一：例如LLaMA-65B在2048块A100上训练。2022年8月美国政府要求A100和H100对华出口须获许可证，它成为这一轮管制最早点名的芯片之一。

背景

V100与Tensor Core把Tensor Core引入GPU，但留下几处摩擦。一是格式：Tensor Core只接受FP16输入，FP16的指数只有5位，小梯度容易下溢成0，必须照混合精度训练的做法配合损失缩放；而大量科学计算和老训练代码仍是FP32，它们根本用不上Tensor Core。二是规模：2020年的语言模型已经到百亿、千亿参数（GPT-3就是在V100集群上训的），显存和卡间带宽都成了瓶颈。三是利用率：推理任务常常很小，一整块大GPU只跑一个小模型很浪费。

方法

据白皮书，A100的GA100芯片用台积电7nm工艺（见台积电N7：代工领先），542亿个晶体管，面积826mm²，108个流处理器共432个第三代Tensor Core。

新数值格式（见浮点精度：FP32、FP16、BF16、INT8）。TF32：1位符号、8位指数（与FP32相同）、10位尾数（与FP16精度相同），输入输出仍是标准FP32，所以FP32程序不改代码就能自动走Tensor Core。同时支持谷歌的bfloat16：8位指数、7位尾数，数值范围与FP32一样宽，一般不再需要损失缩放。

峰值算力。FP16/BF16 Tensor Core 312 TFLOPS（V100约为其四成），TF32 Tensor Core 156 TFLOPS；不用Tensor Core的普通FP32只有19.5 TFLOPS——差距说明几乎所有AI算力都在Tensor Core里。

2:4结构化稀疏。规定权重矩阵每连续4个数中至多2个非零，硬件只存非零值和位置，跳过零的乘法，官方称数学运算最多再快2倍。做法是先正常训练，再按这个格式剪枝并微调。

内存与互连。40GB HBM2，带宽1555GB/s，比V100高73%（见HBM高带宽内存）；40MB二级缓存；第三代NVLink与NVSwitch总带宽600GB/s，是V100的2倍；8卡机内由NVSwitch全互连。后来又推出80GB版。

MIG（多实例GPU）。一块A100可切成最多7个相互隔离的小GPU，各有自己的显存和计算单元，给多个小推理任务同时使用。

结果

NVIDIA官方称AI训练和推理性能比前代最多高20倍——这个数字是拿TF32加稀疏与V100的普通FP32比，同口径（FP16 Tensor Core对FP16 Tensor Core）大约是2.5倍。同时发布的DGX A100整机装8块A100；用于服务器厂商的八卡HGX A100底板，官方称AI算力10 PFLOPS（新闻稿未说明是哪种精度、是否含稀疏）。

实际使用上：LLaMA论文写明65B模型在2048块80GB A100上训练，每卡每秒处理约380个token，1.4万亿token约需21天。

后来的发展

A100这一代之后，“BF16计算、FP32累加”成为GPU上大模型训练的常见精度设置。下一代H100在其基础上加FP8和专为Transformer设计的Transformer Engine，显存带宽再提高；Grace CPU与超级芯片把CPU和GPU用高速链路连在一起。

据NVIDIA 2022年8月提交给SEC的文件（CNBC报道），美国政府要求A100、H100以及峰值性能和芯片间I/O性能都达到大致相当于A100门槛的芯片对华出口须获许可证；同年10月出台了正式规则（美国对华先进芯片出口管制）。NVIDIA随后推出把NVLink限制到400GB/s的A800供应中国（据媒体报道），这条“降规格特供”路线延续到H800、H20禁售、解禁与分成。

容易误解的地方

  • “比V100快20倍”是不同精度、加上稀疏后的峰值对比，不能理解为训练同一个模型快20倍。
  • 2:4稀疏需要专门剪枝和微调，大模型训练中很少用到，日常拿到的通常是不含稀疏的那组数字。
  • TF32的尾数只有10位，比真正的FP32精度低；对精度敏感的科学计算需要显式关闭。

读懂它需要的概念

浮点精度：FP32、FP16、BF16、INT8 CPU、GPU与并行计算 显存、内存带宽与“内存墙” 矩阵乘法与线性变换 分布式训练：数据并行与模型并行

本篇术语

  • TF32　NVIDIA为A100定义的Tensor Core内部格式：8位指数、10位尾数。数值范围同FP32、精度同FP16，让FP32代码自动获得Tensor Core加速。
  • 2:4结构化稀疏　要求每4个连续权重里至少2个为零，硬件可跳过零值乘法。比随机稀疏规则，所以硬件容易实现。
  • MIG　多实例GPU：把一块物理GPU切成多个隔离的小GPU，分别分配给不同任务。

怎么学

先补浮点精度：FP32、FP16、BF16、INT8，画出FP32、FP16、BF16、TF32各自的符号/指数/尾数位数。然后读白皮书中Third-Generation Tensor Core和Structured Sparsity两节。动手：在PyTorch里开关torch.backends.cuda.matmul.allow_tf32，比较同一矩阵乘的速度和数值误差。
