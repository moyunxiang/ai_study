ALFRED具身指令基准

ALFRED: A Benchmark for Interpreting Grounded Instructions for Everyday Tasks
2019.12数据集延伸CVPR 2020Shridhar, Thomason, Gordon, Bisk, Han, Mottaghi, Zettlemoyer, Fox · 华盛顿大学 / CMU / AI2 / NVIDIA待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

当时的语言+视觉具身基准多是「照指令走到某处」或「问答」，几乎不涉及操作物体、状态变化和长任务，离真实家务差得远。

方法

在AI2-THOR的120个室内场景里，为家务任务录制规划器生成的专家示范，并给每条示范配上高层目标和逐步低层指令两级人工语言标注，共约2.5万条。

影响

成为具身指令跟随的标准测试台，后续大量模块化方法（语言规划+感知+导航+操作）和用大模型做任务规划的工作都以它为评测对象。

方法

此前的VQA只把语言和静态图片对上，Room-to-Room这类导航基准只要求「走到哪」，不需要拿起、清洗、加热物体。而SHRDLU那样的早期系统虽然能在积木世界里按语言操作物体，却建立在手写的符号世界上，没有真实的视觉输入。ALFRED要的是把两者合起来：机器人只能看到第一人称图像，要把自然语言翻译成一串动作。

它在AI2-THOR 2.0的120个室内场景里，由规划器自动生成完成任务的专家示范，再请人给每条示范写两种语言：高层目标，例如「把马克杯冲洗干净放进咖啡机」；以及逐步的低层指令，例如「走到右边的咖啡机前」。论文称共有约2.5万条语言指令。任务特点是：很长、由多个子目标组合而成、有不可逆的状态变化（物体洗过、切过、加热过就回不去）、部分可观测、指令常常说得不完整。动作除了移动，还要求对要操作的物体预测像素级掩码。

论文给出的基线是一个基于当时具身视觉语言任务的序列到序列模型，表现很差，作者据此指出还有很大的研究空间。

局限与后续

  • 环境是AI2-THOR的仿真，动作是离散的，物体操作靠「对物体打掩码」的抽象接口完成，没有真实抓取的物理难度和视觉域差距。

  • 指令由人写、任务来自固定的几类模板，语言和任务的开放程度有限，难以检验对新词汇和新任务的泛化。

它建立在什么之上

  • 延续
    VQA2015.05 · 数据·评测
    把「语言对应静态图像」的视觉语言任务推广到需要连续动作、物体交互和状态变化的交互式任务。
  • 延续
    SHRDLU1972 · NLP
    延续「按自然语言指令操作物体」的目标，但把手写的符号积木世界换成第一人称视觉输入的真实感家居环境。
  • 改进
    R2R视觉语言导航2017.11 · 具身·世界模型
    动作限制在预设的导航图上，不是连续控制，也没有物体操作。
