BIRD大库文本转SQL

Can LLM Already Serve as A Database Interface? A BIg Bench for Large-Scale Database Grounded Text-to-SQLs
2023.05数据集延伸NeurIPS 2023 Datasets and BenchmarksJinyang Li, Binyuan Hui, Ge Qu, Jiaxi Yang, Binhua Li, Bowen Li, Bailin Wang, Bowen Qin et al. · 香港大学 / 阿里巴巴等待核对
arXiv ↗排行榜 ↗在交互版中打开（演化树、学习进度）

问题

Spider、WikiSQL的数据库只有很少几行数据，模型只要懂表结构就够；真实业务库数据量大、取值脏乱、还需要领域知识，这些都没被考到。

方法

收集95个真实数据库（共33.4GB，37个专业领域）和12,751对问题—SQL，重点考察对数据库取值的理解、外部知识和SQL执行效率。

影响

成为大模型时代与Spider并列的文本转SQL主榜；发布时ChatGPT执行准确率仅40.08%，远低于人类的92.96%。

方法

BIRD（BIg Bench for LaRge-scale Database Grounded Text-to-SQL）延续Spider文本转SQL的跨数据库设定，但把数据库换成大而真实的库：95个数据库合计33.4GB，覆盖37个专业领域，问题—SQL对共12,751条。

它刻意加入三类Spider里很少出现的难点：一是脏数据，列里的取值格式不统一，模型必须看过真实数据才知道怎么写条件；二是外部知识，问题里的说法要借助领域知识或给出的“证据”说明才能对应到具体的列和数值；三是效率，在海量数据上，语义正确但写得低效的SQL代价很高，因此除了执行准确率还给出效率分析。

据摘要，在Codex和ChatGPT发布这些当时最强的模型中，ChatGPT执行准确率只有40.08%，人类为92.96%。

局限与后续

  • 仍是单轮问答式的一条SQL，没有覆盖企业里多步、跨多种数据系统的完整数据工作流。

读懂它需要的概念

基准、排行榜与SOTA 语言模型 上下文学习与提示 零样本与少样本

本篇术语

  • 执行准确率　把模型写的SQL和标准SQL都在数据库上执行，比较返回结果是否一致；比逐字比较SQL更宽容。

怎么学

先读Spider文本转SQL了解跨数据库文本转SQL的设定，再读BIRD原文的数据构建和外部知识部分；在开发集上挑几道题，对比加与不加“证据”说明时大模型生成SQL的正确率。
