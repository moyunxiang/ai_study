GeoQuery与CHILL语义解析

Learning to Parse Database Queries Using Inductive Logic Programming
1996.08论文延伸AAAI 1996John M. Zelle, Raymond J. Mooney · 德克萨斯大学奥斯汀分校待核对
AAAI ↗在交互版中打开（演化树、学习进度）

问题

让用户用自然语言查询数据库，以前要为每个数据库手写语法和语义规则，工作量大且难以移植；能不能从「问题-查询」示例中自动学出一个语义解析器？

方法

CHILL把语义解析器表示为一个移进-归约分析器的逻辑程序，用归纳逻辑程序设计从标注好的「句子-数据库查询」对里学出在每一步该选哪个动作的控制规则；并为此构建了美国地理问答数据集GeoQuery。

影响

这是最早从语料中端到端学习语义解析器的工作之一，GeoQuery（后来扩充到880个问题，常称Geo880）成为此后二十年语义解析最常用的基准，CCG、神经seq2seq等方法都在它上面比较。

背景

自然语言数据库接口有很长的历史：LUNAR月岩问答（1972）用手写的扩充转移网络ATN语法回答月岩样本问题，80年代的系统也都靠专家为每个领域编写词典和规则，移植到新数据库几乎要重写。90年代统计方法在句法分析上取得进展，但把句子直接映射到可执行的逻辑查询（语义解析），还缺少能从数据中学习的方法。

方法

表示。 目标查询是Prolog形式的逻辑表达式，例如问题「What is the capital of the state with the largest population?」对应 answer(C, (capital(S, C), largest(P, (state(S), population(S, P)))))，可以直接在地理数据库Geobase上执行。

分析器框架。 CHILL先用一个通用的移进-归约分析器框架：分析器读入词、在栈上组合出部分逻辑式，可用的操作包括引入一个词对应的谓词、把两个部分逻辑式合并（共享变量）、把一个部分逻辑式作为另一个的参数等。这个框架本身是高度非确定的：每一步都有许多可能的操作。

学习控制规则。 对每个训练样本，找出能从句子推出标准查询的操作序列，记录每一步做出的正确选择和其他错误选择，形成正例和反例。然后用归纳逻辑程序设计（一种从正反例中学习一阶逻辑规则的方法）为每个操作学出「在什么样的栈和输入状态下应该执行它」的规则。把学到的规则加到分析器里，它就变成确定性的。

数据。 作者收集了用户关于美国地理的问题，并人工写出对应的Prolog查询，形成GeoQuery语料。

结果

摘要称：在一个完整的数据库查询应用上的实验表明，CHILL从示例中学到的解析器可以把新句子直接映射为可执行查询；论文报告其准确率随训练数据增加而上升，并与手工构建的系统比较（具体数字未核对）。

后来的发展

Mooney组随后提出COCKTAIL、WASP、KRISP等方法并把GeoQuery扩充到880句；语义解析（CCG）（Zettlemoyer与Collins，2005）在GeoQuery上用概率CCG取得大幅提升；Seq2Tree神经语义解析（2016）首次用注意力seq2seq在其上取得有竞争力的结果。之后语义解析的基准逐步转向WikiSQL文本转SQL、Spider文本转SQL等文本到SQL数据集，但GeoQuery仍常用于组合泛化研究。

它建立在什么之上

  • 竞争
    扩充转移网络ATN1970.10 · NLP
    早期系统用手写的ATN语法分析问句，CHILL用可学习的移进-归约分析器。
  • 改进
    LUNAR月岩问答1972 · NLP
    LUNAR式数据库接口靠手写语法与语义规则，CHILL从「问题-查询」示例中自动学出解析器。
  • 延续
    Montague语义学1973 · NLP
    延续把句子组合式地翻译成逻辑式的思路，但翻译规则不再手写，而从数据中学。

本篇术语

  • 语义解析　把自然语言句子转成计算机可以执行的形式化意义表示，如逻辑式、SQL查询。
  • 归纳逻辑程序设计（ILP）　从正例、反例和背景知识中学出一阶逻辑规则（如Prolog子句）的机器学习方法。
  • 移进-归约分析　逐个读入词（移进）并把栈顶若干元素合并（归约）来构造结构的分析方式。

怎么学

先了解Prolog查询的基本写法 → 读原文第2–3节的分析器框架与控制规则学习 → 动手：下载Geo880数据，看几十条问题与查询的对应关系，再用一个现成的seq2seq模型在上面训练，观察它在组合新问题时的错误。
