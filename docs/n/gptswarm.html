GPTSwarm智能体图优化

Language Agents as Optimizable Graphs
2024.02论文延伸Mingchen Zhuge, Wenyi Wang, Louis Kirsch, Francesco Faccio, Dmitrii Khizbullin, Jürgen Schmidhuber · KAUST / IDSIA待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

思维链、反思、多智能体辩论等提示技巧各有一套代码，多个智能体之间谁把结果传给谁也全靠人手工设计，没法自动比较和改进。

方法

把任何LLM智能体都写成一张计算图：节点是一次LLM或工具调用，边是信息流向；再分别自动优化每个节点的提示和整张图的连边。

影响

较早把多智能体之间的连接结构当作可学习的参数来优化，是后来自动设计智能体系统、用RL学编排拓扑这条线的常见起点。

方法

GPTSwarm先做统一表示：一个智能体是一张图，节点实现「处理输入」「调用LLM」等函数，边表示数据从哪个操作流向哪个操作；多张图可以再拼成更大的复合图，节点之间跨智能体的边就代表协作关系（见图、树与搜索）。

在此之上有两种优化。边优化：给每条可能的边一个0到1之间的概率θ，每次按这些概率随机采样出一张无环图去跑任务，把任务得分当作回报，用REINFORCE策略梯度式的策略梯度更新θ，相当于学习「哪些智能体应该互相连接」。节点优化：沿用OPRO以LLM为优化器让LLM改写提示的思路，根据节点过去的输入输出改进它的提示。

论文报告：在Mini Crosswords上用GPT-3.5-Turbo，优化后的连边分布得分0.575，初始分布为0.465；HumanEval在线优化从0.76升到0.88。另一个实验里一半智能体被设定为故意给错答案，边优化学会切断它们的连接，使群体准确率回到接近单个诚实智能体的水平。

局限与后续

  • 优化出的是每个任务一张固定的图，所有问题都用同一种协作结构，不会根据具体问题或中间状态临时调整。

本篇术语

  • 边优化　把智能体之间每条连接是否存在当作一个概率参数，按任务得分用强化学习调整，学的是协作结构而不是模型权重。

怎么学

先读多智能体框架AutoGen了解手写多智能体流程的样子 → 读原文第3节（图表示）和第4节（边优化与节点优化） → 动手：给3个LLM智能体之间的6条可能连边设概率，用REINFORCE在一个小问答集上学连边。
