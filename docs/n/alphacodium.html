AlphaCodium流程工程

Code Generation with AlphaCodium: From Prompt Engineering to Flow Engineering
2024.01论文延伸arXiv 2024Tal Ridnik, Dedy Kredo, Itamar Friedman · CodiumAI待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

写竞赛题代码要精确匹配语法、覆盖边界情形，而自然语言里有效的提示技巧对代码未必有用，单次提示成功率低。

方法

不再只优化一句提示，而是设计“流程工程”：多阶段、以测试为中心的迭代流程，先理解题目，再生成测试，再生成并反复修改代码。

影响

提出“从提示工程到流程工程”的口号，推动了围绕测试反馈迭代的代码智能体设计。

方法

AlphaCodium是一个多阶段流水线。先让模型用要点复述题目、推理样例，生成多个解法思路并选出最好的；再让模型生成额外的测试用例（包括边界情形）；然后生成代码，在公开样例测试和自己生成的测试上运行，根据报错反复修改。流程中大量采用结构化输出（如YAML）来减少格式混乱，并且有“先做简单、已验证的部分”之类的原则。

测试对象是竞赛题数据集CodeContests（来自Codeforces等）。摘要称GPT-4在验证集上的pass@5从单个精心设计的直接提示的19%提高到AlphaCodium流程的44%。它与AlphaCode的区别是不靠大规模采样加过滤，而是靠少量调用加迭代修复，与Reflexion同样利用执行反馈。

  • 流程是为竞赛题手工设计的，迁移到真实代码库（多文件、依赖复杂）需要重新设计。
