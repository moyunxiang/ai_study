ReTool工具强化学习

ReTool: Reinforcement Learning for Strategic Tool Use in LLMs
2025.04论文延伸Jiazhan Feng, Shijue Huang, Xingwei Qu, Ge Zhang, Yujia Qin, Baoquan Zhong, Chengquan Jiang, Jinxin Chi, Wanjun Zhong · 字节跳动 Seed待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

靠RL训练的推理模型擅长文字推理，但遇到几何、精确计算、解方程等需要工具的问题就吃力，而代码解释器正擅长这些。

方法

在长思维链里穿插真实的代码执行，并用以最终结果为奖励的RL，让模型自己学会何时、如何调用代码解释器。

影响

把工具调用纳入RL训练，AIME上同尺寸模型明显超过纯文本RL。

方法

ReTool分两步。冷启动：先合成一批「推理中穿插代码」的长思维链数据，对基座做监督微调，让模型知道格式。再做RL：模型在生成过程中遇到代码块就暂停，交给沙箱真实执行，把执行结果插回上下文再继续生成（多轮），最终仅用答案是否正确作为奖励，没有人工规定何时用工具。

摘要称32B模型在AIME上仅训练400步就达到67%，而纯文本RL基线训练1080步只有40%；扩展设置下达到72.5%，超过OpenAI o1-preview。训练中模型自主发现调用代码的时机，不需要人工规定。

后来的发展

它与o3/o4-mini工具内推理「在推理中调用工具」的产品方向一致，是学术界较早的开源对应；类似的思想用于搜索则是Search-R1。

局限与后续

  • 只在数学场景与代码解释器一种工具上验证，多工具、长链场景未覆盖。
    后来针对它的工作　Search-R1
  • RL时需要真实沙箱执行，训练基础设施更复杂、更慢。
