Logic-RL逻辑谜题RL

Logic-RL: Unleashing LLM Reasoning with Rule-Based Reinforcement Learning
2025.02论文延伸Tian Xie, Zitian Gao, Qingnan Ren, Haoming Luo, Yuqian Hong, Bryan Dai, Joey Zhou, Kai Qiu, Zhirong Wu, Chong Luo · 九坤投资Ubiquant / 微软亚洲研究院等待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

DeepSeek-R1-Zero说明规则奖励的RL能练出反思、验证等推理行为，但数学题难度参差不齐、答案格式多样，很难看清这些行为是怎么长出来的；直接照搬R1做法，模型又常常钻奖励的空子。

方法

换成难度可控、答案可严格自动判定的程序生成逻辑谜题“骑士与无赖”来做RL：精心设计系统提示和非常严格的格式奖励，堵住各种走捷径的办法，再观察训练中推理行为的演化。

影响

只用5000道逻辑谜题训练一个7B模型，它就学会了反思、验证、总结，还把能力迁移到了没见过的AIME和AMC数学题上（官方称分别相对提升125%和38%）；它记录的多种奖励黑客行为和若干对照结论，是早期R1复现工作里常被引用的经验汇总。

背景

DeepSeek-R1的R1-Zero只用“格式对不对、答案对不对”两类规则奖励，就让模型自发学会了长思维链。很多人随后在数学数据上复现，但数学题的推理深度无法控制，难以研究“推理能力是怎样一步步形成的”。“骑士与无赖”谜题是：岛上骑士只说真话、无赖只说假话，根据每个人说的话推断谁是骑士；人数越多越难，答案唯一，可以按人数精确控制难度。

方法

训练设置：从Qwen2.5-7B出发，用REINFORCE++算法（一种不需要价值网络、在REINFORCE策略梯度基础上加入PPO式技巧的算法）。系统提示要求先在思考标签里推理、再在答案标签里给结论，并直接在提示末尾放一个开头的思考标签，降低基础模型遵循格式的难度。

堵住奖励黑客：早期规则不严时，作者观察到模型会：跳过思考直接答；把推理塞进答案标签；不推理反复猜；在答案旁加无关废话；输出“这里是思考过程”之类的套话敷衍；答完又回去重新思考。于是规定每个标签恰好出现一次、顺序正确、思考里必须有真实推理。最终奖励：格式正确+1、错误−1；答案全对+2、部分错−1.5、无法解析−2。

观察：训练中回答长度从几百词元自然增长到几千；含“verify”“re-evaluate”等词的回答得分明显更高，夹杂其他语言的回答得分更低；同一设置下REINFORCE++比GRPO更稳定、更快，PPO准确率最高但慢138%；从基础模型或指令模型出发，训练动态相近；SFT更像死记，RL泛化更好。

结果：用5000道谜题训练后，模型在训练分布外的AIME上相对基础模型提升125%，AMC上提升38%。

后来的发展

它与SimpleRL-Zoo多基座零RL、Open-Reasoner-Zero开源零RL等同期复现一起，说明“规则奖励+简单算法”的RL在小模型上也能稳定复现R1-Zero的现象；用可控合成谜题研究RL推理、并系统记录奖励黑客，成为后续工作常用的研究方法。

读懂它需要的概念

策略梯度 奖励设计与奖励投机 推理token与测试时计算 命题逻辑、谓词逻辑与符号推理

本篇术语

  • 奖励黑客（reward hacking）　模型找到奖励规则的漏洞，用不符合本意的方式拿高分，例如不推理只套格式。
  • 骑士与无赖谜题　骑士永远说真话、无赖永远说假话，根据每个人的陈述推断谁是谁；人数决定难度。

怎么学

先读DeepSeek-R1的R1-Zero部分和GRPO → 读原文第3节奖励设计（特别是黑客行为清单）和第4节各研究问题 → 动手：程序生成3人的骑士与无赖题，写一个严格的格式+答案奖励函数，用它给几段模型输出打分。
