字节潜变量BLT

Byte Latent Transformer: Patches Scale Better Than Tokens
2024.12论文延伸arXiv 2024Artidoro Pagnoni, Ram Pasunuru, Pedro Rodriguez 等 · Meta FAIR / 华盛顿大学 / 芝加哥大学待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

几乎所有大模型都依赖固定词表的分词器：它对拼写错误、罕见语言和字符级任务脆弱，且对所有token一视同仁地花同样算力。

方法

直接在字节上训练，把字节按下一个字节的熵动态切成大小不一的patch：容易预测的地方patch长，难预测的地方patch短。

影响

首次在大规模下让字节级模型追平基于分词的模型，并提升推理效率与鲁棒性。

方法

BLT由三部分组成：一个小的本地编码器把原始字节压成patch；一个大的潜在Transformer只在patch上运行；一个小的本地解码器把patch还原成字节。patch的边界由一个小模型预测的下一字节熵决定：下一个字节很好猜时（比如单词中间），patch拉长，省算力；不好猜时（比如新词开头），patch缩短，把更多算力留给困难处。

作者做了首个按FLOP对齐的字节级模型缩放研究，规模到8B参数和4万亿训练字节。摘要称，在固定推理成本下，BLT随patch和模型规模同时增大，缩放优于基于分词的模型，并且在推理和长尾泛化上有质的改进。

局限与后续

  • 训练和推理代码需要自定义的动态patch逻辑，现有加速库对此支持差；结论只到8B规模。
    后来针对它的工作　H-Net动态分块
  • patch切分依赖一个独立的熵模型，不是端到端学出来的。
    后来针对它的工作　H-Net动态分块

它建立在什么之上

  • 改进
    BPE子词切分2015.08 · NLP
    绕开固定词表分词带来的脆弱性。
  • 改进
    SentencePiece2018.08 · NLP
    多语言共用一个固定大小的词表时，高资源语言占据大部分子词，低资源语言的句子被切得很碎，序列更长、效果更差。
  • 改进
    Unigram子词与子词正则化2018.04 · NLP
    子词仍是固定词表，跨语言和多语言时的切分公平性问题仍存在。
  • 竞争
    ByT5字节级模型2021.05 · LLM
    同为无分词路线；ByT5直接按字节处理，计算量大，BLT用patch把序列压短。
  • 延续
    MEGABYTE2023.05 · LLM
    同样用小模型处理局部字节、大模型处理全局，但BLT的patch大小由熵动态决定而非固定。

后来的相关工作

  • 竞争
    SuperBPE超词切分2025.03 · NLP
    BLT放弃固定词表改为动态字节块，SuperBPE保留词表、只改合并规则。
  • 改进
    H-Net动态分块2025.07 · LLM
    把BLT里依赖熵阈值的切块，换成与网络联合训练、可学习的动态分块。
  • 竞争
    连续自回归CALM2025.10 · LLM
    BLT在字节上动态分块以提高效率；CALM固定K个token成块并转到连续空间。

读懂它需要的概念

分词与token 自注意力与多头注意力 信息量与熵 自回归生成 参数量、计算量与显存

怎么学

先读MEGABYTE；读BLT第2–3节的熵patching和三个模块；动手：用小语言模型算一段文本中每个字节的熵，画出据此划分的patch。
