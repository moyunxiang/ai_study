Tomasulo算法：乱序执行

An Efficient Algorithm for Exploiting Multiple Arithmetic Units
1967.01论文延伸IBM Journal of Research and Development 1967Robert M. Tomasulo · IBM待核对
IBM JRD论文DOI ↗维基百科 ↗在交互版中打开（演化树、学习进度）

问题

处理器里有多个运算部件，但指令之间的寄存器依赖让后面的指令只能干等；CDC 6600与记分牌的记分牌遇到寄存器被重复使用时也只能停顿。

方法

给每个运算部件配一组“保留站”暂存等待中的指令，用标签代替尚未算出的寄存器值（硬件寄存器重命名），结果算出后通过公共数据总线广播给所有等它的指令。

影响

这套机制先在IBM System/360：兼容的计算机家族 Model 91的浮点单元里实现，1990年代起成为乱序执行处理器的基础，今天的高性能CPU仍在用它的变体。

方法

考虑两条指令：F2 = F0 × F4 和 F6 = F2 + F8。第二条要等第一条的乘法结果；如果后面还有一条与它们无关、却恰好也要写F2的指令，按顺序执行的机器就必须等前两条都完成。这类“名字冲突”（写后写、读后写）其实不是真正的数据依赖，只是寄存器不够用造成的。

Tomasulo的办法有三件：每个运算部件前有若干保留站，指令发射后在那里等操作数；如果某个操作数还没算出来，保留站里记下的不是寄存器名，而是“将由哪个保留站产生”的标签——这就是硬件寄存器重命名，名字冲突因此消失；运算结果通过一条公共数据总线广播，所有持有该标签的保留站和寄存器同时取走数值，操作数凑齐的指令立即开始执行。

维基百科记载，这个算法1967年在IBM提出，首先用在System/360 Model 91的浮点单元上，之后多年没有在IBM之外使用；到1990年代，缓存缺失越来越常见、多发射处理器需要动态调度和分支预测，它的使用迅速增加。Tomasulo因此获得1997年Eckert–Mauchly奖。

局限与后续

  • 原始方案不能保证精确异常，也不支持分支之后的推测执行，后来的处理器要加重排序缓冲区才能按程序顺序提交结果。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 保留站、广播总线和重命名逻辑随发射宽度迅速变复杂、耗电，单核乱序执行的收益在2000年代逐渐见顶。

读懂它需要的概念

本篇术语

  • 保留站　运算部件前面的小缓冲区，存放已经发射、还在等操作数的指令。
  • 寄存器重命名　用内部标签或物理寄存器代替程序里写的寄存器名，让只是重名、并无真实依赖的指令可以同时执行。
