Adapter

Parameter-Efficient Transfer Learning for NLP
2019.02论文延伸ICML 2019Neil Houlsby, Andrei Giurgiu, Stanislaw Jastrzebski 等 · Google待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

微调BERT要为每个下游任务保存一份完整模型，任务一多存储爆炸；而冻结全部参数又让效果大幅下降。

方法

在每层Transformer里插入几个很小的瓶颈模块（adapter），只训练它们，原模型参数冻结，每个任务只多出少量参数。

影响

开启参数高效微调路线，后续的LoRA等方法都在这个思路上改进。

方法

Adapter是一个很小的两层网络：先把隐藏向量降到较低维度，经过非线性，再升回原维度，并加一个残差连接，使其初始接近恒等映射。它被插入BERT每个子层之后。训练时冻结BERT全部参数，只更新adapter与层归一化。

因为每个任务只有这些小模块，部署时共用一份主干，按任务切换adapter即可，也能增量添加新任务而不影响旧任务。论文把BERT迁移到26个文本分类任务，在GLUE上与完整微调相差在0.4%以内，而每个任务只新增3.6%的参数，完整微调则每个任务训练100%的参数。

局限与后续

  • 推理时多出串行的小模块，增加少量延迟。
    后来针对它的工作　LoRA
  • 需要为每个任务保存并选择一套adapter，仍有管理成本。
    后来针对它的工作　Hugging Face PEFT库

它建立在什么之上

  • 延续
    BERT2018.10 · LLM
    在BERT预训练模型上，只加小模块来适配新任务，而不是整体微调。
  • 改进
    ULMFiT2018.01 · LLM
    每个任务都要完整微调并保存一份模型副本。

后来的相关工作

  • 改进
    LoRA2021.06 · 系统·效率 已核对
    Adapter串行插入新层，在GPT-2 medium、批大小1时单次前向延迟增加20.7%到30.3%；LoRA的增量与原权重并联，部署时可合并，不增加推理延迟。
  • 竞争
    Prefix / Prompt Tuning2021.01 · 系统·效率
    同属参数高效微调，Adapter在层间插小模块，前缀方法不改结构只加向量。
  • 竞争
    BitFit2021.06 · 系统·效率
    同为参数高效微调，Adapter加模块，BitFit不加任何模块。
  • 使用
    T2I-Adapter2023.02 · 生成
    沿用Adapter式的“冻结主干、训练小模块”思路，由NLP迁移到扩散。
  • 改进
    Hugging Face PEFT库2023.02 · 系统·效率
    需要为每个任务保存并选择一套adapter，仍有管理成本。

读懂它需要的概念

预训练与微调 迁移学习 参数高效微调 残差连接

怎么学

用Hugging Face的PEFT或adapters库给BERT加adapter，只训练它们，对比参数量与精度。
