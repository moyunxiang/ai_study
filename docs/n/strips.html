STRIPS规划

STRIPS: A New Approach to the Application of Theorem Proving to Problem Solving
1971论文重要IJCAI 1971；Artificial Intelligence 2 (1971)Richard E. Fikes, Nils J. Nilsson · Stanford Research Institute（SRI）待核对
论文PDF ↗Wikipedia: STRIPS ↗在交互版中打开（演化树、学习进度）

问题

机器人要自己想出“先去哪、再推哪个箱子”的动作序列；纯用定理证明来规划时，每一步都要重新推导世界里哪些事实没变（框架问题），稍复杂就解不出来。

方法

把每个动作写成“前提 + 删除表 + 增加表”：执行后只删掉和加上列出的事实，其余默认不变；定理证明只用来检查前提和目标，搜索动作序列交给GPS式的手段—目的分析。

影响

给出了此后几十年经典规划的标准动作表示，前提/增加/删除三件套至今是规划语言的核心，也是Shakey机器人的规划器。

背景

1960年代末，SRI在做会移动、会推箱子的机器人（即后来的Shakey机器人）。给它一个目标，比如“把三个箱子推到一起”，它得自己规划出一串动作。

当时有两条路。一条是通用问题求解器GPS式的手段—目的分析：比较当前状态和目标的差异，找能减少差异的操作；但GPS的状态是简单的表结构，装不下机器人世界里房间、门、物体位置这么多事实。另一条是Green的做法：把世界和动作都写成一阶逻辑公式，让定理证明器直接证出一个动作序列。论文指出它被“框架问题”拖累：每做一个动作，都要用公理证明其他所有事实仍然成立，非平凡的问题解不出来。

方法

STRIPS把世界模型表示为一组一阶谓词公式，例如ATR(a)（机器人在a处）、AT(BOX1, b)（箱子1在b处）。每个动作（算子）写成三部分。以推箱子为例：

push(k, m, n)：前提AT(k, m) ∧ ATR(m)；删除表ATR(m), AT(k, m)；增加表AT(k, n), ATR(n)。

执行一个算子就是从当前公式集里删掉删除表、加上增加表，没提到的事实一律原样保留，框架问题由这条约定绕了过去。

搜索是两层分工。定理证明器（SRI的归结证明器QA3.5）只在单个世界模型内部回答问题：目标是否已经成立？某个算子的前提是否满足？证不出来时，残留的未完成证明就是“差异”。搜索层像GPS一样，找增加表能消除这个差异的算子，把它的前提设为子目标，递归下去；用一个评估函数（考虑剩余目标数、差异复杂度等）决定先展开哪个节点。整个程序用LISP写在PDP-10上（见Lisp语言）。

结果

论文的“三箱子”问题：机器人在a，箱子分别在b、c、d，目标是三个箱子在同一处。STRIPS很快给出goto(a, c)、push(BOX2, c, b)、goto(b, d)、push(BOX3, d, b)；论文称Green的定理证明规划器解不了这个版本，只解出了只需两个动作的简化版。另有几个更大的例子：一条走廊连着四个房间，世界模型里写明了哪扇门连哪两个房间、灯开关在哪、状态如何，机器人要完成开灯、搬箱子等任务。

后来的发展

STRIPS的动作表示被后来的经典规划几乎原样继承，规划领域通用的描述语言PDDL就是在它的基础上扩展的。它也确立了“感知 → 符号世界模型 → 规划 → 执行”的机器人架构，这一架构在1991年遭到行为主义机器人学的正面批评。到大语言模型时代，SayCan、Code as Policies等工作让语言模型来做高层规划，等于把手写的算子和世界模型换成了从数据里学到的常识。

局限与后续

  • 假设动作结果确定、世界完全已知且只因机器人而变；真实机器人轮子打滑、箱子被人挪走，规划就失效，只能靠执行监控重新规划。
    后来针对它的工作　POMDP规划 《概率机器人》
  • 谓词和算子全部由人手写，符号与摄像头看到的像素之间没有连接；换一个环境就要重写一套世界模型。
    后来针对它的工作　SayCan Code as Policies
  • 手段—目的分析一次只盯一个差异，多个目标相互干扰时可能给出很长甚至错误的计划，搜索量随计划长度指数增长。

读懂它需要的概念

命题逻辑、谓词逻辑与符号推理 图、树与搜索 博弈树搜索：minimax与MCTS 状态、观测与动作

本篇术语

  • 框架问题　用逻辑描述动作时，不仅要写动作改变了什么，还要证明它没改变什么；事实一多，这部分推理就爆炸。
  • 算子（operator）　规划里对一个动作的抽象描述：何时能做（前提）、做完后哪些事实不再成立（删除表）、哪些新事实成立（增加表）。
  • 手段—目的分析　比较当前状态与目标的差异，挑一个能减少差异的操作；若该操作还不能执行，就把它的前提当作新的子目标。

怎么学

先了解一阶逻辑的谓词写法（命题逻辑、谓词逻辑与符号推理）和树搜索（博弈树搜索：minimax与MCTS）。读原文第2节（问题表示与搜索）和第3.2节（算子描述），对着三箱子例子手工推一遍。动手：用Python写一个最小的STRIPS规划器（状态是事实集合，算子是前提/增加/删除三组集合，用宽度优先搜索），解积木世界问题。
