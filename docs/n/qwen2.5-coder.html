Qwen2.5-Coder

Qwen2.5-Coder Technical Report
2024.09论文延伸arXiv 2024Binyuan Hui, Jian Yang, Zeyu Cui 等 · 阿里巴巴Qwen团队待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

前代CodeQwen1.5在代码能力上落后于最强的开源代码模型。

方法

以Qwen2.5架构为底座，在超过5.5万亿token的代码语料上继续预训练，并强化数据清洗、合成数据和配比。

影响

0.5B到32B六个规模覆盖从端侧到服务器，官方称在10多个基准上超过同规模模型。

方法

Qwen2.5-Coder共有六个规模（0.5B、1.5B、3B、7B、14B、32B），都是在Qwen2.5的基础上，用超过5.5万亿token继续预训练得到的。论文强调三件事：细致的数据清洗，可扩展的合成数据生成，以及代码、数学和通用文本之间的平衡配比，使模型在提升代码能力的同时不丢失数学和通用能力。训练里使用了中间填充FIM任务，使它能做编辑器内的中间补全。

官方称在代码生成、补全、推理、修复等10多个基准上达到同规模最好水平，并以宽松许可发布。

局限与后续

  • 基准多为函数级题目，对真实仓库的长程修改能力并不能完全反映。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 合成数据的质量依赖验证手段，错误样本可能被放大。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    中间填充FIM2022.07 · LLM
    训练中包含填空任务，支持中间补全。
  • 改进
    Code Llama2023.08 · LLM
    虽能接受10万token输入，但只在约16K长度上训练，更长时的真实利用能力未经充分检验。
  • 改进
    StarCoder2与Stack v22024.02 · LLM
    依然在函数级补全基准上评测为主，仓库级、多文件任务能力有限。
  • 竞争
    DeepSeek-Coder-V22024.06 · LLM
    同期的开源代码模型；Qwen2.5-Coder走的是覆盖多个小尺寸、稠密架构的路线。
  • 延续
    Qwen2.52024.12 · LLM
    以Qwen2.5为底座做代码专用的继续预训练。
