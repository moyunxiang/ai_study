跨层注意力CLA

Reducing Transformer Key-Value Cache Size with Cross-Layer Attention
2024.05论文延伸NeurIPS 2024William Brandon, Mayank Mishra, Aniruddha Nrusimha, Rameswar Panda, Jonathan Ragan-Kelley · MIT、MIT-IBM Watson AI Lab待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

长序列、大批量推理时KV缓存占满显存；MQA和GQA已经让多个查询头共享键值头（在“头”这一维度上压缩），能否再在另一个维度上压缩？

方法

在“层”这一维度上共享：相邻的若干层只有第一层计算并缓存自己的K、V，后面的层直接复用这份K、V，只计算各自的查询。在MQA基础上再省一半KV缓存，精度几乎不变。

影响

给出KV缓存压缩的另一条正交路线，可以与MQA/GQA、量化叠加；腾讯Hunyuan-Large、NVIDIA Hymba等模型都采用了跨层KV共享。

方法

背景：推理时每生成一个token，都要读取之前所有token在每一层的键和值，KV缓存大小为 2 × 层数 × KV头数 × 头维度 × 序列长度 × 批量。多查询注意力MQA让所有查询头共用一个KV头，分组查询注意力GQA让每组查询头共用一个KV头，把KV头数这一项大幅降低，精度损失很小。

CLA处理“层数”这一项。把网络的层按共享因子分组，例如共享因子为2时，第1层正常计算K、V并写入缓存，第2层不再有自己的K、V投影，而是直接用第1层的K、V，只计算自己的Q；第3层重新计算，第4层复用，依此类推。于是缓存中只需要保存一半层的K、V。这一改动在训练时就要采用（从头训练），因为被共享的层失去了自己的K、V参数。作者把它与MQA结合（称为CLA2加MQA等配置），并系统扫描了学习率、共享因子和头维度。

结果：在从头训练的1B和3B参数模型上，CLA在MQA的基础上把KV缓存再缩小一半，困惑度与未修改的MQA几乎相同；在“显存—精度”权衡曲线上，CLA给出了比单纯MQA更好的帕累托点，从而支持更长的序列和更大的批量。

局限与后续

  • 只在1B和3B规模、从头训练的设定下验证；能否把已训练好的模型改造成CLA，以及在数十亿参数以上和长上下文任务上的精度影响，原文没有给出。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 共享KV减少的是显存而不是计算，每层仍要对完整的K、V做注意力；KV缓存的读写带宽问题也只减半。

它建立在什么之上

  • 改进
    Transformer2017.06 · LLM
    原始Transformer每层都要缓存自己的键值，长序列推理显存开销大，CLA让相邻层共用一份。
  • 使用
    FlashAttention2022.05 · 系统·效率
    注意力计算本身不变，仍可使用FlashAttention等高效实现，节省来自缓存而非算子。
  • 延续
    分组查询注意力GQA2023.05 · LLM
    同属减少KV头数的方案，CLA与GQA正交，可以组合使用。
  • 延续
    多查询注意力MQA2019.11 · LLM
    MQA在头维度上共享KV，CLA在层维度上再共享一次，两者可叠加。

后来的相关工作

  • 改进
    DeepSeek-V2与MLA2024.05 · LLM
    共享KV减少的是显存而不是计算，每层仍要对完整的K、V做注意力；KV缓存的读写带宽问题也只减半。
  • 竞争
    ResFormer值残差2024.10 · LLM
    同样跨层共享KV来省缓存；SVFormer只共享V，并与之互补。

读懂它需要的概念

KV缓存 自注意力与多头注意力 显存、内存带宽与“内存墙” Transformer层的结构

本篇术语

  • 共享因子　多少个相邻层共用一份KV；共享因子为2表示每两层只缓存一份键值。

怎么学

先读多查询注意力MQA和分组查询注意力GQA，自己算一遍KV缓存大小公式；读原文第2节CLA结构图和第3节帕累托曲线；动手：在小GPT里实现共享因子2的CLA，比较KV缓存大小和验证困惑度。
