MinMo对齐式语音大模型

MinMo: A Multimodal Large Language Model for Seamless Voice Interaction
2025.01论文延伸Qian Chen, Yafeng Chen, Yanni Chen, Mengzhe Chen, Yingda Chen, Chong Deng, Zhihao Du, Ruize Gao et al. · 阿里巴巴通义实验室待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

语音对话大模型分两类：原生模型把语音和文本放进一个框架，但两种序列长度差异大、预训练不足；对齐模型保留文本LLM的能力，却往往只在小数据、少数语音任务上训练。

方法

约80亿参数的对齐式多模态大模型，用140万小时语音数据，依次做语音到文本、文本到语音、语音到语音和全双工交互四个阶段的对齐训练，并提出一个简单的新语音解码器。

影响

在多项语音理解和生成基准上达到当时最好，同时保住文本LLM的能力，并支持全双工对话和按指令控制情感、方言、语速；是通义FunAudioLLM系列在语音对话上的代表模型。

方法

论文把已有语音对话模型分成两类：原生模型（如Moshi全双工语音对话、GLM-4-Voice）把语音token和文本token放在同一个模型里建模，困难是语音序列比文本长得多、可用的语音预训练也不够；对齐模型（如LLaMA-Omni、Freeze-Omni冻结LLM对话）在文本LLM外面接语音编码器和语音解码器，保住了文本能力，但通常数据少、任务窄。MinMo属于后一类，重点是把对齐做大做全。

四阶段对齐：

  • 语音到文本：让LLM听懂语音，覆盖识别、翻译、情感、音频事件等大量理解任务；
  • 文本到语音：训练语音解码器，把LLM的输出变成语音token；
  • 语音到语音：端到端的语音问答与对话；
  • 全双工交互：学习何时开口、何时停下，支持同时双向交流。

训练数据共约140万小时，模型约80亿参数：语音编码器用预训练的SenseVoice与FunAudioLLM-Large编码器初始化，文本LLM是Qwen2.5-7B-Instruct，输出端的语音token语言模型用预训练的CosyVoice 2 LM模块初始化，并沿用CosyVoice 2的流式生成机制。

摘要报告：多阶段训练后在语音理解和生成的多项基准上达到最好；能按指令控制情感、方言、语速并模仿特定声音；语音到文本延迟约100毫秒，全双工延迟理论约600毫秒、实际约800毫秒。

局限与后续

  • 全双工延迟实际约800毫秒，仍明显慢于人类对话中通常两三百毫秒的轮换间隔。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 对齐式结构里语音解码器和LLM分开，副语言信息（语气、笑声）从输入到输出的传递有限。

它建立在什么之上

  • 使用
    SenseVoice与FunAudioLLM2024.07 · 语音
    语音编码器用预训练的SenseVoice-Large编码器初始化。
  • 竞争
    Moshi全双工语音对话2024.09 · 语音
    Moshi是原生全双工模型；MinMo走对齐路线，在保住文本能力的同时加入全双工。
  • 改进
    Freeze-Omni冻结LLM对话2024.11 · 语音
    Freeze-Omni类对齐模型数据少、任务窄；MinMo用140万小时数据和四阶段对齐覆盖更多任务并支持全双工。
  • 使用
    CosyVoice 22024.12 · 语音
    输出端语音token语言模型用CosyVoice 2的LM模块初始化，并沿用其流式音频生成机制。
  • 使用
    Qwen2.52024.12 · LLM
    以Qwen2.5-7B-Instruct作为预训练文本LLM主干。
