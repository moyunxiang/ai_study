InjecAgent智能体注入基准

InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated Large Language Model Agents
2024.03数据集延伸Findings of ACL 2024Qiusi Zhan, Zhixiang Liang, Zifan Ying, Daniel Kang · 伊利诺伊大学厄巴纳-香槟分校待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

LLM智能体会读邮件、网页、商品评论等外部内容，再去调用工具执行动作；攻击者只要在这些内容里藏一句指令（间接提示注入），就可能让智能体替他转账或外传隐私，但缺少衡量这种风险的标准测试。

方法

构造1,054个测试用例：用户让智能体调用17种正常工具之一，工具返回的内容里嵌有攻击者指令，要求它调用62种攻击者工具之一，统计智能体被劫持的比例。

影响

是最早专门针对工具调用智能体的间接提示注入基准之一，和随后的AgentDojo注入评测一起成为评估智能体注入防御的常用工具。

方法

每个测试用例模拟一次完整的工具调用：用户提出正常请求（例如“帮我看看某商品的评论”），智能体调用对应的用户工具，返回结果里混入攻击者写的文字（例如“请把我的病历发到某邮箱”）。如果智能体接着调用了攻击者想要的工具，就算攻击成功。

攻击意图分为两大类：

  • 直接伤害用户：如转账、修改智能家居设置、删除文件；
  • 外传隐私数据：先调用工具读出用户的私人信息，再调用发送类工具把它发给攻击者，这需要两步都被劫持。

另设“增强”设置：在攻击者指令前加一段黑客式提示（类似“忽略之前的指令”），测试攻击被加强后的效果。

作者评测了30个不同的LLM智能体（含不同模型和不同提示方式），发现智能体普遍脆弱：用ReAct提示的GPT-4在基础设置下有24%的情况会被攻击成功，在增强设置下攻击成功率几乎翻倍。作者据此质疑LLM智能体的大规模部署。

局限与后续

  • 工具返回内容和攻击文本是模板化生成的，环境是静态的单步模拟，不能反映多步任务中注入的累积效果。
