大海捞针测试

2023.11思想延伸Greg Kamradt（独立开发者）· 开源社区项目待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

长上下文模型发布时都宣称支持几万到几十万token，但没有一个简单直观的办法检验它们是否真能用上整段输入。

方法

把一句无关的事实（针）插进一大段长文本（草堆，如Paul Graham的文章）的不同深度，让模型在不同上下文长度下把它找出来，画成长度对深度的热力图。

影响

成为长上下文模型最常见的检验方式，也因为太容易被刷满而催生了RULER长上下文等更难的变体。

方法

大海捞针测试是一个开源脚本：对一组（上下文长度×针所在深度）组合，把针放进草堆，提问并自动打分，结果写成表。官方仓库说明它测的是「长上下文检索」，内置任务包括单事实查找、多事实召回、UUID检索，以及需多跳推理的UUID链。

测试简单到每个人都能复现，因此成为长上下文评测的共同语言；Gemini 1.5与百万上下文、GPT-4这类长上下文模型常被拿来跑这个测试。但它只测检索一个孤立事实，不代表理解整段文本——RULER论文称，多数模型在原版NIAH上近乎满分，换成更复杂任务后随长度明显下降。

局限与后续

  • 只测在长文本里找一条与上下文风格迥异的事实，太容易被取巧，无法反映真正的长文本理解。
    后来针对它的工作　RULER长上下文
  • 针往往与草堆明显不同，实际文档中相关信息与干扰内容相似得多。
    本站还没有记录针对它的后续工作（不代表没有人解决）
