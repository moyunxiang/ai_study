GitHub Copilot

Introducing GitHub Copilot: your AI pair programmer
2021.06系统重要GitHub与OpenAI（发布者Nat Friedman） · GitHub / Microsoft待核对
GitHub博客：Introducing GitHub Copilot ↗GitHub博客：正式发布（2022-06） ↗GitHub博客：生产力对照实验 ↗在交互版中打开（演化树、学习进度）

问题

编辑器里的自动补全只能根据语法和符号表补一个变量名或方法名；写样板代码、查陌生API仍要靠手敲和搜索。

方法

把在大量公开代码上训练的语言模型Codex装进编辑器插件：读取光标前后的代码和注释，实时以灰色文字建议下一行乃至整个函数，按Tab接受。

影响

第一个被上百万开发者日常使用的大模型产品，证明了“AI结对编程”有真实需求，并为后来的Cursor、编码智能体铺好了用户习惯和商业模式。

背景

2021年以前，IDE的补全主要靠静态分析：知道一个对象有哪些方法，就把方法名列出来。也有基于小模型的补全工具，但通常只补一个词或几个token。GPT-3发表后，人们发现它能根据注释写出简单代码，OpenAI随即在大量公开GitHub代码上继续训练，得到专门写代码的Codex（论文于2021年7月发表）。问题是如何把这种能力放进程序员每天的工作流里，而不是停留在演示网页上。

方法

GitHub Copilot于2021年6月29日以“技术预览”形式发布，是VS Code等编辑器的插件，背后是OpenAI Codex。

工作方式。程序员正常写代码，插件把当前文件中光标附近的代码、函数签名和注释整理成提示发给模型，模型以自回归生成方式续写，结果以灰色“幽灵文字”显示在光标处：可能是一行，也可能是整个函数或一组单元测试。按Tab接受，继续打字则忽略，也可以翻看其他候选。例如写下注释“// 解析ISO日期并返回时间戳”和函数名，它往往能直接给出完整函数体。

定位。官方称预览版对Python、JavaScript、TypeScript、Ruby和Go效果最好。2022年6月21日正式收费：个人每月10美元或每年100美元，认证学生和流行开源项目维护者免费，支持VS Code、Visual Studio、JetBrains和Neovim。

结果

官方称技术预览一年内有超过120万开发者使用，在启用它的文件里，Python等主流语言中近40%的代码由Copilot写出。GitHub在2022年9月公布的对照实验中，95名专业开发者随机分组用JavaScript写HTTP服务器，使用Copilot的一组平均用时1小时11分钟，对照组2小时41分钟，快55%；完成率78%对70%。

另一面，Pearce等人在2021年8月针对高风险漏洞场景让Copilot生成了1689个程序，约40%存在安全漏洞。

后来的发展

Copilot把“大模型写代码”变成了按月付费的日常工具，后来的产品都在它的交互上加码：2022年发表的中间填充FIM让模型同时看光标前后文，成为代码补全的标准训练方式；Cursor AI编辑器把整个编辑器围绕模型重做；Aider、SWE-agent和Claude Code与终端编码智能体让模型直接改多个文件、运行命令。Copilot自己也从补全扩展到聊天（2023年11月换用GPT-4）、可选多家模型，2025年加入“agent模式”和在云端接任务、提交PR的编码智能体（参见云端异步编码智能体）。训练数据引发的许可证争议也在2022年11月演变成集体诉讼。

容易误解的地方

  • Copilot不是一个模型，而是产品；早期背后是OpenAI Codex，后来换过多代模型，并允许用户选择不同厂商的模型。
  • “快55%”来自一项特定任务（写HTTP服务器）的对照实验，不能直接推广为所有编程工作都快一半。

本篇术语

  • 幽灵文字（ghost text）　编辑器在光标处用灰色显示的模型建议，按Tab才真正写入文件。
  • 技术预览　限量邀请、免费试用的早期版本，用来收集反馈，功能和定价都可能变化。

怎么学

先了解语言模型和自回归生成续写，再读Codex论文第2–3节，理解pass@k和代码模型怎样训练。然后读GitHub那篇对照实验博客，注意实验设计和它没有回答的问题。动手：装一个开源补全插件（如接本地代码模型的Continue），对比只给光标前文和同时给前后文时的补全质量。
