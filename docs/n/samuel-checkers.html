Samuel跳棋程序

Some Studies in Machine Learning Using the Game of Checkers
1959论文延伸IBM Journal of Research and Development 1959Arthur L. Samuel · IBM待核对
Wikipedia ↗在交互版中打开（演化树、学习进度）

问题

让计算机下好棋，传统做法是程序员手写评估规则，水平停在程序员本人的水平。

方法

让程序自己下棋、不断调整评估函数里的权重，并把搜索得到的深层评估作为浅层评估的学习目标。

影响

第一个有影响的自学习博弈程序，Samuel在1959年提出“机器学习”一词，其“用后续预测修正当前预测”的做法是时序差分的前身。

方法

据维基百科，Samuel在IBM开发了跳棋程序，是最早成功的自学习程序之一，他于1959年提出了“machine learning”这个词，并且是alpha-beta剪枝的早期实现者之一。

程序用一个评估函数给局面打分：若干人为设计的棋盘特征（子力、位置、控制中心等）乘以权重再求和。搜索几步后用这个分数选走法。学习有两种：死记——保存见过局面的搜索得分以后直接查；泛化——调整特征权重，让当前局面的分数更接近几步搜索之后的分数。这就是用“后面的预测”修正“前面的预测”，思想上就是时序差分学习。程序还通过自我对弈提高，并用Alpha-Beta剪枝分析类剪枝加速搜索。

后来的发展

这一“自举”思想被Sutton系统化为时序差分学习；相似的自我对弈学习在TD-Gammon大放异彩。

局限与后续

  • 特征需要人手工设计，权重学习也缺少理论保证。
    后来针对它的工作　时序差分学习 TD-Gammon
  • 只在跳棋这个小游戏上验证，通用性不清楚。
    后来针对它的工作　TD-Gammon

它建立在什么之上

  • 改进
    维纳《控制论》1948 · 事件
    提供的是跨学科的类比和数学框架，没有给出能执行复杂任务（下棋、证明定理）的具体程序或算法。
  • 改进
    香农：计算机下棋1950 · RL
    评估函数的项和系数全靠人手写，机器不会从对局中改进自己，香农本人也承认这是主要弱点。
  • 使用
    动态规划与Bellman方程1957 · RL
    用后续状态的价值更新当前状态，和Bellman递推同构，但用采样而非完整模型。

后来的相关工作

  • 延续
    Actor-Critic（ASE/ACE）1983 · RL 已核对
    继承Samuel“用后来的评估修正先前评估”的想法，并把它写成一条简单的类神经元更新规则。
  • 改进
    时序差分学习1988 · RL
    Samuel用后续评估修正当前评估的做法缺乏理论，TD给出了一般形式和收敛证明。
  • 改进
    TD-Gammon1995 · RL
    延续Samuel“程序自己下棋、用后来的评估修正先前评估”的思路，把线性特征换成神经网络并用TD(λ)规范化。
  • 延续
    Arcade学习环境ALE2012.07 · RL
    延续用游戏作为AI试验场的传统，但从单一棋类扩展到几十款风格各异的电子游戏。
  • 延续
    维纳论自动化的后果1960.05 · 安全·可解释
    沿用Samuel程序「学得比设计者更强」的事实，进一步追问设计者如何确保它追求的目标是对的
  • 使用
    信用分配问题的提出1961 · RL
    把Samuel程序作为信用分配的典型例子来分析。
  • 延续
    ICML的起点1980 · 事件
    Samuel的跳棋学习是机器学习最早的著名案例，这个社区在二十年后才形成自己的会议。
  • 竞争
    Chinook夺得跳棋人机冠军1994 · RL
    同样玩跳棋，Samuel靠学习，Chinook靠搜索加人工知识库，后者最终取胜。
  • 延续
    Logistello击败黑白棋世界冠军1997.08 · RL
    沿着Samuel“让程序从数据里学评估函数”的路线，规模大了几个量级。
