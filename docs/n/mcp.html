模型上下文协议MCP

Introducing the Model Context Protocol
2024.11系统主干David Soria Parra, Justin Spahr-Summers · Anthropic来源已核对
官方公告 ↗规范2024-11-05 ↗捐赠给AAIF的公告 ↗在交互版中打开（演化树、学习进度）

问题

函数调用让模型能用工具，但每个AI应用都要为每个数据源单独写一遍接入代码：M个应用×N个系统，就是M×N份互不通用的集成。

方法

定义一个开放协议：数据源和工具方各写一个“MCP服务器”，AI应用各实现一个“MCP客户端”，双方用JSON-RPC说同一种话，M×N变成M+N。

影响

据Anthropic在2025年12月的统计，一年内已被ChatGPT、Gemini、Cursor、VS Code等采用，活跃公开服务器超过1万个；同月移交Linux基金会下新成立的AAIF。

背景

2023年函数调用成为标准接口成为大模型API的标配：开发者把一个函数的名字、参数用JSON Schema描述给模型，模型输出结构化的调用请求，由应用代码去真正执行（见工具调用）。这解决了“模型怎么表达想调用什么”，但没解决“工具从哪里来”。

每个AI应用都得自己写连接代码：想让聊天助手读Google Drive，要写一个Drive适配器；想让编程助手查GitHub，又写一个。换一个应用，这些代码基本不能复用。ChatGPT插件试过用OpenAPI描述文件统一插件，但只在ChatGPT里有效；Assistants API与GPTs的Assistants API同样绑在一家平台上；LangChain提供了大量现成的工具封装，但那是一个Python/JS库，工具必须和应用跑在同一个进程里。

Anthropic在公告里把问题概括为：模型被困在“信息孤岛”里，每接一个新数据源都要定制实现，连通的系统难以规模化。软件业以前遇到过同样的结构性问题：每个编辑器都要为每种语言单独做补全和跳转，直到微软的语言服务器协议LSP把它变成“编辑器实现一次客户端、语言实现一次服务器”。MCP的规范明确说它借鉴了LSP。

方法

2024年11月25日，Anthropic开源了MCP规范和SDK，并在Claude桌面应用里支持本地MCP服务器，同时发布了一个开源的MCP服务器仓库。

三种角色。宿主（host）是用户直接使用的AI应用，如Claude桌面版或一个IDE；宿主内部为每个连接开一个客户端（client）；服务器（server）是暴露数据和能力的独立程序，比如一个“GitHub服务器”。

消息格式。所有通信都是JSON-RPC 2.0：请求带方法名和参数，响应带结果或错误。连接建立时双方先交换各自支持哪些功能（能力协商），之后保持一个有状态的会话。

服务器能提供三类东西：

  • 工具（tools）：模型可以调用的函数，例如create_issue(repo, title, body)，由模型决定何时调用；
  • 资源（resources）：可读取的上下文数据，如一个文件、一张数据库表，规范称它由宿主应用决定怎样放进上下文（和检索增强生成RAG一样，都是把外部数据放进模型的输入）；
  • 提示模板（prompts）：服务器预先写好的工作流模板，由用户挑选使用。

客户端反过来可以提供采样（sampling）：服务器请求宿主替它调用一次大模型，从而实现嵌套的智能体行为，但规范要求用户明确批准。

传输层。初版定义两种：stdio（宿主把服务器作为子进程启动，按行收发JSON消息，适合本地工具）和HTTP加服务器推送事件SSE（适合远程服务）。

一次调用的流程：宿主启动时连接配置好的服务器，调用tools/list拿到所有工具的名字、说明和参数Schema，把它们作为函数定义交给模型；模型在对话中决定调用某个工具，宿主经客户端发出tools/call，把返回结果再塞回模型上下文，进入下一轮智能体循环。对模型而言这仍是普通的函数调用，MCP标准化的是函数定义从哪来、调用发往哪里。

结果

发布当天Anthropic提供了Google Drive、Slack、GitHub、Git、Postgres、Puppeteer等预置服务器，Block、Apollo已经接入，Zed、Replit、Codeium、Sourcegraph等开发工具公司宣布跟进。

2025年采用面明显扩大：3月26日OpenAI CEO宣布将在自家产品中支持MCP，当天已在Responses API与Agents SDK中可用；同月规范的2025-03-26修订版加入基于OAuth 2.1的授权框架，并用更灵活的Streamable HTTP取代HTTP+SSE，远程服务器从此可用。官方在2025年12月称：活跃的公开MCP服务器超过1万个，ChatGPT、Cursor、Gemini、Microsoft Copilot、VS Code等已采用，Python和TypeScript SDK月下载量超过9700万。

后来的发展

MCP让“给智能体加能力”更接近装插件：Claude Code与终端编码智能体的官方文档把MCP列为连接外部服务的扩展方式，Codex CLI、Gemini CLI等编码智能体也支持MCP，ChatGPT应用与Apps SDK把它扩展到能在ChatGPT里渲染界面的应用，OpenClaw个人智能体这类个人智能体则靠它连接用户的各类账户。2025年12月9日，Anthropic把MCP捐给Linux基金会新成立的智能体AI基金会AAIF，与Block的goose、OpenAI的AGENTS.md并列。

大规模使用也暴露了协议本身的代价，引出了后续改进：工具说明太多会挤占上下文，于是有了用代码调用工具和Agent Skills的按需加载；智能体之间的协作由Agent2Agent协议另立协议；Anthropic的捐赠公告称2025年11月25日的规范版本已加入异步操作、无状态等特性，之后的MCP 2026-07-28规范规范也以便于云上水平扩展为目标。

容易误解的地方

  • MCP不是一种新的模型能力。模型看到的仍是函数调用；MCP规定的是工具的发现、描述和调用怎么在应用与外部程序之间传递。
  • MCP服务器不一定在远端。初期大多数服务器是用户电脑上的本地进程，通过stdio与桌面应用通信。
  • 协议本身无法保证安全。规范写明工具等同于任意代码执行，用户同意和权限控制要由宿主实现，协议层无法强制。

读懂它需要的概念

工具调用 智能体循环 上下文窗口 检索与向量数据库 提示注入

本篇术语

  • JSON-RPC 2.0　一种很简单的远程调用格式：请求是一个带method、params、id字段的JSON对象，响应带result或error，用id对应起来。
  • LSP（语言服务器协议）　微软2016年提出的协议，让编辑器与“语言服务器”通信来获得补全、跳转等功能，使M个编辑器×N种语言的问题变成M+N。MCP借用了这个设计。
  • 宿主 / 客户端 / 服务器　宿主是用户用的AI应用；客户端是宿主里负责一条连接的组件；服务器是提供工具和数据的外部程序。
  • stdio传输　宿主把服务器当作子进程启动，通过它的标准输入输出逐行收发JSON消息，不需要网络。

怎么学

先弄懂工具调用：模型如何输出一个结构化的函数调用。再读官方公告和规范的Overview与Architecture两页，重点看tools/list与tools/call两个方法的请求和响应格式。动手：用官方Python SDK写一个暴露两个工具（比如查天气、读本地文件）的MCP服务器，接到Claude桌面版或任意支持MCP的编码智能体里，观察模型何时调用它。最后读用代码调用工具，理解工具多了以后上下文为什么会被挤爆。
