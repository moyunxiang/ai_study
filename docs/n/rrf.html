倒数排名融合RRF

Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods
2009.07论文延伸SIGIR 2009Gordon V. Cormack, Charles L. A. Clarke, Stefan Büttcher · 滑铁卢大学 / Google待核对
ACM DL ↗PDF ↗Elasticsearch RRF文档 ↗在交互版中打开（演化树、学习进度）

问题

多个检索系统各给一份排名，分数的量纲和分布互不相同，直接相加没有意义；当时的融合方法要么依赖原始分数，要么像Condorcet投票那样复杂。

方法

完全不看分数，只看名次：每份排名里第r名的文档得 1/(k+r) 分，k取60，把各份排名的得分加起来重新排序。

影响

一行公式、不需训练，至今是关键词检索与向量检索做混合检索时最常用的融合方法，Elasticsearch等搜索引擎内置了它。

方法

TREC文本检索评测式评测里常有几十个检索系统针对同一查询给出排名。融合它们的标准做法是Condorcet Fuse（两两多数投票）和CombMNZ（把各系统的分数相加，再乘以命中该文档的系统数），后者要求分数可比。作者原本只想做一个简单基线，结果它几乎总是最好。

公式。对文档d，RRF(d) = Σ_r 1/(k + r(d))，r(d)是它在第r份排名中的名次。名次靠前的贡献大，但靠后的文档贡献不会像指数衰减那样迅速消失；常数k压低了某一个离群系统把文档顶到第一名的影响。k=60在试验阶段定下，之后没有再调；表1中k从10到100的MAP都在0.21左右，说明对k不敏感。

结果。融合TREC 3、5、9和2004 Robust四组提交结果，RRF的MAP在所有情况下都高于Condorcet，四次中三次高于CombMNZ。在LETOR 3的58万多个文档—查询对上，把ListNet列表式排序、Ranking SVM点击学排序、AdaRank、RankBoost等学习排序方法的输出用RRF融合，MAP为0.6051，高于其中任何单个方法（最好的ListNet为0.5846）。

后来稠密向量检索兴起，BM25关键词结果与向量结果的分数完全不可比，RRF因此成为混合检索的默认选择；Elasticsearch的RRF检索器默认k也是60。

局限与后续

  • 只用名次、丢掉了分数大小，一个系统非常确信的结果与勉强排进前列的结果被同等对待；也不能按系统好坏加权。

它建立在什么之上

  • 使用
    TREC文本检索评测1992.11 · 数据·评测
    用TREC 3、5、9和Robust赛道参赛系统提交的真实排名来验证融合效果。
  • 延续
    BM251994 · NLP
    BM25等检索函数给出的分数难以跨系统比较；RRF只用名次，后来成为把BM25与向量检索结果合并的标准做法。
  • 使用
    Ranking SVM点击学排序2002.07 · NLP
    Ranking SVM是被融合的学习排序方法之一，RRF融合后的MAP比它高约0.03。
  • 使用
    ListNet列表式排序2007.06 · NLP
    把ListNet等学习排序方法在LETOR 3上的输出当作待融合的排名，融合结果超过其中最好的单个方法。

读懂它需要的概念

检索与向量数据库 基准、排行榜与SOTA 集成学习

本篇术语

  • MAP（平均精度均值）　对每个查询，在每个相关文档出现的位置计算一次精度并取平均，再对所有查询取平均；越接近1说明相关文档排得越靠前。
  • Condorcet Fuse　把每份排名当作选票，按“多数系统认为A排在B前面”的两两比较结果来排序的融合方法。

怎么学

先补BM25和TREC文本检索评测的评测方式 → 原文只有两页，直接读公式和表1到表3 → 动手：对同一组查询分别用BM25和一个嵌入模型检索，用RRF融合，比较融合前后的召回率。
