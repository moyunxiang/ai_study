Cyc常识知识库

1984系统延伸Douglas Lenat · MCC，后为Cycorp待核对
Wikipedia ↗在交互版中打开（演化树、学习进度）

问题

专家系统只懂一个狭窄领域，一离开领域就出笑话，缺的是人人都有的常识。

方法

1984年Lenat在MCC启动Cyc：由人手工把常识写成形式化断言和规则，建一个覆盖基本概念与世界运行方式的巨大本体和知识库。

影响

成为“靠手工输入知识获得常识”路线的最大实验，数十年未能达到通用常识，也成为后来数据驱动方法的反面参照。

方法

据Wikipedia，Cyc（取自encyclopedia）于1984年7月由Douglas Lenat在微电子与计算机技术公司MCC启动，MCC是两家美国公司为“对抗日本第五代计划”而成立的研究联盟；1995年1月起由Lenat任CEO的Cycorp接手开发。

Cyc关注隐含知识，即人人默认但很少写出来的事实。它用自己的表示语言CycL（起源于Lenat早先的RLL）写下事实和规则，再由推理引擎做推导。CycL规范是公开的，但推理引擎代码和完整的启发式模块清单是Cycorp专有的。

这是《具有常识的程序》“用逻辑表示常识”设想最大规模的实现尝试，也是1980年代对日本第五代计算机计划的美国式回应之一。

局限与后续

  • 全靠人手工逐条录入，知识量和一致性维护成本极高，几十年也没达到能自动学习新知识的程度。
    后来针对它的工作　GPT-3
  • 引擎与大部分内容为专有，外界难以独立评估其成果。

  • 改进
    德雷福斯的哲学批判1972 · 事件
    关于背景常识无法被机器获得的论断，当时没有可检验的形式，也低估了从海量数据中学习常识的可能。
  • 改进
    物理符号系统假说1976.03 · 事件
    常识知识量巨大且难以写成显式规则，按符号路线逐条录入几乎不可能完成。
  • 改进
    专家系统的商业化1980 · 事件
    想弥补专家系统领域狭窄、缺乏常识的脆弱性，但用的仍是手工规则。
  • 改进
    《具有常识的程序》1959 · 事件
    把McCarthy提出的“用逻辑陈述表示常识”落实成一个长期的工程项目。
  • 改进
    McCarthy获图灵奖1971 · 事件
    他提倡的“逻辑加常识”路线始终没有造出通用常识系统，被数据驱动的方法超越。
  • 竞争
    日本第五代计算机计划1982 · 事件
    项目在MCC内为抗衡日本第五代计划而启动。
