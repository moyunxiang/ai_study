modded-nanogpt速通

2024.06系统延伸Keller Jordan 与社区贡献者待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

训练一个GPT-2级别的小模型本来要几十分钟到几小时，没有一个公开的、可量化比较的基准来竞赛哪些训练技巧真正有效。

方法

设立NanoGPT速通（speedrun）：固定硬件为8块H100、固定目标为FineWeb验证集损失3.28，大家协作或竞争，看谁能用最短的墙钟时间达到。

影响

把「训练效率」变成可复现、可刷榜的公共竞赛，不少技巧（如Muon优化器优化器）由此被验证并推广。

方法

仓库从llm.c的PyTorch训练代码出发，llm.c的GPT-2复现要约45分钟才能达到3.28的验证损失。社区在这个基础上逐项提交改进，每项改进都记录运行日志以便复现：更好的优化器、改进的架构细节、低精度、更高效的数据和内核等。每刷新一次纪录，仓库就更新一次。

README当前标题是「NanoGPT (124M) in 90 seconds」，即纪录已被压到约90秒（这是我读取页面时的状态，纪录会继续变化）。

后来的发展

这些技巧中最有影响的包括Muon优化器，它之后又在大模型上被验证（见Muon规模化到LLM）；仓库也是nanochat的思路来源之一。

局限与后续

  • 目标是124M小模型在固定数据上的速度，技巧能否迁移到更大模型、更长训练并不总是成立。
    后来针对它的工作　Muon规模化到LLM
  • 追逐纪录的改动可能过拟合这一个基准，牺牲通用性。
    本站还没有记录针对它的后续工作（不代表没有人解决）

读懂它需要的概念
