神经缓存语言模型

Improving Neural Language Models with a Continuous Cache
2016.12论文延伸ICLR 2017Edouard Grave, Armand Joulin, Nicolas Usunier · Facebook AI Research待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

文章里刚出现过的词很可能再次出现（人名、地名、术语），LSTM语言模型却很难把几百上千词之前的具体词「抄」过来；带记忆的网络能做到，但要额外训练且计算昂贵。

方法

把最近几千个时刻的隐状态和它们后面的那个词存起来；预测时用当前隐状态与存储的隐状态做点积，相似的历史位置就把它的下一个词的概率调高，再与原模型的分布插值。

影响

不需要训练、可直接加到任何预训练LSTM上，在WikiText-2上把困惑度从99.3降到68.9；它把n-gram时代的缓存模型带进了神经语言模型，也成为之后动态评估、kNN-LM等「从上下文检索」方法的常见对照。

方法

缓存模型最早出现在语音识别里（Kuhn与De Mori等，1988–1990）：把最近出现过的词的一元频率混进n-gram模型，因为文章倾向于重复用词。神经网络版本的对应物是端到端记忆网络、Pointer Sentinel（见WikiText）等记忆/指针网络，它们需要专门训练注意力参数，计算量也随记忆长度增长。

神经缓存把这件事简化到极点。在LSTM语言模型运行时，记下每个位置i的隐状态h_i和它之后实际出现的词x_{i+1}。在第t步：

p_cache(w) ∝ Σ_{i<t} 1{x_{i+1}=w} · exp(θ · h_t·h_i)

即凡是与当前状态相似的历史位置，都把票投给它后面的那个词，θ控制分布的尖锐程度。最终分布是线性插值p = (1−λ)·p_vocab + λ·p_cache。只有θ和λ两个标量，在验证集上调即可，模型本身不再训练，存储几千个位置也几乎不增加开销。

结果：WikiText-2测试集上，作者自己的LSTM困惑度99.3，加100个位置的缓存为81.6，加2000个位置为68.9，低于Pointer Sentinel LSTM的80.8；在1亿词的WikiText-103上从48.7降到40.8，相对改进约16%，比小数据上的约30%小。作者也指出，在103M词上训练的普通LSTM远远好过在2M词上训练的复杂模型，因此主张在较大的数据上比较方法。

局限与后续

  • 缓存只能「抄」最近出现过的词，对从未在上下文中出现过的长距离信息没有帮助，且依赖人工调的插值权重。
    后来针对它的工作　Transformer-XL
  • 改进随训练数据增大而缩小，说明它补的主要是小模型记不住上下文的缺陷，而不是新的建模能力。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    LSTM1997 · 基础
    缓存存储的是LSTM语言模型各时刻的隐状态，可直接加在预训练LSTM之上。
  • 改进
    缓存语言模型1990.06 · NLP
    缓存只记录词频，不区分词出现时的上下文，对「同一个词在不同语境下」无法区别对待。
  • 竞争
    端到端记忆网络2015.03 · NLP
    端到端记忆网络需要训练注意力参数访问记忆；神经缓存用隐状态点积直接查表，无需训练，能扩展到几千个位置。
  • 改进
    WikiText2016.09 · 数据·评测
    WikiText论文提出的Pointer Sentinel要训练指针网络来复制上下文词，神经缓存不训练也达到更低困惑度。

读懂它需要的概念

本篇术语

  • 缓存模型　把最近出现过的词的统计混进语言模型，利用「文章倾向重复用词」这一现象。
  • 线性插值　两个概率分布按权重λ和1−λ相加，得到的仍是合法的概率分布。

怎么学

先读AWD-LSTM或任一LSTM语言模型教程 → 读原文第3节（神经缓存的定义与插值）→ 动手：在一个训练好的小LSTM语言模型上实现缓存，扫描θ和λ，观察验证集困惑度随缓存长度的变化。
