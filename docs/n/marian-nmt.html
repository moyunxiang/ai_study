Marian C++翻译框架

Marian: Fast Neural Machine Translation in C++
2018.04系统延伸ACL 2018 DemoMarcin Junczys-Dowmunt, Roman Grundkiewicz, Tomasz Dwojak, Hieu Hoang, Kenneth Heafield, Tom Neckermann, Frank Seide, Ulrich Germann et al. · 微软、爱丁堡大学、波兹南大学等待核对
arXiv ↗项目主页 ↗在交互版中打开（演化树、学习进度）

问题

2017年前后的神经机器翻译工具大多基于Python和通用深度学习框架（Theano、TensorFlow），训练和推理都慢，部署到生产系统要再写一套C++代码。

方法

用纯C++从零写一个只为翻译服务的框架：自带基于动态计算图的自动微分引擎，内置RNN与Transformer编码器-解码器、多GPU训练、批量束搜索解码，没有Python依赖。

影响

Marian成为WMT评测中许多冠军系统和微软翻译的训练与推理工具；Hugging Face上上千个「Opus-MT」双语翻译模型都用Marian训练，至今被大量下载使用。

背景

研究用的NMT工具如Nematus（基于Theano）、OpenNMT（Lua/PyTorch）、tensor2tensor（TensorFlow）方便改模型，但速度受限于框架的通用性和Python开销；工业界部署往往要重新实现推理。爱丁堡大学的Nematus团队此前已写过一个只做推理的C++解码器amun，Marian是在此基础上扩展出训练能力的完整框架。

方法

自动微分。 Marian实现了自己的反向模式自动微分：前向计算时动态构建表达式图，节点是张量运算，反向时按拓扑逆序计算梯度；针对GPU写了融合的CUDA核（例如把层归一化、softmax的多个步骤合并），减少显存读写。

模型。 内置深层RNN（带注意力的编码器-解码器、Nematus兼容结构）和Transformer，支持模型集成、语言模型融合。

训练。 同步/异步的多GPU数据并行，按显存动态决定批大小（按token数而不是句子数组批），支持梯度延迟累积以模拟大批量。

解码。 批量束搜索，多个句子同时解码，CPU与GPU都能跑；后来加入8位整数量化等推理优化。

结果

摘要称：描述了编码器-解码器框架的设计，并展示了一个便于研究的工具包也能达到很高的训练和翻译速度。论文中的具体速度对比数字未核对。

后来的发展

Marian被WMT多年的高效翻译共享任务和很多参赛系统采用，微软翻译的生产模型也基于它。赫尔辛基大学用Marian在OPUS语料上训练并公开了上千个语言对的Opus-MT模型，后被移植到Hugging Face Transformers（MarianMT类）。浏览器本地翻译（Firefox Translations / Bergamot项目）也用Marian的量化推理。

局限与后续

  • C++实现修改模型结构的门槛高，研究者做新架构实验时仍更常用基于PyTorch的fairseq等工具。

读懂它需要的概念

自动微分与计算图 编码器-解码器 CPU、GPU与并行计算 吞吐、延迟与批处理 解码：贪心、束搜索、温度与top-p

本篇术语

  • Opus-MT　赫尔辛基大学用Marian在OPUS开放平行语料上训练并公开的大量双语翻译模型。
  • 按token组批　每个批次按总token数而不是句子数确定大小，长短句混在一起时更能用满显存。

怎么学

先了解Transformer编码器-解码器 → 读原文第2–3节框架设计 → 动手：用Hugging Face的MarianMT加载一个Opus-MT英中模型翻译几句话，再用marian-decoder命令行比较CPU推理速度。
