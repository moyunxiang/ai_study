《Building Effective Agents》

Building Effective Agents
2024.12思想延伸Anthropic工程博客 2024-12-19Erik Schluntz, Barry Zhang · Anthropic待核对
Anthropic博客 ↗在交互版中打开（演化树、学习进度）

问题

「智能体」一词被滥用，团队常一上来就套重型框架，结果系统复杂、难调试，却不一定更有效。

方法

区分工作流和智能体，并总结一组简单可组合的模式，建议先用最简单的方案，需要时才增加复杂度。

影响

成为工程界讲智能体设计的常引用文献，确立了「先工作流、后智能体」的思路。

方法

文章给出一个架构上的区分：工作流是由预设代码路径编排LLM和工具；智能体是LLM自己动态决定流程和工具使用。Anthropic把两者统称agentic systems。核心建议是找最简单的方案，只在需要时才增加复杂度，因为智能体常以延迟和成本换取更好的任务表现。

文中列出的工作流模式包括：提示链（把任务拆成顺序步骤，中间可加检查）、路由（先分类再交给专门的后续处理）、并行化、编排者-工作者（中心LLM动态拆分任务分发给工作者再汇总）和评估者-优化者。作者还建议不必一开始就用重型框架，直接用API往往够用。文章页首注明：自2024年12月以来文中的很多工具已变化。

后来的发展

这篇文章让「工作流还是智能体」成为设计时必问的问题，与多智能体为何失败对多智能体失败的研究互相印证；之后的上下文工程和Claude Agent SDK把这些经验落成工程实践。
