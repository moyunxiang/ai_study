Magicoder与OSS-Instruct

Magicoder: Empowering Code Generation with OSS-Instruct
2023.12论文延伸ICML 2024Yuxiang Wei, Zhe Wang, Jiawei Liu, Yifeng Ding, Lingming Zhang · 伊利诺伊大学厄巴纳-香槟分校 等待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

用大模型凭空合成代码指令（Self-Instruct、Evol-Instruct）时，题目会集中在模型自己熟悉的少数类型上，带着教师模型的偏差，真实性和多样性不足。

方法

提出OSS-Instruct：每次从开源代码库里随机抽一段真实代码片段给大模型当“灵感”，让它据此出一道编程题并给出解答，用开源代码的多样性来对冲合成数据的偏差。

影响

让70亿参数的完全开源代码模型在HumanEval+上略超ChatGPT；“以真实种子数据引导合成”的做法被后来的代码指令数据和代码模型广泛借鉴。

方法

OSS-Instruct的流程：从开源代码语料中随机取一段几行到几十行的代码，连同提示交给ChatGPT，要求它受这段代码启发写出一个自包含的编程问题和对应解答。由于种子代码覆盖了大量真实的库、领域和写法，生成的题目比凭空想象的更贴近实际开发，也更多样。作者这样得到约7.5万条指令数据，用它微调7B级的开源基座（如Code Llama），得到Magicoder。

它与WizardCoder的Evol-Instruct是正交的：一个靠种子代码扩展题目的覆盖面，一个靠逐步改写提高题目难度。两者叠加训练得到的MagicoderS效果更好。作者报告，MagicoderS-CL-7B在HumanEval+上pass@1为66.5，超过ChatGPT的65.9；Magicoder系列在多个代码基准上超过同等甚至更大规模的代码模型，并且代码、权重和数据全部开源。

局限与后续

  • 题目和答案仍由闭源模型生成，答案没有经过执行验证；种子代码也可能与评测题重合，存在数据污染的风险。

读懂它需要的概念

怎么学

先读Self-Instruct和WizardCoder；读本文OSS-Instruct的提示模板和数据多样性分析；动手：从自己的代码库里随机抽20段代码，用一个开源模型按OSS-Instruct方式出题，比较与凭空出题的差异。
