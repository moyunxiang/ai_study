Claude Opus 4.5

Introducing Claude Opus 4.5
2025.11模型重要Anthropic待核对
官方公告 ↗Claude Opus 4.5 System Card ↗在交互版中打开（演化树、学习进度）

问题

最强的Opus档模型太贵、用量受限，日常编码和长时程智能体任务多用中档的Sonnet；而前沿模型做长任务时要么想得太多浪费token，要么半途卡住。

方法

新一代Opus把价格降到每百万token输入5美元、输出25美元，并在API加入effort参数让开发者在“省token”和“多思考”之间调节，配合上下文压缩、子智能体编排等工具支撑更长的自主任务。

影响

Opus档首次成为日常主力模型；它在2025年末带动Claude Code在非程序员中流行，也是后续Opus 4.6和Mythos系列的直接前身。

背景

2025年，编码智能体（Claude Code与终端编码智能体、Cursor、Codex）成为大模型最赚钱的用途，评价模型的标准从答题转向“能否在真实代码库里独立完成任务”，如SWE-bench Verified和Terminal-Bench 2.0与Harbor。Anthropic的产品线分Haiku、Sonnet、Opus三档，Claude 4以来Opus能力最强，但价格高、订阅里有单独配额，大部分开发者实际用的是同年9月的Claude Sonnet 4.5。

同月的Gemini 3和GPT-5.1也在争夺这个市场。另一个痛点是成本不可控：推理模型往往在简单任务上也长篇思考，在长任务里又会因上下文用满而中断。

方法

模型本身的训练细节未公开，公告重点在三方面。

价格与配额。API价格降为每百万token输入5美元、输出25美元，取消Claude应用里Opus专属的用量上限，Max用户可用的Opus token约等于此前的Sonnet用量。

effort参数。开发者可设低、中、高三档努力程度（概念上类似思考预算与推理强度），决定模型花多少token思考和反复检查。这让同一个模型既能当快速助手，也能当深度求解器。

长任务配套。上下文压缩（快满时自动总结早期内容，见上下文窗口）、更强的工具调用、管理一组子智能体的能力（见智能体循环）；Claude Code的计划模式会先提问、写出可编辑的plan.md再执行。安全上，官方称它是抗提示注入最强的前沿模型。

结果

官方称：在中档effort下，它在SWE-bench Verified上追平Sonnet 4.5的最好成绩，但输出token少76%；最高档比Sonnet 4.5高4.3个百分点，token仍少48%。Aider Polyglot比Sonnet 4.5提高10.6%，Vending-Bench长期经营模拟多赚29%。组合使用压缩、记忆和子智能体后，一个深度研究评测从70.48%升到85.30%。在Anthropic性能工程岗的2小时笔试中（使用并行采样），得分超过了所有参加过的人类候选人。

后来的发展

Opus 4.5让“用最强模型干日常活”在价格上可行，2025–2026年冬季Claude Code在大量非程序员中流行起来（见Vibe Coding）。三个月后的Claude Opus 4.6在它的基础上继续改进；2026年4月的Claude Mythos分级开放则把能力推到一个新档位，并第一次因网络攻防风险而不公开发布。

容易误解的地方

  • 公告中的大部分数字是厂商自测，SWE-bench Verified等成绩以图表给出；不同厂商的评测设置（思考预算、harness、重试次数）不同，横向比较要谨慎。
  • τ2-bench里它绕开“经济舱不能改签”的方式是先升舱再改签，被判为失败。官方认为这是创造性解法，但同样的能力用在不该用的地方就是规约博弈。

读懂它需要的概念

语言模型 推理token与测试时计算 上下文窗口 智能体循环 工具调用 基准、排行榜与SOTA

本篇术语

  • effort参数　API里控制模型投入多少计算的开关：低档少思考、少检查，快而省；高档多思考，慢而准。
  • 上下文压缩（compaction）　对话或任务快用满上下文窗口时，让模型把前面的内容总结成短摘要再继续，以换取更长的工作时间。
  • 并行测试时计算　同一题让模型独立做多次，再从多个结果中挑最好的，用更多算力换更高准确率。

怎么学

先补智能体循环和工具调用，再看SWE-bench Verified是怎么评测编码智能体的。读官方公告的评测部分和脚注（注意每个数字的设置），再翻System Card的对齐与提示注入章节。动手：用同一个编码任务分别以低、高effort调用模型，记录成功率和token数。
