NLLB两百种语言翻译

No Language Left Behind: Scaling Human-Centered Machine Translation
2022.07论文重要arXiv 2022；Nature 2024NLLB Team: Marta R. Costa-jussà, James Cross, Onur Çelebi, Maha Elbayad, Kenneth Heafield, Kevin Heffernan, Elahe Kalbassi et al. · Meta AI待核对
arXiv ↗Nature论文（2024） ↗代码与模型 ↗在交互版中打开（演化树、学习进度）

问题

机器翻译的进步集中在少数高资源语言上，世界上大多数语言几乎没有平行语料，连可靠的评测集都没有，模型在这些语言上的质量无从衡量，更谈不上改进。

方法

从数据、模型、评测三方面同时下手：请专业译者为200多种语言做统一的评测集Flores-200和种子训练数据；训练能识别200多种语言的语言识别器和跨语言句向量LASER3，从网页中挖掘出11亿对句子，再加上回译数据；用545亿参数的稀疏混合专家模型一次覆盖200种语言。

影响

一个模型支持200种语言、4万多个翻译方向，在Flores-101上平均spBLEU比此前最好结果高约44%；数据、模型和评测集全部开源，并被用于帮助维基百科编辑翻译低资源语言条目。2024年以修订版发表于《自然》。

背景

多语言NMT与零样本翻译证明了一个模型可以翻多种语言，M2M-100非英语中心翻译把规模推到100种语言并直接挖掘非英语句对。但覆盖面仍集中在有大量网络文本的语言上，非洲、南亚等地区的数百种语言几乎被忽略。原因是一个循环：没有平行语料就训不出模型；网页上这些语言的文本很少，而且常被语言识别器误判；连公认的评测集都没有，做出来也不知道好坏。另一个难点是容量：语言越多，每种语言在一个稠密模型里分到的参数越少，高低资源语言之间还会相互干扰。

方法

评测与种子数据。在FLORES-101基础上，请专业译者把同一组3001个维基媒体句子翻成204种语言，得到Flores-200，可评测40,602个翻译方向；另为39种低资源语言人工翻译了一批训练用的种子数据（NLLB-Seed）。

挖掘数据。先训练一个覆盖200多种语言的语言识别器，从网页单语文本中准确挑出低资源语言的句子；再用师生蒸馏训练句向量编码器LASER3，把不同语言、意思相同的句子映射到相近的向量，按相似度配对。最终为148种语言挖出11亿多对新句子。再加上回译：既用多语言神经模型回译，也为极低资源方向训练Moses式统计翻译模型当回译“老师”。

模型。基于Transformer的编码器-解码器，把部分前馈层换成稀疏门控混合专家层（稀疏门控MoE层，见混合专家），总参数545亿，每个词只激活少数专家。为防止低资源方向过拟合，提出专家输出遮蔽（EOM）：训练时随机丢弃部分词的专家输出；并采用课程学习：容易很快过拟合的低资源方向不从头参与，而是在训练结束前K步才加入（K约等于它们开始过拟合所需的步数）。另提供3.3B、1.3B稠密模型和蒸馏得到的1.3B、600M小模型。

结果

在Flores-101的全部方向上，NLLB-200平均spBLEU比此前最好的DeltaLM高约7.3，即约44%的相对提升；在与M2M-100、Deepnet可比的87种语言子集上，平均spBLEU 25.5，对比M2M-100的13.6和Deepnet的18.6。数据消融（Flores-200开发集，chrF++）：只用人工和公开平行语料，翻译到英语的平均值47.4，加入挖掘数据升到53.9，再加两类回译数据升到55.9；极低资源语言翻译到英语从36.7升到50.9。

后来的发展

NLLB-200成为低资源语言翻译最常用的开源基线，Flores-200成为多语言评测的通用测试集。Meta随后把多语言翻译扩展到语音，推出SeamlessM4T。大语言模型兴起后，通用模型在主要语言上的翻译也变得很强，但它们的训练数据同样集中于高资源语言，数百种低资源语言仍依赖NLLB这类专门的数据挖掘和评测工作。

它建立在什么之上

  • 改进
    WMT机器翻译评测2006.06 · 数据·评测
    只覆盖少数欧洲语言，训练数据以议会记录为主，难以反映低资源语言和其他领域的翻译难度。
  • 使用
    Moses2007.06 · NLP
    为部分极低资源方向训练统计翻译模型作为回译的“老师”，因为这些方向上统计模型的数据效率更高。
  • 使用
    回译2015.11 · NLP
    回译是数据来源之一；实验表明在挖掘数据之外再加两类回译数据，翻译到英语的平均chrF++从53.9升到55.9。
  • 改进
    多语言NMT与零样本翻译2016.11 · NLP
    沿用“一个模型、目标语言标记、全部共享”的多语言翻译框架，规模扩大到4万多个方向。
  • 使用
    稀疏门控MoE层2017.01 · LLM
    用稀疏门控混合专家层扩大容量，缓解200种语言在同一模型里争夺参数的问题。
  • 改进
    XLM-R2019.11 · LLM
    100种语言之外的上千种语言仍几乎没有数据，网页语言识别对小语种也不可靠。
  • 改进
    OpenNMT2017.01 · NLP
    单语言对、单任务的框架，多语言大模型时代已被其他框架取代。
  • 延续
    LASER多语言句向量2018.12 · NLP
  • 改进
    XTREME跨语言基准2020.03 · 数据·评测
    设定偏重英语到其他语言的零样本迁移，对真正使用目标语言训练数据的情形覆盖不足。
  • 改进
    COMET译文质量评估2020.09 · 数据·评测
    在训练数据没覆盖的语言对、领域上，评分的可靠性没有保证。
  • 改进
    M2M-100非英语中心翻译2020.10 · NLP
    延续M2M-100的非英语中心多语言翻译，把语言数从100扩到200，并大量投入低资源语言的数据挖掘与人工评测。
  • 改进
    mT52020.10 · LLM
    多语言共享参数，容量被分摊，高资源语言会拖低低资源语言的表现。
  • 改进
    FLORES-1012021.06 · 数据·评测
    把Flores-101的101种语言扩展为204种语言的Flores-200评测集。

读懂它需要的概念

编码器-解码器 Transformer层的结构 混合专家 嵌入向量 文本生成的自动指标 迁移学习

本篇术语

  • 低资源语言　可用于训练的数字文本（尤其是平行语料）极少的语言，例如许多非洲和南亚语言。
  • 双语文本挖掘（bitext mining）　从互不相关的单语网页中自动找出互为译文的句子对，通常靠多语言句向量的相似度判断。
  • chrF++ / spBLEU　翻译自动指标。chrF++按字符n-gram（加词n-gram）计算重合，对形态丰富的语言更友好；spBLEU先用统一的SentencePiece模型切分再算BLEU，便于跨语言比较。

怎么学

先读过多语言NMT与零样本翻译和回译，补混合专家和文本生成的自动指标。原文190多页，先读第1–2节了解动机，第5节看数据挖掘流程，第6节看混合专家与EOM，再看表21（各类数据的贡献）和表30（与已有模型对比）。动手：从Hugging Face下载蒸馏的600M模型，翻译几句话到一种低资源语言，再翻回来，观察质量。
