MiniMax-M3与MSA稀疏注意力

MiniMax Sparse Attention
2026.06论文延伸arXiv 2026（MSA）MiniMax（Xunhao Lai, Weiqi Xu, Yufeng Yang 等，MSA论文） · 稀宇科技待核对
MSA论文 ↗Hugging Face模型卡 ↗在交互版中打开（演化树、学习进度）

问题

智能体工作流、仓库级代码推理都需要模型在数十万到上百万token上做注意力，softmax注意力的平方成本让这在部署规模下难以承受。

方法

在GQA之上做块稀疏注意力：轻量的索引分支给KV块打分，每个GQA组独立选Top-k块，主分支只在选中的块上做精确注意力，并与GPU内核协同设计。

影响

在1M上下文下，MiniMax-M3的预填充和解码分别比M2快9倍和15倍，每token计算降到1/20；MSA在109B模型上与GQA效果相当、注意力计算减少28.4倍。

背景

MiniMax-01闪电注意力用闪电注意力（线性注意力）做到百万上下文，但随后的MiniMax-M2回到了全注意力以保证智能体任务的效果。另一方面，原生稀疏注意力NSA、MoBA块注意力、DeepSeek-V3.2与DSA的DSA证明了可训练的稀疏注意力能在保持质量的同时降低长上下文成本。

方法

MSA（MiniMax Sparse Attention）建立在分组查询注意力GQA之上：

  • 索引分支：轻量地给每个键值块打分，并为每个GQA组独立选出Top-k个块，使不同组可以检索不同的位置，同时保持块级的高效执行；
  • 主分支：只在被选中的块上做精确的块稀疏注意力；
  • 内核协同设计：用不需要指数运算的Top-k选择，以及“KV在外层循环”的稀疏注意力实现，提高块粒度访问下的张量核心利用率。

MiniMax-M3是用MSA训练的原生多模态模型：总参数约4280亿、激活约230亿，从第一步就混合文本、图像和视频训练，上下文100万token；支持enabled、adaptive、disabled三种推理模式，其中adaptive由模型自己判断是否需要额外推理。

结果

MSA论文报告：在109B参数的原生多模态模型上，MSA与GQA效果相当，1M上下文下每token注意力计算减少28.4倍，配合内核在H800上预填充提速14.2倍、解码提速7.6倍。模型卡报告MiniMax-M3在1M上下文下预填充比M2快9倍、解码快15倍，每token计算降为1/20，并在长时程编码与办公协作类智能体基准上达到前沿水平。

后来的发展

MSA的推理内核已开源；它与DeepSeek的DSA/CSA、月之暗面的MoBA块注意力一起，说明2026年前沿开放模型普遍转向“GQA加可训练块稀疏”的长上下文方案。此后MiniMax又发布了M3.1-Flash。

局限与后续

  • 块级选择可能漏掉块内少量关键token，对需要精确定位大量分散细节的任务仍有风险。

它建立在什么之上

  • 延续
    分组查询注意力GQA2023.05 · LLM
    MSA在GQA之上为每个组独立选择KV块。
  • 竞争
    MiniMax-01闪电注意力2025.01 · LLM
    MiniMax-01用线性注意力做长上下文，M3改用精确的块稀疏注意力。
  • 竞争
    原生稀疏注意力NSA2025.02 · LLM
    同为可训练的块稀疏注意力，MSA强调按GQA组选择和内核简洁。
  • 竞争
    MoBA块注意力2025.02 · LLM
    MoBA也用门控选块做注意力，MSA以独立索引分支打分。
  • 延续
    MiniMax-M22025.10 · LLM
    M2系列的下一代，用MSA把1M上下文下的预填充和解码分别提速9倍和15倍。
  • 改进
    MiniMax-M2.52026.02 · LLM
    仍沿用M2的上下文与架构，超长上下文下成本较高。

读懂它需要的概念

稀疏注意力与高效注意力 KV缓存 混合专家 上下文窗口 吞吐、延迟与批处理

怎么学

先读原生稀疏注意力NSA和MoBA块注意力；读MSA论文第2节索引分支与主分支；动手：实现一个按块打分、每组取top-k块的玩具注意力，与全注意力比较输出误差。
