Codex-Max与上下文压缩

Building more with GPT-5.1-Codex-Max
2025.11模型延伸OpenAI待核对
OpenAI官方（HN收录） ↗TestingCatalog前瞻报道 ↗在交互版中打开（演化树、学习进度）

问题

编码智能体做大项目时，上下文窗口装不下全部历史，一次对话撑不过几个小时就要被迫中断。

方法

训练模型原生支持“压缩”：窗口快满时自己把历史浓缩成摘要，在多个窗口之间接力，把长时程任务连续做下去。

影响

让长时间不间断的自主编码成为模型层面的能力，而不再只靠外部脚本拼接。

方法

GPT-5.1-Codex-Max在2025年11月19日发布（Hacker News收录的OpenAI公告《Building more with GPT-5.1-Codex-Max》）。从媒体标题看，它是面向长时程智能体式编码的模型，通过压缩（compaction）在多个上下文窗口之间继续工作；发布前，TestingCatalog根据代码库里的描述预告它将更聪明更快，面向项目级的大型任务。

与外部循环脚本（如Ralph循环）把进度写到磁盘上再重新开始不同，这里是模型在训练中学会自行把过去的内容压缩成可继续使用的摘要。这一思路属于上下文工程里“压缩”这一手法的模型内化版本。注意：OpenAI原始公告页访问被拒，我无法核对具体的基准数字和连续工作时长，所以这里没有引用任何数字，细节请以官方页面为准。
