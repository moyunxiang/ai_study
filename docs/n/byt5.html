ByT5字节级模型

ByT5: Towards a token-free future with pre-trained byte-to-byte models
2021.05论文延伸TACL 2022Linting Xue, Aditya Barua, Noah Constant, Rami Al-Rfou, Sharan Narang, Mihir Kale, Adam Roberts, Colin Raffel · Google Research待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

几乎所有预训练语言模型都依赖分词器和固定词表，对拼写错误、新词和多语言不友好，还多出一套易出错的预处理流程。

方法

基本不改T5的结构，直接把UTF-8字节序列当输入输出，取消分词器，得到ByT5。

影响

证明标准Transformer可以直接处理字节，在抗噪声、拼写和发音敏感任务上更好，为“无分词”路线提供了可用基线。

方法

背景：mT5等模型用子词词表（见分词与token），遇到拼错的词会被切成怪异的片段，词表还要为每种语言留位置。把文本当字节读可以覆盖任何语言，但序列会变长，以往的无分词模型为此设计了专门结构。

做法：ByT5沿用T5的编码器-解码器，输入是原始字节，预训练仍用span corruption（遮掉一段连续字节让模型补全）。因为字节序列更长，作者调整了编码器和解码器的深度比例，让编码器更深，同时把省下的词表参数重新分配给其他层。

作者量化了参数量、训练FLOPs和推理速度的取舍：字节级模型与同类词级模型整体有竞争力，但推理更慢；在噪声文本以及对拼写、发音敏感的任务上明显更稳健。他们还发布了一整套预训练ByT5模型和代码。

局限与后续

  • 字节序列比子词序列长数倍，训练和推理更慢，注意力开销按序列长度平方增长。

它建立在什么之上

  • 改进
    WordPiece2012.03 · NLP
    初始词表必须包含所有基本字符（日语约22,000个），训练语料没见过的字符仍无法表示。
  • 改进
    BPE子词切分2015.08 · NLP
    合并只看频率，不看语义和形态，切出的片段常常不对应词素；数字、多语言词表分配不均等问题都由此而来。
  • 改进
    SentencePiece2018.08 · NLP
    多语言共用一个固定大小的词表时，高资源语言占据大部分子词，低资源语言的句子被切得很碎，序列更长、效果更差。
  • 使用
    T52019.10 · LLM
    结构几乎照搬T5，只改输入单位和层数配比。
  • 改进
    Unigram子词与子词正则化2018.04 · NLP
    子词仍是固定词表，跨语言和多语言时的切分公平性问题仍存在。
  • 延续
    mT52020.10 · LLM
    在mT5相同的多语言设置上，把子词词表换成字节，免去词表和分词器。

后来的相关工作

  • 改进
    MEGABYTE2023.05 · LLM
    同样走字节级无分词路线，但用分块解决字节序列过长的成本问题
  • 竞争
    字节潜变量BLT2024.12 · LLM
    同为无分词路线；ByT5直接按字节处理，计算量大，BLT用patch把序列压短。
