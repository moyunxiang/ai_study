自适应softmax

Efficient softmax approximation for GPUs
2016.09论文延伸ICML 2017Edouard Grave, Armand Joulin, Moustapha Cissé, David Grangier, Hervé Jégou · Facebook AI Research待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

大词表语言模型（One Billion Word的词表约80万）每一步都要算一个与词表一样大的softmax；层次softmax、采样类方法要么测试时仍需完整softmax，要么在GPU上并不快，要么效果下降。

方法

利用词频的齐普夫分布：把少数高频词和几个「尾部簇」的代表放在第一层softmax里直接预测，低频词分到若干尾部簇中、只在需要时再计算；簇的大小按GPU上矩阵乘法的真实耗时模型优化，尾部簇用降维投影减小容量。

影响

比标准softmax快2到10倍，精度接近完整softmax；在One Billion Word上单GPU训练5天达到困惑度48。它成为大词表语言模型的常用输出层，Transformer-XL等模型在WikiText-103和One Billion Word上都采用了它的变体。

方法

观察一：词频极不均衡。在Penn Treebank里，20%的词覆盖了87%的文本。如果把词表分成高频的头部V_h和低频的尾部V_t，绝大多数时候只用到头部。观察二：GPU上的耗时不是线性的。作者实测，隐状态矩阵（批大小×d）乘以词向量矩阵（d×k）的耗时在k较小时几乎不变，k超过某个阈值后才线性增长；因此把计算拆成太多很小的块反而不划算。

结构。第一层（根节点）是一个短名单：包含头部所有词加上每个尾部簇各一个「簇记号」。若目标词在头部，概率就是根节点softmax给出的值；若在第i个尾部簇，则p(w|h) = p₁(簇i|h) × p₂(w|簇i, h)，第二个因子只在该簇内做softmax。与把所有簇都放在叶子上的两层树不同，高频词只经过一次softmax，作者指出把所有词都放进叶子会带来5%–10%左右的效果下降。

按代价优化。给定词频分布和耗时模型g(k, d)，期望计算时间约为g(k_h + J, d) + Σ_i p_i·g(k_i, d_i)（J为尾部簇数，p_i为第i簇的概率质量），据此用动态规划选出各簇的边界。由于尾部词见得少，不需要高容量，尾部簇先把隐状态投影到更低维（如d/4）再做softmax，进一步加速。

结果。在Text8、Europarl和One Billion Word上，相对标准softmax有2–10倍加速，且在最大语料上同等训练数据下精度没有损失；比同样改进过的层次softmax快2–3倍。

局限与后续

  • 簇的划分依赖训练语料的词频，换领域后高频词变化时需要重新划分。

它建立在什么之上

  • 延续
    Brown聚类1992 · NLP
    延续基于词类分解softmax的思路，但按词频和计算代价而不是分布相似性分簇。
  • 延续
    探索语言模型的极限2016.02 · NLP
    在One Billion Word这一大词表基准上，把单GPU训练LSTM语言模型的成本降到数天。
  • 改进
    层次softmax语言模型2005 · NLP
    层次softmax把所有词放到树叶上，效果下降且不贴合GPU；自适应softmax让高频词留在根节点、按GPU耗时设计簇，速度更快且效果接近完整softmax。
  • 竞争
    NCE训练语言模型2012.06 · NLP
    NCE等采样方法只在训练时近似，测试仍要完整softmax；自适应softmax训练和测试都快。
  • 使用
    LSTM语言模型2012.09 · NLP
    实验中被加速的语言模型是LSTM语言模型，词类分解输出层是它的前身。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

本篇术语

  • 齐普夫分布　词的频率大致与其频率排名成反比：极少数词非常常见，绝大多数词很罕见。
  • 短名单　放在第一层直接预测的高频词集合，罕见词通过簇记号间接预测。

怎么学

先读层次softmax语言模型和NCE训练语言模型的讲解 → 读原文第4节GPU耗时模型和簇的优化 → 动手：用PyTorch的AdaptiveLogSoftmaxWithLoss在WikiText-103上训练一个LSTM语言模型，比较与完整softmax的每步耗时。
