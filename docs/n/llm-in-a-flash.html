LLM in a flash闪存推理

LLM in a flash: Efficient Large Language Model Inference with Limited Memory
2023.12论文延伸ACL 2024Keivan Alizadeh, Iman Mirzadeh, Dmitry Belenko, Karen Khatamifard, Minsik Cho, Carlo C Del Mundo, Mohammad Rastegari, Mehrdad Farajtabar · 苹果待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

手机和笔记本的内存（DRAM）有限，放不下几十亿参数的模型；模型可以放在容量大得多的闪存里，但闪存读取慢，尤其不擅长大量零碎的小块随机读取。

方法

参数平时存在闪存，按需读进内存；为闪存的读写特性建一个代价模型，用两个办法减少读取：只读这次会被激活的神经元并复用最近几个token已经读过的（窗口化），把会一起用到的行和列连续存放、一次读大块（行列捆绑）。

影响

说明了“模型可以超过设备内存”这一端侧方向的可行性，常被视为苹果端侧大模型部署的系统研究之一，并与PowerInfer等共同推动了利用激活稀疏的端侧推理。

方法

端侧设备的DRAM往往只有几GB到十几GB，而闪存（SSD或手机存储）容量大一个数量级以上，但带宽低得多，并且读取一次的固定开销大，只有成块连续读取才快。FlexGen单卡卸载推理把卸载用于服务器上的大批量吞吐，端侧需要的是单用户低延迟。

作者先为闪存推理建立代价模型，结论是优化两件事：少读、读大块。少读依赖前馈层的激活稀疏：在OPT-175B、Falcon这类ReLU模型里，每个token只有很少的前馈神经元输出非零，用一个低秩预测器提前猜出哪些会激活，只从闪存读这些神经元的权重。窗口化进一步利用相邻token激活的神经元高度重叠，内存里保留最近k个token用过的神经元，每来一个新token只需补读新增的那一小部分。行列捆绑：前馈层上投影矩阵的第i列和下投影矩阵的第i行总是同时被用到，把它们拼在一起连续存储，一次读出的数据块翻倍。注意力等稠密部分则常驻内存。

摘要报告：可以运行大到可用DRAM两倍的模型，相比朴素的加载方式，在CPU上推理快4–5倍，在GPU上快20–25倍。

局限与后续

  • 同样依赖ReLU式激活稀疏；对SwiGLU等稠密激活的主流模型和注意力部分收益有限，模型仍需大约一半能常驻内存。
