PyTorch FSDP

PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel
2023.04论文延伸VLDB 2023Yanli Zhao, Andrew Gu, Rohan Varma 等 · Meta待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

ZeRO与DeepSpeed的思想要靠DeepSpeed等外部库才能用，PyTorch用户缺少原生、与框架深度结合的全分片数据并行。

方法

把参数、梯度和优化器状态按卡切分，计算每层前临时汇集参数、计算后释放，并与PyTorch的autograd和内存分配器深度集成。

影响

成为PyTorch原生的大模型训练方案，被众多开源训练栈采用。

方法

每个GPU只持有参数的一片。前向到某一层时，通过all-gather拿到该层完整参数，算完立即释放；反向时再收集一次，并用reduce-scatter把梯度归约并切分，同时通信与计算重叠。论文介绍了它如何和张量内存管理、混合精度、激活检查点、通信分组配合，以及不同分片策略之间的取舍。摘要称它在达到与DDP相当的性能的同时，在TFLOPS上接近线性扩展，具体数字摘要中没有给出。设计继承了ZeRO与DeepSpeed第三阶段的思想。

局限与后续

  • 通信量大于普通数据并行，跨机带宽低时扩展性变差。

它建立在什么之上

  • 使用
    PyTorch2017.01 · 系统·效率 待核对
    作为PyTorch的内置分布式模块。
  • 改进
    Hugging Face Transformers2018.11 · 系统·效率
    为可读性设计的逐模型实现不包含大规模分布式训练所需的切分与显存优化，训练数十亿参数以上的模型要依赖外部工具。
  • 改进
    梯度检查点2016.04 · 系统·效率
    只减少激活内存，参数、梯度与优化器状态的内存仍需另外处理。
  • 延续
    ZeRO与DeepSpeed2019.10 · 系统·效率
    把ZeRO的分片思想落成PyTorch原生实现并补上工程细节。
  • 改进
    PyTorch DDP数据并行2020.06 · 系统·效率
    每张卡要放下完整的模型参数、梯度和优化器状态，模型一大就装不下；更早的ZeRO与DeepSpeed已经提出把这些状态切分到各卡，PyTorch原生的对应实现是后来的FSDP。
  • 改进
    Megatron 3D并行2021.04 · 系统·效率
    需要手工选择三种并行的度数，配置依赖硬件拓扑，换集群要重新调。
  • 改进
    ZeRO-Infinity异构卸载2021.04 · 系统·效率
    数据要在PCIe和硬盘之间反复搬运，单步迭代很慢，适合“装得下”而非“训得快”；在超大规模预训练中，主流仍是张量、流水线和数据并行的组合。

读懂它需要的概念

分布式训练：数据并行与模型并行 互连：从芯片到机柜到集群 参数量、计算量与显存

怎么学

先读ZeRO与DeepSpeed，再读论文的系统设计一节；动手：用FSDP包装一个小Transformer并比较显存占用。
