函数调用成为标准接口

Function calling and other API updates
2023.06事件重要OpenAI来源已核对
OpenAI：Function calling and other API updates ↗TechCrunch报道（2023-06-13） ↗Anthropic：Claude工具调用正式可用（2024-05） ↗在交互版中打开（演化树、学习进度）

问题

让模型调用工具时，开发者只能在提示里约定一种文本格式（如ReAct的Search[...]），再用正则表达式去解析；模型一旦写错格式，程序就崩溃。

方法

开发者在API请求里用JSON Schema描述可用函数；模型经过专门微调，能判断何时需要调用函数，并输出符合函数签名的JSON参数，由开发者的程序执行后再把结果交回模型。

影响

把“工具调用”从提示技巧变成了API的一项正式功能。之后Anthropic等厂商也提供了形式相近的接口，许多智能体框架、编码智能体和MCP都以这种“模型发结构化调用、程序执行”的方式工作。

背景

2022到2023年上半年，让大模型使用工具主要靠提示：ReAct在示例里约定Search[实体]这样的文本格式，LangChain提供了一堆解析器把模型输出的文本变成函数调用。Toolformer显示可以把调用API的能力训练进模型，但只覆盖少数几个工具。OpenAI自己的ChatGPT插件（2023年3月）让ChatGPT读OpenAPI文档调用第三方服务，但只能在ChatGPT产品里用。开发者的普遍痛点是：模型输出的格式不稳定，经常多一句解释、少一个括号，解析失败只能重试。

方法

2023年6月13日，OpenAI发布新版GPT-4和GPT-3.5-turbo（gpt-4-0613、gpt-3.5-turbo-0613），同时推出函数调用（见工具调用）。流程是：

1. 开发者在请求中附上函数列表，每个函数有名字、自然语言描述，以及用JSON Schema写的参数定义，例如get_current_weather(location: string, unit: celsius | fahrenheit)； 2. 用户问“波士顿天气怎么样？”，模型不直接回答，而是返回一个结构化的调用请求：函数名get_current_weather，参数{location: Boston}； 3. 开发者的程序真正调用天气接口，把结果作为一条新消息发回给模型； 4. 模型读结果后用自然语言回答，或继续调用下一个函数。

官方称这些模型“经过微调，能检测何时需要调用函数，并以符合函数签名的JSON作答”。注意模型只负责生成调用请求，执行仍由开发者完成，这让开发者可以在执行前检查和拦截。官方举的用途包括：调用外部工具回答问题、把自然语言转成API调用或数据库查询、从文本中抽取结构化数据。公告同时提醒，工具返回的不可信数据可能指使模型执行意外操作，建议只接可信工具，并在发邮件、下单等有现实影响的操作前加用户确认。

结果

同一次更新还推出了上下文为16k token的gpt-3.5-turbo（价格是原版的两倍），gpt-3.5-turbo的输入token降价25%，text-embedding-ada-002降价75%。函数调用本身没有公布准确率数字。此后其他厂商陆续推出同样形式的接口，例如Anthropic在2024年5月30日宣布Claude 3全系列的工具调用正式可用，用途描述几乎相同：抽取结构化数据、把自然语言转为API调用、查询数据库。

后来的发展

之后的智能体产品多以函数调用为基础接口：Assistants API与GPTs推出Assistants API和GPTs；ToolLLM与ToolBench等开源工作用ChatGPT构造工具调用训练数据，让开源模型也学会调用工具；2024年8月的结构化输出让输出严格符合Schema——OpenAI在该公告中称，在其复杂Schema评测上gpt-4-0613不到40%，新模型加结构化输出为100%。2024年底的模型上下文协议MCP把“函数怎么描述、怎么发现”标准化，让同一个工具能接入不同模型和应用；编码智能体如SWE-agent、Claude Code与终端编码智能体本质上都是“模型发调用请求—程序执行—结果回传”的循环。

容易误解的地方

  • 函数调用不是模型自己去执行函数；模型只输出想调用什么、参数是什么，执行和权限控制完全在开发者一侧。
  • 早期版本只是“尽量”符合Schema，并不保证JSON一定合法或参数一定齐全。

局限与后续

  • 生成的JSON只是尽量符合Schema，仍可能缺字段、类型错误或编造参数值，开发者必须自己校验。

  • 每个应用都要自己写函数定义和对接代码，同一个工具在不同模型、不同应用之间无法复用。
    后来针对它的工作　模型上下文协议MCP
  • 所有函数定义都要放进每次请求的上下文，工具一多既占token又让模型选错工具。
    后来针对它的工作　用代码调用工具 Agent Skills
  • 多步调用的循环、状态和工具执行都要开发者自己管理，API本身不托管对话和工具。

读懂它需要的概念

工具调用 智能体循环 指令微调与对话模板 上下文窗口 预训练与微调

本篇术语

  • JSON Schema　一种用JSON描述“一个JSON数据应该长什么样”的标准：有哪些字段、什么类型、哪些必填、可选值有哪些。
  • 函数签名　函数的名字、参数名和参数类型的总和，规定了调用它时要提供什么。

怎么学

先理解工具调用和智能体循环。然后用任意一家支持工具调用的API写一个最小程序：定义一个查天气或查数据库的函数，处理模型返回的调用请求、执行、回传结果，直到模型给出最终回答。最后读模型上下文协议MCP，看它如何把这里的函数定义变成独立的服务。
