Petals协作推理

Petals: Collaborative Inference and Fine-tuning of Large Models
2022.09系统延伸ACL 2023 DemoAlexander Borzunov, Dmitry Baranchuk, Tim Dettmers, Max Ryabinin, Younes Belkada, Artem Chumachenko, Pavel Samygin, Colin Raffel · Yandex, 华盛顿大学, Hugging Face等待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

BLOOM-176B、OPT-175B的权重已经公开下载，但普通研究者没有能装下它们的多卡服务器；卸载到内存太慢，托管API又拿不到隐藏状态和注意力，没法做研究。

方法

把模型按层切成若干段，分给互联网上许多志愿者的消费级GPU各自托管一段；用户的请求依次穿过这些服务器完成前向计算，像BitTorrent一样拼成一个完整模型。

影响

展示了在普通GPU和公网上跑千亿参数模型交互推理的可行性，是“去中心化推理/训练”方向常被引用的系统。

方法

Petals把一个大模型的Transformer块分给多台服务器，每台只需装下几个块（可用8比特量化进一步省显存）。客户端本地只保存词嵌入和输出层，生成每个token时把隐藏状态依次发给持有第1段、第2段……的服务器，最后在本地算出下一个词。服务器可以随时加入或掉线，客户端会重新寻找其他持有相同块的服务器继续。

与只给文本输出的推理API不同，Petals暴露每一层的隐藏状态，用户可以在本地训练Prefix / Prompt Tuning式的软提示或Adapter这类小模块，梯度会穿过远程服务器反向传回，不改动服务器上的共享权重。

摘要报告：对超大模型，这种方式比卸载到内存更快，在消费级GPU上运行BLOOM-176B的推理约每秒1步，足以支撑许多交互式应用。

局限与后续

  • 依赖志愿者节点，延迟和可用性受公网与节点掉线影响，吞吐远低于数据中心里的推理引擎；数据要经过陌生节点，隐私也无法保证。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    BLOOM2022.07 · LLM
    主要演示对象是BigScience的BLOOM-176B，Petals本身也出自BigScience社区。
  • 使用
    Adapter2019.02 · 系统·效率
    用户在本地训练适配器或软提示等参数高效模块，远程共享权重保持冻结。
  • 竞争
    ZeRO-Infinity异构卸载2021.04 · 系统·效率
    卸载方案把权重放到CPU内存或硬盘，在单机上可行但交互推理太慢；Petals把权重分散到多台机器的GPU上。
  • 使用
    8比特优化器与bitsandbytes2021.10 · 系统·效率
    借助bitsandbytes的8比特权重压缩，减少每台服务器托管一段模型所需的显存。
