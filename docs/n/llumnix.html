Llumnix请求迁移调度

Llumnix: Dynamic Scheduling for Large Language Model Serving
2024.06论文延伸OSDI 2024Biao Sun, Ziming Huang, Hanyu Zhao, Wencong Xiao, Xinyi Zhang, Yong Li, Wei Lin · 阿里巴巴待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

大模型请求的输入长度、输出长度事先无法知道，显存占用随生成不断增长；请求一旦分配到某个推理实例就只能在那里跑完，结果有的实例排长队、有的空闲，显存碎片化，高优先级请求也会被拖慢。

方法

像操作系统在CPU核之间做上下文切换那样，在多个模型实例之间运行时重新调度请求：把正在生成的请求连同其KV缓存在线迁移到另一实例，迁移过程几乎不停顿。

影响

把“请求可以在实例间迁移”引入LLM服务调度，成为多实例集群调度研究中常被引用的系统，也在阿里巴巴的线上服务中使用。

方法

单个推理实例内部，vLLM与PagedAttention的PagedAttention和Orca连续批处理的迭代级调度已经把显存和批处理管得很好；但生产环境通常同时运行很多实例，前端负载均衡只能在请求到达时做一次分配决定。由于每个请求最终生成多长事先未知，实例之间很快失衡：一些实例显存不足而排队甚至抢占请求，另一些则空着，空闲显存又被切成零散的小块，装不下新来的长请求。

Llumnix的核心是请求的在线迁移：把一个正在解码的请求及其KV缓存从实例A搬到实例B。为了不让请求停太久，迁移分多轮流水线进行：先在请求继续生成的同时拷贝已有的KV块，最后只需短暂停顿拷贝最后几块新增的部分，停顿时间与序列长度基本无关。在此基础上，一个统一的动态调度策略用同一套机制处理负载均衡、消除碎片（为大请求腾出整块空间）、按优先级隔离以及实例扩缩容前的排空。

摘要报告：与当时最先进的LLM服务系统相比，尾延迟改善一个数量级，高优先级请求最多加速1.5倍，在尾延迟相近时成本最多节省36%。
