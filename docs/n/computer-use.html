Computer Use

Introducing computer use, a new Claude 3.5 Sonnet, and Claude 3.5 Haiku
2024.10事件重要Anthropic来源已核对
官方公告 ↗Developing computer use（研发经过） ↗在交互版中打开（演化树、学习进度）

问题

让模型操作软件，过去要么为每个应用单独写API接口，要么靠解析网页源码；大量只有图形界面的桌面软件根本接不进来。

方法

不改软件，让模型像人一样看屏幕截图，算出鼠标该移到哪个像素，再发出点击、输入、按键指令，循环直到完成任务。

影响

官方称这是第一个以公测形式提供“直接用电脑”能力的前沿模型，把GUI智能体从研究原型交到开发者手里；之后OpenAI、Google也推出了类似的产品。

背景

到2024年，大模型调用外部能力的主流方式是函数调用成为标准接口：开发者把一个API描述成函数，模型输出结构化的调用参数。这要求每个要操作的系统都有现成的API。现实中大量工作发生在只有图形界面的软件里——报销系统、老旧的企业后台、桌面办公软件——它们没有API，或者API覆盖不全。

研究界已有一批GUI智能体，如CogAgent、SeeAct，但多数是研究原型，或针对网页场景，或依赖专门训练的模型。2024年4月发布的OSWorld基准在真实操作系统里测试369个任务，人类能完成72%以上，而当时最好的模型只有约12%，主要卡在“GUI定位”（看懂截图并点准位置）上。

方法

2024年10月22日，Anthropic随升级版Claude 3.5 Sonnet推出“computer use”公测API。它本质上是一组特殊的工具：开发者在自己的虚拟机或容器里运行一个小程序，负责截屏和执行动作；模型则在一个智能体循环中工作：

  • 收到任务和当前截图；
  • 推理下一步该做什么，输出一个动作，如“把光标移动到(x, y)并单击”“输入这段文字”“按下回车”；
  • 宿主程序执行动作，再截一张新图返回给模型；
  • 重复，直到模型判断任务完成。

关键能力是数像素：官方研发笔记说，模型要从截图上算出光标需要水平、垂直移动多少像素才能点中目标，训练这一点对整个功能至关重要。模型看到的是一张张离散截图（官方称“翻页书”式视角），而不是连续视频。

结果

官方称，在OSWorld的“仅截图”设置下得分14.9%，当时排第二的系统为7.8%；允许更多步数时达到22.0%。同一公告中，新Sonnet在SWE-bench Verified上从33.4%提升到49.0%。官方同时承认它“仍是实验性的，有时笨拙且容易出错”，滚动、拖拽、缩放这些人类轻而易举的动作对它仍有困难。公告列出Asana、Canva、Cognition、DoorDash、Replit和The Browser Company已在探索这一能力。

后来的发展

computer use把“通用操作电脑”变成可调用的能力。之后几个月里同类产品和开源系统陆续出现：Google的Project Mariner（2024年12月）、OpenAI的Operator与浏览器智能体（2025年1月，其CUA模型在OSWorld完整电脑任务上报告38.1%，对比表中此前最好为Claude的22.0%），以及开源的UI-TARS原生GUI智能体（论文报告OSWorld 50步24.6、15步22.7，直接与Claude的22.0、14.9比较）、Browser Use；同期的Agent S则略早于它发布。官方研发笔记自己就提醒，模型读到的屏幕内容可能夹带提示注入攻击，这类风险随GUI智能体的普及更受重视。后来Anthropic把这一能力用进Claude Cowork等面向普通用户的产品；在有API可用的场景，不少产品也会优先用模型上下文协议MCP这样的结构化接口。

容易误解的地方

  • computer use不是一个单独的模型，而是Claude模型加一组工具定义；截屏、执行鼠标键盘动作的环境由开发者自己提供。
  • OSWorld上14.9%意味着绝大多数任务仍然失败，发布时它是研究预览而非可靠的自动化工具。

局限与后续

  • 成功率很低：OSWorld仅截图设置下14.9%，远低于人类的72%以上，多步任务中一步点错就全盘失败。

读懂它需要的概念

智能体循环 工具调用 状态、观测与动作 图像块与视觉token

本篇术语

  • GUI定位（grounding）　根据一句话描述（如“点击保存按钮”）在截图中找到对应元素的准确坐标。GUI智能体最常见的失败点。
  • 提示注入　攻击者把指令藏在模型会读到的内容里（网页、邮件、文档），让模型误以为是用户的命令去执行。

怎么学

先了解智能体循环和工具调用。读官方公告和《Developing computer use》两篇短文，再看OSWorld论文第1、3节理解任务是怎么评测的。动手：用Anthropic提供的computer use参考实现（Docker镜像）在虚拟机里跑一个简单任务，观察每一步的截图和动作日志。
