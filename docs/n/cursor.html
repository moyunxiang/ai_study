Cursor AI编辑器

2023.03系统重要Michael Truell, Sualeh Asif, Arvid Lunnemark, Aman Sanger · Anysphere待核对
Cursor官网 ↗TechCrunch：Anysphere获OpenAI领投种子轮（2023-10） ↗Latent Space对Aman Sanger的访谈（2023-08） ↗在交互版中打开（演化树、学习进度）

问题

Copilot这类插件只能在别人的编辑器里补全光标处的代码，拿不到整个项目的上下文，也改不了编辑器的交互方式。

方法

直接分叉VS Code，把编辑器围绕大模型重做：内置可选GPT-4的对话、用@把文件和文档拉进上下文、用自然语言让模型改写选中的代码，并能就整个代码库提问。

影响

证明了“AI原生编辑器”可以从微软和GitHub手里抢到开发者，后来从对话式编辑走向能自己改多文件、跑命令的智能体，2026年被SpaceX以600亿美元收购。

背景

GitHub Copilot在2021到2022年让大模型补全变成日常工具，但它是VS Code等编辑器的一个插件：只能在光标处显示灰色建议，界面和可用的上下文都受宿主编辑器限制。2023年3月GPT-4发布，模型已经能读懂较长的代码、按要求做跨函数的修改，聊天式交互也因ChatGPT发布普及。程序员却要在浏览器和编辑器之间来回复制代码。Anysphere的四位创始人是MIT学生，他们认为插件形态是瓶颈：要让模型真正参与写代码，编辑器本身得重新设计。

方法

Cursor是VS Code开源代码的一个分叉，所以保留了原有扩展和快捷键，再在其上加入AI功能。2023年时的核心功能：

  • 内置对话：侧栏里直接问关于当前代码的问题，可在GPT-3.5和GPT-4之间选择。
  • @引用：用“@文件名”或“@文档”把指定文件、库文档拉进提示，需要跨文件修改时一起附上。
  • 代码库问答：例如问“VS Code里哪个服务能把状态存到磁盘？”，它会找出相关定义和文档（见检索与向量数据库）。
  • 提示管理：自研的Priompt在对话超出上下文窗口时决定保留哪些历史、丢掉哪些文件。

创始人当时表示，他们不想在补全上与Copilot正面竞争，而是做“补全之后”的事：找bug修bug、代码库问答、跨文件编辑，长期目标是把整个任务交给智能体端到端完成。

结果

2023年10月获OpenAI创业基金领投的800万美元种子轮，团队当时只有5人。之后增长很快：维基百科汇总的报道称，2025年1月年化收入过1亿美元，6月超5亿美元，同月以99亿美元估值融资9亿美元；2025年11月以293亿美元估值融资23亿美元，年化收入超10亿美元；2026年5月彭博报道年化收入达30亿美元。2026年4月SpaceX与其达成收购权协议，6月宣布行使，8月14日以全股票交易完成，隐含估值600亿美元。

后来的发展

Cursor让“AI编辑器”成为独立赛道：Windsurf智能体IDE等竞品沿用同样的分叉VS Code路线，GitHub Copilot也加入了聊天和agent模式。它自己的产品逐步从对话式编辑走向智能体：能搜索代码库、改多个文件、运行终端命令，2025年的Cursor 2.0与Composer推出自研编码模型并支持多个智能体并行。另一条路线是不要编辑器、直接在终端里工作的Claude Code与终端编码智能体。公司本身的增长和被收购见Cursor的爆发式增长和SpaceX收购Cursor；收购完成后，OpenAI宣布停止向Cursor提供模型。

容易误解的地方

  • Cursor本身不是模型，早期完全依赖OpenAI等第三方模型，后来才训练了自己的模型；产品能力很大程度上取决于接入的模型。
  • “分叉VS Code”意味着它与微软的编辑器长期共用同一套底层代码，并非从零写的新编辑器。

局限与后续

  • 早期的修改仍要用户逐次发起、逐处确认，跨多个文件的完整任务（实现功能、跑测试、修到通过）做不了。

本篇术语

  • 分叉（fork）　复制一个开源项目的全部代码，在此基础上独立开发自己的版本。

怎么学

先用一用GitHub Copilot式补全，再用一用Cursor的对话和智能体模式，对比两者能做的事。读Latent Space对创始人的访谈，理解为什么他们认为必须重做编辑器。然后读SWE-agent，看“给模型设计好用的工具界面”这一思路如何从研究进入产品。
