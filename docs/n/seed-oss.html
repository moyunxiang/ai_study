字节Seed-OSS-36B

Seed-OSS Open-Source Models
2025.08模型延伸ByteDance Seed团队 · 字节跳动待核对
GitHub ↗Hugging Face ↗在交互版中打开（演化树、学习进度）

问题

字节跳动的豆包/Seed系列此前只以闭源API提供，研究社区拿不到它的长上下文、推理和智能体能力；含合成指令数据的预训练基座也会干扰后训练研究。

方法

开源一个36B稠密模型，原生512K上下文、可控思考预算，并同时发布含与不含合成指令数据两种预训练基座。

影响

字节Seed团队的第一个开源通用大模型，以Apache 2.0许可发布，只用12T训练token就在多项开放基准上表现突出。

背景

2025年中开源模型普遍支持Qwen3混合思考式的思考模式，但思考长度难以按需控制（见思考预算与推理强度）；长上下文多靠后期外推。另外很多基座在预训练时就混入了大量合成指令数据，研究者想单独研究后训练时，分不清能力来自哪一阶段。

方法

据官方仓库，Seed-OSS-36B采用常见的因果语言模型结构：旋转位置编码RoPE（基频1e7）、分组查询注意力GQA（80个查询头、8个KV头，头维128）、RMSNorm和SwiGLU，64层，隐藏维5120，词表约15.5万。主要特性：

  • 思考预算可控：用户可以指定推理长度，模型在推理过程中按预算收尾，以权衡效果和成本；
  • 原生长上下文：训练时直接支持到512K token；
  • 研究友好：同时发布含合成指令数据的Base和不含的Base-woSyn两个预训练版本，以及Instruct版本；
  • 针对推理、工具使用和代码仓库问题修复等智能体任务做了优化，主要面向国际（i18n）场景。

结果

官方称仅用12T token训练，就在多项流行开放基准上取得优秀表现；具体分数见官方仓库的评测表。

后来的发展

它是国内大厂“闭源旗舰 + 开源中等规模模型”并行策略的又一个例子；Base与Base-woSyn的对照发布为研究合成数据对后训练的影响提供了素材。

局限与后续

  • 没有完整技术报告，训练数据构成和后训练方法公开得很少。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 36B稠密结构推理成本高于同等效果的MoE模型，512K长上下文在本地部署时显存压力很大。
    本站还没有记录针对它的后续工作（不代表没有人解决）

读懂它需要的概念

语言模型 上下文窗口 推理token与测试时计算 KV缓存

怎么学

先读思考预算与推理强度了解思考预算；看Seed-OSS仓库的模型参数表；动手：分别设置不同的思考预算回答同一道题，比较长度与正确率。
