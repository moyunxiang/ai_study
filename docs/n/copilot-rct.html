Copilot提速55.8%实验

The Impact of AI on Developer Productivity: Evidence from GitHub Copilot
2023.02论文延伸Sida Peng, Eirini Kalliamvakou, Peter Cihon, Mert Demirer · Microsoft Research / GitHub / MIT待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

GitHub Copilot上线后，人们普遍感觉写代码变快了，但缺少随机对照实验来回答：AI结对编程到底让开发者快了多少？

方法

通过自由职业平台招募程序员，随机分成两组，让他们用JavaScript尽快实现同一个HTTP服务器，一组可以用Copilot，另一组可以上网搜索但不能用Copilot，比较完成时间。

影响

“快了55.8%”成为生成式AI提升生产率最常被引用的数字之一，也是后续一系列生产率实验（包括结论相反的METR实验）的参照对象。

方法

论文2023年2月发在arXiv。实验在2022年Copilot正式商用前不久进行：通过Upwork发出166份邀约，95人接受，随机分为实验组45人、对照组50人；论文称两组都有35名开发者完成了任务和问卷。参与者多为25–34岁，主要来自印度和巴基斯坦，平均编程经验6年、每天写代码约9小时。

结果：在完成任务的人中，实验组平均用时71.17分钟，对照组160.89分钟，缩短55.8%（t检验p=0.0017，95%置信区间21%–89%），4个超过300分钟的离群值都在对照组，去掉后结论不变。异质性分析显示，编程经验较少、年龄较大、每天编码时间较长的开发者获益最多。作者据此认为GitHub Copilot这类工具可能帮助更多人进入软件开发职业。

局限在于任务是一个从零开始、规格明确的小项目，与在大型既有代码库中工作差别很大；后来METR开发者效率实验在真实开源仓库任务上得到了相反的结论。

局限与后续

  • 任务是规格清晰的独立小项目，完成任务的样本只有几十人，难以外推到在大型既有代码库中的日常开发。
