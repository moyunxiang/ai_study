Freebase

Freebase: A Collaboratively Created Graph Database for Structuring Human Knowledge
2007.03系统重要2007年3月上线；论文SIGMOD 2008Metaweb Technologies（Danny Hillis、John Giannandrea、Kurt Bollacker等）；SIGMOD论文作者：Bollacker, Evans, Paritosh, Sturge, Taylor待核对
SIGMOD 2008论文（DOI） ↗维基百科：Freebase ↗Google收购Metaweb公告 ↗在交互版中打开（演化树、学习进度）

问题

网上的知识大多写在网页和维基百科的自由文本里，机器读不懂；Cyc这类由专家手工编写的知识库又小又慢，覆盖不了海量的人名、地名、电影、公司。

方法

做一个人人可以编辑的大型图数据库：每个实体是一个节点，事实是节点间带类型的边；数据一部分从维基百科信息框、MusicBrainz等结构化来源批量导入，一部分由社区补充，并通过开放API和数据转储免费提供。

影响

成为第一个被NLP研究大规模使用的开放实体知识库：远程监督关系抽取、知识库问答、TransE等知识图谱嵌入都以它为数据来源；被Google收购后是Google知识图谱的重要组成部分。

背景

让计算机拥有“世界知识”是AI的老问题。1984年起的Cyc常识知识库走专家路线：由受过训练的知识工程师用形式逻辑一条条写常识，几十年下来仍然覆盖有限。WordNet整理的是词与词的语义关系（同义、上下位），不收录“某部电影的导演是谁”这类具体事实。

与此同时，维基百科语料证明了众包可以写出覆盖面极广的百科，但内容是给人读的文本，机器只能靠关键词匹配。语义网（Semantic Web）倡导者希望网站发布结构化数据，但要求先定好严格的本体，进展缓慢。2007年前后，搜索引擎和NLP研究者都缺一个大规模、可直接查询、免费可用的实体知识库。

方法

数据模型。Freebase内部是一个图：节点是“话题”（topic，即实体，如某个演员、某座城市），节点之间的边是带类型的关系。一个话题可以同时属于多个“类型”，例如施瓦辛格既是演员、也是健美运动员和政治家；每个类型定义了一组“属性”（如演员的“出演作品”）。查询用基于JSON的MQL语言，存储引擎是自研的三元组库graphd。

数据来源。大量事实从维基百科的信息框和表格、NNDB（人物资料）、MusicBrainz（音乐）、美国证监会（公司数据）等来源批量导入，用户再以维基方式修改和补充。

半开放的模式。用户可以自己创建新类型，类似给事物打标签；但只有经Metaweb员工审核的类型才进入公共区，因为外部程序依赖这些模式，随意改动会让别人的查询失效。

开放。数据以知识共享署名许可发布，提供HTTP API、RDF接口和完整的数据转储，研究者可以下载整个知识库离线使用。

结果

Google在2010年7月收购Metaweb时称，Freebase收录了超过1200万个“事物”，涵盖电影、书籍、电视节目、名人、地点、公司等。斯坦福的远程监督关系抽取论文使用2008年7月的数据导出，转换为二元关系后有1.16亿条关系实例、7,300种关系、900万个实体。维基百科记载，到2014年1月Freebase约有4400万个话题和24亿条事实。

后来的发展

研究方面，它几乎是2009–2015年间知识相关NLP的标准数据源：远程监督关系抽取用它自动标注训练句子，基于Freebase的语义解析问答在它上面做自然语言问答，TransE知识图谱嵌入等知识图谱嵌入从它抽出FB15k等数据集做链接预测。

产业方面，Google在2010年收购Metaweb，2012年推出的Google知识图谱部分基于Freebase。2014年12月Google宣布关闭Freebase并协助把数据迁往Wikidata，网站于2016年5月下线；其图数据库graphd和查询语言MQL后来开源。大语言模型出现后，研究者开始讨论模型参数本身能否充当知识库（语言模型即知识库），以及检索外部知识（检索增强生成RAG）与结构化知识图谱（GraphRAG）如何结合。

局限与后续

  • 覆盖严重不完整：大量实体缺少出生地、国籍等基本属性，而人工补录跟不上，需要从文本中自动抽取和推断缺失的事实。
    后来针对它的工作　远程监督关系抽取 TransE知识图谱嵌入
  • 只能用MQL这类结构化查询访问，普通用户的自然语言问题要先翻译成查询，中间的语义解析非常困难。
    后来针对它的工作　基于Freebase的语义解析问答 检索增强生成RAG
  • 众包加批量导入导致重复实体、类型重叠和错误事实，质量控制依赖少数员工审核。

  • 被一家公司拥有，2016年关停，依赖它的研究和应用只能迁移到Wikidata等其他知识库。

它建立在什么之上

  • 竞争
    Cyc常识知识库1984 · 事件
    同样想让机器拥有世界知识：Cyc由专家用逻辑手工编写常识，Freebase靠批量导入加众包收集具体实体事实；后者规模大得多，成为NLP研究实际使用的知识库。
  • 延续
    WordNet1995 · 数据·评测
    WordNet把词义之间的关系做成网络，Freebase把同样的“节点加关系”思路用到数以百万计的具体实体与事实上。
  • 使用
    维基百科语料2001.01 · 数据·评测
    大量事实直接从维基百科的信息框和表格中导入，后来研究者还用“Freebase Wikipedia Extraction”做文本语料。
  • 竞争
    开放信息抽取TextRunner2007.01 · NLP
    同年的开放信息抽取直接从网页文本抽出不规范的关系串，不需要预先定义模式；Freebase坚持有类型和属性的结构化模式，数据更干净、但覆盖靠人和导入。

读懂它需要的概念

图、树与搜索 命题逻辑、谓词逻辑与符号推理

本篇术语

  • 知识库/知识图谱　把“实体—关系—实体”形式的事实（如〈斯皮尔伯格, 导演, 拯救大兵瑞恩〉）存成一张图，节点是实体，边是关系，可以被程序查询和推理。
  • 三元组　一条事实的最小存储单位：主语、谓词、宾语，例如〈约翰·斯坦贝克, 国籍, 美国〉。
  • MQL　Metaweb Query Language，用JSON写查询模板、留出空位让数据库填充的查询语言，是Freebase的主要访问方式。

怎么学

先补图、树与搜索。读维基百科Freebase条目了解它的模式（话题、类型、属性）；再读远程监督关系抽取论文第3节，看研究者如何把Freebase转成二元关系数据。动手：下载FB15k-237这类由Freebase抽出的小数据集，统计关系种类和每个实体的平均边数，体会知识库的不完整程度。
