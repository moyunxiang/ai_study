PettingZoo多智能体环境

PettingZoo: Gym for Multi-Agent Reinforcement Learning
2020.09系统延伸NeurIPS 2021J. K. Terry, Benjamin Black, Nathaniel Grammel, Mario Jayakumar, Ananth Hari, Ryan Sullivan, Luis Santos, Rodrigo Perez et al. · 马里兰大学 / Farama Foundation待核对
arXiv ↗文档 ↗在交互版中打开（演化树、学习进度）

问题

单智能体RL有OpenAI Gym统一接口，多智能体RL的环境却各写各的API，代码难以互换和复现；常用的「所有智能体同时行动」模型也描述不好轮流行动的游戏，容易埋下难查的bug。

方法

做一个多智能体版的Gym：用统一的Python API封装大量多智能体环境，并提出「智能体-环境循环」（AEC）博弈模型，让智能体按顺序一个个行动和接收奖励。

影响

成为多智能体RL事实上的标准环境接口，现由Farama基金会与Gymnasium一起维护，RLlib、Tianshou等主流库都直接支持。

方法

PettingZoo收录了多类环境：Atari多人游戏、棋牌类经典游戏（国际象棋、围棋、德州扑克等）、粒子世界（MPE）、蝴蝶（Butterfly）协作游戏、SISL等，全部提供同一套接口。

AEC模型：环境维护一个「当前该谁行动」的智能体选择器；每次只让一个智能体观察、行动，环境随后更新状态并给所有智能体累计奖励，再轮到下一个。同时行动的游戏可以看作每个智能体依次提交动作、最后一起结算的特例，所以AEC能统一表示轮流和同时两种情况。为了方便，PettingZoo也提供Parallel API用于所有智能体同时行动的环境。

摘要称，PettingZoo的API继承了Gym的许多特点，但它基于新的AEC博弈模型，这在多智能体RL API中是独特的；作者通过对常用MARL环境中主要问题的案例分析指出，流行的博弈模型（如部分可观测随机博弈）作为这些游戏的概念模型并不好，会导致难以察觉的bug，而AEC模型解决了这些问题。

局限与后续

  • 基于Python与CPU，逐智能体顺序执行，环境步进速度远不能满足大规模训练。

它建立在什么之上

  • 竞争
    马尔可夫博弈1994 · RL
    马尔可夫博弈假设所有智能体同时行动；AEC模型改为按顺序行动，论文认为更适合实际的MARL游戏。
  • 延续
    OpenAI Gym2016.06 · RL
    明确以Gym为蓝本，把统一的环境接口推广到多智能体。
  • 竞争
    星际多智能体挑战SMAC2019.02 · RL
    SMAC只提供星际争霸微操一类任务；PettingZoo追求多种环境家族与统一接口。

读懂它需要的概念

马尔可夫决策过程 基准、排行榜与SOTA 状态、观测与动作 博弈论基础与纳什均衡

本篇术语

  • AEC博弈　Agent Environment Cycle：智能体轮流观察和行动，每次行动后环境更新并分发奖励的多智能体模型。

怎么学

先熟悉OpenAI Gym的接口；读PettingZoo论文第3–4节AEC模型；pip安装后用AEC API在连连看（Connect Four）上写一个随机对弈循环，再试Parallel API。
