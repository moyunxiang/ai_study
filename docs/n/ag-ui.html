AG-UI智能体界面协议

AG-UI: the Agent-User Interaction Protocol
2025.05系统延伸CopilotKit及社区（与LangChain、CrewAI等框架合作）待核对
GitHub ↗官方文档 ↗在交互版中打开（演化树、学习进度）

问题

智能体不是“发一个请求、回一个答复”：它会逐字流式输出、在回答中途调用工具、更新共享状态、停下来等人确认、再派生子智能体。每个智能体框架对这些行为的接口都不同，前端要为每个框架单独写一套对接代码。

方法

定义一个开放、轻量的事件协议：智能体通过一条双向事件流发出带类型的事件——运行开始/结束、文本消息开始/增量/结束、工具调用、状态快照与增量、子智能体等——任何前端只要会渲染这些事件，就能接入任何框架写的智能体。

影响

2025年5月开源后，LangChain/LangGraph、CrewAI、微软Agent Framework、谷歌ADK、AWS Strands、Mastra、Pydantic AI等框架相继接入，官方把它与MCP、A2A并列为三种互补的智能体协议；后来发布了冻结规范并带JSON Schema的1.0版本。

背景

模型上下文协议MCP统一了智能体连接工具与数据的方式，Agent2Agent协议统一了智能体与智能体之间的通信，但“智能体如何把自己的工作过程实时呈现给用户、并接收用户的中途干预”仍没有标准。各家框架如LangGraph图式编排、CrewAI角色分工框架都有自己的流式输出格式。

方法

基本形态：一个AG-UI智能体就是一个HTTP端点，接收一个运行请求（包含会话线程、消息历史、工具和状态），然后以流的形式返回事件（默认可用服务器推送事件SSE等传输方式）。

事件类型：

  • 生命周期事件：一次运行以RunStarted开始，中间可有若干StepStarted/StepFinished，最后以RunFinished或RunError结束；
  • 文本消息事件：TextMessageStart、TextMessageContent（每次一个增量片段）、TextMessageEnd，实现逐字显示；
  • 工具调用事件：报告智能体调用了什么工具、参数是什么、结果如何；也支持“前端工具”，即由用户界面执行的操作；
  • 状态管理事件：用快照和增量同步智能体与界面共享的状态，例如一份正在协同编辑的表单；
  • 子智能体与活动事件：标明某段输出来自哪个子智能体，报告进行中的任务进度。

所有事件都有类型、时间戳和可选的元数据（如词元用量）。

人在回路：智能体可以暂停等待用户确认或补充信息，前端把用户输入作为新事件发回。

与其他规范的关系：A2UI、MCP Apps等“生成式UI规范”描述智能体想展示什么界面，AG-UI是承载这些内容在智能体与应用之间传输的运行时协议。

后来的发展

它补上了智能体协议栈中“面向用户”的一层，使同一个智能体可以同时驱动网页、移动端、终端和Slack等聊天工具；智能体产品中常见的“实时展示思考与工具调用、允许中途打断”交互因此有了跨框架的统一实现方式。

局限与后续

  • 协议只规范事件格式，不规定界面该如何设计，也不解决智能体在前端执行操作时的权限与安全问题。

读懂它需要的概念

智能体循环 工具调用 吞吐、延迟与批处理

本篇术语

  • 事件流　服务端不是一次性返回结果，而是持续推送一个个小消息（事件），前端收到一个就处理一个。
  • 前端工具　由用户界面而不是后端执行的工具，例如让智能体在页面上高亮某段文字或弹出确认框。
