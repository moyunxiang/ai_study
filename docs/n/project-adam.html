Project Adam

Project Adam: Building an Efficient and Scalable Deep Learning Training System
2014.10论文延伸OSDI 2014Trishul Chilimbi, Yutaka Suzue, Johnson Apacible, Karthik Kalyanaraman · Microsoft Research待核对
OSDI 2014 ↗在交互版中打开（演化树、学习进度）

问题

DistBelief与Downpour SGD证明了大规模训练可行，但需要上万核的集群，且通信开销大，能否用更少机器达到同样的规模？

方法

针对商用服务器优化整个系统：多线程无锁更新共享权重，把模型分到多台机器并减少通信量。

影响

证明了精心设计的系统工程可以用更少的机器训练更大的网络，是深度学习系统设计的早期代表。

方法

Project Adam由微软研究院构建，在单机内采用类似Hogwild!并行SGD的无锁多线程更新，在多机间用异步更新并对全连接层使用通信量更小的激活与误差传输（而非整块权重），再结合对NUMA内存的优化。论文用它训练了ImageNet 22k类的大网络；具体精度与机器数量本次未能核对，故不写具体数字。

它与DistBelief与Downpour SGD同属于「参数服务器」前夜的系统：两者都证明了异步SGD和大量机器可以结合，但都没有提供通用的接口，后来由参数服务器和各通用框架吸收。

局限与后续

  • 系统与特定模型紧密耦合，不是通用框架，难以复用。
    后来针对它的工作　参数服务器 TensorFlow
  • 异步更新引入过期梯度，精度对机器数量较敏感。
    后来针对它的工作　参数服务器
