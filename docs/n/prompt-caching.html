Prompt Caching

Prompt caching with Claude
2024.08系统延伸Anthropic待核对
公告 ↗在交互版中打开（演化树、学习进度）

问题

很多应用每次请求都携带同样的长前缀（系统提示、文档、代码库、几十个示例），每次都要重新处理，既慢又贵。

方法

API允许开发者标记要缓存的前缀，之后的请求命中同一前缀时直接复用已算好的状态，缓存读取按低价计费。

影响

把推理引擎内部的前缀缓存（见vLLM与PagedAttention、SGLang与RadixAttention）变成对开发者可见、可计费的产品能力，之后各家API都跟进。

方法

公告发布时（Hacker News记录显示2024-08-14）还是公开测试版；页面更新写明，2024年12月17日起在Anthropic API上正式可用，Amazon Bedrock和Google Cloud Vertex AI上为预览。官方称，对长提示可降低最高90%的成本和最高85%的延迟。

原理上，模型处理一段提示后会得到每层的KV缓存（见KV缓存）。如果下一次请求的开头与之前完全相同，这部分KV就不必重算，而是从缓存中读取。适用场景包括长对话、带文档的问答、代码库问答、大量示例的提示。

后来的发展

此后各大模型API都提供了类似的上下文缓存；长上下文代理应用的成本结构因此改变，开发者开始刻意把稳定内容放在提示开头。

局限与后续

  • 只对完全相同的前缀有效，提示中间有一处变化，其后的缓存都失效。

读懂它需要的概念

KV缓存 吞吐、延迟与批处理 上下文窗口 训练与推理的算力差别

本篇术语

  • 前缀缓存　把提示开头部分已经算好的KV状态保存下来，下次遇到相同开头直接复用。

怎么学

先读vLLM与SGLang中的前缀缓存 → 阅读官方文档的cache_control用法 → 对比缓存命中与未命中的计费。
