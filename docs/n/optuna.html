Optuna超参数优化

Optuna: A Next-generation Hyperparameter Optimization Framework
2019.07论文延伸KDD 2019Takuya Akiba, Shotaro Sano, Toshihiko Yanase, Takeru Ohta, Masanori Koyama · Preferred Networks待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

已有调参工具要求先把整个搜索空间写成静态配置；但实际的空间常常是有条件的（选了某个优化器才有某些参数、层数决定有几组宽度），写起来别扭，也难把搜索、提前终止和分布式运行组合起来。

方法

把Chainer、PyTorch的“边运行边定义”（define-by-run）用到调参上：在目标函数里用普通Python代码边执行边询问下一个超参，搜索空间随代码动态生成；同时内置高效的采样和剪枝（提前终止差的试验），并能从笔记本扩展到分布式。

影响

成为机器学习和Kaggle社区最常用的超参数优化库之一，也常作为Ray Tune等分布式框架的搜索算法后端。

方法

超参搜索的基本循环是：选一组超参，训练、评估，根据结果选下一组。常用的算法有超参数随机搜索、贝叶斯优化调参和Hyperband早停调参式的早停。Optuna提出三条设计准则：

  • define-by-run API：用户写一个目标函数，里面像 n = trial.suggest_int('层数', 1, 4)、再在循环里为每层 suggest 宽度这样边执行边要超参，条件分支、循环都可以自然表达，这一思路来自Chainer与Define-by-Run的动态计算图（同一家公司开发）。
  • 高效的搜索与剪枝：采样默认用TPE（树结构Parzen估计器），也支持CMA-ES等；训练过程中可以向框架汇报中间指标，框架用中位数规则或异步Successive Halving等规则把明显没希望的试验提前终止。
  • 易部署的架构：试验记录存放在关系数据库等存储中，多个进程或机器连到同一存储即可并行搜索，也能在笔记本里交互式使用并可视化。

论文用实验和实际应用展示了这些设计的效果；它自称是第一个按define-by-run原则设计的优化软件。

局限与后续
