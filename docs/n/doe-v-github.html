Copilot集体诉讼

Doe v. GitHub
2022.11事件延伸匿名开源开发者（Joseph Saveri律所代理）诉GitHub、微软、OpenAI · 美国加州北区联邦法院 → 第九巡回上诉法院待核对
Wikipedia：GitHub Copilot ↗在交互版中打开（演化树、学习进度）

问题

GitHub Copilot用公开代码仓库训练，这些代码大多带有MIT、GPL等开源许可证，要求保留署名和许可证声明；Copilot的输出偶尔会逐字复现训练代码，却不带任何署名。

方法

2022年11月，一批匿名开发者提起集体诉讼，指控Copilot与Codex违反开源许可、删除版权管理信息（违反DMCA）并侵犯隐私，挑战GitHub“用公开数据训练属于合理使用”的说法。

影响

这是针对生成式AI训练数据的第一起大型集体诉讼，比图像、新闻和图书的同类官司都早，诉状和律所随后成为一系列AI版权诉讼的模板；2026年9月第九巡回法院维持驳回其中的DMCA诉求。

方法

背景：GitHub Copilot2021年6月推出，底层是OpenAI的Codex。当时GitHub CEO Nat Friedman说“用公开数据训练机器学习系统属于合理使用”。2022年6月，软件自由保护协会（SFC）宣布在自己的项目里停用GitHub，指责Copilot无视训练数据中的代码许可证。GitHub也承认有一小部分输出可能是逐字复制的，这让人担心其输出不够“转化性”。

诉讼：2022年11月，由Joseph Saveri律所代理的集体诉讼（通常称Doe v. GitHub）起诉GitHub、微软和OpenAI，诉由从违反与GitHub用户的合同、违反开源许可证，到依据加州消费者隐私法分享个人信息不等。诉状称“训练就是合理使用”纯属推测，没有任何法院审理过这个问题。

进展：据Wikipedia，2026年9月16日，第九巡回上诉法院维持了对DMCA诉求的驳回，理由是原告没有证明Copilot和Codex从现有作品中删除或篡改了版权管理信息——系统生成的是新作品，本来就不含这些信息；违反开源许可的诉求不在这次裁决范围内。

2023年1月，同一家律所又代理画家起诉Stability AI等图像生成公司（画家诉Stability AI），开源代码界也开始用The Stack开放代码语料这类只收宽松许可证代码、允许作者退出的语料来回应。

局限与后续
