OpenAI文本嵌入

Text and Code Embeddings by Contrastive Pre-Training
2022.01论文延伸arXiv 2022Arvind Neelakantan, Tao Xu, Raul Puri, Alec Radford, Jesse Michael Han, Jerry Tworek, Qiming Yuan, Nikolas Tezak, Jong Wook Kim, Chris Hallacy, Johannes Heidecke, Pranav Shyam et al. · OpenAI待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

不同任务（分类、检索、相似度）各训各的嵌入模型，通用性差，且小模型效果有限。

方法

用大规模无标注的（文本，相邻文本）配对做对比预训练，得到一套通用的文本和代码嵌入模型，并以API形式提供。

影响

让「把文本转成向量再检索」变成人人可调用的服务，推动了向量数据库和RAG应用的普及。

方法

沿用CLIP的对比学习思路，但对象是文本对：从互联网文本中取相邻或相关的片段配对，用大批量对比损失训练，从GPT-3系列初始化编码器。代码嵌入则用（文本，代码）对训练。

摘要报告：在7个任务的线性探测分类上，最佳无监督模型相对此前最佳无监督和有监督文本嵌入分别提高4%和1.8%；在MSMARCO、Natural Questions、TriviaQA的大规模语义搜索上，相对此前最佳无监督方法分别提高23.4%、14.7%、10.6%；代码搜索相对提高20.8%。

后来的发展

之后OpenAI的嵌入API被大量RAG应用使用，开源的E5文本嵌入、BGE嵌入模型等嵌入模型与它竞争。

局限与后续

  • 模型和训练数据不开放，只能通过API使用，无法针对自己的领域继续训练。
    后来针对它的工作　E5文本嵌入 BGE嵌入模型
  • 文本嵌入只给出一个相似度，不能解释为什么相关。

它建立在什么之上

  • 使用
    GPT-32020.05 · LLM
    编码器从GPT-3系列初始化。
  • 使用
    CLIP2021.01 · 多模态
    借用CLIP式的对比预训练配方，对象从图文换成文本对和文本代码对。
  • 改进
    FAISS向量检索2017.02 · 推理·智能体
    它只负责“在向量里找近邻”，检索质量完全取决于向量本身是否表达了语义；当时还没有好用的文本检索向量。
  • 延续
    Sentence-BERT2019.08 · NLP
    同样把句子映射为向量做语义搜索，但改用海量无标注数据的对比预训练，规模大得多。
