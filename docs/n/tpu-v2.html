TPU v2/v3与TPU Pod

2017.05硬件重要Google I/O 2017（v2） / Google I/O 2018（v3）Google（Jeff Dean、Urs Hölzle发布）待核对
Google博客：Cloud TPU发布（2017） ↗维基百科：Tensor Processing Unit ↗TOP500：TPU 3.0解读 ↗在交互版中打开（演化树、学习进度）

问题

第一代TPU只能做8位整数推理，权重放在慢速DDR3上，芯片之间也不能联网；谷歌训练模型仍要靠几十块GPU跑一整天。

方法

第二代TPU改成能做浮点的训练芯片，换上HBM显存，并自带高速互连，把256颗芯片连成一台“TPU Pod”超级计算机，同时通过Google Cloud对外出租。

影响

第一款量产的深度学习训练专用芯片，也是第一次把整台AI超算按需出租。BERT、AlphaZero等都在它上面训练；v3加大算力并改用液冷，Pod扩到1024颗芯片。

背景

Google TPU证明了专用芯片做推理很划算，但它留下三个缺口：只支持8位整数，做不了需要浮点精度的训练；权重存在每秒34GB的DDR3上，很多负载被内存带宽卡住；每颗芯片作为PCIe协处理器单独工作，没法把一个大模型拆到多颗芯片上一起训练。

与此同时，训练的算力需求增长得比推理更快（见《AI and Compute》：算力每3.4个月翻倍）。谷歌2017年的发布博客举例：一个大型翻译模型在32块当时最好的商用GPU上要训练一整天。

方法

能训练。训练要做反向传播，梯度的数值范围很大，8位整数装不下。v2的矩阵单元改为支持浮点运算，主要使用的16位格式是谷歌自己定义的bfloat16（后来单独成为bfloat16节点）：保留与FP32相同的8位指数，只把尾数砍到7位，所以数值范围和FP32一样宽、不容易溢出，代价是精度低一些（见浮点精度：FP32、FP16、BF16、INT8）。

换内存。每颗芯片配16GiB的HBM高带宽内存，带宽从v1的34GB/s提高到600GB/s，单芯片峰值约45 TFLOPS。

联网成超算。4颗芯片装在一块板上（官方称每块180 TFLOPS），每颗芯片自带高速互连端口，板与板之间直接相连，不经过数据中心以太网。64块板（256颗芯片）组成一个TPU Pod，官方称峰值11.5 PFLOPS，可以用来训练单个大模型。

v3（2018年5月）。单芯片算力约翻倍，每块板的HBM翻倍到128GB；机架更密，因此第一次改用液冷。Pod扩到1024颗芯片，官方称每个Pod超过100 PFLOPS。

软件上，TPU用TensorFlow编程，由XLA编译器编译器把计算图编译成TPU指令。

结果

谷歌2017年称：上面那个要32块GPU训练一整天的翻译模型，用八分之一个TPU Pod一个下午就能训练到同样精度。Cloud TPU于2018年2月对外开放（最初每次只能租一块板）。BERT的预训练用的就是Pod：BERT-Base用16颗TPU芯片、BERT-Large用64颗，各训练4天；AlphaZero用64颗第二代TPU训练网络，用5000颗第一代TPU生成自我对弈棋局。

后来的发展

TPU Pod确立了“芯片+专用互连+整机柜”作为一个整体来设计的思路，NVIDIA后来的NVLink机柜方案（Blackwell与整机柜液冷）也走到同一方向。bfloat16被NVIDIA、Intel等普遍采用，成为大模型训练的默认精度。后续TPU v4与光路交换用光路交换把Pod扩到4096颗芯片，脉动阵列核心设计一直沿用至TPU Ironwood。

局限与后续

  • Pod内芯片按固定的网格连线，规模上限是1024颗，坏一块板或想换一种切分方式都很不灵活。

读懂它需要的概念

浮点精度：FP32、FP16、BF16、INT8 反向传播 矩阵乘法与线性变换 显存、内存带宽与“内存墙” 分布式训练：数据并行与模型并行 互连：从芯片到机柜到集群

本篇术语

  • TPU Pod　用专用高速链路连在一起的一整组TPU芯片（v2是256颗，v3是1024颗），可以当作一台计算机来训练一个模型。
  • TFLOPS / PFLOPS　每秒万亿次 / 千万亿次浮点运算。厂商标的通常是低精度下的峰值，实际训练只能达到其中一部分。

怎么学

先读Google TPU理解脉动阵列，再补浮点精度：FP32、FP16、BF16、INT8，自己算一算FP16、bfloat16、FP32各能表示的最大值。然后读2017年的发布博客和维基百科的代际对比表，最后看BERT论文附录里的训练配置，理解“16颗TPU芯片训练4天”是多大的算力。
