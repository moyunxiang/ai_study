StruQ结构化查询防注入

StruQ: Defending Against Prompt Injection with Structured Queries
2024.02论文延伸USENIX Security 2025Sizhe Chen, Julien Piet, Chawin Sitawarin, David Wagner · UC Berkeley待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

提示注入之所以有效，是因为LLM把开发者的指令和要处理的数据（网页、邮件、用户文本）拼成同一串文字，模型既善于遵循指令、又分不清哪段是指令哪段是数据。

方法

借鉴数据库防SQL注入的“参数化查询”：把提示和数据放进两个分开的通道，由安全前端用特殊分隔符编码；再训练模型只服从提示通道里的指令，对数据通道里出现的指令视而不见。

影响

把“指令与数据分离”从提示技巧变成训练目标，开启了一批通过微调抵御提示注入的防御（同组随后有SecAlign），也是指令层级同一思路的早期版本。

方法

传统软件里，SQL注入的根治办法是不让用户输入被解释成代码：查询语句和参数分开传。StruQ把同样的思想用在LLM上，系统由两部分组成。

  • 安全前端：把开发者的提示和外部数据格式化成一种特殊格式，用保留的分隔词元标出“这是指令”“这是数据”，并把数据里可能伪造这些分隔符的字符过滤掉，攻击者因此无法在数据里冒充指令通道。
  • 结构化指令微调：从一个未经指令微调的基础模型出发，用改造过的指令微调数据训练。除了普通样本，还加入数据部分里夹带了额外指令的样本，训练目标是仍然只完成提示通道里的任务、忽略数据中的指令。这样模型学会的“遵循指令”从一开始就只针对指令通道。

摘要报告：该系统显著提高了对提示注入攻击的抵抗力，对输出质量几乎没有影响。作者也指出，基于优化的强攻击（如自动化越狱攻击GCG式）仍是挑战，这成为后续工作的出发点。

与Spotlighting防提示注入这类只在提示里加标记、不改模型的做法相比，StruQ把分离写进了权重，代价是需要自己微调模型。

本篇术语

  • 参数化查询　数据库编程中把查询语句和用户数据分开传递的做法，使用户输入永远不会被当作代码执行。

怎么学

先读提示注入和间接提示注入 → 读原文的前端格式和训练数据构造 → 设计几条把指令藏在数据中的样例，比较普通指令模型和StruQ模型的反应。
