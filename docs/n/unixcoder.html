UniXcoder统一代码预训练

UniXcoder: Unified Cross-Modal Pre-training for Code Representation
2022.03论文延伸ACL 2022Daya Guo, Shuai Lu, Nan Duan, Yanlin Wang, Ming Zhou, Jian Yin · 中山大学、微软亚洲研究院待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

代码模型要同时做理解（搜索、克隆检测）和生成（补全、摘要）。编码器—解码器结构能兼顾两者，但对代码补全这类必须逐词生成的任务既低效又不够好；编码器模型又不能生成。

方法

用一个Transformer，通过不同的注意力掩码矩阵和前缀标记切换成编码器、解码器或编码器—解码器三种模式；再把AST和注释作为额外模态喂进去，并用对比学习对齐不同语言的代码表示。

影响

在5个代码任务、9个数据集上大多达到当时最好，提出零样本代码到代码搜索任务，是微软CodeBERT系列的集大成者，也是代码检索等任务长期使用的编码模型。

方法

背景：CodeBERT、GraphCodeBERT数据流预训练是编码器，PLBART代码去噪预训练和CodeT5是编码器—解码器。作者指出，编码器—解码器框架对代码补全这类自回归任务并不理想：补全要求仅解码器的方式，才能边写边高效推理。能否用一个模型同时覆盖三种用法？

统一模型：参考UniLM的做法，同一个Transformer在输入前加一个模式前缀（如[Enc]、[Dec]、[E2D]），配合不同的注意力掩码矩阵：

  • 编码器模式：所有位置互相可见（双向注意力）；
  • 解码器模式：每个位置只能看到它左边的位置（因果注意力），用于补全；
  • 编码器—解码器模式：源部分双向、目标部分因果，用于摘要、翻译等。

三种模式共享全部参数，分别用掩码语言建模、单向语言建模和片段去噪训练。

跨模态内容：除代码本身外，还输入代码注释和AST。树不能直接并行编码，作者提出一种一一对应的映射，把AST按特定遍历规则展开成序列，同时保留树的全部结构信息（可以从序列唯一还原树）。

表示学习：为了得到好的代码片段向量，作者用多模态内容做对比学习——同一段代码的不同视图（如加不同dropout）作为正样本；再用跨模态生成任务（由代码生成注释）对齐不同编程语言的表示，使语义相同的Python和Java函数向量相近。

结果：在5个代码相关任务、9个数据集上评估，另外构建了零样本代码到代码搜索的新数据集（用一种语言的代码去检索另一种语言中功能相同的代码）。摘要报告：模型在多数任务上达到最好，分析表明注释和AST都对UniXcoder有帮助。

后来的发展

UniXcoder常被用作代码检索、克隆检测的嵌入模型和检索增强代码生成中的检索器；“一个模型多种注意力模式”的思路后来被更大的统一代码模型沿用。

读懂它需要的概念

自注意力与多头注意力 掩码建模 自回归生成 对比学习 编码器-解码器 嵌入向量

本篇术语

  • 注意力掩码矩阵　决定序列中每个位置能看到哪些其他位置的0/1矩阵；全1是双向注意力，下三角是只看左边的因果注意力。
  • 零样本代码到代码搜索　不做任何微调，用一种语言的代码作为查询，检索另一种语言中功能相同的代码。

怎么学

先读CodeBERT和GraphCodeBERT数据流预训练；读本文第3节三种模式的掩码矩阵与AST映射规则；动手：用公开的UniXcoder分别取一个Python函数和功能相同的Java函数的向量，计算余弦相似度，与不相关函数比较。
