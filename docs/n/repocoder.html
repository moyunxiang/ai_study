RepoCoder仓库级补全

RepoCoder: Repository-Level Code Completion Through Iterative Retrieval and Generation
2023.03论文延伸EMNLP 2023Fengji Zhang, Bei Chen, Yue Zhang, Jacky Keung, Jin Liu, Daoguang Zan, Yi Mao, Jian-Guang Lou et al. · 微软 / 香港城市大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

代码补全工具通常只看当前文件，但真实项目里要调用的函数、类和约定散落在仓库的其他文件中，模型看不到就会编造不存在的接口。

方法

先用当前代码去仓库里检索相似片段并生成一版补全，再拿这版补全当新的查询重新检索，反复几轮，让检索越来越贴近真正需要的代码。

影响

把检索增强从问答搬到仓库级代码补全，提出的RepoEval基准和“迭代检索—生成”流程成为后来仓库级代码生成工作的常用对照。

方法

普通的检索增强代码补全（见检索增强生成RAG）用光标前的几行代码当查询，在仓库的其他文件里找相似片段，拼到提示里再让模型续写。问题是：光标前的代码往往和要写的内容不太像，第一次检索经常找偏。

RepoCoder的做法是迭代：

  • 第1轮：用光标前的代码检索，生成一版补全；
  • 第2轮起：把“光标前代码+上一轮生成的补全”合起来当查询再检索——生成的内容虽然可能有错，但它更像目标代码，因此能检索到更相关的定义和用法；
  • 重复几轮后输出最终补全。

检索器只用简单的词袋相似度，生成器是现成的预训练代码模型（如Codex），整个框架不需要训练。

作者同时构建了RepoEval基准，从较新的真实仓库中挖出三种粒度的补全任务：补一行、补一个API调用、补整个函数体（用单元测试判定）。实验显示RepoCoder在所有设置下都比只看本文件的基线高出10%以上，并稳定优于只检索一次的检索增强补全。
