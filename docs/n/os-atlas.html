OS-Atlas跨平台GUI定位

OS-ATLAS: A Foundation Action Model for Generalist GUI Agents
2024.10论文延伸ICLR 2025Zhiyong Wu, Zhenyu Wu, Fangzhi Xu, Yian Wang, Qiushi Sun, Chengyou Jia, Kanzhi Cheng, Zichen Ding et al. · 上海人工智能实验室 / 上海交通大学 / 香港大学 / MIT等待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

做GUI智能体的人大多依赖GPT-4o等闭源视觉模型，因为开源视觉语言模型在「指出屏幕上该点哪里」（GUI定位）和陌生界面上差距明显，而公开的跨平台定位数据又很少。

方法

先写一套跨Windows、Linux、macOS、安卓和网页自动采集GUI定位数据的工具，造出1300多万个界面元素的语料；再分两阶段训练开源模型：先学定位，再在统一的动作空间上学执行任务。

影响

发布了当时最大的开源跨平台GUI定位语料，7B模型在ScreenSpot上平均82.47%（SeeClick为53.40%）；OS-Atlas常被后续开源GUI智能体当作基座或对照。

方法

数据：在各平台上自动遍历界面、读取可访问性树或网页DOM，记录每个元素的文字和位置框，配上截图，共约220万张截图、1358万个元素；另用模型为元素生成「点击搜索框」式的指令。

两阶段训练，基座为InternVL2-4B和Qwen2-VL与开源VLM-7B：

  • GUI定位预训练：给截图和一句描述，输出目标元素的坐标，得到OS-Atlas-Base；
  • 动作微调：不同数据集的动作名五花八门，作者统一成点击、输入、滚动三个基本动作加打开应用、拖拽等自定义动作，动作种类从17个合并为10个，减少冲突；在Mind2Web等智能体数据上微调得到OS-Atlas。

评测：作者发现常用的ScreenSpot有部分标注错误，重新标注了11.32%的样本，发布ScreenSpot-V2。在ScreenSpot上，不借助规划模型时OS-Atlas-Base-7B平均82.47%、SeeClick GUI定位为53.40%；以GPT-4o为规划器时分别为85.14%和62.89%。在AndroidControl、GUI-Odyssey、OmniAct等五个智能体基准上也明显超过此前方法。

局限与后续

  • 主要解决「点哪里」的定位，多步任务的规划和出错后的恢复仍较弱，复杂任务常需配合GPT-4o等规划器。
    后来针对它的工作　Aguvis纯视觉GUI智能体 UI-TARS原生GUI智能体
  • 数据主要来自可访问性树和DOM自动采集，缺少这类信息的应用（如游戏、部分专业软件）覆盖不足。

怎么学

先读SeeClick GUI定位 → 读原文第3节数据采集工具和第4节统一动作空间 → 动手：用OS-Atlas-Base对一张自己的桌面截图输入几句「点击某按钮」指令，检查返回坐标是否落在按钮上。
