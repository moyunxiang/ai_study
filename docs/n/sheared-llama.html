Sheared-LLaMA结构化剪枝

Sheared LLaMA: Accelerating Language Model Pre-training via Structured Pruning
2023.10论文延伸ICLR 2024Mengzhou Xia, Tianyu Gao, Zhiyuan Zeng, Danqi Chen · 普林斯顿大学, 清华大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

想要1–3B的小模型，从头预训练要上万亿token；把现成大模型剪小又往往得到层宽不一、跑不快的怪形状，而且剪完的模型在各领域上恢复速度不均衡。

方法

把LLaMA2-7B按指定的目标形状（层数、隐藏维、头数、前馈维）端到端学出剪枝掩码，再继续预训练；继续预训练时按各领域损失离目标还差多少，动态调整每批数据的领域配比。

影响

用约3%的算力得到超过同尺寸从头训练模型的1.3B和2.7B模型，确立了“从大模型剪出小模型再续训”这条做小模型的路线，后来的Minitron等沿用这一思路。

方法

SparseGPT一次性剪枝、Wanda权重乘激活剪枝做的是逐个权重的非结构化剪枝，GPU上难以真正提速。结构化剪枝直接删整层、整个注意力头或整段隐藏维，剪完就是一个普通的小稠密模型。

定向结构化剪枝：给层、注意力头、前馈中间维、隐藏维各配一组可学习的掩码（服从hard concrete分布，源自L0正则化），用拉格朗日乘子把“剪完必须恰好是目标形状”写成约束，与语言模型损失一起做min-max优化。目标形状取现成的高效架构：1.3B参照Pythia-1.4B（24层、隐藏维2048），2.7B参照INCITE-3B（32层、隐藏维2560）。这一步用0.4B token。

动态批加载：剪枝后各领域（网页、代码、书籍等）掉点程度不同。受DoReMi启发，按每个领域当前损失与参考损失的差距，在线调大落后领域的采样比例，不需要额外训练代理模型。继续预训练用50B token。

摘要称，Sheared-LLaMA在多种下游与指令微调评测上超过同尺寸的Pythia、INCITE、OpenLLaMA和同期的TinyLlama，而所用算力只相当于从头训练的3%。

局限与后续

  • 仍需要几十亿token的继续预训练，算力远高于一次性剪枝；剪枝阶段要为7B模型维护掩码与梯度，显存开销大。

  • 竞争
    Pythia2023.04 · LLM
    以Pythia的形状为剪枝目标并与之比较，代表“从头训练同尺寸小模型”的做法。
  • 改进
    LLM-Pruner结构化剪枝2023.05 · 系统·效率
    剪掉20%以上参数后困惑度和下游精度下降明显，仅靠少量数据的LoRA恢复补不回来；后来的方法改用更多数据做继续预训练或蒸馏。
  • 改进
    Wanda权重乘激活剪枝2023.06 · 系统·效率
    非结构化稀疏在普通GPU上几乎不能变成实际加速；2:4等结构化稀疏下与稠密模型的差距明显变大。
