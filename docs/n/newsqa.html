NewsQA新闻阅读理解

NewsQA: A Machine Comprehension Dataset
2016.11数据集延伸ACL 2017 RepL4NLP WorkshopAdam Trischler, Tong Wang, Xingdi Yuan, Justin Harris, Alessandro Sordoni, Philip Bachman, Kaheer Suleman · Maluuba（后被微软收购）待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

SQuAD发布后，抽取式阅读理解很快被刷高，但很多题靠词匹配就能答，需要更长文章、更多推理的阅读理解数据。

方法

让众包工人只看CNN新闻的标题和摘要来提问，再由另一批工人在全文中找答案片段，得到10万多个更具探索性的问题。

影响

成为SQuAD之后的主要抽取式阅读理解基准之一，被MRQA共享任务收录，常用于检验模型跨领域泛化。

方法

四阶段收集。第一步，提问者只看新闻标题和要点摘要，写出自己好奇的问题，这样问题不会照抄原文句子；第二步，答题者阅读全文标出答案片段，也可以标记“无答案”；第三步，验证者在多个候选答案中选择最好的；最后再做整理。文章取自1万多篇CNN新闻，平均比SQuAD的维基段落长得多。

为什么更难。因为提问者没看过全文，问题和原文措辞差别大，有些问题文章里没有答案，还需要综合多句。论文分析表明，NewsQA需要的能力超出简单词匹配和文本蕴含识别。

结果。人类与当时强神经模型的F1差距为0.198。

后来的发展

NewsQA与SQuAD、TriviaQA、Natural Questions等一起被统一格式化用于跨数据集泛化研究；“提问者看不到答案所在原文”的做法也被后续数据集采用。

局限与后续

  • 众包答案片段的一致性不高，部分题目答案有歧义；新闻文章较长，当时的模型只能截断处理。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 竞争
    注意力阅读器与CNN/DM2015.06 · NLP
    两者都用CNN新闻，注意力阅读器的CNN/DailyMail是自动生成的完形填空，NewsQA是人写的问题。
  • 延续
    SQuAD2016.06 · 数据·评测
    沿用SQuAD的抽取式问答格式，用更长的新闻文章和看不到原文的提问方式提高难度。
  • 使用
    众包标注Mechanical Turk2005.11 · 数据·评测
    提问、答题和验证都由众包工人完成。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。
