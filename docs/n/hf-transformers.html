Hugging Face Transformers

Transformers: State-of-the-Art Natural Language Processing
2018.11系统重要前身pytorch-pretrained-BERT发布于2018年11月；论文 arXiv 2019-10Thomas Wolf, Lysandre Debut, Victor Sanh, Julien Chaumond, Clement Delangue, Anthony Moi, Pierric Cistac, Tim Rault et al. · Hugging Face待核对

问题

BERT、GPT等预训练模型各自用不同框架、不同代码风格发布（BERT官方只有TensorFlow版），想换一个模型就要重新读一遍代码、重写加载和分词逻辑，复现和比较都很费劲。

方法

把各种Transformer预训练模型用统一的三件套（分词器、模型主体、任务头）和统一的接口重新实现，一行代码按名字下载预训练权重，配套一个任何人都能上传模型的中心化模型库。

影响

成为使用预训练模型的事实标准入口：from_pretrained一行加载几乎所有开源模型，模型库从NLP扩展到视觉、语音和大语言模型，大大降低了用预训练模型做研究和应用的门槛。

背景

2018年下半年，预训练语言模型接连出现：ELMo、GPT-1，以及10月的BERT。它们效果很好，但使用门槛高：BERT官方代码和权重只有TensorFlow版本，而研究界正在转向PyTorch；每个模型的分词方式不同（BERT用WordPiece，GPT用BPE子词切分），输入格式、位置编码、掩码细节各不一样；预训练权重散落在各自的仓库和网盘里。想在同一个任务上比较三个模型，往往要维护三套代码。

2018年11月，Hugging Face发布了pytorch-pretrained-BERT：把BERT移植到PyTorch并能加载Google发布的预训练权重。随后GPT、GPT-2等更多模型陆续加入，项目最终更名为Transformers。

方法

论文描述的设计核心是统一的抽象层次：

  • 分词器（Tokenizer）：把原始文本变成模型需要的编号序列，每个模型一个类，负责它特有的子词切分、特殊符号、截断到最大长度等。为了速度，又用Rust重写了独立的tokenizers库。
  • 模型主体（Transformer）：每个架构的基类实现从词嵌入经过若干自注意力层到最终隐状态的计算，尽量贴近原始实现；大多数模型的代码放在单个文件里，方便阅读和修改，而不是层层继承抽象。
  • 任务头（Head）：在主体之上加分类、问答、语言建模等输出层。

不同架构尽量保持同样的接口，一组Auto类根据预训练模型的名字自动实例化正确的配置、分词器和模型。典型用法：

tok = AutoTokenizer.from_pretrained(「bert-base-uncased」) model = AutoModelForSequenceClassification.from_pretrained(「bert-base-uncased」)

换成另一个模型只需改名字。同一套模型同时提供PyTorch和TensorFlow实现，可以互相转换权重。

模型库（Model Hub）：任何人都可以上传预训练或微调后的模型，附带说明模型来源和用途的模型卡，并在网页上直接试用推理。部署方面，PyTorch版可导出为TorchScript，也可以转成ONNX模型交换格式格式加速。

结果

论文（2020年版）称项目有400多位外部贡献者，模型库已有2097个社区上传的模型；与ONNX团队合作优化BERT、RoBERTa和GPT-2的推理，在一个模型上取得接近4倍的加速。论文还展示了2019年10月至2020年5月间最热门预训练模型的日均下载量，其中为该库专门开发的DistilBERT也位列其中。

后来的发展

Transformers把“下载预训练模型→微调”变成了几行代码的标准流程，此后发布的开源模型大多直接提供Transformers格式的权重。模型库发展为Hugging Face Hub与Datasets，加入数据集托管；同一家公司又推出了扩散模型库Diffusers和参数高效微调库Hugging Face PEFT库。大模型时代，它的单文件、可读优先的实现成了研究者理解新架构的常用参考，但大规模训练通常交给ZeRO与DeepSpeed、PyTorch FSDP等工具，高吞吐推理则交给vLLM与PagedAttention等专门的推理引擎。

容易误解的地方

  • Transformers是“模型实现与权重分发库”，不是训练框架本身：底层计算由PyTorch、TensorFlow或JAX完成。
  • 同一个名字的模型，分词器必须与权重配套；用错分词器不会报错，但输出会完全没有意义。
  • 每个模型单独一个文件是刻意的设计（便于阅读和修改），代价是大量相似代码重复。

局限与后续

  • 为可读性设计的逐模型实现不包含大规模分布式训练所需的切分与显存优化，训练数十亿参数以上的模型要依赖外部工具。
    后来针对它的工作　ZeRO与DeepSpeed PyTorch FSDP
  • 推理按普通批处理逐token生成，没有针对大模型服务的KV缓存管理和连续批处理，线上吞吐低。
    后来针对它的工作　vLLM与PagedAttention

  • 使用
    Transformer2017.06 · LLM
    库里的模型都共享Transformer的多头注意力核心，差别在位置表示、掩码和是否为编码器-解码器结构。
  • 使用
    GPT-12018.06 · LLM
    把GPT等生成式预训练模型纳入同一接口，用户可在同一套代码中切换双向和单向模型。
  • 改进
    BERT2018.10 · LLM
    BERT官方只有TensorFlow实现；项目最初就是把BERT及其预训练权重移植到PyTorch，让更多研究者能直接使用。
  • 使用
    SentencePiece2018.08 · NLP
    为每个模型实现其原有的子词切分方式（WordPiece、BPE、SentencePiece等），保证与预训练权重一致。
  • 使用
    ONNX模型交换格式2017.09 · 系统·效率
    模型可导出为ONNX格式部署，论文报告与ONNX团队合作后推理加速接近4倍。

读懂它需要的概念

Transformer层的结构 预训练与微调 分词与token 自注意力与多头注意力 迁移学习

本篇术语

  • from_pretrained　Transformers中按名字或路径加载预训练配置、分词器和权重的方法，首次使用时自动下载并缓存。
  • Auto类　如AutoModel、AutoTokenizer，根据预训练模型的配置自动选择正确的具体类，使代码不必写死模型类型。
  • 模型卡（model card）　随模型发布的说明文档，记录训练数据、用途、局限和评测结果。

怎么学

先补预训练与微调和分词与token。跟着Hugging Face课程的前几章完成：用pipeline做情感分析，用AutoTokenizer看一句话被切成了哪些token，再在一个小数据集上微调一个BERT分类模型。然后打开库中BERT的模型文件，对照Transformer原文找到多头注意力和前馈层的代码。
