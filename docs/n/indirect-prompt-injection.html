间接提示注入

Not what you've signed up for: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection
2023.02论文延伸AISec 2023Greshake, Abdelnabi, Mishra, Endres, Holz, Fritz · CISPA / Saarland University 等待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

当时的提示注入假设攻击者就是在和模型对话的用户；但接入搜索、邮件、代码库后，模型读到的网页文字本身就可能被别人写入指令。

方法

把攻击指令藏进模型之后会检索到的数据里（网页、文档），让应用在毫不知情时执行，等于远程注入，无需直接接触模型。

影响

提出了间接提示注入这一威胁类别，成为后来智能体安全（工具调用、浏览器代理）的核心问题。

方法

提示注入原本指用户在输入里写『忽略之前的指令』。这篇论文指出，LLM应用（如微软追加投资与新Bing的GPT-4聊天、代码补全）会把检索到的内容和系统指令拼在同一个上下文，模型无法区分哪些是数据、哪些是指令——作者称之为『模糊了数据与指令的边界』。攻击者因此不必直接对话，只需把指令放在目标会检索到的网页或文档里。

论文从计算机安全角度给出一个威胁分类：数据窃取、蠕虫式传播、信息生态污染等；并在真实系统（Bing Chat、代码补全引擎）和基于GPT-4搭建的合成应用上演示攻击可行，称处理被检索到的提示可以起到类似任意代码执行的效果，还能控制应用是否、如何调用其他API。

局限与后续

  • 没有可靠的防御：只要模型把检索内容与指令放在同一文本流里，就无法保证不被劫持，论文只是揭示了攻击面。
