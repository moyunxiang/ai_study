梯度检查点

Training Deep Nets with Sublinear Memory Cost
2016.04论文延伸Tianqi Chen, Bing Xu, Chiyuan Zhang, Carlos Guestrin待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

训练一个n层的网络，反向传播需要保存每层的中间激活，显存与层数成正比，很多先进模型已经顶到了GPU显存上限。

方法

只保存少数几层的激活，其余的在反向传播需要时重新前向计算一次，用算力换显存。

影响

成为训练大模型的标准手段，PyTorch、DeepSpeed、Megatron等都提供激活重计算。

方法

摘要的核心结果：训练n层网络只需 O(√n) 的内存，代价是每个小批量多做一次前向计算。做法是把网络切成约 √n 段，前向时只保留每段边界处的激活；反向传播到某一段时，从该段开头的检查点重新前向算出段内激活，用完即丢。内存从保存全部 n 层降到约 2√n 层，额外计算相当于多做一遍前向。

论文还基于计算图分析实现了自动的就地计算和内存共享，并在MXNet里实现，使在显存有限时能训练更深的网络（如深层ResNet）。

局限与后续

  • 额外约一遍前向的计算开销，对计算受限的训练是实实在在的减速。
    后来针对它的工作　FlashAttention
  • 只减少激活内存，参数、梯度与优化器状态的内存仍需另外处理。
    后来针对它的工作　ZeRO与DeepSpeed PyTorch FSDP

它建立在什么之上

  • 延续
    反向传播1986 · 基础
    在反向传播需要保存全部中间值的基础上，用重计算换内存。
  • 改进
    反向模式自动微分1970 · 系统·效率
    反向遍需要正向遍的全部中间值，存储量随计算步数线性增长，深而长的计算会被内存卡住。
  • 改进
    Speelpenning梯度代码生成1980 · 系统·效率
    需要保存整个前向计算过程的中间值，内存与计算步数成正比。
  • 使用
    MXNet2015.12 · 系统·效率
    在MXNet的计算图内存优化基础上实现。

后来的相关工作

  • 使用
    GPipe流水线并行2018.11 · 系统·效率
    每段只保存边界激活、反向时重算本段前向，用梯度检查点式的重计算大幅降低激活显存。
  • 使用
    FlashAttention2022.05 · 系统·效率
    反向传播时不存注意力矩阵而是重算，与梯度检查点“以计算换显存”的思路相同，只是重算发生在片上SRAM。
  • 改进
    ZeRO与DeepSpeed2019.10 · 系统·效率
    只减少激活内存，参数、梯度与优化器状态的内存仍需另外处理。
  • 改进
    PyTorch FSDP2023.04 · 系统·效率
    只减少激活内存，参数、梯度与优化器状态的内存仍需另外处理。
