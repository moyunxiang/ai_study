CRAFT字符级文字检测

Character Region Awareness for Text Detection
2019.04论文延伸CVPR 2019Youngmin Baek, Bado Lee, Dongyoon Han, Sangdoo Yun, Hwalsuk Lee · NAVER Clova AI待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

场景文字检测器大多用单词级的矩形或四边形框训练，遇到弯曲、变形、任意方向的文字时框不住；而真实数据集只有单词级标注，没有逐字符的标注可用。

方法

不直接框单词，而是预测两张热力图：每个像素是不是某个字符的中心（region score），以及是不是两个相邻字符之间的连接处（affinity score），再把字符连成单词；真实图片的字符标注由模型自己在训练中逐步估计。

影响

字符级的检测思路特别适合弯曲文字，CRAFT因官方开源代码好用，成为EasyOCR等开源OCR工具的默认文字检测器之一。

方法

CRAFT的网络是带批归一化的VGG-16骨干加一个类似U-Net的上采样解码器，输出半分辨率的两张图：

  • 字符区域分数：像素离某个字符中心越近值越高，用二维高斯热力图表示；
  • 字符亲和分数：相邻两个字符之间的“连接区域”，同样用高斯表示。

推理时把两张图阈值化后求连通域，同一个连通域里的字符就组成一个单词，再按需要输出矩形或多边形框，因此天然能处理弯曲文字。

难点是监督信号：合成数据（SynthText）有字符框，真实数据只有单词框。CRAFT采用弱监督：用当前的中间模型在真实图片的单词框内预测字符区域，用分水岭算法切出字符框；再按“预测出的字符数与单词真实长度的吻合程度”给这份伪标注一个置信度，不可靠的伪标注权重小。随着训练进行，伪标注越来越准。

摘要称在包括TotalText和CTW-1500（含大量弯曲文字）在内的六个基准上显著超过当时最好的检测器，能检测任意方向、弯曲或变形的文字。

后来的发展

CRAFT与同年的DBNet可微二值化是开源OCR流水线里最常见的两种检测器：前者被EasyOCR采用，后者被PaddleOCR / PP-OCR采用。识别端通常接CRNN文字识别一类模型。之后端到端的文档与场景文字理解逐渐被多模态大模型接管。

本篇术语

  • 场景文字检测　在街景、招牌、商品照片等自然图像里找出文字所在区域，比扫描文档难得多。
  • 亲和分数　表示某个像素落在相邻两个字符之间连接区域的可能性，用来把字符串成单词。
