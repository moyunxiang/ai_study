cuDNN

cuDNN: Efficient Primitives for Deep Learning
2014.09系统延伸arXiv 2014Sharan Chetlur, Cliff Woolley, Philippe Vandermersch, Jonathan Cohen, John Tran, Bryan Catanzaro, Evan Shelhamer · NVIDIA / UC Berkeley待核对
来源 ↗在交互版中打开（演化树、学习进度）

问题

每个深度学习框架都要自己手写和优化卷积等GPU内核，换一代GPU就得重写，研究者的时间花在底层优化上。

方法

借鉴高性能计算里的BLAS：由NVIDIA提供一个深度学习原语库（卷积、池化、激活等），框架直接调用，换GPU由库负责适配。

影响

几乎所有深度学习框架都通过cuDNN使用NVIDIA GPU，这也成为NVIDIA软件护城河的一部分。

方法

论文的论点是：深度学习的计算很重，优化内核困难而耗时；并行硬件每代都变，内核要不断重新优化，维护代码很累。HPC界早就靠BLAS（基础线性代数子程序）解决过这类问题，而深度学习没有对应的库。

cuDNN就是这个库：包含面向GPU的深度学习常用例程，像BLAS一样，原则上也可以在其他平台实现。它容易集成进现有框架，并提供优化的性能和内存使用。论文的例子是：把cuDNN集成进流行的卷积网络框架Caffe，一个标准模型的性能提高36%，同时降低内存消耗。

它的深远影响不在36%这个数字，而在分工：框架（AlexNet之后涌现的Caffe、Torch、Theano和TensorFlow等）负责计算图和自动微分，cuDNN负责每一种算子在具体GPU上的最快实现。

局限与后续

  • 只服务NVIDIA GPU，形成对单一厂商软件栈的依赖。

  • 算子逐个优化，无法自动融合多个算子以省显存带宽。

它建立在什么之上

  • 使用
    CUDA2006.11 · 硬件 待核对
    cuDNN是在CUDA之上写成的深度学习算子库。
  • 使用
    AlexNet2012.09 · 视觉 待核对
    AlexNet之后卷积网络成为主流，cuDNN为这类网络提供标准化的GPU卷积实现。
  • 改进
    BLAS线性代数接口1979.09 · 系统·效率
    接口按单个稠密矩阵设计，不支持批量小矩阵、稀疏、低精度（FP16/INT8）以及把激活函数等运算融合进矩阵乘法，这些都是深度学习的需求。
  • 改进
    GPU训练深度网络2009.06 · 硬件
    每种模型的GPU实现都要专门手写CUDA代码，换一个网络结构就得重写，没有通用工具。
  • 改进
    Caffe2013.12 · 系统·效率
    im2col把输入展开会成倍增加显存占用，卷积性能受限于通用矩阵乘法。
  • 改进
    GPU上的卷积网络2006.10 · 硬件
    展开卷积窗口会重复存储数据，占用显存。
  • 改进
    GPU上的大而简单的网络2010 · 硬件
    需要自己用GPU手写训练代码，缺乏通用的框架和库。

后来的相关工作

  • 使用
    TensorFlow2015.11 · 系统·效率 已核对
    卷积、池化等关键运算调用cuDNN，这也是它与Torch单卡性能接近的原因。
  • 使用
    PyTorch2017.01 · 系统·效率 已核对
    卷积等关键算子调用cuDNN和cuBLAS，这也是各框架单机性能接近的原因。
  • 使用
    V100与Tensor Core2017.05 · 硬件
    cuDNN和cuBLAS把卷积、矩阵乘自动映射到Tensor Core上。
  • 改进
    TVM深度学习编译器2018.02 · 系统·效率
    厂商算子库只覆盖少数硬件、无法提供任意融合组合；TVM自动生成并调优算子，在新硬件上不再依赖手写库。
  • 竞争
    Triton GPU编程语言2019.06 · 系统·效率
    厂商库只覆盖常见算子；Triton用通用编译器重写了cuDNN的IMPLICIT_GEMM卷积且不掉性能，说明不必为每个新算子等厂商。
  • 使用
    TensorRT2016 · 系统·效率
    底层的卷积等内核基于cuDNN及NVIDIA自己的优化内核。
  • 使用
    Tesla P100与DGX-12016.04 · 硬件
    预装的cuDNN负责卷积等核心算子的加速。
  • 改进
    CUDA Tile与cuTile2025.12 · 硬件
    只服务NVIDIA GPU，形成对单一厂商软件栈的依赖。
