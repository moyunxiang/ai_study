OpenAI强化微调RFT

Reinforcement Fine-Tuning
2024.12系统延伸OpenAI待核对
研究计划公告 ↗API文档 ↗在交互版中打开（演化树、学习进度）

问题

企业想让模型在法律、医疗、金融等专业任务上更可靠，但传统监督微调只能模仿示范答案，需要大量标注，也学不到o1那样靠反复尝试练出来的推理方式。

方法

把训练推理模型的强化学习做成微调服务：用户只需上传少量带参考答案的任务和一个评分器，平台让模型反复作答、按评分器打分来更新模型。

影响

让“用可验证奖励做强化学习”从研究实验变成普通开发者可以调用的API功能，评分器（grader）这一概念也随之普及。

方法

在2024年12月的“12天发布”活动中，OpenAI公布了强化微调（RFT）的研究预览计划，面向希望在专业领域定制OpenAI o1推理模型系列模型的机构；HN上的研究计划公告时间是2024-12-06。2025年5月，OpenAI开发者账号宣布RFT向通过验证的组织开放。

用法上，开发者需要准备：

  • 任务数据：一组提示，以及用于判分的参考信息（如标准答案）；
  • 评分器：API里支持字符串比对、文本相似度（如BLEU、ROUGE、余弦相似度）、运行一段Python代码打分、让另一个模型按评分标准给分，以及把多个评分器组合起来。

平台用模型的多次作答和评分结果做强化学习更新，思路与开源社区的奖励设计与奖励投机和可验证奖励RL一致：只要能自动判对错或打分，就不必提供完整的示范推理过程。和监督微调相比，它更适合“答案容易检验、推理过程难以示范”的任务。OpenAI没有公开具体使用的RL算法。

局限与后续

  • 效果高度依赖评分器的设计：评分标准有漏洞时，模型会学会钻评分器的空子，即奖励被投机利用。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 只开放给特定模型和通过验证的组织，训练算法和超参数不透明，难以和开源的RLVR方法直接比较。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 竞争
    PPO2017.07 · RL
    开源社区常用PPO、GRPO等算法自己实现同类训练，RFT则把算法细节封装在平台内部。
  • 延续
    InstructGPT与RLHF2022.03 · LLM
    InstructGPT式RLHF用学出来的奖励模型打分，RFT主要依赖用户定义的、可检验的评分器。
  • 延续
    OpenAI o1推理模型2024.09 · 推理·智能体
    把训练o1类推理模型所用的强化学习做成可由用户定制的微调服务。
  • 竞争
    Tülu 3开放后训练2024.11 · LLM
    Tülu 3同期公开了可验证奖励强化学习（RLVR）的开源配方，RFT是同一思路的商业化服务。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

奖励设计与奖励投机 策略梯度 预训练与微调 人类反馈强化学习

怎么学

先读OpenAI o1推理模型和Tülu 3开放后训练 → 读OpenAI的RFT文档中评分器一节 → 动手：为一个“从合同里抽取日期”的任务写一个Python评分器，想一想模型可能怎样钻它的空子。
