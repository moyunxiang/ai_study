生成知识提示

Generated Knowledge Prompting for Commonsense Reasoning
2021.10论文延伸ACL 2022Jiacheng Liu, Alisa Liu, Ximing Lu, Sean Welleck, Peter West, Ronan Le Bras, Yejin Choi, Hannaneh Hajishirzi · 华盛顿大学 / 艾伦人工智能研究所待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

常识推理题常需要题目里没写出的背景知识；接入外部知识库要专门的检索系统和融合训练，而很多常识（如数字类常识）在现成知识库里根本找不到。

方法

先用少量示例提示GPT-3，为问题写出若干条相关的知识陈述；再把每条知识分别拼到问题前交给回答模型，取置信度最高的那个答案，全程不需要知识库和额外训练。

影响

在NumerSense、CommonsenseQA 2.0和QASC上刷新了当时最好成绩，说明大语言模型本身可以充当灵活的外部知识来源。

方法

论文中的例子：判断“打高尔夫的目标之一是比别人得更高的总分”，不加知识时模型答“对”。生成知识提示先让GPT-3写出相关知识，其中一条是“杆数最少的选手获胜”，把它接在问题前，模型就答对了“错”。

生成知识：对每个任务人工写5组“问题—知识”示例，作为上下文学习与提示的提示；对新问题用核采样生成20条知识陈述（CSQA2为5条），去掉重复和空白。整合知识：把每条知识分别与问题拼接，交给回答模型（零样本的T5-11B，或微调过的UnifiedQA、Unicorn），对每个选项打分；在所有拼接版本中，选置信度最高的那个回答作为最终答案。回答模型不需要为此再训练。

结果：NumerSense从此前最好的66.18%提到72.47%；CSQA2从70.2%到73.03%；QASC从76.74%到80.33%；零样本T5在CommonsenseQA上从39.89%到47.26%。与检索知识相比，在NumerSense上检索几乎无效，生成知识高出7到9个点；在CSQA2上检索谷歌摘要仍更好；作者认为没有合适的领域知识库时，生成知识最有价值。它和三个月后的思维链CoT一样，都是让模型在给出答案前先写出一段中间文字，只是这里写的是背景知识而不是推理步骤。

局限与后续

  • 生成的知识可能是错的或编造的，模型会照样据此作答；论文主要靠在20条中挑置信度最高的来降低影响，没有校验知识的真伪。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 每道题要生成20条知识并做20次推理，成本远高于直接回答；知识生成示例要为每个任务手写。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    GPT-32020.05 · LLM
    用GPT-3按少量示例生成知识陈述，利用的是它的上下文学习能力。
  • 竞争
    检索增强生成RAG2020.05 · 推理·智能体
    检索增强从外部语料取知识；生成知识提示让模型自己写知识，在知识库缺失的数字常识上更有效，但在有谷歌摘要可检索时不如检索。
  • 延续
    语言模型即知识库2019.09 · LLM
    LAMA证明语言模型里存着事实知识；生成知识提示把这些知识显式写出来，交给另一个模型用于推理。
  • 使用
    T52019.10 · LLM
    以零样本T5-11B及其微调版本UnifiedQA作为回答模型，对拼接了知识的问题打分。
  • 使用
    CommonsenseQA2018.11 · 数据·评测
    CommonsenseQA是四个评测数据集之一，零样本T5上从39.89%提到47.26%。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

上下文学习与提示 零样本与少样本 解码：贪心、束搜索、温度与top-p 语言模型

本篇术语

  • 知识陈述　由模型生成的一句与问题相关的背景事实，例如“企鹅不会飞”，拼在问题前帮助回答。
  • 核采样　生成时只从累计概率达到p的那批最可能的词中抽样，p越小输出越保守。

怎么学

先补上下文学习与提示和解码：贪心、束搜索、温度与top-p，读语言模型即知识库 → 读原文第2节方法和表1、第4节生成与检索知识的对比 → 动手：用任意LLM对10道常识题各生成5条知识，比较加知识前后的正确率，并检查生成的知识有几条是错的。
