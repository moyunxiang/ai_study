FlexAttention注意力变体

Flex Attention: A Programming Model for Generating Optimized Attention Kernels
2024.12论文延伸MLSys 2025Juechu Dong, Boyuan Feng, Driss Guessous, Yanbo Liang, Horace He · Meta, 密歇根大学待核对
arXiv ↗PyTorch博客 ↗在交互版中打开（演化树、学习进度）

问题

FlashAttention极快但是一个写死的整体内核，研究者想试滑动窗口、ALiBi、文档掩码这类变体，要么等人手写新内核，要么退回又慢又占显存的朴素实现——论文称之为“软件彩票”。

方法

让用户用几行PyTorch写两个小函数：mask_mod决定哪些位置可见，score_mod修改注意力分数；torch.compile把它们编译成Triton代码，塞进手写好的融合注意力模板，并按块跳过全被掩掉的部分。

影响

成为PyTorch内置的注意力变体写法，多数常见变体不再需要专门的内核，并被torchtune、gpt-fast等PyTorch生态项目采用。

方法

FlashAttention-2把注意力融合成一个内核，但每加一种变体（ALiBi线性偏置位置偏置、滑动窗口、前缀语言模型掩码、vLLM与PagedAttention的分页KV）都要改内核源码，变体之间还会组合爆炸。

FlexAttention把变体抽象成两个函数。mask_mod(b, h, q_idx, kv_idx) → bool：返回这个位置能不能看，例如因果掩码是q_idx >= kv_idx。score_mod(score, b, h, q_idx, kv_idx)：改写分数，例如加上ALiBi的距离偏置。掩码可以用与、或组合，前缀LM就是“前缀掩码或因果掩码”。

编译路径借助PyTorch 2与torch.compile：TorchDynamo抓取这两个函数的计算图（连同自动求出的反向），TorchInductor把它们降成Triton GPU编程语言代码，注入手写的前向、反向和解码注意力模板（模板里已经处理好在线softmax、分块和GQA）。另一个关键是BlockMask：把分数矩阵按128×128分块，事先算出哪些块完全被掩掉、直接跳过，哪些块完全可见、只需执行score_mod，只有部分可见的块才逐元素判断掩码。

论文报告：因果掩码下前向是FA2的1.00–1.22倍、反向0.86–1.05倍；在torchtune训练LLaMA3-8B端到端提速超过2.4倍。

局限与后续

  • 性能略逊于为特定变体手工调到极致的内核（反向最低只有FA2的0.86倍），且依赖torch.compile，首次编译慢、对动态形状不够友好。
    本站还没有记录针对它的后续工作（不代表没有人解决）
