MX微缩放格式与FP4

Microscaling Data Formats for Deep Learning
2023.10论文延伸arXiv 2023Rouhani, Zhao, More, Hall 等 · Microsoft、AMD、Arm、Intel、Meta、NVIDIA、Qualcomm等待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

FP8训练格式让每个张量共用一个缩放因子，但数值分布不均时容易溢出或损失精度，再降到6位、4位更难。

方法

把张量切成固定小块（例如32个数），每块共用一个8位指数缩放因子，块内元素用FP8、FP6、FP4或INT8，这就是微缩放（MX）格式。

影响

成为开放计算项目（OCP）标准，为后来Blackwell的FP4和FP6支持奠定了数据格式基础。

方法

MX块由一个共享缩放因子X和k个窄位宽元素组成。论文给出的具体格式都以E8M0（8位指数）作缩放格式，块大小k为32，元素格式有MXFP8（E4M3或E5M2）、MXFP6、MXFP4和MXINT8等。由于每32个数各有自己的缩放，同一个张量里数值大的区域和小的区域不再互相迁就，窄位宽就够用。

论文在超过两打基准上验证，MX格式可以作为FP32的直接替代用于推理和训练，用户几乎不用改代码；并首次演示了权重、激活和梯度都低于8位的语言模型生成式训练，精度损失很小，无需修改训练配方。

局限与后续

  • 块内共享缩放要求硬件支持按块乘缩放，普通加速器需要专门电路。
