Neurocube：3D内存里的加速器

Neurocube: A Programmable Digital Neuromorphic Architecture with High-Density 3D Memory
2016.06论文延伸ISCA 2016Duckhwan Kim, Jaeha Kung, Sek Chai, Sudhakar Yalamanchili, Saibal Mukhopadhyay · 佐治亚理工学院 / SRI International待核对
IEEE DOI ↗在交互版中打开（演化树、学习进度）

问题

神经网络计算需要不断从DRAM读取大量权重和中间结果，普通加速器隔着一条窄带宽的内存总线，运算单元常常在等数据。

方法

把一层运算单元直接叠在HMC混合存储立方体那样的3D堆叠DRAM的逻辑层里，每个运算单元簇就近访问一个存储通道（vault），并由vault控制器中的专用状态机主动把数据“推”给运算单元。

影响

较早把神经网络加速器放进3D堆叠内存逻辑层的设计之一，与次年的TETRIS：3D内存上的加速器一起开启了“近存计算加速器”这一研究方向。

方法

3D堆叠内存把多层DRAM芯片用硅通孔垂直连起来，底下有一层逻辑芯片，内部被划分成多个可以并行访问的通道（HMC里叫vault）。从逻辑层到各个vault的内部带宽远高于芯片外的内存接口。

Neurocube在这层逻辑芯片上放置多个运算单元簇，簇之间用二维网格网络相连；每个簇对应一个vault，所有簇并行访问各自的存储通道。它的运行方式被称为以内存为中心的计算：不是由处理器发指令去取数据，而是在vault控制器里嵌入专门的状态机，按照神经网络的计算顺序生成地址、把数据主动送进运算单元。这种方式也让同一硬件能通过编程支持不同的网络。

论文给出了逻辑层在28nm和15nm工艺下的综合分析，并通过映射一个卷积神经网络，估算了训练和推理时的功耗与性能。

局限与后续

  • 逻辑层的面积和散热预算很小，能放的运算单元有限；结果来自综合与估算，没有实际流片。
