短语统计机器翻译

Statistical Phrase-Based Translation
2003.05论文重要HLT-NAACL 2003Philipp Koehn, Franz Josef Och, Daniel Marcu · 南加州大学信息科学研究所（ISI）待核对
ACL Anthology ↗Koehn《Statistical Machine Translation》教材主页 ↗在交互版中打开（演化树、学习进度）

问题

IBM模型一个词一个词地翻译，德语“es gibt”这种整体才有意义的搭配（意思是“there is”）只能拆开硬译；已有的几种短语方法各自为战，没人说清该怎么建短语表。

方法

先做双向词对齐，把所有与对齐一致的连续词串对都抽出来当作“短语对”，按相对频率估计翻译概率；解码时把源句切成短语、逐个翻译、允许调序，用束搜索找最优译文。

影响

确立了此后十年统计机器翻译的标准流水线：词对齐→短语抽取→打分→束搜索解码。Pharaoh、Moses和早期Google翻译都基于这一框架。

背景

1990年代的IBM统计翻译模型把翻译建模成词到词的对应：源句每个词独立地选一个目标词，再调整位置。这对“house→Haus”有效，但语言里大量意义由多个词合起来表达。论文举的例子是德语“es gibt”，字面是“it gives”，实际意思是“there is”；英语的“with regard to”“note that”结构复杂，却常常对应另一种语言的一个词。逐词翻译很难译对这些。

2003年前已有几种“短语”方案：Och等人的对齐模板、Marcu和Wong的联合概率短语模型，还有主张只保留句法成分作短语的句法翻译模型。但它们的解码器、训练数据各不相同，无法比较，没人知道哪个环节真正重要。

方法

模型。沿用噪声信道翻译模型的噪声信道：e_best = argmax_e p(f|e) · p_LM(e) · ω^{length(e)}。p_LM是三元语言模型，ω是每生成一个词乘一次的长度因子（通常大于1，防止译文过短）。翻译模型把源句f切成I个短语，每个短语f̄_i独立地翻成英文短语ē_i，再乘一个调序（distortion）惩罚：p(f|e) = Π φ(f̄_i | ē_i) · d(a_i − b_{i−1})，其中d根据当前短语起点与上一个短语终点的距离打折。

短语从哪来。用GIZA++与对齐模型比较的GIZA++分别做“德→英”和“英→德”两个方向的IBM Model 4词对齐。两者取交集精度高、取并集召回高，于是从交集出发，按启发式逐步加入并集中与已有对齐点相邻的点（论文比较了diag、diag-and等变体）。然后抽出所有与对齐一致的短语对：短语内的词只与短语内的词对齐，不与外面的词对齐。φ(f̄|ē)用相对频率估计，即count(f̄, ē) / count(ē)。

词汇权重。短语对出现次数少时频率估计不可靠，于是再用词翻译概率检查短语内部的词是否真能互译，作为额外打分。

解码。从左到右生成译文，每一步任选一段未翻译的源短语接到译文末尾。按已翻译源词数把假设放进不同的栈，每个栈只保留最好的若干个（束宽100就够），排序时加上用动态规划预先算好的“剩余部分的未来代价”估计。

结果

主实验在Europarl语料的德→英方向，训练集从1万句对到32万句对，用BLEU评分，结论在其他语言对上同样成立。

  • 抽取“所有与对齐一致的短语”优于联合概率模型，两者都优于IBM Model 4逐词系统。
  • 只保留句法成分的短语有害：它删掉了80%以上的短语对，“es gibt/there is”这类非成分搭配全被丢掉。
  • 短语最长只取3个词就基本足够，更长收益很小，短语表却大得多。
  • 词汇权重最多带来约0.01 BLEU（以0–1计）的提升；不同对称化启发式之间最好与最差相差约0.02 BLEU。

后来的发展

这套做法很快成为默认：作者随后发布Pharaoh解码器，2007年开源的Moses集成了全部流程，并用最小错误率训练MERT调各特征的权重，形成对数线性翻译模型框架下的标准系统。Google翻译上线（统计MT）上线时的统计翻译也属于这一路线。层次短语翻译Hiero在它的基础上允许短语带“空位”，以处理长距离调序。

2014年起，RNN编码器-解码器与GRU先把神经网络当作短语表的一个额外打分特征，随后Seq2Seq和注意力机制直接端到端生成译文，到谷歌神经机器翻译时短语翻译在主流产品中被取代。“对齐一致的短语抽取”和调序建模的思路仍出现在低资源翻译和对齐工具中。

局限与后续

  • 短语是扁平的连续词串，长距离调序（如德语动词放句末、中英文语序差异）只靠一个按距离打折的惩罚，常把词放错位置。
    后来针对它的工作　层次短语翻译Hiero 注意力机制
  • 无法表示不连续的搭配，如法语“ne … pas”或英语“not only … but also”中间夹着其他词。
    后来针对它的工作　层次短语翻译Hiero
  • 词对齐、短语抽取、打分、调序是分别训练的独立环节，前一步的错误无法被后一步纠正，也无法整体优化。
    后来针对它的工作　Seq2Seq 注意力机制
  • 短语表规模随训练数据几乎线性增长，大多数短语对只出现一次，存储和查询开销都很大。
    后来针对它的工作　谷歌神经机器翻译

它建立在什么之上

  • 改进
    IBM统计翻译模型1993 · NLP 待核对
    IBM模型逐词翻译，处理不了多词整体表意的搭配；这篇把多词短语当翻译单位，实验中明显好于IBM Model 4逐词系统。
  • 延续
    噪声信道翻译模型1990.06 · NLP
    沿用IBM噪声信道的分解：翻译模型p(f|e)乘语言模型p(e)，只是把翻译单位从词换成了短语。
  • 使用
    BLEU2002.07 · 数据·评测
    全部对比实验用BLEU自动评分，使得大量配置之间可以快速比较。
  • 使用
    GIZA++与对齐模型比较2003 · NLP
    用GIZA++在两个方向做IBM Model 4词对齐，再对称化后抽取短语。
  • 改进
    SYSTRAN规则机器翻译1968 · NLP
    每个语言对和领域都要人工写词典和规则，成本高、扩展慢，翻译质量对未覆盖的表达不稳定。
  • 改进
    IBM Candide翻译系统1994 · NLP
    训练依赖大规模双语对照语料，词对词的对齐模型难以表达词序大幅变化和短语翻译。
  • 延续
    对数线性翻译模型2002.07 · NLP
    论文本身仍用噪声信道加长度因子；短语翻译概率、词汇权重、调序惩罚随后作为特征放进Och的对数线性框架，成为Pharaoh/Moses的标准形态。

后来的相关工作

  • 竞争
    注意力机制2014.09 · NLP 已核对
    在不含未登录词的句子上BLEU 36.15，略超短语系统Moses的35.63，但全测试集上仍落后。
  • 竞争
    Seq2Seq2014.09 · NLP 已核对
    直接翻译的BLEU 34.81超过作者所用短语基线的33.30，但仍低于当时最好的WMT’14系统（37.0）；两条路线的分歧在于端到端学习还是多部件组合。
  • 改进
    层次短语翻译Hiero2005.06 · NLP
    短语模型只能整块搬运连续词串、块间调序与内容无关；Hiero允许短语带空位，用规则本身表达“X₁的X₂→the X₂ that X₁”这类大跨度调序。
  • 使用
    WMT机器翻译评测2006.06 · 数据·评测
    提供的基线解码器Pharaoh实现的是短语统计翻译，参赛系统也大多属于这一类。
  • 延续
    Moses2007.06 · NLP
    把Koehn等人的短语翻译模型实现为开源、完整的工具链，并扩展出因子化翻译和混淆网络解码。
  • 使用
    RNN编码器-解码器与GRU2014.06 · NLP
    不替换短语系统，而是用编码器-解码器给其短语表中的每个短语对重新打分，作为额外特征。
  • 改进
    回译2015.11 · NLP
    统计翻译靠独立语言模型吸收单语数据；回译把这一能力带进端到端神经翻译，不需要单独的语言模型。
  • 改进
    谷歌神经机器翻译2016.09 · NLP
    在生产数据上，人工并排评测显示它把短语翻译与人工译文之间的差距缩小了58%–87%，取代短语系统上线。
  • 竞争
    多语言NMT与零样本翻译2016.11 · NLP
    传统做法是经英语中转的短语翻译（葡→西28.99 BLEU）；零样本模型加少量数据增量训练后达到31.77，解码时间减半。
  • 竞争
    GHKM句法翻译规则2004.05 · NLP
    短语翻译完全不用句法；GHKM坚持用英语句法树，但放宽规则形式以覆盖短语翻译能处理的现象。
  • 使用
    Pharaoh短语解码器2004.09 · NLP
    实现的就是Koehn等2003年短语翻译模型的解码。
  • 使用
    Europarl平行语料2005.09 · 数据·评测
    短语翻译表需要大量句子对齐的双语数据，Europarl提供了免费的训练集。
  • 使用
    Google翻译上线（统计MT）2006.04 · NLP
    统计翻译核心是短语翻译加语言模型的系统，Google在此基础上扩大规模。
  • 延续
    跨语言词向量线性映射2013.09 · NLP
    目标是自动生成和扩充统计翻译系统所依赖的词典和短语表。
  • 竞争
    循环连续翻译模型2013.10 · NLP
    与短语翻译的路线不同：不使用短语表和词对齐，用端到端的连续表示建模翻译。
  • 改进
    RNN中文诗歌生成2014.10 · NLP
    统计机器翻译式作诗每次只看上一句、主题易跑偏；RNNPG用上下文模型汇总全诗语境。

读懂它需要的概念

噪声信道与词对齐 n-gram与平滑 条件概率与贝叶斯公式 解码：贪心、束搜索、温度与top-p 动态规划 文本生成的自动指标

本篇术语

  • 短语表　从平行语料里抽出的“源语短语—目标语短语—概率”大表，一个系统往往有数百万条，这里的“短语”只是连续词串，不要求是语法成分。
  • 对齐一致　一对短语里的每个词，只与对方短语里的词有对齐连线，与短语外的词没有连线；满足这个条件才被抽成短语对。
  • 对称化　把两个翻译方向各自得到的词对齐合并成一个：交集精确但稀疏，并集全面但噪声多，常用启发式在两者之间取折中。

怎么学

先补噪声信道与词对齐和n-gram与平滑，读过IBM统计翻译模型。读原文第2节（模型与束搜索解码）和第3.1、4.5节（短语抽取与对称化）。动手：在几十句手工词对齐的句对上，写程序抽出所有对齐一致的短语对并统计相对频率；再看Koehn教材第5章对同一算法的图解。
