CodeT生成测试选代码

CodeT: Code Generation with Generated Tests
2022.07论文延伸ICLR 2023Bei Chen, Fengji Zhang, Anh Nguyen, Daoguang Zan, Zeqi Lin, Jian-Guang Lou, Weizhu Chen · 微软待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

Codex这类模型对一道题采样100个程序，往往其中有对的，但不知道是哪个；用测试用例跑一遍最可靠，可人工写测试用例又贵又慢，pass@1远低于pass@100。

方法

让同一个语言模型同时为题目生成测试用例，把所有候选程序在这些测试上运行，再用“双重执行一致”打分：一组程序如果输出相同、且通过的测试多，就更可能正确。

影响

不需要任何额外训练或人工测试，就把HumanEval上的pass@1提高到65.8%，比code-davinci-002绝对提高18.8%，成为“用执行反馈从采样中选程序”的代表方法。

方法

背景：Codex论文显示，对每道题多采样能大幅提高“至少一个正确”的概率（pass@k），但真正用时只能交一个答案。AlphaCode用大量采样再按题目给的示例测试过滤、按行为聚类挑选。可是示例测试很少，很多题目根本没有测试。

生成测试：CodeT用同一个预训练模型，在题目描述和函数签名后面接上 assert 函数名( 这样的提示，让模型续写出许多测试用例，例如 assert add(1, 2) == 3。这些测试不一定都对，但数量多、覆盖面广。

双重执行一致：把每个候选程序x在每个生成的测试y上执行，得到通过与否。把“通过了完全相同那一组测试”的程序归为一个共识集合S。集合的分数为 f(S) = |S_x| × |S_y| 即集合里程序的数量乘以它们共同通过的测试数量。直观上：如果很多个独立采样的程序给出一致的行为（程序之间一致），并且这种行为通过了很多测试（与测试一致），这组程序就很可能是对的；错的程序往往各错各的，很难形成大集合。最后从得分最高的集合中选一个程序作为答案。

结果：在HumanEval、MBPP、APPS、CodeContests四个基准上，用五个不同规模和能力的模型实验，CodeT都带来稳定提升。摘要中的例子：HumanEval上pass@1达到65.8%，比code-davinci-002绝对提高18.8%，比此前最好结果高出20个百分点以上。

后来的发展

“模型自己生成测试、用执行结果做选择或奖励”成为代码生成的常用组件，后来的自我调试、代码重排序和代码RL中的测试生成都沿着这条思路。

局限与后续

它建立在什么之上

  • 改进
    Codex2021.07 · LLM
    Codex的pass@1远低于pass@100，CodeT用自动生成的测试从多个采样中选出正确程序。
  • 改进
    TransCoder无监督代码翻译2020.06 · LLM
    模型对翻译结果是否正确没有自我检查，常常生成能编译但语义有细微错误的代码。
  • 使用
    HumanEval2021.07 · 数据·评测
    主要评测基准，pass@1提升到65.8%。
  • 延续
    AlphaCode2022.02 · 推理·智能体
    AlphaCode用题目给的少量示例测试过滤并按行为聚类，CodeT改为让模型自己生成大量测试，并按程序与测试的双重一致打分。
  • 竞争
    自洽性采样2022.03 · 推理·智能体
    两者都利用多个采样之间的一致性；自洽性对答案投票，CodeT用执行结果衡量程序之间和程序与测试之间的一致。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

解码：贪心、束搜索、温度与top-p 语言模型 零样本与少样本 基准、排行榜与SOTA

本篇术语

  • pass@k　每道题采样k个程序，只要有一个通过隐藏测试就算解出，统计解出题目的比例。pass@1就是只交一个答案时的正确率。
  • 共识集合　在生成的测试上表现完全相同（通过同一组测试）的一组候选程序。

怎么学

先读Codex中pass@k的定义；读本文第2节测试生成提示与双重执行一致的打分；动手：用一个开源代码模型对HumanEval的几道题各采样20个程序和20条测试，实现f(S)打分，比较随机挑选与CodeT挑选的正确率。
