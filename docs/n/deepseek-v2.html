DeepSeek-V2与MLA

DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model
2024.05论文重要arXiv 2024DeepSeek-AI（Aixin Liu, Bei Feng, Bin Wang, Bingxuan Wang et al.） · 深度求索来源已核对
arXiv ↗论文HTML全文 ↗代码与权重 ↗在交互版中打开（演化树、学习进度）

问题

长上下文推理时KV缓存随长度和头数线性膨胀，限制了批大小和速度；GQA、MQA靠减少KV头来省缓存，但模型效果会变差。

方法

提出多头潜注意力MLA：每个token只缓存一个512维的压缩潜向量，推理时把解压矩阵吸收进查询和输出投影；前馈层用放大到236B的DeepSeekMoE。

影响

相比DeepSeek 67B，训练成本省42.5%、KV缓存减少93.3%、最大生成吞吐提高到5.76倍；MLA随后被DeepSeek-V3、Kimi K2等模型采用。

背景

生成文本时，模型要为已生成的每个token、每一层、每个注意力头保存一份键K和值V（见KV缓存），下一步才不用重算。标准多头注意力每个token每层要存 2·n_h·d_h 个数：头数128、每头128维时就是32768个数，128K上下文下显存很快被占满，能同时服务的请求数（批大小）上不去。

已有的办法是让多个查询头共享KV：多查询注意力MQA所有头共享一组，分组查询注意力GQA按组共享。缓存确实小了，但每个头能看到的信息变少，效果下降。另一方面，DeepSeekMoE细粒度专家已经在16B规模验证了细粒度专家，DeepSeek LLM 67B是团队上一代稠密模型。

方法

MLA：把KV压成一个潜向量。对第t个token的隐状态h，先用一个下投影得到低维潜向量 c = W_DKV · h（d_c = 512维），只缓存它；需要时再用上投影还原每个头的键和值：k_i = W_UK_i · c，v_i = W_UV_i · c。关键在于推理时不必真的还原：注意力分数 q_iᵀ k_i = (W_UK_iᵀ q_i)ᵀ c，可以把 W_UK 预先乘进查询投影，W_UV 乘进输出投影，直接在潜向量上算注意力（见低秩近似）。

解耦的RoPE。旋转位置编码RoPE要给键乘上一个随位置变化的旋转矩阵，它夹在 W_Q 和 W_UK 之间，矩阵就合并不了。解决办法是另开一小路：每个头额外有64维查询、所有头共享一个64维的键，只在这一路上加RoPE，这个键也要缓存。于是每个token每层缓存 512 + 64 = 576 个数，约为上面多头注意力32768个数的1.8%，相当于只有2.25组的GQA，但论文的对比实验显示效果反而强于标准多头注意力。

DeepSeekMoE放大。60层，除第一层外的前馈层都是MoE：2个共享专家加160个路由专家，每个token选6个。总参数236B，激活21B。为控制跨卡通信，加了设备受限路由：路由专家分布在8张卡上，每个token最多只能发往其中3张卡上的专家。

训练。8.1T token预训练（中文比英文多约12%），之后用YaRN把上下文从4K扩到128K；对齐先SFT，再用GRPO做强化学习。

结果

与自家稠密的DeepSeek 67B相比，训练成本省42.5%，KV缓存减少93.3%，最大生成吞吐提高到5.76倍。基座模型MMLU为78.5，略高于Mixtral 8x22B的77.6；中文的C-Eval为81.7、CMMLU为84.0，远高于Mixtral 8x22B。128K以内的大海捞针测试表现良好。同时发布的V2-Lite总参数15.7B、激活2.4B。

后来的发展

DeepSeek-V3原样保留MLA和DeepSeekMoE，把规模放大到671B，并换上无辅助损失负载均衡与多token预测。MLA随后被Kimi K2、Kimi Linear等采用，DeepSeek-V3.2与DSA的稀疏注意力也建立在MLA之上。设备受限路由则演化为V3的节点受限路由。

容易误解的地方

  • MLA不是“更少的头”：查询头仍是128个，每个头都有自己的键和值，只是它们都由同一个潜向量线性生成，所以表达能力介于MHA与MQA之间，而非退化成MQA。
  • “训练成本省42.5%”是与自家67B稠密模型相比，不是与其他公司的模型相比。

局限与后续

  • 仍依赖三种辅助均衡损失加训练时丢弃token来平衡专家负载，损失权重需要调，且会干扰主任务。

读懂它需要的概念

KV缓存 自注意力与多头注意力 低秩近似 混合专家 位置编码 显存、内存带宽与“内存墙”

本篇术语

  • MLA（多头潜注意力）　每个token只缓存一个低维潜向量，各注意力头的键和值都由它经线性变换得到；推理时把这些变换合并进查询和输出矩阵，从而直接在潜向量上计算。
  • 权重吸收　利用矩阵乘法结合律，把两个相邻的线性变换预先乘成一个，省掉中间结果的计算和存储。
  • 设备受限路由　专家分布在多张卡上时，先选出得分最高的M张卡，再只在这些卡上的专家里选top-k，限制每个token的通信范围。

怎么学

先补KV缓存和低秩近似，用纸笔算一遍MHA、GQA、MLA每个token的缓存量。然后读原文第2.1节（公式9–19和表1），重点理解为什么RoPE会破坏权重吸收。动手：用PyTorch实现一个不带RoPE的MLA，验证“先还原K再算注意力”和“把W_UK吸收进查询后直接对潜向量算注意力”结果一致。
