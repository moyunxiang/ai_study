ALiBi线性偏置位置

Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation
2021.08论文重要ICLR 2022Ofir Press, Noah A. Smith, Mike Lewis · University of Washington / Facebook AI Research / Allen Institute for AI待核对
arXiv ↗官方代码 ↗在交互版中打开（演化树、学习进度）

问题

Transformer在多长的序列上训练，就只能在多长的序列上用：用正弦位置编码的模型只要输入比训练长度多出几十个token，困惑度就急剧变差。

方法

不给词向量加任何位置编码，而是在注意力分数上直接减去“距离×斜率”：离得越远扣分越多，每个头用一个固定、不学习的斜率。

影响

在1024长度上训练的13亿参数模型，推理时用2048长度，困惑度追平直接在2048上训练的正弦编码模型，训练快11%、省11%显存；后被BLOOM等大模型采用。

背景

注意力本身不知道词的先后，必须额外注入位置信息（见位置编码）。Transformer把正弦向量加到输入词向量上；旋转位置编码RoPE把位置变成对Q、K的旋转；T5则继承相对位置表示的思路，给每个“相对距离桶”学一个加到注意力分数上的标量。

这引出一个一直没被认真回答的问题：外推。训练时只见过长度L的序列，推理时能不能直接喂更长的？如果能，就可以用便宜的短序列训练（注意力的代价随长度平方增长），用的时候再放长。作者在WikiText-103上实测：正弦编码的模型训练长度512，推理时多出约20个token困惑度就开始恶化；rotary能多撑约200个；T5的相对偏置能多撑约600个，但训练速度至少慢一倍，省下的算力全赔回去了。

方法

ALiBi（Attention with Linear Biases）只改一处：算完查询和键的内积之后、做Softmax与logits之前，加一个与距离成正比的负偏置。对第i个位置的查询：

softmax(q_i·Kᵀ + m·[−(i−1), …, −2, −1, 0])

也就是看自己扣0分，看前一个词扣m分，看前100个词扣100m分。输入端不再加任何位置向量，偏置也不参与 √d_k 缩放。

斜率m按头设定且固定不学：8个头时取几何数列 1/2, 1/4, …, 1/256；一般地，n个头时首项和公比都是 2^(−8/n)。斜率大的头几乎只看最近几个词，斜率小的头能看得较远，相当于让不同头有不同的“视野”。

为什么能外推：偏置只依赖相对距离、是一条直线，训练时没见过的更大距离只是同一条直线的延伸，不会出现模型从未见过的位置向量。代价是一种很强的“近因”偏好（归纳偏置）：远处的词被压得很低。

结果

WikiText-103上，ALiBi模型在训练长度512或1024的基础上，推理长度放到上万个token困惑度也不崩，而正弦、rotary、T5偏置都会逐渐变差；训练和推理速度与正弦编码相差不到1%和3%。在更大的语料上，13亿参数模型（25层、16头）用1024长度训练、2048长度推理，困惑度与在2048上训练的正弦模型相同，训练快11%、显存少11%。

作者也做了分析：推理长度超过训练长度时ALiBi的收益，很大一部分来自更少的token落在序列开头、上下文太短的位置（论文称为early token curse），而不是模型真的利用了更远的历史。

后来的发展

BLOOM、MPT等模型直接采用ALiBi。

但主流后来选了另一条路：LLaMA等用旋转位置编码RoPE，再通过位置插值扩上下文、YaRN把窗口真正扩到几万甚至十几万，并用少量长文本微调。原因是ALiBi的近因偏置把远处信息线性压低，长距离检索做不好。无位置编码NoPE进一步比较了包括ALiBi在内的位置方案在长度泛化上的表现。

容易误解的地方

  • “能外推”不等于“能利用长上下文”。ALiBi在更长输入上困惑度不变差，主要是因为它几乎忽略远处的token；要在长文档里找到很远处的信息，它并不擅长。
  • 斜率不是学出来的，ALiBi本身不增加任何参数。

局限与后续

  • 线性距离惩罚让很远的token几乎得不到注意力，外推时困惑度稳定，但模型并没有真正用上更长的历史，长距离检索类任务表现差。

  • 实验集中在语言模型困惑度和13亿参数以内的模型，外推能力在下游任务和更大模型上是否成立没有验证。

  • 斜率是人为固定的一组几何数列，对需要远近兼顾的任务无法自适应调整。

它建立在什么之上

  • 改进
    Transformer2017.06 · LLM 已核对
    原版正弦位置编码在训练长度之外只能多撑几十个token，ALiBi去掉了它，换成注意力上的距离偏置。
  • 改进
    T52019.10 · LLM
    T5的相对偏置外推最好，但训练慢一倍以上；ALiBi不需要分桶查表、没有参数，外推更好且几乎不增加开销。
  • 竞争
    旋转位置编码RoPE2021.04 · LLM
    同期的位置方案；论文实测rotary外推弱于ALiBi，但后来大模型多用RoPE并配合插值扩窗口，RoPE成为主流。
  • 延续
    相对位置表示2018.03 · LLM
    同样把位置信息写在注意力分数上、只依赖相对距离，但把可学习的距离表示换成一条固定直线。
  • 竞争
    Transformer-XL2019.01 · LLM
    Transformer-XL靠缓存上一段的隐状态延长上下文；ALiBi在WikiText-103上用更长的训练长度（3072）超过了它的困惑度。

后来的相关工作

  • 使用
    BLOOM2022.07 · LLM
    用ALiBi的线性距离偏置代替位置嵌入，论文称它在原始长度上也让训练更平稳、下游效果更好。
  • 竞争
    位置插值扩上下文2023.06 · LLM
    ALiBi靠线性距离惩罚天然外推，但必须从头按它训练；位置插值让已有的RoPE模型低成本扩展，在开源界胜出。
  • 使用
    迷失在中间2023.07 · LLM
    被测的MPT-30B-Instruct采用ALiBi位置编码，结果显示换一种位置编码同样存在中间位置的性能下降。
  • 改进
    YaRN2023.08 · LLM
    线性距离惩罚让很远的token几乎得不到注意力，外推时困惑度稳定，但模型并没有真正用上更长的历史，长距离检索类任务表现差。
  • 竞争
    无位置编码NoPE2023.05 · LLM
    ALiBi主张用线性偏置获得外推，本文发现它在下游任务上不如NoPE
  • 改进
    RULER长上下文2024.04 · 数据·评测
    实验集中在语言模型困惑度和13亿参数以内的模型，外推能力在下游任务和更大模型上是否成立没有验证。

读懂它需要的概念

自注意力与多头注意力 位置编码 Softmax与logits 困惑度 上下文窗口 归纳偏置

本篇术语

  • 长度外推　推理时输入比训练时见过的最长序列更长，模型效果是否还能保持。
  • 斜率m　ALiBi里每个注意力头的一个固定系数，决定距离每增加1，注意力分数扣多少。
  • early token curse　评估时靠近序列开头的token前文太短、预测更难；序列变长后这类token的占比下降，平均困惑度会因此变好。

怎么学

先确认会自注意力与多头注意力和位置编码。读原文第2节（各种位置方法的外推对比，图1）和第3节（ALiBi的公式与斜率），再看附录B关于early token curse的分析。动手：在一个小型字符级语言模型上分别用正弦编码和ALiBi训练长度128，测试长度128、256、512的困惑度，再设计一个“答案在很远处”的复制任务，看ALiBi能否做对。
