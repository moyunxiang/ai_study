通用问题求解器GPS

Report on a General Problem-Solving Program
1959系统重要Proceedings of the International Conference on Information Processing (Paris), 1959Allen Newell, J. C. Shaw, Herbert A. Simon · RAND Corporation / 卡内基理工学院待核对
Wikipedia：General Problem Solver ↗Wikipedia：Means–ends analysis ↗在交互版中打开（演化树、学习进度）

问题

Logic Theorist的四种证明方法是为命题逻辑专门写的，换一个问题就得重写整个程序；能不能有一个与具体问题无关的通用求解程序？

方法

把“问题知识”（有哪些对象、哪些操作）作为输入数据，求解策略做成通用引擎：比较当前状态与目标的差异，挑一个能减小差异的操作，不能直接用就先把满足它的前提设为子目标，递归求解（手段-目的分析）。

影响

第一个把问题知识与求解策略分开的程序，“状态—目标—差异—操作—子目标”的框架成为AI规划的原型；它在玩具问题上成功、在真实问题上被组合爆炸击败，也成为“通用方法不够、需要领域知识”的教训。

背景

逻辑理论家证明机器能做推理，但它的代换、分离、链接四种方法是为《数学原理》的命题逻辑量身定做的。下棋、几何、代数各要一套新程序，这与达特茅斯会议提案里“解决目前只有人类才能解决的问题”的通用目标相距甚远。

Newell和Simon同时还在做另一件事：让大学生边解题边说出自己的想法（出声思维），记录下来分析。他们发现人在解题时反复做的是同一件事——看看现在离目标还差什么，再想办法消掉这个差距。于是他们想把这个过程本身写成程序，让它可以套在任何问题上。

方法

问题的表示。用户给出对象和可以施加在对象上的操作（operator），以及一张“差异—操作”对照表：哪种差异可以用哪个操作来减小。问题被看成一张有向图，节点是状态，边是操作，要从初始状态走到目标状态。

手段-目的分析（means–ends analysis）。GPS反复做三类目标：

  • 变换目标：把状态A变成状态B。先找出A与B的差异D；
  • 减小差异：查表找一个能减小D的操作Q；
  • 应用操作：如果Q的前提在当前状态下不满足，就把“把当前状态变成满足Q前提的状态”设为新的子目标，递归求解，然后再应用Q。

如果有关于差异重要性的知识，就先处理最重要的差异。

例子：汉诺塔要把三个盘子从柱1移到柱3。最大的差异是“最大盘不在柱3”，能减小它的操作是“把最大盘移到柱3”，但这个操作的前提是它上面没有盘子、柱3是空的，于是生成子目标“把上面两个盘子移到柱2”，这个子目标又按同样的方式分解。程序就这样从目标倒推出一串操作。

实现。程序1957年开始编写，用的仍是表处理语言IPL；1959年在巴黎的国际信息处理会议上发表报告。

后来的发展

GPS确实解出了汉诺塔、简单的逻辑证明等能被完全形式化的问题，但在任何真实问题上都失败了：推导图里可能的路径数量随步数指数增长，搜索很快迷失。Ernst和Newell 1969年的专著标题就叫《GPS：通用性与问题求解的个案研究》，专门总结了这个教训。

它留下了三样东西。第一，“状态、操作、前提、子目标”的规划框架被STRIPS规划形式化，用于Shakey机器人机器人，后来成为规划领域的标准表示。第二，“通用策略不够，智能主要来自领域知识”的反思，推动了DENDRAL和专家系统的商业化。第三，Newell和Simon把出声思维与程序模拟结合，写成1972年的《Human Problem Solving》，并在1976年把立场概括为物理符号系统假说；GPS的范式后来演化为认知架构Soar。

今天基于大语言模型的智能体（ReAct等）在做的仍是“分解目标、选择动作、检查进度”这件事，只是差异判断和操作选择交给了模型。

本篇术语

  • 手段-目的分析　比较当前状态和目标状态的差异，选一个能减小差异的操作；若操作的前提不满足，先把满足前提设为子目标。
  • 组合爆炸　可能的操作序列数量随步数指数增长，例如每步有10种选择，20步就有10²⁰种序列，穷举不可能完成。
  • 出声思维　让受试者解题时把脑中所想说出来并记录，用来分析人类的解题过程。
