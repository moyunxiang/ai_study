Lucene开源检索库

1999系统延伸Doug Cutting · Apache软件基金会待核对
官网 ↗Wikipedia ↗在交互版中打开（演化树、学习进度）

问题

1990年代后期，想给网站或文档库加全文搜索，要么买昂贵的商业引擎，要么自己从头实现倒排索引、分词、打分和查询解析，研究里的检索模型很难直接变成产品。

方法

用Java写一个开源的全文检索库：提供倒排索引的建立与合并、文本分析（分词、小写化、词干化）、布尔与短语查询、按TF-IDF（后来默认BM25）打分等完整组件，开发者把它嵌进自己的程序即可。

影响

Lucene成为开源搜索的事实标准：Solr、Elasticsearch、OpenSearch都建在它之上，维基百科、众多电商和企业搜索都使用它；学术界也通过Anserini等工具用它做可复现的检索基线。

背景

向量空间模型、IDF与TF-IDF、BM25等检索模型在SMART、Okapi等研究系统中成熟，TREC文本检索评测评测让它们的效果有了公认的比较。但这些研究系统不是为通用开发设计的，商业引擎又封闭。Doug Cutting此前在Xerox PARC、Apple、Excite写过多个搜索引擎，1999年把经验做成一个开源库。

方法

倒排索引：对每个词项记录它出现在哪些文档、出现几次、在什么位置（postings列表）。查询时只需读取查询词对应的列表再合并，而不必扫描全部文档。

分段写入：新文档先写入小的索引段（segment），段是不可变的，后台按策略合并成大段；删除只做标记，合并时才真正移除。这让索引可以边写边查。

文本分析链：Analyzer由分词器和一串过滤器组成（如标准分词→小写→去停用词→Porter词干化），建索引和查询时用同一套处理，保证词项一致。

打分：早期默认是TF-IDF向量空间模型的变体，Lucene 6（2016）起默认改为BM25：

score(q,d) = Σ_t IDF(t) · tf·(k₁+1) / (tf + k₁·(1 − b + b·|d|/avgdl))

此外支持布尔、短语、通配、模糊和范围查询。后来的版本还加入了数值与地理索引、以及基于HNSW图的稠密向量近邻检索。

结果

历史：1999年由Doug Cutting编写，最初在SourceForge发布；2001年9月加入Apache Jakarta项目，2005年2月成为Apache顶级项目；2010年3月Solr并入为Lucene子项目（据维基百科）。

后来的发展

Cutting随后基于Lucene开发了网页爬虫Nutch，又从Nutch中分离出Hadoop。基于Lucene的Solr和Elasticsearch主导了企业搜索和日志分析。学术界的Anserini可复现检索把Lucene包装成可复现的检索研究工具，使「Lucene上的BM25」成为稀疏检索最常用的基线；稠密检索兴起后，Lucene也加入了向量检索，用于混合检索。

读懂它需要的概念

时间与空间复杂度 检索与向量数据库 分词与token

本篇术语

  • 倒排索引（inverted index）　从「词→包含它的文档列表」的映射，是全文检索的核心数据结构，查询时只读相关词的列表。
  • 索引段（segment）　Lucene中不可变的小索引单元，新文档写成新段，后台不断合并。

怎么学

先读BM25和IDF与TF-IDF → 看Lucene官方文档中Analyzer与IndexWriter的说明 → 动手：用PyLucene或Elasticsearch给几千篇新闻建索引，比较开启与关闭词干化时的检索结果。
