BLINK稠密实体链接

Scalable Zero-shot Entity Linking with Dense Entity Retrieval
2019.11论文延伸EMNLP 2020Ledell Wu, Fabio Petroni, Martin Josifoski, Sebastian Riedel, Luke Zettlemoyer · Facebook AI Research、伦敦大学学院、华盛顿大学待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

传统实体链接依赖人工的别名表（名字→候选实体）、实体先验和精心设计的特征，对知识库里很少被提到的长尾实体和训练时没见过的新实体几乎无能为力；直接用BERT逐个比较提及和数百万个实体又太慢。

方法

两阶段：先用双编码器（一个BERT编码提及及其上下文，一个BERT编码实体的简短文字描述）把两者映射到同一稠密空间，用最近邻检索出候选实体；再用交叉编码器把提及与每个候选的文本拼在一起精细打分。每个实体只需一段描述，不需要别名表和实体嵌入。

影响

在零样本实体链接基准上比此前最好结果高出约6个点，在TACKBP-2010等传统基准上也达到最好水平；双编码器在590万个候选实体中检索只需约2毫秒。BLINK成为维基百科实体链接最常用的开源工具之一，“双编码器召回+交叉编码器重排”也成为稠密检索的标准范式。

背景

AIDA集体实体消歧等实体链接系统由别名表生成候选，再结合先验、上下文与实体一致性消歧。Logeswaran等（2019）提出零样本实体链接设定：测试时的实体来自训练时完全没见过的领域，只能依靠实体的文字描述。与此同时，BERT和FAISS向量检索这类近邻检索库显示，预训练编码器可以把文本对的相关性压进向量内积。

方法

双编码器（召回）：提及侧输入 [CLS] 左上下文 [M_s] 提及 [M_e] 右上下文 [SEP]，实体侧输入 [CLS] 标题 [ENT] 描述 [SEP]，各用一个BERT取[CLS]向量 y_m、y_e，打分 s(m, e) = y_m · y_e。训练时以同一批次中其他实体为负例（批内负例），再加入难负例（模型打分高但错误的实体）。实体向量可以离线预先算好，用FAISS做最近邻检索。

交叉编码器（重排）：把提及上下文与候选实体描述拼成一个序列送入BERT，用[CLS]输出打分，在前k个候选（如k=10）中做softmax选出答案。它能让提及与实体文本逐词交互，精度更高，但只在少量候选上运行。

知识蒸馏：用交叉编码器的打分作为软标签训练双编码器，把大部分精度收益转移到快速的双编码器上。

结果

在零样本实体链接基准上取得最好结果，绝对提升约6个点；在TACKBP-2010等非零样本评测上也达到最好；双编码器在590万候选中检索约需2毫秒；通过知识蒸馏，交叉编码器带来的大部分精度提升可以转移给双编码器（arXiv摘要）。

后来的发展

BLINK与同期的GENRE生成式实体检索（自回归生成实体名）成为两种主流实体链接范式；ELQ把BLINK扩展为同时检测提及的端到端问答实体链接，BLINK的实体编码器也被用于知识密集型任务基准KILT。“双编码器召回、交叉编码器重排、蒸馏”的组合被广泛用于检索增强生成中的检索器设计。

读懂它需要的概念

嵌入向量 内积与余弦相似度 预训练与微调 知识蒸馏 检索与向量数据库 k近邻

本篇术语

  • 双编码器　两段文本分别用编码器得到向量，再用内积比较；可以预先算好一侧的向量，检索很快。
  • 交叉编码器　把两段文本拼在一起送入一个编码器，让它们逐词交互后打分；精度高但慢。
  • 零样本实体链接　测试时的实体在训练中从未出现过，模型只能依靠实体的文字描述来判断。

怎么学

先读BERT与稠密检索的基本思路 → 读本文第3节双编码器、交叉编码器与蒸馏 → 动手：运行BLINK的示例脚本，对几句含歧义人名、地名的句子做链接，比较只用双编码器与加交叉编码器的结果。
