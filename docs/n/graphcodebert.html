GraphCodeBERT数据流预训练

GraphCodeBERT: Pre-training Code Representations with Data Flow
2020.09论文延伸ICLR 2021Daya Guo, Shuo Ren, Shuai Lu, Zhangyin Feng, Duyu Tang, Shujie Liu, Long Zhou, Nan Duan et al. · 中山大学、微软亚洲研究院、微软待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

CodeBERT等代码预训练模型把代码当成普通的词元序列，忽略了程序本身的结构；而变量之间“值从哪里来”的关系恰恰决定了代码的语义。

方法

在预训练中加入代码的数据流图：除了掩码语言建模，再让模型预测数据流的边、对齐源代码和数据流节点，并用图引导的掩码注意力把结构信息注入Transformer。

影响

在代码搜索、克隆检测、代码翻译、代码修复四个任务上达到当时最好水平，成为2021–2022年代码理解任务的标准基线，也确立了“把程序结构喂给预训练模型”的思路。

方法

背景：CodeBERT把BERT式预训练用到“自然语言—代码”双模态数据上，效果很好，但它看到的只是一串词元。程序有明确的结构：抽象语法树（AST）描述语法，数据流描述变量之间的依赖。AST层次很深、节点很多，直接喂给模型代价大。

数据流图：作者选择语义层面的数据流。从AST中提取变量，在变量之间连边，表示“这个变量的值来自那个变量”。例如 x = a + b; y = x * 2，就有边 a→x、b→x、x→y。相比AST，数据流图更简洁，同时直接编码了程序语义的关键部分。

输入与注意力：输入序列由三部分拼成：自然语言注释、源代码词元、数据流图中的变量节点。模型用图引导的掩码注意力：变量节点之间只有在数据流图中有边时才允许互相注意，变量节点和它在代码中对应的词元之间也允许互相注意，其余组合被掩掉。这样Transformer的注意力模式本身就体现了图结构。

三个预训练任务：

  • 掩码语言建模：同CodeBERT，遮盖注释和代码中的词元并预测；
  • 边预测：随机遮掉数据流图中的一些边，让模型预测两个变量节点之间是否有边；
  • 节点对齐：遮掉变量节点与代码词元之间的对应边，让模型预测某个变量节点对应代码中的哪个位置。

摘要报告：结构信息和新的预训练任务都带来提升，在四个下游任务上达到当时最好；分析显示在代码搜索中，模型更偏好结构层面的注意力而不是词元层面的注意力。

后来的发展

GraphCodeBERT和同组的UniXcoder是CodeXGLUE时代代码理解任务的主要基线；“结构感知预训练”后来在大规模解码器代码模型中让位于纯文本的规模扩展。

局限与后续

  • 仍是约1.25亿参数的编码器模型，适合理解和检索类任务，不能直接用于自回归的代码生成。
    后来针对它的工作　UniXcoder统一代码预训练 CodeT5
  • 需要为每种语言写解析器提取数据流，扩展到新语言或语法有错的代码片段时不方便。
    本站还没有记录针对它的后续工作（不代表没有人解决）

读懂它需要的概念

掩码建模 自注意力与多头注意力 图、树与搜索 预训练与微调 嵌入向量

本篇术语

  • 数据流图　以变量为节点、以“值从哪里来”为边的有向图，描述程序中变量之间的依赖关系。
  • 抽象语法树（AST）　编译器把源代码解析成的树结构，每个节点表示一个语法成分，如表达式、语句、函数。
  • 克隆检测　判断两段代码在功能上是否相同，即使写法不同。

怎么学

先读CodeBERT；读本文第3节数据流图的构造和图引导掩码注意力的定义；动手：用tree-sitter从一个Python函数中抽取变量依赖，画出数据流图，再用公开的GraphCodeBERT在CodeSearchNet的小样本上做代码检索。
