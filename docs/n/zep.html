Zep时序图谱记忆

Zep: A Temporal Knowledge Graph Architecture for Agent Memory
2025.01论文延伸Preston Rasmussen, Pavlo Paliychuk, Travis Beauvais, Jack Ryan, Daniel Chalef · Zep AI待核对
arXiv ↗Graphiti GitHub ↗在交互版中打开（演化树、学习进度）

问题

智能体的记忆大多是一堆静态的文本片段：用户上个月说住在北京、这个月说搬到上海，向量检索会把两条都找出来，模型分不清哪条现在还成立。

方法

把对话和业务数据实时写进一张带时间的知识图谱（引擎Graphiti）：原始消息、抽取出的实体与事实、实体社区分三层存放，每条事实记下“何时成立、何时失效”，新事实与旧事实矛盾时把旧的标记为过期而不是删掉。

影响

把GraphRAG式的图结构从静态文档搬到不断变化的智能体记忆上，Graphiti开源后成为常用的智能体记忆组件；论文同时指出MemGPT用的DMR评测太容易，推动大家改用LongMemEval这类长程记忆评测。

背景

MemGPT把上下文当内存来分页管理，GraphRAG、HippoRAG图记忆检索把文档整理成知识图谱再检索，但它们处理的大多是写好就不变的资料。企业里的智能体面对的是持续流入的对话和业务数据，事实会过期、会互相矛盾，还常带着“两周前”“下周四”这样的相对时间。

方法

三层图：最底层是情节（episode），原封不动地保存每条消息、文本或JSON，保证不丢信息、事实可追溯到出处；中间层是语义实体，由LLM从情节中抽取实体和关系，实体名编码成1024维向量，并与已有实体做消歧合并；最上层是社区，把联系紧密的实体聚成簇并写摘要，思路来自GraphRAG。

双时间模型：每条事实边记四个时间戳——系统何时写入、何时作废（事务时间线T′），以及这件事在现实中从何时到何时成立（事件时间线T）。新边写入时，LLM把它和语义相近的旧边比较，若在时间上重叠又互相矛盾，就把旧边的失效时间设为新边的生效时间。所以“住在北京”不会被删除，而是变成“截至某日成立”。

检索：先用余弦相似度、BM25全文检索和图上的广度优先搜索三路召回候选，再重排，最后把前20条事实和实体摘要拼成一段上下文交给模型。

结果：在MemGPT团队的DMR评测上，用gpt-4-turbo得94.8%，MemGPT为93.4%；但作者同时报告，直接把整段对话塞给gpt-4o-mini也有98.0%，说明这个评测区分度不够。于是又在平均约11.5万词元的LongMemEval上测试，官方称准确率最多提升18.5%、响应延迟降低约90%。

后来的发展

Graphiti作为开源时序图谱引擎被不少智能体框架接入；之后的Mem0长期记忆、A-MEM卡片盒记忆等记忆系统都拿它作对照，围绕“记忆如何更新与遗忘”的讨论也更多转向显式的时间与冲突处理。

读懂它需要的概念

检索与向量数据库 嵌入向量 图、树与搜索 智能体循环 上下文窗口

本篇术语

  • 双时间模型　数据库里同时记录“事情在现实中何时发生/成立”和“系统何时记下/作废它”两条时间线，便于回答“当时以为是什么”和“实际是什么”。
  • 实体消歧　判断新抽出的“老王”和图里已有的“王经理”是不是同一个人，是就合并。

怎么学

先读MemGPT和GraphRAG → 读原文第2节建图（特别是边失效的规则）和第4节两个评测 → 动手：用Graphiti写入三条前后矛盾的对话，查看旧事实边上的失效时间。
