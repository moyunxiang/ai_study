IPython / Jupyter Notebook

IPython: A System for Interactive Scientific Computing
2011.12系统重要IPython论文 Computing in Science & Engineering 2007；Notebook随IPython 0.12发布（2011年）Fernando Pérez, Brian Granger, Min Ragan-Kelley等 · IPython项目（加州大学伯克利分校等）；2014年拆分出Project Jupyter待核对
IPython 0.12发布说明（Notebook首次发布） ↗IPython论文（CiSE 2007，DOI） ↗维基百科：Project Jupyter ↗在交互版中打开（演化树、学习进度）

问题

做数据分析和模型实验要反复“改一行、跑一遍、看结果”，脚本每次从头运行很慢；代码、图表和文字说明散落在不同文件里，别人很难复现和看懂。

方法

在浏览器里提供一个由“单元格”组成的文档：代码、运行结果、图表、公式和文字交错排列，背后连着一个常驻的计算进程（内核），变量一直留在内存里，可以只重跑某一格。

影响

Notebook成了数据科学和机器学习研究的默认工作界面，大量教程、课程、论文附带代码以.ipynb形式发布；Colab、Kaggle等平台都以它为前端。

背景

IPython始于2001年，是Fernando Pérez在读博时做的增强版Python交互命令行：带补全、历史、内省、方便画图。2007年的论文把它定位为“交互式科学计算”的环境，并支持交互式的并行计算。

但命令行仍有两个问题。第一，交互过程留不下来：试了二十种画法，最后只有记忆知道哪种有效。第二，结果难以分享：代码在.py里，图在文件夹里，结论在邮件或论文里。商业软件Mathematica早有“笔记本”界面，MATLAB也有交互环境，但它们闭源、收费，和Python以NumPy与SciPy为中心的开源生态不兼容。

方法

关键的工程决定是把“界面”和“计算”拆开。IPython 0.11重构出内核：一个独立进程负责执行代码、保存所有变量，前端通过消息协议（基于ZeroMQ）把代码发过去、把结果收回来。终端、Qt控制台和后来的网页笔记本都只是同一内核的不同客户端。

0.12版本加入基于浏览器的Notebook：

  • 文档由一串单元格组成：代码单元执行后，输出（文本、表格、Matplotlib图片）直接显示在下方；Markdown单元写说明，可以嵌入LaTeX公式。
  • 状态在内核里持续存在：读入一个10GB的数据集只需一次，之后每格只做增量分析。
  • 整个文档存为一个JSON文件（.ipynb），代码、输出和图都在里面，可以直接发给别人或放到网上渲染。

2014年，与语言无关的部分（笔记本格式、消息协议、前端）拆分为Project Jupyter，名字取自Julia、Python、R三种语言；IPython保留为Python内核。此后内核扩展到几十种语言。

后来的发展

Notebook改变了机器学习的工作方式：scikit-learn、PyTorch的官方教程，斯坦福CS231n等课程的作业都以笔记本发布；Google Colab在2017年把它放到云端并附带免费GPU，Kaggle数据竞赛也提供在线笔记本。很多论文用笔记本附上可运行的实验代码，“打开就能复现”成为常态。2018年2月JupyterLab作为新一代前端正式面向用户。

容易误解的地方

  • 单元格可以按任意顺序执行，内核里的状态可能与页面上从上到下读到的代码不一致，这是笔记本结果难以复现的首要原因；分享前应“重启内核并全部运行”一遍。
  • .ipynb是带输出的JSON，放进Git后合并冲突和差异很难看，长期维护的代码应移到.py模块里。

局限与后续

  • 隐藏状态和乱序执行让笔记本里的结果难以复现，也很难做单元测试和代码审查。

读懂它需要的概念

训练集、验证集与测试集 怎样读一篇论文

本篇术语

  • 内核（kernel）　笔记本背后真正执行代码的独立进程，保存所有变量；前端只负责显示和编辑，可以重启内核清空状态。
  • .ipynb　笔记本的文件格式，本质是JSON，按顺序记录每个单元格的类型、源代码和输出。

怎么学

装好Jupyter（或直接打开Colab），新建一个笔记本，用NumPy和Matplotlib画一条正弦曲线，在下面用Markdown写一段说明并插入一个公式。然后故意打乱执行顺序制造一个隐藏状态错误，再用“Restart & Run All”检查。之后读IPython 0.12的发布说明，了解内核与前端分离的设计。
