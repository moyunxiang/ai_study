Cursor 2.0与Composer

Introducing Cursor 2.0 and Composer
2025.10系统延伸Cursor（Anysphere）待核对
Cursor官方 ↗在交互版中打开（演化树、学习进度）

问题

编码智能体依赖第三方通用模型，响应慢，一次改动常要等几分钟；同时多个智能体并行又容易互相踩文件。

方法

推出自研编码模型Composer，主打低延迟，同时把界面改为以智能体而非文件为中心，用git worktree隔离并行的智能体。

影响

编码工具公司开始训练自己的前沿模型，并把“多智能体并行、人负责评审”变成IDE的默认工作方式。

方法

Cursor在2025年10月29日发布2.0版。官方称其首个编码模型Composer是前沿模型，速度比同等智能水平的模型快4倍，多数回合在30秒内完成。它是用一组工具训练出来的，包括全代码库语义搜索，因此更善于理解大型代码库。

新的界面围绕智能体设计：可以并行运行多个智能体，用git worktree或远程机器相互隔离。官方还称让多个模型尝试同一问题并挑选最佳结果能显著提升最终效果；并指出随着智能体写更多代码，瓶颈转为代码评审和测试，因此加入了便于评审改动的功能和原生浏览器工具让智能体自己测试。Composer的训练细节公告里没有展开，它所采用的是SWE-RL一类思路的工程化版本这一点属于推测。

局限与后续

  • Composer的训练数据、评测基准和与别家模型的比较多为官方自述，缺少独立复现。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 并行智能体产出的代码量超过人能评审的速度，评审成为新瓶颈。
