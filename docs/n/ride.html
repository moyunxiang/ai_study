RIDE影响驱动探索

RIDE: Rewarding Impact-Driven Exploration for Procedurally-Generated Environments
2020.02论文延伸ICLR 2020Roberta Raileanu, Tim Rocktäschel · NYU / Facebook AI / UCL待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

好奇心、计数类内在奖励假设同一个状态会被反复访问；在每局都重新生成地图的程序化环境里，几乎每个状态都是新的，这些奖励失去区分度。

方法

奖励“造成影响”的动作：如果一个动作让学到的状态表示发生了大的变化，就给它高的内在奖励，再除以本局内对该状态的访问次数的平方根，防止原地来回刷分（RIDE）。

影响

成为MiniGrid等程序化稀疏奖励环境上的标准探索基线，后来的NovelD、E3B等工作都以它为主要对比，并沿用“按局计数”的设计。

方法

RIDE（Rewarding Impact-Driven Exploration）沿用好奇心模块ICM的做法学一个状态嵌入φ：用前向模型（由 φ(s_t) 和动作预测 φ(s_(t+1))）和逆向模型（由前后两个嵌入预测动作）共同训练，使φ只保留智能体能控制的部分。

内在奖励定义为嵌入变化的大小，再按本局计数打折：

r_int(s_t, a_t) = ‖φ(s_(t+1)) − φ(s_t)‖₂ / sqrt(N_ep(s_(t+1)))

其中 N_ep 是这一局里到目前为止访问 s_(t+1) 的次数。分子奖励那些“改变了世界”的动作，比如开门、捡钥匙；分母防止智能体在两个状态之间来回切换不断刷奖励。与ICM不同，这个奖励不是预测误差，所以不会随着模型学好而消失。

实验在多个程序化生成的MiniGrid任务以及此前工作用过的高维观测任务上进行。摘要称RIDE比现有探索方法更省样本，尤其在程序化MiniGrid上；它的内在奖励在训练中不会衰减，并且对与可控物体交互的动作奖励得明显更多。

局限与后续

  • 按局计数需要能判断两个状态是否相同，在连续或高维带噪声的观测下计数没法直接做。
    后来针对它的工作　E3B椭圆局内奖励
  • 嵌入变化大不一定对任务有用，在有大量可交互但无关物体的环境里会被吸引过去。
    后来针对它的工作　Motif AI反馈内在奖励 ELLM大模型引导探索

读懂它需要的概念

探索与利用 奖励设计与奖励投机 嵌入向量 状态、观测与动作

本篇术语

  • 程序化生成环境　每一局都随机生成新地图或新布局的环境，同一个状态很少重复出现。
  • 按局计数（episodic count）　只统计当前这一局里访问某状态的次数，每局开始清零。

怎么学

先读好奇心模块ICM；读RIDE原文第3节的奖励定义；在MiniGrid的KeyCorridor或MultiRoom上比较ICM、RND与RIDE。
