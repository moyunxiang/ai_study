Chainer与Define-by-Run

Chainer: a Next-Generation Open Source Framework for Deep Learning
2015.06系统重要2015年6月开源；论文 NIPS 2015 LearningSys Workshop，KDD 2019Seiya Tokui, Kenta Oono, Shohei Hido, Justin Clayton · Preferred Networks待核对
LearningSys 2015论文 ↗arXiv（KDD 2019版） ↗PFN 2019年迁移到PyTorch的公告 ↗在交互版中打开（演化树、学习进度）

问题

Theano、Caffe等框架要求先把整张计算图定义好再运行：带条件分支、变长输入的模型（循环网络、树形网络）很难写，模型运行时是一个黑盒，没法用普通调试器看里面发生了什么。

方法

Define-by-Run：不预先定义图，而是在用普通Python代码执行前向计算的同时记录每一步运算，反向传播时沿记录倒推。if、for等宿主语言的控制流可以直接用，每次运行的图都可以不同。

影响

第一个以动态计算图为核心的主流框架；PyTorch的设计直接借鉴了它，“边运行边建图”后来成为深度学习框架的默认范式，连TensorFlow 2也改成了这种模式。

背景

2015年的主流框架都属于论文所说的Define-and-Run：先定义图（Caffe的配置文件、Theano与自动微分的符号表达式），再把数据喂进去运行。这对卷积网络这类固定结构很合适——整张图在手，框架可以做全局优化。

但论文指出两个问题。第一，带控制流的动态网络很麻烦：循环网络每个句子长度不同，必须用框架专门提供的循环算子或开关算子，而不能用Python本身的if和for。第二，模型运行时是一个大黑盒，结构、权重、梯度都封装在图对象里，调试器和性能分析工具看不进去，图优化之后更难追查。研究者越来越多地在做循环网络、变分自编码器这类非卷积模型，这些痛点越来越突出。

方法

按需建图。Chainer里的每个数组被包装成Variable，每个可微运算是一个Function。执行y = f(x)时，除了算出y的值，还顺手在图里记下：函数节点f引用输入x，输出y引用f。这张图只记录“如何倒推”，不负责定义前向计算。调用loss.backward()时，从loss沿引用链逆拓扑序遍历，按链式法则累积梯度（即反向模式自动微分）。

因为图只依赖程序实际执行的轨迹，前向代码可以随意使用Python控制流：

h = F.relu(self.l1(x)) for t in range(len(sentence)): h = self.rnn(h, sentence[t])

每个句子长度不同，生成的图大小也不同，梯度依然正确；任何一行都可以下断点、打印中间值。

面向对象的模型定义。模型是一个Python类，参数是成员，前向计算是一个方法，子网络可以像积木一样嵌套——论文称这种写法由Chainer在2015年首先引入，后来被PyTorch和TensorFlow Eager广泛采用。

内存管理。依靠Python的引用计数，一段计算历史不再被引用时立即释放，无需整图分析。

CuPy。最初基于PyCUDA，后来自研了接口与NumPy与SciPy高度兼容的GPU数组库CuPy，np换成cp即可在GPU上运行；CuPy后来独立成为通用项目。

后来的发展

Chainer证明了动态图在研究中的生产力优势。2017年发布的PyTorch采用同样的define-by-run自动微分和面向对象模型写法，借助Facebook的支持迅速成为研究界首选；TensorFlow 2与Eager在2019年把Eager执行设为默认。2019年12月，Preferred Networks宣布发布v7后Chainer进入维护阶段，公司研究平台逐步迁移到PyTorch。CuPy则作为独立的GPU数组库延续至今。

容易误解的地方

  • Define-by-Run不等于没有计算图：图仍然存在，只是在前向时动态生成、每次可以不同，用完即丢。
  • 动态图失去了运行前看到整张图的机会，因此天然难以做算子融合等全局优化，这是它与静态图框架长期的取舍。

局限与后续

  • 每一步运算都要经过Python解释器调度，小算子多时开销显著，也无法做跨算子的全局优化。

读懂它需要的概念

自动微分与计算图 反向传播 循环网络与隐状态 CPU、GPU与并行计算 向量、矩阵与张量

本篇术语

  • Define-and-Run / Define-by-Run　前者先定义完整计算图再运行（静态图）；后者在运行前向计算的过程中同时构建计算图（动态图），也叫eager模式。
  • CuPy　Chainer团队开发的GPU数组库，接口与NumPy几乎一致，后来独立为通用项目。

怎么学

先理解自动微分与计算图中计算图与反向遍历的关系。读KDD 2019论文第2、3节（Define-and-Run的两个问题与按需建图）。动手：用几十行Python实现一个define-by-run的标量自动微分（每个运算返回记得父节点的对象，backward按逆拓扑序走），用它在一个带if分支和for循环的函数上求导，验证梯度正确；再对比在PyTorch里写同样的代码。
