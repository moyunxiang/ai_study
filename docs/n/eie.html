EIE稀疏推理引擎

EIE: Efficient Inference Engine on Compressed Deep Neural Network
2016.02论文延伸ISCA 2016Song Han, Xingyu Liu, Huizi Mao, Jing Pu, Ardavan Pedram, Mark Horowitz, William Dally · Stanford / NVIDIA待核对
来源 ↗在交互版中打开（演化树、学习进度）

问题

剪枝与量化压缩把网络剪枝并共享权重后又小又稀疏，但CPU和GPU都不擅长稀疏矩阵运算，压缩带来的好处用不出来。

方法

EIE是专为压缩网络设计的推理加速器：权重放在片上SRAM，只存非零权重，遇到零激活就直接跳过。

影响

它说明「先压缩模型，再为稀疏结构设计硬件」是可行的，稀疏与低精度后来成为推理芯片的共同特征。

方法

论文的出发点是能耗：从DRAM取一个权重的能耗比一次ALU运算高两个数量级，占了推理功耗的大头。剪枝与量化压缩通过剪枝（去掉冗余连接）和权重共享（多个连接共用同一个值），使AlexNet、VGG这类网络能整个放进片上SRAM。

EIE在此基础上做推理引擎：把压缩后的权重矩阵按稀疏格式存储，只做非零权重与非零激活的乘加，即稀疏矩阵向量乘，并用权重共享表还原数值。ReLU会让很多激活为零，EIE遇到零激活就整列跳过。

论文给出的能效分解：从DRAM换到SRAM省120倍，利用稀疏省10倍，权重共享省8倍，跳过零激活再省3倍。在九个DNN基准上，EIE比未压缩网络的CPU和GPU实现快189倍和13倍；论文称峰值处理能力为102 GOPS/s（直接处理压缩网络），相当于未压缩网络的3 TOPS/s，处理AlexNet全连接层达每秒1.88万帧、功耗600mW，能效比CPU和GPU高24,000倍和3,400倍；相比DaDianNao吞吐、能效、面积效率分别好2.9倍、19倍、3倍。

局限与后续

  • 只针对全连接层的稀疏矩阵向量乘，卷积层和后来的Transformer并不直接适用。
    后来针对它的工作　Google TPU
  • 需要先对模型做剪枝和共享，增加训练流程；现代GPU用结构化稀疏代替了这种非结构化稀疏。
    后来针对它的工作　A100

它建立在什么之上

  • 竞争
    DianNao神经网络加速器2014.03 · 硬件
    DianNao系列处理稠密网络，EIE处理稀疏压缩网络，并与DaDianNao比较。
  • 改进
    Jetson嵌入式AI平台2014.04 · 硬件
    功耗预算只有几瓦到几十瓦，大模型无法在板上运行，需要模型压缩与量化。
  • 使用
    剪枝与量化压缩2015.10 · 系统·效率
    EIE直接以Deep Compression得到的剪枝加权重共享模型作为输入。
  • 改进
    Eyeriss数据流加速器2016.06 · 硬件
    只针对卷积层，全连接层和后来的注意力、稀疏计算不在设计之内。
