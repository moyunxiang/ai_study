键值记忆网络

Key-Value Memory Networks for Directly Reading Documents
2016.06论文延伸EMNLP 2016Alexander Miller, Adam Fisch, Jesse Dodge, Amir-Hossein Karimi, Antoine Bordes, Jason Weston · Facebook AI Research待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

问答系统为了回避直接读文档的难度，多改用知识库作答；但知识库的模式太死，许多答案放不进去，而且太稀疏，维基百科里的信息远多于Freebase。

方法

键值记忆网络：把记忆中的每一项拆成「键」和「值」两部分，寻址时用键和问题比对，读出时返回值；键和值可以用不同方式编码，例如键是一段文字窗口、值是窗口中心的实体，从而让同一个模型既能读知识库三元组，也能直接读文档。

影响

配套构建了同一电影领域里同时有原始文本、信息抽取结果和知识库的WikiMovies数据集，用来比较三种知识来源；键值分离的寻址方式后来成为记忆增强模型和检索式架构中常见的设计。

方法

端到端记忆网络把一组记忆向量存起来，用问题对它们做注意力，再把加权和读出来，同一个向量既用于寻址也用于输出。对知识库问答来说，三元组（主语，关系，宾语）里拿来和问题比对的是「主语+关系」，真正要返回的是「宾语」，两者应该分开。

键值记忆：每个记忆槽是一对(k_i, v_i)。先用问题向量q和每个键做点积再softmax得到权重p_i，读出o = Σ p_i · A·v_i，用o更新问题向量后可以再做一跳，最后和候选答案打分。不同的键值编码方式对应不同的知识来源：知识库三元组的键是主语和关系、值是宾语；文档则可以把以某个实体为中心的一段词窗作为键、中心实体作为值，或者把句子作为键、句中标题实体作为值。

为了公平比较「读知识库」「读信息抽取结果」「直接读维基百科」三种做法，作者构建了WikiMovies：电影领域的问题，配有原始维基文章、自动抽取出的知识库和人工整理的知识库。摘要称，键值记忆网络缩小了三种设定之间的差距，并在已有的WikiQA基准上取得最好结果。

本篇术语

  • 键值记忆　每个记忆项分成键和值：用键和查询比对算出权重，再用这些权重对值加权求和作为读出结果。
  • WikiMovies　本文构建的电影领域问答数据集，同时提供维基百科原文、自动抽取的知识库和人工知识库，用来比较不同知识来源。

怎么学

先读端到端记忆网络的讲解 → 读原文第3节键值寻址与读出、第4节几种键值编码 → 动手：把一个小知识库的三元组分别按「主语+关系为键、宾语为值」和「整条三元组既做键又做值」两种方式存入记忆，比较问答准确率。
