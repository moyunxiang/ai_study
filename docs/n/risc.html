RISC精简指令集

The Case for the Reduced Instruction Set Computer
1980.10论文延伸ACM SIGARCH Computer Architecture News, 1980年10月David A. Patterson, David R. Ditzel · UC Berkeley / Bell Labs待核对
维基百科 ↗在交互版中打开（演化树、学习进度）

问题

主流处理器（如VAX）的指令越来越复杂，设计和验证成本高，而编译器实际上很少用到那些复杂指令。

方法

把指令集精简到简单规整的指令：每条指令只做一件事，运算只在寄存器间进行，访存只用load和store，从而容易做流水线、提高时钟。

影响

RISC成为ARM、MIPS、RISC-V等架构的共同基础，今天手机、GPU控制核和许多AI芯片的主控核都是RISC风格。

方法

Patterson与Ditzel在1980年的《The Case for the Reduced Instruction Set Computer》里论证：与其不断增加复杂指令，不如让硬件只支持简单指令，用流水线把每一条指令的速度提上去，让编译器去组合出复杂操作。

RISC的关键概念是：每条指令只执行一个功能（如把一个值从内存复制到寄存器）；通常有16或32个高速通用寄存器；采用load–store架构，算术和判断只在寄存器上进行，只有load和store两类指令访问内存。代价是完成同样的任务可能需要更多条机器指令，但每条更快，且更容易做指令流水线。

这个思路由此催生出伯克利RISC、斯坦福MIPS，再到ARM；也是RISC-V开放指令集开放指令集的出发点。

  • 改进
    IBM System/360：兼容的计算机家族1964.04 · 硬件
    为兼容而保留的复杂指令和多种寻址方式让硬件越来越复杂，编译器又很少用到其中大部分指令。
