DeepSeek-Coder

DeepSeek-Coder: When the Large Language Model Meets Programming -- The Rise of Code Intelligence
2024.01论文延伸arXiv 2024Daya Guo, Qihao Zhu, Dejian Yang, Zhenda Xie 等 · DeepSeek-AI / 北京大学待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

开源代码模型落后于闭源的Codex和GPT-3.5，而且大多只在单个文件上训练，看不到项目里文件之间的依赖关系。

方法

从零训练1.3B到33B的代码模型，数据按项目级组织（把相互依赖的文件排在一起），并用16K窗口的填空（FIM）任务训练。

影响

成为2024年初最强的开源代码模型系列之一，采用宽松许可，可商用。

方法

训练语料共约2万亿token，按项目级整理：先解析仓库内文件之间的依赖，再把有依赖关系的文件按顺序拼进同一段上下文，让模型学会跨文件补全。训练任务除了普通的下一token预测，还有中间填充FIM（填空）：把一段代码中间挖掉，让模型根据前后文补出来，这正是编辑器里光标处补全的场景。窗口长度16K。

官方称在多个基准上达到开源代码模型的最好水平，并超过Codex和GPT-3.5这类闭源模型；模型以允许商用的许可发布。

局限与后续

  • 上下文只有16K，难以处理超大仓库；语言覆盖有限（后续版本从86种扩到338种）。
    后来针对它的工作　DeepSeek-Coder-V2
  • 只是在HumanEval类基准上评测，与真实仓库级任务仍有差距。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 使用
    中间填充FIM2022.07 · LLM
    训练中使用填空任务，使模型具备编辑器式的中间补全能力。
  • 竞争
    StarCoder2023.05 · LLM
    同为开源代码模型；DeepSeek-Coder用更大语料（2万亿token）和项目级数据组织。
  • 改进
    教科书级数据phi-12023.06 · LLM
    只会Python，缺少大模型掌握的特定API和不常用库的知识。
  • 改进
    CodeRL单元测试强化学习2022.07 · LLM
    模型规模较小（基于CodeT5），绝对水平仍远低于后来的大规模代码模型。
  • 改进
    CodeT5+2023.05 · LLM
    编码器-解码器结构在长上下文、大规模生成和对话式交互上不如纯解码器方便，之后的主流开源代码模型基本都转向纯解码器路线。
  • 使用
    DeepSeek LLM2024.01 · LLM
    沿用DeepSeek LLM的架构与训练基础设施。

后来的相关工作

  • 延续

读懂它需要的概念

语言模型 自回归生成 上下文窗口 预训练与微调

怎么学

先理解中间填充FIM的数据变换（前缀-后缀-中间的重排）；读原文数据处理一节；动手：写一个把代码片段改写成FIM训练样本的函数。
