香农：计算机下棋

Programming a Computer for Playing Chess
1950论文重要Philosophical Magazine 1950Claude E. Shannon · 贝尔实验室待核对
论文PDF（计算机历史博物馆） ↗Wikipedia：Shannon number ↗在交互版中打开（演化树、学习进度）

问题

下棋被看作智力的试金石，但棋局的可能变化多到无法穷举，没人知道该怎样让一台通用计算机下出像样的棋。

方法

用一个给局面打分的近似评估函数，加上有限深度的极小极大搜索：只往前看几步，在搜索树的叶子上打分，再把分数按“我取最大、对手取最小”倒推回来选着法。

影响

确立了此后近七十年棋类程序的基本框架：评估函数加博弈树搜索；它提出的全宽与选择性两种搜索路线一直延续到深蓝和AlphaGo。

背景

1949年前后通用电子计算机刚出现。国际象棋规则明确、胜负清楚，又公认需要智力，是理想的试验场。

理论上棋可以“解”：《博弈论与经济行为》与极小极大已经说明，从终局倒推，每个局面都有确定的胜、和、负。问题在于规模。香农引用De Groot对大师对局的统计：一个典型局面约有30种合法着法，白黑各走一步约有10³种组合，一局约40个回合，于是从开局要算的变化约10¹²⁰种（后来称为Shannon数）；按每微秒算一个变化，第一步就要算10⁹⁰年以上。另一条路——把所有局面和正确着法存成一本“字典”——局面数约10⁴³，同样不可能。所以问题不是下出完美的棋，而是下出“像好棋手那样”的棋。

方法

近似评估函数。精确评估只有胜、和、负三个值，算不出来；香农改用一个连续打分f(P)，把棋手的经验写成加权和。他给的示例是：

f(P) = 200(K−K′) + 9(Q−Q′) + 5(R−R′) + 3(B−B′+N−N′) + (P−P′) − 0.5(D−D′+S−S′+I−I′) + 0.1(M−M′)

其中Q、R、B、N、P是后、车、象、马、兵的数目，D、S、I是叠兵、落后兵、孤兵，M是机动性（合法着法数），带撇号的是黑方。王给200分，相当于把将死人为编码成压倒一切的大数。

有限深度的极小极大（见博弈树搜索：minimax与MCTS）。从当前局面展开所有着法，对手的所有应着……到固定深度后用f(P)打分；轮到自己的层取最大值，轮到对手的层取最小值，逐层倒推到根，选分数最高的着法。这就是Type A策略：全宽、固定深度。

Type B策略。香农算了一笔账：Type A看三个回合（双方各三步）约要10⁹次评估，即使每次一微秒，一步棋也要16分钟以上，而且只看三步、在吃子进行到一半时就打分，会严重误判。他提出两点改进：只在“静止”局面（没有子被攻击、没有将军）才打分，有威胁就继续往下算；用规则挑出值得算的少数变化，而不是全部展开——就像De Groot实验里大师只考察了十几条变化、共44个局面。

结果

论文没有可运行的程序，只给出局面编码和由九个子程序组成的Type A程序结构。香农明确写道，机器的主要弱点是不会从错误中学习；他设想过按对局结果自动调整评估系数，但认为还不实用。

后来的发展

评估函数加博弈树搜索成为棋类AI的标准结构。Samuel跳棋程序把香农设想的“自动调系数”做了出来；Alpha-Beta剪枝分析在不改变结果的前提下大幅剪掉搜索树；深蓝战胜卡斯帕罗夫用专用芯片把全宽深搜推到硬件极限。选择性搜索这条路后来由蒙特卡洛树搜索UCT用随机模拟和统计方法重新实现，AlphaGo再用神经网络代替手写的评估函数和着法筛选。

容易误解的地方

  • 常被引用的10¹²⁰是对“对局变化数”的粗略下界估计，不是局面数；香农自己估计的局面数是约10⁴³。
  • 论文的评估函数系数只是示意，香农明确说0.5、0.1只是他的粗略猜测。

局限与后续

  • 评估函数的项和系数全靠人手写，机器不会从对局中改进自己，香农本人也承认这是主要弱点。

  • 全宽固定深度搜索随深度指数增长：看三个回合就要约10⁹次评估，一步棋需十几分钟。

读懂它需要的概念

博弈树搜索：minimax与MCTS 图、树与搜索 时间与空间复杂度 博弈论基础与纳什均衡

本篇术语

  • 评估函数　给一个局面打分的函数，分数越高表示对己方越有利。精确的评估只有胜、和、负三种值，实际程序用经验规则拼出一个近似分数。
  • 静止局面　没有子正在被吃、没有将军的相对平稳局面。在吃子交换做到一半时打分会严重误判，所以要算到静止局面再评估。
  • Type A / Type B策略　香农的分类：A是所有着法都展开到固定深度的全宽搜索；B是只挑少数有希望的变化往深处算的选择性搜索。

怎么学

先理解博弈树搜索：minimax与MCTS里的极小极大倒推。然后读原文第2–3节（Shannon数与评估函数）和第6节（Type B）。动手：给井字棋写一个极小极大程序，再给一个简化棋类写一个手工评估函数并限制搜索深度，观察深度从1增到4时棋力和耗时的变化。
