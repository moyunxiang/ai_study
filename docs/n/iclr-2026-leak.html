ICLR 2026审稿身份泄露

ICLR 2026 Response to Security Incident
2025.11事件延伸ICLR 2026程序委员会、OpenReview · ICLR官方博客待核对
ICLR 2026 Response to Security Incident（2025-12-03） ↗A Retrospective on the ICLR 2026 Review Process（2026-03-31） ↗OpenReview：Statement Regarding API Security Incident ↗在交互版中打开（演化树、学习进度）

问题

AI顶会投稿量逐年暴涨，ICLR 2026有近两万篇有效投稿，评审高度依赖OpenReview平台的双盲匿名；一旦匿名失效，审稿人可能被施压、收买或骚扰。

方法

2025年11月，OpenReview的一个API漏洞让作者、审稿人和领域主席的匿名身份可被批量查询，约一万篇ICLR投稿的身份信息被抓取并在网上流传，ICLR随即冻结讨论、回滚分数、给所有论文换领域主席。

影响

这是机器学习顶会历史上规模最大的匿名评审泄露，也把投稿爆炸、低质量审稿、LLM代写审稿等积累已久的“审稿危机”推到台前。

方法

据ICLR 2025年12月3日的公告：组委会于11月27日接到漏洞报告，OpenReview当天上午修复；漏洞可能早在11月11日就被利用。有人抓取了超过一万篇ICLR论文（约占45%）的作者、审稿人等信息并在网上传播；另有恶意评论者在600篇论文下公开留言指认审稿人。公告还称出现了作者与审稿人串通的企图，以及第三方骚扰、恐吓和向审稿人行贿。

处置措施：冻结审稿表单和公开评论，冻结审稿讨论；把审稿意见和分数回滚到讨论期开始前的状态；为每篇论文重新指派领域主席，让外人不知道该向谁施压；元评审期延长到2026年1月6日。传播数据者被OpenReview和ICLR封禁，企图串通的作者或审稿人的论文直接拒稿。

2026年3月的复盘给出全年数字：19525篇有效投稿，76139份审稿来自18054名审稿人，接收5355篇，接收率27.4%。同一届还用两种检测器筛查完全由LLM生成的审稿，并对确认含有幻觉参考文献的投稿直接拒稿。

局限与后续

  • 回滚分数和更换领域主席只能限制泄露后的施压，已经公开的身份信息无法撤回，被指认的审稿人仍可能遭到报复。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 漏洞之外的结构性问题——投稿量过大、审稿人负担过重、LLM代写审稿难以可靠检测——这次处置并没有解决。
    本站还没有记录针对它的后续工作（不代表没有人解决）
