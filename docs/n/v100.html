V100与Tensor Core

2017.05硬件重要GTC 2017（2017年5月10日发布）NVIDIA待核对
NVIDIA新闻稿：Volta发布 ↗维基百科：Volta架构 ↗Inside Volta（NVIDIA技术博客） ↗在交互版中打开（演化树、学习进度）

问题

GPU的通用CUDA核心一次只做一个标量乘加，而深度学习几乎全是矩阵乘法；谷歌TPU已经证明专用矩阵单元能效高得多，GPU面临被专用芯片取代的压力。

方法

在GPU里加入专做小矩阵乘加的Tensor Core：每个单元一次完成4×4矩阵的D = A×B + C，FP16输入、FP32累加。V100集成640个，官方称深度学习算力120 TFLOPS。

影响

GPU从此变成“通用核心+矩阵加速单元”的混合体，此后每一代NVIDIA GPU都在扩充Tensor Core。V100成为2018–2020年训练大模型的主力，GPT-3就是在V100集群上训练的。

背景

2016年的Tesla P100与DGX-1用的是Pascal架构的P100。它的计算单元是数千个CUDA核心，每个核心每拍做一次浮点乘加（FMA）。这对图形和科学计算很灵活，但深度学习的主要负载是大矩阵乘法（见矩阵乘法与线性变换），用标量单元去拼，大量能耗花在取指令、搬寄存器上，而不是乘法本身。

同一时期，谷歌公开了Google TPU：一块只做矩阵乘的芯片，能效比K80 GPU高几十倍。如果GPU不改，在数据中心AI这块最赚钱的市场上就可能输给专用芯片。

方法

Tensor Core。每个Tensor Core每拍完成一次D = A×B + C，其中A、B是4×4的FP16矩阵，C、D可以是FP16或FP32。一次就是64个乘加，乘法用FP16（面积小、速度快），累加用FP32（避免很多小数相加时丢精度，见浮点精度：FP32、FP16、BF16、INT8）。程序员不直接写4×4，而是通过CUDA 9的warp级矩阵接口或cuDNN、cuBLAS库调用，库会把大矩阵乘切成小块喂给Tensor Core。

可以把它看作把脉动阵列的思路缩小成很多个小块，嵌进GPU的每个流处理器里，同时保留原来的CUDA核心继续跑非矩阵计算。

其他规格（据新闻稿与维基百科）：台积电12nm FinFET工艺，约211亿个晶体管，芯片面积815mm²；640个Tensor Core；HBM2显存，带宽900GB/s（比上一代高50%，见HBM高带宽内存）；第二代NVLink与NVSwitch，GPU之间的带宽是上一代的2倍。

结果

NVIDIA官方称：V100深度学习算力120 TFLOPS，峰值算力是Pascal的5倍、Maxwell的15倍。

实际影响体现在之后几年的训练记录里：同年的混合精度训练训练方法就是围绕Tensor Core设计的——FP16存储和计算、FP32保留一份权重主副本并做累加、配合损失缩放；论文称这几乎把训练显存需求减半。美国橡树岭的Summit超算超算装了V100；GPT-3论文写明模型在微软提供的高带宽集群上用V100训练（见微软为OpenAI建的超算）。

后来的发展

Tensor Core成为NVIDIA GPU的核心卖点：2018年的Turing：消费级Tensor Core把它带进消费级显卡，A100加入TF32、BF16和结构化稀疏，H100加入FP8，Blackwell与整机柜液冷加入FP4。GPU与TPU这类专用芯片的路线差别因此缩小，NVIDIA靠“兼容CUDA生态+专用矩阵单元”守住了训练市场。

容易误解的地方

  • “120 TFLOPS”只指Tensor Core做FP16矩阵乘的峰值；普通FP32运算的峰值只有十几TFLOPS。不用混合精度、不走Tensor Core的代码拿不到这个数。
  • FP16的数值范围很窄，小梯度会下溢成0，所以用V100训练时必须配合损失缩放；后来的BF16才缓解这个问题。

局限与后续

  • Tensor Core只支持FP16输入，数值范围窄，训练要依赖损失缩放等技巧防止梯度下溢。

它建立在什么之上

  • 使用
    CUDA2006.11 · 硬件
    Tensor Core通过CUDA 9的新接口暴露给程序员，老代码换上新库即可受益。
  • 竞争
    Google TPU2016.05 · 硬件
    TPU用整颗芯片做一个大脉动阵列；V100保留通用GPU，只在其中嵌入大量小矩阵单元，以兼容CUDA生态换取灵活性。
  • 改进
    脉动阵列1982.01 · 硬件
    阵列针对某一类规则计算硬连线，灵活性差；遇到不规则、数据依赖的计算或不同形状的矩阵，利用率会大幅下降。
  • 改进
    GeForce 8800/G802006.11 · 硬件
    只有通用的标量乘加单元，没有专门做矩阵乘法的硬件，神经网络的主要运算无法再提速一个量级。
  • 改进
    GTX 580：AlexNet的显卡2010.11 · 硬件
    只有通用的FP32运算单元，没有低精度矩阵乘硬件，神经网络无法利用半精度再提速。
  • 使用
    HBM高带宽内存2013 · 硬件
    用HBM2提供900GB/s带宽，喂饱大幅增加的算力。
  • 使用
    NVLink与NVSwitch2014.03 · 硬件
    第二代NVLink把GPU间带宽提高到上一代的2倍。
  • 改进
    Kepler：K20/K40/K802012.11 · 硬件
    训练用单精度，没有为低精度矩阵乘法设计的专用单元。
  • 改进
    Xeon Phi众核：弃用路线2012.11 · 硬件
    缺少面向深度学习的软件生态和低精度矩阵单元，被GPU与专用加速器抛在后面。
  • 使用
    cuDNN2014.09 · 硬件
    cuDNN和cuBLAS把卷积、矩阵乘自动映射到Tensor Core上。
  • 延续
    Tesla P100与DGX-12016.04 · 硬件
    接替P100成为DGX整机里的GPU，延续8卡NVLink互连的整机形态。

读懂它需要的概念

CPU、GPU与并行计算 矩阵乘法与线性变换 浮点精度：FP32、FP16、BF16、INT8 显存、内存带宽与“内存墙” 参数量、计算量与显存

本篇术语

  • Tensor Core　NVIDIA GPU里专做小矩阵乘加的硬件单元。V100中每个单元一次做4×4矩阵乘加，后续代际扩大了尺寸并增加了精度格式。
  • FMA（融合乘加）　一次完成a×b+c并只舍入一次的运算，是浮点矩阵乘法的基本操作。

怎么学

先补浮点精度：FP32、FP16、BF16、INT8，搞清FP16和FP32的范围与精度差别。然后读NVIDIA技术博客Inside Volta中的Tensor Core一节，再读混合精度训练论文第3节，理解为什么需要FP32累加和损失缩放。动手：在任意GPU上用PyTorch分别以FP32和FP16跑同一个大矩阵乘，比较速度与结果误差。
