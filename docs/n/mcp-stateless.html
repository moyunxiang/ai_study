MCP 2026-07-28规范

The 2026-07-28 Specification
2026.07系统延伸MCP 维护者 · Agentic AI Foundation待核对
MCP官方博客 ↗在交互版中打开（演化树、学习进度）

问题

MCP的连接是有状态的双向会话，服务器必须记住每个连接，难以放在负载均衡器后面水平扩展，网关也读不出请求要做什么。

方法

把协议核心改成无状态的请求-响应：每个请求自带全部所需信息，方法名与工具名放进HTTP头，服务器到客户端的请求改成多轮往返请求。

影响

让MCP服务器能像普通Web服务一样随意扩缩容，并正式确立扩展框架与更严的授权。

方法

MCP在2026年7月28日发布新规范。官方博客称，自上一次11月发布以来，MCP继续高速增长：各一级SDK每月下载接近5亿次，TypeScript与Python SDK的累计下载都超过10亿次。

这一版的重点是无状态协议核心：取消initialize/initialized握手和Mcp-Session-Id头，每个请求自描述，因此可以落到round-robin负载均衡之后的任何实例；方法名与工具名通过Mcp-Method、Mcp-Name两个HTTP头传递，网关可以直接据此路由和授权；采样、请求用户输入等服务器到客户端的请求改成多轮往返请求（MRTR），不再需要一直开着的双向流。

其他改动还有：列表结果带缓存提示和确定性顺序；正式的扩展框架（Tasks加入，另有MCP Apps和企业托管授权）；授权加固（校验RFC 9207的签发者，并从动态客户端注册转向客户端元数据文档）；以及至少12个月的弃用窗口。

局限与后续

  • 取消会话后，需要多步状态的场景要靠显式的任务或扩展来表达，开发者需要迁移。
