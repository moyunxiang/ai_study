LongBench: A Bilingual, Multitask Benchmark for Long Context Understanding
2023.08数据集延伸ACL 2024Yushi Bai, Xin Lv, Jiajie Zhang, Hongchang Lyu, Jiankai Tang, Zhidian Huang, Zhengxiao Du, Xiao Liu et al. · 清华大学 / 智谱AI / 中国科学院自动化研究所待核对
arXiv ↗代码与数据（GitHub） ↗LongBench v2（arXiv） ↗在交互版中打开（演化树、学习进度）

问题

2023年各种方法把上下文窗口拉长到数万token，但缺少一个覆盖真实长文本任务、中英双语、能自动评分的综合基准来比较它们。

方法

把21个数据集整理成统一格式，覆盖单文档问答、多文档问答、摘要、少样本学习、合成任务和代码补全6类，英文平均6,711词、中文平均13,386字。

影响

被长上下文研究大量引用（OpenAlex记录被引2千余次）；2024年12月的v2改为503道人工编写的长文多选难题，人类专家限时15分钟只有53.7%。

方法

v1。21个数据集分属6类任务：单文档问答、多文档问答、摘要、少样本学习（示例放在长上下文里）、合成任务（如段落计数、段落检索）和代码补全，其中有中文任务，共4,750条测试样本。所有数据统一成“指令、长上下文、问题、答案”的格式，按各任务的指标自动打分。

模型窗口不够时，从中间截断，保留开头和结尾，因为指令和问题常在两端。作者还构建了长度分布更均匀的LongBench-E，按0–4k、4k–8k、8k以上分档，用来单独观察长度增加带来的性能下降。

v2。503道四选一题，上下文从8千词到200万词，由近百位不同专业背景的人编写，覆盖单文档、多文档、长上下文学习、长对话历史、代码仓库和长结构化数据理解六类，经自动和人工两轮审核保证难度。

结果

v1评测了8个模型，GPT-3.5-Turbo-16k整体最好但在更长的输入上仍吃力；扩展位置编码并在长序列上微调带来明显提升；检索等上下文压缩对长上下文能力弱的模型有帮助，但仍不及本身长上下文能力强的模型。在LongBench-E上，即使训练或微调过长上下文的模型，随长度增加也明显下降。

v2中，直接作答的最好模型只有50.1%，带长推理的o1-preview达到57.7%，比人类专家的53.7%高4个百分点。

后来的发展

LongBench与同期的大海捞针测试、RULER长上下文构成了长上下文评测的几条路线：前者用真实任务，后两者用可任意控制长度的合成探针。v2把重点从“能不能读完”转向“读完后能不能推理”，并显示测试时多花计算能提升长文表现。

局限与后续

  • v1多数样本只有数千到一两万词，对后来十万乃至百万token的窗口区分度不足，也无法精确控制长度来测“到多长开始失效”。

  • 使用
    位置插值扩上下文2023.06 · LLM
    被测模型中有通过扩展位置编码延长窗口的版本，作者发现这类方法加长序列微调能明显提升长文理解。
  • 使用
    Llama 22023.07 · LLM
    Llama2-7B-chat-4k是被测的8个模型之一，作为窗口较短的对照。
  • 改进
    LRA长序列基准2020.11 · 数据·评测
    任务多为合成或刻意拉长的序列，与真实长文档、长对话的语言建模能力相关性有限；后来大模型的长上下文评测转向了检索和问答。

读懂它需要的概念

上下文窗口 位置编码 基准、排行榜与SOTA 文本生成的自动指标 检索与向量数据库

本篇术语

  • LongBench-E　从LongBench部分任务中按0–4k、4k–8k、8k+三档均匀抽样得到的子集，用来看同一模型在不同长度下的表现变化。
  • LongBench v2　2024年12月发布的新版：503道人工编写的长上下文四选一题，上下文8千到200万词，强调理解后的推理。
  • 中间截断　输入超过窗口时只保留前一半和后一半、丢掉中间，因为任务指令和问题通常在开头或结尾。

怎么学

先读上下文窗口和位置编码。读v1原文第3节的任务构成和表1，再看v2摘要。动手：挑一个开源长上下文模型，在LongBench-E的同一任务上分别跑0–4k和8k+两档，比较分数下降了多少。
