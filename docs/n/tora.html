ToRA工具集成推理

ToRA: A Tool-Integrated Reasoning Agent for Mathematical Problem Solving
2023.09论文延伸ICLR 2024Zhibin Gou, Zhihong Shao, Yeyun Gong, Yelong Shen, Yujiu Yang, Minlie Huang, Nan Duan, Weizhu Chen · 清华大学 / 微软待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

数学题有两种做法：思维链用自然语言推理，善于分析却常算错；PAL式方法直接写程序交给解释器，算得准却不擅长需要分析的步骤。2023年开源模型在竞赛级MATH上还普遍远低于50%。

方法

把两者交错起来：模型先用自然语言分析，需要解方程、做符号运算时写一段Python代码调用SymPy等库，拿到执行结果再继续推理，可多轮往返。用GPT-4合成这类“推理—代码—结果”交错的轨迹来训练开源模型，再用“输出空间塑形”扩充有效轨迹。

影响

ToRA-7B在MATH上比当时最好的开源模型WizardMath-70B高22个百分点，ToRA-Code-34B以50.8%成为首个在MATH上超过50%的开源模型（论文原话）；“工具集成推理（TIR）”格式此后被DeepSeekMath、Qwen-Math等数学模型直接采用。

背景

思维链CoT用文字推理，PAL/PoT程序辅助推理和Faithful CoT忠实思维链把题目整个转成程序交给求解器。前者计算不可靠，后者在需要先理解题意、分类讨论的题上吃力，而且一次性写完的程序无法根据中间结果调整思路。同期GPT-4的代码解释器展示了“边想边算”的威力，但开源模型没有这种能力。

方法

推理格式：给定题目q，模型生成一段推理 r₁；到了适合用工具的地方，写出程序 a₁（例如用SymPy解方程）；环境执行得到输出 o₁；模型把 o₁ 放进上下文继续写推理 r₂……如此最多3轮，最后给出答案。

第一步：模仿学习。对GSM8K和MATH训练集，用GPT-4按这种格式贪心生成轨迹，只保留答案正确的；做错的题再用核采样多试10次，每题最多保留4条正确轨迹。最终为98.2%的GSM8K题和83.1%的MATH题拿到了轨迹，过滤掉工具出错的之后得到1.6万条，称为ToRA-Corpus，用它微调LLaMA-2和CodeLLaMA系列。

第二步：输出空间塑形。只模仿GPT-4的一条轨迹会让模型的解法单一。于是让微调后的模型对每题采样多条轨迹：正确的直接保留；错误的，从出错处截断，交给一个更强的教师模型（在ToRA-Corpus上训练的CodeLLaMA-34B）续写修正。共得到23.3万条有效样本和6.9万条修正样本，与原语料合并后重新训练。

结果：7B到70B的模型在10个数学数据集上平均比同规模开源模型高13%到19%。ToRA-7B在MATH上为44.6%；ToRA-Code-34B为50.8%，高于GPT-4思维链的42.5%，接近GPT-4用代码解题的51.8%。

后来的发展

TIR格式与“模型推理、解释器计算”的分工成为数学大模型的标配，后来的ReTool工具强化学习、rStar2-Agent智能体RL则把同样的交互格式放进强化学习，让模型自己学会何时调用代码。

读懂它需要的概念

工具调用 预训练与微调 模仿学习与行为克隆 语言模型 解码：贪心、束搜索、温度与top-p

本篇术语

  • 工具集成推理（TIR）　在一段推理里交替出现自然语言分析、代码和代码执行结果的格式。
  • 输出空间塑形　用模型自己采样出的多种正确解法，加上教师修正过的错误解法，扩充训练数据，让模型掌握更多样的合理解题路径。
