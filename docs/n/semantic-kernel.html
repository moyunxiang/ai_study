Semantic Kernel

2023.02系统延伸Microsoft待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

企业开发者大多用C#、Java这类语言写业务系统，而早期LLM应用框架几乎都是Python的；要把大模型接进现有企业应用，缺一套面向工程团队的SDK。

方法

微软开源一个与模型无关的SDK，把提示模板和普通代码函数都包装成可供模型调用的“插件”，再配上记忆、规划和多智能体编排，同时提供.NET、Python、Java三种语言版本。

影响

成为微软生态中构建Copilot类应用的主要SDK之一；2025年后演进为企业级的Microsoft Agent Framework，README称后者是它的继任者。

方法

Semantic Kernel的GitHub仓库创建于2023-02，正值ChatGPT引发企业接入大模型的热潮。它的核心概念是：

  • 内核（Kernel）：统一管理模型连接、服务和插件的容器；
  • 插件（Plugins）：一组可以被模型调用的函数，可以是普通代码函数、提示模板，也可以从OpenAPI规范或模型上下文协议MCP服务器导入。模型据此选择调用哪个插件（函数调用接口成熟后即通过它完成）；
  • 规划与智能体：早期提供“规划器”让模型把目标拆成调用插件的步骤，后来随着函数调用成熟，改为以智能体为中心，支持多个专门智能体协作的编排；
  • 记忆与向量库：对接Azure AI Search、Elasticsearch、Chroma等向量数据库，实现检索增强。

与LangChain相比，它更强调企业工程实践：强类型、依赖注入、可观测性，以及与Azure OpenAI等服务的集成；也支持OpenAI、Hugging Face以及Ollama等本地模型。README现在说明，Semantic Kernel已演进为Microsoft Agent Framework（MAF），后者是面向企业的继任框架。

局限与后续

  • 早期的规划器让模型一次性生成整套调用计划，执行中出错难以纠正，后来被基于函数调用的智能体循环取代。

    ReAct2022.10 · 推理·智能体

  • 使用
    ChatGPT发布2022.11 · LLM
    诞生于ChatGPT引发的企业接入热潮，最初主要对接OpenAI与Azure OpenAI的对话模型。
  • 延续
    MRKL系统2022.05 · 推理·智能体
    MRKL提出由语言模型把请求路由给外部模块，Semantic Kernel把这些模块做成统一注册的插件。
  • 竞争
    LangChain2022.10 · 推理·智能体
    同期出现的LLM应用框架，LangChain以Python社区为主，Semantic Kernel面向.NET/Java企业开发者。

读懂它需要的概念

工具调用 智能体循环 检索与向量数据库

怎么学

先读MRKL系统和函数调用成为标准接口 → 读Semantic Kernel文档中插件与智能体两节 → 动手：把一个普通函数注册成插件，让模型根据用户问题决定是否调用它。
