Claude Code与终端编码智能体

Claude 3.7 Sonnet and Claude Code
2025.02系统主干Anthropic来源已核对
官方公告 ↗How Claude Code works（官方文档） ↗Claude 4发布与正式上线 ↗在交互版中打开（演化树、学习进度）

问题

AI编程助手大多停留在“补全下一行”或“在聊天框里给一段代码”，读代码、改多个文件、跑测试、看报错、再改这些步骤仍由人来串起来。

方法

把模型直接放进开发者的终端：给它读写文件、搜索代码、执行任意shell命令和git的工具，让它在“收集信息—动手修改—运行验证”的循环里自主推进，人只在需要时插话或批准。

影响

之后OpenAI、Google相继推出同类终端编码工具；Anthropic在2025年9月称，Claude Code自5月全面上线以来年化收入已超过5亿美元。Anthropic之后又推出了Agent SDK、Skills等配套的智能体工具。

背景

AI编程工具在2025年前大致有三代。GitHub Copilot做行内补全，人写一半它补一半；Cursor AI编辑器把聊天和多文件编辑放进IDE，但每一步仍由人发起和确认；Aider较早在终端里让GPT-4直接编辑git仓库，但主要是“人提需求—模型改文件—人检查”的结对模式。

研究界已经证明“智能体”式做法更强。SWE-agent在2024年提出，模型的成绩很大程度取决于给它的“智能体—计算机接口”：合适的查看、搜索、编辑命令能让同一个模型在SWE-bench上的解决率显著提高。另一条路线Agentless则认为固定流程（定位—修复—验证）比让模型自由行动更可靠。商业上，Devin在2024年3月以“AI软件工程师”为卖点，跑在云端沙箱里，但真实效果争议很大。

同一时期模型本身的编码能力也在提升：据Anthropic公告，2024年10月升级的Claude 3.5 Sonnet在SWE-bench Verified上从33.4%升到49.0%。

方法

2025年2月24日，Anthropic随Claude 3.7 Sonnet混合推理以“有限研究预览”发布Claude Code，一个用于智能体式编程的命令行工具。官方描述它能搜索和阅读代码、编辑文件、编写并运行测试、提交并推送到GitHub、使用命令行工具，并“让你始终留在循环里”。

核心是一个智能体循环。官方文档把它分成三个交织的阶段：收集上下文、采取行动、验证结果。比如用户说“修好失败的测试”，Claude可能会：运行测试套件 → 读报错 → 搜索相关源文件 → 阅读它们 → 编辑修复 → 再跑一次测试确认。每次工具调用的结果都回到模型的上下文里，决定下一步。

工具就是开发者自己的工具。内置工具分为文件操作、搜索（按文件名模式查找、正则搜索内容）、执行（任意shell命令、启动服务、跑测试、用git）、联网和代码智能几类。除了内置的读写、搜索工具，官方文档写明模型能在终端里执行开发者能执行的任何命令（构建工具、git、包管理器、脚本），而不像SWE-agent那样主要依靠一套专门设计的命令。

项目记忆与扩展：

  • CLAUDE.md：放在仓库里的Markdown文件，写项目约定、构建命令等模型从代码里看不出的信息，每次会话自动读入；
  • 模型上下文协议MCP：通过MCP服务器接入数据库、浏览器、issue系统等外部工具；
  • 子智能体：把独立的子任务交给另一个上下文去做，避免主对话被细节塞满；
  • hooks与权限规则：由程序而不是模型强制执行的规则，例如禁止编辑某个目录、每次改完自动跑格式化。

人在回路。发布公告称它让开发者“在每一步都留在循环里”。截至2026年的官方文档提供几种权限模式：每次编辑文件和执行命令前询问、自动接受文件编辑、只做计划不改代码，以及由分类器在后台拦截高风险操作的“自动”模式（较新版本的交互会话默认从这一模式开始）。用户也可以随时打断、纠正方向。

结果

官方称早期测试中，Claude Code能一次完成通常需要45分钟以上人工的任务。同期公布的Claude 3.7 Sonnet在SWE-bench Verified（489题子集）上，不加额外脚手架时为63.7%；多次并行采样、丢弃破坏可见回归测试的补丁、再用打分模型挑选时为70.3%。

2025年5月22日随Claude 4正式上线，增加了通过GitHub Actions运行后台任务，以及VS Code、JetBrains集成。Anthropic在2025年9月的融资公告中称，Claude Code自5月全面上线以来年化收入已超过5亿美元，使用量三个月增长10倍以上。

后来的发展

之后“终端里的自主编码智能体”出现了多家同类产品：2025年4月OpenAI发布开源的Codex CLI，6月Google发布Gemini CLI；Terminal-Bench专门评测模型在终端里完成任务的能力。它的内部循环被抽出来做成Claude Agent SDK，供开发者构建其他领域的智能体；Agent Skills把“按需加载的说明和脚本”做成标准；AGENTS.md则是业界对CLAUDE.md这类项目说明文件的统一尝试。

使用方式也随之演化：Vibe Coding描述了只靠自然语言驱动编程的风气，Ralph循环让智能体在循环中无人值守地反复工作，长时程智能体harness总结了让智能体连续工作数小时的工程方法，并行智能体团队让多个实例并行协作。2026年的Claude Cowork把同一套智能体带给不写代码的用户，OpenClaw个人智能体等个人智能体也建立在类似的架构上。

容易误解的地方

  • Claude Code不是一个专门训练的模型，而是包在Claude模型外面的“harness”（外壳）：提供工具、管理上下文、处理权限。能力的大头来自模型，外壳决定了这些能力能否稳定发挥。
  • 它默认在本地运行、直接操作你的文件系统和shell，这与Devin、云端异步编码智能体在云端沙箱运行的设计不同（截至2026年的官方文档也提供了云端运行环境），好处是能用你的真实环境，代价是需要权限控制。
  • SWE-bench分数衡量的是模型加脚手架的整体，不同厂商的脚手架差别很大，分数不能直接横比。

局限与后续

  • 长任务会把上下文窗口塞满，早期内容被挤出或压缩后，智能体容易忘记目标、重复劳动。

读懂它需要的概念

智能体循环 工具调用 上下文窗口 推理token与测试时计算 提示注入

本篇术语

  • harness（智能体外壳）　包在模型外面的那层程序：提供工具、把工具结果放回上下文、管理权限和上下文长度。同一个模型换不同的harness，表现可以差很多。
  • CLAUDE.md　放在项目里的说明文件，写构建命令、代码约定等，Claude Code每次会话开始时自动读入，相当于项目的长期记忆。
  • 子智能体　主智能体把一个独立子任务交给另一个拥有独立上下文的智能体实例完成，只收回结果，避免主上下文被搜索细节占满。
  • hooks　在特定事件（如编辑文件后、结束前）自动运行的脚本，由程序强制执行，不依赖模型是否记得遵守。

怎么学

先读SWE-agent，理解为什么工具接口设计决定智能体表现；再读官方文档How Claude Code works和Best practices两页。动手：在一个有测试的小项目里让编码智能体修一个故意埋下的bug，观察它的每一步工具调用；再写一份CLAUDE.md和一个hook，对比前后表现。最后读长时程智能体harness，了解长时间运行时的上下文管理。
