Open Interpreter本地代码智能体

2023.08系统延伸Killian Lucas 等 · Open Interpreter（开源社区）待核对
GitHub ↗官网 ↗在交互版中打开（演化树、学习进度）

问题

2023年ChatGPT的Code Interpreter能写代码并在沙箱里运行，但只能在OpenAI的云端环境里用：不能访问本机文件和软件、有运行时长和文件大小限制，也不能换成本地或开源模型。

方法

做一个开源的命令行工具，让任意大模型在用户自己的电脑上写代码、执行、看结果、再改，像本地版的Code Interpreter一样操作文件、浏览器和各种程序，每次执行前请用户确认。

影响

成为2023年最受关注的开源智能体项目之一（GitHub星标约7万），把“本地运行的代码执行智能体”这一形态带给普通用户，是后来终端编码智能体的先声之一；项目后来转向成为面向低成本模型的编码智能体。

方法

Open Interpreter的GitHub仓库创建于2023-07，2023年8月以“在终端里运行CodeLlama并执行代码”在Hacker News发布，11月又以“在你的终端里本地运行OpenAI的Code Interpreter”再次引发关注。早期的工作方式：

  • 用户在终端里输入interpreter，用自然语言描述任务（比如“把这个文件夹里的图片都转成黑白并压缩”）；
  • 模型生成Python、Shell、JavaScript等代码，工具在本机执行，把输出返回给模型，模型据此继续写下一段代码或修正错误——这就是智能体循环，与CodeAct代码即行动“用代码当行动”的思路相同；
  • 默认每段代码执行前都请用户确认；模型可以接OpenAI等API，也可以接本地运行的开源模型（如Code Llama）。

与ChatGPT插件里的云端代码解释器相比，它最大的区别是能直接操作用户的真实环境，没有文件和时长限制，但安全风险也随之由用户承担。按现在的README，项目已改为基于OpenAI Codex的分支，专注于为低成本模型模拟最合适的智能体外壳（可切换成模仿Claude Code、Kimi Code等的harness）。

局限与后续

  • 直接在用户真实环境中执行模型生成的代码，一旦用户跳过确认，误删文件、泄露数据的风险很高。
