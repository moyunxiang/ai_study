EAGLE-3推测解码

EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test
2025.03论文延伸NeurIPS 2025Yuhui Li, Fangyun Wei, Chao Zhang, Hongyang Zhang · 北京大学, 微软研究院, 滑铁卢大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

EAGLE类草稿器给它喂再多训练数据也涨得很少，原因是它被要求先预测目标模型的顶层特征，这个约束卡住了上限。

方法

去掉特征预测，改为直接预测token；输入改用目标模型低、中、高多层特征的融合，并在训练时模拟多步草稿（训练时测试）。

影响

加速比随训练数据增加而继续上升，SGLang、vLLM等引擎都支持加载EAGLE-3草稿器。

方法

推测解码的速度取决于草稿器每轮能被目标模型接受几个词。EAGLE特征级推测解码的草稿器读目标模型顶层特征，先预测下一位置的特征，再转成词；作者发现这一特征预测损失限制了草稿器的表达力，扩大数据后收益很小。

EAGLE-3做了两处改动。一是放弃特征预测，草稿器直接以预测token为目标。二是输入不再只用顶层特征，而是把目标模型低层、中层、高层的特征拼接融合。问题在于：推理时草稿器第二步以后读到的是自己上一步的输出，而不是目标模型的真实特征，训练与测试不一致。为此作者在训练中就让草稿器把自己的输出接回来连续预测多步，称为“训练时测试”（training-time test），让训练条件贴近实际草稿过程。

结果

论文称在对话模型与推理模型、五类任务上加速比最高6.5倍，比EAGLE-2约高1.4倍；在SGLang中批大小64时吞吐提升1.38倍。

后来的发展

EAGLE-3之后，为每个开源模型训练一个专门草稿器成为常规操作；2026年的DFlash块扩散草稿把草稿器换成块扩散模型并直接以EAGLE-3为基线。

局限与后续

  • 草稿器仍是自回归逐词生成，草稿越长串行开销越大，大批量时收益缩小。
    后来针对它的工作　DFlash块扩散草稿
  • 每个目标模型都要单独训练草稿器，模型更新后需重训。

读懂它需要的概念

自回归生成 解码：贪心、束搜索、温度与top-p KV缓存 吞吐、延迟与批处理

本篇术语

  • 接受长度　每轮草稿里平均有几个词被目标模型验证通过；越长，目标模型需要做的前向次数越少。

怎么学

先读推测解码和EAGLE特征级推测解码的讲解 → 读论文第3节两处改动 → 在SGLang里给开源模型加载EAGLE-3草稿器，测接受长度和加速比。
