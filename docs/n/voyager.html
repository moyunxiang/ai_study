Voyager: An Open-Ended Embodied Agent with Large Language Models
2023.05论文延伸arXiv 2023Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi Fan, Anima Anandkumar · NVIDIA / Caltech / UT Austin / Stanford待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

游戏里的智能体要么靠强化学习从零训练、学得慢且不可迁移，要么只做一次性规划，学到的本领无法积累。

方法

让GPT-4在Minecraft里不断写代码当作技能，成功的技能存进“技能库”，以后遇到新任务先检索再组合，同时有自动课程不断提出新目标。

影响

第一个展示LLM智能体能终身学习的例子，“把技能存成可检索代码”成为后来智能体记忆设计的常见思路。

方法

Voyager有三个部件。自动课程：由GPT-4根据当前背包、位置和已完成任务，提出下一个“刚好够得着”的目标，如“造石镐”。技能库：每个技能是一段可执行的JavaScript函数（调用Minecraft的Mineflayer接口），成功后连同自然语言描述存入向量库，需要时按描述检索，复杂技能可以调用简单技能，所以本领会复合增长。迭代提示：代码生成后先在游戏里运行，把环境反馈、报错信息和另一个GPT-4的自我检查结果一起放回提示，反复改直到通过。整个过程只通过API黑盒调用GPT-4，不更新任何参数。

摘要称它获得的独特物品数是此前最佳方法的3.3倍，行进距离2.3倍，解锁关键科技树里程碑最多快15.3倍，并且带着技能库进入新世界仍能解决新任务。

局限与后续

  • 依赖GPT-4的文字化游戏接口，没有视觉输入；到了没有现成代码API的环境里无法直接套用。

  • 技能库只增不减，没有验证与淘汰机制，检索到错误的技能也不会被发现。
    后来针对它的工作　CoALA认知架构
  • 整个循环调用GPT-4次数多，成本高。
