RvS监督学习式离线RL

RvS: What is Essential for Offline RL via Supervised Learning?
2021.12论文延伸ICLR 2022Scott Emmons, Benjamin Eysenbach, Ilya Kostrikov, Sergey Levine · UC Berkeley, Carnegie Mellon University待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

Decision Transformer等工作显示，不用时序差分、只做“以回报或目标为条件的监督学习”就能做离线RL。但这种做法什么时候有效、哪些组件是必需的（Transformer？长上下文？），并不清楚。

方法

把“通过监督学习做RL”（作者称为RvS）简化到最基本的形式：一个两层MLP，输入当前状态和条件（目标状态或期望平均回报），用最大似然预测数据中的动作。系统地比较条件信息、模型容量、正则化等因素。

影响

表明简单的条件行为克隆在多个离线基准上就能与TD学习或Transformer序列建模方法相当，澄清了序列建模式离线RL成功的关键因素，并指出它在随机/低质量数据上的弱点。

背景

Decision Transformer和Trajectory Transformer把离线RL写成序列建模问题，用Transformer在轨迹上训练，以“期望回报”为条件生成动作，效果可与离线强化学习CQL、隐式Q学习IQL等TD方法相比。更早的“倒置RL”（Upside-Down RL）和目标条件的行为克隆也是类似思路。这引出疑问：是Transformer、长上下文起了作用，还是“以结果为条件的模仿”本身就够了？

方法

RvS把策略写成 π(a | s, ω)，ω是条件变量，有两种：

  • RvS-G：ω是目标状态，训练时从同一条轨迹中当前状态之后的某个状态采样（事后重标注，见后见经验回放HER）；
  • RvS-R：ω是从当前步起的平均奖励（未来回报除以剩余步数），测试时手动设为一个较高的值。

训练目标就是条件最大似然：max_π E_{(s,a,ω)∼D}[ log π(a | s, ω) ]。网络是只有两层隐藏层的前馈网络（宽度约1024），不看历史，只看当前状态。作者在D4RL的Gym运动、Franka Kitchen、AntMaze以及GCSL等任务上做了大量消融：网络容量、dropout等正则、条件选目标还是回报、是否需要历史上下文等。

结果

摘要称：在所考察的每个环境套件中，用两层前馈MLP做简单的最大似然，就能与基于TD学习或Transformer序列建模、复杂得多的方法的最佳结果相竞争；仔细选择模型容量（例如通过正则化或结构）以及选择以什么信息为条件（目标还是回报）对性能至关重要；现有RvS方法在随机数据上相对较弱，并留下若干开放问题。

后来的发展

RvS与同期分析共同说明：Decision Transformer类方法的效果大多来自“以结果为条件的模仿”，而非Transformer本身；它们无法像TD方法那样把不同轨迹的片段“拼接”起来，在需要拼接的AntMaze等任务上明显落后。后续工作因此提出结合价值函数的条件模仿、或改进的拼接方法。

局限与后续

  • 以回报为条件的模仿不能把多条次优轨迹的片段拼接成更好的轨迹，在需要拼接的任务上明显落后于TD方法。

读懂它需要的概念

离线强化学习 模仿学习与行为克隆 最大似然估计 多层感知机 正则化与权重衰减

本篇术语

  • RvS（RL via Supervised Learning）　通过以目标或回报为条件的监督学习来解决RL问题，不使用时序差分或价值函数。
  • 轨迹拼接（stitching）　把数据中不同轨迹的好片段组合成一条更好的新轨迹；TD方法能做到，纯条件模仿通常做不到。

怎么学

先读Decision Transformer；读原文第4节关键设计选择与第5节结果；在hopper-medium-replay上训练RvS-R，改变测试时的目标回报，观察实际回报的变化。
