问题

MobileNetV2靠人工设计，手机上的实际延迟并不总与计算量对应；单纯用NAS搜又难以加入人类发现的有效结构。

方法

先用以手机CPU实测延迟为目标的架构搜索和NetAdapt逐层裁剪得到结构，再手工加入SE注意力、h-swish激活和重新设计的首尾层。

影响

成为端侧分类、检测、分割的常用骨干，“硬件感知搜索+人工改进”也成了后续轻量网络的标准流程。

方法

构建分两步。第一步是搜索：用MnasNet硬件感知NAS式的平台感知NAS，以在手机CPU上实测的延迟为约束搜出整体的块结构；再用NetAdapt逐层微调每层的通道数，每次在略降延迟的前提下选精度损失最小的方案。

第二步是人工改进：

  • 在倒残差块中加入SENet通道注意力的通道注意力；
  • 提出h-swish：h-swish(x) = x · ReLU6(x+3) / 6，用分段线性近似Swish/SiLU，在手机上更便宜，主要用在网络后半段；
  • 重新设计计算量大的最后几层和开头的卷积，去掉冗余部分。

还为分割提出轻量解码头LR-ASPP。摘要报告：Large版在ImageNet上比MobileNetV2准确率高3.2%、延迟降15%；Small版准确率高4.6%、延迟降5%；用作COCO检测骨干在精度相当时快25%；Cityscapes分割比MobileNetV2的R-ASPP快30%。

局限与后续

  • 结构针对特定手机CPU搜出，换到GPU或NPU上延迟优势未必保持；深度可分离卷积在GPU上利用率低。

本篇术语

  • NetAdapt　一种逐层调整通道数的算法：每次以小幅降低实测延迟为目标，挑精度损失最小的那一层去缩减。

怎么学

先读MobileNetV2的倒残差块和SENet，再读MobileNetV3第4–5节的搜索与改进；用torchvision的mobilenet_v3_small测手机或CPU延迟。
