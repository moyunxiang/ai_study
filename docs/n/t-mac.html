T-MAC查表低比特推理

T-MAC: CPU Renaissance via Table Lookup for Low-Bit LLM Deployment on Edge
2024.06论文延伸EuroSys 2025Jianyu Wei, Shijie Cao, Ting Cao, Lingxiao Ma, Lei Wang, Yanyong Zhang, Mao Yang · 微软亚洲研究院, 中国科学技术大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

低比特量化模型推理时要做“低比特权重×高精度激活”的混合精度矩阵乘，CPU没有这种原生指令，只能先把权重反量化回高精度再算，开销大，比特数降低也换不来相应的提速。

方法

把乘法变成查表：权重按比特拆开，每一比特只有0/1两种取值，预先把激活的各种组合和算好放进一张小表，计算时用权重比特直接查表累加，不再反量化、也几乎不做乘法。

影响

让CPU上的低比特推理速度随比特数线性提升，是微软bitnet.cpp等1比特推理内核的技术基础之一。

方法

端侧部署通常把权重量化到4比特、2比特甚至1.58比特（如1.58比特模型BitNet），激活仍是8或16比特。llama.cpp与本地推理等框架在CPU上的做法是先把一块权重反量化成高精度，再做普通的乘加；比特数再低，乘加次数也不变，所以速度提升有限。

T-MAC把一个n比特权重拆成n个1比特平面：W = Σ_i 2^i · W_i，每个 W_i 的元素只取0或1。对一组g个激活（如g=4），它们与任意0/1向量的点积只有 2^g 种可能，可以先算出来存成一张查找表。于是“权重×激活”变成：用每个比特平面上连续g个比特拼成索引去查表，再按 2^i 加权累加。乘法被消除，加法也大为减少；计算量随比特数线性下降。论文还针对CPU的SIMD查表指令、表的存放位置和数据布局做了优化。

摘要报告：在低比特Llama和BitNet模型上，相比llama.cpp吞吐最多提高4倍、能耗降低70%；BitNet-b1.58-3B在M2-Ultra上单核每秒30个词、八核71个词，在树莓派5上每秒11个词。

局限与后续

  • 查表法在解码这类矩阵-向量乘中优势明显，预填充的大批量矩阵乘仍可能更适合传统的反量化加GEMM；也依赖CPU的SIMD查表指令。
