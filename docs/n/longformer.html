Longformer滑窗注意力

Longformer: The Long-Document Transformer
2020.04论文延伸Iz Beltagy, Matthew E. Peters, Arman Cohan · Allen Institute for AI待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

BERT类模型一次最多读512个词，长文档要被硬切段，跨段信息完全断开。

方法

用滑动窗口的局部注意力为主，少数任务相关的位置（如分类符、问题词）使用全局注意力，使成本随长度线性增长。

影响

让预训练编码器第一次实用地处理数千词的长文，LED版本也支持长文摘要，是长文本编码器的标准基线。

方法

Longformer把注意力拆成两类。滑窗注意力：每个词只看左右各w个相邻词，复杂度随序列长度线性增长；堆叠多层后，感受野逐层增大。全局注意力：少数被指定的词（如问答中的问题词、分类用的[CLS]）可以看到所有词，也被所有词看到，它们承担整篇文章的信息汇总。

作者从RoBERTa的权重出发继续预训练得到Longformer，并提供Longformer-Encoder-Decoder（LED）用于生成式长文任务。摘要称，在字符级语言建模的text8和enwik8上达到当时最优，在WikiHop和TriviaQA上取得新最优，在长文任务上稳定超过RoBERTa，并在arXiv论文摘要上验证了LED。

局限与后续

  • 滑窗大小和哪些位置做全局注意力需要按任务手工设计。
    后来针对它的工作　BigBird稀疏注意力
  • 远距离的信息只能靠逐层累积或全局词传递，对需要精细远程对齐的任务不够。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 改进
    BERT2018.10 · LLM 已核对
    输入最长512个token，长文档必须截断或切块。
  • 使用
    RoBERTa2019.07 · LLM
    以RoBERTa的参数为起点继续预训练，并与之比较。
  • 改进
    Transformer-XL2019.01 · LLM
    注意力仍然是对缓存内全部位置计算，长度一大成本依然随长度增长。
  • 延续
    稀疏注意力2019.04 · LLM
    同样用稀疏注意力降成本，但改成更简单的滑窗加全局词，并真正做了预训练和下游微调。

后来的相关工作

  • 使用
    Gated DeltaNet2024.12 · 基础 待核对
    混合版本H1、H2用滑动窗口注意力补足局部比较和精确检索能力；这种局部窗口注意力Longformer已系统使用，但本文没有引用Longformer。
  • 延续
    BigBird稀疏注意力2020.07 · LLM
    在滑窗加全局注意力的基础上又加入随机连接，并补上理论证明。
  • 延续
    StreamingLLM与注意力汇聚2023.09 · 系统·效率
    在滑窗注意力上补上汇聚词，修复窗口超出缓存后失效的问题。
  • 使用
    Mistral 7B2023.10 · LLM
    借鉴局部窗口注意力，改为滑动窗口并按层堆叠
  • 改进
    MoBA块注意力2025.02 · LLM
    滑动窗口式稀疏注意力有固定的任务偏置；MoBA让模型自己选看哪些块。
