CodeT5+

CodeT5+: Open Code Large Language Models for Code Understanding and Generation
2023.05论文延伸EMNLP 2023Yue Wang, Hung Le, Akhilesh Deepak Gotmare, Nghi D. Q. Bui, Junnan Li, Steven C. H. Hoi · Salesforce AI Research待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

代码大模型要么只有编码器（适合理解、检索）要么只有解码器（适合生成），或者用一个统一的编码器-解码器硬套所有任务；预训练目标也单一，与很多下游任务不匹配。

方法

做一族模块可灵活拆装的编码器-解码器代码模型：混合使用片段去噪、对比学习、文本-代码匹配和因果语言建模等预训练目标，并用冻结的现成解码器LLM初始化来高效扩大规模。

影响

是2023年开源代码模型中“编码器-解码器路线”的代表，其编码器部分常被用作代码检索和代码嵌入的基线。

方法

背景：CodeT5是统一的编码器-解码器代码模型，CodeGen、StarCoder走纯解码器路线。作者认为前者把所有任务塞进一个系统、在部分任务上不理想，后者又不擅长需要双向理解的检索和分类任务。

CodeT5+的设计：模块可组合，同一个模型可以只用编码器（做代码检索、缺陷检测）、只用解码器（做生成），或编码器加解码器（做代码摘要、翻译）。混合预训练目标分两阶段：先在只有代码的多语言语料上做片段去噪和因果语言建模；再在代码-文本成对数据上加入文本-代码对比学习、文本-代码匹配和文本到代码的因果生成，以减小预训练与微调任务之间的差距。高效扩大：大模型版本不从头训练，而是用冻结的现成解码器LLM（作者用CodeGen的权重）作为解码器、训练一个较小的编码器和两者之间的交叉注意力层。此外还做了指令微调版本InstructCodeT5+。

摘要称在20多个代码基准上，包括零样本、微调和指令微调设置，取得多项最好结果；指令微调的CodeT5+ 16B在HumanEval代码生成上超过当时其他开源代码模型。

局限与后续

  • 编码器-解码器结构在长上下文、大规模生成和对话式交互上不如纯解码器方便，之后的主流开源代码模型基本都转向纯解码器路线。

读懂它需要的概念

编码器-解码器 对比学习 自回归生成 掩码建模 指令微调与对话模板

本篇术语

  • 片段去噪　把输入中的若干连续片段遮掉，让模型生成被遮的内容，是T5类模型的标准预训练目标。

怎么学

先读CodeT5和T5的片段去噪；读本文第3节两阶段预训练和“冻结解码器初始化”的示意图；动手：用开源的CodeT5+ 110M嵌入模型做一个小型代码检索实验。
