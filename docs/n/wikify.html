Wikify!实体链接

Wikify!: Linking Documents to Encyclopedic Knowledge
2007.11论文延伸CIKM 2007Rada Mihalcea, Andras Csomai · 北得克萨斯大学待核对
DOI ↗在交互版中打开（演化树、学习进度）

问题

一篇文章里提到的「Java」是编程语言、岛屿还是咖啡？要让机器把文本中的重要概念自动连到知识库的对应条目上，需要同时解决「哪些词值得链接」和「链接到哪个意思」两个问题。

方法

以维基百科为知识库和训练数据：维基百科条目里编辑者手工加的超链接，天然提供了「这个词组在这里指哪个条目」的标注。系统先用关键词抽取挑出值得链接的词组（按它在维基百科中被链接的概率排序），再用词义消歧的方法决定链到哪个条目。

影响

Wikify!提出了「维基化」任务，即把文本中的提及链接到维基百科条目，这是实体链接研究的起点之一；此后的Milne & Witten、TAGME、AIDA，乃至BLINK、GENRE都在解决同一个问题。

背景

维基百科语料到2007年已有两百多万英文条目，条目之间有大量人工超链接。词义消歧（Lesk词义消歧、Yarowsky自举词义消歧）此前依赖WordNet这类词典的义项，覆盖不了人名、机构、新概念；关键词抽取（IDF与TF-IDF、TextRank）只挑出重要词，不知道它们指什么。

方法

第一步：关键词识别（detection）。对文中每个n-gram，统计它在维基百科中作为链接锚文本出现的次数与它出现的总次数之比，称为关键词度（keyphraseness）：

keyphraseness(w) = count(w作为链接出现) / count(w出现)

得分高的词组更可能是值得链接的概念。按比例选出前若干个作为候选，作者也比较了tf-idf、卡方检验等排序方法。

第二步：消歧（disambiguation）。一个锚文本在维基百科里可能链接到多个条目（「Java」→ Java (programming language) / Java (island)）。作者比较了两种方法：一是知识型的、类似Lesk的方法，比较候选条目正文与当前上下文的词重叠；二是数据驱动的方法，把维基百科里该锚文本的每次出现当作训练样本，用上下文特征训练分类器；两者组合效果最好。

输出：把文本改写成带有指向维基百科条目超链接的版本。

结果

据摘要：论文提出以维基百科为资源做自动关键词抽取和词义消歧，系统能自动为文本加上指向百科知识的链接，评测表明自动标注可靠、与人工标注几乎难以区分。

后来的发展

Milne & Witten（2008）引入条目之间的关联度做消歧，TAGME（2010）面向短文本，AIDA（2011）在YAGO上做联合消歧；TAC-KBP评测把实体链接定为标准任务。神经时代有双塔检索式的BLINK和生成式的GENRE生成式实体检索。实体链接是构建知识图谱、知识密集问答和检索增强生成的基础组件。

本篇术语

  • 实体链接（entity linking）　把文本中提到的实体（「乔丹」）对应到知识库里的唯一条目（迈克尔·乔丹，篮球运动员），包括找出提及和消歧两步。
  • 关键词度（keyphraseness）　一个词组在维基百科中被作为链接锚文本的比例，用来判断它是否值得链接。
