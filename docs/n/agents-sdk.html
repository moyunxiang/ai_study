Responses API与Agents SDK

New tools for building agents
2025.03系统重要OpenAI待核对
官方公告 ↗Agents SDK（GitHub） ↗在交互版中打开（演化树、学习进度）

问题

开发者要做智能体，得自己拼：Chat Completions只管单轮生成，Assistants API有工具但笨重且是测试版，搜索、文件检索、电脑操作要分别接，多智能体编排和调试也没有标准工具。

方法

推出新的API原语Responses API：一次调用内可连续使用多个内置工具（网页搜索、文件搜索、电脑操作）和多轮模型调用；再开源一个轻量的Agents SDK，用“智能体、交接、护栏、追踪”四个概念编排多智能体流程。

影响

Responses API取代Assistants API成为OpenAI构建智能体的主接口（后者计划2026年中下线），Agents SDK成为常用的开源智能体框架之一，OpenAI随后也在其中支持了MCP。

背景

2023年6月的函数调用成为标准接口让模型能输出结构化的工具调用，但调用循环、状态管理都要开发者自己写。同年11月Assistants API与GPTs推出的Assistants API把线程、检索、代码解释器托管在OpenAI平台上，可它一直是测试版，开发者反馈不够灵活、速度慢。2024年OpenAI还发布过一个实验性的多智能体框架Swarm。与此同时，开源社区的LangChain、LangGraph图式编排、多智能体框架AutoGen提供了各自的编排方式，Anthropic推出了与厂商无关的模型上下文协议MCP。

2025年1月OpenAI发布了浏览器智能体Operator与浏览器智能体，其背后的CUA模型只在ChatGPT内可用。官方在公告里说，客户反映把模型能力变成可上线的智能体很难，往往需要大量提示词迭代和自定义编排逻辑，且缺乏可见性。

方法

2025年3月11日发布的一组构件：

Responses API。官方称它结合了Chat Completions的简单和Assistants API的工具能力，是前者的超集；采用统一的“条目（item）”设计，一次调用中模型可以多次调用工具、多轮推理后再返回。

三个内置工具：

  • 网页搜索：与ChatGPT搜索同一模型，回答附带来源链接；
  • 文件搜索：在开发者上传的文档向量库中检索，支持元数据过滤和重排（即托管版的检索增强生成RAG）；
  • 电脑操作：与Operator相同的CUA模型，输出鼠标键盘动作，由开发者在自己的环境中执行（与Computer Use类似）。

Agents SDK（开源，Python）。在Swarm基础上改进，核心概念只有四个：智能体（配好指令和工具的模型）、交接（handoff，把对话控制权转给另一个智能体）、护栏（对输入输出做安全检查）、追踪（可视化执行过程便于调试）。例如一个“分诊智能体”根据用户问题，把对话交接给“购物助手”（带网页搜索）或“退货客服”（带退款函数）。

结果

官方称：带搜索的GPT-4o在SimpleQA事实问答上准确率90%，GPT-4o mini为88%。CUA在OSWorld上38.1%（此前最佳22.0%，人类72.4%），WebArena 58.1%，WebVoyager 87%。官方同时承认OSWorld的成绩说明它在操作系统任务上还不可靠，建议人工监督。Assistants API计划在功能对齐后宣布弃用，目标下线时间为2026年中。

后来的发展

发布约两周后，OpenAI宣布在Agents SDK和自家产品中支持模型上下文协议MCP，开放协议与平台API开始合流。Responses API随后成为o3/o4-mini工具内推理等推理模型使用工具的主接口，Codex CLI、ChatGPT agent等产品也建立在同一套能力上；ChatGPT应用与Apps SDK把MCP服务器进一步扩展为能在ChatGPT里显示界面的应用。Anthropic后来把自家编码智能体的内核开放为Claude Agent SDK，与之形成对照。

读懂它需要的概念

工具调用 智能体循环 检索与向量数据库 嵌入向量

本篇术语

  • 交接（handoff）　一个智能体把当前对话和控制权转交给另一个更专门的智能体，比如客服分诊后转给退货专员。
  • 护栏（guardrail）　在智能体处理输入或输出前后运行的检查，例如拦截与业务无关或违规的请求。
  • CUA　Computer-Using Agent，OpenAI训练的电脑操作模型，看截图输出鼠标键盘动作，用于Operator和API。

怎么学

先确认会用工具调用写一个最小的工具调用循环；再读官方公告和Agents SDK的README，跑通其中“分诊—购物—退货”的例子，打开追踪界面看每一步的调用。对比自己手写循环和用SDK的代码量差异。
