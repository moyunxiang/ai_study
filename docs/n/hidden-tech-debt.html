机器学习系统的技术债

Hidden Technical Debt in Machine Learning Systems
2015.12论文重要NIPS 2015D. Sculley, Gary Holt, Daniel Golovin, Eugene Davydov, Todd Phillips, Dietmar Ebner, Vinay Chaudhary, Michael Young et al. · Google待核对
NeurIPS 2015论文PDF ↗在交互版中打开（演化树、学习进度）

问题

研究界关注怎样把模型做得更准，但在真实产品里，机器学习系统上线很快、维护却越来越贵，而这些成本几乎没有人系统地讨论过。

方法

借用软件工程的“技术债”比喻，系统梳理机器学习系统特有的长期维护风险：边界侵蚀、特征纠缠、隐藏反馈回路、未声明的使用者、数据依赖、胶水代码、配置债等。

影响

成为MLOps领域被引用最多的出发点之一；其中“机器学习代码只占真实系统的一小部分”的图，推动了数据验证、实验追踪、模型监控等工程实践和工具的发展。

背景

“技术债”是Ward Cunningham在1992年提出的比喻：为了快速交付而走捷径，就像借钱，日后要连本带利地还——重构、补测试、删死代码、理清依赖。到2015年，Google等公司已经在搜索、广告等产品里运行了大量机器学习系统（训练靠DistBelief与Downpour SGD、参数服务器这类基础设施）。作者们发现一个令人不安的普遍现象：开发和部署机器学习系统相对快且便宜，长期维护却又难又贵。传统软件工程的抽象边界、单元测试等手段，到了机器学习系统里常常失灵，因为系统的行为由数据而不是代码决定。

方法

论文没有新算法，而是一份风险清单，几个核心概念：

  • 纠缠与CACE原则：模型用了特征x₁…xₙ，改变x₁的分布，其余n−1个特征的权重都可能变；加一个特征、删一个特征也一样。作者称之为“改动任何东西都会改变一切”（Changing Anything Changes Everything），它同样适用于超参数、采样方式、收敛阈值。
  • 修正级联：在模型A的输出上再训练一个小模型B做修正，B依赖A，A的任何改进都可能让B出错，形成难以拆解的依赖链。
  • 未声明的使用者：别的系统悄悄读取某个模型的输出当作输入，改这个模型就会意外破坏它们。
  • 数据依赖比代码依赖更贵：上游信号的含义会悄悄变化，没有编译器能检查；有些特征贡献极小却带来风险，可以用逐个去掉特征的评估找出来。
  • 反馈回路：模型影响自己未来的训练数据（推荐什么就只收集到什么的点击），理论上应当用上下文老虎机（LinUCB上下文老虎机）这类方法；更隐蔽的是两个系统通过真实世界互相影响。
  • 系统反模式：成熟系统里机器学习代码可能最多只占5%，至少95%是把数据送进送出通用包的胶水代码；不断叠加抽取、连接、采样步骤的管道丛林；留在主代码里的废弃实验分支——论文举了Knight Capital因旧代码路径的意外行为45分钟损失4.65亿美元的例子。作者还指出，分布式学习缺乏公认的抽象，MapReduce不适合迭代式机器学习，参数服务器更稳健但有多种互相竞争的规范。
  • 配置债：成熟系统的配置行数可能远超代码行数，例如“特征A在某几天记录有误”“特征D线上没有，要用D′替代”，每一行都可能出错；配置应当能以小改动表达、可自动校验、可代码审查。
  • 监控：建议监控预测偏差（预测标签分布是否与观测一致）、为会采取行动的系统设动作上限、监控上游数据生产者。

后来的发展

这篇论文把“机器学习工程”变成了一个正式话题。后续的实验追踪与配置管理工具（实验追踪：W&B与MLflow）、记录数据来源与适用范围的数据集说明书Datasheets和模型卡、强调数据质量的以数据为中心的AI运动，都在回应它列出的问题。大模型时代，评测集与训练数据的纠缠（数据泄漏与基准污染）、提示词与模型版本耦合等新形态的技术债仍在出现。

容易误解的地方

  • “5%机器学习代码、95%胶水代码”是作者对成熟系统的估计（原文写的是“最多5%”与“至少95%”），不是统计测量的结果。
  • 论文不反对快速迭代：技术债并非都是坏的，关键是意识到它的存在并有计划地偿还。

读懂它需要的概念

监督学习 训练集、验证集与测试集 分布偏移 特征与表示学习

本篇术语

  • 技术债　软件工程比喻：为求快而采用的权宜设计会在日后持续产生维护成本，就像债务的利息，需要通过重构等方式偿还。
  • 胶水代码　为了把数据送进、送出某个通用库而写的大量适配代码，它会把系统锁死在该库的特性上。
  • 隐藏反馈回路　两个看似无关的系统通过真实世界（例如用户行为）互相影响，改进其中一个会间接改变另一个的训练数据。

怎么学

先熟悉训练集、验证集与测试集和分布偏移。原文只有9页，建议全文精读，重点是第2节（纠缠）、第4节（反馈回路）和图1。读完后找一个自己做过的机器学习项目，对照论文的清单逐条检查：有哪些未声明的数据依赖？配置能否一眼看出两次实验的差别？
