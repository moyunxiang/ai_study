CodeT5

CodeT5: Identifier-aware Unified Pre-trained Encoder-Decoder Models for Code Understanding and Generation
2021.09论文延伸EMNLP 2021Yue Wang, Weishi Wang, Shafiq Joty, Steven C. H. Hoi · Salesforce Research / NTU待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

CodeBERT只有编码器，不擅长生成；GPT式只有解码器，不擅长理解；而且它们把代码当普通文本，忽略了标识符（变量名、函数名）的特殊作用。

方法

基于T5的编码器-解码器统一做代码理解与生成，并加入“标识符感知”预训练任务和代码-注释双向生成任务。

影响

成为开源代码模型的常用基线，后续CodeT5+等系列沿用其统一的文本到文本框架。

方法

背景：把BERT、GPT的预训练搬到代码上后，纯编码器适合缺陷检测、克隆检测，纯解码器适合生成。程序语言又有自己的特点：开发者起的标识符携带大量语义。

方法：CodeT5采用T5式的统一编码器-解码器，并支持多任务学习。新增两个预训练任务：一是标识符感知，让模型判断每个token是否为标识符，并在标识符被遮掉时把它们恢复出来；二是双模态双向生成，利用开发者写的注释，让模型既能从注释生成代码，也能从代码生成注释，拉近自然语言与程序语言的对齐。

结果：论文称在缺陷检测、克隆检测等理解任务，以及代码到自然语言、自然语言到代码、代码到代码的各类生成任务上都明显超过先前方法。

局限与后续

  • 模型规模较小，不具备Codex那样从自然语言直接生成较长函数的能力。

  • 训练和评估偏重生成与摘要等传统任务，没有用单元测试检验功能正确性。
    后来针对它的工作　HumanEval HumanEval+ / EvalPlus

它建立在什么之上

  • 延续

    CodeBERT2020.02 · LLM
