谷歌神经机器翻译

Google's Neural Machine Translation System: Bridging the Gap between Human and Machine Translation
2016.09系统重要Yonghui Wu, Mike Schuster, Zhifeng Chen, Quoc V. Le, Mohammad Norouzi, Wolfgang Macherey, Maxim Krikun, Yuan Cao et al. · Google待核对
arXiv技术报告 ↗Google Research博客：上线公告 ↗在交互版中打开（演化树、学习进度）

问题

神经机器翻译在公开基准上已追平短语翻译，但训练和推理都太慢、罕见词处理差、长句常漏译，没人敢把它放进每天处理海量请求的线上产品。

方法

把注意力Seq2Seq做成工程上可部署的系统：8层编码器+8层解码器的LSTM加残差连接，多GPU模型并行，WordPiece子词，束搜索加长度归一化和覆盖惩罚，推理用低精度运算跑在TPU上。

影响

2016年9月谷歌翻译中译英全部切换到GNMT，谷歌翻译从此由统计翻译转向神经翻译；人工评测中翻译错误比原短语系统平均减少约60%，详细公开的工程方案也让其他翻译服务有了可照做的样板。

背景

Seq2Seq和注意力机制证明了端到端神经翻译可行，但在2016年它离产品还很远。谷歌翻译从2006年起一直用短语统计机器翻译（见Google翻译上线（统计MT））。神经翻译有三个实际障碍：一是慢，深层LSTM训练要很多天，线上逐词解码加束搜索的延迟也难以接受；二是罕见词，固定词表外的词变成UNK；三是漏译，模型有时会跳过源句的一部分，生成一句通顺但不完整的译文。此外，LSTM层数一多就训不动，论文报告普通堆叠LSTM在4层时还行，6层勉强，超过8层就很差。

方法

结构。编码器8层LSTM，只有最底层是双向的，其余单向；解码器8层；注意力用解码器最底层的输出去查编码器最顶层的输出，这样解码器的其他层可以和注意力计算错开，便于流水并行。每层放在不同GPU上（模型并行，见分布式训练：数据并行与模型并行）。

残差连接（见残差连接，思路来自ResNet）。第i层LSTM的输入与输出相加后再送入下一层：x_t^i = m_t^i + x_t^(i−1)，这让8层LSTM能顺利训练。

子词。采用WordPiece，源端和目标端共享约3.2万个词片。例如“Jet makers feud”被切成_J et _makers _fe ud，下划线标记词首，可无歧义地还原原文。

束搜索打分（见解码：贪心、束搜索、温度与top-p）。

s(Y, X) = log P(Y|X) / lp(Y) + cp(X; Y)

长度惩罚lp(Y) = ((5 + |Y|) / 6)^α抵消“短句概率天然更高”的偏好；覆盖惩罚（借鉴覆盖机制）cp = β · Σ_i log(min(Σ_j p_i,j, 1))在某个源词累计得到的注意力不足1时扣分，鼓励覆盖整个源句。实验中取α=β=0.2。

低精度推理。训练时就约束数值范围，推理时用8位整数运算，在Google TPU上运行。还尝试了用强化学习直接优化BLEU。

结果

WMT14英→法单模型BLEU 38.95，英→德24.61；8个模型集成并经RL微调后分别为41.16和26.30。在TPU上用量化推理比CPU快3.4倍，BLEU无损失。RL微调能提高BLEU，但人工评测看不出差别。

生产数据上的人工并排评分（0–6分，评审员看同一源句的多个译文打分）：英→西班牙语短语系统4.885、GNMT 5.428、人工译文5.504；中→英为3.694、4.263、4.636。按“GNMT缩小了短语系统与人工之间差距的百分比”计算，六个语言方向在58%–87%之间，即摘要里“平均减少约60%翻译错误”的来源。官方博客称上线时中译英每天约1800万次翻译全部由GNMT完成。训练一个基础英法模型约需96块K80 GPU跑6天。

后来的发展

同年11月的多语言NMT与零样本翻译在GNMT上只加一个目标语言标记，就让一个模型翻译多种语言并实现零样本翻译。2017年上线的DeepL翻译上线等商业翻译服务也都基于神经网络。2017年的Transformer直接拿GNMT当主要对比对象，用自注意力取代循环层，用一小部分训练成本超过了它。GNMT里的长度惩罚公式、共享子词词表、残差堆叠等工程细节则被长期沿用。

它建立在什么之上

  • 使用
    注意力机制2014.09 · NLP 已核对
    注意力机制是核心部件，但改为用解码器底层查编码器顶层，以提高并行度。
  • 延续
    Seq2Seq2014.09 · NLP 已核对
    沿用深层LSTM编码器-解码器，把层数加到8+8，并解决了训练速度和部署问题。
  • 使用
    Google TPU2016.05 · 硬件
    推理用8位量化运算跑在TPU上，比CPU快3.4倍，是能上线的关键。
  • 改进
    Weaver翻译备忘录1949.07 · NLP
    严重低估了困难：真正的歧义常常需要窗口外的世界知识，后来Bar-Hillel据此论证全自动高质量翻译不可行。
  • 改进
    短语统计机器翻译2003.05 · NLP
    在生产数据上，人工并排评测显示它把短语翻译与人工译文之间的差距缩小了58%–87%，取代短语系统上线。
  • 改进
    Moses2007.06 · NLP
    继承了短语模型的缺陷：译文由局部短语拼接而成，长距离调序和整句的连贯性差。
  • 使用
    WordPiece2012.03 · NLP
    用WordPiece子词（共享约3.2万词片）解决罕见词问题，取代UNK加回退词典。
  • 改进
    RNN编码器-解码器与GRU2014.06 · NLP
    词表限制在1.5万个常见词，其余都映射为未知词，罕见词和新词无法翻译。
  • 竞争
    BPE子词切分2015.08 · NLP
    论文并列引用了BPE子词方案；两者思路相近，GNMT选择了谷歌内部为语音识别开发的WordPiece。
  • 改进
    Google翻译上线（统计MT）2006.04 · NLP
    以英语为枢轴会让两次翻译的错误叠加；短语式统计模型难以保持长句的语法连贯。
  • 改进
    ByteNet卷积翻译2016.10 · NLP
    字符级输入使序列很长，且精度未超过同期的词/子词注意力模型。

读懂它需要的概念

编码器-解码器 注意力机制 残差连接 分词与token 解码：贪心、束搜索、温度与top-p 量化

本篇术语

  • 并排评测（side-by-side）　让双语评审员同时看同一句原文的几个译文（如两个系统和人工译文）并分别打分，比BLEU更接近真实感受。
  • 长度归一化　束搜索按对数概率之和打分时，句子越长累加的负数越多，模型会偏好短译文；除以与长度相关的因子可以抵消这种偏差。
  • 覆盖惩罚　统计每个源词累计被注意了多少，若某些源词几乎没被看过就扣分，用来减少漏译。

怎么学

先补编码器-解码器、注意力机制和解码：贪心、束搜索、温度与top-p，读过Seq2Seq和注意力机制。读原文第3节（结构与残差）、第4节（WordPiece）和第7节（束搜索打分公式），再看表10理解“60%”是怎么算出来的。动手：在一个现成的小翻译模型上实现带长度惩罚和覆盖惩罚的束搜索，对比α、β取不同值时的BLEU和译文长度。
