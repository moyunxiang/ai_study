测试时计算扩展

Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters
2024.08论文延伸Charlie Snell, Jaehoon Lee, Kelvin Xu, Aviral Kumar · UC Berkeley / Google DeepMind待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

推理时多花算力能提高成绩，但各种方法（搜索、修改答案）各自效果如何、该怎么分配，缺乏系统研究，之前的结果也多是负面的。

方法

比较两种扩展测试时算力的机制——用过程奖励模型做搜索，和让模型在测试时按提示逐步修改自己的答案——并按题目难度自适应地分配算力。

影响

提出「计算最优」的测试时扩展策略，证明在一定条件下多用推理算力比换更大模型更划算。

方法

论文先把提高推理阶段表现的做法归为两类。第一类是针对验证器搜索：Best-of-N、束搜索等，用过程监督与过程奖励模型打分。第二类是改变模型的输出分布：让模型在测试时多次修改自己的答案（revision）。

核心发现是没有哪种方法在所有题目上最好：不同方法的效果随题目难度显著变化。因此作者提出compute-optimal策略：先估计题目难度，再给每题分配最合适的方法和预算。摘要称，用这个策略可以把测试时算力的效率提高4倍以上，并且在FLOPs相当时，较小的基础模型加测试时算力在较简单和中等题目上可以胜过大14倍的模型。

后来的发展

与重复采样的扩展律一起成为测试时扩展的学术基础，几周后OpenAI o1推理模型发布，把这条路线推到产品。后来s1与预算强制的预算强制、思考预算与推理强度的思考预算，都是在控制这条曲线。
