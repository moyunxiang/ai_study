LoRA

LoRA: Low-Rank Adaptation of Large Language Models
2021.06论文主干ICLR 2022Edward J. Hu, Yelong Shen, Phillip Wallis, Zeyuan Allen-Zhu, Yuanzhi Li, Shean Wang, Lu Wang, Weizhu Chen · 微软来源已核对
arXiv ↗官方代码 loralib ↗Hugging Face PEFT文档 ↗在交互版中打开（演化树、学习进度）

问题

模型大到GPT-3的1750亿参数后，全参数微调要为每个任务存一份350GB副本、训练要1.2TB显存；Adapter会拖慢推理，prompt类方法又占用上下文、效果不稳。

方法

冻结原权重W，只训练一个低秩增量ΔW = B·A（秩r通常只有1到64）；部署时把B·A直接加回W，推理结构和速度与原模型完全一样。

影响

此后成为最常用的参数高效微调方法之一：从大语言模型的指令微调到Stable Diffusion的风格模型都大量使用它，QLoRA和多适配器服务系统S-LoRA直接在它之上构建。

背景

预训练与微调的标准做法是把预训练模型的全部参数在下游任务上再训练一遍。模型只有几亿参数时这没问题，到了GPT-3就不现实：1750亿参数用Adam微调，还要为每个参数存两份优化器状态，论文估计训练显存约1.2TB；每做一个任务就多一份350GB的模型文件，100个任务就是35TB。

当时已有两类省参数的办法（见参数高效微调）。一类是Adapter：在每个Transformer层里插入一个小的瓶颈网络，只训练它。问题是这些小层是串行加在计算路径上的，推理时必须多算一遍。论文在GPT-2 medium、批大小1的设置下测得，Adapter让单次前向延迟增加20.7%到30.3%；大模型做模型并行时，多出来的层还要额外通信。另一类是Prefix / Prompt Tuning和P-Tuning：在输入前面加一段可训练的“虚拟token”。它不改结构，但会占掉一部分上下文长度，而且论文发现它的效果随可训练参数量变化并不单调，很难调。

还有一条线索：此前的研究发现，预训练模型微调时真正需要调整的“内在维度”很低——用很少的自由度就能达到接近全量微调的效果。

方法

核心假设：微调带来的权重变化ΔW是低秩的（见低秩近似）。

做法：对一个预训练的d×k权重矩阵W₀，不直接改它，而是写成

h = W₀x + ΔWx = W₀x + B·A·x，其中B ∈ ℝ^{d×r}，A ∈ ℝ^{r×k}，r ≪ min(d, k)

训练时W₀冻结，只更新A和B。A用随机高斯初始化，B初始化为0，所以训练开始时ΔW = 0，模型与原模型完全相同；ΔW·x再乘一个缩放系数α/r，这样换不同的r时不必重新调学习率。

算一下省了多少：GPT-3的隐藏维度d=12288，一个d×d投影矩阵有约1.5亿个参数；取r=4时，A和B合计只有2×12288×4 ≈ 9.8万个，是原来的约1/1500。论文只在每层注意力的查询和值投影W_q、W_v上加LoRA。

为什么没有推理延迟：B·A和W₀形状相同，部署时直接算出W = W₀ + B·A合并成一个矩阵，前向计算与原模型一模一样。要换任务，只需减去旧的B·A、加上新的，几十MB就能切换。

为什么省显存：冻结的参数不需要梯度，也不需要Adam的两份状态，所以训练显存大幅下降；被训练的参数少，检查点也极小。

结果

在GPT-3 175B上：可训练参数减少约1万倍，训练显存从1.2TB降到350GB；r=4且只调W_q、W_v时，检查点从350GB缩到35MB；训练吞吐比全参数微调高约25%（每块V100从32.5提高到43.1 token/秒）。效果上，470万个可训练参数的LoRA在WikiSQL上准确率73.4%、MNLI-m 91.7%、SAMSum ROUGE-1/2/L 53.8/29.8/45.9，而全参数微调分别为73.8%、89.5%、52.0/28.0/44.5——除WikiSQL略低外都持平或更好，也优于同参数量级的Adapter、BitFit和prefix类方法。在RoBERTa、DeBERTa（GLUE）和GPT-2（E2E等生成任务）上结论相同。

论文还分析了秩：只调W_q、W_v时，r=1在WikiSQL上就有73.4%，与r=64的73.5%几乎一样；学到的ΔW并不是重复W里最强的方向，而是把W中原本较弱的某些方向放大约21.5倍（r=4时）。

后来的发展

LoRA发表后，开源社区的大模型微调大量采用了它。Hugging Face PEFT库把它做成一行配置；QLoRA把冻结的基座进一步量化到4比特，单张48GB显卡就能微调650亿参数模型；LoRA微调扩散模型把它用到Stable Diffusion开源，几MB的风格/人物LoRA成了图像社区的主要分享形式。服务端，S-LoRA多适配器服务让一个基座同时挂上千个适配器；Apple端侧基础模型在端侧用LoRA式适配器切换不同功能；Tinker微调API这类微调API也以LoRA为默认方式。

方法本身后来也有改进：(IA)³用更少的参数做缩放，DoRA把权重拆成大小和方向分别更新以缩小与全量微调的差距。今天仍有争论的是：在大规模、知识密集的继续训练里，低秩更新是否学得不如全量微调。

容易误解的地方

  • LoRA不减少推理计算，也不减少基座模型本身占用的显存；它省的是训练显存、优化器状态和每个任务的存储。
  • 合并后零延迟的前提是只服务一个任务。同时服务多个不同的LoRA时不能都合并进基座，需要S-LoRA多适配器服务这类专门的批处理方案。
  • 论文只在注意力的W_q、W_v上加LoRA；后来的实践通常加到所有线性层（含前馈层），在小秩下效果更稳。
  • “低秩”指的是更新量ΔW低秩，不是说预训练权重W₀本身低秩。

读懂它需要的概念

预训练与微调 低秩近似 矩阵乘法与线性变换 特征分解与奇异值分解 自适应学习率优化器 参数量、计算量与显存 参数高效微调 Transformer层的结构

本篇术语

  • 秩r　LoRA增量矩阵的秩，也就是中间那条“瓶颈”的宽度。r越大可表达的变化越多，参数也越多；常用4到64。
  • 内在维度　要让模型在某个任务上达到接近最好的效果，真正需要调节的独立自由度有多少。微调的内在维度远小于参数总数。
  • 权重合并　训练完后把B·A算出来加到原权重W₀上，得到一个普通的矩阵，推理时不再需要额外的LoRA分支。

怎么学

先复习低秩近似和特征分解与奇异值分解：一个d×k矩阵怎样写成两个瘦长矩阵的乘积。然后读原文第4节（方法，只有两页）和第7节（秩的分析，看表6、表7）。动手：在nn.Linear外面自己包一个LoRA层（冻结原权重，加A、B两个参数），用它微调一个小GPT-2，统计可训练参数比例；再用Hugging Face PEFT库做同样的事，对比合并权重前后的输出是否一致。
