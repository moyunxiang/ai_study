LangGraph图式编排

LangGraph

问题

LangChain的“链”本质是有向无环图，而智能体需要循环：让LLM反复决定下一步、检查结果、不行再试，用链很难表达。

方法

在LangChain之上提供一个以图为核心的库：节点是函数或LLM调用，边可以带条件并形成环，状态在节点间传递。

影响

成为最常用的智能体编排库之一，“智能体即带状态的图”成为流行的工程抽象。

方法

官方博客的概括是：LangGraph是建立在LangChain之上、便于创建循环图的模块，而循环正是智能体运行时常需要的。官方举的例子是RAG：普通流程是检索再生成，如果第一次检索没有有用结果，就应让LLM判断检索质量差，换个更精细的查询再检索一次，这就需要循环。用LangGraph把这类流程写成状态机：定义共享状态，定义节点，定义节点之间的边（包括根据状态选择下一个节点的条件边）。

它与多智能体框架AutoGen的区别是：AutoGen以多智能体对话为中心，LangGraph以显式的控制流图为中心，开发者对每一步走向有更精确的控制，也方便加入人工审批、保存和恢复状态。

局限与后续

  • 图的结构要开发者手工设计，复杂智能体的图很快变得难以阅读和调试。
