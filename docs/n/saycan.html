SayCan

Do As I Can, Not As I Say: Grounding Language in Robotic Affordances
2022.04论文重要CoRL 2022Michael Ahn, Anthony Brohan, Noah Brown, Yevgen Chebotar, Omar Cortes, Byron David, Chelsea Finn, Chuyuan Fu et al.（共45位） · Robotics at Google / Everyday Robots待核对
arXiv ↗项目主页（含视频、开源桌面版代码） ↗在交互版中打开（演化树、学习进度）

问题

大语言模型懂得“洒了饮料该怎么办”这类常识，但它没见过机器人眼前的环境，会给出机器人做不到或与现场不符的计划；机器人底层技能又只听得懂“拿起海绵”这种简单指令。

方法

让语言模型给每个候选技能打“这一步是否有助于完成指令”的分（Say），让每个技能的价值函数给“在当前状态下能否成功”打分（Can），两个概率相乘选出下一步，循环执行直到完成。

影响

第一次把千亿参数语言模型接到真实的移动机械臂上完成长程家务指令，101条指令规划成功率84%、执行成功率74%；“大模型做规划、技能库做执行”成为具身智能的早期主流架构。

背景

2022年，GPT-3、PaLM这类大语言模型已经能针对“我把饮料洒了，你能帮忙吗”写出一段合理的步骤。但它没有身体：不知道这台机器人会哪些动作、厨房里有没有海绵，写出机器人做不到的步骤也毫无察觉。

另一边，Google的机器人团队已经用模仿学习（BC-Z）和强化学习（QT-Opt的多任务版本）训练出几百个底层技能，每个技能都能听一句简单指令完成一个原子动作，比如“拿起可乐罐”“去桌子那里”。但它们无法理解“我饿了，给我拿点吃的”这样抽象、需要多步才能完成的要求。问题是怎样把“该做什么”的常识和“现在能做什么”的约束接起来。

方法

技能库。共551个技能，分7个技能族、涉及17种物体：拿取、放置、开关抽屉、导航到各个位置等。每个技能 π 配一句文字描述 l_π（如“pick up the sponge”），以及一个用TD学习得到的价值函数 p(c_π | s, l_π)：在当前图像状态 s 下执行这个技能能成功的概率。这就是技能的“可供性”（affordance）。

Say：语言模型打分。不让语言模型自由生成文本，而是把指令和已完成的步骤写进少样本提示（见上下文学习与提示），然后计算语言模型生成每个技能描述的概率 p(l_π | i)，即“下一步做这个对完成指令有多大帮助”。这样输出被限制在机器人确实会的技能里。

Can：价值函数打分。用每个技能的价值函数估计它在当前场景下能否成功。

组合。选择 π* = argmax_π p(c_π | s, l_π) · p(l_π | i)：既有用、又做得到的技能。执行后把它加入提示，再选下一步，直到语言模型选出“done”。比如指令是“把可乐扔掉”，若机器人此刻看不到可乐，“拿起可乐”的价值很低，它会先选“去找可乐”。

结果

在办公室模拟厨房里测试7类、共101条指令。使用540B参数PaLM的版本（PaLM-SayCan）规划成功率84%、执行成功率74%；搬到真实厨房后规划下降3个百分点、执行下降14个百分点。去掉价值函数、只按语言模型打分时规划成功率降到67%。换更大的语言模型效果更好，PaLM也优于137B的指令微调FLAN。

后来的发展

SayCan定义了“大模型规划+技能执行”的框架。Inner Monologue让语言模型在执行中接收成功与否、场景描述等反馈；Code as Policies让语言模型直接写调用感知和控制接口的程序；PaLM-E把图像直接输入语言模型，规划时不再依赖价值函数“转述”现场。同一团队随后在RT-1、RT-2与VLA中改进底层技能本身，最终把规划和控制合进一个视觉-语言-动作模型。

局限与后续

  • 语言模型看不到图像，只能通过价值函数间接感知现场；执行中出错、物体掉落时也不会察觉和重新规划。
    后来针对它的工作　Inner Monologue PaLM-E
  • 能力上限受限于固定的技能库，库里没有的动作（比如擦桌子的特定方式）就无法完成，新增技能要重新采数据训练。
    后来针对它的工作　Code as Policies RT-2与VLA
  • 底层技能本身成功率和泛化能力有限，是整个系统执行失败的主要来源。
    后来针对它的工作　RT-1
  • 每一步都要用千亿参数模型给几百个技能逐一打分，计算昂贵、决策缓慢。
    本站还没有记录针对它的后续工作（不代表没有人解决）

    GPT-32020.05 · LLM
    沿用GPT-3开创的少样本提示，用语言模型给候选技能的文字描述打似然分；论文最终版改用PaLM。
  • 改进
    STRIPS规划1971 · 具身·世界模型
    谓词和算子全部由人手写，符号与摄像头看到的像素之间没有连接；换一个环境就要重写一套世界模型。
  • 改进
    《概率机器人》2005.08 · 具身·世界模型
    地图只有几何（哪里被占据），没有语义，机器人知道墙在哪，却不知道“杯子在厨房”。

    端到端视觉运动策略2015.04 · 具身·世界模型
    底层技能是从相机图像直接输出动作的端到端视觉运动策略，由行为克隆或强化学习训练。
  • 使用
    QT-Opt2018.06 · 具身·世界模型
    强化学习技能和技能价值函数来自QT-Opt的多任务扩展MT-Opt，价值函数直接充当“能否成功”的可供性打分。

    CLIPort2021.09 · 具身·世界模型

  • 使用
    PaLM2022.04 · LLM
    主要实验用540B参数的PaLM作为规划语言模型。
  • 改进
    行为主义机器人学1991 · 具身·世界模型

  • 改进
    PDDL规划描述语言1998 · 具身·世界模型
    需要人手工写出完整、准确的领域模型；真实机器人面对的开放环境里，谓词和动作很难事先穷举。
  • 改进
    ALFRED具身指令基准2019.12 · 具身·世界模型
    环境是AI2-THOR的仿真，动作是离散的，物体操作靠「对物体打掩码」的抽象接口完成，没有真实抓取的物理难度和视觉域差距。
  • 改进
    MT-Opt多任务真机RL2021.04 · 具身·世界模型
    任务用示例图像或固定集合指定，不能直接听懂自由形式的语言指令。

    LLM零样本具身规划2022.01 · 具身·世界模型
    语言模型不知道当前环境里实际有什么、机器人能做什么，生成的计划不一定可行。
  • 使用
    BC-Z2022.02 · 具身·世界模型
    语言条件的模仿学习技能沿用BC-Z的网络结构和训练方法。

  • 延续
    Code as Policies2022.09 · 具身·世界模型

  • 改进
    RT-12022.12 · 具身·世界模型
    SayCan的长程任务常因底层技能不稳而失败；RT-1作为统一的底层策略，让SayCan能完成多达50步的任务。

    SayCan的语言模型看不到图像、只能借价值函数感知现场；PaLM-E让语言模型直接读图规划，并能根据新图像重新规划。

    Inner Monologue2022.07 · 具身·世界模型

    VIMA多模态提示2022.10 · 具身·世界模型

读懂它需要的概念

语言模型 上下文学习与提示 策略与价值函数 模仿学习与行为克隆 条件概率与贝叶斯公式

本篇术语

  • 可供性（affordance）　环境在当前状态下“允许”一个行动者做成某件事的程度；SayCan里用技能价值函数给出的成功概率来表示。
  • 落地（grounding）　让语言模型的输出与真实世界的状态、机器人的能力对应起来，而不是只在文字层面合理。
  • 技能库　一组预先训练好的底层策略，每个负责一个原子动作，配有文字描述，可以被上层规划器按名字调用。

怎么学

先补语言模型的概率打分和少样本提示 → 读原文第3节（SayCan公式）和表2（消融） → 动手：用开源的桌面版SayCan代码，把语言模型换成一个小的开源模型，观察去掉价值函数后计划会出现哪些不可执行的步骤。
