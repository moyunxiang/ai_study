Ragas检索增强评测

Ragas: Automated Evaluation of Retrieval Augmented Generation
2023.09系统延伸EACL 2024 System DemonstrationsShahul Es, Jithin James, Luis Espinosa-Anke, Steven Schockaert · Exploding Gradients / 卡迪夫大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

检索增强生成（RAG）系统要同时评检索找得准不准、模型有没有忠实使用检索内容、回答本身好不好，而给每个问题准备人工标准答案成本很高，开发迭代时没法频繁评测。

方法

提出一套不需要人工标准答案的指标，用大模型自动判断：回答中的陈述是否都能从检索段落推出（忠实度）、回答是否切题（答案相关性）、检索到的段落是否聚焦（上下文相关性）。

影响

Ragas开源库成为工业界评测RAG流水线最常用的工具之一，“忠实度、上下文精确率与召回率”等指标名称被大量RAG评测沿用。

方法

背景。检索增强生成RAG让模型先从文档库检索相关段落再生成回答，可以减少幻觉。但一个RAG系统好不好要看几个环节：检索器有没有找到相关且精炼的段落，生成模型有没有忠实于这些段落，回答是否回应了问题。传统做法是准备人工答案再算重合度，每换一个文档库就要重新标注。

Ragas的指标。核心思想是把评判交给大模型，并拆成可检查的小步骤。忠实度：先让大模型把回答拆成若干条陈述，再逐条判断能否从检索到的上下文中推出，可推出的比例即得分。答案相关性：让大模型根据回答反推可能的问题，与原问题算语义相似度，越相似说明回答越切题。上下文相关性：让大模型从检索段落里挑出回答问题真正需要的句子，所占比例越高说明检索越精准。这些都不需要人工标准答案。

验证。作者构造了带人工判断的数据，显示这些指标与人的判断较为一致。这一思路与G-Eval大模型评分等用大模型打分的方法相通。

局限与后续

  • 指标本身依赖大模型判断，换一个评审模型得分就会变化，也会继承评审模型的错误；只看回答与检索内容是否一致，不检查检索内容本身是否正确。

读懂它需要的概念

检索与向量数据库 幻觉 文本生成的自动指标 嵌入向量

本篇术语

  • 忠实度　回答里的每一条陈述是否都能从提供给模型的检索内容中推出；推不出的就是模型自己编的。
  • 无参考评测　不需要事先写好标准答案，直接根据问题、上下文和回答本身来打分。

怎么学

先读检索增强生成RAG了解检索增强的流程。读Ragas原文第3节三个指标的提示设计；动手搭一个小型RAG问答，用Ragas库算忠实度，再故意让模型编造内容，看分数怎么变。
