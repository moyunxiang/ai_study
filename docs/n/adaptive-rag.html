Adaptive-RAG按难度检索

Adaptive-RAG: Learning to Adapt Retrieval-Augmented Large Language Models through Question Complexity
2024.03论文延伸NAACL 2024Soyeong Jeong, Jinheon Baek, Sukmin Cho, Sung Ju Hwang, Jong C. Park · KAIST待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

简单问题不必检索，复杂多跳问题却要反复检索推理；固定用一种策略，要么简单问题白白多花算力，要么复杂问题答不好。

方法

先用一个小分类器判断问题有多难，再在“不检索、检索一次、多步交替检索”三种策略里选一种去回答。

影响

把“按难度路由检索策略”做成一个可训练的小模块，此后的RAG系统常在前面加一个类似的复杂度判断或路由器。

方法

当时的检索增强问答有两种极端：检索增强生成RAG式的单步检索又快又省，但多跳问题（要先查A再据A查B）常答错；IRCoT交替检索推理把检索与向量数据库和思维链交替进行，多跳问题答得好，但每题要多次调用LLM和检索器。FLARE主动检索、Self-RAG等自适应方法让模型自己决定何时检索，但没有按问题整体难度切换策略。

Adaptive-RAG定义三档：A不检索，LLM直接答；B检索一次再答；C用IRCoT多步迭代。一个T5-Large（770M）分类器读入问题，预测该走哪一档。训练标签不靠人工：用三种策略实际去答，最简单就能答对的策略作为标签；三种都答错的，来自单跳数据集的标为B，来自多跳数据集的标为C。

在SQuAD、NQ、TriviaQA三个单跳和MuSiQue、HotpotQA、2WikiMultiHopQA三个多跳数据集上，以GPT-3.5为读者，Adaptive-RAG平均F1为50.91，多步方法为50.87；耗时（以单步检索为1）从3.33降到1.46。换成FLAN-T5-XL时，F1略低于多步方法（46.94对48.85），耗时从8.81降到3.60。

局限与后续

  • 分类器只在少数开放域问答数据集上训练，标签部分来自“出自单跳还是多跳数据集”这一偏置，换到真实用户问题时判断可能不准。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 只有三档固定策略，判断在答题前一次完成，无法在推理途中根据新信息改变检索次数。

它建立在什么之上

  • 改进
    检索增强生成RAG2020.05 · 推理·智能体
    缓解了单步RAG在多跳问题上答不好、而全部换用多步方法又太贵的两难。
  • 使用
    IRCoT交替检索推理2022.12 · 推理·智能体
    把IRCoT作为最复杂的C档策略，只在分类器判定为多跳难题时才调用。
  • 竞争
    FLARE主动检索2023.05 · 推理·智能体
    FLARE在生成途中按token置信度决定何时检索；Adaptive-RAG在答题前按整体难度一次性决定检索深度。
  • 竞争
    Self-RAG2023.10 · 推理·智能体
    Self-RAG训练生成模型本身用反思token决定是否检索；Adaptive-RAG不改生成模型，用外置小分类器按问题难度选策略。

读懂它需要的概念

检索与向量数据库 准确率、精确率、召回率与F1 语言模型 监督学习

怎么学

先读检索增强生成RAG和IRCoT交替检索推理 → 读原文第3节（三档策略与标签构造）和表1的F1与耗时 → 动手：用一个小分类器给100道问答题分成三档，统计每档实际需要的检索次数。
