AceReason先数学后代码RL

AceReason-Nemotron: Advancing Math and Code Reasoning through Reinforcement Learning
2025.05论文延伸Yang Chen, Zhuolin Yang, Zihan Liu, Chankyu Lee, Peng Xu, Mohammad Shoeybi, Bryan Catanzaro, Wei Ping · NVIDIA待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

当时普遍认为小模型靠蒸馏比靠强化学习更划算，而DeepSeek-R1等前沿模型的数据配方和RL细节又没公开，大规模RL对中小模型到底有多大用并不清楚。

方法

在已蒸馏好的7B、14B推理模型上做大规模RL，先只用数学题训练，再只用代码题训练，并通过大量消融整理出数据筛选和训练稳定的经验。

影响

用公开的消融结论说明RL能在强蒸馏模型之上继续带来明显提升，“先数学后代码”和“只用数学RL也能提升代码”的结论被后续推理RL工作常常引用。

方法

起点是已经从强推理模型蒸馏过的7B和14B模型。作者先搭了一条数据管线，收集答案可验证的高难度数学题、带测试用例的代码题，用于基于验证结果的强化学习（RLVR，算法基于GRPO）。

训练分两段：

  • 只用数学题的RL：除了数学基准大幅提升（AIME 2025上7B/14B分别+14.6%/+17.2%），代码推理也跟着提升（LiveCodeBench上+6.8%/+5.8%）；
  • 再做只用代码题的RL：进一步提高代码成绩，数学成绩基本不掉。

消融里整理出几条经验：训练时让回复长度上限逐步变长的课程比一开始就给满长度更稳；在策略（每批数据只更新一次参数）的更新能显著稳定训练，与此相关的熵坍缩问题见RL中的熵坍缩。作者的解读是：RL既能把预训练和蒸馏阶段已有的推理能力“激发”出来，也能把模型推到原来解不出的题上——后一点与RLVR能否带来新推理的质疑相对照。

局限与后续

  • 起点是已经蒸馏过的强模型，RL的收益有多少依赖蒸馏打下的基础、换成普通基座模型是否同样有效，没有完全分开。

怎么学

先读DeepSeek-R1和GRPO → 读原文的消融部分（回复长度课程、在策略更新） → 动手：在一个小推理模型上只用数学题做几百步RL，同时测数学和代码两个基准，看是否出现跨领域提升。
