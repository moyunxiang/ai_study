Saute RL安全预算增广

Saute RL: Almost Surely Safe Reinforcement Learning Using State Augmentation
2022.02论文延伸ICML 2022Aivar Sootla, Alexander I. Cowen-Rivers, Taher Jafferjee, Ziyan Wang, David Mguni, Jun Wang, Haitham Bou-Ammar · 华为诺亚方舟实验室 / UCL待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

CMDP只要求期望代价不超限，平均满足不等于每次都安全；飞机起降这类场景需要约束“几乎必然”（以概率1）满足。

方法

把“还剩多少安全预算”加进状态：每走一步预算减去本步代价，预算一旦用完就把奖励换成很大的惩罚；约束从此消失，变成一个普通MDP，任何RL算法都能直接用（Saute MDP）。

影响

提供了一个即插即用的安全RL包装方式，PPO、TRPO、SAC、模型RL都可以“Saute化”，OmniSafe把它作为状态增广类方法收录。

方法

设每条轨迹的累计代价不能超过预算d。Saute（Safety Augmented）MDP做两件事：

  • 状态增广：引入剩余安全预算 z_t，初值 z_0 = 1（按d归一化），每步更新 z_(t+1) = (z_t − c_t/d)/γ，把 (s_t, z_t) 作为新的状态；
  • 奖励重塑：若 z_t > 0，奖励保持原样 r_t；若预算已经耗尽 z_t ≤ 0，奖励换成一个很大的负值 −n。

这样原来的约束问题就被改写成一个没有约束的MDP。论文证明这个增广MDP满足贝尔曼方程，因此可以直接套用任何现成的RL算法；当惩罚n足够大时，最优策略对应以概率1满足约束的策略。

由于预算是状态的一部分，同一个策略在训练后还能对不同的预算d泛化：部署时给不同的初始预算，策略就表现出不同的保守程度。摘要称在约束满足非常重要的情形下，Saute化的算法可以超过对应的最先进安全RL算法。

局限与后续

  • 惩罚值n和预算的归一化方式影响学习难度，惩罚过大会让价值估计数值不稳。

它建立在什么之上

  • 使用
    PPO2017.07 · RL
    实验中把PPO、TRPO、SAC等现成算法“Saute化”。
  • 改进
    约束MDP（CMDP）1999 · RL
    CMDP只保证期望约束；Saute把约束改写进状态，追求几乎必然满足。
  • 延续
    通用值函数近似UVFA2015.07 · RL
    把预算作为额外输入，让同一策略对不同预算泛化，与目标条件价值函数思路相近。
  • 改进
    CPO约束策略优化2017.05 · RL
    只保证期望代价近似满足，单条轨迹仍可能严重违规。
  • 竞争
    RCPO奖励约束策略优化2018.05 · RL
    RCPO用拉格朗日乘子；Saute不用乘子，直接把约束变成状态与奖励的改写。

读懂它需要的概念

马尔可夫决策过程 奖励设计与奖励投机 状态、观测与动作 Bellman方程

本篇术语

  • 几乎必然满足　以概率1满足约束，即除了概率为零的情况外每条轨迹都不违规。
  • 状态增广　把额外的信息（这里是剩余安全预算）拼进状态，使原本依赖历史的约束变成马尔可夫的。

怎么学

先读约束MDP（CMDP）；读Saute原文第3节增广与重塑的定义；用OmniSafe的PPOSaute在SafetyPointGoal上训练，部署时改变初始预算观察行为变化。
