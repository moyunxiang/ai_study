DeepSeek-R1

DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning
2025.01论文主干Nature 2025DeepSeek-AI（Daya Guo, Dejian Yang, Haowei Zhang, Junxiao Song, Peiyi Wang, Qihao Zhu, Runxin Xu et al.）· 深度求索来源已核对
arXiv ↗Nature论文 ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

o1展示了长思维链推理的效果，但做法保密；外界对做法有多种猜测（大量人工标注的推理过程、过程奖励模型、蒙特卡洛树搜索），开源模型与o1差距明显。

方法

直接对基础模型做大规模强化学习，奖励只看最终答案对不对、格式对不对，用GRPO优化。模型自己学会了写长推理、反思和验证；再加少量冷启动数据和多阶段训练修好可读性。

影响

开放权重并公开了训练方法，推理成绩与o1-1217相当；之后许多推理模型采用“规则可验证奖励＋强化学习”的做法，它也引发了2025年的开源复现潮和市场震动。

背景

2024年9月，OpenAI o1推理模型展示了一种新能力：模型在回答前先生成很长的思维链（见推理token与测试时计算），数学、编程成绩大幅提升，而且想得越久越准。OpenAI只说用了强化学习，没有公开任何细节。

外界的猜测集中在三类重型方案上：用大量人工写的推理过程做监督微调；训练过程监督与过程奖励模型（过程奖励模型）对推理的每一步打分；或者像AlphaZero那样在推理步骤上做树搜索（如AlphaZero式LLM树搜索）。更早的STaR自举推理用“只保留答对的推理过程再微调”的办法自举推理，需要多轮“生成—筛选—微调”迭代。2024年11月的Tülu 3开放后训练把“用可自动判对错的奖励做强化学习”（RLVR）用于后训练（R1论文没有引用它）。

开源一侧最好的推理模型如QwQ开源推理模型与o1仍有明显差距。DeepSeek手里有刚训完的671B参数混合专家基础模型DeepSeek-V3。问题是：能不能不靠任何人工推理示范，只靠强化学习把推理能力“激发”出来？

方法

R1-Zero：纯强化学习。从DeepSeek-V3-Base出发，不做任何监督微调。提示模板只要求模型先把思考写在<think>与</think>之间，再给答案，不规定怎么思考。奖励完全由规则计算：

  • 准确性奖励：数学题要求把最终答案放进指定格式，与标准答案比对；编程题用编译器跑测试用例；
  • 格式奖励：检查思考是否放在标签内。

论文特意不用神经网络奖励模型，理由是大规模训练中它容易被模型钻空子（reward hacking），见奖励设计与奖励投机。

优化算法是GRPO。对每道题q，用当前策略采样一组G个回答，得到奖励r_1…r_G，每个回答的优势直接用组内标准化计算：

A_i = (r_i − mean(r_1…r_G)) / std(r_1…r_G)

然后像PPO一样，用新旧策略的概率比乘以优势并做裁剪，再加一项与参考模型的KL惩罚。与PPO相比，它不需要另训一个与策略同样大的价值网络（critic），节省了显存和计算。直观地说：同一题做16遍（修订版v2写明R1-Zero每题采样16个回答），比平均水平好的回答被强化，差的被抑制。

训练中出现了未被教过的行为：回答越来越长，模型开始自我检查、回头重算、尝试别的方法。论文展示了一个中间版本在解方程时写下“Wait, wait. Wait. That’s an aha moment I can flag here”，随后重新逐步检查。

R1：修可读性。R1-Zero的推理难读，还常中英混杂。R1用四个阶段：①几千条长思维链的冷启动数据做微调；②面向推理的强化学习，额外加“语言一致性奖励”（思维链中目标语言词的比例）；③用拒绝采样从②的模型收集约60万条推理样本，加约20万条写作、问答等非推理样本，共约80万条，重新微调V3-Base；④再做一轮覆盖所有场景的强化学习，推理题用规则奖励，一般问题用偏好奖励模型。

蒸馏。用这80万条样本直接微调Qwen2.5和Llama的1.5B到70B共6个小模型，只做监督微调、不做强化学习。

结果

R1-Zero在AIME 2024上的单次正确率（pass@1）从训练前的15.6%升到71.0%（v1数字；修订版v2报告为77.9%），64次多数投票达86.7%，与o1-0912相当。R1：AIME 2024 79.8%（o1-1217为79.2%），MATH-500 97.3%，Codeforces等级分2029、超过96.3%的人类参赛者，SWE-bench Verified 49.2%。

蒸馏模型：R1-Distill-Qwen-7B在AIME 2024得55.5%，超过QwQ开源推理模型-32B-Preview；Distill-Qwen-32B得72.6%。一个对照实验很关键：在Qwen-32B基础模型上直接做1万多步强化学习，只得47.0%，远低于蒸馏的72.6%。论文结论是：小模型从强模型蒸馏远比自己做RL划算，但要突破能力边界仍需更强的基础模型和更大规模的RL。

论文还坦白了失败尝试：过程奖励模型难以定义“一步”、难以标注且会被钻空子；蒙特卡洛树搜索因为token级搜索空间太大而难以扩展。

后来的发展

R1在2025年1月20日开源后，迅速引发“DeepSeek时刻”：一个开源模型以低得多的成本追上o1，冲击了市场对算力需求的预期。随后研究界掀起复现潮（Open-R1与R1复现潮），并围绕GRPO修出一批改进：DAPO针对熵坍缩、全组同分时没有梯度、长回答训练不稳提出了四项改动，Dr. GRPO与R1-Zero再审视指出GRPO存在人为拉长回答（尤其是错误回答）的优化偏差，GSPO序列级优化改为序列级优化。s1与预算强制、LIMO少样本推理则从另一侧说明少量蒸馏数据也能激活推理。RLVR能否带来新推理质疑RL是否带来了基础模型之外的新能力。

“规则可验证奖励＋组相对策略优化”被Qwen3混合思考等模型的推理RL采用（同期的Kimi k1.5同样不用价值网络，但用的是自己的在线镜像下降变体，且未开放权重），并被推广到搜索（Search-R1）、工具调用（ReTool工具强化学习）和智能体训练。2025年9月，扩充了训练细节的版本作为同行评审论文发表在Nature。

容易误解的地方

  • “纯RL、无需人工数据”只对R1-Zero成立。正式的R1用了冷启动数据和约80万条监督样本，其中推理样本由模型自己生成、经拒绝采样筛选。
  • “aha moment”是论文对某个中间版本的一段输出的描述；后来的Dr. GRPO与R1-Zero再审视发现DeepSeek-V3-Base在RL之前就已出现这种“aha”式自我检查，RL更多是放大了它。
  • 蒸馏模型（R1-Distill-Qwen等）只是用R1的输出做了监督微调，不是用强化学习训练的。

读懂它需要的概念

策略梯度 奖励设计与奖励投机 人类反馈强化学习 推理token与测试时计算 知识蒸馏 KL散度 混合专家

本篇术语

  • 可验证奖励（RLVR）　奖励由程序自动判定：答案与标准答案一致、代码通过测试就给1分，否则0分。不需要人打分，也不需要训练奖励模型。
  • 冷启动数据　在强化学习开始前，先用几千条格式规范、可读性好的长推理样本微调模型，让RL从一个“会好好说话”的起点出发。
  • 拒绝采样　让模型对每道题生成多个回答，只保留答对且可读的那些，作为下一轮监督微调的数据。
  • pass@1 / cons@64　pass@1是单次作答的正确率（论文对每题采样多次取平均）；cons@64是采样64次后取多数答案的正确率。
  • DeepSeek-R1-0528　2025年5月28日发布的R1更新版，官方称基准成绩和前端代码能力提升、幻觉减少，并支持JSON输出和函数调用，API用法不变。

怎么学

先补策略梯度和PPO的裁剪目标，再读GRPO的优势计算。然后读R1论文第2.2节（R1-Zero的奖励和模板）、2.3节（四阶段流程）和4.2节（失败尝试）。动手：用verl或TRL的GRPO实现，在一个1.5B左右的模型上用GSM8K做可验证奖励训练，观察回答长度和正确率随步数的变化，并亲眼看看“wait”是否出现。
