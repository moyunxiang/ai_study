上下文腐烂Context Rot

Context Rot: How Increasing Input Tokens Impacts LLM Performance
2025.07思想延伸Kelly Hong, Anton Troynikov, Jeff Huber · Chroma待核对
技术报告 ↗在交互版中打开（演化树、学习进度）

问题

前沿模型宣称百万token上下文、大海捞针近乎满分，但实际用在智能体和长对话里，输入越长越不靠谱，缺少一份控制住任务难度、只改长度的测量。

方法

保持任务本身极简不变，只加长输入，系统测18个模型在语义匹配、干扰项、文本结构、长对话记忆、复述重复词等设置下怎样随长度掉分。

影响

“上下文腐烂”成了2025年下半年社区描述长上下文退化的通用说法，并推动“上下文工程”成为智能体开发的热门话题。

方法

Chroma在2025年7月14日发布这份技术报告，评测GPT-4.1、Claude 4、Gemini 2.5、Qwen3等18个模型。思路是控制变量：任务都很简单，只改变输入长度，从而分离出“长度本身”的影响。

几个发现：问题和答案句只是语义相近、没有字面重合时，掉分随长度加快；加入1个和答案相似的干扰句就降分，4个更糟；把背景文章的句子打乱，模型反而比读通顺原文时表现更好，18个模型一致；在LongMemEval对话记忆任务上，给完整的约11.3万token历史，比只给相关的约300 token时所有模型都明显变差；让模型照抄一串重复词，长度从25词增到1万词时错误、拒答逐渐增多。报告的结论是：信息放在上下文里不等于会被用上，放多少、怎么组织和信息本身同样重要。

它建立在什么之上

  • 延续
    迷失在中间2023.07 · LLM
    前者发现位置影响，这里发现长度、干扰和结构本身也会让表现下降。
  • 延续
    大海捞针测试2023.11 · 数据·评测
    在大海捞针基础上加入语义匹配、干扰项和文本结构等变量，说明满分高估了长上下文能力。
  • 延续
    RULER长上下文2024.04 · 数据·评测
    同样认为字面检索太简单，但不加任务复杂度，只控制长度。
  • 竞争
    Michelangelo与MRCR2024.09 · 数据·评测
    MRCR用合成结构任务给出单一分数，Context Rot用多组控制实验刻画掉分的条件。

上下文窗口 注意力机制 智能体循环

本篇术语

  • 上下文工程　决定把哪些信息、按什么顺序和格式放进模型输入，而不是一股脑塞满上下文窗口。

怎么学

先读迷失在中间和大海捞针测试，再读报告里干扰项和LongMemEval两节；可用其开源代码在自己的模型上复现一个实验。
