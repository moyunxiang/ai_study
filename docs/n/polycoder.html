PolyCoder与代码模型评测

A Systematic Evaluation of Large Language Models of Code
2022.02论文延伸MAPS 2022Frank F. Xu, Uri Alon, Graham Neubig, Vincent J. Hellendoorn · 卡内基梅隆大学待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

Codex展示了大模型写代码的能力，但它不开源，外界不知道它的模型和数据设计；开源界也没有一个只用多种编程语言代码训练的大模型可供研究。

方法

系统评测当时最大的几个代码模型（Codex、GPT-J、GPT-Neo、GPT-NeoX-20B、CodeParrot）在12种编程语言上的表现，并训练、开源一个只用多语言代码训练的2.7B模型PolyCoder。

影响

给出了Codex之后第一份开源与闭源代码模型的横向对比，PolyCoder在C语言上超过所有模型包括Codex，成为StarCoder之前常用的开源代码模型基线之一。

方法

背景：Codex在HumanEval上表现出色，但模型和训练数据都不公开。开源方面，GPT-J-6B、GPT-NeoX-20B主要为自然语言训练，只是语料（如The Pile与开放预训练语料）中混有一部分GitHub代码；CodeParrot只做Python。研究者无从回答：模型多大、数据怎么配、多语言代码训练有什么用。

系统评测：作者用困惑度在12种编程语言（C、C++、C#、Go、Java、JavaScript、PHP、Python、Ruby、Rust、Scala、TypeScript）的保留代码上比较各模型，并在HumanEval上比较功能正确性。他们特别注意去重，避免测试代码出现在训练集中。发现：Codex虽然不开源，但开源模型在一些语言上已经能达到接近的结果，尽管它们主要是为自然语言训练的。

PolyCoder：作者认为缺少的一块是“只用多语言代码训练的大型开源模型”。于是基于GPT-2架构训练了2.7B参数的PolyCoder，语料是从GitHub收集、跨12种语言的249GB代码，并且只用一台机器完成训练。

结果：在C语言上，PolyCoder的困惑度低于包括Codex在内的所有模型；在其他多数语言上与同规模模型相当或更好；但在HumanEval（Python）上，它明显不如Codex和在大量自然语言加代码上训练的GPT-NeoX等模型，说明自然语言数据对理解问题描述很重要。模型全部开源。

后来的发展

PolyCoder和它的评测方法（多语言困惑度+HumanEval）被后续的SantaCoder、StarCoder等开源代码模型引用和比较，也让“多语言代码预训练”和“代码数据去重”成为后续工作的标准步骤。

读懂它需要的概念

语言模型 困惑度 自回归生成 分词与token 数据泄漏与基准污染

本篇术语

  • 困惑度　衡量语言模型对测试文本的预测好坏，等于平均每个词元负对数概率的指数，越低越好。

怎么学

先读Codex了解HumanEval和pass@k；读本文第3节多语言困惑度对比表和第4节PolyCoder训练设置；动手：用公开的PolyCoder-2.7B和一个通用模型分别计算一段C代码的困惑度，再各自补全一个C函数。
