ProgPrompt程序式任务规划

ProgPrompt: Generating Situated Robot Task Plans using Large Language Models
2022.09论文延伸ICRA 2023Ishika Singh, Valts Blukis, Arsalan Mousavian, Ankit Goyal, Danfei Xu, Jonathan Tremblay, Dieter Fox, Jesse Thomason et al. · University of Southern California、NVIDIA待核对
arXiv ↗项目页 ↗在交互版中打开（演化树、学习进度）

问题

用大语言模型做机器人任务规划有两种做法：让它给所有可能的下一步打分（要把每个候选动作列出来），或让它自由生成文字计划（可能写出机器人做不了、环境里也没有的动作）。

方法

把提示写成程序：先用Python风格的import列出机器人能调用的动作函数、用列表列出环境里的物体，再给几个写成函数的示例任务，最后让模型补全一个新任务的函数体，生成可直接执行、带断言检查的程序式计划。

影响

在VirtualHome家务任务上取得当时最高的成功率，并部署到真实机械臂的桌面任务；与Code as Policies一起把“让LLM写程序当计划”确立为具身规划的常见做法。

方法

LLM零样本具身规划让语言模型直接生成自然语言步骤，再映射到最接近的可执行动作；SayCan则让模型给技能库里的每个候选技能打分。前者常生成不存在的动作，后者要求枚举所有候选。

ProgPrompt的提示由三部分组成：其一，from actions import grab, putin, open, close, walk... 这样的导入语句，告诉模型机器人有哪些原子动作；其二，objects = [salmon, fridge, microwave, ...]，告诉模型当前环境里有什么；其三，几个完整的示例程序，比如 def throw_away_lime(): 下面一行行调用动作函数，并穿插注释说明子目标、穿插 assert('close' to 'fridge') 这样的检查语句，检查失败时执行恢复动作。新任务只给出函数名（如 def microwave_salmon():），由Codex类模型补全函数体。

作者通过消融给出了提示结构和生成约束的具体建议，例如注释和断言都能提升成功率。方法在VirtualHome家务模拟环境里取得最好的成功率，并在真实机械臂上完成桌面任务。

局限与后续

  • 原子动作和物体列表要人工提供，计划正确与否依赖底层技能是否可靠执行。

读懂它需要的概念

上下文学习与提示 语言模型 零样本与少样本 工具调用

本篇术语

  • VirtualHome　一个模拟家庭环境的平台，智能体可以执行走动、拿取、开关等动作，用来评测家务任务规划。
  • 断言（assert）　程序里检查某个条件是否成立的语句，这里用来确认环境状态，比如是否已靠近冰箱。

怎么学

先读Language Models as Zero-Shot Planners和SayCan了解两种基线，再读ProgPrompt第3节的提示结构；可以用任意代码模型照着论文的提示格式在纸面上规划一个家务任务。
