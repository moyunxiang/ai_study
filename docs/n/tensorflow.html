TensorFlow

TensorFlow: Large-Scale Machine Learning on Heterogeneous Distributed Systems
2015.11系统主干2015-11-09开源（白皮书）；系统论文 OSDI 2016Martín Abadi, Ashish Agarwal, Paul Barham, Eugene Brevdo, Zhifeng Chen, Jeffrey Dean, Rajat Monga, Sanjay Ghemawat et al.（共40位） · Google Brain来源已核对
白皮书（arXiv 1603.04467） ↗OSDI 2016系统论文（arXiv 1605.08695） ↗TensorFlow 2.0发布博客 ↗在交互版中打开（演化树、学习进度）

问题

Google的第一代系统DistBelief只能表达固定的层状网络，研究者难以实现新模型；参数服务器是只有专家能改的特权代码；训练、手机端推理、多GPU、集群各要一套系统，学术界的Theano、Caffe、Torch又不能扩展到大规模分布式。

方法

把一切——模型计算、参数存储与更新、跨设备通信、控制流——都表示成同一张带可变状态的数据流图；运行时把图切分到CPU、GPU、手机乃至上百台机器上执行，并在图上自动求导。以Apache 2.0许可证开源。

影响

一套代码从研究原型一路跑到手机和数据中心，开源后被工业界广泛采用，把大规模分布式训练能力交到普通开发者手里；Google之后在它的整图表示上发展出XLA编译器、TPU软件栈与TensorFlow Lite。

背景

Google Brain从2011年起用第一代系统DistBelief与Downpour SGD训练了大量模型——无监督学习、图像分类、语音识别、搜索与广告。白皮书提到，与Google Brain合作的50多个团队用DistBelief把深度网络部署进了产品。但它有三处硬伤：网络只能按预定义的层来搭，想试一种新的优化器或新层要改C++系统代码；参数服务器（见参数服务器）的更新规则写死在“特权代码”里，研究者改不了；它面向CPU集群，不擅长GPU，也无法把同一个模型放到手机上运行。

与此同时，学术界的框架各有所长：Theano与自动微分有计算图和自动微分，Caffe在单GPU上很快，Torch7灵活好写，但都基本局限在单机。Google需要一个既有学术框架的灵活性、又有DistBelief规模的系统。

方法

数据流图。程序先构建一张图：节点是运算（op，如MatMul、Add、ReLU），边上流动的是张量（多维数组）。白皮书的例子：

W = tf.Variable(tf.random_uniform([784, 100], -1, 1)) relu = tf.nn.relu(tf.matmul(W, x) + b)

这几行只建图，真正计算要通过Session.run(C, feed_dict={x: input})，运行时只执行算出C所需的那部分子图。

可变状态也在图里。Variable是一种特殊的op，返回一个跨多次运行持续存在的张量，用Assign、AssignAdd修改。于是“参数服务器”不再是特殊系统：把变量放在某些机器上、把更新规则写成普通的图运算，就得到一个用户可编程的参数服务器。队列、互斥锁、条件分支（Switch/Merge）和循环（Enter/NextIteration）也都是op。

自动求导。tf.gradients(C, [b, W, x])沿着从C到各输入的路径反向遍历，为每个前向op添加对应的“梯度函数”节点，结果仍是图的一部分（见自动微分与计算图）。

切分与放置。运行时用代价模型模拟执行、贪心地把每个节点放到某个设备上（用户也可以手动指定），然后把跨设备的边替换成一对Send/Recv节点——同一台机器内走PCIe拷贝，跨机器走TCP或RDMA。所有通信被隔离在这对节点里，其余运算的代码与设备无关。跨机器传输时还可以把float32截成16位再传，以节省带宽。

并行方式。数据并行（同步或异步地把多个副本的梯度汇总）和模型并行（把一个模型的不同部分放到不同设备）都只是“同一张图的不同切法”。OSDI论文还加入了备份worker：同步训练时多启动几个副本，每步只取最先完成的m个结果，缓解个别慢机器拖累全体。

结果

白皮书称，与DistBelief相比编程模型更灵活、性能显著更好，几十个内部用户已经迁移，任务从手机上的视觉模型推理到用数百台机器训练数千亿参数的模型。OSDI 2016论文的测试：在单块Titan X上训练四个卷积网络，TensorFlow比Caffe快，与当时最新版Torch相差不到6%（两者都用cuDNN），但在四个模型中的三个上慢于用手写汇编卷积核的Neon；在最多200个K40 GPU worker上训练Inception-v3，同步训练加备份worker最多提升15%吞吐。

后来的发展

TensorFlow开源后被工业界广泛采用，周边生态包括可视化工具TensorBoard、移动端的TensorFlow Lite、为图做整体编译优化的XLA编译器，以及支撑Google TPU的软件栈；Keras后来成为它的官方高层API。Transformer论文的代码发布在基于TensorFlow的tensor2tensor库里，BERT的官方代码也基于TensorFlow，Mesh-TensorFlow张量切分在它上面实现了张量切分。

但“先建图、再Session.run”的模式难调试、难写动态模型，之后很多研究者转向PyTorch（PyTorch论文统计了arXiv论文中提及它的比例自2017年起持续上升）。2019年的TensorFlow 2与Eager把eager执行设为默认、用tf.function按需转成图，与PyTorch的路线更接近；同样出自Google的JAX则以函数变换加XLA编译的方式延续了“整图优化”的思路。

容易误解的地方

  • TensorFlow 1.x的Python代码只是在“描述”计算：relu变量是图里的一个符号，打印它不会得到数值，这正是它难调试的根源。TF 2.x默认eager，行为已经完全不同，读旧代码时要注意版本。
  • “数据流图”并不意味着只能做神经网络：它是通用的带状态数值计算图，但几乎所有优化都围绕深度学习展开。

读懂它需要的概念

自动微分与计算图 反向传播 分布式训练：数据并行与模型并行 随机梯度下降与小批量 CPU、GPU与并行计算 向量、矩阵与张量

本篇术语

  • 数据流图　节点表示运算、边表示数据（张量）流向的有向图。一个节点的所有输入都就绪后即可执行，因此图结构天然暴露了可以并行的部分。
  • Session.run　TF 1.x中执行图的入口：指定要取回的张量和喂入的数据，运行时只执行计算这些张量所必需的子图。
  • Send/Recv节点　图被切分到不同设备后，跨设备的边被替换成成对的发送和接收节点，所有设备间通信都封装在其中。
  • 备份worker　同步数据并行中额外启动的几个副本；每步只聚合最先完成的若干个梯度，避免个别慢机器拖慢整体。

怎么学

先确认会自动微分与计算图和分布式训练：数据并行与模型并行的基本概念。读白皮书第2节（编程模型）、第3.2节（跨设备执行与Send/Recv）和第4.1节（梯度计算），再读OSDI论文第4.4节（同步与备份worker）。动手：在TF 2.x里用tf.function包一个小MLP的训练步，用TensorBoard查看生成的图；再写同样的PyTorch代码，对比静态图与动态图的调试体验。
