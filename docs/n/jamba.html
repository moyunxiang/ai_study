Jamba混合架构

Jamba: A Hybrid Transformer-Mamba Language Model
2024.03论文延伸arXiv 2024Opher Lieber, Barak Lenz, Hofit Bata 等 · AI21 Labs待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

Transformer的KV缓存随长度线性增长、注意力计算量随长度平方增长；Mamba状态空间模型这类状态空间模型成本低，但在需要精确回忆上下文的任务上不如注意力。

方法

把Transformer层和Mamba层交替堆叠，再在部分层里加入MoE，兼顾效果、吞吐和显存。

影响

第一个在大规模上验证的Transformer-Mamba混合架构，之后「少量注意力加大量线性层」成为主流长上下文方案之一。

方法

Jamba的基本单元是把若干Mamba层和少量注意力层交错排列：Mamba层负责便宜地压缩历史，注意力层负责需要精确查找的部分，由于只有少数层有KV缓存，缓存占用比纯Transformer小得多。此外在部分层里把前馈网络换成混合专家（做法参考Mixtral 8x7B），增加总参数但每个token只激活一部分。

摘要称，这个配置可以放进单张80GB GPU，长上下文表现强，最长支持256K token，同时吞吐高、显存占用低。论文还做了消融：Mamba与注意力如何搭配、专家如何放置都对大规模效果有影响。权重以宽松许可开放。

局限与后续

它建立在什么之上

  • 延续
    Transformer2017.06 · LLM
    保留少量注意力层，补足纯状态空间模型在精确回忆上的不足。
  • 改进
    S4结构化状态空间2021.10 · 基础
    语言建模仍落后同规模Transformer，实验最大只到约2.5亿参数，能否扩展到大语言模型未知。
  • 使用
    Mixtral 8x7B2024.01 · LLM
    在部分层引入稀疏专家混合，借鉴Mixtral的做法扩大参数而不增加激活计算。
  • 改进
    RetNet2023.07 · LLM
    论文实验规模最大到数十亿参数，没有在前沿规模上与Transformer正面对比；长上下文的精确回忆能力通常弱于全注意力。
  • 使用
    Mamba状态空间模型2023.12 · 基础
    把Mamba层作为主体，用选择性状态空间模型以线性成本处理长序列。
  • 改进
    门控线性注意力GLA2023.12 · LLM
    只在中等规模的语言建模上验证，在大模型和需要精确回忆的任务上是否追得上softmax注意力没有定论。
  • 改进
    Mamba-2与状态空间对偶2024.05 · 基础
    固定状态的限制仍在，精确检索能力弱于注意力，因此多与注意力层混合使用。
