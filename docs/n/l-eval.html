L-Eval长上下文评测

L-Eval: Instituting Standardized Evaluation for Long Context Language Models
2023.07数据集延伸ACL 2024Chenxin An, Shansan Gong, Ming Zhong, Xingjian Zhao, Mukai Li, Jun Zhang, Lingpeng Kong, Xipeng Qiu · 复旦大学 / 香港大学 / 伊利诺伊大学厄巴纳-香槟分校待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

2023年各家竞相扩展上下文长度，但长上下文模型的评测没有统一标准：数据集零散，常用的n-gram指标也和人的判断对不上。

方法

整理一套覆盖多领域、多题型的长文档评测集，并系统研究长回答该用什么指标评，提出按长度指令约束输出、改用大模型裁判。

影响

与LongBench同期成为2023年长上下文模型最常用的评测之一，它对评测指标的分析也推动了长文本任务改用模型裁判。

方法

数据。共20个子任务、508篇长文档、2000多条人工标注的问答对，输入长度从3千到20万词元，领域包括法律、金融、学术论文、小说、会议记录、代码等；题型分为有标准答案的封闭式任务（多选、判断、数学）和开放式生成任务（摘要、问答）。

指标研究。作者发现，开放式长回答用ROUGE等n-gram匹配指标打分，与人工判断相关性差，主要原因之一是模型回答长短不一。为此提出“长度指令增强”评测：在问题里告诉模型参考答案大约多少词，让输出长度可比；同时提倡用大模型裁判打分。

结果。评测了4个商业模型和12个开源模型，当时GPT-4、Claude这类商业模型基本能在长上下文中保持推理能力，开源模型仍处于早期阶段。

局限与后续

  • 不少文档和题目来自已有公开数据，存在被训练数据覆盖的风险；样本量较小，子任务间分数波动大。
    本站还没有记录针对它的后续工作（不代表没有人解决）

    LongBench长上下文2023.08 · 数据·评测
