封建式分层RL

Feudal Reinforcement Learning
1993论文延伸NeurIPS 1992（论文集1993）Peter Dayan, Geoffrey E. Hinton · 多伦多大学待核对
NeurIPS ↗在交互版中打开（演化树、学习进度）

问题

强化学习要在很多步之后才得到奖励，平铺的单层决策很难学长任务。

方法

把智能体组织成像封建等级的管理者和下属：上级给下级设定目标，下级只负责在更细的尺度上完成目标并得到奖励。

影响

分层强化学习最早的方案之一，影响了options和后来的FeUdal Networks。

方法

封建式强化学习把状态空间按不同分辨率划分，形成等级：高层管理者在粗糙的空间里决定“下一步让下属去哪里”，低层下属接受命令，在更细的空间里决定具体动作。下属因完成命令而得到奖励，不必关心整个最终目标；高层也不必知道低层的细节，这叫信息隐藏。

这样长任务被拆成几个短任务，奖励传播的路径变短，学习更快。论文在迷宫任务中验证了这个思路。

后来的发展

Options时间抽象框架把“子策略加终止条件”形式化；FeUdal Networks用神经网络重做了这个想法。

局限与后续

  • 层级结构需要人手工设计，不能自动发现。
    后来针对它的工作　Option-Critic
  • 只在小迷宫上实验。
    后来针对它的工作　FeUdal Networks

它建立在什么之上

  • 使用
    Q-learning1992 · RL
    每一层的管理者都用Q学习更新自己的价值。

后来的相关工作

  • 竞争
    Options时间抽象框架1999 · RL
    封建式RL用固定的管理者-下属层级传达目标；options不规定层级结构，任何闭环子策略都可以和原始动作混用。
  • 延续
    MAXQ值函数分解1999.05 · RL
    同为分层RL，MAXQ给出明确的价值函数加性分解与收敛证明。
  • 延续
    h-DQN分层DQN2016.04 · RL
    延续上层给下层下达子目标的分层结构。
  • 改进
    Option-Critic2016.09 · RL
    层级结构需要人手工设计，不能自动发现。
  • 延续
