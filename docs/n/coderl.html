CodeRL单元测试强化学习

CodeRL: Mastering Code Generation through Pretrained Models and Deep Reinforcement Learning
2022.07论文延伸NeurIPS 2022Hung Le, Yue Wang, Akhilesh Deepak Gotmare, Silvio Savarese, Steven C. H. Hoi · Salesforce Research待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

代码生成模型通常只用“题目—标准答案”对做监督微调，完全不用单元测试这类能自动判断程序对错的信号，在复杂的新题上表现很差。

方法

把代码生成模型当作演员（actor），训练一个评论家（critic）网络预测生成程序能否通过单元测试，给演员提供逐词的密集反馈做强化学习；推理时再根据示例测试结果和评论家分数自动修改、重新生成程序。

影响

较早系统地把单元测试结果作为强化学习奖励用于代码生成，在APPS上取得当时最好成绩，并零样本迁移到MBPP，是后来“以执行结果为奖励训练代码模型”的先例。

方法

背景：CodeT5、Codex等模型的训练目标是最大化标准答案的似然，即模仿人写的程序。但代码有一个自然语言没有的优势：可以运行单元测试自动判断对错。APPS等竞赛题基准正好提供了每道题的测试。

训练（演员—评论家）：

  • 演员：一个预训练的代码生成模型（作者扩展了CodeT5的编码器—解码器结构，用更大的模型、更好的预训练数据和改进的目标），先做常规监督微调；
  • 奖励：对演员生成的程序运行单元测试，按结果分四档：编译错误、运行时错误、测试失败、全部通过，分别给不同的奖励值；
  • 评论家：另一个网络，读入题目和生成的程序，预测它会落在哪一档。用评论家对每个词元的预测概率作为密集的逐词信号，告诉演员程序的哪一部分最可能导致失败；
  • 策略梯度：以奖励（减去基线）乘以对数似然的梯度更新演员，即REINFORCE策略梯度式的目标，同时保留监督学习的损失。

推理（评论家采样）：先生成一批程序，用题目给出的示例测试运行。通过的程序拿去做程序修复的种子：评论家指出可能出错的位置，模型从那里截断并重新生成；没通过的程序则交给一个修复模块，根据错误信息修改。这样可以在推理时迭代改进。

结果（摘要）：在困难的APPS基准上取得新的最好结果，并在更简单的MBPP上零样本迁移，也取得最好结果。

后来的发展

单元测试作为奖励、评论家指导重采样的思路，被PPOCoder、RLTF等后续工作沿用；到2024–2025年，以可验证奖励训练代码和推理模型成为主流做法。

局限与后续

  • 奖励只按四档粗粒度划分，全部通过之外的程序得不到“差多少”的细致反馈；训练需要每道题都有可执行的单元测试。

读懂它需要的概念

策略梯度 Actor-Critic与优势函数 奖励设计与奖励投机 预训练与微调 编码器-解码器

本篇术语

  • 演员—评论家　强化学习的一种结构：演员负责产生动作（这里是生成程序），评论家负责估计这些动作有多好，并用估计帮助演员更新。
  • 密集反馈　不是只在整段程序结束后给一个分数，而是对每个词元都给出信号，指出哪里可能出了问题。

怎么学

先补REINFORCE策略梯度的策略梯度与基线；读本文第3节奖励分档、评论家训练和第4节评论家采样；动手：在MBPP的几道题上，对一个小代码模型的采样程序运行测试并按四档打分，统计各档分布，体会这种奖励的稀疏程度。
