llm.c

2024.04系统延伸Andrej Karpathy待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

训练一个GPT-2要依赖PyTorch这样的庞大框架，读者很难看清从数据到梯度每一步究竟在做什么。

方法

用纯C和CUDA从零实现GPT-2的训练：手写每层的前向和反向，不依赖PyTorch和Python。

影响

成为理解LLM训练底层细节的教学项目，也直接催生了后续的speedrun类项目。

方法

llm.c在nanoGPT之后，把整个训练循环下沉到C：train_gpt2.c是约一千行的CPU fp32参考实现，train_gpt2.cu是追求速度的CUDA主线。每一层（嵌入、LayerNorm、注意力、MLP、交叉熵）的前向和反向都是手写的，内存一次性按所需大小分配。仓库还附带一个对照的PyTorch版本train_gpt2.py，用来核对数值。当前重点是复现GPT-2和GPT-3系列小模型的预训练。

仓库README称，目前它比PyTorch Nightly快约7%（作者自述）。

后来的发展

其GPT-2复现设置（在FineWeb上达到3.28验证损失、约45分钟）成为modded-nanogpt速通速通的基线。

局限与后续

  • 手写内核难以跟上新架构和新硬件，主流模型的变体支持有限。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 规模停留在小模型的复现，不是多机大模型训练系统。
    后来针对它的工作　TorchTitan
