IBM Granite Code

Granite Code Models: A Family of Open Foundation Models for Code Intelligence
2024.05论文延伸Mayank Mishra, Matt Stallone, Gaoyuan Zhang, Yikang Shen, Aditya Prasad, Adriana Meza Soria, Michele Merler et al. · IBM Research待核对
arXiv ↗模型 ↗在交互版中打开（演化树、学习进度）

问题

企业要把代码模型用到软件开发流程里，既需要代码生成、修错、解释、仓库维护等多种能力，也需要规模从端侧到服务器可选、训练数据来源清楚、许可证允许商用的模型。

方法

IBM发布3B到34B的纯解码器代码模型家族，用116种编程语言的代码训练，针对企业软件开发工作流优化，全部以Apache 2.0许可开源。

影响

在开源代码模型中给出一个许可证宽松、数据治理透明的选择，多项代码任务上达到同规模开源模型的领先水平，是2024年企业场景中常被比较的开源代码模型之一。

方法

背景：2023–2024年，开源代码模型已经有StarCoder、StarCoder2与Stack v2、Code Llama、DeepSeek-Coder等，但企业用户还关心几件事：训练数据的许可证是否干净、是否有适合内存受限设备的小模型、是否除了“写新代码”外也擅长修bug、解释代码、做老系统现代化改造。

模型家族：Granite Code包括3B、8B、20B、34B四个规模的纯解码器模型，每个规模都有基础版和指令版。小模型面向端侧和内存受限场景，大模型面向复杂的应用现代化（例如把老的COBOL系统迁到新语言）任务。

训练：代码数据覆盖116种编程语言，基础模型分两阶段训练：先在大量代码上预训练，再混入高质量的代码与自然语言数据继续训练，以提升推理和遵循指令的能力；训练中加入中间填充FIM式的中间填空目标，支持IDE里的补全。指令版在代码提交信息、合成的代码指令数据和开源指令数据上微调。34B模型据作者介绍是把20B模型的层复制叠加后继续训练得到的（深度扩展）。

数据治理：作者强调数据来源和过滤：按许可证筛选、去除个人信息和恶意代码、精确与模糊去重。

结果（摘要）：在包括代码生成、修复、解释在内的一系列任务上，Granite Code在可用的开源代码模型中持续达到最好水平；全部模型以Apache 2.0许可发布，可用于研究和商业用途。

后来的发展

Granite Code之后IBM把代码能力并入通用的Granite 3系列；它的多规模、宽松许可和数据治理说明，是企业选型时比较开源代码模型的参照之一。
