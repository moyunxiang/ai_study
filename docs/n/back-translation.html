回译

Improving Neural Machine Translation Models with Monolingual Data
2015.11论文重要ACL 2016Rico Sennrich, Barry Haddow, Alexandra Birch · 爱丁堡大学待核对
arXiv ↗ACL Anthology ↗在交互版中打开（演化树、学习进度）

问题

神经翻译只能用成对的平行语料训练，而目标语言的单语文本多出几十倍却用不上；统计翻译靠单独的语言模型吸收单语数据，神经翻译没有现成的接口。

方法

先训一个反方向的翻译模型，把目标语言的单语句子“翻回”源语言，得到“机器译出的源句 + 真人写的目标句”这样的合成平行句对，混进真实平行语料里一起训练，网络结构一点不改。

影响

WMT15英德翻译涨了2.8–3.7 BLEU，此后回译成为机器翻译的标准配置，从WMT冠军系统、无监督翻译到NLLB都依赖它；“用模型生成训练数据”的思路也延续到今天大模型的合成数据。

背景

统计机器翻译（如短语统计机器翻译）把翻译拆成两部分：翻译模型负责“意思对”，用平行语料训练；语言模型负责“说得通顺”，可以用海量单语文本训练。目标语言的单语数据往往比平行语料多出一两个数量级，所以语言模型是统计翻译提升流利度的主要来源。

神经翻译（Seq2Seq、注意力机制）是一个端到端网络，只吃平行句对。此前的尝试是另外训练一个语言模型，再在解码时把它和翻译模型的输出融合（浅融合、深融合），这要改网络，效果也有限。作者注意到：神经翻译的解码器本身就是一个以源句为条件的RNN语言模型，应该可以直接用单语数据训练它，问题是单语句子没有源句可配。

方法

论文比较了两种给单语句子补源句的方法。

空源句（dummy source）。源句只放一个<null>符号，按1:1和平行数据混合，训练单语样本时冻结编码器和注意力。问题是单语比例一高，网络就学会忽略源句，忘掉“看原文翻译”这件事。

合成源句（回译）。以英→德为例：

  • 先用已有平行语料训练一个德→英模型；
  • 用它把德语单语句子翻成英语，得到质量一般的英语句子；
  • 把（机器英语，真人德语）当作新的平行句对，和真实平行语料混在一起，训练英→德模型，不做任何区分，也不冻结参数。

关键在于：只有源端是合成的，目标端是真人写的句子。模型的输出侧始终在学习自然流畅的目标语言，即使输入有噪声，也不会学会生成错误的句子。论文中英→德从1.6亿句德语单语中抽了360万句回译，WMT平行语料约420万句；子词切分沿用作者同期的BPE子词切分。

结果

WMT15英→德（newstest2015）BLEU：只用平行语料单模型22.8、4模型集成23.6；加空源句单语数据23.2 / 24.6；加回译数据25.7 / 26.5，比基线高约3 BLEU。把基线继续训练一周则没有提升。低资源的IWSLT14土耳其→英语（平行语料仅32万句）提升2.1–3.4 BLEU。分析发现回译数据推迟了过拟合，并让模型生成更多自然的词；回译模型本身的质量差6 BLEU时，最终翻译只差0.6–0.7 BLEU，说明方法对回译质量并不敏感。

后来的发展

回译成为神经翻译的标准做法。无监督神经机器翻译把它和去噪自编码交替迭代，在完全没有平行语料时也能训出翻译模型；中英新闻翻译“人类水平”等系统用大规模回译数据冲击人类水平；NLLB两百种语言翻译在200种语言上同时使用回译和挖掘数据。“用模型为无标注数据造训练样本”的思路后来也出现在Noisy Student自训练和Self-Instruct等合成数据方法中。

局限与后续

  • 需要先有一个能用的反向翻译模型，平行语料极少或为零的语言对无从起步。

  • 只做一轮回译，回译模型本身不会因新数据而变好，两个方向的模型没有互相迭代提升。

读懂它需要的概念

编码器-解码器 语言模型 半监督学习与伪标签 注意力机制 文本生成的自动指标

本篇术语

  • 平行语料 / 单语语料　平行语料是逐句对齐的原文和译文；单语语料只有一种语言的文本，数量通常大得多。
  • 回译（back-translation）　把目标语言句子用机器翻译回源语言，从而为单语数据人为补上源句，构造合成的平行句对。

怎么学

先补编码器-解码器和文本生成的自动指标里的BLEU，读过Seq2Seq。读原文第3节（两种补源句方法以及空源句为什么失败）和表3。动手：用一个现成的开源翻译模型，把几千句目标语言单语文本翻成源语言，和少量真实平行句混在一起微调一个小模型，对比加与不加回译数据的BLEU。
