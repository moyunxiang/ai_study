TVM深度学习编译器

TVM: An Automated End-to-End Optimizing Compiler for Deep Learning
2018.02论文重要OSDI 2018陈天奇（Tianqi Chen）, Thierry Moreau, Ziheng Jiang, Lianmin Zheng, Eddie Yan, Meghan Cowan, Haichen Shen, Leyuan Wang et al. · 华盛顿大学等待核对
arXiv ↗Apache TVM官网 ↗在交互版中打开（演化树、学习进度）

问题

深度学习框架的性能依赖厂商手写的算子库（如cuDNN），只覆盖少数服务器GPU；要把模型部署到手机CPU、移动GPU或新加速器上，每个算子、每种硬件都要专家重新手工优化。

方法

做一个端到端的深度学习编译器：在计算图层面做算子融合等优化，在算子层面沿用Halide“计算与调度分离”的思想生成各种实现，再用一个机器学习代价模型在巨大的调度空间里自动搜索最快的版本。

影响

开创了“深度学习编译器加自动调优”这条路线，让同一模型可移植地跑在CPU、GPU、FPGA等硬件上；后来成为Apache项目，其思想影响了Ansor、MLIR生态和MLC LLM等后继工作。

背景

2018年，TensorFlow、MXNet、PyTorch等框架把计算图中的每个算子交给厂商库执行——卷积用cuDNN、矩阵乘法用cuBLAS。这有两个问题。第一，库只针对少数服务器级GPU精心优化，手机CPU、移动GPU、FPGA和各种新的专用芯片要么没有库，要么性能很差，移植要大量手工劳动。第二，图层面的优化受限于库：想把卷积、偏置加法、ReLU融合成一个内核以省掉中间结果的读写，就必须库里恰好有这个融合版本；新算子不断出现，可能的融合组合数爆炸式增长。

XLA编译器尝试用编译器为TensorFlow做融合，但主要面向自家后端；图像处理领域的Halide：算法与调度分离提出把“算什么”和“怎么算”分开，却没有处理GPU共享内存协作、专用张量指令和加速器上的访存延迟隐藏等深度学习特有的问题。

方法

TVM分成三层。

图层优化。从各种框架（TensorFlow、MXNet、PyTorch、Keras、CNTK）导入模型，在计算图上做常量折叠、内存规划、数据布局变换和算子融合。论文把算子分成四类：一对一映射（如加法）、归约（如求和）、可在输出端融合逐元素运算的复杂算子（如conv2d）和不可融合的算子（如排序），再用通用规则融合。例如“conv2d → 加偏置 → ReLU”合成一个内核，中间结果不写回显存；论文测得融合带来1.2到2倍加速。

张量表达式与调度。每个算子用张量表达式描述“算什么”，例如矩阵乘法C[i, j] = Σ_k A[i, k]·B[j, k]；再用调度原语描述“怎么算”：分块、循环重排、展开、向量化、绑定GPU线程。在Halide的基础上增加了三类新原语：GPU上线程协作地把数据搬进共享内存；张量化——把一段计算替换成硬件的专用指令（如加速器的8×8矩阵乘指令），且新硬件只需声明这条指令就能被利用；显式的访存延迟隐藏——为没有硬件多线程的加速器生成流水线，让数据搬运和计算重叠。

基于机器学习的自动调优。分块大小、循环顺序、缓存、展开等选择组合起来构成巨大的调度空间，逐个上机测试太慢，手写代价模型又难以跟上硬件复杂度。TVM的做法是：用梯度提升树（基于XGBoost）从循环程序中抽取特征，预测每个候选的运行时间；用并行模拟退火在空间中游走，挑出预测最快的一批真正在硬件上测量，再把测量结果加入训练数据更新模型。这样只需少量真机测试就能找到接近最优的实现。

结果

在服务器GPU（Titan X）、嵌入式GPU（Mali）、嵌入式CPU（ARM A53）和一个基于FPGA的通用深度学习加速器上测试。论文称相对依赖手工优化库的现有框架加速1.2到3.8倍；在Titan X上对比MXNet、TensorFlow和TensorFlow XLA（前两者用cuDNN v7），端到端加速1.6到3.8倍。在FPGA加速器上，延迟隐藏把峰值算力利用率从70%提高到88%。

后来的发展

TVM成为Apache基金会项目，“深度学习编译器”此后成为独立的研究方向：后续的Ansor去掉了手写调度模板，MLIR提供了更通用的多层编译基础设施，MLC LLM与WebLLM用TVM系列编译器把大语言模型部署到手机、浏览器等各种设备。在训练侧，Triton GPU编程语言让研究者用Python写分块的GPU内核，PyTorch 2与torch.compile的torch.compile把图捕获和内核生成纳入主流框架，都可以看作同一思路在不同层面的落地。

容易误解的地方

  • TVM的自动调优是“搜索+学习代价模型”，不是让神经网络直接生成代码；代价模型只负责给候选调度排序，最终仍要上机测量。
  • 它主要面向推理部署：训练所需的反向传播、优化器和分布式并行不在这篇论文的范围内。

局限与后续

  • AutoTVM需要专家为每类算子手写调度模板来定义搜索空间，且为每个模型、每种硬件调优往往要很长时间。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 假设张量形状在编译时固定，对序列长度不断变化的语言模型等动态形状支持不足。
    后来针对它的工作　MLC LLM与WebLLM
  • 图层融合规则固定、只在算子层面搜索循环结构，无法自动发现像分块重算softmax这样改变算法本身的优化。

  • 与训练框架是分离的两套系统，研究者在训练阶段仍要靠手写CUDA内核获得性能。

读懂它需要的概念

CPU、GPU与并行计算 显存、内存带宽与“内存墙” 矩阵乘法与线性变换 卷积层、池化与感受野 决策树 晶体管、制程与摩尔定律

本篇术语

  • 调度（schedule）　描述一个计算如何在硬件上执行的方案：循环怎样分块、按什么顺序、哪些部分并行、数据放在哪一级存储。改变调度不改变计算结果，只改变速度。
  • 算子融合　把计算图中相邻的多个算子合成一个内核，中间结果留在寄存器或片上缓存里，不写回显存。
  • 张量化（tensorize）　把一段循环计算替换成硬件提供的专用张量指令，如一次完成8×8矩阵乘的加速器指令。
  • 自动调优　在大量可能的实现中自动搜索在目标硬件上最快的一个，通常结合代价模型和真机测量。

怎么学

先补显存、内存带宽与“内存墙”和CPU、GPU与并行计算，理解为什么同一个矩阵乘法换个循环顺序速度会差很多倍。读论文第3节（图优化）、第4节（张量表达式与调度）和第5节（自动优化器）。动手：按TVM官方教程用张量表达式写一个矩阵乘法，依次加上分块、向量化、并行三个调度，记录每一步的速度变化；再试一次自动调优。
