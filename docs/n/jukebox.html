Jukebox

Jukebox: A Generative Model for Music
2020.04论文重要arXiv 2020Prafulla Dhariwal, Heewoo Jun, Christine Payne, Jong Wook Kim, Alec Radford, Ilya Sutskever · OpenAI待核对
arXiv ↗代码 ↗在交互版中打开（演化树、学习进度）

问题

符号音乐模型（如Music Transformer）只能生成乐谱，没有人声和真实音色；直接生成原始音频的WaveNet几秒后就失去连贯性，因为一首4分钟的歌有1000万个采样点。

方法

先用三层VQ-VAE把44.1kHz音频分别压缩8、32、128倍变成离散token，再用自回归Transformer在最粗的一层上生成，逐层“上采样”回细节，并以歌手、流派和歌词为条件。

影响

第一次从零生成带人声演唱、长达数分钟、风格可控的完整歌曲音频，确立了“音频压缩成离散token + 语言模型生成”的路线，后来的AudioLM、MusicLM、MusicGen都沿用这一思路。

背景

音乐生成此前有两条路。一条是符号音乐：Music Transformer等模型生成MIDI音符序列，结构好，但只有音符，人声、音色、混音都要另外渲染。另一条是直接生成波形：WaveNet能做出几秒好听的片段，但CD音质每秒44100个采样点，一首4分钟的歌超过1000万个点，远超任何自回归模型的上下文，几秒后风格和乐器就会漂移。另一方面，VQ-VAE和VQ-VAE-2已经证明可以把图像压缩成离散码再在码上训练先验，GPT-2则证明大规模Transformer能建模很长的token序列。Jukebox把两者结合用于音频。

方法

第一步：多层VQ-VAE压缩（见向量量化与离散token、自编码器）。三个独立的自编码器分别把波形压缩8倍、32倍、128倍，编码器输出的每个向量都替换成码本（2048个向量）中最近的那个，于是音频变成三条不同粗细的离散token序列。编码器和解码器是WaveNet风格的非因果空洞卷积。除了波形重建损失，还加了多分辨率频谱损失，否则高频细节会丢；码本里长期没被用到的向量会被随机重置，防止“码本坍塌”。

第二步：分层先验。概率分解为p(z) = p(z_top)·p(z_mid|z_top)·p(z_bot|z_mid, z_top)。顶层先验是50亿参数的自回归Sparse Transformer（见稀疏注意力、自回归生成），上下文8192个token，在顶层约合24秒音频；中层和底层各有一个10亿参数的“上采样器”，以上一层的token为条件补出细节。更长的歌用滑动窗口续写。

第三步：条件控制。每首歌的歌手、流派标签和“当前已播放到全曲的百分之几”作为条件输入。歌词条件用编码器-解码器结构：歌词字符先经编码器，音乐解码器通过交叉注意力学会何时唱哪个字；训练时用Spleeter分离出人声、再用自动对齐工具把歌词粗略对到每个片段上。

结果

训练数据是从网上收集的120万首歌（其中60万首英文），配LyricWiki的歌词和元数据。VQ-VAE在256块V100上训练3天；两个上采样器在128块V100上训练2周；顶层先验在512块V100上训练4周。生成的样例覆盖摇滚、嘻哈、爵士等流派，能模仿指定歌手的嗓音，歌词与旋律能对上。但代价极高：生成1分钟顶层token约需1小时，再上采样到音频约需8小时。作者也指出样本缺少副歌重复这类大尺度结构，细节处常有杂音。

后来的发展

Jukebox的生成速度让它几乎无法实用，但它的框架被继承了下来：先用神经编解码器把音频变成离散token，再用语言模型生成。神经音频编解码器和EnCodec提供了更高保真的音频token，AudioLM把语义token与声学token分层，MusicLM与音乐生成和MusicGen把条件换成自由文本描述并大幅提速。Jukebox的中间层表示后来也被用作音乐理解任务的特征。

  • 延续
    GPT-22019.02 · LLM
    沿用OpenAI用大规模自回归Transformer做生成式预训练的思路，把对象从文本token换成音频token。
  • 使用
    VQ-VAE2017.11 · 生成
    用VQ-VAE把原始音频压缩成离散码，让Transformer能在可承受的长度上建模。
  • 改进
    NSynth2017.04 · 语音
    只覆盖单个音符，不是完整乐曲；音高、响度等不能被显式控制。
  • 竞争
    Music Transformer2018.09 · 语音
    Music Transformer生成符号音符，结构强但没有真实音色和人声；Jukebox直接生成音频，音色真实但结构较弱。
  • 使用
    稀疏注意力2019.04 · LLM
    顶层先验和上采样器都是Sparse Transformer，以处理8192个token的长上下文。
  • 延续
    VQ-VAE-22019.06 · 生成
    借鉴VQ-VAE-2的多层级码本，但改为三个独立训练的自编码器，并加入频谱损失和码本重置。

本篇术语

  • 码本坍塌　VQ-VAE训练中只有少数码本向量被使用、其余长期闲置，等于压缩容量大幅缩水。Jukebox把闲置向量随机重置到当前编码附近来缓解。
  • 上采样器（upsampler）　这里指以粗粒度token为条件、生成细粒度token的自回归模型，作用是给粗略的音乐骨架补上音色和细节。
