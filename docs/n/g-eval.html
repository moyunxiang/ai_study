G-Eval大模型评分

G-Eval: NLG Evaluation using GPT-4 with Better Human Alignment
2023.03论文延伸EMNLP 2023Yang Liu, Dan Iter, Yichong Xu, Shuohang Wang, Ruochen Xu, Chenguang Zhu · 微软待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

BLEU、ROUGE这类依赖参考答案的指标与人工判断相关性低，尤其在需要创造性的生成任务上；早期用大模型直接打分的方法，与人的一致性还不如中等规模的神经评估器。

方法

让GPT-4先根据评价标准自动写出评估步骤（思维链），再按“填表”的格式给摘要或对话的某个维度打分，作为无需参考答案的评测指标。

影响

在摘要评测上与人工判断的Spearman相关达0.514，大幅超过此前方法，是“大模型当裁判”在自然语言生成评测中的早期代表；论文也提示了大模型评估器可能偏爱大模型生成文本的风险。

方法

G-Eval把评测写成一段提示，包含三部分：任务介绍、评价标准（例如摘要的“连贯性”定义），以及由大模型自己根据前两部分生成的评估步骤——这一步就是让模型先想清楚“该怎么评”，即思维链CoT。然后把待评文本放进一个“表格”，要求模型只输出某个维度的分数（如1到5分）。

这样得到的是一个无需参考答案的指标：只要写清评价标准，就能用于没有人工参考答案的新任务，而ROUGE、BERTScore这类指标都要先有参考文本。

作者在两个生成任务上实验：文本摘要和对话生成。用GPT-4作为骨干时，G-Eval在摘要任务上与人工评分的Spearman相关为0.514，大幅超过此前所有方法。论文还初步分析了大模型评估器的行为，指出它可能偏爱由大模型生成的文本——如果用同类模型既生成又评测，分数可能被抬高。

局限与后续

  • 评估器本身有偏好：可能偏爱大模型生成的文本，且分数受提示写法和模型版本影响。

它建立在什么之上

  • 使用
    思维链CoT2022.01 · 推理·智能体
    先让模型生成评估步骤再打分，把思维链用于评测。
  • 使用
    GPT-42023.03 · LLM
    以GPT-4为评估骨干，摘要上与人工的Spearman相关0.514。
  • 改进
    ROUGE2004.07 · 数据·评测
    ROUGE与人工判断相关性低，G-Eval直接按评价标准打分，显著提高了一致性。
  • 改进
    BERTScore2019.04 · 数据·评测
    BERTScore等神经指标仍需参考答案，G-Eval无需参考且与人工相关更高。
  • 改进
    MoverScore推土机距离指标2019.09 · 数据·评测
    仍需要参考答案，开放式生成里合理答案很多时同样会误判；计算最优运输比逐词匹配慢。
  • 改进
    SAMSum对话摘要2019.11 · 数据·评测
    论文自己指出ROUGE与人工判断不一致，但没有给出替代指标，后来的工作多改用人工评测或大模型打分。
  • 改进
    BARTScore生成式指标2021.06 · 数据·评测
    分数依赖BART自身的偏好，倾向于给常见、流畅的措辞高分，对长文本和与预训练分布差别大的领域可靠性下降。
  • 改进
    UniEval多维度评估器2022.10 · 数据·评测
    各维度的负例靠规则扰动构造，模型学到的可能是识别这些扰动而非真正的质量；很快被直接用大模型打分的方法超过。
  • 改进
    GPTScore大模型概率打分2023.02 · 数据·评测
    需要拿到模型的逐词概率，闭源聊天模型往往不提供；分数受提示措辞影响大，不同方面的分数尺度也不统一。

读懂它需要的概念

文本生成的自动指标 语言模型 上下文学习与提示 方差、种子与统计显著性

本篇术语

  • 无参考指标　不需要人工写的标准答案，直接根据输入和输出判断质量的自动评测方法。
  • Spearman相关　比较两组打分的排名是否一致的相关系数，1表示排序完全一致，0表示无关。

怎么学

先了解ROUGE和BERTScore的局限。读G-Eval原文第2节的提示结构；动手选20篇摘要，用一个强模型按G-Eval格式给“连贯性”打分，再与人工打分算Spearman相关。
