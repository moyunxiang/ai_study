TPU v4与光路交换

TPU v4: An Optically Reconfigurable Supercomputer for Machine Learning with Hardware Support for Embeddings
2021.05硬件延伸ISCA 2023Norman P. Jouppi, George Kurian et al. · Google待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

大模型训练需要数千块芯片协同，传统电交换网络要么造价高、要么一个节点故障就拖垮整个任务，且难以按需重组拓扑。

方法

TPU v4用光路交换机（OCS）动态重组芯片间的互连拓扑，并加入SparseCore专门加速嵌入层，组成4096块芯片的超级计算机。

影响

OCS证明了在大规模AI集群里用光交换换取可用性与灵活性可行，TPU v4也是论文里与A100对比的主要参照。

方法

按arXiv摘要，TPU v4是Google第五代领域专用架构、第三代机器学习超算。OCS动态重构互连拓扑，用户可选扭曲3D环面；光交换机及相关光学部件成本占系统不到5%、功耗不到3%，比InfiniBand便宜、低功耗且更快。每颗TPU v4带SparseCore（数据流处理器），将依赖嵌入的模型加速5至7倍，却只占5%的芯片面积和功耗。

整机最多4096块芯片，比上一代大4倍。故障时只需让OCS绕开坏的块，不必整台停机；用户还可以按任务需要重新切分拓扑。这套‘把网络做成可编程’的思想，延续了TPU v2/v3与TPU Pod用高速专用互连连成Pod的做法。

结果

论文称TPU v4比TPU v3快2.1倍、每瓦性能提高2.7倍；4096芯片的整机约快10倍；与相近规模的A100系统相比快1.2至1.7倍且功耗低1.3至1.9倍，与Graphcore IPU Bow相比快约4.3至4.5倍（均为论文自述）。

后来的发展

OCS思路后来被Google用到TPU v5p及更新的Pod中（见TPU v5e/v5p），也促使业界讨论光互连（共封装光学交换机）。

局限与后续

  • OCS重配置需要毫秒到秒级时间，不适合每步都变拓扑的负载。

它建立在什么之上

  • 改进
    Google TPU2016.05 · 硬件 待核对
    单芯片作为PCIe协处理器工作，芯片之间没有高速互连，无法把一个大模型分到多颗芯片上协同计算。
  • 改进
    TPU v2/v3与TPU Pod2017.05 · 硬件
    把TPU Pod的专用互连升级成可重构的光路交换网络，并把规模扩大4倍到4096芯片。
  • 改进
    Eyeriss数据流加速器2016.06 · 硬件
    只针对卷积层，全连接层和后来的注意力、稀疏计算不在设计之内。

后来的相关工作

  • 竞争
    H1002022.03 · 硬件 已核对
    同一时期训练大模型的两条路线：谷歌TPU v4以4096颗芯片组成SuperPod，是谷歌自研的专用芯片；H100是跑CUDA生态的通用GPU，由各家公司采购后自建集群。
  • 使用
    PaLM2022.04 · LLM
    在两个TPU v4 Pod共6144块芯片上训练，是当时公开描述的最大TPU配置。
  • 改进
    TPU v5e/v5p2023.12 · 硬件
    同样的3D环面互连思路，把Pod规模做到8960块芯片，算力超过v4的两倍。
