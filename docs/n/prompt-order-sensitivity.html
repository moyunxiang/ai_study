示例顺序敏感性

Fantastically Ordered Prompts and Where to Find Them: Overcoming Few-Shot Prompt Order Sensitivity
2021.04论文延伸ACL 2022Yao Lu, Max Bartolo, Alastair Moore, Sebastian Riedel, Pontus Stenetorp · UCL / Mishcon de Reya待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

GPT-3式少样本提示里，只把同样几条示例换个顺序，准确率就能从接近最优掉到接近随机猜测，没人知道怎么挑顺序。

方法

把所有排列当作候选，让模型自己生成一份“人造验证集”，再用各排列在这份数据上预测分布的熵统计来挑出好顺序，不需要额外标注数据。

影响

证明少样本提示的脆弱性是系统性问题而非个别现象，推动了后来对示例选择、校准和稳健提示的研究。

方法

背景：GPT-3之后，大家用几条示例拼成提示就能做分类，被称为上下文学习与提示。但提示的细节很敏感，先校准再用已经发现标签偏向问题。

这篇论文专门研究示例顺序。做法是对同一组少量训练样本枚举不同排列，在多个文本分类任务上测试。结论有三点：顺序敏感在各种模型规模下都存在，包括当时最大的模型；它和具体选了哪几条示例无关；某个模型上的好顺序换到另一个模型上并不通用。

解决思路是：如果用带标注的开发集来挑顺序，就违背了“只有几条样本”的少样本设定。作者改为让语言模型根据这些示例自己生成一批文本当作人造开发集，然后对每个候选排列统计模型在这批文本上预测标签的熵（预测越平衡、越不偏向某一类，越好），选熵统计最好的排列。摘要报告在11个文本分类任务上，GPT系列模型相对提升13%。

局限与后续

  • 挑好顺序需要对排列做枚举和打分，示例一多，排列数爆炸，推理成本高。
    本站还没有记录针对它的后续工作（不代表没有人解决）
  • 方法针对分类任务的标签预测熵设计，对开放式生成任务不直接适用；好顺序也不能跨模型迁移，换模型要重新选。
