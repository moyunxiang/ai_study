InCoder代码补全

InCoder: A Generative Model for Code Infilling and Synthesis
2022.04论文延伸ICLR 2023Daniel Fried, Armen Aghajanyan, Jessy Lin, Sida Wang, Eric Wallace, Freda Shi, Ruiqi Zhong, Wen-tau Yih, Luke Zettlemoyer, Mike Lewis · Meta AI / CMU / UW / UC Berkeley / TTIC待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

Codex这类模型只会从左到右续写，而写代码经常是回头修改、在中间插入。

方法

训练时把代码里随机一段遮掉并移到文件末尾，让模型既能从左到右生成，也能用左右两侧上下文做代码填充。

影响

成为第一个能零样本做代码填充的生成模型，并预示了后来的填充中间（FIM）训练在代码模型里的普及。

方法

背景：写程序不是一次性线性完成的。补全函数体里缺的一段、给变量改名、推断类型，都需要同时看到前后文。

做法：InCoder在大量许可宽松的代码上训练。训练时随机选取一段代码替换成一个哨兵标记，并把这段内容移到文件末尾，模型照常从左到右预测，但因此学会了根据两侧上下文生成中间缺失的代码。推理时可以直接做普通续写，也可以在代码中间留出空位让模型填。

结果：论文称这是第一个能直接零样本做代码填充的生成模型，在类型推断、注释生成、变量重命名等任务上，利用双向上下文能显著提高表现，同时在标准程序合成基准上与同规模从左到右模型相当。

局限与后续

  • 训练的重排方式让模型更复杂，对很长的文件和跨文件上下文支持有限。
