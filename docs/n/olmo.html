OLMo完全开放模型

OLMo: Accelerating the Science of Language Models
2024.02论文延伸ACL 2024Dirk Groeneveld, Iz Beltagy, Pete Walsh 等 · Allen Institute for AI / 华盛顿大学等待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

当时的「开源模型」大多只放权重和推理代码，训练数据、训练日志和评测代码不公开，研究者无法研究模型为什么这样。

方法

发布有竞争力的语言模型OLMo，同时公开训练数据、训练与评测代码和中间检查点。

影响

把「开放」的标准从只放权重提高到放全流程，成为研究预训练数据和训练动态的基础设施。

方法

OLMo强调的是「完全开放」：除了模型权重，还公开预训练语料（Dolma开放语料）、训练代码、训练日志、评测代码和多个中间检查点。这样别人可以复现训练，也可以研究数据里有什么、模型何时学会了什么，而不只是拿一个黑盒用。

架构上采用与Llama 2类似的稠密Transformer设计；它的前身与相邻工作还有Pythia，后者同样公开了数据和检查点，但模型较早、性能较弱。OLMo的目标是在保持开放的同时，性能不要差太多。

局限与后续

  • 开放的7B级模型在能力上仍落后于同期闭源或半开放模型，开放程度与性能之间有取舍。
    后来针对它的工作　Tülu 3开放后训练
  • 只公开数据来源和处理脚本，并不能解决数据版权和污染问题。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 竞争
    Llama 22023.07 · LLM
    LLaMA-2只开放权重，OLMo开放权重加数据加代码；性能上OLMo追赶但不占优。
  • 延续
    Pythia2023.04 · LLM
    继承Pythia公开数据与检查点的思路，把模型能力提高到可与主流开源模型比较。
  • 改进
    Mistral 7B2023.10 · LLM
    报告没有披露训练数据和训练细节，难以复现。

后来的相关工作

  • 竞争
    苹果OpenELM2024.04 · LLM
    同样强调完全开放，摘要称在约1B规模上准确率高2.36%且预训练词元少一半。
  • 延续
    MAP-Neo完全开源双语2024.05 · LLM
    沿用完全开放的发布方式，并把它扩展到中英双语、提升到与最强同规模模型相当的水平。
  • 延续
    日本LLM-jp开放项目2024.07 · LLM
    同样追求数据、代码、检查点全部开放的“完全开放”模型。
  • 延续
    OLMoE开放MoE2024.09 · LLM
    沿用OLMo的完全开放理念和训练基础设施，把它推广到稀疏MoE。
  • 延续
    OLMo 22024.11 · LLM
    延续完全开放的发布方式，重点解决初代的训练不稳定和性能落后问题。
  • 改进
    Tülu 3开放后训练2024.11 · LLM

    瑞士Apertus合规开放模型2025.09 · LLM
