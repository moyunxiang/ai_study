Connection Machine

The Connection Machine
1985硬件延伸1985（博士论文，MIT Press专著）W. Daniel Hillis · MIT / Thinking Machines待核对
来源 ↗在交互版中打开（演化树、学习进度）

问题

冯·诺依曼结构一次只处理一个数据，做AI与符号处理需要同时对海量数据做相同操作，单处理器太慢。

方法

用成千上万个简单的处理器按超立方体方式互连，所有处理器同步执行同一条指令，各自处理自己那一小块数据。

影响

大规模数据并行的思想后来在GPU上实现；公司1994年破产，说明专用并行硬件难以敌过商品化路线。

方法

Connection Machine出自Danny Hillis在MIT的博士研究，他1983年与Sheryl Handler创办Thinking Machines公司，把论文变成产品。论文1985年获ACM优秀博士论文奖并以专著出版。

CM-1与CM-2由65,536个位串行（一次只处理1位）的简单处理器组成，每片芯片装16个，处理器之间按超立方体连线。这种「数据并行」模型对每个数据元素做同样的操作，很适合图像、模拟和早期的符号处理。机器最初面向AI，后来在科学计算上更成功；到1993年，世界最快的四台计算机都是Connection Machine。

公司在1994年申请破产，硬件和并行软件部门后来被Sun收购。

局限与后续

  • 位串行的简单处理器单个速度很慢，一旦程序不是规则的数据并行，利用率很低。
    后来针对它的工作　CUDA
  • 专用大规模并行硬件价格高、软件生态封闭，难以和商品化微处理器竞争。
    后来针对它的工作　Beowulf商用集群

它建立在什么之上

  • 改进
    冯·诺依曼架构1945.06 · 硬件 待核对
    控制器一次只执行一条指令、运算逐位串行，没有为大规模并行运算设计，无法同时处理大量相互独立的数据。
  • 竞争
    Amdahl定律1967.04 · 硬件
    Amdahl定律认为串行部分限制并行收益，Connection Machine则押注数据量足够大时可并行部分占绝对多数。
  • 竞争
    Cray-1向量超级计算机1976.03 · 硬件
    Cray-1用少量极快的向量处理器，Connection Machine用大量极慢的简单处理器，路线相反。

后来的相关工作

  • 改进
    CUDA2006.11 · 硬件
    位串行的简单处理器单个速度很慢，一旦程序不是规则的数据并行，利用率很低。
  • 竞争
    Beowulf商用集群1994 · 硬件
    同样追求大规模并行，但Connection Machine用专用大规模并行硬件，Beowulf走商品化集群路线，后者胜出。
  • 延续
    Slurm集群调度2003.06 · 系统·效率
    都要解决大型并行机器如何被多人共享，Slurm面向普通Linux集群而非专用硬件。
  • 延续
    Blue Gene/L2004.11 · 硬件
    继承大规模并行的路线，但用商品化的低功耗处理器代替专用位串行处理器。
