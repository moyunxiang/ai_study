EPR学习检索示例

Learning To Retrieve Prompts for In-Context Learning
2021.12论文延伸NAACL 2022Ohad Rubin, Jonathan Herzig, Jonathan Berant · 特拉维夫大学待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

上下文学习的效果很依赖放进提示的那几个示例，可当时挑示例只能靠BM25或句向量找“表面上像”的训练样本，而表面相似不等于对模型有帮助。

方法

让语言模型自己给候选示例打分：看加上某个示例后，模型生成正确答案的概率有多高；高的当正例、低的当负例，用对比学习训练一个专门挑示例的稠密检索器。

影响

把“选示例”变成一个可以用LM信号监督训练的检索问题，在三个语义解析任务上明显超过此前的示例选择方法；此后的示例检索与“用LM反馈训练检索器”的工作大多以它为起点或基线。

背景

GPT-3让“在提示里放几个例子、不更新参数”的上下文学习与提示流行起来，但怎样选好示例等工作发现，换一组示例，准确率可以相差很大。常见做法是用BM25或Sentence-BERT找与测试问题字面或语义最近的训练样本，这只是代理指标。

方法

造训练数据：对训练集中的每一对 (x, y)，先用无监督检索器（BM25或SBERT）从其余训练样本里召回约50个候选 ē。然后把每个候选当作单个示例放在 x 前面，让一个打分LM（实验里主要用GPT-Neo）计算生成正确输出的概率 Prob(y | ē, x)。概率最高的k个标为正例，最低的k个标为负例。因为召回时能用到正确答案 y，候选本身就和目标很接近，负例因此是“看起来像但帮不上忙”的难负例。

训练检索器：仿照稠密检索DPR用两个BERT编码器，一个编码测试输入，一个编码候选示例，用对比损失让正例的内积高于负例和同批其他样本。

推理：测试时只用这个检索器取最相关的若干训练样本拼成提示，交给推理LM（可以与打分LM不同，例如更大的GPT-J、GPT-3或Codex）。

结果：任务是把自然语言映射成结构化表示的Break、MTop、SMCalFlow。打分LM与推理LM都用GPT-Neo时，相比最好的基线，Break从26%到31.9%，MTop从57%到64.2%，SMCalFlow从51.4%到54.3%；用GPT-Neo打分、换更大的模型推理，提升同样存在。

后来的发展

“用目标模型的似然给检索结果打标签”这个信号，后来也被REPLUG黑盒检索增强用来训练文档检索器；示例选择、示例排序和自动构造示例（如Auto-CoT自动思维链）此后成为提示工程中的独立研究方向。

局限与后续

  • 每个训练样本都要让打分LM把几十个候选各算一遍，造数据的计算量随训练集大小线性增长。

  • 每个候选是单独打分的，没有考虑多个示例放在一起时的组合效果和先后顺序。

读懂它需要的概念

本篇术语

  • 打分LM　专门用来评估“这个示例对生成正确答案有没有帮助”的语言模型，只在造训练数据时使用。
  • 难负例　表面上和正例很像、但其实是错的样本，用它训练能逼模型学会细微区别。

怎么学

先读怎样选好示例和稠密检索DPR → 读原文第3节打分与训练流程 → 动手：对一个小分类任务，用小模型计算不同示例下正确标签的对数概率，看它和句向量相似度的排名差多少。
