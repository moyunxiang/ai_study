GPT-Engineer整项目生成

2023.04系统延伸Anton Osika等开源社区 · 后来发展为Lovable待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

Copilot式补全一次只写几行，写一个完整的小程序仍要人一步步拆功能、建文件、拼起来；能不能只用自然语言描述需求，让模型生成整个代码库？

方法

用户在一个名为prompt的文件里写需求，命令行工具让模型一次性生成项目里的全部文件并尝试运行；之后还可以用同样方式描述改进，让模型修改已有代码。

影响

2023年最早引起广泛关注的整项目代码生成工具之一，GitHub星标超过5万；仓库自述是Lovable的前身，代表了后来「描述需求、直接生成应用」这类产品的早期形态。

方法

gpt-engineer是一个命令行工具，仓库创建于2023年4月底，作者是Anton Osika。用法很简单：

  • 新建一个空文件夹，在里面写一个名为prompt的文本文件，描述想要的软件；
  • 运行 gpte <项目目录>，模型（默认调用OpenAI API，也可换成本地或Azure模型）读需求后生成整个项目的文件结构和代码，并可尝试执行；
  • 想改进已有代码时，在prompt里写修改要求，运行 gpte <项目目录> -i，模型在现有代码上修改。

它把「需求→整个代码库」交给模型一口气完成，而不是像GitHub Copilot那样逐行补全；这与同年的Aider（在已有仓库里结对改代码）、多智能体分工写软件的ChatDev和MetaGPT属于同一波尝试。README后来写明：想要维护良好的命令行工具可以去用aider，想要托管服务可以用gptengineer.app——也就是后来的Lovable。仓库已于2026年4月22日归档。

局限与后续

  • 一次性生成整个项目，没有在真实仓库里检索、跑测试、根据报错迭代的闭环，项目一复杂就容易出错且难以修改。
