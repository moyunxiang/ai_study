MultiChallenge多轮对话

MultiChallenge: A Realistic Multi-Turn Conversation Evaluation Benchmark Challenging to Frontier LLMs
2025.01数据集延伸Ved Sirdeshmukh, Kaustubh Deshpande, Johannes Mols, Lifeng Jin, Ed-Yeremai Cardona, Dean Lee, Jeremy Kritz, Willow Primack et al. · Scale AI待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

已有的多轮对话评测（如MT-Bench）已被前沿模型刷到接近满分，但真实用户和模型聊上几轮后，模型照样会忘掉早先的要求、前后自相矛盾。

方法

从真实人机对话中归纳出四类多轮对话难点，由人工编写专门让前沿模型出错的多轮对话，再配上逐题的评分细则让LLM裁判自动判分。

影响

前沿模型在已有多轮基准上接近满分，在MultiChallenge上全部不到50%，它因此成为2025年各家模型发布时报告多轮对话能力的常用指标之一。

方法

背景。LLM-as-a-Judge与MT-Bench只有两轮，题目中第二轮通常是简单追问；IFEval指令遵循考单轮的格式指令。真实使用中，用户会在第一轮说“我对坚果过敏”，十轮以后再问菜谱；会要求“以后都用正式语气”；会让模型反复修改同一段文字。这些需要模型同时做到准确遵循指令、在长对话中分配注意力、结合上下文推理。

四类挑战。作者把真实对话里常见又难的情况归为四类：

  • 指令保持：早先给出的全局要求要在后面每一轮都遵守；
  • 推断记忆：用户在前面不经意提到的信息，后面要能主动用上；
  • 可靠的版本化编辑：多轮来回修改同一份内容时，要正确跟踪当前版本；
  • 自我一致：不能因为用户的追问或质疑就推翻自己先前正确的说法。

怎么造题和判分。人工标注者与多个前沿模型对话，只保留至少让一部分模型失败的对话，最后一轮作为考题。每道题附一条实例级的评分细则（例如“回答是否避开了坚果”），交给LLM裁判做二元判断。作者报告，这种带细则的自动评测与经验丰富的人工评审一致性尚可。

结果。摘要称，尽管在现有多轮基准上接近满分，所有前沿模型在MultiChallenge上的准确率都低于50%，表现最好的Claude 3.5 Sonnet（2024年6月版）平均只有41.4%。

局限与后续

  • 题目是对着当时的前沿模型筛出来的，模型一更新就可能失去难度；只评最后一轮，且依赖LLM裁判，与人工的一致性只是“尚可”。
    本站还没有记录针对它的后续工作（不代表没有人解决）

它建立在什么之上

  • 改进
    LLM-as-a-Judge与MT-Bench2023.06 · 数据·评测
    MT-Bench只有两轮且已被刷到接近满分，MultiChallenge用更长、更真实、专门挑模型弱点的对话恢复区分度。
  • 延续
    迷失在中间2023.07 · LLM
    长上下文中间的信息容易被忽略，MultiChallenge在多轮对话场景下检验同类问题。
  • 使用
    Claude 3.5 Sonnet2024.06 · LLM
    被测前沿模型之一，也是得分最高的模型（41.4%）。
  • 延续
    IFEval指令遵循2023.11 · 数据·评测
    IFEval考单轮可验证的格式指令，MultiChallenge考指令在多轮中是否被持续遵守。

这些关系由AI模型整理。“改进”指后来的工作针对它的某个问题做了改进，不代表问题已经解决；“竞争”指同一问题的不同路线，不代表谁取代了谁。标有“已核对”的对照过原始来源，其余未逐条核对。

读懂它需要的概念

基准、排行榜与SOTA 上下文窗口 指令微调与对话模板 生成质量指标：IS与FID

本篇术语

  • 实例级评分细则　为每道题单独写的判分标准，把开放式回答的评判变成一个是否满足的具体问题。

怎么学

先读LLM-as-a-Judge与MT-Bench和IFEval指令遵循；读MultiChallenge原文的四类挑战示例；动手和一个聊天模型进行十轮以上对话，第一轮给一条全局约束，统计后面它违反了几次。
