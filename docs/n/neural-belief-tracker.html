神经信念追踪NBT

Neural Belief Tracker: Data-Driven Dialogue State Tracking
2016.06论文延伸ACL 2017Nikola Mrkšić, Diarmuid Ó Séaghdha, Tsung-Hsien Wen, Blaise Thomson, Steve Young · 剑桥大学、Apple待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

任务型对话系统要在每一轮判断用户目前的目标（想要什么菜系、什么价位），但已有的信念追踪器要么依赖需要大量标注的口语理解模块，要么依赖手写的同义词词典来处理用户的各种说法，难以扩展到新领域。

方法

直接在预训练词向量上建模：把用户这一轮的话、系统上一轮的话和每个候选「槽-值」对（如food=chinese）都编码成向量，用一个小网络判断这一轮是否表达了该槽值，从而不需要口语理解标注，也不需要手写词典。

影响

NBT是第一批完全基于表示学习的对话状态追踪模型，把DST从依赖词典的工程问题变成了可迁移的学习问题，后续的GLAD、TRADE等模型都以它为基线。

背景

经典的任务型对话系统是流水线：口语理解（识别意图和槽位）→ 对话状态追踪（维护每个槽当前的取值分布）→ 对话策略 → 回复生成。剑桥组的DSTC2餐馆预订数据是当时的标准评测。2014–2015年最强的追踪器（如基于RNN的Henderson等人的模型）直接读用户话语，但需要「去词汇化」：用手写词典把「便宜」「不贵」「实惠」都替换成同一个占位符，否则模型见不到足够的变体。

方法

对每一轮和每个候选槽值对 (s, v) 分别做二分类：这一轮用户是否表达了 s=v。

表示。 用户话语 r 由预训练词向量经过深度平均网络或卷积网络得到句向量；槽值对的表示是槽名和值的词向量之和 c = c_s + c_v；系统上一轮的行为分两类——系统请求某个槽（「你想要什么价位？」）和系统确认某个槽值（「你是说中餐吗？」），分别编码为 t_q 和 (t_s, t_v)。

交互。 话语与候选的语义相似 d = r ⊙ c（逐元素乘）；上下文门控：若系统刚请求了槽 s，则用户回答的一个短词（「便宜的」）就足以决定槽值，模型用 m = (c_s · t_q) r + (c_s·t_s)(c_v·t_v) r 引入这部分信息。最后 y = softmax(W [d; m]) 输出是/否。

状态更新。 每轮的判断与上一轮的信念用简单规则合并成当前对话状态。

关键在于词向量的质量：作者使用用counter-fitting等方法注入了同义/反义约束的词向量，使「cheap」和「inexpensive」相近、「cheap」与「expensive」远离。

结果

摘要报告：在两个数据集上，NBT与依赖手写语义词典的最好模型持平，在不提供词典时则超过它们。具体数字未核对。

后来的发展

此后的DST研究走向不依赖预先枚举槽值的生成式或抽取式方法：TRADE对话状态追踪用复制机制直接生成槽值以支持多领域和零样本迁移，BERT类编码器出现后DST在MultiWOZ任务型对话上又提升了一大截。NBT展示的「语义专门化的词向量可以替代手写词典」也推动了词向量后处理（counter-fitting、attract-repel）的研究。

读懂它需要的概念

本篇术语

  • 对话状态追踪（DST）　任务型对话中每一轮根据对话历史估计用户目标，即每个槽（菜系、价位、地点）当前取什么值。
  • 任务型对话　帮助用户完成订餐、订票等具体任务的对话系统，通常由理解、状态追踪、策略和生成几个模块组成。
  • 去词汇化（delexicalisation）　用词典把话语中提到的具体槽值替换成占位符，以减少模型需要学习的变体，但需要手工维护同义词表。

怎么学

先了解任务型对话的流水线结构（端到端任务型对话系统） → 读原文第3节模型和第5节词向量的影响 → 动手：在WOZ 2.0数据上用GloVe和counter-fitted两种词向量分别训练一个简化版NBT，比较联合目标准确率。
