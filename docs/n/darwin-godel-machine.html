达尔文哥德尔机DGM

Darwin Godel Machine: Open-Ended Evolution of Self-Improving Agents
2025.05论文延伸Jenny Zhang, Shengran Hu, Cong Lu, Robert Lange, Jeff Clune · 不列颠哥伦比亚大学 / Vector研究所 / Sakana AI待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

智能体的架构都是人设计的，不会自己变强；理论上的哥德尔机要求先证明每次自我修改有益，这在实践中做不到。

方法

让编码智能体直接修改自己的代码，用编程基准实测代替证明；同时保留所有变体组成的档案，像生物进化一样从档案里不断分叉出新版本。

影响

SWE-bench成绩靠自我修改从20.0%升到50.0%，把「自我改进的AI」从思想实验变成可复现的实验，引发大量关于递归自我改进与其安全性的讨论。

方法

起点是一个只有Bash和文件编辑两个工具的简单编码智能体，背后的基础模型权重不变。每一轮：从档案中挑一个父代（得分越高、已有可用子代越少，越容易被选中）；父代阅读自己的评测日志，提出一个改进想法，并在自己的代码库里实现它；新智能体在SWE-bench或Aider的Polyglot编程基准上分阶段评测（先小子集，表现够好再上更大子集），只要还能正常编辑代码就放回档案。

这正是ADAS自动设计智能体的升级：ADAS里负责设计的元智能体是固定的，而DGM修改的对象就是自己，改进编码能力也就改进了「改自己」的能力。保留整个档案而不是只留最好的一个，是为了让暂时不好的分支日后可能成为通向更好设计的跳板。

跑80轮后，SWE-bench从20.0%升到50.0%，Polyglot从14.2%升到30.7%。自动发现的改进包括按行查看、按字符串替换的更细粒度编辑工具，多次尝试后用另一个模型挑最好的方案等。这些改进换用其他基础模型时仍然有效。
