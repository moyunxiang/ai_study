Samba混合SSM

Samba: Simple Hybrid State Space Models for Efficient Unlimited Context Language Modeling
2024.06论文延伸ICLR 2025Liliang Ren, Yang Liu, Yadong Lu, Yelong Shen, Chen Liang, Weizhu Chen · 微软、伊利诺伊大学厄巴纳-香槟分校待核对
arXiv ↗GitHub ↗在交互版中打开（演化树、学习进度）

问题

全注意力的计算随长度平方增长、训练长度之外外推能力差；纯状态空间模型（如Mamba）是线性时间的，但把历史压进固定大小的状态后，难以精确回忆很久之前的具体内容。

方法

逐层交替堆叠Mamba层和滑动窗口注意力（SWA）层（中间配MLP）：Mamba负责把整段历史压缩成循环状态，SWA只看最近一段窗口、负责精确回忆近处内容，整体保持线性时间。

影响

以3.8B参数、3.2万亿token的规模说明这种简单的层间混合在常规基准和长上下文外推上都能胜过同规模Transformer，是2024年“SSM＋局部注意力”混合架构的代表之一。

方法

背景：Mamba状态空间模型用输入相关的选择性状态空间做到线性时间序列建模，但它的状态大小固定，长距离的精确检索（如在长文中找一串密码）不如注意力；Longformer滑窗注意力、Mistral 7B用的滑动窗口注意力只看最近的若干token，也是线性的，但看不到窗口外。Jamba混合架构则把Mamba和全注意力层混合。

Samba的结构很简单：按“Mamba → MLP → SWA → MLP”的模式逐层重复。Mamba层提供对整个历史的压缩记忆和隐式位置信息，SWA层（窗口2048）在局部做精确的内容寻址，两者互补。因为没有任何全注意力层，计算和显存都随长度线性增长，推理时状态大小固定，可以无限流式生成。

结果：作者把Samba扩展到38亿参数、3.2万亿训练token，摘要称在多种基准上显著超过当时最好的同规模模型。只在4K长度上预训练，零样本困惑度在长达100万token时仍持续改善；只用4K长度的数据微调后，就能外推到256K长度并在密码检索（Passkey Retrieval）任务上完全召回，在更难的电话簿检索任务上也优于全注意力模型。对128K长度的提示，吞吐量是使用GQA的Transformer的3.73倍；流式生成64K token时提速3.64倍。

局限与后续

  • 没有全局注意力层，需要在很长距离上精确比对多处内容的任务（多跳检索、长文多处引用）仍受限于固定大小的状态；窗口外的信息只能靠Mamba的压缩记忆。

读懂它需要的概念

本篇术语

  • 滑动窗口注意力（SWA）　每个token只关注它之前固定长度窗口内的token，计算量随长度线性增长。
  • 密码检索（Passkey Retrieval）　在一大段无关文字里藏一串数字，测试模型能否在长上下文中准确找回它。
