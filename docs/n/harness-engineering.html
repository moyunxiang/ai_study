长时程智能体harness

Effective harnesses for long-running agents
2025.11思想延伸Anthropic（Justin Young 等）待核对
Anthropic ↗在交互版中打开（演化树、学习进度）

问题

智能体要跨很多个上下文窗口持续工作，但每个新会话都不记得上一班做了什么；只靠压缩，交接常常不清晰。

方法

用“初始化智能体”搭好环境，再让后续每个会话的“编码智能体”只做一点增量进展，并在结束时留下干净的状态和给下一班看的记录文件。

影响

“harness”（智能体外壳）成为独立的工程对象，如何给长时程智能体设计交接、验证和状态文件，成了新的工程学问。

方法

Anthropic在2025年11月26日发文，打了个比方：就像一个项目由轮班工程师接力，而每个新工程师都失忆。他们观察到，即使用Claude Agent SDK的压缩，让前沿编码模型在多个窗口中循环，仍达不到生产质量的网页应用。失败有两种：一是想一口气做完，结果窗口耗尽时留下半成品；二是项目后期新实例看到已有进展就宣布完工。

解法是两段式：第一次会话由初始化智能体搭环境，写init.sh脚本、claude-progress.txt进度记录和一次初始git提交；之后每次会话都由编码智能体增量地推进一点，结束时让环境处于可合并到主分支的干净状态，并把结构化的更新留给下一个会话。这与Ralph循环的无状态循环相比，多了显式的交接约定与验收标准。

局限与后续

  • 智能体自己写的完成度判定不可靠，需要端到端测试这类外部验证才能防止过早宣布完成。
