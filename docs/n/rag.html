检索增强生成RAG

Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
2020.05论文主干NeurIPS 2020Patrick Lewis, Ethan Perez, Aleksandra Piktus, Fabio Petroni, Vladimir Karpukhin, Naman Goyal, Heinrich Küttler, Mike Lewis et al. · Facebook AI Research / UCL / NYU来源已核对
arXiv ↗HuggingFace Transformers中的RAG实现 ↗在交互版中打开（演化树、学习进度）

问题

预训练语言模型把知识存在参数里：记不准就会编，没法告诉你依据，世界变了也只能重新训练。已有的检索方法只能从文档里抽取答案片段，不能自由生成。

方法

给生成模型配一个可检索的外部记忆：先用稠密检索器从2100万段维基百科里找出最相关的几段，再让BART以“问题+检索到的段落”为条件生成答案，并把检索结果当作隐变量求和，端到端微调。

影响

给出了“参数记忆+非参数记忆”组合的通用微调方案，在三个开放域问答上刷新当时纪录，并演示了只换索引就能更新知识。“RAG”一词后来常被用来泛指“先检索再生成”的系统。

背景

2019到2020年间，研究者发现大型预训练模型能“记住”不少事实：语言模型即知识库直接用填空题从BERT里问出知识，T5不看任何文档（闭卷）也能回答一部分开放域问题。但这种参数记忆有三个硬伤：记不准时会一本正经地编造（幻觉）；说不出答案的出处；知识停在训练数据的那一刻，想更新只能再训练。

另一条路线是“先检索再阅读”。DrQA开放域问答先用TF-IDF找维基百科段落，再让阅读模型从中抽取一个答案片段；稠密检索DPR把检索换成双塔BERT稠密向量，REALM更进一步，把检索器和语言模型一起预训练。但这些系统都是抽取式的：答案必须是原文中的一段连续文字，无法综合多段内容，也做不了生成句子、出题之类的任务。

问题因此变成：能否让一个通用的生成模型在生成时“查资料”，并且整套系统用一个目标端到端训练？

方法

RAG由两个现成的预训练模块组成（见检索与向量数据库）：

检索器 p_η(z|x)：直接用DPR。文档编码器把维基百科（2018年12月版，切成100词一段，共2100万段）编码成向量，用FAISS向量检索建索引；查询编码器把问题x编码成向量，取内积最大的前K段（K取5或10）。p_η(z|x) ∝ exp(d(z)·q(x))。

生成器 p_θ(y|x,z)：4亿参数的BART-large，输入就是把问题和一段检索结果直接拼起来。

把检索结果当隐变量（见隐变量模型）。训练数据里没有“该看哪一段”的标注，所以对前K段求和：

RAG-Sequence: p(y|x) ≈ Σ_z p_η(z|x) · Π_i p_θ(y_i | x, z, y_<i)

整句答案基于同一段文档生成，再按检索概率加权平均。另一种 RAG-Token 在每生成一个词时都对K段重新加权求和，允许答案的不同部分来自不同文档。

训练。只最小化答案的负对数似然。梯度通过p_η(z|x)流回查询编码器，于是检索器在没有任何检索标注的情况下学会找“能帮生成器答对”的段落。文档编码器和索引保持冻结——如果像REALM那样一起更新，就得反复重建2100万条向量的索引，作者发现没必要。

例子：问“秘鲁总统是谁”，检索器取回几段维基百科，BART读着这几段生成名字；把索引换成2016年的版本，答案就随之变成2016年的总统。

结果

开放域问答精确匹配（EM）：Natural Questions上RAG-Sequence 44.5，高于DPR的41.5、REALM的40.4和闭卷T5-11B的34.5；WebQuestions 45.2、CuratedTrec 52.2，三项都是当时最好。参数量接近的T5-large闭卷只有28.9。

生成任务上，Jeopardy出题的人工评测中，评测者认为RAG比BART更符合事实的比例为42.7%，反过来只有7.1%。FEVER三分类事实核查准确率72.5%，在没有检索监督的条件下离当时最好的流水线系统差4.3个点。

换索引实验：用82位在2016到2018年间换届的各国领导人提问，索引与年份匹配时答对70%和68%，错配时只有12%和4%——知识确实可以靠换文档库来更新。

后来的发展

之后很快出现了沿这一方向的工作：FiD融合解码让解码器同时综合大量检索段落，并发现段落越多效果越好；RETRO把检索库扩到2万亿token并在预训练阶段就接入检索；Atlas检索增强少样本联合训练检索器做少样本学习。

2022年底以后，大模型足够强，人们不再微调整套系统，而是把检索到的段落直接塞进提示词里，再由LangChain、LlamaIndex这类框架和向量数据库组装起来，这套做法沿用了RAG这个名字。此后的发展集中在“何时检索、检索什么”：WebGPT用搜索引擎并给出引用，FLARE主动检索和Self-RAG让模型自己决定什么时候再查，GraphRAG按知识图谱组织文档，上下文检索改进切块，Deep Research让智能体多轮搜索。长上下文模型出现后，“还要不要RAG”也成了专门的问题（RAG还是长上下文）。

容易误解的地方

  • 原论文的RAG是联合微调的检索器+生成器，梯度会更新查询编码器；今天常说的RAG多半是“向量库检索+冻结大模型+提示词拼接”，没有任何训练。
  • RAG不保证不幻觉：检索到的段落不相关或互相矛盾时，模型仍会生成，甚至把错误内容说得很肯定。
  • 检索器和生成器都不是这篇发明的（来自DPR和BART），它的贡献是把两者用隐变量边缘化接起来，并在问答、出题、事实核查等多种知识密集任务上显示了效果。

局限与后续

  • 只在生成开始前根据问题检索一次，无法在推理过程中发现缺什么再去查，多跳问题吃力。
    后来针对它的工作　Self-Ask ReAct FLARE主动检索 Self-RAG Search-R1
  • 每段文档单独与问题拼接、只看前5到10段，难以综合大量证据。
    后来针对它的工作　FiD融合解码 RETRO
  • 文档编码器和索引被冻结，检索器只能部分适应任务；某些任务上检索会“坍缩”成总是返回同几篇文档。
    后来针对它的工作　Atlas检索增强少样本
  • 模型不判断检索结果是否可信或相关，也不给出逐句引用，用户仍无法核实答案。
    后来针对它的工作　WebGPT Self-RAG
  • 每个任务都要微调整套模型，并且依赖固定的维基百科索引，换到私有文档、网页等场景需要重新搭建。
    后来针对它的工作　LangChain LlamaIndex

  • 竞争

    闭卷T5靠参数记忆答题；RAG用4亿参数加外部索引，在NQ上以44.5对34.5超过了110亿参数的T5。

    BART2019.10 · LLM 已核对

  • 改进
    语言模型即知识库2019.09 · LLM 待核对

    ELIZA1966.01 · NLP
    完全没有对句子含义和世界知识的表示，回复只是对用户原话的改写，无法回答事实问题或进行推理。

    Freebase2007.03 · NLP
    只能用MQL这类结构化查询访问，普通用户的自然语言问题要先翻译成查询，中间的语义解析非常困难。

    Google知识图谱2012.05 · NLP

  • 改进
    NELL永不停止的语言学习2010.07 · NLP

  • 改进
    IBM Watson赢得Jeopardy!2011.02 · NLP
    系统由大量人工设计的组件和针对节目题型的调优拼成，换到医疗等专业领域效果和成本都不理想。
  • 改进
    基于Freebase的语义解析问答2013.10 · NLP
    逻辑形式的搜索空间随复杂度指数增长，只擅长简单的单属性问题，难以回答多步推理的复杂问题。
  • 改进
    CoQA对话问答2018.08 · 数据·评测
    对话是众包工人围绕给定文章人为展开的，与真实用户的多轮提问有差别。
  • 改进
    HotpotQA多跳问答2018.09 · 数据·评测
    训练和评测都假设给定了候选段落，与真实检索设置有差距。
  • 改进
    参数里能装多少知识2020.02 · LLM
    知识只存在参数里，无法更新，也难以判断答案是不是编造的，容易出现幻觉。

读懂它需要的概念

检索与向量数据库 嵌入向量 编码器-解码器 隐变量模型 内积与余弦相似度 预训练与微调 幻觉

本篇术语

  • 参数记忆 / 非参数记忆　参数记忆是模型权重里“背下来”的知识；非参数记忆是外部可替换的文档库，模型用检索的方式去查。
  • 最大内积搜索（MIPS）　在大量向量里找出与查询向量内积最大的几个，是稠密检索的核心操作，通常用近似算法加速。
  • 边缘化　对一个看不见的变量（这里是“用了哪篇文档”）的所有取值按概率加权求和，得到不依赖它的总概率。
  • 开放域问答　不给定参考文章，模型需要自己从整个知识库（如维基百科）中找依据来回答问题。

怎么学

先补检索与向量数据库、编码器-解码器和隐变量模型，并读一下稠密检索DPR的双塔检索。然后读原文第2节（两个公式和训练方式）、表1和第4.5节的换索引实验。动手：用sentence-transformers给几百段文本建FAISS索引，对一个问题取前5段拼进提示词交给任意开源LLM生成答案，再对比不检索时的回答——这就是今天工程上的“RAG”；想体会原论文的训练方式，可以跑HuggingFace里的RagSequenceForGeneration示例。
