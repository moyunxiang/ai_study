verl / HybridFlow RL训练框架

HybridFlow: A Flexible and Efficient RLHF Framework
2024.09论文延伸EuroSys 2025Sheng, Zhang, Ye, Wu, Zhang, Zhang, Peng, Lin et al. · 香港大学, 字节跳动待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

RLHF流程里有多个模型（策略、参考、奖励、价值）和生成、训练两种阶段，单控制器灵活但调度开销大，多控制器高效但改算法就要重写。

方法

HybridFlow：把单控制器和多控制器混合，用分层API解耦计算与数据依赖，并设计3D-HybridEngine实现训练与生成间的模型重分片。

影响

其开源实现verl是常用的开源LLM强化学习训练框架之一。

方法

RLHF可以看成一张数据流图：每个节点是一个分布式的LLM训练或生成程序，每条边是多对多的数据传输。HybridFlow让每个节点内部用多控制器（高效，沿用Megatron-LM模型并行、FSDP等并行），节点之间用单控制器（灵活，基于Ray），所以改RL算法只需改图。3D-HybridEngine解决同一模型在训练与生成两阶段使用不同并行方式的问题：不冗余地重新分片，并显著减少两者之间的通信。生成侧可接入vLLM与PagedAttention，算法上支持PPO和GRPO等。

结果

论文称在多种RLHF算法上，相比当时最先进的基线，吞吐提升1.53到20.57倍。

后来的发展

此后推理模型的强化学习训练大量使用这类框架，GRPO是其支持的算法之一。

  • 使用
    Megatron-LM模型并行2019.09 · 系统·效率

  • 改进
    Axolotl微调框架2023.04 · 系统·效率
    配置项多而分散，出错时要穿过多层封装定位问题；大规模预训练与复杂RL训练仍需专门框架。
  • 改进
    DeepSpeed-Chat RLHF训练2023.08 · 系统·效率
    四个模型挤在同一组GPU上串行执行，生成与训练不能重叠，规模更大或回答更长时效率下降，资源调度也不够灵活。
  • 改进
    Unsloth2023.12 · 系统·效率
    面向单卡或少量卡的场景，大规模多机训练不是它的目标。
  • 使用
    GRPO2024.02 · 推理·智能体
    支持GRPO等无价值模型的RL算法。
  • 改进
    torchtune微调库2024.04 · 系统·效率
    每个新模型都要手工写模型定义和配方，维护负担大，最终在2025年停止活跃开发；强化学习类后训练支持有限。
