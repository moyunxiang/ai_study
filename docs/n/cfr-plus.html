CFR+

Solving Large Imperfect Information Games Using CFR+
2014.07论文延伸arXiv 2014Oskari Tammelin · 独立研究者待核对
arXiv ↗在交互版中打开（演化树、学习进度）

问题

反事实遗憾最小化CFR及其采样变体是求解扑克近似均衡的最好方法，但要求解限注德州扑克这种规模的博弈，所需计算时间仍然太长。

方法

对CFR做几处简单修改：累计遗憾一旦为负就截断为零（遗憾匹配+），双方交替更新，并对平均策略按迭代次数加权；这样收敛快得多。

影响

摘要称通常比已有算法快一个数量级以上，几个月后被用来求解两人限注德州扑克（Cepheus：限注德扑被解决），之后成为CFR家族改进的基准。

方法

原版反事实遗憾最小化CFR在每个信息集上记录每个动作的累计遗憾，按正遗憾的比例分配下一轮的策略（遗憾匹配）。问题是：一个动作如果早期表现很差，累计遗憾会变成很大的负数，之后即使它变成好动作，也要很多轮才能「还清」负债重新被选上。

CFR+的核心改动是遗憾匹配+：每轮更新后把累计遗憾里的负值直接截成零，好动作一旦变好就能立刻被选中。常与之一起使用的还有两点：两个玩家交替而不是同时更新，以及计算平均策略时让后期的迭代权重更大。

这些改动让收敛速度大幅提升。摘要称，CFR+通常在计算时间上比已有算法快一个数量级或更多，同时可能需要更少内存。Cepheus：限注德扑被解决团队于2015年用CFR+求解了两人限注德州扑克。

  • 按原设计要遍历整棵博弈树，和采样版本结合时效果不稳定，不适合无限注扑克这样更大的游戏。

它建立在什么之上

  • 延续
    反事实遗憾最小化CFR2007 · RL
    保留反事实遗憾的分解，修改遗憾累积与平均方式，使收敛快一个数量级以上。
  • 竞争
    蒙特卡洛CFR（MCCFR）2009.12 · RL
    MCCFR靠采样降低每轮代价，CFR+靠改更新规则减少所需轮数；后来大规模扑克的工作在两者之间取舍或结合。
  • 改进
    序列式博弈表示1996.06 · RL
    线性规划的规模虽是多项式的，但对德州扑克这类上亿信息集的博弈，用通用LP求解器内存和时间仍然无法承受。
  • 改进
    遗憾匹配2000.09 · RL
    平均策略的收敛速度只有 O(1/√T)，大博弈里需要非常多次迭代。

本篇术语

  • 遗憾匹配+　遗憾匹配的变体：累计遗憾一旦变成负数就重置为零，避免坏动作的历史拖累它之后的表现。

怎么学

先实现库恩扑克上的CFR；把遗憾更新改成截断负值，观察可剥削度下降速度的变化；再读Cepheus：限注德扑被解决的讲解，了解CFR+怎样被用于求解限注德扑。
