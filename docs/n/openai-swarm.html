OpenAI Swarm框架

2024.10系统延伸OpenAI Solutions团队待核对
GitHub ↗在交互版中打开（演化树、学习进度）

问题

2024年开发者想把客服、分诊、查询等能力拆给多个智能体，但已有框架概念繁多、状态难以控制和测试。

方法

只保留两个原语：智能体（指令加工具）和交接（handoff）——一个工具函数如果返回另一个智能体，对话就转交给它。

影响

以「教学用实验框架」发布即引起大量讨论和移植，交接这一原语被2025年的OpenAI Agents SDK直接继承。

方法

Swarm是OpenAI于2024年10月在GitHub公开的一个小型Python库，自称experimental、educational，只用于演示多智能体编排的写法。

它的设计非常简单：一个Agent包含一段系统指令和一组可调用的函数（见函数调用成为标准接口）；如果某个函数的返回值是另一个Agent，运行时就把后续对话交给那个Agent处理，这就是「交接」。例如分诊智能体判断用户要退票，就调用transfer_to_refund函数，把对话交给退款智能体。整个库只跑在Chat Completions接口之上，两次调用之间不保存任何状态，所以容易测试和复现。

仓库说明写明Swarm已被Responses API与Agents SDK取代，后者是它面向生产的演进版本。名字虽叫Swarm，它既不训练模型，也与群体智能算法无关。

容易误解的地方

  • 它不是「用强化学习训练智能体群」的方法，只是手写编排的开发框架；搜swarm RL请看Conductor指挥家模型、Kimi K2.5视觉智能体等。
  • 无状态设计意味着记忆、持久化需要开发者自己处理。

局限与后续

  • 实验性质、无状态、没有追踪和护栏等生产功能，不适合直接用于正式产品。
