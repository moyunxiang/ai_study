这个网站是怎么设计的

AI脉络（moyunxiang.com/ai_study）是一张可探索的AI研究发展地图。这一页是纯静态的，不运行脚本就能读，把定位、信息结构、内容可信度体系、数据格式、每个页面的布局、演化树的画法、搜索规则、性能、测试和已知问题一次讲完，供人或AI助手评审。页面里的数字每次构建时自动更新；2026-11-22做过一次面向公开发布的整体改版，随后又做了一次整体视觉升级（Organic Neural Chronology：有机的枝条画法，见第8节和第13节）；2026-11-24换了配色（深色“石墨”、浅色“粉纸”，版式没有动，见第13节）。本页描述的是现在的状态。升级前的设计完整存档在仓库的design-v1标签和archive/design-v1目录。

给评审者（包括AI助手）的说明。交互版的页面由脚本渲染、挂在同一个地址的#后面，不运行脚本读不到；但每个节点、概念、专题都另有一个静态页面，正文相同，可以直接读，例如 n/transformer.html、s/why-transformer.html、start.html、about.html，完整列表在 sitemap.xml。源文件的直接地址在第16节，界面截图在第17节。

1　定位、读者与非目标

定位：一张可探索的AI研究发展地图，帮助读者理解不同的研究问题是怎样出现的、重要的方法怎样回应这些问题、又推动了哪些后来的研究。核心是四样东西：历史、研究问题、技术机制、工作之间的联系。

读者：会编程、学过大学初级数学（微积分、线性代数、概率），但不一定读过论文的中文读者。

它要让人做到：按时间看懂AI是怎么走过来的；知道每个阶段研究者想解决什么；知道一个关键方法为什么出现、怎么工作、影响了什么；看到不同方向之间的分叉和借用；从任何一个概念或论文出发，拿到一条从零读到它的路线。

不做：AI新闻聚合、论文数据库、社区、聊天产品。没有后端、账号和评论，全部是GitHub Pages上的静态文件。

2　信息结构

2.1　四层

层数量说明
大方向6树干（学习方法）、三根大枝（语言与推理、感知与生成、决策与真实世界）、土壤（数据、系统与算力）、环境（社会）
分支16每条分支有一个它要回答的问题、几个阶段，以及“树上画成从哪条分支分出来”
主题线190沿着同一个问题接力的一串工作，每条分支11或12条
节点3372一个工作：论文2185、模型135、系统239、硬件121、数据集294、事件279、思想119

节点分三档：主干（69个，缺了它后面就讲不通）、重要（704个）、延伸（2599个，用到再查）。

这棵树是一种整理方式，不是历史事实。每条分支、每条主题线只画了一个来源，实际的研究有很多交叉。站内在领域地图的列表版、首次进入地图的提示条、“关于内容”页都写明了这一点；分支的“分叉原因”和14条“跨分支借用”在这次改版中逐条对照来源审过，改掉了21条说过头的措辞（例如“序列模型第一次可以并行训练”“整棵树的起点”）。

2.2　关系

节点之间有13143条有方向的关系（从较早到较晚），四种类型。改版时把第一种的显示名从“解决”改成了“改进”，并在所有出现的地方写明含义：

类型数量含义（站内原话）图上的画法
改进（solves）5618后来的工作针对前面工作的某个问题做了改进，不代表问题已经解决红色粗实线
延续（extends）2549沿着同一个思路往前推了一步灰色细实线
使用（uses）3394把前面的工作当作部件来用灰色虚线
竞争（rivals）1582同一个问题的不同路线，不代表谁取代了谁绿色点线

类型不只靠颜色区分：线型和粗细不同，列表里每条关系都有文字标签。关系来自三处：登记表里的parents、讲解里的relations（带一句说明）、讲解里“局限”的solved_by。做过来源核对的节点以核对后的relations为准，登记表里有、核对时删掉的关系不再生成。

2.3　另外四种内容

  • 基础概念（206个）：读讲解要先会的知识，分预备、入门、进阶三级，互相有“先要会”的依赖。
  • 研究思路（264个）：一串论文共同在做的事（如“在策略自蒸馏”），有成员节点和出处。两者合起来是“知识索引”。
  • 研究专题（10篇）：围绕一个问题，按时间把6到10个已有节点串成一条线，每一站回答“上一站留下了什么问题，这一站怎么回应”。每篇必须写一段“这条线简化了什么”。专题只复用已有节点的事实，不另建知识库。
  • 机制图（16张）：讲清一个机制怎么运转的SVG小图（反向传播、梯度下降、自注意力、多头注意力、Transformer层、自回归、训练三阶段、PPO裁剪、GRPO、蒸馏、扩散、RAG、KV缓存、混合专家、ViT分块、世界模型），嵌在对应的概念页、节点页和专题里。每张图记录了画图时对照的出处。

两条路线：入门路线14站（1958年的感知机到2025年的DeepSeek-R1，每站一句“为什么读它”）和完整主干路线（全部主干节点，按时代折叠）。

3　内容可信度体系

全部讲解、关系、概念词条和专题由AI模型撰写。写作时每个节点留了一条check（一个出处加一句“核对了什么”），但那是写作模型自己的记录，不能当作验证。改版建立了三种明确的状态：

状态含义目前
人工复核真人核实过。构建脚本只接受data/review/_humans.json里登记的人写这个状态；旧数据里的check不会被当成它0个节点
来源已核对另一次独立的核对：AI模型实际打开原始来源（论文、官方公告），逐项对照作者、日期、数字、方法描述，改掉不一致的地方，降级说过头的措辞，留下记录。没有经过人工复核150个节点，其中主干69 / 69
待核对其余全部节点和全部概念词条其余

核对按 guide/review.md 做，每个节点一条记录data/review/<id>.json：

{"id": "transformer", "status": "source", "date": "2026-11-22", "by": "ai:claude-opus",
 "sources": [{"url": "https://arxiv.org/abs/1706.03762", "what": "摘要页：标题、作者、提交日期"}, …],   // 这次实际打开的
 "checked": ["8位作者及单位", "英德BLEU 28.4、英法41.8", …],      // 逐项，至少3项
 "changed": ["results 原写“训练成本是此前最好模型的几分之一到几十分之一”，表2不支持，改为…", …],
 "unverified": ["legacy里“层结构多数仍被沿用”属于概括，没有逐个核对"],
 "edges": {"bahdanau-attention": "ok", "convs2s": "revised", "rope": "weak"},     // 每条关系的结论
 "registry": {}}
  • 这次核对的范围：全部主干节点、入门路线和专题用到的节点、连接最多的一批2024–2026年的重要节点。优先级见第4节的审计报告queue.md。
  • 关系：核对过的节点，它的每条关系得到一个结论。ok和revised在页面上标“已核对”（目前1217条）；weak（说得通但没找到明确依据）标“待核对”；不成立的直接从数据里删掉。判断标准：后一篇工作自己写明建立在前一篇之上才算“延续”；用了相似技术不算“使用”；时间先后不等于因果。
  • 局限：节点页的“局限与后续”分四种情况显示：作者在原文中指出的（核对时在原文里看到）；后来有针对它的工作（列出）；本站还没有记录后续工作（明说“不代表没有人解决”）；有依据表明仍未解决（必须写出依据）。原来把“没有后续节点”当作开放问题的汇总页已经撤掉。
  • 页面上怎么显示：节点标题下面一个小标签；列表里只给核对过的节点加标签，避免满屏“待核对”；节点页底部有完整的核对记录（核对了什么、仍未能核对什么、打开了哪些来源）和“报告错误”按钮（跳到GitHub Issue，预填节点id和页面地址，不需要注册本站账号）。
  • 总说明：about.html，首页底部有一句话指向它。

4.3　检查

  • 构建时校验（python3 scripts/build.py --check，有错误就不生成）：登记表格式、id唯一、日期、引用的节点和概念是否存在、关系方向、正文里的[[链接]]、各档讲解的必填字段和最少字数、主题线成环、审核记录的格式和权限（AI不能写“人工复核”）、专题和机制图的格式（机制图不能写颜色值、不能有脚本和外链）。
  • 内容审计（python3 scripts/audit.py，只出报告不改数据，写到data/_audit/）：待核对节点的优先顺序；说得很满的措辞（“彻底解决”“首次”“证明了”等）逐条列出；可能重复的研究思路、主题线和节点；只有二手来源的节点；按月份比较时间对不上的关系；带“目前”“至今”这类会过时说法的节点；加--links时联网检查出处链接。
  • 搜索回归（node scripts/search_test.mjs）和浏览器回归（scripts/xbrowser.mjs、scripts/browse.mjs），见第14节。

5　内容规范：一个节点写什么

每个节点一个JSON文件。短字段显示在卡片、列表和树的侧栏里，长字段是讲解页的正文。

{
  "id": "与文件名一致",
  "who": "主要作者 · 机构",
  "venue": "NeurIPS 2017",
  "links": [{"label": "arXiv", "url": "https://…"}],

  "problem": "当时卡在哪里",        // 三个短字段，每个一两句话，约80字以内
  "idea":    "它怎么解决的",
  "impact":  "它改变了什么",

  "background": "背景：当时的主流做法是什么，具体卡在哪",
  "method":     "方法：核心机制，讲到读者能向别人复述，该有公式就给公式",
  "results":    "结果：关键实验和数字",
  "legacy":     "后续：它直接催生了什么，今天还在用吗",
  "pitfalls":   "常见误解",

  "limits":    [{"text": "它留下的一个具体问题", "solved_by": ["后来解决它的节点id"]}],
  "relations": [{"to": "更早的节点id", "type": "solves | extends | uses | rivals", "note": "一句话"}],

  "prereq": ["读懂这篇要先会的概念key，3–8个"],
  "terms":  [{"t": "本篇新出现的术语", "d": "一两句大白话"}],
  "learn":  "怎么学：先补什么 → 读原文哪几节 → 动手做什么",
  "check":  {"source": "写作时实际打开核对的地址", "confirmed": "核对了什么"},
  "aka":    ["别名", "缩写"]
}
  • 写法：面向没读过论文的人；先讲问题再讲解法；数字、作者、机构、日期只写打开原始出处确认过的；正文用空行分段，支持列表、粗体、行内代码和[[链接]]。
  • 三档的要求不同：主干节点要写满所有字段并讲透方法；延伸节点可以短，但三个短字段、留下的问题和关系必须有。
  • 谁写的：全部讲解、概念词条、思路、主题线划分和别名都由AI模型按guide/目录里的规范撰写，要求联网对照原文。站长只抽查了少量节点，没有逐条人工复核。站点页脚写明“仍可能有错，请以原文为准”。
  • 规范文件：guide/census.md（收什么、怎么登记）、guide/content.md（讲解和概念词条怎么写）、guide/threads.md（主题线怎么划）、guide/hot.md（补录当下在讨论的工作、写思路、补别名）。

6　页面、导航与路由

顶栏只有五项：开始学习、时间线、领域地图、知识索引、搜索（桌面上搜索是顶栏里的输入框）。“更多”菜单里是我的进度、工具、关于内容与纠错、外观。改版前有八个一级入口。

路由页面内容

旧链接都保留：#/path、#/guide到开始学习，#/eras到时间线，#/tracks到地图的列表版，#/concepts到知识索引，#/chain/<id>到从零读到它。撤掉的两个页面：开放问题汇总（#/open回首页）和自测卡片。原来的使用指南页并进了首页、开始学习页和地图上的提示条。

节点讲解页从上到下

  1. 位置（大方向 › 分支 › 主题线）、标题、英文原题、日期、类型、档、发表处、作者机构、审核状态、原始资料链接。
  2. 三格摘要：问题、方法、影响。
  3. 页内跳转：讲解、局限与后续、前驱、后续、树上的位置、从零读到它。
  4. “读之前最好先会”：最关键的三个概念，其余折叠。
  5. 背景、方法、机制图（最多直接显示两张）、结果、后来的发展、容易误解的地方。
  6. 局限与后续；它建立在什么之上；后来的相关工作（各显示前8条，其余折叠；每条有类型、说明、是否已核对）。
  7. 它在演化树上的位置：文字路径、所属研究思路、出现在哪些专题；一个按钮在页内画出它和前驱后续的小树（不再默认画）。
  8. 读懂它需要的全部概念、本篇术语、怎么学。
  9. 审核记录和“报告错误”。
  10. 我的学习记录：状态、收藏、分享链接、笔记。
  11. 本分支上一个和下一个、主干下一站。

7　“从零读到它”的路线

任何一个节点、概念或研究思路都能得到一条从头读到它的路线，入口在搜索结果、节点页、词条页和开始学习页的输入框。

  • 第一步，概念：目标直接需要的概念；它们再往下需要的基础折叠起来，按预备、入门、进阶分组。
  • 第二步，主线：从目标往回，每一步在它的前驱里挑“最该先读”的一个，一直走到没有前驱为止，再按时间正着读。打分是：主干4分、重要2分、延伸0.6分；“延续”和“改进”关系2分、“使用”1分；同一分支加1分；有说明加0.5分；已核对加0.5分；“竞争”关系不走。全站主线长度的中位数是9站，最长20站。例：DeepSeek-R1的主线是 图灵机 → M-P神经元 → 感知机 → 反向传播 → LSTM → 注意力机制 → Transformer → GPT-1 → GPT-2 → GPT-3 → 思维链 → o1 → DeepSeek-R1。
  • 旁支：目标直接建立其上、但不在主线上的主干和重要工作单独列出；“主线+旁支”模式再加上主线每一站的主干前驱。
  • 概念和思路的路线是：前置概念 → 它的出处节点的主线 → 词条本身 → 代表工作。
  • 页面底部写明：这是按登记的关系自动排出来的一条可行的阅读顺序，不是唯一的，也不代表只有这一条传承线。

8　演化树

演化树仍然是站点的核心可视化，由treeLayout（在抽象坐标里算位置）和treeDraw（映射成像素）完成，横向和竖向共用一套布局。默认只显示16行、每行只标主干节点，不会一次画出全部节点。

8.1　行

  • 一行是一条分支，按大方向分组。树干（学习方法）在正中；排在树干前面的大方向里，分支倒序排，让更早的分支贴着树干。
  • 收起的分支只标“地标节点”：它的主干节点，不足3个时用连接最多的重要节点补足。每条分支画成一根枝条：中间一根细亮线，外面一层随年份变粗变细的半透明“肉”，粗细是这一年这条分支的节点数（高度与节点数的平方根成正比），用平滑曲线连起来。
  • 展开一条分支（点左边的分支名）：这一行变成一个标题行加若干主题线行，每条主题线一行，从它的母线分叉出来。可以同时展开多条，有“全部展开”和“全部收起”。展开后显示哪些节点由“主干 / 主干+重要 / 全部”三档控制，每一档有文字说明。
  • 仍然活跃的线（最后一个节点在最近两年内）延伸到最右，末端是一个发亮的芽；已经停止的线末端是一个空心圆，并标“止于某年”。
  • 分叉画成一根由粗到细的S形枝，终点落在子分支开始的那一刻（分叉节点的日期），起点在母分支上略早的位置；横向跨度随两行的距离增长，但不会早于母分支自己的起点。鼠标停在分叉上显示“从哪条分支分出、在哪个节点、为什么”。
  • 没有母分支的几条（基础、NLP、事件等）从最左边的同一粒“种子”像根一样散开。种子在时间轴起点之前，只表示“这几条没有画母分支”，不对应任何年份。

8.2　时间轴

  • 非线性。一年占多长，取决于这一年要画多少个节点：没有节点的年份压得很短，拥挤的年份拉长（横向时长度约为“节点数的0.7次方”的线性函数，上限200px）。1943年以前压成一小段，标“更早”。
  • 缩放三档：适应屏幕、1×、2×。“适应”会把整棵树压进一屏宽，下限是原长的20%。
  • 时代作为背景的交替色带，顶部固定一行时代名和年份刻度（可点进时代页和年度页）；左侧固定一列行名（桌面168px，手机100px）。左上角常驻“不等比例”四个字，首次进入的提示条和每棵嵌入的小树下面也写明这一点。

8.3　节点和标签

  • 节点是一个带圆点的文字标签（绝对定位的链接），不是纯圆点，所以不用悬停就能读出名字。主干节点24px高、加粗、带分支色的细边和底色；重要节点和延伸节点只有圆点和文字，底色与页面相同以盖住后面的线。圆点用分支色，深色外观下带一圈很弱的同色光晕。标签最宽196px，超出截断。
  • 不重叠：每个标签沿时间方向占一段区间，同一行里放不下就换到下一子行（贪心装箱，先放主干节点），行高随子行数增长。竖向时每列固定宽136px，节点按时间往上叠。

8.4　线和交互

  • 默认不画节点之间的关系，结构由行和分叉表达。把鼠标停在一个节点上、用键盘把焦点移到它上面或点它，才画出它登记的全部前驱和后续，其余节点变淡。对方画在树上，就连到那个节点；对方所在的分支没有展开，就连到那条分支上它的日期处，用一个带分支色的小圆点标出来，所以不展开也能看到跨分支的联系。线型仍按关系类型区分（改进：红色实线；延续：灰色实线；使用：虚线；竞争：绿色点线）。连线从选中的节点向外展开一次（约0.4秒），之后静止。
  • 点一个节点：出现摘要面板（桌面在右侧360px；手机从底部升起，最高占46%）。面板里是三句话摘要、读完整讲解、只看它的前后关系、从零读到它，以及前驱和后续两个可折叠的列表，每条带关系类型。
  • 点面板里的相关节点：直接在树上选中它，不在画面里就滚过去；树上没画它（分支没展开或档位不够）就先展开。面板顶上有“回到刚才看的位置”，点一下回到第一次选中之前的滚动位置。
  • 键盘：Tab在节点间移动，回车选中，方向键在同一行的前后节点和相邻行最近的节点之间移动，Esc关闭面板。分支名是带aria-expanded的按钮。
  • 首次进入的提示条（可关闭，“怎么看”按钮可以再打开）：一行是一条分支、点分支名展开；点节点看前驱和后续；枝条的粗细、末端和分叉各表示什么；时间轴不等比例；这棵树是一种整理方式。
  • 重画时（展开、切档、缩放）保持视口中心对应的年份和被点那一行在屏幕上的位置。
  • 有机的画法不改变数据：曲线只用在三处——分叉、根、选中时的关系线，它们的端点都落在真实的行和日期上；节点的位置、行的顺序、时间刻度和关系类型的线型与升级前相同。枝条的粗细、末端的芽和空心圆各对应一项数据（年工作量、是否仍活跃）。
  • 列表版（#/map?view=list，手机上的默认）：大方向 › 分支 › 主题线的层级列表，内容和树相同，供不方便用可视化的读者使用；另有不依赖脚本的 fields.html 和每条分支的全部节点列表 t/<分支>.html。
  • 同一套画法还用在：首页的缩略图、分支页里这条分支自己的树、只看一个节点前后关系的视图、一个概念或一次搜索对应的节点、节点页里按需画出的小树。嵌入的小树下面都有图例和“时间轴不等比例”的说明。

  • 输入时的提示栏：四个搜索框共用同一套（顶栏、首页第三个入口、开始学习页、搜索页），边输入边列出最接近的7–8条，可以用上下键选、回车进入、Esc关闭；节点、概念和研究思路的每一条右边有一个“路线”按钮，直接到“从零读到它”。开始学习页的那一个，点结果本身就是给路线。中文输入法还在选字时不触发，确认候选词的回车也不会被当成提交。手机上顶栏的输入框是隐藏的，所以首页和搜索页的提示栏是手机上唯一的一处。
  • 结果页：最接近的结果做成卡片（节点带问题和方法两句话，三个按钮：读讲解、从零读到它、看它的前后关系）；然后是概念、思路、主题线；然后是节点，先显示20个，其余折叠；筛选和排序折叠。“把这些结果画到演化树上”是一个按钮，不再每次自动画。
  • 没找到时：给出换叫法的建议、正文搜索的入口，和“告诉我们该收录它”（预填的GitHub Issue）。

  • 700px以下：主导航变成固定在底部的五个标签（开始学习、时间线、领域地图、知识索引、搜索），顶栏只留站名、搜索、更多。按钮和状态圆点放大到32px和30px。

11　静态页面、分享与收录

  • 构建时为每个节点、每个概念和思路、每篇专题、每条分支各生成一个静态HTML（n/<id>.html、c/<key>.html、s/<key>.html、t/<分支>.html），另有 start.html、timeline.html、fields.html、glossary.html、about.html，共3873个。正文和交互版出自同一份数据。
  • 每页有自己的title、description（取问题和方法两句）、canonical（指向自己）、Open Graph信息和分享图。静态页顶上有“交互版”链接；交互版里的“复制分享链接”给的是静态页地址。

13　视觉规范

风格名是 Organic Neural Chronology：把“知识沿时间生长、分叉、交汇”画成像枝条和神经纤维的线。五个关键词：有机、微光、克制、按时间、编辑式排版。原则是装饰只出现在能对应到数据的地方（树、时间线、路线、关系列表），阅读页面保持安静。

配色两套，2026-11-24从十套备选里选定，只换了颜色变量，版式和画法没有动。深色叫“石墨”：近黑的灰底、冷白的字，强调色是白，没有带颜色的底。浅色叫“粉纸”：三文鱼粉的纸色、暖灰的字，强调色是青绿，思路来自财经报纸的网站（只借了颜色的思路）。颜色只留给有含义的东西：十六条分支各自的颜色，以及下面的红、蓝、绿。

  • 分支色：每条分支仍然只定义一个色相，16条分支16种颜色，不随主题变。颜色由公式生成：在支持的浏览器里用oklch(from hsl(色相 70% 50%) L C h)，深色外观主色L=0.83、C=0.105，底色L=0.25、C=0.042；浅色外观主色L=0.47、C=0.115，底色L=0.926、C=0.035。这样不同色相的亮度一致，黄色和蓝色的分支名对比度相同。不支持的浏览器退回hsl()。16个色相大致每隔24度取一个：大语言模型0、NLP 24、基础48、硬件72、具身96、强化学习120、科学144、语音168、系统192、视觉216、多模态240、数据264、生成288、安全312、智能体336；产业事件用低饱和的30。
  • 光晕：只在深色外观下、只加在小圆点上（节点、标签、路线上的站、枝条末端），是一圈8px以内的同色box-shadow；首页的缩略树线条有约3px的同色光晕，首页标题后面有一团很淡的白色光斑。浅色外观下光晕半径为0，标题后面的光斑也不画。没有霓虹描边，没有大面积发光。
  • 字体：标题和正文都用系统无衬线（苹方、Inter等），标题字重600、字距略收紧；年份、数量、小标签用等宽字体。正文15px、行高1.65；讲解正文16.5px、行高1.9。不加载任何网络字体。
  • 组件：尽量不用卡片。分区靠1px的细线和留白；原来的卡片改成“上方一条细线加一小段色条”；提示和审核记录是左边一条细线。按钮是圆角6px的矩形（34px高，小号28px），节点标签仍是带分支色圆点的胶囊，概念是灰色小菱形。顶栏56px高，半透明加模糊，底部一条1px细线。
  • 脉络元素用在哪：首页的缩略树；领域地图；时间线的茎；入门路线和专题里每一站的圆点和连线；讲解页的章节导航（一排小芽）和关系列表（每条关系从左边的细枝上分出来）。讲解正文、搜索结果、索引页没有装饰。
  • 动效：四种，都只播一次、不循环：树第一次画出来时沿时间方向展开（1.1秒）；选中节点时关系线从它向外展开（0.42秒）；首页标题区上移淡入（0.5秒）；悬停时细线延长或颜色变化（0.15–0.35秒）。系统设置了“减少动态效果”时全部关闭。
  • 版心：普通页面最宽1180px，讲解正文812px；全景树占满视口。
  • 断点：700px以下主导航移到屏幕底部、顶栏只留站名、搜索和“更多”，领域地图默认显示列表；820px以下地图的节点面板从底部升起；720px以下三格摘要竖排；620px以下时间线的年份移到茎的右侧。
  • 主题：默认是深色。在“更多”菜单里可以切到浅色或跟随系统，三态循环，选择记在浏览器里。升级前选过浅色或深色的读者保持原来的选择。
  • 对比度（按WCAG公式计算）：深色外观下正文16.0:1、次级文字10.9:1、弱化文字6.5:1、强调色12.5:1、分支色10.5–11.6:1；浅色外观下正文16.0:1、次级文字8.9:1、弱化文字5.3:1、强调色5.9:1、分支色5.8–6.8:1。控件边框对底色3.2:1。焦点状态统一用2px强调色描边。
  • 机制图：SVG内联进页面，不写任何颜色值，只用样式表里的class（三种强调色、方框、线型），所以随主题切换。
  • 打印：隐藏顶栏、按钮和页脚，强制白底黑字。

为什么换掉原来的设计：原来的米色纸张、衬线标题、赭红强调色辨识度不高；内容本身是一棵按时间生长的树，视觉上却没有体现。升级后把树本身当成标识。

14　测试

  • 构建校验：0错误。
  • 搜索回归：data/search_tests.json 共143条用例，覆盖完整论文原题、中文概念、英文缩写、别名、多词查询、分隔符和大小写变化、拼写错误、有歧义的缩写、方向词、作者和机构、无结果查询、评测子集和版本名、口语化的问法。通过条件是期望的条目出现在前N个结果里。当前143/143通过；建索引约65毫秒，单次查询中位数约6–8毫秒、最慢约50–65毫秒（放宽再找的查询要跑两遍）（Node，M系列Mac）。
  • 浏览器回归（scripts/xbrowser.mjs，Playwright）：Chrome 157、WebKit 18.2、Firefox 132 三个内核，每个内核把38个页面（交互版各路由和静态页）在390、768、1440三种宽度下各打开一遍，检查脚本报错、整页横向溢出、空白页；再在1440和390两种宽度下各走一遍25步的功能流程（首页和搜索页输入时的提示栏 → 首页搜索Transformer → 读讲解 → 前驱后续 → 页内画树 → 标记状态、收藏、笔记 → 刷新后仍在 → 从零读到它 → 从开始学习页进入“大语言模型是怎么训练出来的”专题 → 输入“扩散模型”拿到路线 → 机制图 → 演化树展开、选中、跳到相关节点、回到原位、键盘操作 → 列表版 → 我的进度 → 导入 → 默认深色并切到浅色外观 → 旧链接 → 静态页的canonical和分享信息）。当前492/492通过。
  • 没有测的：真机（iPhone、安卓手机）、真正的Safari（WebKit内核不等于Safari本体）、屏幕阅读器的实际朗读效果、IE和很旧的浏览器。

15　已知问题与没做完的事

内容

  • 大部分内容仍是待核对。3372个节点里做过来源核对的是150个，人工复核0个；206个概念词条和264个研究思路都没有核对。已核对的节点里平均每个改了约7处，说明没核对的节点里也会有相当数量的事实错误和说过头的措辞，尤其是数字、作者单位、“首次”类说法和2024年以后的产品与事件。
  • “来源已核对”是AI模型做的，不是人做的。它会漏掉来源里没有、但写得像真的的细节；每条记录里的“仍未能核对”如实列出了没查到的部分。
  • 13143条关系里核对过的是1217条。没核对的关系里，“改进”一类（5618条）是从“局限”的后续工作自动生成的，最容易把“相关”说成“针对”。
  • 审计脚本在全站找到约1700处说得很满的措辞，其中九百多处是“首次、第一个”，没有逐条处理，清单在data/_audit/claims.md。
  • 约330个节点只有二手来源（维基百科、新闻）。按月份比较，有一百多条关系的两端时间对不上（多为同年不同月，可能是登记日期口径不同）。
  • 40多对研究思路有重叠（如“测试时训练”和“测试时适应”），是按分支各写一份造成的，没有合并。
  • 专题是事后整理的叙事。每篇写了它简化了什么，但读者仍可能把“上一站的问题是……”读成当事人的说法。

结构与交互

  • 主题线的划分和节点归属由模型完成，没有逐个复核；各分支都是11或12条，个别线是为凑数合并的。
  • “从零读到它”的主线是贪心算法挑的，个别节点的主线会经过不太相关的早期工作，或者跳过读者以为必经的一站。
  • 演化树在手机上能用但不好用：行名列占100px，横向滚动距离长。手机默认给列表就是因为这个。
  • 全部展开且显示全部节点时，树很宽很长，属预期，没有做虚拟滚动。
  • 学习进度只存在浏览器本地，没有同步；站内各处都写明了。

收录与工程

  • 根目录robots.txt和sitemap提交没有做（见第11节）。
  • 设计说明页的截图要手动重截；数字是自动的。
  • 没有给GitHub Issue建“内容纠错”的标签和模板，报错入口只预填了标题和正文。
