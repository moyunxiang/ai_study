这个网站是怎么设计的

网站本体（moyunxiang.com/ai_study）的所有页面都由脚本在浏览器里渲染，而且全部挂在同一个地址的#后面，所以不运行脚本的读者——包括大多数只抓网页文字的AI助手——只能看到一个空壳。这一页是纯静态的，把定位、信息结构、数据格式、每个页面的布局、演化树的画法、搜索规则、视觉规范和已知问题一次讲完，供人或AI助手评审并提出改进建议。页面里的数字每次构建时自动更新。

给评审者（包括AI助手）的说明。读完这一页就能了解整个设计。需要看原始实现时，第12节列出了每个源文件的直接地址；需要看实际界面时，第13节有截图。最想听的意见在第11节。评审时请区分三类问题：结构与信息架构、交互与视觉、内容的准确性与覆盖面。

1　目标、读者与非目标

一句话：把AI从1943年到今天的发展画成一棵按时间生长的树。只有基本编程和大一数学基础的人，靠它按时间顺序读下来，就能入门AI研究的各个方向。

读者：中文读者；会一点编程、学过微积分和线性代数的入门内容；没有读过论文。界面和讲解全部是中文，专有名词保留英文原文。

成功标准

  • 全。每条分支里真正有贡献的工作（论文、模型、系统、硬件、数据集、事件）都是树上的一个节点。
  • 每个节点都有讲解。当时卡在哪、它怎么解决、关键结果、留下什么问题、后来谁解决了这些问题。读者不看原文也能懂。
  • 连接带含义。节点之间的边有类型（解决、延续、使用、竞争）和一句说明，能回答“谁解决了谁的什么问题”。
  • 零基础可入门。讲解里遇到的概念都有词条可以点过去。
  • 结构看得懂。默认一屏总览，点开才展开细节。
  • 能查。现在大家在讨论的任何一篇论文、一个思路、一个概念，都能直接搜到（名字、英文原题、缩写、别名、中英文叫法都认），并且看到它长在树上的哪里。
  • 能跟着学。按时代、分支或主干路线阅读，记录学习进度。
  • 事实可追溯。每个节点记录写作时核对过的出处。

非目标

  • 不做后端、账号、评论。进度只存在浏览器本地，提供导出和导入。
  • 不追求收录每一篇顶会论文，标准是“有贡献”或“读者现在很可能听到这个名字并来搜它”。
  • 不做英文版。

2　信息结构

2.1　四层树

整个领域按“大方向 › 分支 › 主题线 › 节点”四层组织：6个大方向、16条分支、190条主题线、3309个节点。大方向用一棵树来比喻：

大方向在树上的角色包含的分支（括号里是代码里的key）
环境 · 社会气候：钱和人往哪边流、公众怎么看、谁来管思潮、机构与产业事件（biz）；安全、对齐与可解释性（safety）
语言与推理今天的主枝语言与NLP（nlp）→ Transformer与大语言模型（llm）→ 推理、检索与智能体（agent）
树干 · 学习方法所有分支共用的方法，画得最粗机器学习与深度学习基础（dl）
感知与生成大枝计算机视觉（vision）、语音与音频（speech）、生成模型（gen）、多模态理解（mm）
决策与真实世界大枝强化学习与博弈（rl）、具身智能与世界模型（robot）、AI for Science（sci）
土壤 · 数据、系统与算力树靠什么长数据集与评测（data）、系统、框架与效率（sys）、硬件与算力（hw）
  • 分支之间有分叉关系。每条分支记录它从哪条分支、在哪个节点处长出来，以及一句原因。例如大语言模型在2017年的Transformer处从NLP分叉，智能体在检索增强生成处从大语言模型分叉，系统在Theano处从硬件分叉。有7条分支是“独立的根”（没有母分支）。
  • 一条分支只画一个母分支，这是为了可读性做的简化。其余来源用14条手工挑选的“跨分支汇流”表示，例如“Transformer进入视觉（ViT）”“视觉语言模型直接输出动作（RT-2）”。
  • 主题线是分支下面的一层：沿着同一个问题接力的一串工作，规范允许每条分支6–12条，实际每条分支是11或12条，例如大语言模型下的“架构与组件”“长上下文与高效注意力”“非自回归与扩散”。每个节点只属于一条主题线；主题线之间也有“从哪条线分出来”的关系。

2.2　节点

  • 重要程度分三档：主干必读（tier 1，69个，缺了就讲不通）、重要（tier 2，702个）、延伸（tier 3，2538个）。几乎所有列表和树都能按这三档过滤。
  • 类型七种：论文2183、事件279、系统239、数据集239、模型129、硬件121、思想119。
  • 时间精确到年或月。另有9个时代（1943–1968起源、1969–1985寒冬与专家系统、1986–2005统计学习、2006–2011蓄力、2012–2016深度学习爆发、2017–2019 Transformer与预训练、2020–2022规模化与基础模型、2023–2024生成式AI浪潮、2025–2026推理、智能体与物理AI），时代和分支是两个正交的切法。

2.3　边

共12963条，方向统一为“较早 → 较晚”，四种类型：解决（5586）、使用（3328）、延续（2504）、竞争（1545）。每条边带一句说明。边有三个来源：登记表里的parents（默认算“延续”）、讲解里的relations（作者写明类型和说明）、讲解里“留下的问题”的solved_by（生成“解决”边，说明就是那个问题本身）。

2.4　基础概念与研究思路

  • 基础概念（206个）：读讲解前要先会的知识，如梯度下降、注意力、KL散度。分13个领域、3个难度（预备、入门、进阶），有“先要会”的依赖关系。每个概念记录出处节点（例如“自回归生成”从香农1948年的工作开始）和所有用到它的节点。
  • 研究思路（264个）：大家讨论时挂在嘴边的做法和话题，例如“在策略自蒸馏”“扩散语言模型”“智能体群”“测试时训练”。它不是某一篇论文，而是一串论文共同在做的事。每个思路有中英文名、一组别名、一句话定义、两三段正文、出处节点和属于它的节点列表（至少2个）。
  • 别名：节点、主题线、概念、思路都可以带别名（缩写、中文译名、产品代号），只用于搜索和“也叫”一行。

设计上的要求是：任何一篇论文、一个思路、一个概念，都必须落在树上——思路和概念通过“属于它的节点”落到树上，页面上直接画出来。

3　数据文件与构建

所有内容是仓库里的纯文本文件，由scripts/build.py校验并生成站点读取的JSON。没有数据库。

构建做的校验

  • 登记表：id唯一、日期格式、档位和类型合法、parents都已登记且不晚于自己、官方标题重复时警告。
  • 讲解：只允许规定的字段，短字段有长度上限，relations必须指向更早的节点并写明类型和说明，正文里的[[…]]链接必须能解析。
  • 树：6个大方向不重不漏地覆盖16条分支；分叉和汇流里的节点都存在；主题线的母线不能成环；每个节点都有主题线（漏写时按同分支的第一个parent自动归入并警告）。
  • 思路：key不和概念冲突，至少2个已登记的节点，链接可解析。

有任何错误就不生成输出。当前状态：0错误，4条有意保留的警告。

4　内容规范：一个节点写什么

每个节点一个JSON文件。短字段显示在卡片、列表和树的侧栏里，长字段是讲解页的正文。

{
  "id": "与文件名一致",
  "who": "主要作者 · 机构",
  "venue": "NeurIPS 2017",
  "links": [{"label": "arXiv", "url": "https://…"}],

  "problem": "当时卡在哪里",        // 三个短字段，每个一两句话，约80字以内
  "idea":    "它怎么解决的",
  "impact":  "它改变了什么",

  "background": "背景：当时的主流做法是什么，具体卡在哪",
  "method":     "方法：核心机制，讲到读者能向别人复述，该有公式就给公式",
  "results":    "结果：关键实验和数字",
  "legacy":     "后续：它直接催生了什么，今天还在用吗",
  "pitfalls":   "常见误解",

  "limits":    [{"text": "它留下的一个具体问题", "solved_by": ["后来解决它的节点id"]}],
  "relations": [{"to": "更早的节点id", "type": "solves | extends | uses | rivals", "note": "一句话"}],

  "prereq": ["读懂这篇要先会的概念key，3–8个"],
  "terms":  [{"t": "本篇新出现的术语", "d": "一两句大白话"}],
  "learn":  "怎么学：先补什么 → 读原文哪几节 → 动手做什么",
  "check":  {"source": "写作时实际打开核对的地址", "confirmed": "核对了什么"},
  "aka":    ["别名", "缩写"]
}
  • 写法：面向没读过论文的人；先讲问题再讲解法；数字、作者、机构、日期只写打开原始出处确认过的；正文用空行分段，支持列表、粗体、行内代码和[[链接]]。
  • 三档的要求不同：主干节点要写满所有字段并讲透方法；延伸节点可以短，但三个短字段、留下的问题和关系必须有。
  • 谁写的：全部讲解、概念词条、思路、主题线划分和别名都由AI模型按guide/目录里的规范撰写，要求联网对照原文。站长只抽查了少量节点，没有逐条人工复核。站点页脚写明“仍可能有错，请以原文为准”。
  • 规范文件：guide/census.md（收什么、怎么登记）、guide/content.md（讲解和概念词条怎么写）、guide/threads.md（主题线怎么划）、guide/hot.md（补录当下在讨论的工作、写思路、补别名）。

5　页面与路由

单页应用，路由全部在#后面。顶栏固定：站名、8个导航（指南、路线、时代、分支、全景树、概念、开放问题、我的）、搜索框、主题切换。

5.1　节点讲解页的结构（从上到下）

  1. 页头：面包屑（大方向 › 分支 › 主题线 · 时代）、标题、英文原题、日期、类型、档位、发表处、作者和机构；一排操作（学习状态、在全景树上的位置、只看来龙去脉、学习链、和另一个工作的联系、收藏、原文链接）。
  2. 三格摘要：当时卡在哪、它怎么解决、改变了什么。不想读全文的人看到这里就够了。
  3. 它长在树上的哪里：一棵小树，画出它所在的主题线、它直接建立其上的工作和直接接着它做的工作，只画和它相连的边；旁边列出它所属的思路。
  4. 正文：先要会的概念 → 背景 → 方法 → 结果 → 后续 → 常见误解 → 本篇术语 → 它留下的问题（每条标出后来的解决者，或标“可能仍是开放问题”）→ 它建立在什么之上 → 后来谁接着做 → 怎么学 → 同一年别的分支在做什么 → 我的笔记。
  5. 页尾：核对出处；本分支上一个、下一个节点；主干下一站。左右方向键翻页。

正文栏宽812px，嵌入的小树用页面全宽（1180px）。

5.2　学习进度

每个节点和概念右侧有一个圆点，点一下在“未读 → 在读 → 已读”之间切换。已读的节点在树上加删除线。进度、收藏、笔记、自测的薄弱卡片、全景树的设置、主题选择都存在浏览器的localStorage里（键名以aimap.开头），可以导出成一个JSON文件再导入。

6　演化树的画法

这是整个站点的核心可视化，由两个函数完成：treeLayout在抽象坐标里算位置（t是时间方向，c是横断方向），treeDraw把它映射成像素。横向（时间从左到右）和竖向（根在下、往上长）共用同一套布局，只在最后映射时不同。宽屏默认横向，窄于760px默认竖向，用户可以切换，选择会被记住。

6.1　行

  • 一行是一条分支，按大方向分组。树干（学习方法）在正中；排在树干前面的大方向里，分支倒序排，让更早的分支贴着树干。
  • 收起的分支只标“地标节点”：它的主干节点，不足3个时用连接最多的重要节点补足。行上画一条密度带，粗细随这一年这条分支的节点数起伏（高度与节点数的平方根成正比）。
  • 展开一条分支（点左边的分支名）：这一行变成一个标题行加若干主题线行，每条主题线一行，从它的母线分叉出来。可以同时展开多条，有“全部展开”和“全部收起”。展开后显示哪些节点由“主干 / + 重要 / 全部”三档控制。
  • 仍然活跃的线（最后一个节点在最近两年内）末端画箭头并延伸到最右；已经停止的线画一个终止符并标“止于某年”。

6.2　时间轴

  • 非线性。一年占多长，取决于这一年要画多少个节点：没有节点的年份压得很短，拥挤的年份拉长（横向时长度约为“节点数的0.7次方”的线性函数，上限200px）。1943年以前压成一小段，标“更早”。
  • 缩放三档：适应屏幕、1×、2×。“适应”会把整棵树压进一屏宽，下限是原长的20%。
  • 时代作为背景的交替色带，顶部固定一行时代名和年份刻度（可点进时代页和年度页）；左侧固定一列行名。

6.3　节点和标签

  • 节点是一个带圆点的文字标签（绝对定位的链接），不是纯圆点，所以不用悬停就能读出名字。主干节点24px高、加粗、带分支色的边框和底色；重要节点20px高、白底细边；延伸节点没有边框。标签最宽190px，超出截断。
  • 不重叠：每个标签沿时间方向占一段区间，同一行里放不下就换到下一子行（贪心装箱，先放主干节点），行高随子行数增长。竖向时每列固定宽126px，节点按时间往上叠。

6.4　线

  • 默认不画节点之间的边，结构由行和分叉表达，否则一万多条边会糊成一团。
  • 分支和主题线各有一条轨道（分支2.6px，树干5px，主题线1.6px），用分支的颜色；分叉用圆角折线从母线接到子线，接点在分叉节点的年份。没有母分支的几条根在最左边用一条竖线连起来。
  • 跨分支汇流是灰色虚线，只在两端的分支都收起时画，可以整体关掉；鼠标停在线上显示说明。
  • 悬停或点一个节点时，才画出它的所有连接，其余节点变淡。四种边的画法：解决是红色实线，延续是灰色实线，使用是灰色虚线，竞争是绿色点线。
  • 点节点后右侧滑出一个360px的讲解面板（窄屏时从底部升起，最高占62%）：三格摘要、它建立在什么之上、后来谁接着做、“读完整讲解”和“只看来龙去脉”。

6.5　同一套画法的几种用法

7　搜索

完全在浏览器里做，没有服务端。顶栏输入时下拉显示前几条，回车进入结果页；按/聚焦搜索框。

7.1　索引里有什么

  • 节点：标题、英文原题、别名、作者机构、三个短字段、所在分支名；另有“英文原题首字母缩写”。
  • 主题线：名称、简介、别名。
  • 概念和思路：中文名、英文名、别名、一句话定义。
  • 术语表里的术语。
  • 可选的全文：16个分支的讲解正文，第一次用到时才下载。

7.2　打分

命中方式分数
和标题完全相同100
和某个别名完全相同80
是标题或别名里的一个完整英文单词70
是标题或别名的开头60
出现在标题或别名中间40
出现在其他主要字段里20
是英文原题的首字母缩写14
出现在次要字段里6
  • 同义词：手写了约100组中英文同义叫法（如rl = 强化学习 = reinforcement learning，kd = 蒸馏），通过同义词命中的分数打八折。
  • 短英文词（4个字母以内）只在单词开头处匹配，避免“marl”命中人名里的片段。
  • 多个词：默认要求每个词都命中。整个查询正好等于某个标题或别名时直接算满分。完全命中的结果少于8条时，补上“只匹配了部分关键词”的结果，但必须包含最稀有的那个词，并按词的稀有程度加权。
  • 中文长串（4个字以上、没有空格、没有任何命中）自动切成两个词再搜。
  • 自动全文：标题和别名里命中的节点少于6个时，自动把讲解正文也搜一遍。

7.3　结果页（从上到下）

  1. “主题线、概念、思路与术语”：命中的非节点结果，用卡片显示。
  2. “它在树上的位置”：一棵嵌入的小树。画哪些节点：最多3个强命中的主题线、概念或思路的全部成员，加上命中分数高的节点；都没有时取前30个节点。可以一键在全景树里打开。
  3. “节点”：按分数排的列表，可改为按时间排。
  4. “讲解正文里提到”：只在全文里命中的节点。
  5. “只匹配了部分关键词”。

  • 打印：隐藏顶栏、按钮和页脚，白底。

9　技术实现与部署

  • 无依赖、无构建工具。一个index.html、一个app.js（约125KB，未压缩未混淆）、一个style.css（约28KB）。页面用模板字符串拼HTML后整体替换；树用绝对定位的链接加两层SVG。
  • 哈希路由。所有页面是index.html#/…。好处是纯静态托管、子路径零配置；代价见第10节。
  • 数据：启动时并行取graph.json和concepts.json，在内存里建好索引（按id、按分支、入边、出边、主题线成员、每年节点数）；讲解正文按分支懒加载并缓存。
  • 缓存：每次构建生成一个版本戳，写进index.html，所有脚本、样式和数据请求都带上它。
  • 部署：GitHub Pages从main分支的/docs目录发布，推送后约一分钟生效。本地预览是python3 -m http.server -d docs。
  • 内容生产：分支定义、时代划分、规范、校验和前端由站长和一个AI助手设计；节点普查、逐节点讲解、概念、主题线、思路和别名由多个后台AI代理按规范并行完成，每个代理只负责一条分支。

10　已知问题与做过的取舍

内容

  • 全部讲解由AI撰写，没有逐条人工复核。规范要求打开原文核对并记录出处，但有一部分延伸节点是在查询工具被限流时凭模型记忆写的；2025–2026年的产品和行业事件有些只有二手来源。
  • 覆盖面不均。每条分支每轮补录有名额上限，另有约120个“该收但没排上”的近期工作和约380个更早的候选没收。
  • 思路之间有重叠。思路按分支各写一份，同一个话题可能出现两条（例如“测试时训练”和“测试时适应”、强化学习分支的“群体智能”和基础分支的“群体优化”）。
  • 主题线的划分由模型完成，多条分支都用满了12条的上限，个别线是为了凑上限合并的。

结构

  • 一条分支只有一个母分支，多模态这类同时来自两边的分支只能画一边，另一边靠汇流虚线。
  • 一个节点只属于一条分支、一条主题线，跨领域的工作（例如同时属于强化学习和大语言模型的）只能选一边，靠思路层和边来补。

性能

  • 首屏数据大：打开任何页面都要先取约6.5MB（压缩后约2.5MB）的两个文件，哪怕只看一个节点。
  • 全文搜索第一次要下载全部16个讲解文件（约7.8MB）。耗时没有测过。
  • 全部展开且显示全部节点时，页面上有三千多个绝对定位的元素，页面很长很宽。这是预期内的极端情况，没有做虚拟滚动。

可达性与可见性

  • 搜索引擎和AI助手读不到内容：哈希路由加脚本渲染，没有任何一个节点有独立的、不运行脚本就能读的地址。这一页是目前唯一的补救。
  • 无障碍：树是视觉化的，没有为读屏软件提供等价的结构；节点标签可以用Tab聚焦，但没有方向键导航；颜色对比度没有系统检查过。
  • 没有分享卡片：所有页面共用同一个标题和描述，分享到社交平台时看不出是哪个节点。

没有验证过的

  • 只在桌面Chrome上看过。没有在真机手机、Safari、Firefox上测试。
  • 手机宽度下只有截图（见第13节的16–20），没有实际用手操作过。截图里能看到的问题：嵌入在搜索页、概念页、节点页里的小树，左侧的行名列固定168px，占了近一半宽度，树本身只剩约190px，必须横向滑动；节点页页头里很长的原文链接按钮会折成两行。
  • 搜索只用约十几个查询词人工检查过第一屏，没有系统的评测集。

其他取舍

  • 进度只存本地，换设备会丢；没有同步。
  • 同义词表是手写的，遇到搜不到的叫法只能靠补别名或补同义词。
  • 树上默认不画边，读者可能意识不到点节点能看到连接；指南页里写了，但界面上的提示很弱。

11　最想听到的建议

  1. 信息架构：“大方向 › 分支 › 主题线 › 节点”加上正交的“时代”“概念”“思路”，对一个入门者来说是不是层次太多？首页应该先把人带到哪里？
  2. 树的可读性：一屏总览 → 点开分支 → 点节点看连接，这个三步模型是否直观？默认不画边、节点用文字标签、非线性时间轴，这三个决定有没有更好的替代？
  3. “每个思路和概念都长在树上”现在的做法是在页面里嵌一棵过滤后的小树。有没有更清楚的表达方式？
  4. 节点讲解页的顺序和长度是否合适？三格摘要之后紧跟小树、再跟正文，会不会打断阅读？
  5. 搜索：打分规则和结果页的五个区块是否合理？在不加后端的前提下，怎样系统地发现“搜不到”的词？
  6. 首屏性能：怎样拆分graph.json最合算（例如把边的说明、别名、短字段拆成按需加载）？
  7. 可见性：要不要在构建时为每个节点生成一个静态页面，让搜索引擎和AI助手能直接读？对纯静态托管来说代价多大？
  8. 内容质量：在没有人力逐条复核的前提下，怎样排优先级去核对三千多篇AI写的讲解？怎样向读者标明每一篇的可信程度？
  9. 学习功能：路线、学习链、自测卡片、进度，这些对真正想入门的人够用吗？缺什么？
  10. 手机上的体验：竖向的树、底部升起的面板、横向滚动的导航，是否可用？
