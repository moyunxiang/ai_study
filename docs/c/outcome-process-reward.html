结果奖励与过程奖励（ORM/PRM）

Outcome and Process Reward Models

也叫：ORM　outcome reward model　结果奖励模型　process reward model　过程奖励模型　过程监督　process supervision　结果监督　outcome supervision　verifier　验证器　步骤级奖励　step-level reward

在交互版中打开（看它长在树上的哪里）

给推理过程打分的两种方式：结果奖励模型（ORM）只看最终答案对不对，过程奖励模型（PRM）给每一个推理步骤单独打分。PRM能指出错在哪一步，但标注更贵。

先要会：奖励模型 信用分配

一道数学题的解答有十几步。只告诉模型“最后答案错了”，它很难知道是哪一步出了问题，这就是长推理里的信用分配难题。而且答案对了不代表过程对：模型可能中间算错两次、碰巧抵消。于是出现了两种监督粒度。

结果奖励模型（outcome reward model，ORM）。输入题目和完整解答，输出“这个解答最终正确”的概率。训练数据很容易得到：采样大量解答，按最终答案是否正确自动打标签。GSM8K的论文就训练了这样的“验证器”，在多个候选里挑最可能正确的那个（见best-of-N与拒绝采样微调）。在答案可以直接校验的场景，ORM甚至可以换成规则校验器（见可验证奖励强化学习（RLVR））。

过程奖励模型（process reward model，PRM）。对解答的每一步分别判断“这一步是否正确”。一个解答的整体分数可以取各步正确概率的乘积或最小值。

  • 人工标注：过程监督与过程奖励模型（OpenAI的“Let’s Verify Step by Step”）请标注员逐步标注了大量数学解答，发现用PRM挑选解答明显好于用ORM。
  • 自动标注：人工逐步标注很贵。Math-Shepherd自动过程监督从某一步出发继续采样多条后续解答，用能走到正确答案的比例估计这一步的质量，相当于用蒙特卡洛采样估计这一步的价值。PRIME隐式过程奖励则从结果奖励中隐式地学出每个token的过程奖励。

怎么用。

  • 挑选：best-of-N或加权投票时作为打分器。
  • 搜索：在推理的每一步用PRM给候选打分，保留高分分支，类似束搜索或树搜索（见博弈树搜索：minimax与MCTS）。
  • 强化学习：提供逐步的稠密奖励，代替末尾的单一奖励。

争议。DeepSeek-R1的报告称，在他们的大规模强化学习中尝试过PRM但没有成功，原因包括“一步”很难明确定义、自动标注的步骤标签噪声大、模型容易钻PRM的空子。之后不少推理模型主要用结果奖励训练，PRM更多用于推理时的搜索和挑选。两种粒度各有适用场景，并没有定论。

例子

题目：“3个苹果每个2元，再买1瓶4元的水，一共多少钱？”某解答：

  • 第1步：苹果 3×2 = 6元 ✓
  • 第2步：6 + 4 = 11元 ✗
  • 第3步：答案11元

ORM只看到答案11 ≠ 10，给整段低分。PRM给三步打分 (0.95, 0.10, 0.20)，指出错误出在第2步。

另一个解答：“3×2 = 5，5 + 4 = 10，答案10元。”ORM判它正确（答案对了），PRM会在第一步给低分，识别出“答案对但过程错”。

容易误解的地方

  • PRM的“步”通常按换行切分，切法不同，步骤分数就不同。
  • 用PRM做强化学习奖励时，模型可能学会把推理拆成很多“看起来正确”的小步来刷分。
