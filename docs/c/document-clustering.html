文本聚类

Document Clustering

也叫：文本聚类　文档聚类　document clustering　text clustering　新闻聚类　news clustering　话题发现　topic discovery　短文本聚类　short text clustering　调整兰德指数　adjusted Rand index　ARI　归一化互信息　NMI　轮廓系数　silhouette score　HDBSCAN　话题检测与跟踪　topic detection and tracking

不依赖标签，把内容相近的文档自动归组：先把文档变成向量（TF-IDF、主题分布或句向量），再用k-means、层次或密度聚类分组。用于新闻聚合、话题发现、整理检索结果。

先要会：聚类 嵌入向量

每天上万条新闻，哪些在讲同一件事？几十万条用户反馈，主要集中在哪几类问题？一次搜索返回几百篇文档，能不能按子话题分组展示？这些都是文本聚类的应用。它是聚类在文本上的具体做法，难点主要在“怎样把文档变成好的向量”。

第一步：表示。

  • 词袋与TF-IDF：每篇文档是一个词表大小的稀疏向量，用IDF与TF-IDF加权，降低“的”“是”这类常见词的权重。维度高达数万，常用降维与PCA（如截断SVD，即潜在语义分析LSA，见低秩近似）压到几百维。
  • 主题分布：用LDA主题模型等主题模型把每篇文档表示成主题比例（见主题模型）。主题模型本身就是一种“软聚类”。
  • 句向量：用Sentence-BERT等编码器把整篇文档编码成稠密向量（见嵌入向量），能识别用词不同但意思相近的文档，是现在的主流选择。

第二步：聚类。

  • k-means：配合余弦相似度（先把向量归一化到单位长度，见内积与余弦相似度），简单快速，需要预先指定簇数k（见k-means聚类）。
  • 层次聚类：自底向上合并最相似的簇，得到一棵树，可以在不同粒度上切分，适合话题有层级的情况。
  • 密度聚类：HDBSCAN不需要指定k，还能把不属于任何簇的文档标成噪声。BERTopic主题模型的流程就是“句向量 → UMAP降维降维 → HDBSCAN聚类 → 用按类计算的TF-IDF给每个簇起名”。

第三步：解释与评估。聚完后要给每个簇找代表词或代表文档，方便人理解。有人工标签时可以用纯度、调整兰德指数、归一化互信息等外部指标（见互信息）；没有标签时看轮廓系数等内部指标，最终还要人工抽查。

流式场景。新闻话题检测与跟踪要求在线处理：新文档到来时，若与已有某个簇足够相似就并入，否则开一个新簇（见在线学习与遗憾）。

与近似重复检测的区别。聚类找“话题相同”的文档，近似重复检测：MinHash与SimHash找“内容几乎一样”的文档，后者的相似度阈值高得多。

例子

5条新闻标题：A“央行宣布降准0.5个百分点”、B“降准释放长期资金约1万亿元”、C“国足主场2比1取胜”、D“世预赛国足逆转对手”、E“央行下调存款准备金率”。用句向量加k-means（k = 2）：A、B、E一组（货币政策），C、D一组（足球）。E与A几乎不共享词汇（“降准”与“下调存款准备金率”），TF-IDF表示可能把它分错，句向量则能识别两者同义。（标题为虚构示例）

容易误解的地方

  • 聚类结果没有“唯一正确答案”：同一批新闻可以按话题、地区或情感来分，取决于表示方式和目的。
  • k-means偏好大小相近、近似球形的簇；话题规模差别悬殊时，大话题可能被拆开、小话题被吞并。
