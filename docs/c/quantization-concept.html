量化

Quantization

也叫：权重量化　weight-only quantization　W4A16　W8A8　训练后量化　post-training quantization　模型量化　INT4　INT8量化　低比特　PTQ　QAT　量化感知训练

在交互版中打开（看它长在树上的哪里）

把模型的权重（有时也包括激活值）从16位浮点数换成8位、4位等更少比特的数来存和算，用少量精度损失换取几倍的显存节省和速度提升。

先要会：浮点精度：FP32、FP16、BF16、INT8

一个70亿参数（7B）的模型，用FP16存需要14GB，普通笔记本和手机根本放不下；生成每个token又要把这14GB完整读一遍（见显存、内存带宽与“内存墙”），读得越多越慢。量化的想法很直接：神经网络的权重大多集中在一个不大的区间里，不需要16位那么精细，用更少的比特近似它们，模型往往几乎不变差。

基本做法：线性量化。选一个缩放因子s（有时再加一个零点z），把实数映射到整数：

q = round(w / s)，反量化ŵ = q · s

对称INT8取s = max|w| / 127，于是q落在−127到127之间。误差最多是s/2。缩放因子的粒度很关键：整层共用一个s最省，但一个离群大值就会让其余权重都挤在少数几个整数上；所以实际做法是按通道或每32/64/128个数一组各用一个s。

两条路线。训练后量化（PTQ）：模型训好之后直接量化，可用少量校准数据挑选更好的取整方式，代表是GPTQ训练后量化、AWQ激活感知量化。量化感知训练（QAT）：训练时就模拟量化误差，让模型适应它，见量化感知训练与整数推理。大语言模型的难点是激活值里有少数特别大的离群维度，LLM.int8()与离群特征和SmoothQuant专门处理它们。

量化什么。只量化权重最常见（解决显存和带宽），推理时再反量化成BF16计算；同时量化激活值才能真正用上INT8/FP8计算单元（见浮点精度：FP32、FP16、BF16、INT8）；KV缓存也可以量化（见KV缓存）。

它出现在哪里：本地跑大模型几乎都靠4位量化，llama.cpp与本地推理和GGUF与k-quants格式让7B模型能在笔记本上运行；QLoRA在4位冻结权重上做微调；极端情况下1.58比特模型BitNet把权重压到三值{−1, 0, 1}。量化也和知识蒸馏、剪枝一起被称为模型压缩。

例子

四个权重[0.12, −0.5, 0.33, 0.9]做对称INT8量化：s = 0.9/127 ≈ 0.00709，q = [17, −71, 47, 127]，反量化得[0.1205, −0.5031, 0.3331, 0.9]，最大误差约0.003。

7B模型的权重占用：FP32为28GB，FP16/BF16为14GB，INT8为7GB，4位为3.5GB。如果每128个权重存一个FP16缩放因子，额外只多约0.11GB。所以4位7B模型连同KV缓存和运行开销，一块8GB显存的显卡就能跑。

容易误解的地方

  • 量化省的是显存和带宽；如果硬件没有低比特计算单元，计算时仍要反量化回BF16，算力并没有省。
  • 位数越低损失越不均匀：困惑度只涨一点，不代表数学、代码等难任务也只掉一点，需要在具体任务上评测。
  • 4位、3位的“同名”格式之间差别很大（分组大小、是否非均匀、离群值处理），不能只看比特数比较。
