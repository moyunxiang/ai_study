参考模型与KL惩罚

Reference Model and KL Penalty

也叫：KL penalty　KL惩罚　KL正则　KL regularization　KL约束　KL constraint　reference model　参考模型　π_ref　ref model　KL系数　beta　β系数　k3估计　k3 estimator　KL估计　adaptive KL

在交互版中打开（看它长在树上的哪里）

大模型强化学习和偏好优化里的“缰绳”：保留一份训练前的模型作为参考模型π_ref，在目标中减去当前策略与它之间的KL散度乘以系数β，防止模型为了刷奖励而偏离正常语言太远。

先要会：KL散度 人类反馈强化学习

用奖励训练语言模型时，模型总能找到让奖励变高的捷径：重复奖励模型喜欢的词、输出极长的回答、甚至生成不像人话的字符串（见奖励作弊）。而且语言模型一旦大幅偏离预训练学到的分布，流畅性和知识也会受损。解决办法是把模型“拴”在一个起点附近。

目标函数。在RLHF中（见人类反馈强化学习）：

max_π E_(x, y∼π)[ r(x, y) ] − β · KL( π(·|x) ‖ π_ref(·|x) )

  • 参考模型π_ref：通常是RL之前的监督微调模型，参数冻结、不再更新。训练时它和策略一起前向计算，提供每个token的对数概率。
  • β：KL系数，越大越保守。InstructGPT与RLHF等工作中，它控制着“奖励涨多少”和“偏离多远”之间的权衡；有的实现会动态调整β，使KL保持在目标值附近。

按token实现。整段回答的KL写成每个token对数概率比的和。常见做法是把它并入奖励：每个token的奖励为−β · log(π(y_t)/π_ref(y_t))，最后一个token再加上奖励模型的分数。

KL的估计（见KL散度）。精确KL要对整个词表求和，实践中用采样得到的token估计。设ρ = π_ref(y_t) / π(y_t)：

  • k1 = −log ρ：无偏，但单个样本可能为负，方差大。
  • k3 = (ρ − 1) − log ρ：无偏且恒为非负，方差较小。

这几种估计由Schulman在一篇博客中整理，GRPO把k3形式的KL项直接加在损失里，而不是并入奖励。

在别处的形式。DPO直接偏好优化的推导从同一个带KL约束的目标出发，参考模型以log(π/π_ref)的形式出现在损失里；ORPO无参考模型偏好优化、SimPO等方法尝试去掉参考模型以节省显存。推理模型的RL中（见可验证奖励强化学习（RLVR）），不少工作（如DAPO）发现去掉KL项反而更好，因为希望模型的推理方式能大幅改变；是否保留它仍取决于任务。

例子

某个token：策略π给它的概率0.6，参考模型π_ref给0.3。ρ = 0.3/0.6 = 0.5。

  • k1 = −log 0.5 ≈ 0.693
  • k3 = (0.5 − 1) − log 0.5 ≈ −0.5 + 0.693 = 0.193

设β = 0.05，按k1并入奖励时这个token被扣0.05×0.693 ≈ 0.035分。一段200个token的回答若平均每个token的k1为0.3，总惩罚约0.05×60 = 3分，如果奖励模型对它的打分只比原始回答高2分，这次偏离就是不划算的，模型会被拉回去。

容易误解的地方

  • 参考模型要和策略用同样的输入格式和分词，否则对数概率比没有意义。
  • β太大，模型几乎学不动；β太小，很快出现奖励作弊。调β时应同时看奖励和KL两条曲线，而不只看奖励。
