奖励、回报与折扣

Reward, Return and Discounting

也叫：折扣因子　discount factor　γ　累计奖励

在交互版中打开（看它长在树上的哪里）

奖励是环境在每一步给出的一个数；回报是从某一刻起所有未来奖励的（折扣）总和。强化学习要最大化的是期望回报，而不是眼前这一步的奖励。

先要会：期望与方差 马尔可夫决策过程

强化学习不像监督学习那样告诉模型“正确答案是什么”，只给一个数说“刚才这步怎么样”。这个数就是奖励r。下棋时可能只有最后一步才有奖励（赢+1、输−1），中间每步都是0；控制机器人走路时可能每步都按前进距离给奖励。

回报。只看眼前奖励会短视：棋局里吃掉对方一个子（眼前有利）可能导致输棋。所以真正要优化的是从时刻t开始所有未来奖励的总和，叫回报（return）：

G_t = r_{t+1} + γ·r_{t+2} + γ²·r_{t+3} + … = Σ_k γ^k·r_{t+k+1}

它满足一个递推关系：G_t = r_{t+1} + γ·G_{t+1}，这是Bellman方程的来源。环境有随机性、策略也可能随机，所以优化目标是回报的期望与方差意义下的期望。

折扣因子γ。取值在0到1之间，有三个作用：一是数学上保证无限长任务的回报有界（每步奖励最多为1时，总和不超过1/(1−γ)）；二是表达“早拿到的奖励更确定”；三是控制智能体看多远——γ=0.99时大约关注未来100步，γ=0.9时约10步。γ越接近1越有远见，但学习也越难，因为要把远处的奖励归功到早先的动作上，见信用分配。

它在哪里。DQN把Atari游戏分数的变化当奖励，并把它裁剪到−1到+1之间以统一不同游戏的尺度；AlphaGo只在终局给胜负奖励；用人类偏好微调语言模型里奖励来自一个模仿人类偏好打分的奖励模型，整段回答结束后才给一个分数。奖励怎么定会极大影响学到的行为，见奖励设计与奖励投机。

例子

一局游戏四步的奖励为(0, 0, 0, 10)，γ=0.9。从起点算回报：G₀ = 0 + 0.9×0 + 0.9²×0 + 0.9³×10 = 7.29。用递推从后往前算更方便：G₃=10，G₂=0+0.9×10=9，G₁=0+0.9×9=8.1，G₀=0+0.9×8.1=7.29。

若每步奖励恒为1且永不结束，回报为1/(1−γ)：γ=0.9时是10，γ=0.99时是100。这就是“有效视野约为1/(1−γ)步”的来历。

容易误解的地方

  • 奖励和回报经常被混用。奖励是单步的，回报是累积的；价值函数估计的是期望回报。
  • 奖励的下标约定不统一：有的书写r_t，有的写r_{t+1}表示“在t时刻做动作后得到的奖励”。
  • γ既是问题定义的一部分，也常被当作调节学习难度的超参数，两种用法要分清。
