排序指标：NDCG、MRR与Recall@K

Ranking Metrics: NDCG, MRR, Recall@K

也叫：排序指标　ranking metrics　检索指标　retrieval metrics　NDCG　nDCG　NDCG@10　DCG　归一化折损累计增益　normalized discounted cumulative gain　MRR　MRR@10　平均倒数排名　mean reciprocal rank　平均精度均值　mean average precision　Recall@K　R@K　Precision@K　P@K　Hit Rate　HR@K　Hits@K　hits@10　命中率

评价搜索、推荐、检索结果排序好坏的指标：Recall@K看前K个里找回了多少相关项，MRR看第一个相关项排在第几，NDCG按位置折扣给分并支持多级相关度。

先要会：准确率、精确率、召回率与F1

检索系统返回的是一个有序列表，用户只会看最前面的几条。所以评价时不仅要问“相关的东西找到了没有”，还要问“排在第几位”。设对一个查询返回的列表中，第i位结果的相关度为rel_i。

Precision@K与Recall@K。前K个结果中相关项所占比例是Precision@K；前K个结果里找回的相关项占全部相关项的比例是Recall@K。推荐系统的召回阶段、检索增强生成的检索器常报告Recall@K：答案所在的段落有没有进入前20、前100。Hit Rate@K（或Hits@K）只问前K个里是否至少有一个相关项，在每个查询只有一个正确答案时等于Recall@K。

MRR（平均倒数排名）。对每个查询，找到第一个相关结果的位置r，取1/r；再对所有查询取平均。第一条就对得1分，第二条0.5，第十条0.1。适合“只需要一个正确答案”的场景，如问答检索。MS MARCO的段落排序官方指标是MRR@10。

MAP（平均精度均值）。对每个查询，在每个相关结果出现的位置计算Precision@k，再平均得到AP；对所有查询取平均就是MAP。它同时考虑了所有相关项的位置。

NDCG（归一化折损累计增益）。允许多级相关度（如0到3分），并对靠后的位置打折：

DCG@K = Σ_{i=1}^{K} (2^{rel_i} − 1) / log₂(i + 1)

把DCG除以“理想排序”下的DCG（IDCG），得到0到1之间的NDCG@K。BEIR零样本检索、MTEB嵌入基准的检索任务主要报告NDCG@10；TREC文本检索评测评测也大量使用它。

和训练目标的关系。这些指标对排序是离散的、不可导，不能直接作为损失。学习排序方法用可导的替代：RankNet排序学习用成对的交叉熵，ListNet列表式排序用列表级的概率分布，LambdaRank与LambdaMART用“交换两项对NDCG的影响”给梯度加权（见合页损失与间隔类损失中的排序损失）。

它出现在哪里。搜索引擎、推荐系统与协同过滤、稠密检索（见双塔模型与交叉编码器和检索与向量数据库）、知识图谱链接预测（Hits@10、MRR）。线下排序指标最终还要用A/B测试与在线实验验证。

例子

一个查询返回5条结果，相关度依次为(3, 0, 2, 0, 1)。

  • 第一个相关项在第1位，倒数排名为1。
  • DCG@5 = 7/1 + 0 + 3/2 + 0 + 1/log₂6 ≈ 7 + 1.5 + 0.387 = 8.887；理想排序(3, 2, 1, 0, 0)的DCG = 7 + 3/1.585 + 1/2 ≈ 9.393；NDCG@5 ≈ 0.946。
  • 只把相关度 > 0 当作相关：Precision@3 = 2/3，若总共只有这3个相关项，Recall@3 = 2/3。

容易误解的地方

  • 不同论文的NDCG公式略有差异（分子用rel还是2^rel − 1），只有同一实现下的数字才能直接比较。
  • 相关性标注通常不完整，没被标注的结果默认算不相关；系统找到了真正相关却未被标注的结果，分数反而会被低估。
