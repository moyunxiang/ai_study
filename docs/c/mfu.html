MFU：模型FLOPs利用率

Model FLOPs Utilization (MFU)

也叫：MFU　模型FLOPs利用率　模型算力利用率　model FLOPs utilization　HFU　硬件FLOPs利用率　hardware FLOPs utilization　算力利用率　GPU利用率　FLOPs利用率　训练效率

在交互版中打开（看它长在树上的哪里）

模型FLOPs利用率：训练（或推理）实际完成的“模型本身需要的”浮点运算速率，占硬件理论峰值的比例。它是衡量大规模训练系统效率最常用的单一指标，常见的好成绩在40%到60%之间。

先要会：参数量、计算量与显存 CPU、GPU与并行计算

买了一千张GPU，每张的标称算力是每秒近千万亿次运算，训练却远达不到“一千倍”的速度：数据要在显存和计算单元之间搬运（见显存、内存带宽与“内存墙”），卡与卡之间要通信（见集合通信原语：all-reduce、all-gather与all-to-all），流水线有空泡，有的计算还要重算。MFU（Model FLOPs Utilization）把这些损失合成一个数。

定义。

MFU = (每秒处理的token数 × 每个token所需的模型FLOPs) / (卡数 × 每卡峰值FLOPS)

Transformer训练时，每个token约需6N次运算（N为参数量；前向2N、反向4N，见参数量、计算量与显存），长序列时再加上注意力的部分。关键是分子只算模型数学上必须的运算。

MFU与HFU。如果用了梯度检查点，反向时会重算一部分前向，硬件实际做的运算更多。把重算也算进去的叫硬件FLOPs利用率（HFU）。HFU可以通过多重算而“刷高”，MFU不会，所以MFU更适合比较不同系统。PaLM提出用MFU作为标准，报告其540B模型达到46.2%，同表中GPT-3为21.3%。

典型取值与提升手段。序列并行与选择性重计算用序列并行加选择性重算，把MFU从42.1%提到54.2%；MegaScale万卡训练与容错报告在上万张GPU上的大模型训练中取得了比Megatron-LM更高的MFU。提升MFU的常见手段：算子融合与FlashAttention减少显存读写；让通信与计算重叠；选择合适的并行组合以减少跨机通信（见分布式训练：数据并行与模型并行）；用FP8等更低精度提高峰值（但这时分母的峰值也变了，比较时要注意）。

为什么不是100%。即使单个大矩阵乘法也只能达到峰值的七八成；归一化、激活函数等逐元素运算受带宽限制，几乎不贡献“模型FLOPs”；通信、数据加载、流水线空泡、故障恢复都会占用时间。

例子

一个7B模型在64张峰值约989 TFLOPS（BF16稠密）的GPU上训练，实测每秒处理约60万个token。模型FLOPs约6 × 7×10⁹ × 6×10⁵ ≈ 2.5×10¹⁶次/秒，硬件峰值合计64 × 9.89×10¹⁴ ≈ 6.3×10¹⁶次/秒，MFU约40%。若开启全量重算，硬件实际多做约一次前向（2N），HFU约为8/6 × 40% ≈ 53%，而MFU不变。吞吐数字为示意。

容易误解的地方

  • 不同论文计算“模型FLOPs”时是否计入注意力、嵌入层、是否按稀疏峰值作分母，各不相同，直接比较前要核对口径。
  • MFU高不代表训练好：它只衡量算力利用，不衡量收敛速度或最终效果。
