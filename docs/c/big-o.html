时间与空间复杂度

Computational Complexity

也叫：大O记号　Big-O notation　时间复杂度　O(n²)　渐近复杂度

在交互版中打开（看它长在树上的哪里）

用O(·)记号描述算法的时间或内存如何随输入规模增长，只关心增长的阶数，忽略常数。它决定了一个方法能不能扩展到更长的序列、更大的数据。

AI论文里经常出现这样的话：“注意力的复杂度是序列长度的平方”“这个方法把复杂度降到了线性”。这些说法决定了一个方法在规模变大时会不会崩掉，所以读论文时必须能快速判断。

定义。如果存在常数c和n_0，使得n ≥ n_0时运行步数T(n) ≤ c·g(n)，就说T(n) = O(g(n))。它只描述增长趋势：常数倍和低阶项都被忽略。常见的阶从小到大是：O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(n³)、O(2ⁿ)。空间复杂度用同样的记号描述所需内存。

怎么估算。数循环嵌套和每次循环做多少事。两个n×n矩阵相乘按定义要n³次乘加，所以是O(n³)；在长度为n的已排序数组里二分查找是O(log n)；穷举n个布尔变量的所有组合是O(2ⁿ)，n稍大就不可行，这正是早期符号AI遇到的组合爆炸。

在深度学习里的典型用法。自注意力要计算每对token之间的分数，长度为n、维度为d时，时间是O(n²d)，并且要存一个n×n的分数矩阵。序列长度翻倍，这部分开销变成4倍。循环网络和状态空间模型逐步处理序列，时间是O(n)，但难以并行。

它出现在哪里。Transformer的平方复杂度是长上下文的核心瓶颈；FlashAttention没有改变O(n²)的计算量，而是通过分块计算避免把n×n矩阵写回显存，把额外内存从O(n²)降到O(n)；线性注意力和Mamba状态空间模型则从算法上把复杂度降到O(n)，代价是表达能力上的取舍。另见参数量、计算量与显存和上下文窗口。

例子

注意力分数矩阵大小是n×n。n = 4096时有4096² ≈ 1678万个元素；n = 8192时是约6711万个，正好4倍。用16位浮点（每个2字节）存储，n = 8192时单个注意力头、单层就要约134MB。如果模型有32层、每层32个头，全部显式存下来就是这个数的1024倍，因此长序列必须换用不存整张矩阵的算法。

容易误解的地方

  • O记号忽略常数，但工程上常数很要紧：理论上更优的算法在实际规模下可能更慢，比如很多“线性注意力”在中等长度时并不比优化过的普通注意力快。
  • 时间复杂度和实际运行时间之间还隔着硬件：GPU上，内存读写往往比计算本身更慢，见显存、内存带宽与“内存墙”。
