前缀缓存与上下文缓存

Prefix Caching and Context Caching

也叫：前缀缓存　prefix caching　上下文缓存　context caching　prompt cache　提示缓存　KV复用　KV cache reuse　缓存命中　cache hit　RadixAttention　自动前缀缓存　APC

在交互版中打开（看它长在树上的哪里）

很多请求共享同一段开头（系统提示、文档、多轮历史），把这段算好的KV缓存存起来复用，就省掉重复的预填充。

智能体和多轮对话的请求往往以同样的长前缀开头。SGLang与RadixAttention用基数树（RadixAttention）组织所有请求的KV缓存，自动发现并复用公共前缀；vLLM与PagedAttention随后也加入了自动前缀缓存。2024年各家API推出的Prompt Caching把这一点变成价格：命中缓存的输入token显著便宜。

规模再大，显存就装不下所有前缀，于是缓存被搬到内存、磁盘和远端存储：Mooncake以KV缓存为中心以KV缓存为中心设计整个服务系统，LMCache KV缓存层作为独立的KV缓存层在多个引擎之间共享。

实际难点是命中率：上下文截断、动态插入的时间戳、工具结果的顺序都会让前缀对不上；LMCache论文就报告截断上下文会让命中率约减半。
