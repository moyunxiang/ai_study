博弈树搜索：minimax与MCTS

Game-Tree Search: Minimax and MCTS

也叫：蒙特卡洛树搜索　极小极大　alpha-beta剪枝　game tree

在交互版中打开（看它长在树上的哪里）

把“我走一步、对手走一步……”的所有可能展开成一棵树，从叶子往回推算每一步的好坏。minimax假设双方都走最优，MCTS用随机模拟和统计来选择值得深挖的分支。

先要会：图、树与搜索 蒙特卡洛采样 探索与利用

下棋时人会想“我走这里，他会怎么应，然后我再怎么走”。把这个过程系统化，就是在博弈树上搜索：根节点是当前局面，每条边是一步棋，子节点是走完后的局面，叶节点是终局或搜索到的最大深度，树的基本概念见图、树与搜索。

Minimax。两人零和博弈里，我方想让分数最大，对手想让它最小。从叶子开始往上推：轮到我方的节点取子节点的最大值，轮到对方的取最小值，根节点选值最大的那步。叶子如果不是终局，就用一个评估函数打分（如子力差）。香农：计算机下棋在1950年提出了这一框架。

Alpha-Beta剪枝。很多分支不必看完：如果已经知道某步至少能得3分，而另一步的对手第一个回应就能把我压到2分，这一步剩下的回应就不用算了。最好情况下，同样时间能搜的深度翻倍，见Alpha-Beta剪枝分析。深蓝战胜卡斯帕罗夫就是alpha-beta加专用硬件加手工评估函数。

蒙特卡洛树搜索（MCTS）。围棋分支太多（每步约250种走法），也很难写出好的评估函数。蒙特卡洛树搜索UCT换了思路：反复执行“选择—扩展—模拟—回传”四步。选择时用UCT公式在“已知胜率高”和“试得少”之间平衡（见探索与利用）：

UCT = W/N + c·√(ln N_父 / N)

W/N是该分支的模拟胜率，N是访问次数。模拟就是从新节点随机下到终局，结果沿路径回传更新统计。搜索结束后选访问次数最多的那一步。

与神经网络结合。AlphaGo用策略网络给出走法先验、用价值网络代替随机模拟，MCTS把网络的直觉变成更强的决策；MuZero把搜索搬到学到的模型里，见基于模型的强化学习。今天大语言模型的推理也在借鉴这些思想，用搜索多条推理路径来换取更好的答案，见推理token与测试时计算。

例子

Minimax与剪枝：我方有两步A、B。走A后对手可回应得到3分或12分，对手会选3；走B后对手可回应得到2分或8分，对手会选2。所以A值3、B值2，选A。用alpha-beta时，算完A知道至少能得3；看B的第一个回应得2，已经低于3，B的另一个回应（8）不用再算。

MCTS选择（c=√2）：父节点被访问14次。子节点1模拟10次赢6次，子节点2模拟4次赢3次。ln 14≈2.639。

  • 子节点1：0.6 + √(2×2.639/10) ≈ 0.6 + 0.727 = 1.327
  • 子节点2：0.75 + √(2×2.639/4) ≈ 0.75 + 1.149 = 1.899

下一次模拟选子节点2：它胜率更高，而且被试得更少。

容易误解的地方

  • MCTS最终选的是访问次数最多的走法，不一定是当前估计胜率最高的，因为访问次数更稳定。
  • minimax假设对手完美理性；面对会犯错的人类对手，它不一定是最赚分的策略。
  • 搜索能力依赖评估函数：搜得再深，叶子上的估值错了，结论也会错。
