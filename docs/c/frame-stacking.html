帧堆叠、跳帧与像素输入的预处理

Frame Stacking, Frame Skip and Pixel Preprocessing

也叫：帧堆叠　frame stacking　frame stack　堆叠帧　跳帧　frame skip　frame skipping　动作重复　action repeat　奖励裁剪　reward clipping　Atari预处理　Atari preprocessing　粘性动作　sticky actions　max pooling over frames

像素输入RL的标准预处理：把最近几帧叠在一起作为观测，让网络看出速度和方向；每个动作重复执行几帧（跳帧/动作重复）以缩短决策链并节省计算；奖励常被裁剪到[−1, 1]。

先要会：状态、观测与动作 图像作为张量 马尔可夫决策过程

从DQN开始，几乎所有在Atari等像素环境上的工作都沿用一套预处理。它们看起来像工程细节，却会实质性地改变问题本身，比较不同论文的分数时必须知道。

帧堆叠（frame stacking）。单独一帧画面看不出球往哪边飞、飞多快：只看一帧，环境是部分可观测的（见状态、观测与动作）。把最近k帧（DQN取4）沿通道维叠起来作为一个观测，网络就能从相邻帧的差异推出速度。这是用很短的历史近似马尔可夫状态的最简单办法；需要更长记忆时改用循环网络，如R2D2。

跳帧与动作重复（frame skip / action repeat）。Atari每秒60帧，相邻两帧几乎一样，没必要每帧都决策。做法是智能体选一个动作，环境把它重复执行k帧（DQN取4），只返回最后的画面和这k帧奖励之和。好处是决策步数减为1/k，信用分配的链条变短，计算也省了。为避免Atari某些物体隔帧闪烁，常对最后两帧逐像素取最大值。连续控制（如DeepMind Control Suite）也常用2到8的动作重复。

其他常见处理。转灰度并缩放到84×84；奖励裁剪把所有正奖励记为+1、负奖励记为−1，使同一组超参数能用于奖励尺度不同的游戏，代价是智能体分不清10分和1000分；把丢一条命当作回合结束（只用于训练）。

评测协议。原始ALE是确定性的，智能体可以靠背下固定的动作序列取得高分。重访ALE与粘性动作建议使用粘性动作：每一步以一定概率（论文推荐0.25）重复上一步的动作而不执行新选的动作，引入随机性，并呼吁统一报告协议。环境本身见Arcade学习环境ALE。

例子

DQN的输入：每次决策看最近4个处理后的画面，形状为4×84×84。智能体每做一次决策，环境前进4帧，所以“每秒决策15次”。论文常说训练了“5000万帧”，按跳帧4换算是1250万个决策步、也就是1250万个转移。若另一篇论文报告的是决策步数，两者看起来差了4倍。

容易误解的地方

  • 帧数和步数混用是Atari文献里最常见的比较错误之一。
  • 帧堆叠只能提供几帧的记忆，需要记住几十步之前信息的任务（如钥匙在哪个房间）仍然是部分可观测的。
  • 奖励裁剪改变了最优策略，训练出的智能体优化的是“得分事件次数”而不是真实分数。
