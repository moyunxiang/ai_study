双塔模型与交叉编码器

Two-Tower Models and Cross-Encoders

也叫：双塔模型　双塔　two-tower model　two-tower　dual encoder　双编码器　bi-encoder　交叉编码器　cross-encoder　cross encoder　重排序　reranking　reranker　重排　召回模型　晚交互　late interaction　embedding模型　文本嵌入模型　text embedding model

在交互版中打开（看它长在树上的哪里）

用两个独立的编码器分别把查询和候选（用户与物品、问题与文档、图与文）编码成向量，用内积打分。候选向量可以提前算好建索引，所以能在上亿候选里毫秒级检索。

先要会：嵌入向量 内积与余弦相似度

搜索和推荐都要回答：给定一个查询，几十亿个候选里哪些最相关？如果每个候选都要和查询一起送进一个大模型打分，计算量根本承受不了。

双塔（two-tower / dual encoder / bi-encoder）。两个编码器：查询塔把查询q编码成向量e_q，候选塔把候选d编码成e_d，相关度就是内积或余弦相似度s(q, d) = e_qᵀe_d（见内积与余弦相似度和嵌入向量）。关键在于两座塔互不交流：

  • 所有候选的向量可以离线算好，存进向量索引；
  • 线上只需编码一次查询，再做近似最近邻检索（如FAISS向量检索、HNSW近似近邻），见检索与向量数据库。

训练。通常用对比学习：一对匹配的(q, d⁺)作为正样本，批内其他样本和挖掘出的难负样本作为负样本，用InfoNCE或softmax交叉熵让正样本得分高于负样本（见对比学习和难例挖掘与难负样本）。

交叉编码器（cross-encoder）。另一种做法是把查询和候选拼在一起送进同一个模型（如BERT），让每一层的注意力都能在两者之间交互，最后输出一个分数。它准确得多，但每个候选都要重新跑一遍，只能用于对少量候选重排序，如BERT重排序。实际系统常是“双塔召回几百个 → 交叉编码器重排”的级联。ColBERT后期交互是两者的折中：保留每个token的向量，打分时做细粒度的“晚交互”，候选仍可预先编码。

它出现在哪里。

  • DSSM深度语义匹配（2013）用两个网络分别编码搜索词和网页标题，是双塔的早期代表；推荐系统的召回阶段普遍使用用户塔和物品塔，见推荐系统与协同过滤。
  • 稠密检索DPR把它用于开放域问答的段落检索；Sentence-BERT让BERT能产生可直接比较的句向量；E5文本嵌入、BGE嵌入模型等通用文本嵌入模型都属于这一类，是检索增强生成（RAG）的检索器。
  • CLIP的图像编码器和文本编码器也是一个双塔，所以能做零样本的图文检索。

例子

一个问答库有1000万个段落，每个编码成768维向量（FP16约15GB），离线一次算完。用户提问时，只需对问题跑一次编码器（几毫秒），再用ANN索引找出内积最高的100个段落（几毫秒）。若改用交叉编码器给全部段落打分，要跑1000万次模型前向；所以它只用来对这100个候选重排。

容易误解的地方

  • 双塔把所有信息压进一个向量，难以表达“查询里的否定词”“必须同时满足两个条件”这类细粒度匹配，召回结果常需要重排。
  • 查询塔和候选塔一旦更新，所有候选向量都要重新计算并重建索引，否则两边的向量不在同一个空间。
