奖励模型

Reward Model

也叫：reward model　RM　奖励模型　偏好模型　preference model　奖励模型训练　reward modeling　Bradley-Terry loss　BT奖励模型　标量奖励模型　scalar reward model　value head　价值头　generative reward model　生成式奖励模型

在交互版中打开（看它长在树上的哪里）

一个给“提示+回答”打分的模型，分数代表人类会有多喜欢这个回答。通常由语言模型改造而成，用人类的成对偏好数据训练，在RLHF中充当强化学习的奖励信号，也用于挑选和过滤回答。

先要会：人类反馈强化学习 逻辑回归

强化学习需要一个奖励函数（见奖励、回报与折扣）。下棋有输赢，可“这段回答好不好”没有现成的公式，也不可能让人实时给模型的每一个回答打分。奖励模型（reward model，RM）的办法是：先收集一批人类判断，训练一个模型去模仿这些判断，之后用它代替人来打分。

结构。取一个预训练好的语言模型（常与要训练的策略同源），去掉输出词表的语言模型头与输出层，换成一个输出单个标量的线性层。输入“提示x + 回答y”，读取最后一个token位置的隐状态，输出分数r(x, y)。

训练。数据是成对偏好：同一提示下的两个回答，标注者选出更好的y_w和较差的y_l（见偏好数据）。用Bradley–Terry模型（见Elo评分与两两比较）把分数差变成偏好概率：

P(y_w ≻ y_l) = σ(r(x, y_w) − r(x, y_l))

损失是−log σ(r_w − r_l)。注意只有分数差有意义，绝对值可以整体平移，所以实践中常把分数做归一化。

怎么用。

  • RLHF的奖励：PPO训练时，奖励模型给每个完整回答打分，再减去相对参考模型的KL惩罚（见人类反馈强化学习、参考模型与KL惩罚）。代表工作是InstructGPT与RLHF和Anthropic HH-RLHF。
  • 挑选与过滤：对同一提示采样多个回答，取RM分数最高的（见best-of-N与拒绝采样微调），或用它筛选合成数据。
  • 评测：RewardBench奖励模型评测专门评测奖励模型判断偏好的准确率。

几种变体。只看最终结果的结果奖励模型与对每一步打分的过程奖励模型（见结果奖励与过程奖励（ORM/PRM））；让语言模型先写出评语再给分的生成式奖励模型（生成式验证器），与LLM当裁判相通；数学和代码任务里，则可以用答案校验器替代学出来的奖励模型（见可验证奖励强化学习（RLVR））。

核心风险：过度优化。奖励模型只是人类偏好的一个不完美的近似。策略对它优化得越狠，越会钻它的空子——回答越来越长、越来越谄媚，RM分数一路上涨，真实质量却先升后降（奖励模型过优化，见奖励作弊）。

例子

提示：“怎么煮米饭？”两个回答：

  • y_w：给出米和水的比例、浸泡和焖煮时间。RM打分 r_w = 1.8。
  • y_l：“用电饭锅煮就行。”RM打分 r_l = 0.3。

预测偏好概率σ(1.8 − 0.3) = σ(1.5) ≈ 0.82，与标注一致，损失−log 0.82 ≈ 0.20。若RM打反了（r_w = 0.3、r_l = 1.8），概率≈0.18，损失≈1.70，梯度会推动它拉开正确的差距。

容易误解的地方

  • 奖励模型的准确率通常只有六七成到八成左右（取决于数据），人类标注者之间本身也常不一致，所以不要把RM分数当作“真实质量”。
  • RM容易学到表面特征，比如更长、更多列表格式的回答得分更高，需要专门检查和控制长度偏差。
