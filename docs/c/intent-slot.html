意图识别与槽填充

Intent Detection and Slot Filling

也叫：intent detection　意图识别　意图分类　intent classification　slot filling　槽填充　槽位填充　槽位　slot　NLU　自然语言理解（对话）　dialogue state tracking　对话状态跟踪　DST　task-oriented dialogue　任务型对话　语义框架（对话）

任务型对话系统理解用户一句话的标准方式：意图识别判断用户想做什么（订机票、查天气），槽填充从句中抽出完成任务所需的参数（出发地、日期）。再加上对话状态跟踪，就构成了传统语音助手的核心。

先要会：序列标注 监督学习

“帮我订一张明天从北京到上海的机票”——要真正执行，系统必须知道两件事：用户的目的是订机票，以及完成它所需的参数是什么。传统的任务型对话系统（订票、客服、车载语音、智能音箱）把这拆成两个子任务。

意图识别（intent detection）。把整句话分到预先定义好的意图类别之一：订机票、查航班、退票、闲聊……本质是文本分类。

槽填充（slot filling）。每个意图有一组“槽”，即完成任务需要的字段：订机票有出发地、目的地、日期、舱位等。从句子中找出每个槽的值，通常写成序列标注问题，用BIO标注方案逐词标注：“北京/B-出发地 到 上海/B-目的地”。

两个任务关系密切（意图决定了有哪些槽），常用一个模型联合训练。

多轮对话。用户往往不会一句话说全。系统要维护一个对话状态：目前已知哪些槽、还缺哪些，这叫对话状态跟踪（DST）。缺了日期，系统就追问“请问哪天出发？”。MultiWOZ任务型对话是跨多个领域（酒店、餐厅、火车等）的多轮任务型对话数据集，是DST的主要评测基准。经典流水线是：理解（意图+槽）→ 状态跟踪 → 对话策略（下一步做什么）→ 回复生成，端到端任务型对话系统尝试用神经网络把这条流水线端到端地连起来。

大模型时代的变化。大语言模型可以直接理解“帮我订明天去上海的票”，再通过工具调用调用订票接口：函数名相当于意图，函数参数相当于槽，参数的JSON Schema就是槽的定义。缺参数时，模型可以自己追问。这让很多场景不再需要单独训练意图分类器和槽填充模型；但在要求低延迟、高可控、可审计的场景（车载、客服）中，显式的意图与槽设计仍很常见。闲聊型的对话系统见聊天机器人。

例子

用户：“帮我订一张明天从北京到上海的经济舱机票。”

  • 意图：订机票
  • 槽：出发地 = 北京，目的地 = 上海，日期 = 明天（需归一化成具体日期），舱位 = 经济舱
  • BIO标注：帮 我 订 一张 明天/B-日期 从 北京/B-出发地 到 上海/B-目的地 的 经济舱/B-舱位 机票

若用户只说“我要去上海”，意图仍是订机票，但出发地和日期为空，对话状态记录缺失项，系统追问：“请问从哪里出发、哪天走？”

大模型写法：调用book_flight(origin=北京, destination=上海, date=2026-11-28, cabin=economy)。

容易误解的地方

  • 意图体系需要事先设计，用户说出体系外的需求时系统只能落到“其他”或误分类。
  • 槽值的归一化（“明天”“下周五”“国庆节”转成具体日期）往往比识别槽本身更容易出错。
