参数高效微调

Parameter-Efficient Fine-Tuning

也叫：PEFT　LoRA　Adapter　适配器　低秩适配　轻量微调　prefix tuning

在交互版中打开（看它长在树上的哪里）

微调大模型时冻结绝大部分原有参数，只训练很少一部分新增或选定的参数，从而大幅降低显存、存储和切换任务的成本。

先要会：预训练与微调 低秩近似 参数量、计算量与显存

预训练与微调的标准做法是全量微调：用新任务的数据更新模型的全部参数。模型小的时候这没问题，到了几十亿参数就出现三个麻烦。一是训练显存：用Adam训练时，每个参数除了权重本身，还要存梯度和两份优化器状态，混合精度下合计约16字节/参数（见参数量、计算量与显存、自适应学习率优化器）。二是存储和部署：每个任务都要保存一整份模型副本，100个客户就是100份几十GB的文件。三是小数据上更新全部参数容易过拟合，也容易丢掉原有能力（见持续学习与灾难性遗忘）。

参数高效微调（PEFT）的思路是：既然预训练模型已经很好，适配新任务只需要很小的改动，那就冻结原模型，只训练一小部分参数。主要有三类做法：

  • 加入新模块：Adapter在每层插入一个“先降维再升维”的小瓶颈网络，只训练它。
  • 加入可训练的输入：Prefix / Prompt Tuning在每层的注意力前拼接一段可学习的向量（软提示），模型本身不动。
  • 重参数化已有权重：LoRA假设微调带来的权重变化是低秩的（见低秩近似），把权重写成

W' = W + ΔW = W + B·A

其中W（d×k）冻结，只训练B（d×r）和A（r×k），秩r通常只有4–64。A随机初始化、B初始化为0，所以训练开始时模型与原模型完全相同。训练完后可以把B·A直接加回W，推理时没有任何额外开销。

还有只训练偏置项的BitFit等更极端的做法。QLoRA把冻结的底座量化到4比特（见量化），再在上面训练LoRA，使消费级或单张数据中心GPU也能微调很大的模型。

它出现在哪里：LoRA原论文报告，对GPT-3 175B，可训练参数比全量微调少约1万倍，显存需求降到约1/3；如今开源社区的模型微调绝大多数用LoRA或QLoRA，Hugging Face PEFT库把这些方法做成了统一的库；扩散模型的风格、角色定制也普遍用LoRA（LoRA微调扩散模型）。一个底座加许多个几十MB的LoRA文件，可以在服务时按请求切换（S-LoRA多适配器服务）。

例子

一个4096×4096的注意力投影矩阵有4096 × 4096 ≈ 1678万个参数。加秩r = 8的LoRA，只需训练4096×8 + 8×4096 = 65536个参数，约为原矩阵的0.39%。

对一个7B参数的模型：全量微调用Adam约需7×10⁹ × 16字节 ≈ 112GB（还没算激活），一张80GB的卡放不下；LoRA只需把底座以FP16存一份（约14GB），梯度和优化器状态只针对几百万个LoRA参数；QLoRA把底座压到4比特，约3.5GB。

容易误解的地方

  • PEFT省的是可训练参数和优化器状态，前向和反向仍要经过整个模型，计算量并没有按比例减少。
  • 秩r太小或只加在少数层上，复杂任务（如学习大量新知识）效果可能明显不如全量微调。
  • LoRA微调不等于不会遗忘，学习率过大时同样会破坏原有能力。
