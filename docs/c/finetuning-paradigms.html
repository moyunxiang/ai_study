微调范式：全量微调、部分冻结与提示

Fine-Tuning Paradigms

也叫：fine-tuning　微调　全量微调　full fine-tuning　full-parameter fine-tuning　全参数微调　linear probing　线性探测　冻结　freezing　冻结层　partial fine-tuning　部分微调　微调方式　微调范式　fine-tuning strategies

把预训练模型用到新任务上的几种做法，按改动多少排列：只训练一个新的输出头（线性探测）、冻结大部分层只训练少量参数（参数高效微调）、更新全部参数（全量微调），以及完全不改参数、只写提示。

先要会：预训练与微调 参数高效微调

拿到一个预训练模型（见预训练与微调），要让它做好某个具体任务，最关键的决策是：改多少参数。改得越多，适配能力越强，但需要的显存、数据和存储也越多，越容易忘掉原有能力。

几种做法。

  • 只用提示，不改参数：把任务说明和示例写进输入（见上下文学习与提示）。零训练成本，一个模型服务所有任务，但受上下文长度和模型原有能力的限制。
  • 线性探测（linear probing）：冻结整个主干网络，只在最后加一个新的分类层并训练它。最便宜，也常被用来衡量“预训练表示本身有多好”（见特征与表示学习）。
  • 部分冻结：只训练最后几层或特定模块。ULMFiT提出逐层解冻、不同层用不同学习率，减轻对预训练知识的破坏。
  • 参数高效微调（PEFT，见参数高效微调）：冻结原模型，只训练新增的少量参数，如LoRA的低秩矩阵、Adapter的小模块、Prefix / Prompt Tuning的可学习前缀，或者只训练偏置（BitFit）。可训练参数通常不到1%，每个任务只需存一小份增量权重。
  • 全量微调（full fine-tuning）：所有参数都参与更新。效果上限通常最高，但需要为优化器状态、梯度准备约为参数本身数倍的显存（见参数量、计算量与显存），每个任务都要存一份完整模型。BERT时代的标准做法是在每个下游任务上全量微调。

怎么选。

  • 数据很少：提示或线性探测，参数多了容易过拟合（见泛化与过拟合）。
  • 要学新格式、新风格、新领域：LoRA通常就足够，且显存友好；QLoRA把基座量化到4比特后再训LoRA，单卡也能微调大模型。
  • 要大幅改变能力、数据量很大：全量微调或继续预训练。
  • 担心遗忘原有能力：改动越小越安全（见持续学习与灾难性遗忘）。

不少对比研究发现，在常见的指令微调规模下，调得好的LoRA与全量微调差距不大；在需要学习大量新知识或强化学习等场景，两者的差距与设置有关，没有统一结论。

例子

一个70亿参数的模型，用BF16存储权重需要约14GB。

  • 全量微调（Adam优化器）：权重14GB + 梯度14GB + 两份优化器状态（常用FP32存储，约56GB），再加激活，合计远超80GB，通常需要多卡。
  • LoRA（秩16，加在所有注意力投影上）：可训练参数约几百万到几千万，优化器状态只有几百MB，主要显存是冻结的14GB权重加激活，单张大显存卡即可。
  • 线性探测做情感二分类：只训练一个4096×2的线性层，8194个参数。

（显存为粗略估算，实际取决于实现和序列长度。）

容易误解的地方

  • 全量微调的学习率通常要比预训练小得多，太大会迅速破坏预训练学到的能力。
  • “冻结”的参数仍参与前向和反向计算（梯度要穿过它们传回去），所以PEFT省的主要是优化器状态和梯度存储，不是计算量。
