token对数概率（logprobs）

Token Log-Probabilities

也叫：logprobs　logprob　log probability　对数概率　token概率　token probability　top_logprobs　序列对数似然　sequence log-likelihood　output scores　输出分数　置信度分数

在交互版中打开（看它长在树上的哪里）

模型给每个token的对数概率log p。很多推理框架和API可以返回生成的每个token及其logprob，以及每一步概率最高的几个候选。它是打分、置信度估计、分类和评测的基础工具。

先要会：Softmax与logits 随机变量与概率分布

语言模型每一步都会输出整个词表上的概率分布（见Softmax与logits、语言模型头与输出层），但通常只把采样出的token交给用户。如果同时把它的概率也拿出来，就能做很多事。由于概率连乘会迅速变得极小，实践中一律使用对数概率（logprob）：

logprob(y_t) = log p(y_t | 前文)，取值≤0，越接近0越确定。

整段文本的对数概率就是各token对数概率之和（见自回归生成），平均负对数概率取指数就是困惑度。

能拿来做什么。

  • 给文本打分：比较几段候选文本在模型下哪个更可能，用于多选题评测（见多选题评测：似然打分与字母作答）、重排序和检测训练数据泄漏（见数据泄漏与基准污染）。
  • 分类：让模型输出“是/否”或类别名，直接比较这几个token的概率，比解析自由文本更稳定，还能得到一个连续的分数。
  • 置信度：答案token的概率低，往往意味着模型没把握，可以据此提示用户或转人工（见模型校准、拒答与不确定时弃权）。不过对话模型经过对齐训练后，概率的校准程度通常变差，不能直接当作正确率。
  • 调试生成：查看每一步的top-k候选（top_logprobs），能看出模型在哪个位置“犹豫”，以及采样参数（见解码：贪心、束搜索、温度与top-p）实际起了什么作用。高熵分叉词元的研究就关注推理链中那些概率分布很分散、决定了后续走向的少数token。
  • 训练：强化学习和偏好优化都需要策略和参考模型在生成序列上的logprob（见参考模型与KL惩罚、DPO直接偏好优化）。

接口上的常见参数。是否返回生成token的logprob、每一步返回前几个候选（top_logprobs）、是否返回提示部分各token的logprob（有的API为防止模型被“蒸馏”或窃取而不提供）。窃取生产级LLM的参数展示了仅凭API返回的logits或logprob信息就能恢复出模型最后一层的部分参数，这是一些服务限制logprob输出的原因之一。

例子

模型生成“巴黎”，返回：

  • 第1个token“巴”：logprob = −0.05（概率约0.95），候选：“巴” −0.05、“里” −3.2、“马” −4.1。
  • 第2个token“黎”：logprob = −0.01（概率约0.99）。

整段logprob = −0.06，概率约0.94。

分类用法：问“这条评论是正面的吗？回答是或否”，读取下一个token“是”的logprob −0.36（0.70）和“否”的logprob −1.24（0.29），得到正面概率约0.70。

容易误解的地方

  • logprob依赖分词：同一个词在不同模型里被切成不同数量的token，直接比较两个模型的logprob没有意义。
  • 采样时用了温度或top-p，返回的logprob可能是调整前或调整后的分布，不同API约定不同，用之前看文档。
