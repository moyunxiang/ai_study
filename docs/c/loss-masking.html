损失掩码：只对回答计算损失

Loss Masking

也叫：loss masking　loss mask　损失掩码　只对回答计算损失　completion-only loss　train on completions only　response-only loss　ignore_index　-100　标签掩码　label masking　prompt loss　提示损失

在交互版中打开（看它长在树上的哪里）

训练时只在一部分token上计算损失，其余位置的标签设为忽略值（常用−100）。指令微调里最典型：提示和系统指令只作为条件，只对助手的回答部分计算损失。

先要会：交叉熵 指令微调与对话模板

语言模型的标准损失是在每个位置上预测下一个token的交叉熵，再取平均。但并不是每个位置都值得学：

  • 指令微调时，用户的问题是给定的，我们不希望模型学会“生成用户的问题”，只希望它学会“看到问题后怎么回答”。
  • 填充位置（见填充、截断与注意力掩码）不是真实内容。
  • 多轮对话中，工具返回的结果、检索到的文档是外部输入，不该由模型来“编”。

损失掩码就是给每个位置一个0/1权重，只在权重为1的位置算损失。

实现。最常见的做法是把不需要学习的位置的标签设为一个特殊值，PyTorch的交叉熵函数用ignore_index = −100跳过这些位置：

L = −(1/|M|) · Σ_(t∈M) log p(y_t | y_<t)，M是需要计算损失的位置集合

注意这只影响损失，不影响注意力：被掩掉的提示token仍然输入模型、仍然可以被后面的回答看到。它和因果掩码、attention_mask是不同的“掩码”。

在哪里出现。

  • 指令微调（见指令微调与对话模板）：只对回答计算损失（completion-only loss）。多轮对话可以对每一轮助手回复都计算，也可以只对最后一轮计算。
  • 预训练中的打包（见序列打包与文档掩码）：通常所有位置都算损失，但若用到填充，填充位置要掩掉。
  • 掩码语言模型（见掩码建模）：只在被遮住的约15%位置上计算损失，其余位置的标签都是忽略值。
  • 强化学习后训练：智能体与环境交互的轨迹中，环境返回的观察不由策略生成，计算策略梯度时要掩掉（见智能体强化学习）。

对不对提示算损失。经验上，只对回答计算损失通常更好或相当，但有工作发现提示很长、回答很短时，适当保留一部分提示上的损失也有帮助。这取决于数据，没有统一结论。

例子

一条对话样本按模板拼成9个token：

<user> 1 + 1 = ? <assistant> 2 <eos>

位置：0 <user>、1 1、2 +、3 1、4 =、5 ?、6 <assistant>、7 2、8 <eos>。

标签（每个位置预测下一个token）：前6个位置的标签设为−100；位置6的标签是“2”，位置7的标签是“<eos>”。于是损失只在2个位置上计算，模型只学“看到问题后回答2并结束”。如果把位置7的标签也错设为−100，模型就学不会在回答后停下来（见生成的停止条件）。

容易误解的地方

  • 损失是按有效token取平均，还是先按样本平均再跨样本平均，会改变长短回答的相对权重，结果可能差别明显。
  • 对话模板和分词器的边界不一致时（例如回答开头的空格被并入了助手标记里），掩码位置可能偏一位，模型会学到奇怪的开头。
