KV缓存压缩

KV Cache Compression

也叫：KV cache compression　KV缓存淘汰　KV cache eviction　KV驱逐　token淘汰　KV量化　KV cache quantization　KV稀疏　长上下文推理优化　注意力汇聚　attention sink　MLA　多头潜在注意力

在交互版中打开（看它长在树上的哪里）

KV缓存随上下文长度线性增长、常常比模型还占显存，于是想办法少存、存小或干脆从架构上把它变小。

KV缓存与推理扩展分析的分析指出，长上下文和大批量时推理的瓶颈是KV缓存的显存与读写带宽。压缩它有三类办法。

一是丢：只留重要的token。H2O KV缓存淘汰按累计注意力分数保留“重击者”加最近的token；StreamingLLM与注意力汇聚发现开头几个token是注意力汇聚点，保留它们加滑动窗口即可无限长生成。二是压：把KV量化到4比特等低精度，QuaRot旋转量化就把KV缓存和权重、激活一起压到4比特。三是改架构：DeepSeek-V2与MLA的MLA把KV压成低维潜向量，原生稀疏注意力NSA等稀疏注意力只读取部分KV。

与之互补的是“放到别处”：vLLM与PagedAttention分页管理显存，LMCache KV缓存层把KV卸载到内存和磁盘。主要争议是丢弃式方法在大海捞针式检索、长推理链上会悄悄出错。
