智能体群与强化学习编排

Agent Swarms and RL-Trained Orchestration

也叫：swarm　agent swarm　Agent Swarm　swarm RL　LLM swarm　智能体群　智能体集群　多智能体编排　multi-agent orchestration　orchestrator　编排器　orchestration RL　PARL　Parallel-Agent RL　并行智能体强化学习　子智能体　subagents　multi-agent RL for LLMs　LLM MARL　learned orchestration　conductor

让一个模型学会调度一群LLM智能体——派谁、做什么、彼此能看到什么——并用强化学习按最终结果训练这种调度能力。

手工搭建的多智能体系统（见「多智能体协作」）常在智能体变多后效果停滞。一条思路是把协作结构本身当作可学习的对象：GPTSwarm智能体图优化把智能体写成图并用REINFORCE学连边，AFlow自动工作流、ADAS自动设计智能体自动搜索工作流；OpenAI Swarm框架则只是以swarm命名的手写编排框架。

2025年起，用RL训练「编排器」成为主线。Puppeteer演化式编排训练中心编排器逐步决定激活哪个智能体，奖励是答对减去成本；ToolOrchestra小模型编排器让8B模型把其他LLM当工具调用；Conductor指挥家模型让7B模型用自然语言为每题写出分工和可见范围，调度GPT-5等工人模型；Kimi K2.5视觉智能体的Agent Swarm用PARL只训练编排器、冻结子智能体，并用并行奖励防止「退回单智能体」和「虚假并行」；OrchestraRL智能体群编排研究智能体数量增大时的通信控制。另一类做法如MAGRPO多智能体协作RL直接把多个LLM一起训练，借用合作式多智能体RL的集中训练、分散执行。

开放问题包括：只训练编排器还是连同工人一起训；怎样在奖励里计入延迟和费用；智能体多了以后如何避免沟通开销吞掉收益（见多智能体为何失败）。经典的多智能体强化学习与群体智能算法见RL分支。
