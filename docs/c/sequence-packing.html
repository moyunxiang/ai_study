序列打包与文档掩码

Sequence Packing and Document Masking

也叫：sequence packing　packing　序列打包　样本打包　sample packing　数据打包　document masking　文档掩码　跨文档注意力掩码　intra-document masking　block-diagonal mask　块对角掩码　varlen attention　变长注意力

训练时把多条短样本首尾相接拼成一条接近最大长度的序列，消除大量填充造成的算力浪费；配合文档掩码可以防止不同样本之间互相“看见”。

先要会：填充、截断与注意力掩码 因果掩码

训练数据的长度差别很大：有的对话几十个token，有的文档几千个。如果每条样本单独成一行、统一填充、截断与注意力掩码到最大长度，一批里可能大半位置都是PAD，GPU在空转。序列打包（packing）把多条样本拼起来填满每一行。

预训练中的做法。把整个语料的文档用EOS（见特殊token）连接成一条极长的token流，再按固定长度（如4096）切块，每块就是一条训练样本。一块里可能包含一篇文档的结尾和下一篇的开头。GPT-2、GPT-3以来的预训练基本都这样做，几乎没有填充。

跨文档注意力。简单拼接后，用普通的因果掩码训练，后一篇文档的token能“看见”前一篇文档的内容。两篇无关的文档之间本没有关系，模型可能学到一些虚假的依赖，并在推理时把无关的上下文当回事。两种处理：

  • 不管它：很多模型就是这样训练的，影响通常不大，模型会学会在EOS之后基本忽略前文。
  • 文档掩码（document masking）：把因果掩码改成块对角形式，每个token只能看到同一文档内、在它之前的token；位置编号也在每篇文档开头重置为0。Llama 3的技术报告写明使用了“阻止同一序列内不同文档之间自注意力”的掩码。FlashAttention等高效注意力实现提供了“变长序列”接口，可以直接支持这种掩码而不浪费计算。

微调中的打包。监督微调的样本更短、长度差异更大，打包的收益更明显。此时一般同时使用文档掩码和损失掩码：只对回答计算损失：每条样本只对自己的回答部分算损失，且不能看到同一行里的其他样本。

一个副作用。打包后每个优化步里包含的样本数不再固定，样本越短，一步里的样本越多。若损失按token平均，长样本在梯度中的权重相对更大；若按样本平均，又会反过来。不同的实现选择会影响训练结果，需要在对比实验时注意。

例子

最大长度8，三条样本长度分别为3、2、3：A = [a1 a2 a3]，B = [b1 b2]，C = [c1 c2 c3]。

  • 不打包：3行×8 = 24个位置，真实token只有8个，填充率67%。
  • 打包：一行 [a1 a2 a3 b1 b2 c1 c2 c3]，8个位置全部有效。

文档掩码下，b1只能看到自己，看不到a1到a3；c2只能看到c1和自己。位置编号为 [0 1 2 0 1 0 1 2]，而不是 [0 1 2 3 4 5 6 7]。

容易误解的地方

  • 打包但不重置位置编号，模型看到的位置分布会和推理时不同（推理时每段对话都从位置0开始）。
  • 用了打包的训练，batch size应该按token数而不是样本数来统计和报告。
