模型尺寸超参数：维度、层数与头数

Model Dimensions: Width, Depth and Heads

也叫：d_model　hidden size　hidden_size　隐藏层维度　隐藏维度　模型维度　num_layers　层数　num_heads　头数　head dim　每头维度　intermediate_size　d_ff　FFN维度　模型尺寸　model config　参数量估算　12Ld²

描述一个Transformer“形状”的几个超参数：隐藏维度d_model、层数L、注意力头数h和每头维度、前馈层中间维度d_ff、词表大小V。参数量大致是12·L·d_model²。

先要会：Transformer层的结构 参数量、计算量与显存

读模型的技术报告或配置文件（config.json）时，最先看到的就是一组尺寸数字。它们决定了参数量、计算量、显存占用，也部分决定了模型的能力。弄懂这几个数，就能大致估算一个模型有多大、跑起来要多少资源（见参数量、计算量与显存）。

主要的几个。

  • d_model（hidden_size，隐藏维度）：每个token在模型内部被表示成多少维的向量，也是残差流的宽度。
  • L（num_hidden_layers，层数）：堆叠多少个Transformer块（见Transformer层的结构）。
  • h（num_attention_heads，头数）和d_head（每头维度）：通常d_head = d_model / h，常见取64或128。
  • KV头数（num_key_value_heads）：使用GQA时比h小，见MHA、MQA、GQA与MLA。
  • d_ff（intermediate_size，前馈中间维度）：前馈层先升维再降回d_model（见Transformer的前馈层）。经典取4·d_model；用SwiGLU时有三个矩阵，常取约8/3·d_model，使参数量与前者相当。
  • V（vocab_size）：见词表大小的取舍。
  • 最大位置数（max_position_embeddings）：训练时的上下文长度，见上下文窗口。

估算参数量。每层注意力有Q、K、V、输出四个d×d矩阵，共4d²；前馈层两个d×4d矩阵，共8d²。所以每层约12d²，总计

N ≈ 12 · L · d² + V·d（后一项是嵌入，若输出层不共享再加一份）

归一化层和偏置的参数很少，可以忽略。

宽与深。同样的参数预算，可以更宽（d大、L小）或更深（L大、d小）。语言模型的规模定律的实验发现，在一个相当宽的范围内，损失主要由总参数量决定，对具体形状不太敏感；实践中还要考虑GPU矩阵乘法效率（维度取128的倍数）、并行切分方式和推理延迟（层数越多，逐层串行的延迟越长）。

例子

GPT-3最大的版本：L = 96，d_model = 12288，h = 96（每头128维）。

12 × 96 × 12288² ≈ 12 × 96 × 1.51×10^8 ≈ 1.74×10^11

约1740亿，与公布的1750亿参数基本吻合；剩下的差额主要是约5万×12288 ≈ 6亿的嵌入矩阵。

小一点的例子：L = 12、d = 768（BERT-base和GPT-2最小版的尺寸），12×12×768² ≈ 8500万，再加上词嵌入（BERT约2300万，GPT-2约3900万），合计一亿出头。

容易误解的地方

  • 混合专家模型（见混合专家）的总参数和每个token实际用到的“激活参数”差别很大，估算计算量要用后者。
  • 公式里的12d²假设了标准MHA和4倍FFN；用了GQA、SwiGLU、不同的d_ff时要相应调整。
