基于偏好的强化学习与Bradley-Terry模型

Preference-Based RL and the Bradley–Terry Model

也叫：偏好强化学习　基于偏好的强化学习　preference-based RL　PbRL　从人类偏好学习　learning from human preferences　Bradley-Terry　Bradley-Terry模型　BT模型　成对比较　pairwise comparison　奖励学习　reward learning　奖励建模　reward modeling　偏好学习　preference learning

不直接写奖励，而是让人比较两段行为哪个更好，再从这些成对偏好里学出一个奖励函数（常用Bradley-Terry模型），然后用它做强化学习。这是RLHF的基础。

先要会：奖励、回报与折扣 逻辑回归 交叉熵

很多任务的好坏人一看就知道，却很难写成公式：机器人后空翻是否漂亮、一段回答是否有帮助。直接打绝对分数也不可靠，不同的人、同一个人在不同时间的尺度都不一样。但比较两个东西哪个更好，人通常判断得又快又一致。基于偏好的强化学习就利用这种比较信号。

Bradley-Terry模型。假设存在一个潜在的奖励函数r，人选择轨迹（或回答）τ₁而不是τ₂的概率取决于二者总奖励之差：

P(τ₁ ≻ τ₂) = exp(R(τ₁)) / (exp(R(τ₁)) + exp(R(τ₂))) = σ(R(τ₁) − R(τ₂))

σ是sigmoid，R(τ) = Σ_t r(s_t, a_t)。这与Elo评分与两两比较的胜率公式是同一种结构，也与逻辑回归一致。

学习奖励模型。收集大量成对比较(τ₁, τ₂, 哪个更好)，用神经网络r_φ参数化奖励，最小化交叉熵：

L(φ) = −E[ log σ(R_φ(τ_win) − R_φ(τ_lose)) ]

然后把r_φ当作普通奖励，用任意RL算法（常用PPO）优化策略；也可以交替进行：用当前策略生成新的比较对，让人标注，继续更新奖励模型。

历史与应用。从人类偏好学习奖励只对不到1%的交互给出比较、总共约一小时的人类反馈，在MuJoCo和Atari上学会了复杂行为。用人类偏好微调语言模型和InstructGPT与RLHF把同一套流程用在语言模型上，奖励模型给整段回答打分，并加入KL惩罚防止策略偏离太远，见人类反馈强化学习。DPO直接偏好优化进一步证明：在KL正则的目标下，可以跳过显式的奖励模型和RL，直接用偏好数据训练策略。

局限。BT模型假设偏好可以由一个标量奖励解释；真实的人类偏好可能不一致、不可传递，或因人而异。学到的奖励模型也会被策略钻空子，见奖励设计与奖励投机。

例子

奖励模型给两段回答的打分为R₁=2.0、R₂=1.0，预测人选第一段的概率是σ(1.0) ≈ 0.73。若标注者实际选了第二段，这一对的损失是−log σ(1.0 − 2.0) = −log 0.27 ≈ 1.31，梯度会把R₂往上推、R₁往下压；若标注者选了第一段，损失只有−log 0.73 ≈ 0.31。

容易误解的地方

  • 奖励模型只在打分差值上被确定：给所有输出加同一个常数，偏好概率不变，所以奖励的绝对值没有意义，常需要归一化。
  • 比较的是整段轨迹，奖励却分摊到每一步，这本身就是一个信用分配问题，见信用分配。
