上下文学习与提示

In-Context Learning and Prompting

也叫：ICL　提示工程　prompt engineering　少样本提示　few-shot prompting　语境学习

在交互版中打开（看它长在树上的哪里）

不改变模型参数，只在输入里写下任务说明和几个示例，模型就能照着完成新任务。提示（prompt）就是用来引导这种能力的输入文本。

先要会：语言模型 零样本与少样本 上下文窗口

传统做法是一个任务训练一个模型：想做情感分类，就收集几千条标注数据去微调（见预训练与微调）。GPT-3（2020）展示了另一种方式：把几个例子直接写进输入，模型读完后就能对新例子给出同样格式的答案，整个过程不更新任何参数。论文把它称为上下文学习（in-context learning，ICL）。

几种形式（见零样本与少样本）。

  • 零样本：只给任务描述，比如“把下面的句子翻译成英文：……”。
  • 单样本/少样本：在问题前面放1个或若干个“输入→输出”的示例，让模型从示例中推断出任务是什么、答案格式是什么。
  • 思维链（思维链CoT）：示例中不仅给答案，还写出推理步骤，模型会模仿着先推理再回答，在数学题上效果大幅提升。

这些示例和说明都占用上下文窗口，所以示例数量受窗口限制；窗口变大后，多样本ICL发现放上百上千个示例还能继续提升。

它为什么能工作。模型做的仍然只是“预测下一个token”（见语言模型）。预训练语料里有大量隐含着“若干例子后跟同类内容”的文本（词表、问答列表、代码样例），要把这类文本续写好，模型必须学会从前文中识别出规律并延续下去。目前对其机制有几类解释：归纳头与ICL在Transformer中找到了“看到A后面跟着B，下次见到A就预测B”的注意力回路；ICL即隐式贝叶斯推断认为模型在推断示例来自哪种“任务”；ICL即梯度下降等工作表明，在简化设定下，注意力层的前向计算可以等价于在示例上做一步梯度下降。这些解释都还不完整。

一些反直觉的发现。示例标签不重要？发现，在一些分类任务上把示例的标签随机打乱，效果下降不大——示例提供的主要是格式和输入分布的信息；示例顺序敏感性发现示例的顺序也会显著影响结果。

提示工程就是围绕这些性质，琢磨怎样写说明、选示例、安排顺序。指令微调（见指令微调与对话模板）之后，模型对零样本的自然语言指令也能很好地遵循，复杂的少样本技巧不再那么必要。

例子

GPT-3论文中的少样本翻译提示（原文为英译法，这里换成中译英）：

输入： “海獭 => sea otter 薄荷 => peppermint 长颈鹿毛绒玩具 => plush giraffe 奶酪 =>”

模型续写出“cheese”。没有任何一行明说“请翻译”，模型从三个示例中推断出了任务。

同一个模型，如果把示例换成“海獭 => 哺乳动物，薄荷 => 植物，奶酪 =>”，它会续写“食品”之类的类别——参数没变，任务完全由输入决定。

容易误解的地方

  • 上下文学习不改变参数，所以下一次对话不会“记住”学到的东西。
  • 它对提示的细节很敏感：示例的选择、顺序、格式，甚至标点都可能明显影响结果。
  • “学习”一词容易误导：很多时候模型只是从示例中认出了它在预训练中已经会的任务，而不是真的学会了全新的技能。
