生成的停止条件

Stopping Criteria for Generation

也叫：stopping criteria　停止条件　stop sequence　stop sequences　停止序列　停止词（生成）　stop tokens　eos_token_id　max_new_tokens　max_tokens　max_length　min_new_tokens　最大生成长度　finish_reason　生成截断　停不下来

在交互版中打开（看它长在树上的哪里）

自回归生成什么时候停下：模型输出结束token（EOS）、遇到用户指定的停止序列、达到最大新token数，或超时。设置不当会导致回答被截断或停不下来。

先要会：自回归生成 特殊token

自回归生成模型一次只生成一个token，本身不知道“写完了”意味着什么，除非它学会了在合适的时候输出一个特殊的结束token。生成循环必须有明确的停止规则。

几种停止条件。

  • 结束token（EOS，见特殊token）。最自然的方式：模型在训练中见过“回答在这里结束”，学会在内容完整时输出EOS。对话模型还常用一个专门的“本轮结束”标记（如<|im_end|>、<|eot_id|>），配置里可以同时指定多个EOS。
  • 停止序列（stop sequences）。用户指定的字符串，一旦生成的文本中出现就停止，且通常不把它包含在输出里。典型用途：少样本提示里每个示例以“\n\n问：”开头，设它为停止序列，模型答完当前问题就不会接着编下一个问题；在ReAct式的智能体循环中，生成到“Observation:”就停下，等待真实的工具结果（见智能体循环）。
  • 最大长度。max_new_tokens限制本次最多生成多少个新token；max_length限制提示加生成的总长度（不能超过上下文窗口）。达到上限时回答会被硬截断，API通常会返回一个“因长度而停止”的标记（例如finish_reason为length），提醒调用方答案可能不完整。
  • 最小长度。min_new_tokens在达到最少长度之前把EOS的概率置零，防止模型过早结束。
  • 时间与自定义条件。如最长生成时间，或者用一个函数检查当前输出（例如JSON已经闭合）就停止。

和别的设置的关系。束搜索（见束宽、长度惩罚与束搜索的细节）里每条候选各自可能先结束，需要决定什么时候整体停止，以及如何比较长短不同的候选。推理模型（见推理token与测试时计算）的思考段落可能很长，“思考预算”本质上也是对思考部分单独设置的最大长度。

流式输出中的停止序列。逐token流式返回时（见流式输出），停止序列可能跨越多个token：前几个token已经发给用户，后面才拼成完整的停止串。实现上要缓存可能是停止序列前缀的那部分输出，确认不是之后再发送。

例子

少样本提示：

问：1+1=？\n答：2\n\n问：2+3=？\n答：

不设停止序列时，模型输出“5\n\n问：4+4=？\n答：8\n\n问：……”，一直编下去直到max_new_tokens。设停止序列为“\n\n问：”，输出在“5”之后停止，返回“5”。

长度截断：max_new_tokens = 50，模型写到第50个token时还在一句话中间，返回的文本缺了结尾，finish_reason为length而不是stop。

容易误解的地方

  • 微调数据的每条回答末尾若没有EOS，或者EOS被当作填充在损失中忽略了，模型就学不会停止，会一直重复或续写下去。
  • 用错对话模板时，模型输出的“结束标记”可能和推理框架配置的EOS对不上，表现为不停地自问自答。
