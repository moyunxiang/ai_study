位置编码

Positional Encoding

也叫：position embedding　位置嵌入　RoPE　旋转位置编码　正弦位置编码　相对位置编码

在交互版中打开（看它长在树上的哪里）

给每个token附加关于它所在位置的信息，因为自注意力本身分不清词序。做法从加一组正弦向量，到旋转查询和键的向量（RoPE）。

先要会：自注意力与多头注意力 嵌入向量 内积与余弦相似度

自注意力与多头注意力把一句话当作一个集合来处理：第i个词对第j个词的关注分数只取决于两者的向量内容，与它们在句中的位置无关。于是“狗咬人”和“人咬狗”在没有位置信息时得到完全相同的一组输出（只是排列不同）。RNN按顺序读，天然知道先后；卷积的卷积核也区分左右邻居；Transformer则必须显式地把位置告诉模型。

正弦位置编码（原始Transformer）。给第pos个位置构造一个d维向量，偶数维用sin、奇数维用cos，频率逐维降低：

PE(pos, 2i) = sin(pos / 10000^(2i/d)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

把它直接加到词向量上（见嵌入向量）。低维分量变化快，像秒针；高维分量变化慢，像时针，合起来每个位置得到一个独特的“指纹”。而且对任意固定偏移k，PE(pos + k)可以由PE(pos)经一个线性变换（旋转）得到，模型有可能从中读出相对距离。

可学习的绝对位置。BERT、GPT-2直接给每个位置0, 1, …, 最大长度−1各学一个向量。简单有效，但超过训练时最大长度的位置根本没有向量可用。

相对位置。语言里更重要的往往是“两个词相距多远”而不是“这个词在第几位”。相对位置表示在注意力分数里加入与距离i − j有关的项；ALiBi线性偏置位置直接给分数加一个与距离成正比的负偏置，越远越被压低。

旋转位置编码RoPE（旋转位置编码RoPE）。今天大语言模型的主流做法。它不往词向量上加东西，而是在算注意力之前，把q和k的每两维看作一个二维平面上的点，按位置旋转：位置m的向量旋转m·θ角度（不同的维度对用不同的θ）。两个旋转后的向量做内积，结果只依赖于原始q、k和角度差(m − n)·θ——相对位置自然出现在分数里。上下文扩展方法如位置插值扩上下文和YaRN都是在调整这些旋转角度。

例子

正弦编码。取d = 4，两组频率是1/10000^0 = 1和1/10000^(2/4) = 0.01。

  • 位置1：[sin 1, cos 1, sin 0.01, cos 0.01] ≈ [0.841, 0.540, 0.010, 1.000]
  • 位置2：[sin 2, cos 2, sin 0.02, cos 0.02] ≈ [0.909, −0.416, 0.020, 1.000]

前两维变化剧烈，后两维几乎不动；真实模型d = 512，各分量的波长从2π到接近2π×10000呈等比排列，最慢的分量约6万个位置才转一圈。

RoPE。只看一对维度，取θ = 1，q = k = [1, 0]。q在位置3旋转3弧度、k在位置1旋转1弧度，二者内积 = cos(3 − 1) = cos 2 ≈ −0.416。把两者都往后挪到位置5和3，内积仍是cos 2 ≈ −0.416。分数只与相距2有关，与绝对位置无关。

容易误解的地方

  • 位置编码的外推能力有限：训练时最长4K的模型直接用到32K，效果通常会崩，需要专门的长度扩展方法。
  • 加法式编码（正弦、可学习）改变的是输入向量；RoPE和ALiBi只作用在注意力分数上，值向量V里没有位置信息。
  • 因果掩码的解码器本身就隐含了一些位置信息（第i个位置只能看到i个token），所以完全不加位置编码的模型（无位置编码NoPE）也能工作。
