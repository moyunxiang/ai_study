人类反馈强化学习

RLHF

也叫：human preference　人类偏好学习　偏好学习　奖励模型　reward model　对齐　alignment

在交互版中打开（看它长在树上的哪里）

让人比较模型的两个回答哪个更好，用这些比较训练一个打分的奖励模型，再用强化学习让语言模型去提高这个分数，同时不偏离原模型太远。

先要会：指令微调与对话模板 策略梯度 KL散度 逻辑回归

指令微调与对话模板需要人写出“理想回答”，但很多任务（写一首好诗、给出得体又有用的建议）人很难写出最好的答案，却能轻松判断两个答案哪个更好。而且监督微调只教模型模仿，不告诉它哪些回答是不好的。RLHF（基于人类反馈的强化学习）把“比较”这种更便宜、更可靠的信号变成训练目标。

三个阶段（以InstructGPT与RLHF为代表）。

1. 监督微调：先用示范数据做一轮指令微调，得到初始策略π_SFT。

2. 训练奖励模型。对同一个提示x，让模型生成几个回答，请标注员排出好坏。训练一个奖励模型r(x, y)（通常是去掉输出层、改为输出一个标量的语言模型），使它给更好的回答打更高的分。常用Bradley–Terry模型：人们认为y_w比y_l好的概率是

P(y_w ≻ y_l) = σ(r(x, y_w) − r(x, y_l))

损失是−log σ(r_w − r_l)，和逻辑回归的形式一样，只是输入换成了两个分数之差。

3. 强化学习。把语言模型看作策略（见策略梯度）：输入提示是状态，生成整段回答是一次动作，奖励模型的分数是回报。用PPO算法最大化

E[r(x, y)] − β · KL(π(·|x) ‖ π_ref(·|x))

后一项是相对参考模型π_ref（通常就是π_SFT）的KL散度惩罚。没有它，模型会很快找到奖励模型的漏洞——生成一些奖励模型打高分、其实很糟的文本（奖励模型过优化），这是奖励设计与奖励投机里“奖励投机”的典型例子。

效果与发展。用人类偏好微调语言模型和人类反馈学摘要先在风格续写和摘要上验证了这套流程；InstructGPT论文报告，人类评估者更偏好13亿参数的InstructGPT的输出，而不是1750亿参数的GPT-3，这套方法随后用于ChatGPT发布。Anthropic HH-RLHF把它用于“有用且无害”的助手。DPO直接偏好优化（2023）证明在同样的目标下可以跳过奖励模型和强化学习，直接用偏好对做一个分类式的损失，大大简化了训练；RLAIF用AI代替人来给出偏好。后来的推理模型则改用可自动验证的奖励（答案对不对）来做强化学习（见推理token与测试时计算）。

例子

奖励模型的一步训练。提示“解释什么是光合作用”，标注员认为回答A比回答B好。奖励模型当前打分r(A) = 2.0，r(B) = 0.5。

模型认为A更好的概率：σ(2.0 − 0.5) = σ(1.5) ≈ 0.818，损失 = −ln 0.818 ≈ 0.201。梯度会把r(A)往上推、r(B)往下压，直到两者的差距足够大。如果反过来r(A) = 0.5、r(B) = 2.0，概率只有σ(−1.5) ≈ 0.182，损失约1.70，更新幅度更大。

KL惩罚的作用。某个回答中的一个token，当前策略给它的对数概率是−1.0，参考模型给的是−1.5：策略比原模型更偏爱它，这一项的KL估计为−1.0 − (−1.5) = 0.5。取β = 0.1，奖励中扣掉0.05。偏离越多扣得越多，把模型拴在原来的语言分布附近。

容易误解的地方

  • RLHF优化的是“标注员（或奖励模型）喜欢什么”，不是“什么是正确的”。模型可能学会讨好、回答更长、更自信，而不是更准确。
  • 奖励模型只是人类偏好的一个不完美近似，优化得越狠，偏差越容易被放大。
  • RLHF主要改变模型的行为和风格，通常不会给模型增加新知识。
