倒排索引

Inverted Index

也叫：inverted index　倒排索引　反向索引　倒排表　posting list　倒排列表　全文索引　full-text index　Lucene　Elasticsearch　关键词检索

在交互版中打开（看它长在树上的哪里）

搜索引擎的基本数据结构：不是“每篇文档包含哪些词”，而是反过来记录“每个词出现在哪些文档里”。查询时只需取出查询词对应的文档列表求交或合并，不用扫描全部文档。

先要会：分词与token

要在一亿篇文档里找出包含“深度学习”的那些，最笨的办法是逐篇扫描，每次查询都要读完整个语料。倒排索引把这件事提前做好。

结构。正常的存储方式是“文档 → 词”：文档1里有哪些词。倒排索引反过来，是“词 → 文档”：

  • 词典：所有出现过的词（经过分词与token和文本规范化与分句，可能还做了词干提取与词形还原）。
  • 倒排列表（posting list）：每个词对应一个列表，记录包含它的文档编号，通常还记录词频，以及词在文档中的位置（用于短语查询“深度 学习”必须相邻）。

列表按文档编号排序，相邻编号之差很小，可以用变长编码大幅压缩。

查询。查询“深度 学习”时，取出两个词的倒排列表：

  • 要求两个词都出现（AND）：两个有序列表做归并求交，时间与列表长度成正比。
  • 只要出现其一（OR）：合并两个列表，再对每篇候选文档按IDF与TF-IDF或BM25打分排序。

高频词（“的”“是”）的列表极长，几乎每篇都有，信息量又低，这是停用词被去掉或降权的原因之一；长列表还会配合跳表、提前终止等技巧，只算可能进入前k名的文档。

它在哪里出现。从TREC文本检索评测时代的检索系统到网页搜索引擎（见PageRank与Google搜索），倒排索引一直是核心；开源库Lucene以及在它之上的Elasticsearch都以它为基础。今天的检索增强系统里，BM25这一路仍然靠倒排索引；SPLADE学习式稀疏检索这类学习式稀疏检索的输出也是“词 → 权重”，能直接放进倒排索引。稠密向量则无法这样索引，要用近似最近邻结构（见检索与向量数据库），两者结合就是混合检索。

例子

三篇文档：

  • D1：“猫 喜欢 鱼”
  • D2：“狗 喜欢 骨头”
  • D3：“猫 和 狗”

倒排索引：猫 → [D1, D3]；狗 → [D2, D3]；喜欢 → [D1, D2]；鱼 → [D1]；骨头 → [D2]；和 → [D3]。

查询“猫 AND 狗”：对[D1, D3]和[D2, D3]做有序归并，得到[D3]，只比较了4个编号，完全没读文档内容。查询“猫 OR 鱼”：合并得[D1, D3]，再按BM25打分，D1同时含两个词，排在前面。

容易误解的地方

  • 倒排索引只解决“找出含这些词的文档”，排序好不好取决于打分函数。
  • 中文没有空格，建索引前的分词方式决定了能搜到什么：按词建索引，搜单字可能搜不到；很多系统同时建字和词的索引，或用n-gram索引。
