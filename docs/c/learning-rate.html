学习率与学习率调度

Learning Rate and Schedules

也叫：LR　步长　step size　学习率衰减　warmup　预热　余弦退火　cosine schedule

在交互版中打开（看它长在树上的哪里）

梯度下降每一步迈多大的系数；学习率调度则让这个系数随训练进程变化，常见形式是先预热、再逐渐衰减。

先要会：梯度下降 随机梯度下降与小批量

梯度下降的更新θ ← θ − η · g里，η就是学习率。它可能是深度学习里最重要的超参数：太大，损失震荡甚至变成NaN；太小，训练慢到不可接受，还可能停在不好的地方。同一个模型，学习率差3倍，结果可能差很多。

为什么要随时间变化：训练早期参数离好的区域很远，可以大步走；后期接近低谷，随机梯度下降与小批量的梯度噪声会让参数在谷底附近来回晃，这时缩小步长才能稳定下来。于是有了学习率调度（schedule）：

  • 阶梯衰减：每过若干轮乘以0.1，早期CNN（如ResNet）常用。
  • 余弦衰减：η_t = η_min + ½(η_max − η_min)(1 + cos(π·t/T))，从最大值平滑降到最小值，余弦退火SGDR推广了这种做法。
  • 预热（warmup）：最开始几百到几千步从接近0线性升到峰值。刚初始化时梯度方向不可靠，自适应学习率优化器的统计量也还没估准，直接用大学习率容易崩。学习率预热与大批量SGD用预热把ImageNet训练的批大小扩到8192。

今天的大语言模型几乎都用“线性预热 + 余弦（或线性）衰减”，也有“预热—恒定—快速衰减”的变体。

它出现在哪里：调学习率很费算力，所以有不少工作试图减少调参：μP与超参数迁移让小模型上调好的学习率可以直接迁移到大模型；Schedule-Free优化尝试完全去掉衰减调度。学习率与批大小、动量、权重衰减彼此耦合，比较两种方法时要注意它们的学习率是否各自调过。

例子

峰值学习率3×10⁻⁴，前2000步线性预热，之后到第100000步按余弦降到0：

  • 第1000步：处于预热中间，η = 1.5×10⁻⁴
  • 第26500步：衰减阶段走了1/4，η = ½×3×10⁻⁴×(1 + cos(π/4)) ≈ 2.56×10⁻⁴
  • 第51000步：衰减阶段走了一半，η = 1.5×10⁻⁴
  • 第100000步：η = 0

容易误解的地方

  • 损失曲线在学习率衰减时常会突然下降一截，这是调度造成的，不一定说明模型“学会了新东西”。
  • 对Adam类优化器，学习率的合理量级（常见1e-4到1e-3）和SGD（常见0.01到0.1）差别很大，不能直接照搬。
