CPU、GPU与并行计算

CPU, GPU and Parallel Computing

也叫：显卡　图形处理器　CUDA　SIMD　加速卡

在交互版中打开（看它长在树上的哪里）

CPU用少量强大的核心快速完成一步接一步的任务，GPU用上万个简单核心同时做同一种计算；神经网络几乎全是矩阵乘法，正好适合GPU。

先要会：矩阵乘法与线性变换

神经网络的训练和推理，绝大部分时间花在矩阵乘法与线性变换上：一个4096×4096的矩阵乘以另一个同样大小的矩阵，要做约687亿次乘加（约1374亿次浮点运算），而且每个输出元素的计算彼此独立。这种“同一种运算、海量独立重复”的工作，决定了用什么芯片最划算。

CPU为延迟而设计。一颗服务器CPU有几十到上百个核心，每个核心很“聪明”：大缓存、分支预测、乱序执行，能把一段充满if和跳转的程序尽快跑完。芯片面积大多花在控制逻辑和缓存上，真正做算术的部分占比不高。

GPU为吞吐而设计。GPU把面积主要用来堆算术单元。以H100为例，它有132个流式多处理器（SM），共一万多个CUDA核心，外加专做小矩阵乘法的Tensor Core。程序员写一个“内核函数”，GPU同时启动成千上万个线程，每个线程算输出矩阵的一小块。单个线程很慢、也不擅长分支，但总吞吐远超CPU。这种模式叫SIMT（单指令多线程），本质上是时间与空间复杂度意义下工作量不变、靠并行把墙钟时间压下来。

为什么是GPU赢了。GPU本来是为游戏渲染设计的（每个像素独立着色），CUDA在2006年让它可以用C语言编程，GPU训练深度网络和AlexNet证明它能把训练提速几十倍。2005年前后单核频率停止增长（见晶体管、制程与摩尔定律），并行成了提速的唯一出路。之后专用电路继续出现：V100与Tensor Core引入Tensor Core，Google的Google TPU用脉动阵列专做矩阵乘法。

它出现在哪里：几乎所有深度学习框架都把张量放在GPU显存里计算；GPU的瓶颈往往不在算力，而在把数据送进算术单元的速度，见显存、内存带宽与“内存墙”。

例子

两个4096×4096矩阵相乘需要2 × 4096³ ≈ 1.37×10¹¹次浮点运算。一颗每秒能做约1万亿次（1 TFLOPS）的多核CPU需要约0.14秒；H100的BF16 Tensor Core官方标称稠密算力约989 TFLOPS，理论上只需约0.14毫秒，快约一千倍。实际能达到的比例取决于数据能否及时从显存送到计算单元。

容易误解的地方

  • GPU不是在所有任务上都更快：串行、分支多、数据量小的任务（如解析JSON、遍历树）CPU更合适。
  • 厂商标称的TFLOPS常带“稀疏”星号，是稠密算力的2倍；比较时要看清楚是哪一种精度、是否含稀疏。
  • 数据从CPU内存搬到GPU显存要走PCIe，很慢；频繁来回搬运会抵消GPU的优势。
