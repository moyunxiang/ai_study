多跳问答

Multi-Hop Question Answering

也叫：multi-hop QA　multi-hop question answering　多跳问答　多跳推理　multi-hop reasoning　多步问答　组合问题　compositional questions　组合性差距　compositionality gap　bridge entity　桥接实体

在交互版中打开（看它长在树上的哪里）

需要把两条或更多条分散的信息串起来才能回答的问题，例如“《哈利·波特》作者的出生地是哪里”要先找作者、再找出生地。它考验模型的检索规划和推理组合能力。

先要会：检索与向量数据库

很多问题的答案不在任何一个段落里。“发明电话的人出生在哪个国家？”需要先知道“贝尔发明了电话”，再知道“贝尔出生在苏格兰”。每一步叫一“跳”（hop）。单跳问答只要找到一个相关段落再抽取答案（见机器阅读理解）；多跳问答必须把多条证据组合起来，而且第二步要查什么，往往依赖第一步的结果。

为什么难。

  • 检索：第二跳需要的段落和原始问题的字面相似度可能很低（问题里根本没提“贝尔”），一次检索很难同时找全。
  • 组合：模型可能各步都“知道”，却不会把它们串起来。研究者把这种现象称为组合性差距：模型能分别答对两个子问题，却答不对合起来的问题。
  • 捷径：数据集里有的问题其实单跳就能猜出答案，模型不必真正推理。

数据集。HotpotQA多跳问答是代表性的多跳问答数据集，基于维基百科，除了答案还标注了支撑事实（哪几句话构成证据链），可以评测模型是否“因为对的理由答对”。StrategyQA隐式推理的问题需要隐含的推理步骤（“亚里士多德用过笔记本电脑吗？”）。

方法。

  • 迭代检索：检索一次、读一读，再根据已知信息构造下一个查询（见查询改写与扩展）。IRCoT交替检索推理让思维链和检索交替进行：每写一步推理，就用它去检索下一批段落。
  • 问题分解：先把问题拆成子问题，逐个回答。Self-Ask让模型显式地提出并回答“追问”；DecomP分解式提示把复杂任务分派给不同的子提示。
  • 智能体式：ReAct让模型在“思考—搜索—观察”循环中自己决定下一步查什么（见智能体循环、智能体式检索），今天的深度研究类智能体是这个方向的延伸。

多跳问答的评测通常同时报告答案的精确匹配与token级F1和F1，以及支撑事实的预测准确度。

例子

问题：“执导《泰坦尼克号》的导演，他的下一部长片叫什么？”

  • 第1跳：检索“泰坦尼克号 导演”→ 詹姆斯·卡梅隆。
  • 第2跳：用新得到的实体构造查询“詹姆斯·卡梅隆 电影 年表”→ 《泰坦尼克号》（1997）之后的下一部故事长片是《阿凡达》（2009）。

若只用原问题检索一次，最相关的段落都在讲《泰坦尼克号》本身，很可能找不到《阿凡达》的信息。

容易误解的地方

  • 答案对了不等于推理链对了：检查支撑事实或中间步骤，才能区分“真正多跳”和“走捷径”。
  • 跳数越多，每一步的错误会累积，第一跳找错实体，后面全错。
