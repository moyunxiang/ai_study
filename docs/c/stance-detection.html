立场检测

Stance Detection

也叫：立场检测　立场分析　stance detection　stance classification　立场识别　观点立场　支持反对中立　favor against none　零样本立场检测　zero-shot stance detection　跨目标立场检测　cross-target stance　谣言立场　rumour stance　SemEval-2016 Task 6

在交互版中打开（看它长在树上的哪里）

判断一段文本对某个给定目标（人物、政策、观点、事实陈述）持支持、反对还是中立态度。它和情感分析不同：一条语气很负面的推文，可能恰恰是在支持某项政策。

先要会：监督学习 预训练与微调

情感分析问的是“这段话的情绪是正面还是负面”，立场检测问的是“这段话对某个目标是赞成还是反对”。两者经常不一致：“那些反对控枪的人真让人恶心”情绪强烈负面，对“控枪”的立场却是支持；“这项减税政策终于来了”情绪正面，但如果目标是“提高税收”，立场就是反对。

任务形式。输入是一对（文本，目标），输出是{支持, 反对, 中立/无关}之一。变体包括：

  • 目标明确：给定目标，如“气候变化是真实存在的”。SemEval 2016的推特立场检测任务（见Senseval / SemEval）是常用基准，按多个预设目标分别标注。
  • 跨目标与零样本立场：训练时没见过的目标，要靠理解目标本身的含义来泛化（见零样本与少样本）。
  • 谣言与事实核查中的立场：判断一条回复对原帖的说法是支持、否认、质疑还是评论；FEVER事实核查式事实核查中，判断证据对声明是“支持”“反驳”还是“信息不足”，本质上是立场检测与自然语言推理与文本蕴含的结合。

方法演变。早期用词袋特征加SVM或逻辑回归（见文本分类），再到把目标与文本一起编码的注意力模型（如为目标建模的LSTM，见ATAE-LSTM方面级情感这一类方面级情感方法）；BERT之后通常把目标和文本拼成句对输入做微调（见预训练与微调）；大语言模型则可以直接用提示零样本判断，但对讽刺、隐含立场和需要背景知识的情况仍然容易出错（见反讽：情感与情境对比）。

为什么难。立场常常是隐含的，需要推理和背景知识：“我们的孩子不应该在恐惧中上学”对“控枪”的立场需要联系上下文才能判断。文本里可能根本没提目标的名字。数据集的类别分布也很不均衡，中立类往往最多（见类别不平衡与长尾），所以常报告支持类与反对类的宏平均F1（见不均衡数据的指标：平衡准确率与MCC）。

应用。舆情分析、政策民意调查、谣言检测与事实核查、辩论分析，以及评估大模型在争议话题上是否保持中立。

例子

目标：“城市应扩建自行车道”。

  • “每天开车上班堵一个小时，真希望有条安全的路骑车。”——情绪负面，立场支持。
  • “又要占车道？本来就够堵了。”——立场反对。
  • “今天天气不错。”——无关。

情感分类器会把前两句都判为负面，立场检测则要把它们分开。

容易误解的地方

  • 把立场检测当成情感分析来做，是最常见的错误；评测时要检查模型是否只是在学情绪词。
  • 同一文本对不同目标的立场可以完全不同，标注和训练时目标必须作为输入的一部分。
