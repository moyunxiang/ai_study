本体与语义网

Ontology and the Semantic Web

也叫：本体　本体论　ontology　ontologies　领域本体　domain ontology　OWL　Web Ontology Language　RDF　RDFS　语义网　semantic web　描述逻辑　description logic　分类法　taxonomy　schema.org　本体匹配　ontology alignment　is-a关系

在交互版中打开（看它长在树上的哪里）

对一个领域“有哪些概念、彼此什么关系”的形式化描述：类与子类、属性、关系及其约束。它为知识图谱提供模式，让不同系统能用同一套词汇交换和推理知识。

先要会：命题逻辑、谓词逻辑与符号推理 图、树与搜索

“本体”这个词借自哲学（研究“存在什么”），在计算机科学里指一份明确、形式化的概念体系说明。它回答的问题是：这个领域里有哪些类型的东西？它们怎样分类？彼此之间可能有什么关系？

组成部分。

  • 类（概念）及其层级：动物 → 哺乳动物 → 猫。子类关系（is-a）是最核心的结构，可以继承：猫是哺乳动物，哺乳动物有脊椎，所以猫有脊椎。
  • 实例：具体的个体，如“汤姆”是猫的一个实例。
  • 属性与关系：药物“治疗”疾病，人“出生于”城市；还可以规定定义域和值域（“出生于”的主语必须是人、宾语必须是地点）、基数（一个人只有一个出生日期）、对称或传递等性质。
  • 公理与规则：如“母亲 = 女性且有子女的人”，允许推理机自动推出新的事实或发现矛盾（见命题逻辑、谓词逻辑与符号推理）。

与相关概念的区别。

  • 知识图谱是大量的事实三元组，本体是它的模式：规定可以有哪些类型的实体和关系。DBpedia有一个人工维护的本体，Wikidata的类型体系则由社区协作逐步形成（见知识图谱）。
  • 词汇语义资源如WordNet记录词与词之间的上下位、同义关系，关注的是语言中的词；本体关注的是领域中的概念。两者常被结合使用，HowNet则用一组“义原”来描述概念。
  • 分类法（taxonomy）只有层级，本体还有更丰富的关系和约束。

技术标准。语义网用RDF表示三元组，用RDFS和OWL（Web本体语言）描述类、属性和约束，并基于描述逻辑进行自动推理；schema.org为网页标注提供了一个通用本体。

在AI历史与今天。专家系统需要显式的领域知识（见专家系统的商业化）；Cyc常识知识库试图手工构建覆盖人类常识的巨型本体和规则库，几十年投入巨大却难以规模化，成为“知识获取瓶颈”的典型例子。ConceptNet常识图谱则从众包中收集更松散的常识关系。今天，生物医学（如基因本体、医学术语体系）、电商商品类目、企业数据治理仍大量使用本体；大语言模型被用来自动抽取本体和补全知识图谱，而本体反过来为检索增强生成提供结构化约束（见检索与向量数据库和知识图谱嵌入与知识表示学习）。

例子

一个小型医药本体：类“药物”“疾病”“症状”，子类“抗生素 ⊂ 药物”；关系“治疗（药物 → 疾病）”“表现为（疾病 → 症状）”，规定“治疗”的主语必须是药物。若知识库中有（阿莫西林，类型，抗生素）和（阿莫西林，治疗，肺炎），推理机可以推出“阿莫西林是一种药物”；若有人录入（发烧，治疗，肺炎），推理机会报告类型冲突，因为“发烧”属于“症状”而不是“药物”。

容易误解的地方

  • 本体的质量取决于建模者的判断，同一领域的不同本体可能互不兼容，对齐它们（本体匹配）本身就是一个难题。
  • 本体越严格，推理越可靠，但覆盖面越窄、维护成本越高；真实世界的知识常常有例外和模糊边界。
