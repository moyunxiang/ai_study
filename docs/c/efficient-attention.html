稀疏注意力与高效注意力

Sparse and Efficient Attention

也叫：sparse attention　线性注意力　linear attention　滑动窗口注意力　长序列注意力　FlashAttention

在交互版中打开（看它长在树上的哪里）

标准注意力的计算和内存随序列长度平方增长；高效注意力通过只看部分位置、近似、或改进实现方式，把长上下文的成本降下来。

先要会：自注意力与多头注意力 时间与空间复杂度 显存、内存带宽与“内存墙”

自注意力与多头注意力要为每对位置算一个分数，序列长度n时注意力矩阵是n×n。n = 1000时只有一百万个数，n = 128k时有一百七十亿个。这限制了上下文窗口能开多长，也让长文档、长视频、长代码库的处理很贵。改进方向大致有四类。

1. 稀疏注意力：只算一部分位置对。稀疏注意力用固定的跨步模式；Longformer滑窗注意力让每个token只看前后w个位置的滑动窗口，再加几个能看全局的特殊token；BigBird稀疏注意力组合了窗口、全局和随机连接。代价从n²降到n·w。缺点是模式是人定的，可能漏掉远处真正相关的内容。近年的原生稀疏注意力NSA等方法让模型自己学习选哪些块，并做到与硬件对齐。

2. 线性化与低秩近似。注意力里的softmax(QKᵀ)V如果去掉softmax、换成核函数φ(Q)φ(K)ᵀ，就能先算φ(K)ᵀV（d×d），复杂度变成O(n)，这是线性注意力和Performer核近似注意力的思路；高效长序列注意力用局部敏感哈希只在相似的键之间算注意力。线性注意力可以写成RNN形式，与状态空间模型与线性RNN是同一家族。

3. 不改数学，改实现。FlashAttention不近似任何东西，计算量也不变，而是把计算分块放在GPU片上高速缓存里完成，从不把n×n矩阵写回显存，用Online Softmax边算边归一化。它的加速来自减少显存、内存带宽与“内存墙”上的读写，已经成为默认实现。

4. 压缩KV缓存。生成时每步都要读一遍所有历史的K、V。多查询注意力MQA和分组查询注意力GQA让多个查询头共享同一组K、V；DeepSeek-V2与MLA的MLA把K、V压缩成低维潜向量，都直接减少KV缓存的显存占用。

例子

序列长度n = 131072（128k）：

  • 完整注意力矩阵有n² ≈ 1.7×10¹⁰个元素，按FP16每个2字节，单头单层就是32 GiB——这就是为什么不能把它整个写进显存。
  • 改用窗口w = 4096的滑动窗口注意力，每个token只看4096个位置，计算量是完整注意力的4096/131072 = 1/32。
  • FlashAttention计算量仍是n²量级，但只在片上缓存里分块处理，不需要那32 GiB。

容易误解的地方

  • “线性复杂度”不等于实际更快：n不够大时，常数项和硬件利用率往往让近似方法比FlashAttention还慢。
  • 很多近似方法在困惑度上接近完整注意力，却在“大海捞针”式的精确检索任务上明显变差。
  • FlashAttention是精确注意力的快速实现，不属于近似方法，二者常被混为一谈。
