文本规范化与分句

Text Normalization and Sentence Segmentation

也叫：text normalization　文本规范化　文本标准化　文本归一化　Unicode normalization　NFKC　NFC　全角半角　全角转半角　lowercasing　小写化　大小写转换　sentence segmentation　分句　句子切分　文本清洗　text cleaning　文本预处理　text preprocessing　正则化文本　文本正则化

在分词和建模之前把原始文本整理成统一的形式：统一Unicode编码和全半角、处理大小写和空白、切分句子等。看似琐碎，却直接决定同一个字符串会不会被当成两个东西。

先要会：分词与token

计算机眼里，“Ａ”（全角）和“A”（半角）是两个不同的字符；“é”既可以存成一个字符，也可以存成“e”加一个组合重音符号；从网页上抓来的文本里还混着不换行空格、零宽字符、HTML实体。不先统一，分词器、词表、检索和去重都会把本该相同的东西当成不同的。文本规范化就是处理这些问题的一组步骤。

常见步骤。

  • Unicode规范化。Unicode标准定义了NFC、NFD、NFKC、NFKD四种形式。NFC把可组合的字符合成一个码位；NFKC更进一步，把“兼容等价”的字符也统一，例如全角字母转半角、“ﬁ”连字拆成“fi”、上标“²”变成“2”。SentencePiece默认就先做一种基于NFKC的规范化。
  • 大小写。经典NLP和检索常把文本全部转小写，让“Apple”和“apple”合并；代价是丢掉专有名词的线索，所以NER和现代语言模型一般保留大小写（BERT就有cased和uncased两个版本）。
  • 空白与控制字符：合并连续空格、统一换行符、去掉零宽字符。
  • 繁简、标点：中文可能需要繁简转换、统一中英文标点。
  • 领域相关：语音合成里还要把“2024年”展开成“二零二四年”、把“Dr.”展开成“Doctor”，这也叫文本规范化。

分句（sentence segmentation）。很多任务以句子为单位处理。英文句号有歧义：“Dr. Smith arrived at 3 p.m. today.”里只有最后一个句点是句子结束；中文的问号、感叹号、省略号也要考虑引号嵌套。规则加缩写词表能解决大部分情况，统计或神经分句器处理剩余部分。

在大模型时代。字节级BPE的分词器（见分词与token）能直接处理任意字节序列，所以很多大模型的分词器只做很轻的规范化，尽量保持原文，好让输出可以逐字节还原。但在预训练数据处理（见预训练语料的清洗、过滤与去重）中，规范化仍很重要：同一篇文章的两个版本只差全半角或空白，如果不规范化，去重就识别不出来。

例子

三个看起来一样的字符串：

  • “ＡＩ２０２６”（全角）
  • “AI2026”（半角）
  • “AI²⁰²⁶”（上标）

不做规范化，它们的字节完全不同，会被切成不同的token、在检索里互不匹配。做NFKC规范化后，三者都变成“AI2026”。

分句的例子：“他说：“明天见！”然后走了。”句中的“！”在引号里面，不应在那里断句，整段是一句话。

容易误解的地方

  • NFKC会改变一些有意义的区别，例如数学公式里的上标、某些语言的兼容字符，对代码、公式类数据要谨慎。
  • 训练和推理必须用完全相同的规范化流程，否则同一句话在两边会被切成不同的token。
