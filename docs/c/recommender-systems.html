推荐系统与协同过滤

Recommender Systems and Collaborative Filtering

也叫：推荐系统　recommender system　recommendation system　推荐算法　协同过滤　collaborative filtering　矩阵分解推荐　matrix factorization　隐语义模型　latent factor model　基于内容的推荐　content-based filtering　冷启动　cold start　召回与排序　candidate generation　点击率预测　CTR prediction　CTR

根据用户过去的行为预测他接下来会喜欢什么。核心思路是协同过滤：口味相近的人喜欢相近的东西；经典实现是把评分矩阵分解成用户向量和物品向量的乘积。

先要会：低秩近似 嵌入向量

电商、短视频、音乐、新闻的首页都由推荐系统决定。它要解决的问题是：用户和物品都数以百万计，每个用户只和极少数物品有过交互，怎么猜出他对其余物品的兴趣？

协同过滤（collaborative filtering）。不看物品内容，只看“谁和什么有过交互”。

  • 基于邻居：找和你行为相似的用户，推荐他们喜欢而你还没看过的（基于用户）；或者找和你喜欢的物品经常被同一批人喜欢的物品（基于物品）。相似度常用余弦相似度（见内积与余弦相似度）。
  • 矩阵分解：把用户×物品的评分矩阵R（绝大多数位置是空的）近似为两个瘦矩阵的乘积R ≈ U·Vᵀ。每个用户得到一个d维向量u，每个物品得到一个向量v，预测评分是uᵀv。只在已知评分上最小化平方误差并加正则化，可以用SGD或坐标下降与交替优化中的交替最小二乘求解。这本质上是低秩近似假设：口味只由少数几个隐含因素决定（喜不喜欢动作片、偏好老片还是新片……）。Netflix Prize竞赛让矩阵分解与集成方法成为主流。

基于内容与混合方法。用物品的文字、图像、类别等特征和用户画像做预测，能处理没有交互记录的新物品，即冷启动问题。实际系统都是两者混合。

深度学习时代的工业架构。通常分两级：

  • 召回：从上亿物品中快速找出几百个候选。常用双塔模型与交叉编码器：用户塔和物品塔分别编码成向量，用近似最近邻检索（见检索与向量数据库），DSSM深度语义匹配是这一结构的早期代表。
  • 排序：用更复杂的模型对候选精细打分，预测点击率、观看时长等，常用二元交叉熵与sigmoid输出训练。

作为决策问题。推荐会改变用户接下来看到什么，进而改变未来的数据，所以也被建模为老虎机或强化学习：LinUCB上下文老虎机用上下文老虎机做新闻推荐，YouTube REINFORCE推荐用策略梯度优化长期观看；离线评估需要处理“日志只记录了旧策略推荐过的东西”这一偏差，见老虎机回放离线评估和探索与利用。

评测。离线常用Recall@K、NDCG等排序指标（见排序指标：NDCG、MRR与Recall@K），最终以线上A/B测试与在线实验为准。

例子

3个用户对4部电影的评分（?为未看）：A：(5, 4, ?, 1)，B：(4, ?, 1, 1)，C：(1, 1, 5, ?)。用d = 2的矩阵分解，可能学到A ≈ (2.2, 0.2)、电影3 ≈ (0.3, 2.4)，预测A对电影3的评分为2.2×0.3 + 0.2×2.4 ≈ 1.1：A和B口味相近，B给电影3打了低分，所以A大概也不喜欢。

容易误解的地方

  • 推荐系统只能从用户看到过的物品里收集反馈，曝光偏差和流行度偏差会自我强化，“越推越窄”。
  • 离线指标与线上效果常常不一致；离线涨了，线上不一定涨。
