困惑度

Perplexity

也叫：PPL　perplexity score　语言模型评测

在交互版中打开（看它长在树上的哪里）

评价语言模型的标准指标：模型在测试文本上平均每个token的交叉熵取指数。直观含义是模型平均在“几个等可能的选项”之间犹豫，越低越好。

先要会：交叉熵 信息量与熵 语言模型

要比较两个语言模型哪个更好，最直接的办法是看它们给一段没见过的真实文本打多高的概率：好模型应该觉得真实文本“不意外”。但整段文本的概率是很多小数连乘，长度不同就没法比，需要归一化成“每个token平均”的量。

定义。测试文本有N个token，模型给第t个token的条件概率是p(w_t | w_<t)。平均负对数似然（也就是交叉熵）是

H = −(1/N) · Σ_t ln p(w_t | w_<t)

困惑度是它的指数：

PPL = exp(H) = (Π_t p(w_t | w_<t))^(−1/N)

即每个token概率的几何平均的倒数。若对数以2为底，H的单位是比特，PPL = 2^H，结果相同。

怎么理解这个数。如果模型每一步都在k个选项中均匀地猜（每个概率1/k），那么PPL恰好等于k。所以PPL = 20可以理解为：模型平均来说，像是在20个同样可能的词中犹豫。一个什么都没学的模型对V个词均匀猜，PPL = V；完美模型PPL = 1。它和信息量与熵的关系是：PPL是“有效选项数”，H是对应的信息量。

它在哪里出现。困惑度Perplexity（1977）在语音识别中提出这个度量；n-gram时代的平滑方法（n-gram平滑）、RNN语言模型、探索语言模型的极限都以测试集困惑度作为主要结果；GPT-2在多个语言建模数据集上报告了零样本困惑度。大模型时代，预训练损失（就是ln PPL）仍是最基本的监控曲线，规模定律（语言模型的规模定律）描述的也正是这个损失怎样随规模下降。

例子

一段4个token的测试文本，模型给每个真实token的概率依次是0.5、0.25、0.1、0.4。

  • 对数：ln 0.5 = −0.693，ln 0.25 = −1.386，ln 0.1 = −2.303，ln 0.4 = −0.916。
  • 平均负对数似然：H = (0.693 + 1.386 + 2.303 + 0.916)/4 ≈ 1.325。
  • 困惑度：PPL = e^1.325 ≈ 3.76。

这个模型平均像是在不到4个选项中犹豫。对照：词表大小5万、完全均匀猜测的模型，困惑度是50,000。

若某个token的概率接近0（比如0.0001），ln 0.0001 ≈ −9.2，一个token就能把平均值大幅拉高——困惑度对“完全没料到”的情况惩罚很重。

容易误解的地方

  • 不同分词器的困惑度不能直接比较：切得更碎的分词器，每个token更容易预测，困惑度天然更低。跨分词器比较时应换算成每字节或每字符的比特数。
  • 困惑度低不等于生成质量好或回答有用。指令微调和RLHF后的模型在普通文本上困惑度常常变高，用起来却更好。
  • 测试集如果混进了训练数据（见数据泄漏与基准污染），困惑度会虚低。
