预填充与解码两阶段

Prefill and Decode Phases

也叫：prefill　预填充　prefill阶段　decode阶段　解码阶段　decode phase　prefill and decode　预填充与解码　compute-bound　memory-bound　算力受限　带宽受限　算术强度　arithmetic intensity　首token延迟　TTFT　TPOT

在交互版中打开（看它长在树上的哪里）

大模型推理分两个阶段：预填充一次性并行处理整段提示、建立KV缓存，受算力限制；解码阶段每步只生成一个token，要反复读取全部权重和缓存，受显存带宽限制。

先要会：KV缓存 显存、内存带宽与“内存墙” 吞吐、延迟与批处理

用户发来一段2000个token的提示，模型要回答500个token。这两部分在计算上完全不同，理解这一点是理解推理优化的起点。

预填充（prefill）。把整段提示一次输入模型，所有位置并行计算（训练时的做法一样，见因果掩码），得到每层每个位置的K、V，存进KV缓存，并算出第一个输出token。2000个token一起算，矩阵乘法的规模很大，GPU的计算单元能被充分利用——这一阶段受算力限制（compute-bound）。它决定了首token延迟（TTFT，见流式输出）。

解码（decode）。之后每一步只输入上一步生成的1个token，读取KV缓存，算出下一个token，再把新的K、V追加进缓存。每一步的计算量很小，但必须把模型的全部权重和越来越长的KV缓存从显存读一遍。读数据的时间远超计算时间——这一阶段受显存带宽限制（memory-bound，见显存、内存带宽与“内存墙”）。它决定了每token间隔（TPOT）。

用算术强度来看。算术强度 = 计算量 / 读写的字节数。一个d×d的权重矩阵乘以n个token，计算约2·n·d²次，读权重约2·d²字节（FP16），强度约为n。预填充n = 2000，强度很高；解码n = 1，强度约为1，GPU算力大部分闲着。

由此产生的优化。

  • 批处理：把很多用户的解码步拼成一批，权重读一次供多个请求共用，提高解码的算术强度（见吞吐、延迟与批处理）。Orca连续批处理的连续批处理让请求随到随加入、完成即离开。
  • 分块预填充：长提示的预填充会让同一批里的解码请求卡顿，分块预填充Sarathi把预填充切成小块，与解码混合调度。
  • 预填充-解码分离：两阶段需要的硬件特性不同，Splitwise阶段拆分推理和预填充-解码分离部署把它们放到不同的机器上，中间传输KV缓存（见预填充-解码分离）。
  • 缩小KV缓存和权重：MHA、MQA、GQA与MLA、量化都减少了解码时要读的字节数。
  • 推测解码：用小模型一次猜多个token，大模型一次验证，把多步解码变成一次类似预填充的并行计算（见推测解码家族）。

例子

某70亿参数模型用FP16存储，权重约14GB；GPU显存带宽约2TB/s，算力约300 TFLOPS（示意值）。

  • 解码一步：至少要读一遍14GB权重，约7毫秒；计算约2×7×10^9 = 1.4×10^10次运算，只需约0.05毫秒。读数据的时间是计算的上百倍，所以单请求每秒最多约140个token。
  • 预填充2000个token：计算约2.8×10^13次运算，约0.09秒；权重仍只读一遍。计算成为瓶颈。
  • 若把64个请求的解码合成一批：权重还是读一次（约7毫秒），却产出64个token，吞吐提高几十倍，每个请求的速度几乎不变。

容易误解的地方

  • “推理慢”要先分清是首token慢（预填充、排队）还是逐字慢（解码），两者的优化手段不同。
  • 长上下文下，解码读KV缓存的字节数可能超过读权重的字节数，这时批处理的收益会下降。
