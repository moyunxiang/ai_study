MHA, MQA, GQA and MLA

也叫：MHA　MLA　多头注意力　multi-head attention　多查询注意力　multi-query attention　分组查询注意力　grouped-query attention　多头潜在注意力　multi-head latent attention　KV头　KV heads　num_key_value_heads

多头注意力的几种变体，区别在于多少个查询头共用一组键和值：MHA每头一组，MQA所有头共用一组，GQA分组共用，MLA把键值压缩成一个低维向量。目的都是缩小KV缓存、加快推理。

先要会：自注意力与多头注意力 KV缓存 查询、键与值（Q/K/V）

大模型生成文本时，每一步都要读取所有历史token的K和V（见KV缓存）。这份缓存随上下文长度线性增长，长对话、大批量时会占满显存，而且每一步都要把它从显存搬进计算单元，解码速度主要受内存带宽限制（见显存、内存带宽与“内存墙”）。缩小KV缓存，就成了推理优化的头号目标。

每个token的KV缓存大小：

2 × 层数 × KV头数 × 每头维度 × 每个数的字节数

前面的2对应K和V。可以动的主要是“KV头数”。

MHA（多头注意力）。Transformer原本的设计：h个查询头，各有自己的K头和V头，KV头数 = h。表达能力最强，缓存最大。

MQA（多查询注意力）。多查询注意力MQA（2019）让所有查询头共用一组K和V，KV头数 = 1，缓存缩小为1/h。代价是质量有所下降，训练也可能不稳定。PaLM采用了它。

GQA（分组查询注意力）。分组查询注意力GQA（2023）折中：把h个查询头分成g组，每组共用一组K、V，KV头数 = g。g = h就是MHA，g = 1就是MQA。论文还提出可以把已训练好的MHA模型的KV头按组取平均，再少量继续训练，转换成GQA。Llama 2的大尺寸版本和Mistral 7B等模型使用GQA，它成为开源大模型的默认选择。

MLA（多头潜在注意力）。DeepSeek-V2与MLA提出：不缓存每个头的K、V，而是缓存一个低维的“潜在向量”，用时再通过矩阵把它还原成各头的K、V（见低秩近似）。缓存比GQA更小，而每个头仍有各自不同的K、V。旋转位置编码与这种压缩不兼容，所以MLA把位置信息放在额外的一小段维度里单独处理。

这些变体只改动K、V的数量，查询头数和注意力的计算方式不变；它们与稀疏注意力与高效注意力（改变“谁看谁”）是两类不同的优化。

例子

设某模型有80层、64个查询头、每头维度128，用FP16（2字节）存储。

  • MHA：每个token的KV缓存 = 2×80×64×128×2 = 2,621,440字节 ≈ 2.5MB。4096个token的上下文约10GB。
  • GQA，8个KV头：缩小到1/8，每token约0.31MB，4096个token约1.25GB。
  • MQA，1个KV头：再缩小到1/64，4096个token约0.16GB。

同一张显卡上，缓存越小，能同时服务的请求越多、能支持的上下文越长。

容易误解的地方

  • GQA减少的是KV缓存和显存读写，不是参数量的主要部分，也几乎不减少训练时的计算量。
  • 用张量并行把注意力头分到多张卡上时，KV头数太少（如MQA的1个）会让每张卡都得保留同一份K、V，节省效果打折扣。
  • “多头潜在注意力”的“潜在”指压缩后的低维向量，与生成模型的潜空间无关。
