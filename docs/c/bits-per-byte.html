每字节比特与每字符比特

Bits per Byte and Bits per Character

也叫：bits per byte　BPB　bits-per-byte　每字节比特　每字节比特数　bits per character　BPC　每字符比特　字符级困惑度　压缩率（语言模型）　语言模型即压缩

在交互版中打开（看它长在树上的哪里）

把语言模型的交叉熵损失换算到“每个字符或每个字节平均需要多少比特”。与按token算的困惑度不同，它不依赖分词方式，可以在用不同分词器的模型之间公平比较。

先要会：困惑度 交叉熵 信息量与熵

困惑度是按token计算的：模型平均每个token有多“困惑”。但不同模型的token不一样大：一个分词器把“unbelievable”切成1个token，另一个切成3个。前者每个token要预测的内容更多，困惑度自然更高，可这不代表它更差。要比较用不同分词器、甚至直接读字节的模型（如ByT5字节级模型、字节潜变量BLT），需要换一个与分词无关的单位。

定义。设一段文本共有B个字节（或C个字符），模型对这段文本的总负对数似然为L = −Σ log p(token)（自然对数，单位奈特）。则

BPB = L / (B · ln 2)（每字节比特数）

BPC = L / (C · ln 2)（每字符比特数）

除以ln 2是把奈特换成比特（见信息量与熵、交叉熵）。总似然与怎么切token无关——无论怎么切，模型都是在给同一段文本打分，所以换算到每字节后就可以比较。

与困惑度的换算。若每个token平均对应b个字节，

BPB = log₂(PPL_token) / b

直观意义。BPB也是用这个模型做无损压缩时，每个字节平均需要的比特数（借助算术编码可以接近这个值）。原始文本每个字节8比特；BPB为1，相当于压缩到原来的1/8。“语言模型就是压缩器”的说法正源于此。

在哪里出现。字符级建模的经典基准enwik8/text8字符级基准就以BPC（实际是每字节比特）报告结果；The Pile与开放预训练语料用BPB作为主要的语言建模指标，RETRO等工作沿用；字节级模型和分词器研究必须用它来和子词模型比较。比较时要确认统计口径：UTF-8下一个汉字占3个字节，同一段中文按字符算和按字节算的数值差约3倍。

例子

一段文本共1000个字节，分词器A切成250个token，分词器B切成400个token。

  • 模型A：每token交叉熵2.4奈特，PPL ≈ e^2.4 ≈ 11.0；总损失600奈特，BPB = 600 / (1000 × 0.693) ≈ 0.87。
  • 模型B：每token交叉熵1.6奈特，PPL ≈ 4.95，看上去好得多；总损失640奈特，BPB ≈ 0.92。

按困惑度B明显占优，按每字节比特A反而略好：B的“低困惑度”主要来自它的token更小、更好猜。

容易误解的地方

  • 按字节和按字符算的结果不能混用，中文、日文等多字节文字差别尤其大。
  • 报告BPB时要说明是否包含特殊token、文档边界等，否则不同论文的数字无法直接比。
