智能体循环

The Agent Loop

也叫：AI代理　ReAct　agentic　代理循环　自主智能体

在交互版中打开（看它长在树上的哪里）

让语言模型反复执行“观察当前情况 → 决定下一步 → 调用工具行动 → 读取结果”的循环，直到任务完成。它把一次性的问答变成了多步完成复杂任务的系统。

先要会：工具调用 上下文学习与提示 上下文窗口

一次问答只能解决一步就能完成的事。修一个代码bug需要先跑测试看报错、再打开相关文件、再修改、再重跑测试，每一步要做什么都取决于上一步看到了什么。没有任何人能预先写好这些步骤，模型也不能一次性给出全部答案。

循环的结构。智能体就是把工具调用放进一个循环：

  • 初始化：上下文 = [系统提示, 工具说明, 任务]
  • 让模型生成：输出 = 模型(上下文)
  • 如果输出是最终答案，结束。
  • 否则执行其中的工具调用：结果 = 执行(输出)，然后上下文 += [输出, 结果]，回到第二步。

每一轮，模型根据目前积累的全部上下文（任务、自己之前的想法、每次工具调用及其结果）决定下一步。这与强化学习里“状态—动作—观测”的循环结构相同（见马尔可夫决策过程），只是策略是一个通过提示驱动的语言模型。

关键设计。

  • 边想边做：ReAct（2022）让模型在每次行动前先写一段推理（“我需要先查X，因为……”），推理和行动交替进行，比只推理或只行动都好。
  • 反思与重试：Reflexion让模型在失败后写下总结，作为下一次尝试的上下文。
  • 上下文管理：每轮都把输出和结果追加进去，上下文会迅速增长（见上下文窗口）。长任务需要总结旧内容、把信息写到外部文件，或把子任务交给子智能体，以免超出窗口。
  • 停止条件：模型给出最终答案、达到最大步数，或请求人类介入。

发展。2023年AutoGPT与自主智能体热潮让“给一个目标、让模型自己循环”的想法广为人知，但当时的模型很容易原地打转。随着模型更擅长使用工具，面向具体环境的智能体开始可用：SWE-agent为模型设计了专门的文件浏览和编辑命令来修复真实GitHub问题；Claude Code与终端编码智能体等终端编码智能体直接在开发者的代码仓库里读写文件、运行命令。《Building Effective Agents》总结了实践经验：先用简单的固定流程，只有确实需要时才用开放式的循环。METR任务时间跨度用“智能体能以50%成功率完成的任务、人类专家需要多长时间”来度量进展。

例子

修复一个失败的单元测试，每一行是一轮循环：

1. 想：先看哪个测试失败。行动：运行pytest。结果：test_parse失败，报错KeyError: 'date'。 2. 想：去看解析函数。行动：读取parser.py。结果：函数把字段名写成了'Date'。 3. 想：改成小写。行动：编辑第42行。结果：文件已修改。 4. 想：确认修复。行动：再次运行pytest。结果：全部通过。 5. 输出最终答案：“已修复，原因是字段名大小写不一致。”

为什么长任务难。如果每一步独立地有95%的概率做对，且任何一步出错都会导致失败，那么20步全对的概率只有0.95^20 ≈ 0.36。智能体必须能发现并纠正自己的错误（比如第4步测试仍失败时回到第2步），否则成功率随步数指数下降。

容易误解的地方

  • 智能体的“自主”取决于给它的工具和权限。权限过大的智能体在误判时可能造成真实损失，需要沙箱和人工确认。
  • 多步循环的成本远高于一次问答：每一轮都要把越来越长的上下文重新输入模型。
  • 循环本身很简单，能力主要来自模型。同一套循环，换一个更弱的模型往往就会陷入重复或偏离目标。
