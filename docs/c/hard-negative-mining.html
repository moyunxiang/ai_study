难例挖掘与难负样本

Hard Negative Mining

也叫：难例挖掘　难负样本挖掘　难负样本　hard negative mining　hard negatives　hard example mining　在线难例挖掘　OHEM　online hard example mining　半难负样本　semi-hard negatives　负样本挖掘　negative mining　批内负样本　in-batch negatives

训练时专门挑模型最容易搞错的负样本（看起来像正样本的反例）来学，而不是随机抽。随机负样本大多太简单、几乎不提供梯度，难负样本才逼模型学到细微差别。

先要会：损失函数 对比学习

检测器要学“这里没有行人”，可一张图里绝大多数位置是天空、马路，一眼就能排除；检索模型要学“这篇文档不相关”，随机抽一篇文档几乎总是毫不相关。如果负样本都这么容易，模型很快就把它们的损失降到接近0，之后的训练几乎都浪费在已经会的东西上。

难负样本是那些模型当前打分很高、但其实是负类的样本：长得像行人的电线杆、与问题用词高度重合却答非所问的段落。难例挖掘就是在训练中主动找出它们，加大它们在损失里的分量。

常见做法。

  • 离线挖掘：先用当前模型在全量数据上打分，把得分最高的负样本存下来，下一轮训练加入。传统的检测器（如HOG + SVM的行人检测）就是“训练—找误报—再训练”循环几轮。
  • 在线难例挖掘（OHEM）：每个批次里计算所有候选的损失，只对损失最大的那一部分反向传播，Fast R-CNN之后的检测器和MTCNN人脸检测用过这种方法。SSD按1:3的比例只保留最难的负样本。
  • 批内难负样本：在对比学习里，同一批次的其他样本天然是负样本；批次越大、负样本越多，越可能碰到难的。SimCLR依赖大批次，MoCo用队列存下大量历史负样本。
  • 检索中的难负样本：稠密检索DPR用BM25检索出来、但不含答案的段落作为难负样本；后来的稠密检索模型（如Contriever无监督检索、E5文本嵌入、BGE嵌入模型）普遍使用由模型自己检索出来的难负样本，见检索与向量数据库。
  • 软性加权：Focal Loss与RetinaNet的focal loss不是挑样本，而是按“模型错得多严重”连续地给每个样本加权，可以看作一种平滑的难例挖掘，见类别不平衡与长尾。

和三元组损失的关系。三元组损失（见合页损失与间隔类损失）对已满足间隔的三元组梯度为0，随机采样时绝大多数三元组都没有梯度；FaceNet与三元组损失提出在批次内选“半难”负样本：比正样本远、但仍在间隔以内的那些。

例子

一张图上有2000个候选框，其中只有20个包含物体。随机抽128个负框，其中大概只有几个与物体部分重叠、模型容易误判，其余的损失都接近0。OHEM改为计算全部1980个负框的损失，只取损失最大的那些反向传播，模型的注意力集中在真正混淆的区域。

容易误解的地方

  • 太难的负样本可能其实是假负例（标注漏了的正样本，或者确实也相关的文档），一味加大它们的权重会教坏模型；检索中常用更强的模型过滤掉疑似正例。
  • 只训练最难的样本会让训练不稳定，实践中通常与随机负样本混合使用。
