参数量、计算量与显存

Parameters, FLOPs and Memory

也叫：算力　显存占用　6ND　模型大小

在交互版中打开（看它长在树上的哪里）

衡量模型大小与成本的三把尺子：参数量（有多少个可学习的数）、计算量FLOPs（要做多少次浮点运算）、显存（运行时要占多少内存）。几条简单的估算公式就能算出大致数量级。

先要会：矩阵乘法与线性变换 浮点精度：FP32、FP16、BF16、INT8 Transformer层的结构

读AI论文时常看到“7B模型”“训练用了3×10^23 FLOPs”“需要80GB显存”。这些数字决定了一个模型要花多少钱训练、能不能在你的显卡上跑、每秒能生成多少字。会用几条经验公式自己估算，就能判断一篇论文的宣称是否合理。

参数量N。所有权重矩阵和偏置里数字的总数。一个d_in×d_out的线性层有d_in·d_out个权重。一个Transformer层约12d²个参数（见Transformer层的结构），再加上词表大小×d的嵌入矩阵。“7B”就是约70亿个参数。

计算量FLOPs。一次浮点乘法或加法算1次运算。矩阵乘法(m×k)·(k×n)需要约2mkn次（每个输出元素k次乘、k次加，见矩阵乘法与线性变换）。由此可得两条最常用的估算：

  • 推理：每处理一个token，前向传播约2N次运算（每个参数参与一次乘加）。
  • 训练：每个token约6N次——前向2N，反向传播要对输入和权重各求一次梯度，约4N。整个训练的总计算量C ≈ 6·N·D，D是训练token数。

这两条忽略了注意力分数的计算（与上下文长度有关），上下文不太长时误差不大。注意区分FLOPs（运算次数，一个总量）和FLOP/s（每秒运算次数，硬件速度）。

显存。由三部分组成：

  • 权重：N × 每个数的字节数。FP32是4字节，BF16/FP16是2字节，INT4量化后约0.5字节（见浮点精度：FP32、FP16、BF16、INT8、量化）。
  • 训练状态：用Adam混合精度训练时，每个参数要存半精度权重(2) + 半精度梯度(2) + FP32主权重(4) + Adam的两个动量(8)，合计约16字节，见ZeRO与DeepSpeed。
  • 激活值和KV缓存：与批大小、序列长度成正比，训练时要为反向传播保留中间结果，推理时要存KV缓存。

它在哪里出现。GPT-3报告了总训练计算量；语言模型的规模定律和Chinchilla用C ≈ 6ND讨论给定算力下N和D怎么分配；混合精度训练和ZeRO与DeepSpeed专门对付显存问题。混合专家让“总参数量”和“每个token的计算量”脱钩，所以讨论MoE时要分开说总参数和激活参数。

例子

GPT-3的训练计算量。N = 1750亿，D = 3000亿token：C ≈ 6 × 1.75×10^11 × 3×10^11 = 3.15×10^23次浮点运算。论文报告的数字是3.14×10^23，公式估得很准。

7B模型的显存。BF16推理时权重占7×10^9 × 2字节 = 14GB，一张24GB的消费级显卡放得下（还要留出KV缓存的空间）；量化到4比特约3.5GB。若要用Adam全量训练，仅训练状态就要7×10^9 × 16字节 = 112GB，一张80GB的卡放不下，必须多卡切分或改用参数高效微调。

生成速度的上限。7B模型每个token前向约2×7×10^9 = 1.4×10^10次运算。但单条请求逐token生成时，每一步都要把14GB权重从显存读一遍；在带宽约1TB/s的显卡上，光读权重就要约14毫秒，即每秒最多约70个token。此时瓶颈是带宽而不是算力（见显存、内存带宽与“内存墙”）。

容易误解的地方

  • 6ND是近似：没算注意力、没算重算激活带来的额外前向，也不反映硬件利用率（实际常只有峰值算力的30%–50%）。
  • “参数量”在MoE模型里有两个含义（总量与每token激活量），比较时要看清是哪一个。
  • 推理显存常被低估：长上下文时KV缓存可能比权重本身还大。
