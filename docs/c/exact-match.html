精确匹配与token级F1

Exact Match and Token-Level F1

也叫：exact match　EM　精确匹配　完全匹配　token-level F1　token级F1　SQuAD F1　问答F1　QA F1　答案规范化　answer normalization　EM/F1　严格匹配

在交互版中打开（看它长在树上的哪里）

问答评测最常用的两个指标：精确匹配（EM）要求预测答案经规范化后与标准答案完全相同；token级F1按两者共有的词数计算部分得分。有多个标准答案时取得分最高的一个。

先要会：准确率、精确率、召回率与F1

抽取式问答（见机器阅读理解）和开放域问答（见开放域问答）的答案通常是一小段文字，例如“1876年”“亚历山大·贝尔”。怎样自动判断模型答得对不对？完全按字符串比较太苛刻（“贝尔”和“亚历山大·贝尔”算全错），人工判断又太贵。SQuAD确立的EM和F1成了这类任务的标准做法。

规范化。比较之前先对预测和标准答案做同样的处理：转小写、去掉标点、去掉英文冠词（a、an、the）、合并多余空白。“The Eiffel Tower.”和“eiffel tower”规范化后相同。

精确匹配（EM）。规范化后完全一样记1分，否则0分，对所有问题取平均。

token级F1。把预测和标准答案都看成词的集合（准确说是多重集合），计算重合部分：

P = 共有词数 / 预测词数，R = 共有词数 / 标准答案词数，F1 = 2PR / (P + R)

这和分类里的F1公式一样（见准确率、精确率、召回率与F1），只是作用在一个答案内部的词上。它给“部分正确”打部分分：预测“贝尔”、标准“亚历山大·贝尔”时EM为0，F1大于0。

多个标准答案。一个问题常由几位标注者给出几个答案，计分时对每个标准答案分别算EM和F1，取最大值。

中文。中文没有空格，一般按字计算F1，或先分词再算。

在哪里出现。SQuAD、SQuAD 2.0、Natural Questions、TriviaQA、HotpotQA多跳问答等问答基准都报告EM和F1。在大模型评测里，数学题、选择题也常用“抽取最终答案后精确匹配”的方式打分，抽取通常靠正则表达式。

局限。它们只看字面：“1876年”与“一八七六年”、“美国”与“美利坚合众国”会被判错；生成式模型的回答越来越长、越来越口语化，EM会严重低估正确率。于是出现了用模型判断语义等价的做法（见LLM当裁判），以及要求模型按固定格式输出最终答案的评测协议。

例子

标准答案：“the Eiffel Tower in Paris”。规范化后为 [eiffel, tower, in, paris]（4个词）。

  • 预测“Eiffel Tower”→ [eiffel, tower]。EM = 0；共有2个词，P = 2/2 = 1，R = 2/4 = 0.5，F1 = 2×1×0.5/1.5 ≈ 0.67。
  • 预测“The Eiffel Tower in Paris.”→ 规范化后完全相同，EM = 1，F1 = 1。
  • 预测“Louvre”→ EM = 0，F1 = 0。

若同一问题还有另一个标准答案“Eiffel Tower”，第一个预测的EM取两者最大值，变为1。

容易误解的地方

  • 规范化规则不同，分数就不同；比较不同论文的EM时要确认用的是同一套评测脚本。
  • 模型输出带解释的长回答时，即使包含正确答案，EM也是0，需要先抽取答案再比较。
