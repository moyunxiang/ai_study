实体链接

Entity Linking

也叫：entity linking　实体链接　实体消歧　entity disambiguation　named entity disambiguation　NED　Wikification　维基化　实体对齐到知识库　mention　提及

在交互版中打开（看它长在树上的哪里）

把文本中提到的名字（如“苹果”“乔丹”）对应到知识库里一个确定的条目上。它解决同名不同物、同物不同名的问题，是把文本接入知识图谱的关键一步。

先要会：嵌入向量 检索与向量数据库

命名实体识别只告诉我们“乔丹”是一个人名，却不知道是篮球运动员迈克尔·乔丹，还是机器学习学者迈克尔·乔丹。反过来，“特朗普”“川普”“第45任美国总统”指的是同一个人。要把文本里的信息汇总到知识库里，或者用知识库帮助理解文本，就必须先确定每个提及（mention）到底指哪个实体。这就是实体链接（entity linking），也叫实体消歧、Wikification（链接到维基百科条目）。

流程。

1. 提及识别：找出文本中指代实体的片段，通常借助NER。 2. 候选生成：根据别名词典（来自维基百科的重定向页、锚文本等）为每个提及列出可能的实体。“苹果”的候选有苹果公司、水果苹果、苹果唱片等。 3. 候选排序：结合上下文挑出最合适的一个。主要线索有三类：

  • 先验流行度：在大量锚文本里，“苹果”被链接到各个条目的频率。
  • 上下文相似度：提及周围的词和候选实体描述的相似度，如“发布了新款手机”更像苹果公司。
  • 全局一致性：同一篇文章里的实体彼此相关，“乔丹”与“公牛队”“NBA”一起出现时，更可能是运动员。

4. NIL判定：知识库里没有对应条目时，要能输出“无对应实体”，而不是硬选一个。

方法。传统系统用人工特征加排序模型；神经方法用一个编码器把“提及+上下文”和每个实体的描述分别编码成向量，先用向量检索粗召回候选，再用一个更精细的模型重排序（与交叉编码器与重排序的两阶段思路相同）。

用在哪里。知识图谱和信息抽取要把抽取出的关系挂到确定的实体上；搜索引擎在Google知识图谱上展示实体卡片；知识库Wikidata、Freebase、DBpedia是常用的链接目标。在检索增强生成中，把问题里的实体链接到知识库，也能帮助找到更准确的资料。它和指代消解相关但不同：指代消解在文本内部把“他”“乔丹”归为同一实体，实体链接把这个实体对应到文本外部的知识库条目。

例子

句子：“乔丹在伯克利研究统计机器学习。”

候选：迈克尔·乔丹（篮球运动员）先验0.85，迈克尔·I·乔丹（学者）先验0.10，其他0.05。

上下文中“伯克利”“统计机器学习”与学者条目的描述高度相似，与运动员条目几乎无关。把先验和上下文得分综合后，学者得分反超，系统输出“迈克尔·I·乔丹”。如果只看先验，就会链接错。

容易误解的地方

  • 实体链接的上限很大程度取决于候选生成：正确实体没进候选列表，排序再好也没用。
  • 新出现的实体（新公司、新人物）不在知识库里，系统必须能输出NIL，否则会被强行链接到一个旧实体上。
