语种识别

Language Identification

也叫：language identification　语种识别　语言识别　语言检测　language detection　LID　langid　lang detect　fastText语种识别　lid.176　文本语种判断　spoken language identification

在交互版中打开（看它长在树上的哪里）

判断一段文本是用哪种语言写的。常用字符n-gram统计或fastText这类轻量分类器，几毫秒就能给出结果；它是多语言数据处理、机器翻译和搜索的第一道工序。

先要会：n-gram与平滑 监督学习

从网页抓取的文本混着几百种语言。要训练中文模型，先得把中文网页挑出来；要做翻译，先得知道源语言是什么；搜索引擎要把结果按用户的语言排序。所有这些都需要语种识别（language identification，LID）。

为什么字符n-gram很有效。不同语言的字符组合差异明显：英语常见“th”“ing”，德语常见“sch”“ung”，法语常见“eau”“ion”。对每种语言统计字符n-gram（例如1到4个字符）的频率分布，新文本的n-gram分布与哪种语言最接近，就判为哪种（见n-gram与平滑；也可以用朴素贝叶斯分类式的概率模型）。这种方法不需要分词，对任何书写系统都适用，经典工具几十年前就能在长文本上做到很高的准确率。

今天的常用工具。fastText的语种识别模型用字符n-gram的嵌入加一个线性分类器，支持一百多种语言，速度极快，是大规模语料处理的标准工具：CCNet、RefinedWeb、FineWeb / FineWeb-Edu等网页语料的流水线都用它按语言分流（见预训练语料的清洗、过滤与去重）。NLLB两百种语言翻译为它覆盖的两百种语言专门训练了识别器；FineWeb2多语种则借助覆盖上千种语言的识别器处理多语种网页。

难点。

  • 短文本：一条推文、一个搜索查询只有几个词，统计信息不足，准确率明显下降。
  • 相近语言：塞尔维亚语与克罗地亚语、印尼语与马来语、西班牙语与加利西亚语，字符分布高度相似。
  • 混合语言：一句话里中英混用（见多语言模型与跨语言迁移中的语码转换），或者网页正文是一种语言、导航栏是另一种。
  • 低资源语言：训练数据少，识别器容易把它们误判为相近的大语种，导致这些语言在语料中被进一步低估。
  • 同一语言的不同书写：用拉丁字母书写的印地语、阿拉伯语方言，与标准书写形式差别很大。

语音。从音频判断语种是另一个相关任务，Whisper这类语音模型在转写前会先预测语种。

例子

三段文本的字符trigram特征：

  • “the weather is nice”：含“the”“eat”“her”，在英语模型下得分最高。
  • “das Wetter ist schön”：含“sch”“chö”，判为德语。
  • “天气很好”：汉字字符直接指向中文；但如果只有两个字“日本”，中文和日文都有可能，需要更多上下文。

一个fastText语种识别模型对“das Wetter ist schön”输出：德语0.98、荷兰语0.01……（概率为示意），取最高者。

容易误解的地方

  • 语料处理中常设置置信度阈值，低于阈值的文本被丢弃；阈值过高会系统性地删掉短文本和混合语言文本。
  • 识别器把文本判为某语言，不代表文本质量好，乱码和机器翻译的垃圾文本也会被正常识别。
