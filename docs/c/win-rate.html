胜率与成对评测

Win Rate and Pairwise Evaluation

也叫：win rate　胜率　对战胜率　pairwise win rate　成对评测　pairwise evaluation　head-to-head　LC win rate　长度控制胜率　length-controlled win rate　AlpacaEval　长度偏差　length bias　verbosity bias　冗长偏差　位置偏差（评审）

在交互版中打开（看它长在树上的哪里）

开放式生成的常用评测指标：把待测模型和一个基准模型在同一批提示上的回答两两比较，由人或评审模型判断哪个更好，待测模型胜出的比例就是胜率。平局常按半场胜计。

先要会：Elo评分与两两比较 基准、排行榜与SOTA

写作、对话、建议这类任务没有标准答案，精确匹配与token级F1这样的指标用不上，打绝对分（1到10分）又很难在不同评审之间保持一致。比较两个回答哪个更好，则容易得多、也稳定得多。胜率（win rate）就是基于成对比较的指标。

定义。准备一组提示，待测模型A和参照模型B各回答一遍，对每个提示判断A胜、B胜还是平局：

win rate = (A胜的次数 + 0.5 × 平局次数) / 总数

50%表示两者相当。评判者可以是人，也可以是强模型（见LLM当裁判）。

常见基准。AlpacaEval把待测模型与一个固定的参照模型比较、用GPT-4当评审计算胜率；Arena-Hard挑选难题并用模型评审；LLM-as-a-Judge与MT-Bench系统研究了用模型当评审的可靠性。胜率与Elo评分是一回事的两种表达：Chatbot Arena汇总大量人类的两两投票，再用Bradley–Terry模型换算成排行榜分数（见Elo评分与两两比较、竞技场式人类偏好评测）。

评审的偏差。

  • 长度偏差：评审（尤其是模型评审）倾向于偏爱更长、更详细的回答。模型只要把回答写长，胜率就会上涨。AlpacaEval长度控制提出“长度控制胜率”：用回归估计长度差对胜负的影响，再把它去掉，报告“在长度相同的条件下”的胜率。
  • 位置偏差：评审偏好先出现或后出现的那个回答。常用做法是每对比较两次、交换顺序，结果不一致就记为平局。
  • 自我偏好：模型评审可能偏爱与自己风格相近（或同家族模型）的回答。

和训练的关系。胜率与RLHF的训练信号形式相同，都来自成对偏好（见偏好数据）。所以用胜率评测一个被偏好数据优化过的模型时，要警惕它学会的是“讨评审喜欢”，而不是真正变好（见刷榜与古德哈特效应）。

例子

100个提示，模型A对参照模型B：A胜52次、B胜30次、平局18次。

win rate = (52 + 0.5 × 18) / 100 = 61%

交换位置再比一遍，若有10对的结论翻转，把它们改记为平局，胜率会相应下降。再看长度：A的回答平均比B长60%，长度控制后胜率降到54%，说明有一部分“胜利”来自写得更长。

容易误解的地方

  • 胜率依赖参照模型：对弱参照的90%胜率和对强参照的55%胜率不能直接比较。
  • 样本量小时胜率波动很大，100个提示下几个百分点的差异可能不显著（见方差、种子与统计显著性）。
