数据加载流水线

Data Loading Pipelines

也叫：数据加载　data loading　数据加载流水线　data loading pipeline　输入流水线　input pipeline　DataLoader　数据预取　prefetch　prefetching　num_workers　数据分片　data sharding　WebDataset　tf.data　packing　序列拼接　锁页内存　pinned memory　数据瓶颈

在交互版中打开（看它长在树上的哪里）

把训练数据从磁盘读出、解码、增强、打乱、拼成批次并送上GPU的那条流水线。它若跟不上GPU的速度，再快的显卡也只能空等；常用多进程读取、预取、分片存储等手段来避免成为瓶颈。

先要会：批大小、步数与轮数 CPU、GPU与并行计算

训练循环看起来只有“取一批数据→前向→反向→更新”，但“取一批数据”背后可能很重：从网络存储读几百张JPEG、逐张解码、随机裁剪翻转（见数据增强）、归一化、拼成张量、拷到显存。GPU算一步只要几十毫秒，数据准备若要更久，GPU利用率就会掉到一半以下。

一条典型的流水线。

  • 读取：从本地盘、网络文件系统或对象存储读出原始字节。
  • 解码与变换：图像解码、音频重采样（见波形、频谱与梅尔谱）、文本分词（见分词与token），以及各种增强。
  • 打乱与组批：按随机顺序组成批次；变长序列需要填充或把多条短序列拼接成定长（packing），见批大小、步数与轮数。
  • 传输：拷贝到GPU，使用锁页内存可以让拷贝与计算重叠。

常用加速手段。

  • 多进程并行：PyTorch的DataLoader用多个worker进程同时准备不同的批次，绕开Python的全局解释器锁。
  • 预取：在GPU计算当前批次时提前准备下几个批次，让数据准备与计算重叠。
  • 把小文件打包成分片：上百万个小文件的随机读取非常慢，把它们打包成较大的顺序文件（如tar分片），按分片顺序读取、在缓冲区内局部打乱。
  • 把计算搬到GPU上：图像解码和增强也可以在GPU上做。
  • 预处理一次、反复使用：大模型预训练通常事先把文本分好词、存成连续的token数组（TensorFlow的tf.data等框架也提供类似的流水线工具），训练时直接按偏移读取。

分布式训练中。每个数据并行进程必须读到互不重叠的数据子集，每轮重新打乱时要用相同的随机种子保证全局一致；从检查点恢复时要回到正确的数据位置，否则会重复或跳过数据，见模型检查点与容错训练和分布式训练：数据并行与模型并行。大规模训练系统（如MegaScale万卡训练与容错）也把数据流水线列为需要专门优化的环节。

怎样判断是不是数据瓶颈。把模型换成什么都不做的空操作，只跑数据加载，看每秒能产出多少批；或者用性能分析工具看GPU在每步之间是否有明显空闲。

例子

8张GPU训练图像分类，每张卡每步处理256张图、耗时0.1秒，全机每秒需要约2万张图。若单个CPU核每秒只能解码并增强约200张JPEG，就需要约100个核同时工作；机器只有64核时，数据准备就成了瓶颈，GPU利用率最多约60%。改为GPU解码或降低增强的开销后瓶颈才会消失。数字为示意。

容易误解的地方

  • worker进程太多会争抢CPU和内存带宽，反而变慢；数量需要实测调整。
  • 只在缓冲区内局部打乱时，若数据在存储中按类别或来源排好了序，批次就不够随机，可能影响训练。
