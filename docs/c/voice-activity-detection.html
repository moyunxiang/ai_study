语音活动检测与端点检测

Voice Activity Detection and Endpointing

也叫：语音活动检测　voice activity detection　语音端点检测　端点检测　endpointing　endpoint detection　静音检测　silence detection　语音检测　speech detection　话轮检测　turn detection　turn-taking　挂起时间　hangover

逐帧判断一段音频里“此刻有没有人在说话”。它是语音系统的第一道关卡：决定什么时候开始识别、用户什么时候说完（端点检测），以及把长录音切成可处理的片段。

先要会：波形、频谱与梅尔谱 准确率、精确率、召回率与F1

语音助手一直开着麦克风，但只有用户说话时才该处理；电话录音有大段静音和噪声；长达几小时的会议录音需要切成一段段送进识别模型。这些都需要先回答一个简单的问题：这一帧是语音还是非语音？这就是语音活动检测（VAD）。

基本做法。把音频切成10到30毫秒的帧（见波形、频谱与梅尔谱），对每帧做二分类，再做平滑。

  • 能量与过零率：语音段能量高，最简单的VAD就是能量超过阈值。噪声大时很容易误判。
  • 统计模型：用高斯混合模型分别建模语音和噪声的频谱特征，按似然比判决，常见的开源实时VAD多属此类。
  • 神经网络：用小型卷积或循环网络在大量带噪数据上训练，对噪声、音乐、多人说话更鲁棒，是现在的主流。

平滑与延迟。逐帧结果会抖动：一个词中间的短暂停顿不应被切开。常用“挂起”策略：检测到语音后，要连续若干帧非语音才判定说话结束。挂起时间越长越不容易误切，但用户说完后系统的反应也越慢。

端点检测与轮流说话。对话系统最关心“用户说完了没有”（endpointing）。只看静音时长会在用户思考停顿时抢话，或在用户早已说完时迟迟不回应。级联式语音智能体（见语音智能体与级联管线）高度依赖VAD来决定何时把语音交给识别和语言模型；GPT-4o全模态实时模型、Moshi全双工语音对话这类端到端或全双工模型（见全双工语音对话）则尝试让模型自己决定何时开口、何时让出话轮。

其他用途。长音频转写先用VAD切段再识别，例如WhisperX长音频转写；说话人日志的第一步也是找出有语音的区间，pyannote.audio工具包中包含这一模块。噪声鲁棒性的评测可见CHiME噪声环境语音挑战等挑战。

例子

帧长20毫秒，挂起时间设为300毫秒（15帧）。用户说“帮我订明天……（停顿200毫秒）……早上的票”，停顿只有10帧，不足15帧，VAD不会切断；说完后再等300毫秒确认结束，于是系统至少有0.3秒的额外延迟。把挂起改为100毫秒，延迟变小，但句中停顿会被误判为说完。

容易误解的地方

  • VAD只判断有没有人声，不判断是谁在说、说给谁听；电视里的说话声同样会触发它。
  • 用干净录音调好的阈值在嘈杂环境里常常失效，部署前应在目标场景的噪声下重新评估。
