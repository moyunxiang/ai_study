端到端学习

End-to-End Learning

也叫：E2E　end2end　一体化模型　无需手工特征

在交互版中打开（看它长在树上的哪里）

不把任务拆成多个由人分别设计和训练的模块，而是用一个模型直接从原始输入映射到最终输出，所有部分针对最终目标一起训练。

先要会：反向传播 特征与表示学习 监督学习

传统的AI系统通常是流水线：把一个大任务拆成多个子任务，每个子任务由专门的模块完成，模块之间的接口由人设计。例如经典的语音识别：从波形提取手工声学特征，声学模型（HMM-GMM）把特征映射为音素，发音词典把音素拼成词，语言模型再选出最可能的词序列。自动驾驶类似：感知、预测、规划、控制分开。

流水线的好处是每个模块可以单独开发和调试；坏处是：

  • 每个模块只优化自己的局部目标，局部最优之和不等于整体最优。
  • 中间表示由人定义，可能丢掉了下游需要的信息。
  • 误差会逐级累积，前一级的错误后一级无法纠正。

端到端学习用一个可微分的模型直接从原始输入（像素、波形）映射到最终输出（转写文字、方向盘角度），用反向传播针对最终的损失函数联合训练所有部分。中间表示不再由人规定，而是作为特征与表示学习自动学出来。

发展脉络：ALVINN端到端驾驶（1989）已经用一个小型神经网络从摄像头图像直接输出转向。深度学习之后端到端成为主流：Deep Speech端到端识别用一个网络从频谱直接输出字符，取代了复杂的语音识别流水线；机器人领域也出现了直接从图像输出电机指令的视觉运动策略；端到端自动驾驶和Tesla FSD v12端到端把这一思路用到了自动驾驶。

代价：端到端模型需要大量“输入—最终输出”的配对数据；中间过程不可见，出错时难以定位；无法直接复用已有的模块化知识。所以实践中常采用折中方案，比如UniAD端到端规划保留了模块的结构，但让它们共同针对规划目标训练。

例子

一个三模块流水线，假设每个模块的正确率都是95%，且错误相互独立、下游无法纠正前面的错：整体正确率只有0.95³ ≈ 85.7%。端到端模型没有固定的中间接口，每个部分都直接为最终输出服务，不存在这种逐级相乘的损失（当然，它自身仍会犯错）。

容易误解的地方

  • “端到端”是一个相对说法：几乎每个系统都仍有一些固定的前后处理（分词、图像缩放），不存在绝对的端到端。
  • 端到端不一定更好：数据不够、或者中间监督信号很容易获得时，模块化的系统可能更可靠，也更容易验证安全性。
