多选题评测：似然打分与字母作答

Multiple-Choice Evaluation by Likelihood

也叫：log-likelihood scoring　似然打分　对数似然评测　多选题评测　multiple-choice evaluation　MC评测　cloze formulation　完形式评测　MCF　选项字母打分　acc_norm　长度归一化准确率　选项概率比较　rank classification

多选题评测的一种做法：不让模型自由作答，而是计算每个候选答案在模型下的（对数）概率，选概率最高的那个。另一种做法是让模型生成选项字母再比对。两种方法得到的分数可能差别很大。

先要会：困惑度 基准、排行榜与SOTA

MMLU、HellaSwag这类基准都是选择题。让模型做选择题，有两种主要的打分方式，lm-eval可复现评测等评测工具都同时支持。

方式一：似然打分。把题目作为前缀，对每个选项分别计算“前缀之后接上这个选项文本”的对数概率（见token对数概率（logprobs））：

score(选项i) = Σ_t log p(选项i的第t个token | 题目, 选项i的前t−1个token)

选得分最高的选项。不需要模型按格式输出，GPT-3论文的少样本评测和HellaSwag等补全式任务都这样做，基座模型也能直接用。

长度问题。选项越长，累加的负对数概率越多，长选项天然吃亏。常用的修正：

  • 按token数归一化：score / token数。
  • 按字符或字节数归一化（与分词无关，见每字节比特与每字符比特）。
  • 除以“无条件概率”：log p(选项 | 题目) − log p(选项 | 无关前缀)，消除某些选项本身就很常见的影响（与先校准再用的思路相近）。

方式二：生成选项字母。把选项用A、B、C、D列出来，让模型输出字母，再比较“A”“B”“C”“D”四个token的概率，或者直接解析生成的文本。MMLU的常见评测方式是这种。它更接近用户实际的用法，但要求模型理解“用字母作答”的格式；小模型或基座模型可能在这上面表现很差，即使它“知道”答案。

两种方式会给出不同结论。同一个模型，用似然打分和用字母作答，准确率可能相差很多；不同论文用不同方式，分数就没法直接比较。字母作答还会受选项顺序和字母位置偏好的影响（见提示敏感性）。

对话模型的评测。推理模型和对话模型通常要先写一段推理再给出答案，似然打分不再适用，于是越来越多地采用“生成完整回答 → 抽取最终答案 → 精确匹配”的方式（见精确匹配与token级F1），MMLU-Pro等新基准也增加了选项数并鼓励思维链作答。

例子

题目：“水在标准大气压下的沸点是多少？”选项：A. 100摄氏度 B. 50摄氏度。

  • 似然打分：log p(“100摄氏度” | 题目) = −2.1，log p(“50摄氏度” | 题目) = −6.4，选A。
  • 若选项A改成“100摄氏度，这是在海平面附近测得的”（12个token，总对数概率−9.0），不归一化时得分−9.0低于B的−6.4，会错选B；按token数归一化后A为−0.75、B（5个token）为−1.28，又选回A。
  • 字母作答：提示末尾“答案：”，比较下一个token为“A”和“B”的概率，0.92对0.05，选A。

容易误解的地方

  • 报告多选题分数时要说明用的是哪种打分方式、是否归一化、几个示例，否则数字不可比。
  • 似然打分只能衡量“模型更倾向哪个选项”，不能反映模型能否在开放式问题中生成正确答案。
