PnP：由二维–三维对应求相机位姿

Perspective-n-Point

也叫：PnP　PnP问题　Perspective-n-Point　perspective-n-point problem　P3P　EPnP　相机位姿估计　camera pose estimation　绝对位姿估计　absolute pose estimation　重投影误差　reprojection error　solvePnP　solvePnPRansac　二维三维对应　2D-3D correspondence　视觉定位　visual localization　外参估计　extrinsic estimation

已知若干三维点的坐标、它们在图像中的投影位置和相机内参，求相机的旋转和平移。最少需3个点（P3P），实践中常用EPnP加RANSAC，再做非线性优化。

先要会：相机模型与多视图几何 位姿与齐次变换SE(3)

增强现实要知道手机相机此刻在房间里的什么位置，才能把虚拟物体“放”在桌面上；机器人看到一个已知形状的零件，要算出零件相对相机的位姿才能去抓；视觉定位要在一张已有的三维地图中找到当前照片是从哪里拍的。这些问题都归结为PnP。

问题描述。输入：n个三维点P_i（世界坐标系或物体坐标系），它们在图像中的像素位置p_i，以及相机内参K（见相机模型与多视图几何）。求旋转R和平移t，使投影尽量吻合：

p_i ≈ π(K·(R·P_i + t))

π表示除以深度的透视投影。位姿有6个自由度（见位姿与齐次变换SE(3)），每个点提供2个约束，所以理论上至少需要3个点。

主要解法。

  • P3P：3个点的闭式解，最多有4组解，需要第4个点来消除歧义；适合放进RANSAC做最小样本求解。
  • DLT（直接线性变换）：把投影矩阵的12个元素当作未知数，用至少6个点解线性方程组，再从中提取R和t，简单但不保证R是严格的旋转矩阵（见正交矩阵与正定矩阵）。
  • EPnP：把所有三维点表示成4个虚拟控制点的加权组合，只求这4个控制点在相机坐标系下的坐标，复杂度与点数成线性，是OpenCV等库中的常用选项。
  • 非线性精化：以上解作为初值，最小化重投影误差Σ‖p_i − π(K(RP_i + t))‖²，用Gauss–Newton或Levenberg–Marquardt迭代（见牛顿法与拟牛顿法），这一步本质上是只优化相机位姿的光束平差综述。
  • 鲁棒性：二维–三维匹配中常有大量错误匹配，PnP几乎总是套在RANSAC中使用。

它出现在哪里。

  • 视觉SLAM与视觉里程计：ORB-SLAM等系统在跟踪阶段，用已有地图点与当前帧特征点的匹配求PnP，得到当前相机位姿（见SLAM的基本概念：里程计、后端优化与回环）。
  • 视觉定位：先用全局描述子（如NetVLAD地点识别）检索相似图像，再用局部特征建立二维–三维匹配，最后求PnP。
  • 相机标定与标志物：张正友标定法用平面棋盘格求内外参；AR里的二维码标志物（ArUco、AprilTag）检测出四个角点后直接求PnP。
  • 物体6D位姿估计：许多方法先用神经网络预测物体关键点或稠密的二维–三维对应，再用PnP解出位姿（见姿态估计）。

例子

一张A4纸（210mm×297mm）平放在桌上，四个角在纸面坐标系中的坐标已知：(0, 0, 0)、(210, 0, 0)、(210, 297, 0)、(0, 297, 0)。在照片中检测到四个角的像素坐标，已知手机相机内参，PnP就能算出相机相对纸面的旋转和距离，例如“相机在纸面正上方约40厘米、倾斜30°”。这就是AR应用把虚拟物体稳稳放在纸上的方法。（数字为示意）

容易误解的地方

  • 点几乎共线、或只覆盖图像一小块区域时，解对噪声极其敏感，深度方向的误差尤其大。
  • 内参不准（尤其是焦距和畸变）会直接转化为位姿误差，必须先标定好相机。
