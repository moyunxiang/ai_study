弱监督与数据编程

Weak Supervision and Data Programming

也叫：弱监督　弱监督学习　weak supervision　weakly supervised learning　weakly supervised　数据编程　data programming　标注函数　labeling functions　启发式标注　heuristic labeling　不精确监督　不准确监督　不完全监督　弱标签　weak labels　程序化标注　programmatic labeling

用比人工逐条标注便宜、但不完全准确或不够精细的信号训练模型：启发式规则、知识库自动对齐、网页话题标签、粗粒度的整体标签。代价是标签有噪声，需要专门的聚合与纠正方法。

先要会：监督学习 标签噪声与带噪学习

高质量的人工标注昂贵、慢，还需要领域专家。很多时候我们手里有的是“差不多对”的信号：一条正则规则、一个知识库、用户随手打的标签、只有整体结论的报告。弱监督就是想办法用这些信号来训练模型。它通常分三类：

  • 不完全监督：只有一小部分数据有标签，见半监督学习与伪标签和主动学习。
  • 不精确监督：标签粒度比要预测的粗，例如只有图片级标签却要做检测，见多示例学习与弱监督。
  • 不准确监督：标签本身有错，见标签噪声与带噪学习。

标注函数与数据编程。Snorkel弱监督让领域专家写一批“标注函数”：小段规则或启发式（“邮件里出现‘中奖’就判为垃圾邮件”“两个药名之间出现‘与……合用’就判为相互作用”），每个函数可以投票或弃权。各函数准确率不同、彼此还可能相关，Snorkel用一个生成模型在没有真实标签的情况下估计每个函数的可靠性，再把投票合成概率化的标签，用来训练最终的判别模型。

远程监督。远程监督关系抽取用知识库自动标注文本：知识库里有“A的创始人是B”，就把所有同时提到A和B的句子标为“创始人”关系。量很大，但很多句子其实不表达这个关系，于是需要多示例远程监督那样的多示例方法来降噪。

网络规模的弱标签。Instagram弱监督预训练用Instagram上用户打的35亿张图片的话题标签做预训练，标签很不可靠，但规模带来的收益超过了噪声的损害；CLIP用网页上图片配的alt文本做对比学习（见对比学习），本质上也是把海量弱配对当作监督。这条路线后来演变为“用大规模弱监督或自监督预训练，再用少量干净数据微调”（见预训练与微调和自监督学习）。

用大模型当标注员。今天常见的做法是让大模型按提示给数据打标签或打分，再用于训练更小的模型或过滤数据，这同样是弱监督：便宜、量大，但带着大模型自身的偏差和错误（见用模型筛选预训练数据）。

例子

垃圾邮件分类，写3个标注函数：LF1“含‘中奖’则垃圾”（覆盖10%的邮件，准确率90%），LF2“发件人在通讯录则正常”（覆盖40%，准确率95%），LF3“含3个以上链接则垃圾”（覆盖15%，准确率70%）。一封含“中奖”、有5个链接、发件人不在通讯录的邮件得到两票“垃圾”；聚合模型根据估计的准确率给出约97%的垃圾概率，作为训练标签。（数字为示意）

容易误解的地方

  • 弱标签的系统性偏差（例如规则只覆盖某种写法）会被模型学走，在规则没覆盖到的情况下表现很差；评测必须用独立的人工标注数据。
  • 标注函数之间高度相关时，简单多数投票会重复计算同一信息，夸大置信度。
