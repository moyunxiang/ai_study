解码：贪心、束搜索、温度与top-p

Decoding: Greedy, Beam, Temperature, Top-p

也叫：beam search　greedy decoding　贪心解码　top-k　nucleus sampling　核采样

在交互版中打开（看它长在树上的哪里）

语言模型每一步只给出下一个token的概率分布，解码策略决定从中选哪个：总选最大的（贪心）、同时保留几条候选（束搜索），或按调整过的分布随机抽取（温度、top-k、top-p）。

先要会：Softmax与logits 自回归生成 随机变量与概率分布

语言模型本身不“说话”，它只在每一步输出词表上的一个概率分布。把分布变成具体文字的规则叫解码。同一个模型配不同的解码策略，输出可能从呆板重复变成胡言乱语，所以解码是生成质量的重要组成部分（见自回归生成）。

贪心解码。每一步都选概率最大的token。确定、简单，但目光短浅：当前最好的选择可能把后面引入死胡同；而且容易陷入重复循环。

束搜索（beam search）。同时保留概率最高的B条部分序列（B叫束宽，常取4到10）。每一步把每条序列扩展所有可能的下一个token，再按整条序列的累积对数概率保留前B条。它更接近“整句概率最大”的目标，是机器翻译、语音识别等有标准答案任务的常用方法（Seq2Seq就用了它）。

随机采样。按模型给出的分布随机抽一个token。开放式写作和对话需要多样性，这时“概率最大的句子”反而平淡乏味、甚至不断重复。核采样Top-p的研究显示，束搜索生成的长文本明显比人类文本重复。但完全按原分布采样又会偶尔抽到长尾里很离谱的词。于是有几种对分布的修剪：

  • 温度：p_i ∝ exp(z_i / T)，z是logits（见Softmax与logits）。T < 1让分布更尖锐、更保守，T → 0就退化为贪心；T > 1更平坦、更随机。
  • top-k：只保留概率最大的k个token，重新归一化后再采样。
  • top-p（核采样）：按概率从大到小累加，保留累计概率刚好达到p（如0.9）的最小集合，再归一化采样。分布很尖锐时可能只剩一两个候选，分布平坦时会保留很多——比固定的k更自适应。

实际产品常把温度和top-p组合使用。

它在哪里出现。GPT-2的生成样例用了top-k采样；自洽性采样故意用较高温度采样多条推理路径再投票；推测解码不改变采样结果的分布，只用一个小模型加速。约束解码（如约束解码Outlines）在每一步把不符合语法（比如非法JSON）的token概率直接置零。

例子

某一步下一个token的分布是：A 0.5、B 0.2、C 0.15、D 0.1、E 0.05。

  • 贪心：选A。
  • top-k，k = 2：保留A、B，归一化后A ≈ 0.714、B ≈ 0.286。
  • top-p，p = 0.8：累加0.5 → 0.7 → 0.85，到C时首次达到0.8，保留A、B、C，归一化后约为0.588、0.235、0.176。D和E不可能被选中。

贪心为什么会错过更好的句子。两步生成：第一步A的概率0.6、B 0.4。选了A后，第二步最大的选项概率只有0.4，整句0.6 × 0.4 = 0.24；选B后第二步有一个0.9的选项，整句0.4 × 0.9 = 0.36。贪心得到0.24的句子；束宽为2的束搜索在第一步同时保留A和B，最终找到0.36的那条。

容易误解的地方

  • 温度为0不一定完全确定：GPU上浮点运算顺序不同可能让并列或接近的logits选出不同token（见批不变性与确定性推理）。
  • 束宽不是越大越好：在翻译中，束宽过大反而可能找出很短或空的译文，因为模型给短句的累积概率更高。
  • 解码策略不能弥补模型本身的缺陷；如果正确答案在模型分布里概率很低，任何解码都很难稳定地选中它。
