指令微调与对话模板

Instruction Tuning and Chat Templates

也叫：SFT　监督微调　supervised fine-tuning　chat template　指令跟随

在交互版中打开（看它长在树上的哪里）

用大量“指令—理想回答”的样本继续训练预训练好的语言模型，让它从“续写文本”变成“按要求完成任务”。对话模板规定了多轮对话怎样排成一串token。

先要会：预训练与微调 语言模型 交叉熵 分词与token

预训练得到的语言模型只会续写。给它“请写一首关于秋天的诗”，它可能接着写“请写一首关于冬天的诗”，因为网页上的作业题列表就长这样。要让模型把输入当作要完成的任务而不是要续写的文本，需要再教一次。

定义。收集成对的数据：指令（可带输入材料）和期望的回答。用它们对预训练模型做监督微调（SFT，见预训练与微调）。损失仍是下一个token的交叉熵，但通常只在回答部分计算：指令部分是给定的条件，不要求模型学会生成它。

数据从哪来。

  • 把已有NLP数据集改写成自然语言指令：指令微调FLAN和T0多任务提示训练把几十个数据集套上多种指令模板，发现在多种任务上训练后，模型对没见过的任务的零样本表现明显提高。
  • 人工撰写：InstructGPT与RLHF请标注员写示范回答，作为RLHF之前的第一步。
  • 让强模型生成：Self-Instruct让模型自己扩写指令；Alpaca与廉价指令微调用这种方法生成了5.2万条数据，以几百美元的成本微调出一个能对话的LLaMA。
  • LIMA少即是多用约1000条精选样本就得到了不错的效果，提出模型的知识主要来自预训练，指令微调主要教会的是格式和风格。

对话模板。模型最终只认一串token（见分词与token），多轮对话必须按固定格式拼起来，用特殊token标明每一段是谁说的。例如ChatML风格：

<|im_start|>system\n你是一个助手<|im_end|>\n<|im_start|>user\n1+1等于几？<|im_end|>\n<|im_start|>assistant\n等于2。<|im_end|>

推理时，应用把对话历史按模板排好，在末尾加上“assistant开始”的标记，让模型续写，直到生成结束标记。系统提示、工具调用的结果（见工具调用）也都按模板放进去。每个模型家族的模板不同，用错模板会明显降低效果。

指令微调通常之后还会接一步偏好优化（见人类反馈强化学习），让回答不仅格式正确，而且更有用、更安全。

例子

一条训练样本。指令“把‘早上好’翻译成英文”，回答“Good morning.”。按模板拼接后假设共30个token，其中前24个是模板标记和指令，后6个是回答和结束标记。

训练时30个位置都参与前向计算，但损失只在最后6个位置上计算并取平均。如果在全部30个位置上算损失，模型也会被训练去“生成用户的问题”，这通常没有好处。

指令微调前后的区别。输入“法国的首都是哪里？”

  • 预训练模型可能续写成：“德国的首都是哪里？意大利的首都是哪里？”（像一份题目列表）
  • 指令微调后的模型回答：“法国的首都是巴黎。”

容易误解的地方

  • 指令微调教的主要是“怎么回答”，很难教会模型预训练中没有的知识；用它灌输新知识效果有限，还可能加重幻觉。
  • 用强模型生成的数据做微调，学到的往往是风格而非能力（见模仿闭源模型的假象）。
  • 对话模板里的特殊token必须与训练时完全一致，多一个换行都可能影响输出。
