pass@k

pass@k

也叫：pass@k　pass@1　pass@10　pass at k　passk　通过率　unbiased pass@k estimator　pass@k无偏估计　maj@k　cons@k　覆盖率（重复采样）　coverage

在交互版中打开（看它长在树上的哪里）

代码和数学评测的常用指标：对每道题让模型生成k个答案，只要其中至少一个通过测试就算解出，pass@k是解出题目的比例。pass@1近似“一次答对”的概率，k越大越反映模型的潜力上限。

先要会：随机变量与概率分布 解码：贪心、束搜索、温度与top-p

代码生成很难用文本相似度评测：两段写法完全不同的代码可能都对，只差一个字符的代码可能是错的。Codex的论文提出用单元测试判断对错，并定义了pass@k：每道题采样k个程序，有一个通过全部测试就算这道题解决了。

为什么要k。模型输出是随机采样的（见解码：贪心、束搜索、温度与top-p），只采一次结果波动很大。实际使用中，用户也可能让模型多试几次、挑能运行的那个。pass@k衡量的是“给k次机会能不能做对”。

无偏估计。直接采k个算一次，方差很大。Codex论文的做法：每题采样n个（n ≥ k，例如n = 200），数出其中通过的个数c，再用组合数计算“从这n个里随机抽k个、至少有一个通过”的概率：

pass@k = E_题目[1 − C(n − c, k) / C(n, k)]

C是组合数。C(n − c, k) / C(n, k)是抽到的k个全部失败的概率。k = 1时，它就等于c / n，即单次采样的通过率。

相关指标与用法。

  • pass@1是最常报告的数字，常用贪心解码或低温采样得到，也可以用上面的公式从多次采样中估计。
  • cons@k / maj@k：采样k个答案后多数投票（见自洽性采样），看投票结果是否正确。与pass@k不同，它不需要知道哪个是对的，可以在实际中使用。
  • 重复采样的规律：重复采样的扩展律发现，随着采样数k增加，覆盖率（能解出的题目比例）在很大范围内持续上升。
  • 强化学习分析：RLVR能否带来新推理用很大k下的pass@k比较强化学习前后的模型，讨论RL是在提升模型的能力边界，还是只是把本来就能采到的正确答案的概率提高了（见可验证奖励强化学习（RLVR））。

HumanEval、MBPP、LiveCodeBench等代码基准，以及AIME竞赛数学评测等数学评测都用这一类指标。

例子

某题采样n = 10个答案，其中c = 3个正确。

  • pass@1 = 3/10 = 0.3。
  • pass@3 = 1 − C(7,3)/C(10,3) = 1 − 35/120 ≈ 0.708。
  • pass@5 = 1 − C(7,5)/C(10,5) = 1 − 21/252 ≈ 0.917。

如果某题c = 0，无论k多大，pass@k都是0；如果c ≥ n − k + 1，抽k个必有一个正确，pass@k = 1。整个基准的pass@k是所有题目的平均。

容易误解的地方

  • pass@k（k > 1）假设有一个“神谕”能挑出正确答案；实际产品里没有测试用例时，用户拿到的是一个答案，应该看pass@1或多数投票的结果。
  • 测试用例不全时，错误的程序也可能通过，pass@k会被高估；后来的基准常增加更多隐藏测试。
