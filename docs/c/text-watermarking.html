文本水印

Text Watermarking

也叫：watermarking　text watermarking　文本水印　LLM水印　LLM watermark　大模型水印　green list　绿名单　red list　红名单　水印检测　watermark detection　AI文本检测　AI生成文本检测　AI-generated text detection　SynthID

在模型生成文本时悄悄改变选词的统计规律，人读不出差别，但知道密钥的检测者能用统计检验判断一段文字是不是这个模型写的。代表方法是“绿名单”水印。

先要会：Softmax与logits 解码：贪心、束搜索、温度与top-p 方差、种子与统计显著性

大模型写的文字越来越难与人写的区分。事后检测（训练一个分类器判断“像不像AI写的”）准确率有限，而且容易误伤母语不是英语的人写的文本。文本水印换了一个思路：在生成时就埋下可检测的信号。

绿名单水印（LLM文本水印，2023）。

1. 生成时：每一步，用前一个token和一个密钥算出哈希值，以此为随机种子，把词表随机分成“绿名单”（占比γ，如一半）和“红名单”。给绿名单里所有token的logit加上一个常数δ（见Softmax与logits），然后正常采样（见解码：贪心、束搜索、温度与top-p）。这样生成的文本里，绿名单token会比正常情况多。 2. 检测时：不需要模型，只需要密钥。对文本中每个token，用它的前一个token重新算出那一步的绿名单，数一数有多少token落在绿名单里。没有水印的文本，绿token的比例应该约为γ；有水印的文本会明显偏高。用z检验判断：

z = (G − γT) / √(T·γ(1 − γ))

T是token总数，G是绿token数。z超过阈值（如4）就判定有水印。

特点。文本越长，检测越可靠；δ越大，水印越强，但对文本质量的影响也越大。在低熵的位置（下一个词几乎是确定的，比如代码或固定搭配），加δ也改变不了选择，所以这些位置几乎不携带水印信号。

部署。SynthID文本水印（2024）在生成时用一种“锦标赛采样”嵌入水印，Google称已在其Gemini产品中部署，并公开了实现。

局限。

  • 改写攻击：用另一个模型把文本改写一遍、或者人工逐句修改，水印信号就会大幅减弱。
  • 只对自己有效：只有生成方愿意加水印、并且检测方拿到密钥才行；开源模型的使用者可以直接去掉水印逻辑。
  • 短文本：几十个token的文本统计量不足，难以可靠判断。

因此水印更适合作为溯源手段之一，而不是“AI文本检测”的完整解决方案。

例子

γ = 0.5，一段200个token的文本，检测出绿token 140个。

  • 无水印时期望 0.5 × 200 = 100个，标准差 √(200 × 0.25) ≈ 7.07。
  • z = (140 − 100) / 7.07 ≈ 5.66，远超阈值4，判定有水印。

同一段文字被改写后，绿token降到112个：z = 12/7.07 ≈ 1.70，不足以判定。一段人写的文本，绿token通常在100上下波动，z接近0。

容易误解的地方

  • 检测给出的是统计证据，不是确定的证明；阈值设低了会误判人写的文本。
  • 水印不改变模型的能力，也不能阻止滥用，只能帮助事后溯源。
