时域、分幕任务与终止

Horizon, Episodic Tasks and Termination

也叫：episodic task　分幕任务　回合制任务　continuing task　持续任务　持续性任务　终止状态　terminal state　有限时域　finite horizon　无限时域　infinite horizon　有效时域　effective horizon　截断　truncation　termination　time limit　时间截断　truncation vs termination　timeout bootstrapping　terminated　truncated

任务有没有终点、最多走多少步：分幕任务在终止状态结束，持续任务永不结束；γ决定智能体实际“看多远”；因为超时被截断和真正终止要区别对待。

先要会：奖励、回报与折扣 时序差分与自举

同样是“最大化回报”，下一盘棋和管理一台永不停机的空调是两类问题。前者有明确的终点，后者没有；而很多仿真任务虽然本身没有终点，却被人为限制在1000步。这些区别直接决定价值目标该怎么写，处理错了会让价值估计系统性地出错。

分幕任务与持续任务。分幕任务（episodic）会到达终止状态，之后再无奖励，所以终止状态的价值定义为0，TD目标在这里只剩r。持续任务（continuing）没有终点，必须靠折扣γ < 1让回报有限，或改用平均奖励准则准则。

有限时域与无限时域。有限时域问题规定最多H步，最优策略一般与“还剩几步”有关（最后一步不必为将来打算），价值函数要写成V_h(s)。无限时域加折扣的问题，最优策略可以只依赖当前状态。

有效时域。折扣让很远的奖励几乎不计：权重γ^k在k ≈ 1/(1−γ)附近已明显衰减，这个量常被称为有效时域。γ=0.99大约对应100步，γ=0.999约1000步。γ越接近1看得越远，但价值方差更大、学习更慢，见奖励、回报与折扣。

终止与截断。回合结束有两种原因：真的到了终点（摔倒、赢棋），或者只是到了人为设定的时间上限。前者之后确实没有未来；后者之后世界还在继续，智能体只是看不到。正确做法是：终止时目标为r，截断时仍用r + γ·V(s')自举。把超时当终止，会让价值函数学到一个它根本观察不到的“剩余时间”效应，状态里又没有时间信息，于是估计变得自相矛盾。Gymnasium的接口把两者分成terminated和truncated两个标志，就是为了让算法能区分。

例子

γ=0.99时，第100步之后的奖励权重为0.99^100 ≈ 0.37，第500步为0.99^500 ≈ 0.007，基本不再影响决策。

一个行走任务限时1000步。第1000步时机器人正稳稳地走着，r=1，V(s')≈90。若误当作终止，目标是1；正确的截断处理目标是1 + 0.99×90 ≈ 90.1。两者相差近90倍，而且同一个状态在第10步和第1000步会得到完全不同的目标。

容易误解的地方

  • 很多早期代码把done当成一个标志，超时和失败不分，这是价值估计偏差的常见来源。
  • 有效时域只是一个数量级上的说法，不是严格的截断点。
  • 评估时报告的回报通常不打折扣，而训练用的是打折扣的回报，两者数值不能直接比较。
