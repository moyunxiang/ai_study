束宽、长度惩罚与束搜索的细节

Beam Width, Length Penalty and Beam Search Details

也叫：beam width　束宽　beam size　num_beams　length penalty　长度惩罚　length normalization　长度归一化　early_stopping　提前停止（束搜索）　diverse beam search　多样化束搜索　约束束搜索　constrained beam search　束搜索细节

束搜索的几个关键设置：束宽决定同时保留几条候选；长度惩罚（长度归一化）修正“短句累积概率天然更高”的偏差；提前停止决定何时结束搜索。

先要会：解码：贪心、束搜索、温度与top-p

解码：贪心、束搜索、温度与top-p介绍了束搜索的基本思想：每一步保留累积对数概率最高的B条部分序列。真正用起来，还有几个细节决定了效果。

束宽B。B = 1就是贪心解码。B越大，越可能找到整体概率更高的序列，但计算量和显存约为B倍。机器翻译常用4到10；更大的束宽往往带来的提升很小，有时反而更差（见下）。

长度偏差。序列的得分是各步对数概率之和：

score(y) = Σ_t log p(y_t | y_<t, x)

每一项都是负数，序列越长，加的负数越多。所以束搜索天然偏爱短序列：只要模型给EOS（见生成的停止条件）一个不太低的概率，提早结束的候选就可能胜出。神经机器翻译中观察到，束宽变大时译文反而变短、质量下降，有研究发现在极大的束宽下，模型认为概率最高的输出常常是空句子。这说明问题出在模型的概率本身，而不只是搜索不够。

长度惩罚（长度归一化）。用长度修正得分：

  • 简单平均：score / |y|。
  • GNMT的形式：score / lp(y)，lp(y) = ((5 + |y|) / 6)^α。α = 0时不做修正；α越大越鼓励长句。Hugging Face的length_penalty参数是score / |y|^α的指数α，大于0鼓励长输出、小于0鼓励短输出。

提前停止。当一条候选生成了EOS，就把它移入“已完成”列表，其他候选继续。什么时候整体停止？一种做法是凑够B条已完成的候选就停（early_stopping=True）；另一种是继续搜索，直到可以确定不会再有得分更高的候选。

其他变体。

  • 多样化束搜索：把束分成几组，组间加多样性惩罚，避免B条候选几乎一样。
  • 约束束搜索：强制输出包含某些词。
  • n-gram阻断：不允许重复出现的n元组，见重复惩罚、频率惩罚与存在惩罚。

用在哪里。有标准答案、输出与输入高度对应的任务：机器翻译（Seq2Seq、Transformer的实验都用束搜索）、语音识别、摘要。开放式对话和写作则改用采样，因为束搜索的输出容易平淡和重复（见核采样Top-p、文本退化与重复循环）。

例子

两条已完成的候选：

  • A：“好的。”，3个token，对数概率之和 −1.5。
  • B：“好的，我明天上午九点到。”，12个token，对数概率之和 −4.8。

不做长度修正，A得分−1.5高于B的−4.8，选A。用平均对数概率：A = −0.50，B = −0.40，选B。用HF式长度惩罚、α = 1：同样是A −0.50、B −0.40，选B；α = 0时退化为不修正，选A。

容易误解的地方

  • 束搜索的输出是确定的；同一个输入总得到同一个结果，需要多样的候选时要换用采样或多样化束搜索。
  • 束宽越大并不总是越好：找到模型认为概率更高的输出，可能恰恰暴露了模型概率与人类偏好之间的偏差。
