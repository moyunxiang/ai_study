碰撞检测

Collision Checking

也叫：碰撞检测　collision detection　collision checking　碰撞检查　包围盒　bounding box　AABB　包围体层次　BVH　GJK　有符号距离场　signed distance field　SDF　连续碰撞检测　continuous collision detection　自碰撞　self-collision　穿透深度

判断机器人在某个构型下（或沿一段运动）是否会与障碍物或自身相撞，并常常还要给出离碰撞有多远。它是运动规划中被调用最频繁的操作，也是仿真器处理接触的第一步。

先要会：关节空间、任务空间与构型空间 图、树与搜索

运动规划要找一条“不撞”的路径，物理仿真要知道“哪里接触了”，安全监控要判断“下一步会不会撞人”，都依赖碰撞检测。采样式规划器（如RRT快速随机树）找一条路径可能要检查几万到几百万个构型，碰撞检测往往占掉大部分计算时间。

两个阶段。

  • 粗筛（broad phase）：用简单的包围体快速排除明显不可能相撞的物体对。常用轴对齐包围盒（AABB）、包围球，再组织成层次包围体树（BVH），使检查的物体对数远少于全部两两组合。
  • 精检（narrow phase）：对可能相撞的物体对做精确的几何检测。凸体之间常用GJK算法计算距离或判断相交；非凸物体先分解成若干凸块。

不只是“是否相撞”。

  • 距离与有符号距离：分离时给出最近距离（正值），穿透时给出穿透深度（负值）。基于优化的轨迹规划需要这个连续的量及其梯度，把“离障碍物远一点”写进代价函数，例如CHOMP梯度轨迹优化用预计算的有符号距离场，TrajOpt序列凸轨迹优化用凸体之间的有符号距离做序列凸优化，见规划与模型预测控制。
  • 连续碰撞检测：只检查离散的时间点可能漏掉高速穿过薄障碍的情况（“隧穿”），需要检查整段运动扫过的体积。
  • 自碰撞：机械臂和人形机器人还要检查自身各连杆之间是否相撞，通常排除相邻连杆。

在仿真与学习中。仿真器（如MuJoCo物理仿真）每一步都先做碰撞检测找出接触点，再计算接触力（见机器人动力学与运动方程）。用简化的碰撞几何（胶囊体、凸包）代替精细网格可以大幅加速，这也是仿真与真实接触行为存在差异的原因之一。学习型方法也会把“预测是否碰撞”作为辅助任务，或用学到的有符号距离场表示场景。

例子

一个7轴机械臂用胶囊体近似每个连杆（共7个），场景里有20个障碍物。逐对检查需要7×20=140次胶囊-障碍物检测，外加约15对非相邻连杆的自碰撞检测。若用包围体树粗筛后只剩10对需要精检，精确检测的次数就从约155次降到10次，规划器在同样时间里能检查的构型数随之增加一个数量级左右。

容易误解的地方

  • 碰撞几何过于保守（包得太胖）会让规划器找不到穿过窄缝的路径，过于贴合又会增加计算量和数值不稳定。
  • 只在路径上的离散点检测而不检查中间段，是规划结果在真机上发生碰撞的常见原因。
