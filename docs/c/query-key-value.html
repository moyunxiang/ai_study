查询、键与值（Q/K/V）

Queries, Keys and Values

也叫：QKV　Q/K/V　query key value　查询键值　查询、键、值　注意力分数　attention score　attention weights　注意力权重　scaled dot-product　缩放因子　√d_k

在交互版中打开（看它长在树上的哪里）

注意力里每个token被线性投影成三个向量：查询Q（我在找什么）、键K（我能提供什么的索引）、值V（我实际提供的内容）。Q与K的点积决定权重，再按权重混合V。

先要会：内积与余弦相似度 Softmax与logits 矩阵乘法与线性变换

注意力要回答的问题是：序列中第i个位置应该从其他哪些位置取信息、取多少？如果直接用token的原始向量互相点积，同一个向量既要表达“我想找什么”，又要表达“别人凭什么找到我”，还要承载“被找到后交出的内容”，三种角色挤在一起。Q/K/V把这三种角色拆开，各用一个可学习的矩阵。

定义。输入矩阵X（n个token，每个d维），三个投影矩阵W_Q、W_K、W_V：

Q = X·W_Q，K = X·W_K，V = X·W_V

Attention(Q, K, V) = softmax(Q·Kᵀ / √d_k)·V

  • Q·Kᵀ是n×n的分数矩阵，第(i, j)项是第i个查询与第j个键的内积与余弦相似度，表示相关程度。
  • 除以√d_k：维度大时点积的方差随d_k增长，分数过大会让Softmax与logits几乎变成one-hot，梯度很小。除以√d_k把方差拉回1左右。
  • softmax把每一行变成和为1的权重，再对V加权求和。

一个类比。像查字典：Q是你要查的词，K是字典里每个词条的标题，V是词条的释义。不同的是，这里的“匹配”是软的——不只取最匹配的一条，而是按相似度给所有词条加权。

在哪里出现。Q、K、V都来自同一序列时是自注意力与多头注意力；Q来自一个序列、K和V来自另一个时是交叉注意力。多头注意力把投影拆成h组，每组用较小的维度d/h各算一遍再拼接，让不同头关注不同关系。生成时，过去token的K和V不会变，可以缓存起来，这就是KV缓存；MHA、MQA、GQA与MLA讨论的就是让多个头共享K、V以减小这份缓存。原始出处见Transformer。

例子

两个token，d_k = 2。设

Q = [[1, 0], [0, 1]]，K = [[1, 0], [1, 1]]，V = [[10, 0], [0, 10]]。

第1个token：与两个键的点积为 [1, 1]，除以√2 ≈ 1.41 得 [0.71, 0.71]，softmax为 [0.5, 0.5]，输出 0.5×[10,0] + 0.5×[0,10] = [5, 5]。

第2个token：点积为 [0, 1]，除以√2得 [0, 0.71]，softmax约为 [0.33, 0.67]，输出约 [3.3, 6.7]，更多地取了第2个值向量。

容易误解的地方

  • Q、K、V不是三种不同的输入，而是同一个输入乘上三个不同矩阵；“查询”“键”“值”只是对它们作用的解释。
  • 注意力权重高不等于“模型因此做出了这个判断”，用注意力图解释模型要谨慎。
  • 分数矩阵是n×n的，序列长度翻倍，计算量和显存约变成4倍（见稀疏注意力与高效注意力）。
