GPU执行模型：kernel、线程块、warp与SM

GPU Execution Model: Kernels, Blocks, Warps, SMs

GPU程序（kernel）拆成大量线程，按线程块分配到各个SM上运行，每32个线程组成一个warp同步执行。写出快的算子，关键是安排好数据在显存、共享内存和寄存器之间的搬运。

先要会：CPU、GPU与并行计算 显存、内存带宽与“内存墙”

CPU、GPU与并行计算说GPU靠成千上万个简单核心并行计算。读高性能算子的论文（如FlashAttention）时会遇到kernel、SM、warp、共享内存这些词，它们描述的是GPU实际怎样执行一个程序，这套模型随CUDA和GeForce 8800/G80一起确立，此后基本没变。

kernel与线程层次。在GPU上运行的一个函数叫kernel。启动时指定一个网格（grid），由许多线程块（block）组成，每个线程块包含几十到上千个线程。每个线程执行同样的代码，用自己的编号决定处理哪部分数据，例如一个线程负责输出矩阵的一个元素。

硬件映射。

  • SM（流式多处理器）：GPU由几十到一百多个SM组成，每个线程块被整体分配到一个SM上，块内线程可以共享数据、互相同步。
  • warp：SM以32个线程为一组调度，同一warp内的线程同时执行同一条指令（SIMT）。若遇到分支、不同线程走不同的路，两条路要依次执行，叫分支发散。
  • Tensor Core：SM内专门做小矩阵乘加的单元，从V100与Tensor Core开始引入，提供了大部分深度学习算力。

存储层次（越往上越快、越小）。

  • 寄存器：每个线程私有，最快。
  • 共享内存/L1：每个SM上几百KB以内的片上SRAM，块内线程共享，需要程序员显式管理。
  • L2缓存：全芯片共享。
  • 全局内存（显存，HBM）：几十GB，带宽每秒数TB，但相对于计算仍是瓶颈，见显存、内存带宽与“内存墙”。

高效kernel的核心技巧是分块（tiling）：把一块数据从显存读进共享内存，在片上反复使用多次，再写回。矩阵乘法库（如CUTLASS）和FlashAttention都靠这个思路减少显存读写。相邻线程访问相邻地址时多次访问可以合并成一次（访存合并），否则带宽会被浪费。

为什么AI研究者需要知道。很多“理论上更少计算”的方法实际并不更快，因为它们访存不规则或无法使用Tensor Core；反之，稀疏注意力与高效注意力中的许多改进主要靠更好地利用这套层次结构。Triton GPU编程语言让人用Python按块编写kernel，降低了写高性能算子的门槛；把多个小kernel融合成一个、减少启动开销和中间结果的显存往返，也是编译器（如torch.compile）的主要工作。

例子

对一个1024×1024的矩阵逐元素加1：启动一个kernel，每个线程块256个线程，共1024×1024/256 = 4096个块，每个线程处理一个元素，即8个warp一块。这个操作每个元素只做1次加法、却要读4字节写4字节（FP32），完全受带宽限制：在每秒3TB的显存上约需8MB/3TB/s ≈ 2.8微秒，而kernel启动本身就可能要几微秒，所以把它和前后的操作融合起来最划算。

容易误解的地方

  • “GPU核心数”的营销口径各厂商不同，不能直接拿来比较算力；比较时看各精度的峰值FLOPS和显存带宽。
  • 线程块用的共享内存和寄存器太多，SM上能同时驻留的warp就少（占用率低），隐藏访存延迟的能力随之下降。
