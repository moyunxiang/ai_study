检索与向量数据库

Retrieval and Vector Search

也叫：向量检索　vector database　RAG　检索增强生成　语义搜索　ANN

在交互版中打开（看它长在树上的哪里）

从大量文档中找出与查询最相关的几条。现代做法是把文本变成向量，用向量之间的相似度来找；向量数据库负责在上亿个向量中快速完成这种查找。

先要会：嵌入向量 内积与余弦相似度 范数与距离

语言模型的知识冻结在训练那一刻，容量有限，还会编造（见幻觉）。如果能在回答前先去一个可更新的文档库里找到相关资料，放进上下文再作答，这三个问题都能缓解。检索就是“找资料”这一步。

稀疏检索：按词匹配。经典信息检索把文档和查询都表示成词频向量。IDF与TF-IDF给每个词加权：在本文档中出现越多越重要，在所有文档中都常见（如“的”）则不重要。BM25在此基础上加了词频饱和和文档长度归一化，至今仍是很强的基线。它们的弱点是只认字面：查询“汽车”找不到只写了“轿车”的文档。

稠密检索：按语义匹配。用一个神经网络编码器把查询和每个文档各自编码成一个固定长度的向量（见嵌入向量），训练目标是让相关的查询-文档对向量接近、不相关的远离（见对比学习）。检索时计算查询向量与所有文档向量的相似度，取最高的k个。相似度通常用余弦相似度或内积（见内积与余弦相似度）：

cos(q, d) = q·d / (‖q‖·‖d‖)

稠密检索DPR（2020）证明这种双塔编码器在开放域问答上明显优于BM25；E5文本嵌入等通用文本嵌入模型让它成了标准组件。

向量数据库与近似最近邻。文档有上亿条时，每次查询都和所有向量算一遍太慢。近似最近邻（ANN）索引牺牲一点准确率换取速度：

  • IVF：先把所有向量聚类（见聚类），查询时只搜最近的几个簇。
  • HNSW：建一个多层的邻近图，从顶层粗略定位，逐层往下贪心地走向最近的点。
  • 乘积量化（PQ）：把向量压缩成几个字节的编码，减少显存和计算。

向量数据库就是把这些索引与存储、过滤、更新功能打包起来的系统。

它在哪里出现。检索增强生成RAG把检索器和生成模型连起来，生成时先检索再作答；ColPali文档检索直接对文档页面图像做检索。今天的智能体也常把“搜索”作为一个工具来调用（见工具调用）。

例子

余弦相似度排序。查询向量q = [0.6, 0.8]，三个文档向量都已归一化：d_1 = [1, 0]，d_2 = [0.8, 0.6]，d_3 = [0, 1]。

  • cos(q, d_1) = 0.6
  • cos(q, d_2) = 0.6×0.8 + 0.8×0.6 = 0.96
  • cos(q, d_3) = 0.8

排序为d_2 > d_3 > d_1，top-1是d_2。向量都已归一化时，余弦相似度就等于内积。

为什么需要近似搜索。1000万个文档、每个768维，一次暴力检索要做约1000万 × 768 ≈ 77亿次乘加；FP32存储这些向量需要约1000万 × 768 × 4字节 ≈ 31GB。ANN索引通常只需检查其中很小的一部分向量就能找到绝大多数真正的最近邻。

容易误解的地方

  • 检索到了不等于用上了：模型可能忽略检索结果，或者被不相关的检索结果误导。
  • 稠密检索在训练分布以外（专业术语、产品型号、人名）可能不如BM25，实际系统常把两者混合使用。
  • 文档怎么切块（多长、是否重叠）对检索效果影响很大，往往比换嵌入模型更重要。
