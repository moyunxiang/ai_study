数据泄漏与基准污染

Data Leakage and Benchmark Contamination

也叫：数据泄露　测试集泄漏　benchmark污染　基准污染　test set contamination　训练测试泄漏　特征泄漏　target leakage　数据污染　测试集泄漏　test set leakage　数据泄露　刷题　记忆测试集

在交互版中打开（看它长在树上的哪里）

测试时用到的信息在训练时已经以某种方式被模型看到，使测试分数高估真实能力；大模型时代的典型形式是基准题目混进了预训练语料。

先要会：训练集、验证集与测试集 泛化与过拟合

测试集的意义在于模拟“从没见过的新数据”（见训练集、验证集与测试集和泛化与过拟合）。只要训练过程以任何方式接触到了测试信息，测得的就不再是泛化能力，而部分是记忆力。这种问题统称数据泄漏（data leakage）。

传统机器学习中的泄漏往往很隐蔽：

  • 在划分训练/测试之前，就用全部数据计算了归一化的均值方差或做了特征选择；
  • 同一个病人、同一段视频的不同样本分别落进了训练集和测试集；
  • 时间序列里用了“未来”的数据去预测“过去”；
  • 反复在测试集上挑模型、调参数，相当于间接拟合测试集，见ImageNetV2：榜单过拟合了吗。

大模型时代的基准污染（benchmark contamination）问题更大。预训练语料是从网页上大规模抓取的，而流行基准的题目和答案常常被公开放在GitHub、论坛、题解网站上，自然会被抓进去。模型在训练中见过原题，测试时就可能直接背出答案。GPT-3论文最早系统地做了检查：用13-gram重合找出与训练集重叠的测试题，比较模型在“干净”与“被污染”子集上的分数差异。

怎么检测和缓解：

  • 重合检测：查测试题与训练语料的n-gram或近似重复匹配（需要能访问训练数据）；
  • 行为检测：看模型能否逐字续写出测试题、对题目措辞的微小改动是否特别敏感，见测试集污染检测；
  • 换新题：只用模型训练截止日期之后出现的题目，例如定期更新的LiveBench、LiveCodeBench；
  • 不公开测试集：答案保留在评测方手里，只提供提交接口，如ARC-AGI的竞赛用一组不公开的私有评测题打分。

例子

一个有1000道题的基准，其中200道题连同答案混进了训练语料。模型在这200道题上背出了答案（正确率100%），在其余800道真正没见过的题上正确率为50%。报告的总分是(200 × 1.0 + 800 × 0.5) / 1000 = 60%，比真实水平50%高出10个百分点。只看总分完全发现不了；把题目分成“干净”和“污染”两组分别统计，差距一目了然。

容易误解的地方

  • 没有找到字面重合不等于没有污染：题目可能被改写、翻译后进入训练数据。
  • 闭源模型的训练数据不公开，外部只能做间接推断，结论往往有争议。
  • 污染不只来自预训练，也来自用基准风格数据做的微调或合成数据。
