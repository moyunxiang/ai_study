混合检索

Hybrid Search

也叫：hybrid search　混合检索　hybrid retrieval　稀疏加稠密　sparse + dense　RRF　reciprocal rank fusion　倒数排名融合　排名融合　rank fusion　多路召回

在交互版中打开（看它长在树上的哪里）

同时用按词匹配的稀疏检索（如BM25）和按语义匹配的稠密检索查找文档，再把两份排名融合成一份。两者的强项互补，融合后通常比单用任何一种都稳。

先要会：检索与向量数据库

检索与向量数据库里有两大类方法，各有一个典型的失败场景：

  • 稀疏检索（BM25、IDF与TF-IDF）只认字面。查询“汽车保养”，只写了“轿车维护”的文档拿不到分。
  • 稠密检索（向量检索，见句向量与文本嵌入）认语义，但对精确字符串不敏感。查询一个产品型号“RTX-4090”、一个错误码“E1023”或一个罕见人名，向量可能把它和相近但不同的型号混在一起，而BM25能精确命中。

真实查询两种情况都有，于是很自然地想到：两路都查，再合并。

怎么合并。两路的分数尺度完全不同（BM25可能是十几，余弦相似度在−1到1之间），直接相加没有意义。常用两种办法：

  • 加权分数融合：先把两路分数各自归一化到0到1，再按权重相加：s = α·s_dense + (1 − α)·s_sparse。α需要在自己的数据上调。
  • 倒数排名融合（RRF）：只用名次不用分数。文档d的融合分数是

RRF(d) = Σ_路 1 / (k + rank_路(d))

rank从1开始，k是一个常数（常取60），作用是让排名靠前和稍靠后的文档差距不至于过大。某一路没返回该文档，这一路就不计分。RRF不需要调权重，对分数尺度不敏感，是混合检索最常用的默认做法。

另一条路：学习式稀疏。SPLADE学习式稀疏检索用BERT预测每个词的权重，还能给原文没出现、但语义相关的词加权，得到“带语义的稀疏向量”，可以直接放进倒排索引（见倒排索引），兼顾两者的优点。

位置。混合检索通常是两阶段流水线的第一阶段，融合后的前几十条再交给交叉编码器重排序（见交叉编码器与重排序），然后送进检索增强生成RAG的生成步骤。BEIR零样本检索的零样本评测显示，在训练领域之外，BM25常常比早期稠密检索模型更稳，这是混合检索流行的一个原因。

例子

k = 60。查询返回：

  • BM25排名：文档A第1，文档B第3，文档C第2。
  • 向量检索排名：文档B第1，文档C第2，文档A第10。

RRF分数：

  • A：1/61 + 1/70 ≈ 0.0164 + 0.0143 = 0.0307
  • B：1/63 + 1/61 ≈ 0.0159 + 0.0164 = 0.0323
  • C：1/62 + 1/62 ≈ 0.0161 + 0.0161 = 0.0323

B和C两路都靠前，排在A之前（B和C几乎并列，B在小数点后第五位略高）；A虽然在BM25里第一，但向量检索给它排第10，融合后掉到第三。

容易误解的地方

  • 混合检索不是总比单路好：如果某一路在你的数据上很差，等权融合会把它的噪声带进来，需要在验证集上确认。
  • RRF丢掉了分数大小的信息：第1名领先第2名很多还是只领先一点，RRF看不出来。
