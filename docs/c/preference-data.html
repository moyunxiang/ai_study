偏好数据

Preference Data

也叫：preference data　偏好数据　偏好对　preference pairs　chosen rejected　chosen/rejected　成对比较　pairwise comparison　pairwise preference　成对偏好　人类偏好数据　human preference data　比较数据　comparison data　偏好标注

在交互版中打开（看它长在树上的哪里）

对齐训练用的比较型数据：同一个提示下有两个（或多个）回答，并标出哪个更好（chosen）、哪个更差（rejected）。它比让人写标准答案更便宜也更可靠，是奖励模型和DPO类方法的原料。

先要会：人类反馈强化学习

要让模型的回答更有用、更安全，最直接的办法是请人写出理想回答再做监督微调（见指令微调与对话模板）。但写出好回答很难，判断两个回答哪个更好却容易得多，而且不同标注者在“比较”上的一致性通常高于“打绝对分”。偏好数据就是把人类的这种比较判断记录下来。

格式。最常见的是三元组：

(提示x, 较好的回答y_w, 较差的回答y_l)

也叫chosen / rejected。其他形式有：对k个回答排序（可拆成多个成对比较）、给每个回答打1到10分、只标“好/不好”的二元反馈（KTO前景理论对齐就用这种数据）。

从哪来。

  • 人工标注：对模型采样的几个回答，让标注员按有用性、无害性、事实性等标准比较。InstructGPT与RLHF和Anthropic HH-RLHF都这样收集，后者把“有用”和“无害”分成两份数据。
  • AI反馈：让强模型来当评判者（见LLM当裁判、RLAIF），成本低得多。UltraFeedback AI反馈数据用GPT-4对多个模型的回答打分，构建了大规模开放偏好数据。
  • 用户交互：产品中“哪个回答更好”的选择、点赞点踩、竞技场投票（见竞技场式人类偏好评测）。
  • 可验证构造：数学和代码中，答对的作为chosen、答错的作为rejected。

怎么用。训练奖励模型，再用强化学习优化（见人类反馈强化学习）；或者用DPO直接偏好优化等方法直接在偏好对上优化策略（见直接偏好优化家族）。

质量问题。

  • 标注噪声：不同人的偏好本来就不同，同一对回答的标注一致率常常远低于100%。
  • 表面偏差：标注者倾向选更长、格式更漂亮、更自信的回答，模型会学到“越长越好”。
  • 分布匹配：偏好对最好来自当前要训练的模型自己的输出（on-policy），用别的模型的回答构造的数据效果可能打折扣。

例子

一条偏好数据：

  • 提示：“我的猫不吃东西了怎么办？”
  • chosen：“先观察是否有呕吐、精神萎靡等症状。如果超过24小时完全不进食，建议尽快就医，因为猫长时间不吃东西可能引发脂肪肝。在此之前可以试试……”
  • rejected：“猫有时候就是挑食，过几天就好了。”

用Bradley–Terry模型训练奖励模型时，希望r(chosen) − r(rejected)尽量大；用DPO时，希望模型相对参考模型提高chosen的概率、降低rejected的概率。

容易误解的地方

  • chosen只是“两者中较好的”，不一定是好回答；两个都差的偏好对也会教模型学到东西，未必是你想要的。
  • 偏好数据隐含了标注者的价值观和文化背景，换一群标注者，“更好”的标准可能不同。
