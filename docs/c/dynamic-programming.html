动态规划

Dynamic Programming

也叫：DP　动规　记忆化搜索　memoization　最优子结构

在交互版中打开（看它长在树上的哪里）

把大问题拆成相互重叠的子问题，每个子问题只算一次并记下结果，再由小到大拼出答案。它把很多指数级的穷举变成多项式时间。

先要会：时间与空间复杂度

很多问题的候选答案数量是指数级的：一句话有几十个词，每个词可能有几十种词性标注，所有组合多到无法列举；两段语音对齐的方式也是天文数字。但这些问题往往有一个共同结构：最优的整体答案由最优的局部答案组成，而且不同的候选共享大量相同的局部。动态规划利用的正是这一点。

两个条件。一是最优子结构：问题的最优解可以由子问题的最优解组合得到。二是重叠子问题：同一个子问题会被反复用到。满足这两点，就可以开一张表，按顺序填，每格只算一次。

典型例子：编辑距离。把字符串a变成b最少要几次插入、删除、替换？令D[i][j]是a的前i个字符变成b的前j个字符的最少操作数：

D[i][j] = min(D[i−1][j] + 1, D[i][j−1] + 1, D[i−1][j−1] + [a_i ≠ b_j])

三项分别对应删除、插入、替换（相同则不花代价）。填满(m+1)×(n+1)的表需要O(mn)时间，而穷举所有编辑序列是指数级的，见时间与空间复杂度。

它出现在哪里。动态规划与Bellman方程提出动态规划，并把“当前价值 = 即时回报 + 后续最优价值”写成递推式，这就是强化学习的Bellman方程；Viterbi算法用动态规划在隐马尔可夫模型里找最可能的状态序列，见隐马尔可夫模型；动态时间规整DTW用和编辑距离几乎一样的递推对齐两段语速不同的语音；CTC用前向—后向动态规划对所有可能的对齐求和，让语音识别不再需要逐帧标注，见输入输出不等长时的对齐。

例子

把cat变成cut：表格最后一格D[3][3] = 1，即把a替换成u。经典例子kitten → sitting的编辑距离是3：k换成s，e换成i，末尾插入g。对这两个长度6和7的字符串，动态规划只需填7×8 = 56个格子。

容易误解的地方

  • 动态规划的关键在于设计“状态”，也就是表格每一格代表什么；状态设计得不对，要么递推不成立，要么表格太大。
  • 很多动态规划可以从“求最优”（取max/min）换成“对所有方案求和”（取sum），例如Viterbi与前向算法、DTW与CTC，结构相同，只换了运算。
