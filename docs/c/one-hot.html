独热编码与词表

One-Hot Encoding and Vocabulary

也叫：独热向量　词汇表　vocab　一位有效编码　稀疏表示

在交互版中打开（看它长在树上的哪里）

给词表中的每个符号一个编号，用一个长度等于词表大小、只有对应位置为1其余全为0的向量来表示它。这是把离散符号送进模型的最基本编码方式。

先要会：向量、矩阵与张量

模型的输入必须是数字。对类别型的数据——一个词、一种颜色、一个国家——最直接的想法是编号：猫 = 0，狗 = 1，鱼 = 2。但如果直接把编号当数值输入，模型会以为“鱼 = 2”比“狗 = 1”大，或者“狗”在“猫”和“鱼”中间，这种大小和顺序关系是编号时人为引入的，并不存在。

独热编码消除了这种虚假的顺序：先确定一个词表（vocabulary），即所有可能出现的符号的列表，大小为V；第i个符号表示成一个V维向量，第i位是1，其余是0。

  • 任意两个不同符号的向量内积为0，彼此距离都是√2，没有谁和谁更近。
  • 用one-hot向量乘以一个V × d的矩阵W，结果正好是W的第i行。这说明“查表取向量”与“one-hot乘矩阵”是同一件事，这就是嵌入向量层的数学本质。

在输出端：分类问题的标签也常写成one-hot形式，比如三类中的第2类写作(0, 1, 0)，模型输出的概率分布（经Softmax与logits）与它比较，计算交叉熵损失。语言模型预测下一个token，就是在一个大小为V的词表上做分类。

词表从哪来：早期NLP用整词做词表，遇到没见过的词只能标为“未知”。今天的语言模型用分词与token把文本切成子词，如BPE子词切分，词表规模通常在三万到二十几万之间，既能覆盖任意文本，又不至于太大。

它出现在哪里：神经概率语言模型和word2vec的输入都是one-hot编码的词，再通过嵌入矩阵变成稠密向量；GPT-2使用50257个token的词表。

例子

词表为[猫, 狗, 鱼]，V = 3：猫 = (1, 0, 0)，狗 = (0, 1, 0)，鱼 = (0, 0, 1)。

嵌入矩阵W = [[0.2, 0.5], [0.3, 0.4], [−0.9, 0.1]]（3×2）。“狗”的one-hot向量乘以W：(0, 1, 0) × W = (0.3, 0.4)，正好取出W的第2行。

容易误解的地方

  • 词表很大时（几万到几十万），实际代码从不真的构造one-hot向量，而是直接用整数下标查表，否则内存和计算都浪费。
  • 词表在训练前确定，之后改词表要重新训练嵌入层和输出层。
