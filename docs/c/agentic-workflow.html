提示链与智能体工作流

Prompt Chaining and Agentic Workflows

也叫：智能体工作流　agentic workflow　agentic workflows　LLM workflow　提示链　prompt chaining　prompt chain　链式调用　编排者-执行者　orchestrator-workers　评估-优化循环　evaluator-optimizer　LLM应用编排　复合AI系统　compound AI systems

把复杂任务拆成若干次模型与工具调用，按事先设计的流程串起来：前一步输出作为后一步输入（提示链），或分支、并行、循环。比完全自主的智能体更可控、易调试，是多数生产系统的选择。

先要会：智能体循环 工具调用

让一个大模型一次性“写一份带数据分析的市场报告”，结果常常不稳定。更可靠的做法是把它拆开：先检索资料，再提取要点，再写提纲，再逐节撰写，最后检查格式。每一步用一个专门的提示，步骤之间由代码衔接。这就是提示链，更一般地叫智能体工作流。

常见模式。

  • 提示链：步骤固定、线性执行，每步之后可以加程序检查（格式对不对、长度够不够），不通过就重试。由少到多提示先让模型把问题分解成子问题再逐个解决，是提示链思想在推理上的早期例子。
  • 路由：先用一次调用判断输入属于哪一类（退款、技术问题、投诉），再交给对应的专门流程或更合适的模型。
  • 并行化：同一任务拆成独立的子任务同时做，或者同一问题多次采样再投票（见best-of-N与拒绝采样微调）。
  • 编排者—执行者：一个模型负责规划和分配子任务，其他调用负责执行，最后汇总。
  • 评估—优化循环：一个调用生成，另一个调用按标准批评，生成者据此修改，直到满意，如Self-Refine自我改进和Reflexion（见LLM当裁判）。

工作流与自主智能体。在智能体循环里，模型自己决定每一步调用什么工具、何时结束，如ReAct、AutoGPT与自主智能体热潮；工作流中，控制流程由开发者用代码写定，模型只在每个节点上完成局部任务。二者是一个连续谱：工作流更可预测、成本可控、出错时容易定位；自主智能体更灵活，能处理事先想不到的情况，但更难测试，错误会累积。实践中常见的建议是：能用简单工作流解决的就不要上自主智能体。

工具与框架。LangChain、LangGraph图式编排（把流程写成有状态的图）、Dify LLM应用平台（可视化拖拽编排）、DSPy（把提示当作可优化的参数，见自动提示优化）都是构建这类流程的常用工具；AFlow自动工作流尝试用搜索自动设计工作流本身（见自动设计智能体系统）。

评估。不仅看最终输出，还要看每一步的成功率：链条有n步、每步成功率p，整体成功率约为p^n，步骤越多越需要中间检查和重试机制。

例子

客服邮件处理工作流：

1. 分类：判断是“退款”“物流”还是“其他”（一次小模型调用）； 2. 若为退款：提取订单号和金额（结构化输出，见结构化生成与约束解码）→ 调用订单系统API核对 → 生成回复草稿； 3. 检查：另一次调用核对回复里的金额是否与系统记录一致，不一致就重新生成； 4. 金额超过1000元时转人工。

若每步成功率95%，四步串联约为0.95⁴ ≈ 81%；加入第3步的检查与重试后，常见错误能被拦截下来。

容易误解的地方

  • 步骤拆得过细会增加延迟和成本，每一步还要传递上下文，信息可能在传递中丢失。
  • 工作流对“训练时没想到的输入”很脆弱：路由分类错了，后面所有步骤都会沿着错误的分支执行。
