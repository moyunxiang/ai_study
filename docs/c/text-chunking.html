文档切块

Document Chunking

也叫：chunking　文本切块　文档切块　分块　chunk size　块大小　chunk overlap　重叠窗口　sliding window chunking　chunking策略　chunking strategy　递归切分　recursive splitting　semantic chunking　语义切分　文本分割　text splitting　父子块　parent document retrieval

在交互版中打开（看它长在树上的哪里）

检索增强系统建库时，把长文档切成一段段“块”再分别编码和检索。块的大小、切分边界和相邻块的重叠，会直接影响能不能检索到、检索到的内容够不够回答问题。

先要会：检索与向量数据库 句向量与文本嵌入

检索增强生成（见检索增强生成RAG）要从文档库里找出与问题相关的内容放进提示。整本手册、整篇论文太长，不能整个塞进上下文，而且一个向量也表示不了一整篇长文的所有细节（见句向量与文本嵌入）。所以建索引前，先把文档切成较短的块（chunk），每块单独编码、单独检索。

块大小的取舍。

  • 太小（如一两句话）：语义集中，检索精确；但上下文被切断，“它”“该方法”指代什么丢了，一个答案可能分散在好几块里。
  • 太大（如几千token）：上下文完整；但一块里混了多个主题，向量被“平均”掉，检索变得模糊，放进提示也更占位置（见上下文窗口、迷失在中间）。

常见的起点是几百个token一块，再按任务调整。

常见切法。

  • 固定长度：每N个token切一刀，最简单。
  • 重叠窗口：相邻块之间保留一部分重叠（如块长512、重叠64），避免关键句子正好被切断。
  • 按结构切：按段落、标题、Markdown章节、代码函数切，尽量让每块是一个完整的意思单元。递归切分是常用做法：先按章节切，太长再按段落，再长再按句子（见文本规范化与分句中的分句）。
  • 语义切分：计算相邻句子的嵌入相似度，在相似度明显下降的地方切开。

给块补上下文。切开的块丢失了它在原文中的位置信息。几种改进：在每块前面加上文档标题和章节路径；上下文检索用语言模型为每块生成一句说明它在全文中位置的上下文，再一起编码；Late Chunking后切块先用长上下文编码器编码整篇文档，再按块对token向量做池化，让每块的向量“知道”全文；RAPTOR树状检索对块进行递归聚类和总结，形成树状的多粒度索引。

小块检索、大块阅读。一种折中是用小块建索引以提高检索精度，命中后把它所在的更大段落（父块）或前后相邻块一起交给生成模型。

例子

一份产品手册有一节：“3.2 重置密码。在登录页点击‘忘记密码’，输入注册邮箱。系统会发送一封邮件，其中的链接24小时内有效。”

  • 按固定20个字切且无重叠，可能切成“……输入注册邮箱。系统会发送一封”和“邮件，其中的链接24小时内有效。”问“重置链接多久失效”时，第二块虽然有“24小时”，却没有“重置密码”的字样，检索可能找不到它。
  • 按小节切，整个3.2节作为一块，并在前面加上“产品手册 > 账户管理 > 3.2 重置密码”，检索和回答都更可靠。

容易误解的地方

  • 切块参数与嵌入模型的最大输入长度要匹配，超出部分会被截断，等于白切。
  • 表格、代码和公式按普通文本切容易被拆坏，需要专门的处理规则。
