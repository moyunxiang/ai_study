残差流

Residual Stream

也叫：residual stream　残差流　残差主干　残差通路　residual pathway　残差流视角　共享黑板　中间层表示　hidden states　各层隐状态　hidden state　隐藏状态

在交互版中打开（看它长在树上的哪里）

看待Transformer的一种视角：每个token有一条贯穿所有层的d维“主干”向量，各层的注意力和前馈模块都只是从中读取、再把自己的结果加回去。它是机制可解释性研究的基本框架。

先要会：残差连接 Transformer层的结构

Transformer的每个子层都带残差连接（见残差连接）：x ← x + Attn(x)，x ← x + FFN(x)。把公式展开，最后一层的输出等于：

x_L = x_0 + Σ_层 Attn_l(…) + Σ_层 FFN_l(…)

其中x_0是词嵌入加位置信息（见词嵌入层）。也就是说，最终表示是所有模块输出的总和。Transformer电路的数学框架据此提出把这条不断被“加上东西”的向量称为残差流（residual stream）：它像一条总线或一块共享的黑板，每个模块从黑板上读一部分信息，处理后把结果写回黑板，自己并不覆盖别人写的内容。

这个视角带来什么。

  • 模块之间通过残差流通信。第3层的注意力头可以读取第1层某个头写进去的信息，不必经过中间层。这让研究者能把模型拆成一条条“电路”来分析（见电路发现与电路追踪）。
  • 可以随时“解码”。最后一层的LM head（见语言模型头与输出层）读的就是残差流。Logit Lens把LM head直接用在中间层的残差流上，发现模型往往在中间层就已经“想好”了答案的雏形；Tuned Lens给每层加一个小的变换使这种读出更准确。
  • 方向即特征。残差流的维度d有限（几千维），要表示的概念却远多于d个。研究认为模型把很多特征编码为残差流中近乎正交的方向，彼此叠加（叠加假说）；稀疏自编码器与字典学习就是从残差流里把这些方向分解出来。
  • 干预。往残差流里加上某个方向的向量，可以改变模型行为，例如让回答更积极或更倾向拒答（见激活引导与表示工程）。

与架构的关系。Transformer层的结构是从“怎么搭”的角度讲同一个结构，残差流是从“信息怎么流”的角度讲。前置归一化（Pre-LN Transformer）让主干上只有加法，没有被归一化打断，这也是残差流视角在现代模型上特别自然的原因；TransformerLens可解释性库等工具库就以它为核心来组织激活的读取与修改。

例子

一个2层、每层1个注意力头的玩具模型，处理第t个token：

输入是“法国的首都是”，当前位置是最后一个token“是”，要预测“巴黎”。

  • x_0 = 嵌入(“是”) + 位置，维度d = 512。
  • 第1层注意力写入a_1（比如从前文搬来“法国”“首都”的信息），FFN写入m_1。
  • 第2层注意力写入a_2，FFN写入m_2。
  • 最终 x_2 = x_0 + a_1 + m_1 + a_2 + m_2，LM head读取x_2预测下一个词。

用logit lens看x_0 + a_1 + m_1（只到第1层），如果LM head已经把“巴黎”排在前列，说明这一信息在第1层就已经写进去了。

容易误解的地方

  • 残差流视角是一种分析框架，并不意味着各模块的贡献可以简单相加来解释：后面的模块读到的是前面所有模块之和，非线性会让贡献相互纠缠。
  • 归一化层会对残差流的读出做缩放，直接比较不同层的向量大小要小心。
