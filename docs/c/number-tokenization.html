数字的分词与算术

Number Tokenization and Arithmetic

分词器怎么切数字，会影响模型的算术能力。BPE可能把“12345”切成“123”“45”，同样位数的数字切法也不一致；逐位切分或按三位一组从右往左切，能让算术更稳定。

先要会：分词与token

大模型做多位数加法、比较数字大小时常出奇地出错，一个被反复讨论的原因在分词与token。BPE按语料频率合并字符，常见的数字串（年份“2024”、整数“100”）会变成一个token，其余的被切成不规则的片段：

  • “2024”可能是1个token，“2025”可能也是1个，而“3917”被切成“391”“7”。
  • 同样是5位数，“12345”可能切成“123”“45”，“67890”切成“678”“90”或“6”“7890”。

这带来两个问题。第一，位值对不齐：做竖式加法需要个位对个位、十位对十位，可token边界与位值无关，模型要从不规则的切分中重新推断每一位。第二，表示不一致：同一个数字在不同上下文里可能被切成不同的token序列。

常见的解决办法。

  • 逐位切分：分词时强制每个数字字符单独成为一个token。LLaMA的分词器就把数字拆成单个数字；PaLM的词表也对数字做了逐位切分。代价是数字占用更多token。
  • 三位一组：按三位一组切分，GPT-4等使用的分词器预切分规则会把连续数字限制为最多三位一段。有研究比较发现，从右往左分组（与千位分隔符一致）比从左往右更利于算术。
  • 位置相关的改进：除了分词，也有工作给每一位数字加上表示其位值的嵌入，帮助模型对齐。

更一般的启示。分词器决定了模型“看到”的基本单位：数字、代码缩进、非英语文字、字符级任务（例如数“strawberry”里有几个r）的困难，很多都与分词有关。这也是研究者探索去分词器、直接处理字节的模型的动机之一（见去分词器与字节级语言模型、ByT5字节级模型）。

例子

两种分词下的“5678 + 1234 =”：

  • 不规则BPE：“56”“78”“ +”“ 123”“4”“ =”。千位和百位被分在“56”里，“1234”却被切成“123”和“4”，两边的位值完全对不上。
  • 逐位切分：“5”“6”“7”“8”“ +”“1”“2”“3”“4”“ =”。模型可以学会把第4个数字与第9个数字对齐相加（8 + 4 = 12，写2进1），像竖式一样。

（具体切法取决于分词器，这里为示意。）

容易误解的地方

  • 逐位切分让数字序列变长，长数字计算对上下文和注意力的要求随之提高。
  • 模型算术出错不一定都怪分词，训练数据中精确计算的样本少、自回归逐位生成时从高位写起（而竖式要从低位进位）也是原因。
