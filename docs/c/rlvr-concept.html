可验证奖励强化学习（RLVR）

Reinforcement Learning with Verifiable Rewards

也叫：RLVR　verifiable rewards　可验证奖励　可验证奖励强化学习　reinforcement learning with verifiable rewards　rule-based reward　规则奖励　基于规则的奖励　结果奖励　答案奖励　outcome-based RL　推理强化学习　reasoning RL　R1式强化学习

在交互版中打开（看它长在树上的哪里）

用可以自动判对错的奖励来强化学习：数学题核对最终答案，代码跑单元测试，格式用规则检查。不需要学出来的奖励模型，难以被钻空子，是训练推理模型的主要方法。

先要会：策略梯度 奖励设计与奖励投机

RLHF用学出来的奖励模型打分，奖励模型本身会出错，策略优化得越狠越容易钻它的空子（见奖励作弊）。但有一大类任务的好坏可以直接验证：数学题的答案对不对、代码能不能通过测试、输出是不是合法JSON。用这种验证结果当奖励，就是可验证奖励强化学习（reinforcement learning with verifiable rewards，RLVR）。这个名称由Tülu 3开放后训练明确提出，DeepSeek-R1等推理模型的训练让它广为人知。

奖励怎么定。

  • 答案正确性：从模型输出中抽取最终答案（例如方框里的数字），与标准答案比较，对记1、错记0（见精确匹配与token级F1）。数学答案还要处理等价形式，比如1/2与0.5。
  • 代码测试：在沙箱里运行生成的代码，通过的测试比例或全部通过与否作为奖励（见pass@k）。
  • 格式与规则：是否按要求把思考过程和答案放在规定的标记里，是否满足长度、语言等约束。

奖励通常是稀疏的：一整段长回答只在结尾得到一个0或1（见信用分配）。

怎么优化。对同一道题采样多个回答，比较它们的奖励来估计每个回答的优势，再做策略梯度更新。GRPO用组内奖励的均值和标准差做归一化，省掉了价值网络（见Actor-Critic与优势函数）；DAPO、Dr. GRPO与R1-Zero再审视等对其中的细节做了修正。通常保留或去掉一个相对参考模型的KL项（见参考模型与KL惩罚）。

效果与争议。DeepSeek-R1报告，只用这类规则奖励做大规模强化学习，模型的思维链会变长，并出现回头检查、换思路等行为（见推理token与测试时计算）。但也有质疑：RLVR能否带来新推理用很大k下的pass@k比较发现，RL之后模型在小k时更准，大k时覆盖的题目却不比基座多，提示RLVR可能主要是把基座模型本来就能采到的正确路径的概率提高了；虚假奖励发现在某些模型上，甚至随机或错误的奖励也能带来提升。这说明RLVR的收益与基座模型本身的能力密切相关，具体机制仍在研究中。

局限。只适用于答案可以验证的任务；开放式写作、对话质量仍要靠偏好数据。验证器本身有漏洞时（测试用例不全、答案抽取规则太宽），同样会出现奖励作弊。

例子

一道数学题，对同一提示采样4个回答，抽取最终答案与标准答案“42”比较：

  • 回答1：“……所以答案是42。”→ 奖励1
  • 回答2：“……答案是41。”→ 奖励0
  • 回答3：没有按格式给出答案 → 奖励0
  • 回答4：“……最终结果42。”→ 奖励1

组内均值0.5、标准差0.5，GRPO式的优势为(+1, −1, −1, +1)：提高回答1和4的概率，降低2和3的概率。整个过程中没有任何人工打分或奖励模型。

容易误解的地方

  • “可验证”的前提是验证器可靠；测试用例或答案匹配规则有漏洞时，模型会学会利用漏洞而不是真正解题。
  • 题目太难（全部答错）或太简单（全部答对）时，组内奖励没有差别，优势全为0，这些样本不提供学习信号，需要筛选难度合适的题目。
