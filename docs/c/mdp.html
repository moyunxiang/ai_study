马尔可夫决策过程

Markov Decision Process

也叫：MDP　马尔科夫决策过程　状态转移　transition　强化学习建模

在交互版中打开（看它长在树上的哪里）

描述“智能体在环境中反复观察状态、选择动作、获得奖励”的标准数学框架，由状态、动作、转移概率、奖励和折扣因子五部分组成。

先要会：马尔可夫性与马尔可夫链 随机变量与概率分布 期望与方差

下棋、打游戏、控制机器人、和用户对话，表面上千差万别，但结构相同：一个智能体看到当前情况，做一个决定，环境随之变化并给出好坏反馈，然后重复。要为这类问题设计通用算法，先得有一个统一的数学描述，这就是马尔可夫决策过程（MDP）。

定义。一个MDP是五元组(S, A, P, R, γ)：

  • S：状态集合，例如棋盘局面、机器人的关节角度。
  • A：动作集合，例如落子位置、电机力矩。
  • P：转移概率P(s'|s, a)，在状态s做动作a后到达s'的概率。环境可以有随机性。
  • R：奖励函数R(s, a, s')，每一步给一个实数，表示这一步的好坏，见奖励、回报与折扣。
  • γ：折扣因子，0到1之间，决定未来的奖励打几折。

交互过程是一条轨迹s₀, a₀, r₁, s₁, a₁, r₂, …。“马尔可夫”指下一状态只依赖当前状态和动作，与更早的历史无关，见马尔可夫性与马尔可夫链。这个假设让问题可以一步一步递推求解，后面的Bellman方程就建立在它之上。

目标。找一个策略π（在每个状态下怎么选动作），使期望的累积折扣奖励最大，见策略与价值函数。

现实问题怎么套进来。很多时候智能体看不到完整状态（扑克看不到对手的牌、机器人只有摄像头画面），这叫部分可观测MDP（POMDP），常见处理是把一段历史观测当作“状态”，见状态、观测与动作。早在1957年动态规划与Bellman方程就用动态规划求解这类问题；Q-learning、DQN、PPO等强化学习算法都以MDP为前提；语言模型的RLHF也可以写成MDP：状态是已生成的文本，动作是下一个token。

例子

一个3状态的小MDP，γ=0.9：

  • s₁（起点）：动作“走”确定到达s₂，奖励0；动作“跳”有0.5概率直达s₃并得+10，有0.5概率摔回s₁并得−2。
  • s₂：只有动作“走”，到达s₃，奖励+5。
  • s₃：终点，回合结束。

一条可能的轨迹：s₁ 跳(摔了) → s₁ 跳(成功) → s₃，奖励序列为(−2, +10)，折扣回报为−2 + 0.9×10 = 7。另一条：s₁ 走 → s₂ 走 → s₃，奖励序列(0, +5)，回报0 + 0.9×5 = 4.5。哪种策略更好要看期望，Bellman方程的例子会算出来。

容易误解的地方

  • “马尔可夫”是对状态定义的要求：同一个问题，状态选得不够全就不马尔可夫，把历史拼进状态又能变成马尔可夫。
  • MDP默认环境规则固定不变；对手也在学习的多人博弈要用马尔可夫博弈等更一般的框架。
  • 多数深度强化学习算法并不需要知道P和R的具体形式，只需要能和环境交互采样。
