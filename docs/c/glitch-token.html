异常token

Glitch Tokens

也叫：glitch token　glitch tokens　异常token　故障token　under-trained tokens　训练不足的token　SolidGoldMagikarp　petertodd　anomalous tokens　怪异token

在交互版中打开（看它长在树上的哪里）

词表里存在、但在模型训练数据中几乎没出现过的token。它们的嵌入几乎没被训练，模型遇到时会出现无法复述、胡言乱语或回避等异常行为。著名例子是“ SolidGoldMagikarp”。

先要会：分词与token 嵌入向量

分词器和模型往往是分开训练的：先在一份语料上训练分词器（见分词与token），再在另一份（或经过清洗的）语料上训练模型。如果某个字符串在分词器的语料里很常见、被合并成了一个独立的token，却在模型的训练语料里几乎不出现，这个token的嵌入就几乎停留在随机初始化附近（见词嵌入层）。模型从没学过“看到它该怎么办”，这就是异常token（glitch token），也叫训练不足的token（under-trained token）。

怎么被发现的。2023年初，有研究者在分析GPT系列模型的嵌入空间时，发现一批token的嵌入异常地聚集在所有嵌入的中心附近，其中包括“ SolidGoldMagikarp”（一个Reddit用户名）、“ petertodd”等。让GPT-3或早期ChatGPT发布重复这些词时，模型会说出别的词、拒绝回答、甚至输出带攻击性的内容。原因被推测为：这些字符串在分词器训练所用的网页抓取数据里（例如某些计数类论坛的用户名）反复出现，但模型训练前的数据清洗把这些页面去掉了。这批token来自GPT-2起沿用的分词器。

为什么值得关心。

  • 可靠性：用户输入里偶然出现这种token，模型可能做出不可预期的回答。
  • 安全：它们可以被用来绕过安全训练，或触发奇怪的行为（见大模型越狱）。
  • 浪费：一部分词表容量和嵌入参数没有发挥作用（见词表大小的取舍）。

检测和预防。后来的工作提出了系统的检测方法：看嵌入向量是否异常接近“从未出现过的token”的嵌入，或输出层对应的行是否异常，再用提示测试模型能否复述它。预防的办法是让分词器和模型用一致的训练数据，训练后检查每个token在训练数据中的出现次数，或者从词表中删除计数极少的token。

例子

一个简化的检测流程：

1. 对词表里每个token，统计它在模型训练数据中出现的次数。发现token #X出现了0次，而它在分词器训练数据中出现了上万次。 2. 计算各token嵌入与“全部嵌入平均值”的距离：大多数token距离在1.5到3之间，#X只有0.1，紧挨着平均值——说明它几乎没被梯度更新过。 3. 提示模型“请原样重复下面的词：X”，模型却输出了另一个词。

（数字为示意。）三项证据一致，就可以判定它是异常token。

容易误解的地方

  • 异常token不一定是乱码，可能是看上去很正常的英文词或用户名，单看字面认不出来。
  • 修复了旧词表的问题，换新分词器时如果仍与训练数据不一致，同类问题还会出现。
