滑动窗口注意力

Sliding Window Attention

也叫：sliding window attention　滑动窗口注意力　滑窗注意力　local attention　局部注意力　windowed attention　窗口注意力　band attention　带状注意力　sliding window　局部-全局交替注意力　local-global attention　环形KV缓存　rolling buffer cache

在交互版中打开（看它长在树上的哪里）

每个token只关注它前面固定数量（窗口大小W）的token，而不是全部历史。计算量和KV缓存从随长度平方或线性增长变成固定上限；多层堆叠后，信息仍能间接传得比W更远。

先要会：自注意力与多头注意力 因果掩码

标准自注意力里，第n个token要和前面所有n个token计算分数（见自注意力与多头注意力），训练的计算量随长度平方增长，推理时的KV缓存随长度线性增长。可是很多时候，一个词最需要的是附近的上下文。滑动窗口注意力（sliding window attention，SWA，也叫局部注意力）只保留最近的W个位置。

定义。在因果掩码的基础上再加一个限制：位置i只能看到位置j满足i − W < j ≤ i。注意力矩阵从下三角变成一条宽度为W的对角带。

  • 每个token的计算量和需要缓存的K、V都固定为W个，与总长度无关。
  • 推理时KV缓存可以用一个大小为W的环形缓冲区，旧的K、V被新的覆盖。

感受野随层数扩大。第1层的位置i看到[i−W+1, i]；第2层看到的每个位置又各自看到前面W个，所以间接覆盖了约2W的范围；L层之后，理论上能覆盖约L×W个token，这与卷积网络堆叠扩大感受野的道理相同（见卷积层、池化与感受野）。不过信息每经过一层都会被稀释，远距离依赖传递得并不可靠。

谁在用。

  • Longformer滑窗注意力把滑窗注意力和少数“全局token”结合，用于长文档；BigBird稀疏注意力再加上随机注意力（见稀疏注意力与高效注意力）。
  • Mistral 7B在所有层使用滑窗注意力（窗口4096）。
  • Gemma 2和Gemma 3让局部滑窗层与全局注意力层交替排列，大部分层只需短的KV缓存，少数全局层负责长距离信息。这种“局部+全局混合”是当前长上下文模型的常见设计，与混合线性注意力架构的思路相近。

与注意力汇聚的关系。纯粹的滑动窗口在推理时把最早的token挤出窗口，可能导致输出突然崩坏；StreamingLLM与注意力汇聚发现保留开头几个token（注意力汇聚点）就能稳定住，见注意力汇聚。

例子

窗口W = 3，序列“A B C D E F”：

  • D只能看到B、C、D；看不到A。
  • F只能看到D、E、F。

但如果有2层：第1层中D已经从B、C那里拿到了信息；第2层中F看到D时，也间接获得了B、C的信息。2层、W = 3，F的有效视野约为5个token。

规模：一个32层、窗口4096的模型，理论感受野约13万个token，而每层每个token只需计算4096个注意力分数。

容易误解的地方

  • 理论感受野大不等于真能用好那么远的信息；需要精确回忆很远处内容的任务（如大海捞针，见长上下文评测），纯滑窗模型往往表现较差。
  • 训练和推理的窗口设置要一致，推理时随意改窗口大小会改变模型行为。
