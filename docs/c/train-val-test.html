训练集、验证集与测试集

Train / Validation / Test Split

也叫：dev set　开发集　held-out　交叉验证　cross-validation

在交互版中打开（看它长在树上的哪里）

把数据分成三份：训练集用来调参数，验证集用来选模型和超参数，测试集只在最后用一次，估计模型在新数据上的真实表现。

先要会：泛化与过拟合

要知道模型的泛化与过拟合能力，必须用它没见过的数据检验。但“没见过”这个要求比看上去更容易被打破，所以通常把数据分成三份：

  • 训练集（training set）：用来计算梯度、更新模型参数。
  • 验证集（validation set，也叫开发集dev set）：用来做所有“人为选择”——选哪个模型结构、学习率与学习率调度多大、训练多少步就停、正则化与权重衰减多强。这些超参数不由梯度决定，而是看哪个设置在验证集上最好。
  • 测试集（test set）：所有选择都做完以后，只用一次，报告最终结果。

为什么需要验证集和测试集两份：如果在测试集上试了100种超参数，选出最好的那个报告，那么这个分数就带了“挑选”的乐观偏差——你实际上用测试集训练了超参数。验证集吸收了这部分偏差，测试集才能保持干净。常见的比例是80%/10%/10%，数据少时可以用交叉验证：把数据分成k份，轮流用其中一份验证，取平均。

测试集也会“被用旧”：一个公开基准被整个领域反复使用多年，每篇论文都参考前人的测试分数来改进方法，集体上也是在测试集上调参。自适应过拟合与可复用holdout研究了这种自适应过拟合；ImageNetV2：榜单过拟合了吗按原流程重新收集了一份ImageNet测试集，发现各模型的准确率普遍下降了11%到14%，但在原测试集上更好的模型在新测试集上也更好；作者认为下降并非来自自适应过拟合，而是模型难以泛化到比原测试集稍“难”一些的图片。

更严重的是测试数据混进了训练数据，见数据泄漏与基准污染。

例子

10000个样本，按8000/1000/1000划分。

测试集只有1000个样本时，若真实准确率是90%，测得准确率的标准误约为√(0.9×0.1/1000) ≈ 0.0095，即约±1个百分点。两个模型在这个测试集上差0.5个百分点，很可能只是抽样噪声，见方差、种子与统计显著性。

容易误解的地方

  • 划分要按“独立单位”来：同一个病人的多张片子、同一段视频的相邻帧、同一篇文章的不同段落应当分在同一份里，否则测试集会泄漏训练信息。
  • 时间序列数据要按时间切分（用过去训练、用未来测试），随机打乱会让模型“看到未来”。
