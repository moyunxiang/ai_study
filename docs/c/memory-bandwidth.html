显存、内存带宽与“内存墙”

VRAM, Memory Bandwidth and the Memory Wall

也叫：HBM　访存瓶颈　memory-bound

在交互版中打开（看它长在树上的哪里）

显存容量决定模型放不放得下，内存带宽决定每秒能把多少数据送进计算单元；算力增长远快于带宽增长，许多AI计算的速度其实被搬数据卡住，这叫“内存墙”。

先要会：CPU、GPU与并行计算 浮点精度：FP32、FP16、BF16、INT8

芯片的计算单元只能处理已经送到身边的数据。参数、激活值都存在显存（GPU上的DRAM）里，每次计算前要先读进芯片。如果读数据的速度跟不上算的速度，再多的TFLOPS也只能空等。

三个数要分清。一是容量：显存有多少GB，决定模型和KV缓存放不放得下，例如H100为80GB，H200：141GB HBM3e为141GB，消费级的RTX 4090与本地大模型为24GB。二是带宽：每秒能读写多少字节，H100为3.35TB/s，RTX 4090约1TB/s。三是算力：每秒能做多少次运算，H100的BF16稠密约989 TFLOPS。

算术强度与Roofline。一个计算每读1字节数据做多少次运算，叫算术强度（FLOP/byte）。芯片也有一个“平衡点”：算力 / 带宽，H100约为989×10¹² / 3.35×10¹² ≈ 295。算术强度低于这个数的计算是带宽受限的，高于它才是算力受限的。这套分析叫Roofline性能模型模型。大矩阵乘法强度很高，属于算力受限；逐元素运算（加偏置、激活函数、归一化）强度极低，属于带宽受限，所以要把它们“融合”进同一个内核，少读写几次显存，FlashAttention就是把注意力计算融合以减少显存读写。

大模型生成文本时为什么慢。逐token生成时，每生成一个token都要把全部权重读一遍，却只对一个token做运算，算术强度约为1，远低于295，几乎完全卡在带宽上。这就是为什么推理时要做批处理（见吞吐、延迟与批处理），为什么量化能直接提速，为什么AI芯片都用昂贵的HBM高带宽内存。

内存墙。1995年就有人指出处理器速度增长快于内存速度，见内存墙；AI与内存墙统计过去二十年硬件峰值算力增长远快于内存带宽和互连带宽。这让HBM成为AI芯片供应链里最紧缺的部件之一，见芯片供应链：设计、代工、封装、内存。

例子

7B模型FP16权重共14GB。批大小为1逐token生成时，每个token至少要读14GB：在RTX 4090（约1TB/s）上至少需要约14毫秒，上限约72 token/s；在H100（3.35TB/s）上至少约4.2毫秒，上限约240 token/s。而每个token的计算量只有约2 × 7×10⁹ = 1.4×10¹⁰次运算，H100用不到0.015毫秒就能算完——绝大部分时间都在等数据。换成4位量化后只需读3.5GB，理论上限提高到约4倍。

容易误解的地方

  • 显存容量和带宽是两回事：Apple的统一内存可以有几百GB容量，但带宽低于高端GPU，大模型能装下却生成得慢。
  • 厂商标的带宽是理论峰值，实际能用到的通常只有七八成。
  • “GPU利用率100%”只说明GPU一直有任务在跑，不代表计算单元都在忙，带宽受限的任务也会显示满载。
