向量化环境与并行采样

Vectorized Environments

也叫：向量化环境　vectorized environment　vectorized environments　VecEnv　并行环境　parallel environments　多环境并行　SubprocVecEnv　DummyVecEnv　环境并行　自动重置　auto-reset　GPU并行仿真　批量环境

在交互版中打开（看它长在树上的哪里）

同时运行N个环境副本，把它们的观测拼成一个批次送进策略网络，一次前向得到N个动作。这样既用满了GPU的并行能力，又让每次更新的数据更多样，是现代RL训练的标准做法。

先要会：轨迹、回合与rollout CPU、GPU与并行计算

单个环境一步一步地跑，每一步策略网络只处理一个观测，GPU几乎闲着；而环境模拟本身（尤其是Python写的游戏）又常常占满一个CPU核。向量化环境把N个环境副本组织在一起，对外表现得像一个“批量的环境”：reset()返回N个观测，step(N个动作)返回N个(观测, 奖励, 终止, 截断)。

为什么有用。

  • 吞吐：策略网络一次处理N个观测，摊薄了每次前向的开销。
  • 数据去相关：同一个环境连续的转移高度相关；来自N个独立环境的数据更接近独立同分布，同策略算法（如PPO、A3C的同步版本A2C）因此可以不依赖经验回放也稳定训练，见OpenAI Baselines与A2C。

几种实现方式。

  • 同步串行：在一个进程里逐个调用N个环境，最简单，适合很快的环境。
  • 多进程：每个环境放在单独的进程里并行运行，绕开Python的全局解释器锁，适合较慢的环境。最慢的那个环境决定每一步的耗时。
  • 异步：不等所有环境都完成，先返回已经完成的那部分，EnvPool并行环境引擎用C++线程池实现了高吞吐的同步和异步模式，Sample Factory单机高吞吐RL在单机上把异步采样做到很高的帧率。
  • 在加速器上：把物理仿真本身写在GPU/TPU上，成千上万个环境作为张量一起推进，数据不必在CPU和GPU之间来回拷贝，例如Isaac Gym大规模并行仿真和Brax加速器物理引擎，见仿真到现实的差距。

自动重置。N个环境的回合长度不同，向量化环境通常在某个副本结束时自动重置它，并在返回的信息里附上结束前的最后观测。要正确处理终止与截断（见时域、分幕任务与终止），就必须用到这个“最后观测”来自举价值，这是常见的实现细节错误之一。

例子

PPO用N=16个Atari环境，每轮每个环境跑128步，一轮共收集16×128=2048个转移。若单环境每秒只能跑1000步、网络推理每次2毫秒：串行单环境每步约3毫秒，约每秒330步；16个多进程环境加批量推理，每步约3毫秒但一次得到16个转移，约每秒5000步以上（数字为示意，实际取决于环境和硬件）。

容易误解的地方

  • 环境数太多时，每轮的数据来自同一时刻的很多回合开头，可能使早期训练过度偏向回合起始阶段；长回合任务要注意rollout长度与N的平衡。
  • 每个环境副本要用不同的随机种子，否则N个副本跑出完全相同的轨迹，并行就失去了意义。
