任务与运动规划（TAMP）

Task and Motion Planning

也叫：任务与运动规划　TAMP　task and motion planning　task-and-motion planning　逻辑几何规划　logic-geometric programming　LGP　PDDLStream　长时程操作规划　long-horizon manipulation planning

在交互版中打开（看它长在树上的哪里）

任务与运动规划把两层问题一起解：上层用符号规划决定做哪些动作、按什么顺序，下层用运动规划检查每个动作在几何上能否实现，不行就回到上层换方案。

先要会：规划与模型预测控制 关节空间、任务空间与构型空间

让机器人“把杯子从柜子里拿出来放到桌上”，涉及两类不同的问题：

  • 任务规划：离散的、符号层面的推理。先开柜门，再抓杯子，再关门（还是不关？），再放下。经典工具是STRIPS规划和PDDL规划描述语言描述的状态—动作模型，用搜索求出动作序列（见图、树与搜索和命题逻辑、谓词逻辑与符号推理）。
  • 运动规划：连续的、几何层面的问题。给定起止构型，在避开障碍的前提下找一条关节轨迹（见关节空间、任务空间与构型空间），常用RRT快速随机树、PRM概率路图等采样方法或轨迹优化，配合碰撞检测。

为什么不能分开解。符号规划器以为“抓杯子”总是可行，但杯子可能被挡在后面，手臂够不到；或者抓取的姿势决定了放下时能不能放进狭窄的位置。两层之间互相依赖：几何上的可行性决定哪些符号计划能执行，而符号计划决定要解哪些几何问题。

TAMP的做法。在两层之间来回迭代：

1. 符号规划器给出一个候选动作序列； 2. 为每个动作采样具体的连续参数（抓取位姿、放置位置、轨迹），用运动规划器检查是否可行； 3. 若某一步失败，把失败原因（如“这个位置被挡住”）反馈给上层，生成新的约束或换一个计划。

代表性框架有把连续采样器集成进PDDL的方法，以及把整个问题写成混合整数或非线性优化的“逻辑—几何规划”。难点在于搜索空间极大、几何检查代价高，长任务上可能很慢。

与学习方法的结合。

  • 用学习到的模型预测哪些动作可行、哪些抓取更可能成功，减少无效的几何检查。
  • 大语言模型接管上层：把自然语言指令分解成步骤，由传统规划器或学到的技能执行底层动作，例如SayCan用价值函数评估每一步的可行性，Code as Policies让模型直接写调用感知和运动原语的代码（见提示链与智能体工作流）。
  • 端到端的VLA与WAM的基本结构试图直接从图像和指令输出动作，不显式区分两层，但在长时程任务上常与高层规划配合（见快慢双系统VLA）。

例子

任务：把红色方块放进抽屉。符号计划A：“打开抽屉 → 抓方块 → 放进抽屉”。运动规划发现抽屉拉开后挡住了方块，抓不到，第二步失败。反馈给上层后得到计划B：“抓方块 → 放到桌面空处 → 打开抽屉 → 再抓方块 → 放进抽屉”，每一步几何检查都通过，执行成功。纯符号规划不知道“抽屉会挡住方块”，纯运动规划不知道“需要先开抽屉”。

容易误解的地方

  • TAMP依赖准确的环境模型（物体位置、形状、抽屉怎么打开），感知误差或模型不准时，规划出的方案可能在真实世界中失败，需要闭环重规划。
  • 符号层面的领域描述通常需要专家手写，换一个新任务或新环境的迁移成本高。
