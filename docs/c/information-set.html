信息集与不完全信息博弈

Information Sets and Imperfect-Information Games

也叫：信息集　information set　infoset　不完全信息博弈　imperfect information game　incomplete information　扩展式博弈　extensive-form game　博弈树　完美回忆　perfect recall　公共信念状态　public belief state　诈唬　bluffing

在交互版中打开（看它长在树上的哪里）

不完全信息博弈里，一个玩家无法区分的所有博弈状态构成一个信息集。玩家只能按信息集而不是真实状态决策，这让扑克这类游戏不能像围棋那样逐个局面求解。

先要会：博弈论基础与纳什均衡 博弈树搜索：minimax与MCTS

围棋和国际象棋是完全信息博弈：棋盘对双方都完全可见，每个局面都可以单独分析，博弈树搜索：minimax与MCTS直接适用。扑克、桥牌、斗地主、外交游戏则不同：你看不到对手的牌。从你的角度看，对手持有AA和持有72时的局面完全一样，但它们在博弈树里是两个不同的节点。

扩展式博弈与信息集。用一棵博弈树描述轮流行动的博弈，叶子上标收益，“发牌”等随机事件由一个虚拟的“机会”玩家完成。对每个玩家，把他在行动时无法区分的那些节点归为一组，这一组就是一个信息集。策略的定义因此改为：在每个信息集上给出一个动作分布，而不是在每个节点上。一个玩家记得自己过去所有的观察和动作，叫完美回忆，大多数游戏和算法都假设这一点。

为什么难。

  • 不能分而治之：在完全信息博弈里，一个子树的最优走法与其他子树无关；在不完全信息博弈里，一个子博弈的正确策略依赖于对手认为你在这里的概率，而这又取决于你在其他地方怎么玩。所以博弈树搜索：minimax与MCTS那样的逐局面搜索不能直接使用。
  • 最优策略必须随机：总是有好牌才加注，对手就能读出你的牌，所以需要诈唬，见博弈论基础与纳什均衡。
  • 规模巨大：一对一无限注德州扑克的决策点数量远超可以穷举的范围，需要抽象和近似。

算法。反事实遗憾最小化CFR在每个信息集上做遗憾最小化，平均策略收敛到纳什均衡，见遗憾与遗憾界；序列式博弈表示把问题写成线性规划；DeepStack和Libratus用安全的子博弈求解（安全嵌套子博弈求解）在对局中实时细化策略；ReBeL把“公共信念状态”（所有玩家对私有信息的概率分布）当作新的状态，使搜索重新变得可行。单智能体中与之对应的概念是POMDP规划里的信念状态。

例子

简化扑克：一副牌只有J、Q、K三张，两人各发一张。玩家1拿到K时，对手可能拿J或Q，这两个节点玩家1无法区分，组成一个信息集；玩家1在这个信息集上只能选一个动作分布，比如“加注概率0.9”。若他在拿J时从不加注，对手看到加注就可以确定他不是J，所以均衡策略要求拿J时也以一定概率加注（诈唬）。

容易误解的地方

  • 不完全信息（看不到对手私有信息）与不完美信息（不知道对手刚才做了什么，如同时行动）在博弈论中是不同的术语，中文文献常混用。
  • 信息集定义在单个玩家的视角上，同一个节点对不同玩家属于不同的信息集。
