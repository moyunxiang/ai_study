自我反思与自我修正

Self-Reflection and Self-Correction

也叫：self-reflection　自我反思　self-correction　自我修正　自我纠错　self-refinement　自我改进　self-critique　自我批评　自我验证　反思　reflection　迭代修改　iterative refinement　critique and revise

在交互版中打开（看它长在树上的哪里）

让模型检查、批评并修改自己的输出：先生成答案，再生成对答案的评价，然后根据评价改写。有外部反馈（报错、测试结果、检索证据）时效果明显；只靠模型自己判断时，效果常常有限。

先要会：上下文学习与提示 智能体循环

人写东西会先打草稿再修改。语言模型生成时是一次从左到右写完的（见自回归生成），写错了也没有回头改的机会。自我反思（也叫自我修正、自我改进）把“回头看”变成显式的多轮流程：

1. 生成：给出初始答案。 2. 反馈：让模型（或外部工具）指出答案的问题。 3. 修改：根据反馈重写，必要时重复几轮。

代表方法。

  • Self-Refine自我改进：同一个模型轮流扮演写作者和评审者，在代码优化、对话回复等任务上迭代改进。
  • Reflexion：智能体任务失败后，让模型用文字总结“哪里做错了、下次该怎么做”，把这段反思存进记忆，在下一次尝试时放进提示（见智能体记忆）。
  • CRITIC借工具自我纠错：让模型调用搜索、代码解释器等工具来验证自己的答案，再根据工具的反馈修改。
  • 自我验证反向验算：把答案代回题目反向验算。

关键问题：反馈从哪来。自我纠错的局限的实验发现，在推理任务上，如果没有外部信号（比如不告诉模型答案是否正确），只让模型“检查一下你的答案”，修改后的准确率常常不升反降——模型会把对的改错。早期一些报告的提升，部分来自用了正确答案来决定何时停止修改。由此得到的经验是：

  • 有可靠的外部反馈（编译错误、单元测试、检索到的证据、环境返回的结果）时，自我修正很有效，这也是编程智能体能反复调试代码的原因（见智能体循环）。
  • 只靠内部判断时，模型发现自己错误的能力有限，效果取决于任务和模型。

训练出来的反思。与其靠提示，不如直接训练模型学会修正：SCoRe强化学习自我纠错用强化学习训练多轮自我修正；推理模型（见推理token与测试时计算）在长思维链里自发出现“等一下，这里好像不对”的检查和回溯行为，可以看作把反思内化到了单次生成之中（见可验证奖励强化学习（RLVR））。

例子

任务：写一个函数判断质数。

  • 第1轮生成：for i in range(2, n): if n % i == 0: return False; return True
  • 外部反馈：运行测试，is_prime(1)返回True，与期望的False不符。
  • 第2轮修改：在开头加上if n < 2: return False，测试全部通过。

对比：若没有测试，只问模型“请检查你的代码有没有错误”，它可能回答“代码正确”，也可能把本来正确的循环范围改成range(2, n−1)而引入新错误。

容易误解的地方

  • 每一轮反思都要额外调用模型，成本成倍增加；在没有外部反馈的任务上，先确认它真的有提升。
  • 评测自我修正方法时，不能用标准答案来决定何时停止修改，否则会高估效果。
