注意力汇聚

Attention Sinks

也叫：attention sink　attention sinks　注意力汇聚　注意力汇点　注意力沉没　注意力黑洞　sink token　汇聚token　BOS注意力　StreamingLLM　massive activations　softmax加一　softmax-off-by-one　registers

在交互版中打开（看它长在树上的哪里）

大语言模型的很多注意力头会把大量权重分配给序列开头的一两个token（常是BOS），即使它们语义上不重要。这些位置像一个“垃圾桶”，吸收头不需要用到的注意力。去掉它们，模型输出会崩溃。

先要会：自注意力与多头注意力 Softmax与logits

softmax的输出必须加起来等于1（见Softmax与logits）。如果一个注意力头在当前位置“没什么要看的”，它也不能把所有权重设为0，总得分配到某些位置上。研究者发现，训练好的语言模型找到了一个省事的办法：把多余的权重全部倒给序列最开头的token。这种现象叫注意力汇聚（attention sink），那几个token叫汇聚点。

为什么是开头。在因果掩码之下，序列第一个token能被后面所有位置看到，是唯一一个“永远在场”的位置，于是成了天然的公共垃圾桶。它的值向量通常很小，权重倒过去也几乎不改变输出，相当于“不看”。

StreamingLLM与注意力汇聚的发现（2023）。用滑动窗口注意力的方式处理超长的流式输入时，一旦最早的token被挤出窗口，模型的困惑度会突然飙升、输出变成乱码。原因正是汇聚点被丢掉了：那些本来倒向开头的注意力权重只能被强行分配到别的token上，打乱了表示。只要始终保留开头的少数几个token的KV（论文中用4个），再加上最近的滑动窗口，模型就能在远超训练长度的流式文本上保持稳定的困惑度。论文还提出预训练时加入一个专门的可学习“汇聚token”。

与别的现象的联系。

  • 巨量激活发现极少数位置和维度上存在比其余大几个数量级的激活值，它们与汇聚点相关，也是量化时的一个难点（见激活离群值与旋转量化）。
  • KV缓存压缩方法（见KV缓存压缩）普遍会特意保留汇聚点。
  • 门控注意力在注意力输出后加一个门控，发现可以显著减少汇聚现象，并改善训练稳定性和长上下文外推。
  • 还有工作在softmax的分母里加1（或者加一个可学习的偏置），允许注意力“什么都不看”，从根源上消除对汇聚点的需求。

对可解释性的提醒。看注意力热力图时，开头token上的高权重大多是汇聚现象，不代表模型真的在“关注”那个词。

例子

一个8层模型处理一段1000个token的文本，统计各头的平均注意力分布：第1个token（BOS）平均得到约40%的权重，其余999个token分享另外60%。BOS本身只是一个起始符，没有内容。

流式推理实验：窗口1024，处理到第5000个token时，只保留最近1024个token，困惑度从约10突然跳到几百；保留“最初4个token + 最近1020个token”，困惑度维持在约10。

（数字为示意。）

容易误解的地方

  • 汇聚点不一定是BOS：有时是第一个换行符、句号或其他高频token，取决于模型。
  • 截断上下文或压缩KV缓存时，若不保留汇聚点，效果可能断崖式下跌，而且问题很难从日志里直接看出来。
