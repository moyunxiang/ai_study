行为树与有限状态机

Behavior Trees and Finite State Machines

也叫：行为树　behavior tree　behaviour tree　有限状态机　finite state machine　FSM　状态机　state machine　分层状态机　hierarchical state machine　HFSM　BehaviorTree.CPP　顺序节点　sequence node　选择节点　fallback node　selector node　机器人任务编排　robot task orchestration

编排机器人与游戏AI行为的两种常用结构：有限状态机用“状态 + 转移条件”描述行为；行为树用顺序、选择等控制节点组成树，每周期从根往下执行，更模块化、易扩展复用。

先要会：状态、观测与动作 图、树与搜索

一个送餐机器人要：找到桌号 → 导航过去 → 遇到行人就停下等待 → 到达后提醒顾客取餐 → 电量低就回去充电。这些行为之间的切换逻辑必须写清楚。传统上有两种主流写法。

有限状态机（FSM）。系统在任一时刻处于一个状态（导航中、等待、送达、充电），每个状态定义要做什么，以及在什么条件下转到哪个状态（“检测到行人 → 等待”，“行人离开 → 导航中”）。简单直观，但状态一多，转移的连线就爆炸增长：每加一个“电量低”这样的全局条件，几乎每个状态都要加一条转移，难以维护。分层状态机可以缓解这一问题。

行为树（BT）。行为树起源于游戏AI，后来广泛用于机器人（ROS 2的导航框架就以它为核心）。叶节点是动作（“导航到桌子”）或条件（“电量是否高于20%”），内部节点是控制流：

  • 顺序节点：依次执行子节点，任何一个失败就整体失败（“导航 → 提醒取餐”）；
  • 选择（回退）节点：依次尝试子节点，直到有一个成功（“如果能走主路就走，否则走备用路线，否则请求帮助”）；
  • 并行节点：同时执行多个子节点；
  • 装饰节点：对单个子节点做修饰，如重试、取反、超时。

每个控制周期从根节点发出一次“tick”，节点返回成功、失败或运行中。因为每次都从根开始重新评估，高优先级的条件（如“电量低”）放在左侧分支，就能随时打断低优先级的任务，反应性很好；子树可以像函数一样复用和组合。

与学习方法的关系。行为树和状态机是显式的、人写的逻辑，可解释、可验证；学习得到的策略（见策略与价值函数和模仿学习与行为克隆）更擅长处理感知和连续控制。实际系统常把两者结合：行为树负责高层任务编排和安全兜底，叶节点调用学到的技能或VLA与WAM的基本结构模型；也有工作让大语言模型自动生成行为树（类似提示链与智能体工作流中的编排思路）。在强化学习里，“选项”和分层策略也是对行为进行模块化组织的尝试（见分层强化学习与时间抽象）。

例子

送餐机器人的行为树（从左到右优先级递减）：

根：选择节点

  • 顺序［条件：电量 < 20%］→［动作：回充电桩］
  • 顺序［条件：前方有行人］→［动作：停车等待］
  • 顺序［动作：导航到目标桌］→［动作：语音提醒取餐］→［动作：返回待命点］

每100毫秒tick一次。送餐途中电量跌破20%，下一次tick第一个分支就成功执行，送餐被打断；用状态机实现同样效果，需要从每个状态都加一条转到“充电”的连线。

容易误解的地方

  • 行为树每次从根重新评估，如果动作没有正确返回“运行中”，长时间的动作可能被反复重启。
  • 树变大后同样难以调试，需要可视化工具和清晰的节点命名；它并不能替代对感知与控制本身的可靠性设计。
