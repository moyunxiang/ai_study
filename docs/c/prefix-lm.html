前缀语言模型

Prefix Language Model

也叫：prefix LM　prefix language model　前缀语言模型　前缀LM　非因果解码器　non-causal decoder　前缀双向注意力

在交互版中打开（看它长在树上的哪里）

介于编码器和解码器之间的一种掩码设计：输入前缀部分的token彼此双向可见，之后要生成的部分只能看左边。一个网络同时有“读懂输入”和“逐词生成”的能力。

先要会：因果掩码 仅编码器、仅解码器与编码器-解码器

仅解码器模型读输入时也是单向的：提示里第1个词看不到第2个词，这对理解输入是一种浪费。编码器-解码器能双向读输入，但要两套参数。前缀语言模型（prefix LM）用一个网络、一种掩码折中二者（见仅编码器、仅解码器与编码器-解码器）。

掩码。把序列分成前缀（输入、条件）和目标（要生成的部分）。设前缀长度为p：

  • 前缀内部：任意两个位置互相可见（双向）。
  • 目标部分的位置i：能看到全部前缀和目标里不晚于i的位置（因果）。
  • 前缀位置看不到目标部分。

损失只在目标部分计算。整个掩码是左边一块全1、右下角一个下三角，可以和普通因果掩码对照着看。

出处与使用。UniLM用同一个Transformer切换不同掩码，同时训练双向、单向和序列到序列三种目标；T5的论文把前缀LM当作与编码器-解码器、纯解码器并列的结构做了系统比较；UL2混合去噪的混合去噪训练里也用到这种形式。GLM空白填充的“空白填充”同样让已知部分双向可见、待填部分自回归生成。

为什么没成为主流。前缀LM在需要读懂长输入再生成的任务上有优势，但它让训练目标只覆盖序列的一部分，每条数据提供的监督信号比纯因果LM少；推理时前缀的表示依赖整个前缀，多轮对话中新内容加入后，旧前缀的缓存不能直接复用。大规模下，纯解码器的简单性占了上风。多模态模型里，把图像token设为彼此双向可见、文字部分因果，是一种常见的局部采用。

例子

前缀是“翻译：你好”（3个token：翻译、：、你好），目标是“hello <eos>”（2个token）。5×5掩码（1表示可见）：

翻译 [1,1,1,0,0] ： [1,1,1,0,0] 你好 [1,1,1,0,0] hello[1,1,1,1,0] <eos>[1,1,1,1,1]

纯因果LM里“翻译”那一行会是[1,0,0,0,0]，看不到后面的“你好”。损失只算在“hello”和“<eos>”两个位置。

容易误解的地方

  • prefix LM（前缀语言模型）和prefix tuning（前缀微调，一种参数高效微调方法）名字相近，但毫无关系。
  • 用前缀LM方式训练的模型，推理时也要按同样的掩码组织输入，否则前缀部分的表示和训练时不一致。
