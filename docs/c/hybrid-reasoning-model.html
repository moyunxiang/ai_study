混合推理模型与思考预算

Hybrid Reasoning Models and Thinking Budgets

也叫：混合推理模型　混合推理　hybrid reasoning model　hybrid reasoning　混合思考　hybrid thinking　思考模式　thinking mode　非思考模式　non-thinking mode　思考开关　thinking toggle　思考预算　thinking budget　reasoning budget　推理强度　reasoning effort　按需推理　自适应思考　adaptive thinking

在交互版中打开（看它长在树上的哪里）

同一个模型既能直接回答，也能先长时间“思考”再回答，由用户、开发者或模型自己选择模式，或用思考预算控制想多久。这样不必维护两个模型，简单问题也不必付出长推理的代价。

先要会：推理token与测试时计算 指令微调与对话模板

背景。OpenAI o1推理模型、DeepSeek-R1这类推理模型在回答前生成很长的思维链（见推理token与测试时计算），数学、代码等难题上大幅领先，但代价明显：简单的问候也可能“想”上几百个token，延迟高、费用高，还会出现“想太多”的问题（见高效推理与过度思考）。早期的做法是并存两个模型：一个快的对话模型、一个慢的推理模型，由用户手动选择。

混合推理把两种能力放进同一个模型：

  • 显式开关：通过系统提示、对话模板中的特殊标记或API参数开启或关闭思考模式。Qwen3混合思考在同一个模型里支持“思考”和“非思考”两种模式，可在对话中用指令切换；Claude可见扩展思考让Claude在同一个模型上按需开启可见的扩展思考。
  • 思考预算：允许设定思考token的上限，或者给出低、中、高几档推理强度，在质量和成本之间连续调节。s1与预算强制的“预算强制”是一种在推理时控制思考长度的简单方法：到了上限就强行结束思考，想让它多想时则在它准备结束时追加“等一下”。
  • 自动路由：由系统根据问题难度自动决定是否思考、思考多久。GPT-5的产品形态包含一个在快速模型与深度推理模型之间自动分配请求的路由器。

怎么训练。常见流程是先得到一个强推理模型，再在微调数据中混入带思考过程和不带思考过程的样本，并用对话模板中的标记区分（见指令微调与对话模板）；再通过强化学习让模型在给定预算内尽量做对（见智能体强化学习）。难点在于两种模式互相干扰：加入大量长思考数据可能让非思考模式也变得啰嗦，反之亦然。

评测时要注意。同一个模型在不同模式和预算下的分数差距可能很大，比较模型时必须写清楚用的是哪种模式、多大的思考预算（见可复现性）；推理强度提高带来的分数增长，本质上是测试时计算量的增加。

例子

同一个模型回答两个问题：

  • “法国的首都是哪里？”非思考模式直接答“巴黎”，约5个输出token。
  • 一道竞赛级几何题：开启思考、预算8000 token，模型先写出几千token的推导再给答案；预算降到1000 token时，它更可能给出不完整的推导，正确率下降。

如果把所有请求都放在思考模式下运行，第一类简单请求的平均延迟和费用可能增加数十倍。（数字为示意）

容易误解的地方

  • “关闭思考”不等于模型完全不推理：非思考模式下它仍可能在答案里写出推理过程，只是没有单独的思考段。
  • 自动路由判断错误时，难题可能被分到快速模式而答错，用户不一定察觉。
