图、树与搜索

Graphs, Trees and Search

也叫：图论　graph theory　BFS　DFS　广度优先搜索　深度优先搜索　最短路径　树搜索

在交互版中打开（看它长在树上的哪里）

图由节点和连接节点的边组成，树是没有环的连通图。把问题建模成图之后，“求解”就变成了在图上搜索一条路径。

先要会：时间与空间复杂度

早期AI把智能理解为“搜索”：下棋是在所有可能的走法里找一条通向胜利的路，规划是找一串把当前状态变成目标状态的动作，定理证明是找一串推理步骤。这些问题的共同结构是图。今天，图还被直接用来表示分子、社交网络和知识。

定义。图G = (V, E)，V是节点集合，E是边集合。边可以有方向（有向图）、可以带权重（如距离或代价）。树是连通且无环的图，有一个根节点，每个节点有若干子节点。博弈中，根是当前局面，子节点是走一步之后的局面，这棵树叫博弈树。计算机里常用邻接表或邻接矩阵存储图。

基本搜索。

  • 广度优先（BFS）：一层一层向外扩展，在每条边代价相同时找到步数最少的路径。
  • 深度优先（DFS）：沿一条路走到底再回头，内存省，但未必最短。
  • A*：每次扩展f(n) = g(n) + h(n)最小的节点，g是已走代价，h是对剩余代价的估计。只要h从不高估，A*找到的就是最优路径。

组合爆炸。每个节点平均有b个分支、要看d步，树的大小约为bᵈ，见时间与空间复杂度。搜索算法的全部功夫都花在“少看一些节点”上：剪枝、启发式、采样。

它出现在哪里。通用问题求解器GPS把问题求解建模成状态空间搜索；A*诞生于Shakey机器人机器人项目；深蓝战胜卡斯帕罗夫靠alpha-beta剪枝在国际象棋博弈树上深度搜索；蒙特卡洛树搜索UCT用随机模拟代替穷举，后来成为AlphaGo的骨架，见博弈树搜索：minimax与MCTS。图也是一类数据：图卷积网络等图神经网络直接在图结构上学习，见图神经网络与消息传递。

例子

国际象棋每个局面平均约有35种合法走法。只往前看4步（双方各2步），博弈树就有约35⁴ ≈ 150万个叶子；看10步就是约2.8×10¹⁵个。围棋每步约有250种选择，同样深度下的树要大得多，这就是穷举搜索在围棋上失效的原因。

容易误解的地方

  • 树搜索中同一个局面可能通过不同走法到达，不去重就会重复计算；把树换成图（并记录访问过的节点）可以避免。
  • A*的最优性依赖于启发函数不高估剩余代价；用了高估的启发函数，搜索会更快，但不再保证最优。
