梯度累积

Gradient Accumulation

也叫：梯度累积　gradient accumulation　梯度累加　accumulate gradients　微批　micro-batch　microbatch　等效批大小　effective batch size　累积步数　accumulation steps　no_sync

在交互版中打开（看它长在树上的哪里）

显存放不下想要的批大小时，把一个大批拆成k个小批依次前向、反向，梯度先累加不更新，攒满k次后再做一次参数更新。效果上等价于用k倍大的批训练，代价是更慢。

先要会：批大小、步数与轮数 反向传播 随机梯度下降与小批量

大模型训练常常需要每步上百万个token的批（见批大小、步数与轮数），而一张GPU一次只放得下几个样本：前向传播的激活值随批大小线性增长（见训练显存的组成：参数、梯度、优化器状态与激活）。梯度累积用时间换显存。

做法。设目标批大小为B，每次只能放下b = B/k个样本：

  • 对第1到第k个小批，各做一次前向和反向，把梯度加到参数的梯度缓存上（不清零、不更新）；
  • k次之后，用累加的梯度做一次优化器更新，再把梯度清零。

由于损失通常是批内平均，每个小批的损失要先除以k（或者最后把梯度除以k），累加结果才等于大批平均损失的梯度。在PyTorch里，就是把optimizer.step()和zero_grad()改为每k步调用一次。

和真正的大批有什么不同。

  • 对于梯度本身，数学上完全等价（忽略浮点舍入顺序）。所以学习率等超参数应按等效批大小B来设置。
  • 归一化层里的批归一化按小批统计均值方差，与大批不等价；Transformer常用的层归一化不受影响。
  • 速度不变快：总计算量相同，但k个小批是串行的，GPU利用率可能比一个大批低。

在分布式训练中。数据并行时，每个小批反向后都做一次all-reduce很浪费，通常只在累积的最后一步同步梯度（DDP的no_sync），见分布式训练：数据并行与模型并行和集合通信原语：all-reduce、all-gather与all-to-all。等效全局批大小 = 每卡小批大小 × 累积步数 × 数据并行卡数。流水线并行（如GPipe流水线并行）把一个批切成多个微批依次流过各段，本质上也是在做梯度累积。

与其他省显存手段的关系。梯度检查点用重算换激活显存，ZeRO与DeepSpeed和PyTorch FSDP把参数、梯度、优化器状态切分到多卡，混合精度降低每个数的字节数（见浮点精度：FP32、FP16、BF16、INT8），它们常与梯度累积同时使用。

例子

目标全局批大小512条序列，8张卡数据并行，每卡一次只能放4条。所需累积步数为512 / (8 × 4) = 16：每张卡做16次前向反向，每次损失除以16，最后一次反向时才跨卡all-reduce并更新参数。若忘记除以16，相当于把学习率放大了16倍。

容易误解的地方

  • 累积时忘记把损失除以k，或者在每个小批后都清零了梯度，是最常见的两个bug。
  • 损失按token平均时，各小批的有效token数可能不同，直接除以k与按全部token平均会有偏差，严格做法是按总token数归一化。
