梯度累积

Gradient Accumulation

也叫：梯度累积　梯度累加　gradient accumulation　grad accumulation　accumulation steps　累积步数　gradient_accumulation_steps　微批　micro-batch　microbatch　有效批大小　effective batch size　全局批大小　global batch size

显存放不下想要的批大小时，把一个大批次拆成几个小批次依次前向、反向，梯度先累加起来，攒够了再更新一次参数。效果上等价于用大批次训练，代价是更慢。

先要会：随机梯度下降与小批量 批大小、步数与轮数 反向传播

训练时希望用较大的批大小（见批大小、步数与轮数）：梯度噪声更小、训练更稳，很多论文给出的超参数也是在大批次下调好的。但一个批次的激活值要全部存在显存里等待反向传播（见参数量、计算量与显存），单张GPU可能只放得下8个样本，而配方要求256。

做法。设想要的批大小是B，每次只能放下b，令k = B / b：

1. 清零梯度； 2. 循环k次：取一个大小为b的小批次，前向算损失，把损失除以k，反向传播，梯度自动累加到参数的.grad上； 3. 循环结束后调用一次优化器更新参数，再清零。

因为总损失是k个小批次损失的平均，累加出来的梯度与一次性用B个样本算出的梯度在数学上相同（见随机梯度下降与小批量）。

它和其他省显存手段的关系。

  • 梯度检查点：不存中间激活、反向时重算，用计算换显存，可以与梯度累积同时使用。
  • 数据并行（见分布式训练：数据并行与模型并行）：多张卡各算一部分样本再把梯度平均，相当于在“空间”上累积；梯度累积是在“时间”上累积。实际的大模型训练里，全局批大小 = 每卡微批大小 × 累积步数 × 数据并行卡数。
  • 混合精度训练训练时，梯度累积通常在FP32的主梯度上进行，避免多次相加的精度损失。

不完全等价的地方。依赖批内统计量的层会表现不同：Batch Normalization在每个小批次上分别计算均值和方差，小批次太小时统计量很不准，这也是大模型普遍改用LayerNorm的原因之一（见归一化层）。另外，学习率调度和预热按“优化器步数”而不是“小批次数”计算。

例子

目标批大小256，单卡最多放下32个样本，于是累积8步：每个小批次的损失除以8再反向，8次后更新一次。若有4张卡做数据并行、每卡微批32，只需累积2步就能得到256的全局批大小。代价：单卡时每次参数更新要串行做完8次前向和反向，GPU每次只处理32个样本，硬件利用率通常也比一次处理大批次低。

容易误解的地方

  • 忘记把损失除以累积步数k，梯度会被放大k倍，相当于学习率变成k倍。
  • 按token求平均的语言模型损失里，各小批次的有效token数不同时，简单地除以k并不精确，需要按总token数归一化。
