词表大小的取舍

Vocabulary Size Tradeoffs

也叫：vocabulary size　vocab size　词表大小　词汇表大小　vocab_size　byte fallback　字节回退　压缩率　compression ratio　tokenizer efficiency　分词效率　token税　多语言token成本

分词器词表里token的个数。词表越大，同样的文本切出的token越少、序列越短，但嵌入层和输出层越大、低频token越训不好；词表越小则相反。主流大模型取几万到二十几万。

先要会：分词与token 嵌入向量 参数量、计算量与显存

子词分词（见分词与token）的训练要先定一个目标：词表要多大。这个数决定了模型的很多性质，却常常被当作一个随手设的超参数。

词表大小影响什么。

  • 序列长度。词表越大，越多常见词和词组能整体成为一个token，同一段文本切出的token越少。上下文窗口能装更多内容，生成同样内容需要的步数也更少（见上下文窗口）。衡量这一点的指标叫压缩率，例如平均每个token对应几个字符或字节。
  • 参数和计算。输入嵌入矩阵和输出层（见语言模型头与输出层）的大小都是V × d。V = 128,000、d = 4096时，每个矩阵约5.2亿参数；对小模型来说，这可能占了总参数的相当一部分。输出层每一步都要对V个token算Softmax与logits，V越大越慢。
  • 低频token。词表越大，越多token在训练数据里只出现很少次，它们的嵌入训练不充分；极端情况就是异常token。
  • 多语言公平性。词表主要用英文语料训练时，其他语言的文字会被切得很碎：同样的意思，中文、印地语可能要多用几倍的token，API按token计费时更贵、能放进上下文的内容也更少。扩大词表、增加多语言语料是常见的补救。

一些参考值。GPT-2的词表是50,257个；LLaMA和Llama 2用32,000个；Llama 3扩大到约12.8万个，Meta称这提高了编码效率；Gemma用了约25.6万个。趋势是随着模型变大、语言覆盖变广而增大。

未登录词与字节回退。词级词表遇到表外词只能输出UNK。子词词表保留了全部单字符，但Unicode字符有十几万个，不可能都放进词表。两种解决办法：字节级BPE直接以256个字节为最小单位（GPT-2）；或者SentencePiece的字节回退（byte fallback）——遇到词表外的字符时，把它拆成UTF-8字节，每个字节用一个专门的token表示。这样任何输入都能被无损编码，不会出现UNK。

例子

同一句英文“The tokenizer splits unbelievable words.”：

  • 词表很小（只有字节，256个）：约40个token（每个字符一个）。
  • 词表约5万：大约8个token，如“The”“ token”“izer”“ splits”“ un”“believable”“ words”“.”（具体切法取决于分词器）。

参数量：V = 32,000、d = 4096时，嵌入矩阵约1.3亿参数；V增加到128,000，变为约5.2亿。对一个总共10亿参数的小模型，这差不多占了一半。

容易误解的地方

  • 换了分词器，困惑度就不能直接比较，因为每个token承载的信息量不同；要比就换成每字节比特数（见每字节比特与每字符比特）。
  • 微调时往词表里加新token，需要同时扩展嵌入矩阵和输出层，新行的初始化方式会影响效果。
  • 为了计算效率，实现中常把词表大小补齐到64或128的倍数，模型配置里的vocab_size可能比分词器实际的token数略大。
