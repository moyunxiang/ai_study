Transformer与大语言模型

一个只做“预测下一个词”的模型，放大到什么程度、怎么训练，才能变成通用的智能底座？

整张图的主干。Transformer → 预训练+微调 → 规模定律与少样本 → 指令对齐与ChatGPT → 开源生态、长上下文与前沿模型竞赛，外加扩散语言模型这条非自回归支线。

从“语言与NLP（前Transformer）”分出：Transformer完全用注意力取代循环，训练更容易并行、更好放大，之后NLP的主干逐步转向它。

架构与组件

2017–2026 · 20个节点

注意力、位置编码、归一化和输入单元怎样设计，模型才好训又好用。

  • 2017.06Transformer当时最好的翻译模型是带注意力的RNN：必须一个词一个词按顺序算，一句话内部无法并行训练；相隔很远的两个词之间，信号要沿时间步走很多步。
  • 2018.03相对位置表示靠给输入加绝对位置向量来知道词序，但语言里真正重要的往往是两个词相隔多远。
  • 2018.07Universal Transformer层数固定，在复制字符串、简单逻辑推理这类需要「反复处理」的任务上，一旦输入比训练时长就崩。
  • 2019.11多查询注意力MQA训练时注意力可以并行，但逐词生成时每一步都要把巨大的键、值张量从显存里整个读一遍，推理被带宽拖慢。
  • 2020.02Pre-LN Transformer原版Transformer必须先用几千步把学习率从0慢慢升上去（warmup），否则训练直接失败；warmup步数还很敏感，调它费时费钱，…
  • 2021.04旋转位置编码RoPE绝对位置编码加在输入上，不直接表达“两个词相距多远”；相对位置编码要改注意力矩阵、额外加偏置项，实现复杂且与一些高效注意力不兼容。
  • 2021.05ByT5字节级模型几乎所有预训练语言模型都依赖分词器和固定词表，对拼写错误、新词和多语言不友好，还多出一套易出错的预处理流程。
  • 2021.08ALiBi线性偏置位置Transformer在多长的序列上训练，就只能在多长的序列上用：用正弦位置编码的模型只要输入比训练长度多出几十个token，困惑度就急剧…
  • 2023.05分组查询注意力GQA逐词生成时每一步都要从显存读出全部历史的键和值（KV缓存），显存带宽成了瓶颈。多查询注意力（MQA）让所有头共用一组K、V，速度快但质量下…
  • 2023.05无位置编码NoPETransformer在训练长度之外的长序列上表现崩溃，位置编码被认为是主因，但各种方案在下游任务上到底谁更好没有系统比较。
  • 2023.05MEGABYTE自回归Transformer在长序列（高分辨率图像、播客、代码、书籍）上，计算量随长度平方增长；字节级建模序列又极长，所以大家只能先做分词。
  • 2024.04多token预测MTP标准的下一token预测只看眼前一个词，训练信号偏局部，模型也难以在推理时一次出多个token。
  • 2024.04深度混合MoDTransformer给每个token分配完全相同的计算量，可“的”“了”这样的词和关键推理步骤显然不需要一样多的算力。
  • 2024.10差分注意力标准注意力会把权重分给大量无关内容（注意力噪声），这在长上下文、检索和幻觉问题里都是隐患。
  • 2024.12字节潜变量BLT几乎所有大模型都依赖固定词表的分词器：它对拼写错误、罕见语言和字符级任务脆弱，且对所有token一视同仁地花同样算力。
  • 2025.05门控注意力标准softmax注意力的输出是低秩线性映射，且常把大量注意力分到第一个token上（attention sink），影响稳定性和长文本外…
  • 2025.07H-Net动态分块语言模型仍依赖分词器这个手工预处理步骤，它不随任务学习，对中文、代码、DNA等分词规则弱的数据尤其差。
  • 2025.07递归混合MoR省参数的办法（层间共享权重）和省计算的办法（按token自适应计算）一直分开研究，没有一个架构同时做到两者。
  • 2025.10Ouro循环语言模型现在的模型主要靠写出思维链来“思考”，推理能力推迟到后训练才培养，预训练数据里的推理潜力没被充分利用。
  • 2026.03注意力残差AttnRes残差连接加PreNorm把各层输出以固定权重1累加，隐状态随深度不受控地增长，每层的贡献被逐渐稀释。

混合专家

2017–2026 · 9个节点

参数做得很大，但每个词只激活一小部分，让容量和算力脱钩。

  • 2017.01稀疏门控MoE层模型越大越好，但稠密网络里每个词都要经过全部参数，参数翻一倍计算也翻一倍；“只激活一部分网络”的条件计算一直停留在设想。
  • 2020.06GShard想把的稀疏混合专家扩到几百亿、几千亿参数，需要在大量加速器上手写复杂的并行代码，工程成本极高。
  • 2021.01稀疏MoE大模型等MoE模型让参数量很大而计算量不变，但路由复杂、通信开销大、训练不稳定，很少有人用。
  • 2021.12GLaM像这样的稠密大模型每处理一个token都要动用全部参数，继续放大的训练和推理成本太高。
  • 2022.02ST-MoE稳定训练之类的稀疏专家模型训练容易不稳定，微调后的质量也不确定，阻碍了它们在广泛任务上击败稠密模型。
  • 2024.01Mixtral 8x7BMoE在谷歌已做到万亿参数，但公开的MoE检查点（如Switch Transformer）是T5式的掩码语言模型，不能直接拿来对话；开源最…
  • 2024.01DeepSeekMoE细粒度专家GShard式MoE只有8–16个大专家、每次选1–2个，一个专家要装下很杂的知识，不同专家又各自重复存储常识，专家并没有真正分工。
  • 2024.08无辅助损失负载均衡MoE训练需要让各专家的负载均衡，否则路由塌缩。传统办法加一个辅助损失，但辅助损失太大会干扰主任务的梯度、损害效果。
  • 2026.01Engram条件记忆MoE靠条件计算扩大容量，但Transformer没有原生的“查知识”原语，静态知识和固定搭配也要靠前几层的计算去重建。

非自回归与扩散

2017–2026 · 27个节点

不再一个词一个词地往后写，而是并行生成、反复修改整段文字。

  • 2017.11非自回归翻译NAT翻译时仍要一个词一个词地生成，句子多长就要串行解码多少步，线上延迟下不来。
  • 2019.04Mask-Predict并行解码一次性并行输出，速度快，但译文质量比自回归模型低好几个BLEU。
  • 2021.07离散扩散D3PM在连续的图像和波形上很成功，但文本是离散符号，无法直接加高斯噪声。
  • 2022.05Diffusion-LM想在不重新训练的前提下控制语言模型生成（例如指定句法结构），现有方法只能控制情感等简单属性，复杂细粒度控制几乎没进展。
  • 2022.10DiffuSeq只能做无条件或受约束的生成，而摘要、翻译、改写、对话等序列到序列任务需要根据输入条件生成。
  • 2022.11连续扩散CDCD扩散模型在图像、音频上很成功，靠的是数据是连续的；语言是离散的词，已有的离散扩散方案都放弃了「连续」这个好处。
  • 2023.05Plaid似然扩散LM扩散语言模型虽然越来越多，但没有一个在标准语言建模基准上取得过像样的似然，和自回归模型有明显差距。

  • 2024.06掩码扩散语言模型MDLM扩散模型在图像上很成功，但在语言建模上，离散扩散比自回归模型差一大截，困惑度差距明显。
  • 2024.10DiffuLLaMA自回归转扩散扩散语言模型只在小规模上从头训练过，追不上同规模自回归模型，从头训一个大的又太贵。

  • 2025.03块扩散BD3-LM离散扩散语言模型能并行生成，但似然（困惑度）比自回归差，且只能生成固定长度，也用不了KV缓存。

  • 2025.05Fast-dLLM免训练加速开源扩散大模型号称能并行，实际却比自回归模型慢：双向注意力用不了KV缓存，一步解多个词质量又会崩。

  • 2025.10SDAR块扩散转换从头训练扩散模型训练效率低、推理要整段反复去噪；而自回归模型虽然好训好部署，却只能一个词一个词写。

长上下文与高效注意力

2019–2025 · 24个节点

注意力开销随长度平方增长，怎样让模型读得更长、算得更省。

  • 2019.01Transformer-XL语言模型把长文本切成固定长度的片段分别处理，片段之间信息完全不通，既看不到片段外的上下文，开头几个词也几乎没有上文。
  • 2019.04稀疏注意力自注意力要对所有位置两两计算，时间和显存随序列长度的平方增长，几千个位置就吃不消。
  • 2019.11压缩记忆Transformer缓存旧片段的隐状态，但缓存放满后最老的记忆就直接丢掉，长程信息无法保留。
  • 2020.01高效长序列注意力的注意力需要计算n×n的相似度矩阵，且每一层的激活都要存到反向传播，长序列时显存立刻爆掉。
  • 2020.04Longformer滑窗注意力BERT类模型一次最多读512个词，长文档要被硬切段，跨段信息完全断开。
  • 2020.06Linformer低秩注意力自注意力的矩阵是n×n，时间和空间都随序列长度平方增长。
  • 2020.07BigBird稀疏注意力稀疏注意力能降低成本，但不清楚它是否还保留完整注意力的表达能力。
  • 2020.09Performer核近似注意力线性注意力之前的做法要么靠稀疏、低秩等先验近似，要么与softmax注意力不等价；缺少对标准注意力的有理论保证的近似。
  • 2022.03外接kNN记忆模型要获得新知识通常得重新训练或微调，上下文窗口又很短，没法在推理时直接“读完就记住”长文档或新定义。
  • 2022.07循环记忆Transformer自注意力的计算量随序列长度平方增长，输入长度受限；全局和局部信息又都塞在同一批词表示里。

  • 2023.07迷失在中间2023年各家竞相把上下文扩到16K、100K，但“能放进去”不等于“能用好”：模型到底能不能利用长输入中任意位置的信息，缺少受控的测量。
  • 2023.07RetNetTransformer训练能并行，但推理时KV缓存随序列增长、每步代价不小；RNN推理便宜却难以并行训练。能否兼得？
  • 2023.08YaRN位置插值把RoPE的所有维度一律压缩，高频维度里相邻token变得难以区分；扩展倍数到8倍左右模型就开始退化，而且需要较多的长文本微调。
  • 2023.10Kimi长文本对话主流对话模型的上下文窗口很短，读不完长文档、财报和论文，想让它处理整本书只能手工切片。
  • 2023.12门控线性注意力GLA可以并行训练、又能当RNN逐步推理，但效果通常不如softmax注意力，而且实现没有考虑GPU内存读写，实际比还慢。

预训练目标

2018–2025 · 26个节点

先在无标注文本上学什么任务，才能学到可迁移到各种任务的语言表示。

  • 2018.01ULMFiT视觉里“ImageNet预训练+微调”早已是常规，NLP却仍要为每个任务从头训练专门模型；直接微调语言模型又容易过拟合、忘掉预训练学到的东…
  • 2018.02ELMoword2vec给每个词只有一个固定向量，“bank”在“河岸”和“银行”里是同一个向量，模型分不清一词多义。
  • 2018.06GPT-1NLP任务的标注数据很少，每个任务都要设计专门的模型；预训练的词向量或LSTM特征只能迁移一小部分知识。
  • 2018.10BERTGPT只看左边上下文，ELMo的双向只是两个单向模型拼接；而直接训练双向语言模型会让每个词“看到自己”，任务变得毫无意义。
  • 2019.01跨语言预训练XLM式预训练只在英语上做，其他语言缺少标注数据，跨语言任务和低资源翻译没有好用的起点。
  • 2019.04百度ERNIE随机遮单个字，在中文里容易靠相邻字猜出被遮的字，学不到「词」「实体」整体的含义。
  • 2019.05MASS只有编码器，不能直接做翻译、摘要这类需要「生成」的任务，编码器和解码器仍要从零训练。
  • 2019.05UniLM擅长理解、擅长生成，要同时做两类任务就得训练并维护两个不同结构的模型。
  • 2019.06XLNet预训练时用特殊遮罩符号，但微调时不出现；并且被遮的词之间被当作相互独立，忽略了它们的依赖。
  • 2019.07SpanBERT随机遮单个词，但问答、指代消解等任务需要的是一整段文字（人名、短语）的表示。
  • 2019.07RoBERTaBERT之后新方法层出不穷，但各家数据量、训练时长、超参数都不同，说不清提升究竟来自新方法还是只是训练得更多。
  • 2019.09ALBERT参数共享BERT越大越好，但再往上加宽加深，GPU/TPU显存先装不下，训练也越来越慢。
  • 2019.10T5BERT之后预训练方法一年冒出几十种，目标、结构、数据、规模各不相同，很难说清到底哪个因素在起作用；分类、问答、翻译还各要一套输出层。
