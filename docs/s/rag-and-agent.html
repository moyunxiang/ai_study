RAG和Agent：给模型外挂知识和手脚

语言模型把知识记在参数里，能做的只有输出文字。RAG和Agent各自补的是哪块短板？它们是一回事吗？

在交互版中打开

2020年前后，研究者发现预训练语言模型能直接答出不少事实问题：110亿参数的T5不看任何文档（闭卷），在Natural Questions开放域问答上精确匹配能到34.5%。但这种知识存在参数里，带来三个麻烦：想记住更多事实只能把网络做得更大；答错了说不出依据；世界变了只能重新训练。

另一块短板更根本：模型的输出只是一串文字。它不能在回答途中去查资料，也不能运行程序、修改文件、看看结果对不对再改。参数里没有的信息拿不到，参数里算不准的东西只能猜。

下面这条线上，两类办法交替出现：一类在模型之外接一个资料库，先取信息再生成，后来叫RAG；一类让模型输出“动作”，由外面的程序执行后把结果交回，后来叫智能体（Agent）。

  1. 2020

    把检索器放进预训练，用猜词的好坏来训练它

    REALM · REALM: Retrieval-Augmented Language Model Pre-Training来源已核对

    开头的问题是知识藏在参数里。REALM在掩码语言模型预训练中加了一个检索器：先从1300多万个维基百科段落里取出几篇，再根据句子和这几篇去猜被遮住的词。文档被当作隐变量求和，p(y|x) = Σ_z p(y|z,x)·p(z|x)；某篇文档让猜词更准，梯度就提高它的检索得分，不需要人工标注该看哪篇（见隐变量模型）。3.3亿参数的REALM在NQ上得到40.4，高于T5-11B的34.5。但文档编码器在不断变化，每隔几百步就要重新编码全部段落、重建索引；答案也只能从文档里截取一段原文。

  2. 2020

    只用问答对训练两个编码器，检索也能学

    稠密检索DPR · Dense Passage Retrieval for Open-Domain Question Answering来源已核对

    上一站的检索器和预训练绑在一起，训练很贵。DPR把检索单独拿出来：两个BERT分别把问题和段落编成向量，用内积打分（见检索与向量数据库）；训练时每个问题配一个正确段落，同批次里别的问题的正确段落和一个BM25取回的段落当负样本。段落向量离线算好、建成索引。在2100万段维基百科上，NQ的top-20检索准确率为78.4%，BM25是59.1%；但在问题照着原文写的SQuAD上，它反而不如BM25。它也只管找段落，答案仍要由阅读模型从原文里截取。

  3. 2020

    检索一次，再让生成模型读着资料写答案

    检索增强生成RAG · Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks来源已核对

    上一站和更早的系统都只能从原文截取答案。RAG把DPR检索器接到4亿参数的生成模型BART上：先按问题取回前5或10段，再以“问题+段落”为条件生成答案，对这几段按检索概率加权求和，只用答案的损失端到端微调查询编码器。NQ上得到44.5，高于DPR的41.5；用2018年的索引去问2016年在任的各国领导人，答对率从70%掉到12%，说明换文档库就能换知识。这是第一种外挂：模型之外先取资料、放进输入，再生成。但它只在开头按问题检索一次，生成途中发现缺什么也没法再查。

  4. 2020

    同一个月的另一条路：全靠参数和提示

    GPT-3 · Language Models are Few-Shot Learners来源已核对

    上一站给模型配了外部资料库，同月发布的GPT-3走相反方向：参数放大到1750亿，不微调、不检索，只在提示里写几个例子让模型照着续写（见上下文学习与提示）。闭卷TriviaQA少样本71.2%，高于论文表中带检索的RAG的68.0%，显示规模变大后参数里能装下的知识多了很多。但参数记忆的老问题都还在：它常编造事实，知识只能来自训练数据，多位数算术和多步推理很差。参数之外的信息它拿不到，算不准的东西只能硬猜。

  5. 2022

    先把推理过程写在文本里

    思维链CoT · Chain-of-Thought Prompting Elicits Reasoning in Large Language Models来源已核对

    上一站的模型直接给答案，多步题常出错。思维链提示把少样本示例的答案换成“推理过程+答案”，模型照着先写步骤再作答，参数不变。GSM8K小学数学题上，PaLM 540B从17.9%升到56.9%，超过此前微调GPT-3加验证器的55%；不过这只在约1000亿参数以上的模型上有效。论文的解释是：思维链把多步问题拆成中间步骤，需要更多步骤的题就能分到更多计算；写下的中间结果留在上下文里，后面的步骤可以读到。但推理用的仍只是参数里的知识，一个事实记错，会沿着链条一路错下去。

  6. 2022

    边想边查：检索变成模型自己决定的动作

    ReAct · ReAct: Synergizing Reasoning and Acting in Language Models来源已核对

    上一站的推理只靠参数，RAG的检索又只在开头做一次。ReAct让模型交替输出“思考—行动—观察”：先写一句下一步要查什么，再输出Search[实体]这样的动作；程序截断生成、真正调用维基百科接口，把返回内容作为“观察”拼回提示，模型接着想，直到输出Finish[答案]（见智能体循环）。只用一两个示例，冻结的PaLM-540B在ALFWorld家务模拟里成功率71%，只行动不思考的版本是45%；人工标注的HotpotQA失败样本里，幻觉占比从思维链的56%降到0%。这是第二种外挂。但动作是提示里约定的文本格式，要靠字符串解析，换个工具就得重写示例。

  7. 2023

    把调用工具做成API的正式接口

    函数调用成为标准接口 · Function calling and other API updates来源已核对

    上一站的动作靠约定格式和字符串解析；ChatGPT发布上线时也只能聊天，不能上网或调用工具。2023年6月OpenAI在API里加入函数调用：开发者用JSON Schema描述可用的函数，例如get_current_weather(location, unit)；官方称新模型经过微调，能判断何时需要调用，并输出符合函数签名的JSON参数（见工具调用）。模型只发出调用请求，执行的是开发者的程序，结果再交回模型。查资料、查数据库是一种函数，发邮件、写文件也是，两种外挂从此走同一个接口。但能发调用不等于能完成长任务。

  8. 2023

    一次检索不够：在真实代码库里修bug

    SWE-bench · SWE-bench: Can Language Models Resolve Real-World GitHub Issues?来源已核对

    上一站之后，模型能否用工具完成多步的真实工作还缺一把尺子。SWE-bench从12个Python仓库的真实issue和合并PR构造2294道题：给出issue和整个代码库，要求生成补丁，用PR附带的测试判定是否修好。代码库平均3010个文件，远超上下文窗口，论文的基线是RAG式做法：用BM25按issue文本检索一次相关文件放进提示。最强的Claude 2只解决1.96%，作者在讨论里建议尝试智能体方法。2024年同一团队的SWE-agent让模型自己浏览文件、编辑、跑测试，解决率到12.5%。但每个应用接工具仍各写各的。

  9. 2024

    工具接入标准化：写一次服务器，多个应用都能用

    模型上下文协议MCP · Introducing the Model Context Protocol来源已核对

    上一站的问题是工具对接代码不能复用；函数调用只规定了模型怎样表达调用，没规定工具从哪里来。2024年11月Anthropic开源MCP：工具和数据方写MCP服务器，AI应用实现客户端，双方用JSON-RPC 2.0通信。宿主用tools/list拿到工具名、说明和参数Schema交给模型，模型决定调用时再发tools/call，结果放回上下文。服务器还能提供“资源”，由应用决定放进上下文，和RAG放入检索结果是同一类操作。据Anthropic统计，到2025年12月活跃公开服务器已超过1万个。但工具接好之后，长任务能否一轮轮推进下去，取决于模型外面那层程序。

  10. 2025

    把整个循环放进开发者的终端

    Claude Code与终端编码智能体 · Claude 3.7 Sonnet and Claude Code来源已核对

    上一站把工具接入标准化了。2025年2月Anthropic随Claude 3.7 Sonnet发布Claude Code，官方文档把它的工作分成收集上下文、采取行动、验证结果三个交织的阶段。比如让它修好失败的测试，它可能先跑测试、读报错、搜索并阅读相关源文件、编辑，再跑一次测试确认；每次工具调用的结果都回到上下文，决定下一步。工具包括内置的读写和搜索、终端里的任意命令，外部服务通过MCP接入。文档把这层提供工具、管理上下文的程序叫作harness。在这里，搜代码相当于RAG的那一步检索，改文件、跑测试则是模型的手脚。

现在走到哪了

两条线补的短板不同：RAG补的是知识——参数记不准、说不出出处、更新要重训，就把资料放到外面，按需取回；Agent补的是行动——模型只能输出文字，就让它输出动作，由程序去查、去改、去运行，再看结果。两者的共同点是都在模型之外加了一个循环：取信息或做动作，再把结果放回上下文，模型本身的参数并不改变。区别在谁做决定、做几次：经典RAG由程序按问题检索一次，然后生成；Agent由模型根据上一步的观察决定下一步做什么，步数事先不知道。从这个角度看，RAG可以看作只有一个固定“检索”动作、只走一步的Agent。SWE-bench上，一次检索的基线（Claude 2，1.96%）和SWE-agent（12.5%）的差别就体现了这一点，不过两者用的模型不同，差距不全来自循环。

今天两条线已经交汇：检索成了智能体循环里的一个工具，模型自己决定什么时候查、查几次（FLARE主动检索、Self-RAG、Search-R1沿这个方向）。仍然开放的问题集中在循环本身：轨迹越长越占上下文，ReAct论文就已指出复杂任务的示例容易超出上下文长度；工具返回的内容原样进入上下文，OpenAI在函数调用公告里就提醒，不可信的工具输出可能指使模型执行意外操作（见间接提示注入）。接着可以读SWE-agent看工具接口怎样影响智能体表现，读Agent Skills和用代码调用工具看工具多了以后怎样节省上下文。

这条线简化了什么

“两种外挂、一个循环”是事后归纳，不是当事人的说法。REALM、DPR、RAG相隔只有几个月，彼此的关系以各自论文的引用为准；ReAct论文只把RAG列为FEVER上有监督最好成绩的出处，并没有说自己是RAG的延续，它自述建立在Inner Monologue的闭环思路上；OpenAI的函数调用公告没有提ReAct；MCP规范也没有把“资源”说成RAG，这里的对应是类比。

今天常说的RAG多半是“向量库检索+冻结大模型+把段落拼进提示”，没有任何训练，和原论文联合微调检索器与生成器的RAG不是一回事。Agent这条线也略去了不少同时期的工作，如WebGPT、SayCan、Toolformer、ChatGPT插件。GPT-3与RAG的TriviaQA数字来自GPT-3论文的表格，两者设置不同（少样本闭卷对比微调加检索），只能说明量级。终点选Claude Code只是一个例子，同期还有Codex CLI、Gemini CLI等同类工具；Claude Code的使用和收入数字来自Anthropic自己的公告。GPT-3和ChatGPT两站的事实取自这两个节点已有的讲解，不是本次核对的对象。
