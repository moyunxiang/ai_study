算力和硬件怎样影响了模型的发展

训练多层网络的反向传播在1980年代就有了，为什么深层网络到2010年代才真正训得动？之后模型从几千万参数涨到几千亿，硬件在每一步起了什么作用，又有哪些不是硬件的功劳？

在交互版中打开

今天的计算机基本沿用冯·诺依曼架构描述的结构：程序和数据放在同一块存储器里，处理器按地址一条条取出来算。神经网络的训练几乎全是大量相互独立的乘加（见矩阵乘法与线性变换），每个权重都要在存储器和运算单元之间来回搬，搬运的带宽（见显存、内存带宽与“内存墙”）常常比运算本身更早成为瓶颈。

反向传播给出了训练多层网络的办法，LeNet与卷积网络把卷积网络用在了手写数字上，但在通用CPU上，参数稍多的网络就要训练几周，研究者只能做小模型、用少量数据。

问题因此是：更多的算力从哪里来，怎样变成研究者真正用得上的形式，模型又怎样反过来去适应它？

  1. 1965

    晶体管每隔一两年翻一倍，乘法器越来越便宜

    摩尔定律 · Cramming More Components onto Integrated Circuits来源已核对

    起点的问题是算力不够。1965年Moore根据1959–1964年的五个数据点指出，成本最低时一块芯片上的元件数大约每年翻一倍，并外推到1975年约6.5万个；1975年他把速度改为每两年翻一倍。这条经验规律延续了几十年，1995年一颗Pentium已有近500万个晶体管。对神经网络来说，这意味着同样的钱能买到越来越多的乘法器。但2005年前后单核主频不再上涨（见Dennard缩放终结与并行转向），多出来的晶体管只能变成更多并行单元，问题变成怎样让程序用上它们。

  2. 2006

    让GPU上成千上万个线程能用C语言编程

    CUDA来源已核对

    上一站留下的问题是并行硬件难用。GPU本来就有大量并行单元，但2006年以前要用它做通用计算，得把数据伪装成纹理、把算法写成像素着色器。2006年11月NVIDIA发布CUDA：程序员用C写一个描述“单个线程做什么”的内核，一次启动成千上万个线程，同一线程块内的线程可以共享片上内存、互相同步（见CPU、GPU与并行计算）。2009年GPU训练深度网络用这一编程模型在一块GTX 280上训练深度信念网络，大模型上比双核CPU快最多70倍，1亿参数的四层网络从几周缩短到约一天。但网络一大，光有算力还不够，还要有足够多的标注数据来防止过拟合。

  3. 2012

    GPU加上大规模标注数据，深层卷积网络在比赛中胜出

    AlexNet · ImageNet Classification with Deep Convolutional Neural Networks来源已核对

    上一站让训练变快，但参数多的网络在小数据上会过拟合（见泛化与过拟合）。2012年的AlexNet把卷积网络做到5个卷积层加3个全连接层、6000万参数，用ImageNet里的120万张标注图片，在两块GTX 580上训练了五到六天，作者为此自己写了卷积等全部训练运算的GPU实现。它在ILSVRC-2012上的top-5错误率为15.3%，第二名为26.2%。论文自己把可行性同时归于两件事：GPU配上高度优化的卷积实现，以及ImageNet有足够的标注样本；还写道网络大小主要受GPU显存和能容忍的训练时间限制。但换一种结构，就得重写一遍GPU上的前向和反向代码。

  4. 2015

    框架把“写模型”和“算梯度、分配设备”分开

    TensorFlow · TensorFlow: Large-Scale Machine Learning on Heterogeneous Distributed Systems来源已核对

    上一站的痛点是每个模型都要手写GPU代码。2015年11月开源的TensorFlow让研究者只描述前向计算：程序先构建一张由运算和张量组成的数据流图，tf.gradients沿图反向为每个运算添上求梯度的节点（见自动微分与计算图），运行时再把图切分到CPU、GPU乃至数百台机器上，卷积等关键运算交给cuDNN。2017年1月发布的PyTorch换成即时执行，运行时记录运算再反向求导，论文测得单机速度与最快框架相差在17%以内。模型变得好写了，但这些框架跑在通用芯片上，而谷歌线上推理的算力需求涨得太快。

  5. 2016

    为矩阵乘法专门造一颗芯片

    Google TPU · In-Datacenter Performance Analysis of a Tensor Processing Unit来源已核对

    上一站解决了怎么写，谷歌面对的是怎么算得起：2013年它估算，如果每人每天用3分钟语音搜索，数据中心的算力就得翻倍。它在15个月内做出TPU：核心是256×256个8位乘加单元组成的脉动阵列，权重预装在阵列里，数据一拍一拍流过并被反复复用，从而少读存储器；去掉缓存、乱序执行等提高平均吞吐的设计，换取稳定的低延迟。在谷歌线上负载上，它比同期K80 GPU和Haswell CPU平均快约15–30倍，每瓦性能高约30–80倍。第一代只做推理，能训练的TPU v2/v3与TPU Pod在一年后出现。硬件越来越擅长大块矩阵乘，模型结构是否契合这一点就变得重要。

  6. 2017

    一种能整句并行、主要由矩阵乘构成的结构

    Transformer · Attention Is All You Need来源已核对

    上一站的芯片擅长大块矩阵乘，而当时最好的翻译模型是循环网络，必须一个词一个词按顺序算，一句话内部难以并行。2017年的Transformer去掉循环，只用自注意力（见自注意力与多头注意力）：每个词直接和句中所有词计算相关性，整句可以一起算，主要计算是矩阵乘。论文的大模型在一台装8块P100的机器上训练3.5天，英德翻译BLEU 28.4，比此前最好的结果高2分以上，训练计算量远少于此前的强模型；代码发布在基于TensorFlow的tensor2tensor里。之后的BERT以它为骨架，在Cloud TPU上预训练。但“为什么更多算力总能换来更好的模型”，当时还只是经验。

  7. 2019

    把几十年的经验归纳为“能利用算力的方法终将胜出”

    苦涩的教训 · The Bitter Lesson来源已核对

    上一站之后，越来越多的进展来自更大的模型和更多的计算。2019年3月Sutton在一篇短文里回顾国际象棋、围棋、语音和视觉：研究者总想把自己对问题的理解写进系统，短期有效，长期却会停滞，而能随算力扩展的通用方法——搜索和学习——最终胜出；他把原因归于单位计算成本按指数下降，即摩尔定律的推广。这是挑选历史案例的定性归纳：几天后Rodney Brooks就反驳说，卷积网络的前端本身就是人为处理平移不变性而设计的。文章也没有回答，多少算力能换来多少提升。

  8. 2020

    把“算力越多效果越好”量化成幂律

    语言模型的规模定律 · Scaling Laws for Neural Language Models来源已核对

    上一站只是定性判断。2020年1月，OpenAI的Kaplan等人训练了参数从768到15亿不等的大量Transformer语言模型，发现测试损失随参数量、数据量和训练算力各自按幂律下降（见幂律与规模定律），某些趋势跨越七个数量级以上；只受算力限制时L ∝ C^−0.050。由此推出：算力固定时应训练很大的模型、远未收敛就停下，最优模型大小约按N ∝ C^0.73增长。这让“投入多少算力换多少效果”可以用小实验提前估算（论文并未引用上一站的短文）。四个月后的GPT-3推到1750亿参数，在V100集群上训练；2022年的Chinchilla修正了参数和数据的分配比例。但规划好的巨大训练，需要更快、显存更大、连接更紧的芯片。

  9. 2020

    给大模型训练合适的数值格式、显存和机内互连

    A100来源已核对

    上一站让人可以预先规划巨大的训练。2020年5月的A100在Tensor Core里加入TF32和bfloat16：两者都有与FP32相同的8位指数，FP32代码不改就能走Tensor Core，BF16通常也不再需要损失缩放（见浮点精度：FP32、FP16、BF16、INT8）。FP16/BF16 Tensor Core峰值312 TFLOPS，约为V100的2.5倍；40GB HBM2带宽1555GB/s，NVLink总带宽600GB/s。一个实际例子：LLaMA的650亿参数模型在2048块80GB A100上训练，处理1.4万亿token约需21天。但它最低只到16位浮点，NVLink高速互连也只连得到一台服务器里的8块卡。

  10. 2022

    为Transformer加上8位浮点，并把高速互连扩到服务器之外

    H100来源已核对

    上一站留下了精度和互连的上限。2022年3月发布的H100加入两种8位浮点格式FP8，配合逐层统计数值范围、自动计算缩放因子的Transformer Engine（NVIDIA称其专为Transformer设计）；不含稀疏时FP8峰值约2000 TFLOPS，是FP16的两倍。80GB HBM3带宽约3TB/s，NVLink每卡900GB/s，并可经外部交换机把最多256块GPU连成一个NVLink域。Llama 3.1 405B的4050亿参数模型在最多1.6万块H100上训练，每卡实际达到380–430 TFLOPS，按BF16计的模型算力利用率为38%–43%，也就是说过半的峰值算力没有用在模型计算上。

现在走到哪了

到2024年，最大的训练集群已经是一万多块H100（Llama 3）乃至约10万块H100（xAI的xAI Colossus：122天建成10万卡集群）。限制从单颗芯片的乘法速度转到了显存容量与带宽、芯片间互连、封装产能和供电上：H200：141GB HBM3e把显存换成141GB的HBM3e，之后的Blackwell与整机柜液冷沿着同样的方向继续改。另一边，DeepSeek-V3在带宽低于H100的2048块H800上，用FP8混合精度和针对InfiniBand与NVLink的通信调度完成训练，共用278.8万GPU小时，硬件受限时算法和工程仍有很大的发挥空间。

接着可以读FlashAttention，看注意力怎样为了少读写显存而重写；读Chinchilla，看同样的算力在参数和数据之间怎么分。Transformer本身的来历见专题“Transformer为什么出现”，预训练之后的算力怎么花见专题“预训练与后训练”。

这条线简化了什么

这条线是按“某种硬件出现—某类模型训得动”的对应关系事后归纳的，不是当事人的说法。把每次进展都归到算力上的“算力决定论”同样是一种事后归纳：AlexNet论文自己就把可行性同时归于GPU和ImageNet；ReLU、dropout、数据增强、残差连接、归一化等方法上的改进同样不可少；Transformer论文给出的理由是可并行、训练快、翻译好，并没有说它是为某种芯片设计的。因果也是双向的：H100的Transformer Engine是在Transformer流行之后才加入的。

数据和方法是与算力并列的必要条件。ImageNet的120万张标注图、大语言模型的上万亿token都不是硬件能提供的；Chinchilla的结论是，同样的算力下数据没跟上，模型就会训练不足。苦涩的教训与规模定律之间的衔接也是叙事安排：规模定律论文没有引用那篇短文，Sutton本人在2025年还认为大语言模型并不符合苦涩的教训。

这里省略了很多：GPU训练深度网络以外的早期GPU工作、cuDNN和编译器、TPU v2到v4的演进、AMD等其他厂商的芯片、Ring All-Reduce和Megatron-LM模型并行这类分布式训练方法。文中的官方峰值（以及厂商常说的“最多快20倍、9倍”）都是特定精度和条件下的最好情况，实际训练的利用率常常不到一半。AlexNet、ImageNet、Transformer、规模定律四站的事实取自这几个节点已有的讲解，并对照了本次打开的原文，但这四个节点本身不是本次核对的对象。
