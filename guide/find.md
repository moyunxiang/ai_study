# 搜得到规范（find）：别人会搜的词，站里要搜得到

## 背景

站长把站点给别人看，对方随手搜了一个方法的缩写（一篇2025年的机器人论文的简称），站里什么都没有。前几轮补收录是“按主题线对着综述找缺的论文”，补进来的多是经典；这一轮换个角度：**从读者会往搜索框里敲的词出发**，搜不到的就补上。

你负责的方向 `<area>`（一条或几条分支）和轮次名 `<round>` 在任务说明里。

## 先读

- `guide/more.md` 全文：新增节点的做法、查重、顺序（讲解 → 归线 → 登记）、自检、不要做的事，这一轮**全部照旧适用**，下面只写不同的地方。
- `guide/census.md`、`guide/content.md`（节点讲解和概念词条的写法都在里面）。
- 你负责的分支的 `data/threads/<track>.json`、全部登记表 `data/skeleton/<track>*.txt`、别名表 `data/aliases/<track>.json`。

## 第一步：列查询词

站在这个方向的学生、研究者、工程师的位置上，列出他们会搜的词，**不少于250个**，写到你的专用临时目录里的 `queries.txt`（一行一个，照人实际会敲的样子写：缩写、小写、中文叫法都算）。来源至少覆盖下面几类，每类都要有：

1. **近三年的热门工作（最重要）**：2024–2026年这个方向被广泛讨论、跟进、比较的方法、模型、系统、基准的简称。从近期综述的分类表、awesome list、顶会（2024–2026）的oral和高分论文、主流开源库的模型列表、课程和教程的阅读清单里取。必须联网取，不要凭记忆列。
2. **缩写和俗称**：这个方向里人人都用的缩写（方法、损失、指标、结构、训练技巧），中文圈的叫法。
3. **教材和课程里的知识点**：这个方向的标准教材、课程大纲的章节名和术语表里的概念、定理、技巧（不是论文，是“知识点”）。
4. **经典方法和基线**：综述的对比表格、基准排行榜上反复出现的名字。
5. **数据集、基准、环境、工具库**：这个方向的人做实验会用到的。
6. **站内已经提到却搜不到的**：`data/_audit/search_gaps.tsv`（正文里反复出现、但搜不到的名字）里属于你这个方向的。

## 第二步：探测

```
node scripts/search_probe.mjs <你的临时目录>/queries.txt
```

它用站点真实的搜索代码和最近一次构建的索引，打印没命中的词（MISS 完全搜不到 / WEAK 只搜到沾边的；`--all` 连命中的也打印）。注意两点：

- HIT 不等于搜对了：缩写可能命中了另一个同名的东西。用 `--all` 把命中的结果也过一眼。
- 索引是最近一次构建的，别的agent刚登记的节点看不到。所以对每个 MISS / WEAK，动手之前照 `more.md` 的“查重”再 grep 一遍 `data/skeleton/`。

## 第三步：逐个补上

对每个搜不到的词，先判断它是什么，再用最省的正确办法补：

| 情况 | 做法 |
|---|---|
| 站里已经有这个东西，只是换了个叫法搜不到 | **加别名**。节点在你负责的分支里：在 `data/aliases/<track>.json` 里给那个节点id加（`{节点id: [别名…]}`，已有这个id就往它的列表里加）。节点是本轮你自己新写的：写进讲解文件的 `aka`。节点在别的分支：记到报告的“给别的分支”里，不要改别人的文件。 |
| 是一篇论文、一个模型、系统、数据集、基准，站里没有 | **新增节点**，完全按 `more.md` 的三步做，登记到 `data/skeleton/<track>.<round>.txt`。不属于你负责的分支的，记到报告里转给对应分支。 |
| 是一个知识点（概念、定理、技巧、指标），不是某一篇具体的工作 | 先看能不能当作已有概念词条或已有节点的别名（它确实就是那个东西的另一个名字才行，不要把上位词、下位词硬挂上去）。不能的话：如果它有公认的出处论文，按节点收（`kind` 写 `concept` 或 `paper`，见 `census.md`）；没有单一出处的，**不要自己写概念词条**，记到报告的“需要新概念词条”一节（名称、英文、一句话说明），有专门的agent统一写。 |
| 机构、人名、媒体、编程语言、泛泛的大词 | 不处理。 |

收录标准比 `more.md` 再宽一点：**这个方向的人真的会搜它**就够了，不要求已经被很多后续工作引用。但“真实存在、这次打开来源确认过”这一条不变，核实不了的不收，记到报告里。

每个新节点的 `aka` 要认真填：缩写的各种写法（带不带连字符、大小写不同的不用重复，搜索不分大小写）、全称、中文叫法、常见的误拼。标题和英文原题里已经有的不用重复。

数量：没有上限，以“列出来的查询词里该补的都补了”为准；任务说明里会给一个参考数。

## 改动范围

- 可以新建：你负责分支的 `data/content/<track>/<id>.json`、`data/skeleton/<track>.<round>.txt`、报告。
- 可以改：`data/threads/<track>.json` 的 `assign`（只插入行；别的agent可能同时在改这个文件，**用 Edit 一次插一行，每次插之前重新读文件**，不要整文件重写）、`data/aliases/<track>.json`（只加别名，不删不改已有的；改完确认仍是合法JSON）。
- 其余同 `more.md` 的“不要做的事”：不改已有讲解和登记表，不改概念、思路、脚本、前端，不运行git，不运行不带 `--check` 的 `build.py`。

## 自检

```
python3 scripts/build.py --check --wip 2>&1 | grep -E "<track>\.<round>|threads/<track>|content/<track>/|aliases/<track>"
```

针对你文件的 ERROR 全部修掉。

## 报告

写到 `data/_reports/<round>-<area>.md`：

```
# <area> · <round> 轮报告（日期）

列了多少个查询词，探测结果（HIT / WEAK / MISS 各多少），处理结果（新增节点N个、加别名M处、转出K个、不处理J个）。
新增节点的id列表（tier 2的标出来）。

## 加了别名的节点
## 需要新概念词条
- 名称 | English | 一句话说明          ← 每行一个
## 没核实因此没写
## 凭一般了解写、没有逐项对照来源的地方
## 给别的分支
- <建议分支key> | 名称 | 年份 | 一句话说明
## 还搜不到的（这一轮没来得及补）
```

查询词文件 `queries.txt` 留在临时目录里不用删。最终回复三四行：列了多少查询词、新增了多少节点、加了多少别名、有没有需要主session处理的事、报告路径。
