# 阶段A：节点普查规范（census）

## 这个项目是什么

一个中文的AI发展史学习网站：把1943年至今AI各方向**所有真正有贡献的工作**（论文、模型、系统、硬件、数据集、关键事件）做成一张按时间排列、分16条分支的图。每个节点之后会有完整讲解：当时卡在哪、它怎么解决的、留下什么问题、后来谁解决了这些问题。读者按时间顺序一点点学，理解“每个阶段大家在攻克什么”。

阶段A只做一件事：**把你负责的那条分支的节点清单补全**。不写讲解（那是阶段B）。

## 你要读的文件

- `data/tracks.json`：16条分支的定义、主线问题、阶段划分。先读自己那条，再扫一眼其他分支的 `question`，弄清边界。
- `data/skeleton/*.txt`：现有骨架（约450个节点）。**全部读一遍**，因为 parents 可以跨分支引用，而且你要避免重复添加别的分支已有的节点。

## 收录标准

目标是**全**：读者学完这条分支，不应该在读后续论文的related work时发现一个没见过的重要名字。

收：
- 被后续工作直接建立其上的方法、架构、训练技巧
- 定义了一个问题或一个范式的工作（哪怕方法本身已被取代）
- 改变了从业者实际做法的系统、工具、硬件、数据集
- 重要的负结果、争论、被证明走不通的路线（它们解释了为什么后来不这么做）
- 一个阶段内被广泛比较的强基线
- 引发资金、人才、舆论转向的事件

不收：
- 只在某个榜上涨了一点、没有留下可复用想法的工作
- 同一想法的第N个变体（除非它是事实上被采用的那个版本）
- **2025-06之后**的工作要更挑剔：必须已经被广泛跟进/复现/采用，或被公认为方向性转折。只是中了NeurIPS/ICML/ICLR不算理由。但2025-10到2026-11这段时间的真正重要进展**必须联网搜索补上**（今天是2026-11-19，现有骨架在2025年底之后几乎是空的）。

宁可多收一个tier 3，也不要漏掉一个读者之后会反复遇到的名字。

## 输出

只写一个文件：`data/skeleton/<你的track>.add.txt`（用Write工具新建）。**不要修改任何已有文件。**

每行一个新节点，和现有骨架同一格式（7个字段，竖线分隔）：

```
id | date | tier | kind | title | full | parents
```

- `id`：小写英文、数字、连字符，全局唯一。先 `grep -rn "^<id> " data/skeleton/` 确认没被占用。用通行的简称（`bert`、`resnet`、`gpt-3`），不要带年份，除非重名。
- `date`：`YYYY-MM`，确实不知道月份才写 `YYYY`。论文用首次公开时间（arXiv v1或会议）。模型/产品用发布时间。
- `tier`：
  - `1` 主干必学：缺了它后面的东西讲不通，整张图约80–120个
  - `2` 重要：该方向的人都知道，值得读原文或认真读讲解
  - `3` 延伸：知道它是什么、解决了什么即可
- `kind`：`paper` | `model`（没有论文的模型发布）| `system`（软件、框架、产品）| `hardware` | `dataset` | `event` | `concept`（书、博客、思想）
- `title`：图上显示的短名，中文为主，专有名词保留英文，尽量不超过14个字符宽
- `full`：论文或公告的**官方英文标题原文**，没有就留空
- `parents`：它直接建立在哪些更早的节点上，逗号分隔的id。可以引用任何分支的现有id，也可以引用你自己这个文件里新加的id。**尽量给2–4个**，这张图的价值在连接；跨分支的连接尤其要写。只写真实的思想/技术继承关系，不要为了连而连。parent的日期必须不晚于自己。

还可以写这些注释行（以 `#` 开头）：

```
# FIX <已有id>: <哪个字段应该改成什么，依据的URL>
# PARENT <已有id> <- <应该补上的parent id>, <一句理由>
# SUGGEST <track>: <名称>, <年份>, <为什么重要>
# DROP <已有id>: <为什么不该收>
```

## 准确性

- 日期和官方标题不能凭印象编。2020年之前的经典工作可以靠你的知识，但拿不准的要查。**2024年及之后的每一个节点都必须联网确认日期和标题**（arXiv abs页或官方公告）。
- 查不到、无法确认存在的，不要写。
- 搜索时只用主题关键词，不要带任何个人信息。

## 完成前自检

运行（只读校验，不会改文件）：

```
python3 scripts/build.py --check
```

修掉所有指向你的 `.add.txt` 的 ERROR（格式、重复id、找不到的parent）。如果脚本还不存在或报的是别人文件的问题，忽略并继续。

## 最后回复

简短即可：新增了多少个节点（按tier分），哪几个子方向补得最多，哪些你认为重要但没能核实所以没写。
