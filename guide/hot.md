## 任务二：补思路（ideas）

写 `data/ideas/<track>.json`（新建），一个列表，每项是一个**思路/话题/范式**：它不是某一篇论文，而是一类做法或一个被反复讨论的方向，读者会直接拿它当搜索词。

```json
[
  {
    "key": "on-policy-self-distillation",
    "name": "在策略自蒸馏",
    "en": "On-Policy Self-Distillation",
    "aka": ["OPSD", "自蒸馏推理", "self-distillation"],
    "blurb": "同一个模型既当老师又当学生：老师多看到参考答案，学生在自己生成的轨迹上向老师的输出分布靠拢。",
    "body": "两三段话：这个思路要解决什么、核心做法、它从哪来（链接 [[gkd]]、[[opsd]] 这样的节点）、现在争论什么。",
    "origin": "opsd",
    "nodes": ["gkd", "opsd", "dopsd"]
  }
]
```

- `key`：小写字母、数字、连字符。不能和 `data/concepts.txt` 里已有的概念key重复（先grep；已有基础概念覆盖的东西不要重复写，例如“自回归生成”“注意力”已经有了）。
- `name` 中文名；`en` 英文名；`aka`：缩写、别名、中英文的其他叫法，**尽量写全**，这是搜索能命中的关键。
- `blurb`：一句话定义，80字以内，没学过的人能看懂。
- `body`：150–400字，可用 `[[节点id]]` 和 `[[c:概念key]]` 链接。只写你有把握的内容。
- `nodes`：属于这个思路的节点id，**至少2个**，可以跨分支，可以包含你这次新加的节点；按重要性挑，一般3–15个。只对应一个节点的叫法不算思路，写成那个节点的别名（任务三）。
- `origin`：这个思路最早/最有代表性的出处节点（可省略，默认取最早的）。

数量：8–20个。覆盖本分支里人们实际会搜的话题词，新老都要（例如RL分支：多智能体RL、群体/swarm、离线RL、模仿学习、探索、世界模型里的规划……；已有主题线名字能直接搜到的可以不写，但叫法不同的要写）。

## 任务三：补别名

- 主题线：在 `data/threads/<track>.json` 每条主题线上加 `"aka": [...]`，写这条线的缩写、英文名、其他中文叫法（例如“非自回归与扩散”的 aka 是 `["DLM","扩散语言模型","Diffusion Language Model","dLLM"]`）。已有 `aka` 的可以补充。
