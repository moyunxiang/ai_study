# 机制图规范（figures）

## 是什么

演化树讲的是工作之间的关系；有些机制只靠文字讲不清楚。机制图是嵌在概念页和节点讲解页里的**小示意图**，每张讲清楚**一个真实的机制**：数据怎么流、哪一步算什么、为什么这么设计。读者是会编程、学过大一数学、没读过论文的人，可能在手机上看。

不要装饰图，不要“架构全家福”。一张图只回答一个问题，看图的人不读正文也能说出这个机制的要点。

## 文件

每张图两个文件，放在 `data/figures/`：

- `<key>.svg`：图本身。
- `<key>.json`：标题、图注和挂在哪些页面上。

范例：`data/figures/self-attention.svg` 和 `self-attention.json`。**先看范例再动手，样式和写法照它来。**

```json
{
  "key": "self-attention",
  "title": "自注意力：一个词怎样从整句里取信息",
  "caption": "图注：按图上的编号把机制讲一遍，80–200个汉字。可用 **粗体**、`公式`、[[节点id]]、[[c:概念key]]。示意数值要说明是示意。",
  "concepts": ["self-attention"],
  "nodes": ["transformer"],
  "source": "依据的出处：论文、章节或公式编号"
}
```

- `concepts`：这张图显示在哪些概念/思路页上，key来自 `data/concepts.txt` 或 `data/ideas/*.json`（先grep确认存在）。至少一个。
- `nodes`：显示在哪些节点讲解页上（登记表里的id，先grep确认存在），0–3个，只放这个机制的出处或最典型的工作。
- `source`：你画图时对照的原始出处。**先读原始出处再画**，不要凭印象。

## SVG的硬性要求

构建脚本会校验，不满足会报错：

1. 根元素 `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 420 H" role="img" aria-labelledby="<key>-title">`，**宽度固定420**，高度H在160到560之间。第一个子元素是 `<title id="<key>-title">`，内容与json里的 `title` 一致。
2. **不写任何颜色值**（不出现 `#abc`、`rgb(`、`hsl(`、颜色名）。颜色全部用下面的class，这样深色模式自动适配。
3. 不用 `<style>`、`<script>`、`<image>`、`<foreignObject>`、`<a>`，不写 `style="…"`、`font-size`、`font-family` 属性，不引用外部资源。
4. `<defs>` 里的id（箭头marker等）必须以 `<key>-` 开头，因为多张图会内联进同一个页面。
5. 文字只用 `<text>` / `<tspan>`，必须是真文字（不要转成路径）。

## 可用的class

文字（默认13px、正文色）：

| class | 用途 |
|---|---|
| （不写） | 正文标签，13px |
| `t-s` | 小号说明文字，11.5px，次要色 |
| `t-b` | 加粗 |
| `t-h` | 衬线小标题 |
| `t-m` | 等宽，用于数字、公式、变量名 |
| `t-a` / `t-bl` / `t-g` / `t-mu` | 文字颜色：强调红 / 蓝 / 绿 / 灰 |

形状：

| class | 用途 |
|---|---|
| `box` | 普通方框（纸色底、深色边） |
| `box2` | 次要方框（浅灰底、细边），用来表示容器或背景分组 |
| `hi` / `hi2` / `hi3` | 强调方框：红 / 蓝 / 绿（浅底、彩色边） |
| `ln` / `ln2` | 线：正文色 / 灰色。配 `dash` 变虚线 |
| `ln-a` / `ln-b` / `ln-c` | 彩色线：红 / 蓝 / 绿 |
| `f-a` / `f-b` / `f-c` / `f-ink` / `f-mu` / `f-p` / `f-n` | 只设置填充色：红 / 蓝 / 绿 / 正文色 / 灰 / 纸色 / 无。可配 `fill-opacity` 属性表示数值大小 |

箭头：在 `<defs>` 里定义 `<marker id="<key>-ah" viewBox="0 0 8 8" refX="7" refY="4" markerWidth="7" markerHeight="7" orient="auto"><path d="M0 0L8 4L0 8z" class="f-ink"/></marker>`，线上写 `marker-end="url(#<key>-ah)"`。彩色箭头另定义一个marker，path的class换成 `f-a` 等。

颜色有含义时要全图一致（例如红色始终表示“当前在算的那个东西”），而且**不能只靠颜色区分**：同时用位置、标签或线型。

## 版面

- 手机上图宽约360px，是420的0.86倍，所以**不要用比 `t-s` 更小的字**，一行说明文字不超过30个汉字。
- 优先纵向排布（从上到下的流程），不要画很宽的横向流程图。
- 文字不能压在线上或别的文字上，方框里的文字不能超出方框。汉字约13px宽，英文和数字约7px宽，排之前先算一下。
- 步骤用 ①②③ 编号，图注按同样的编号讲。
- 留白：四周至少留10px，元素之间至少8px。
- 一张图里的元素不要超过大约40个。画不下说明这张图想讲的东西太多，砍掉次要的。

## 准确性

- 画之前读：对应的概念词条 `data/concepts/<key>.json`、相关节点的讲解 `data/content/<track>/<id>.json`、以及原始论文里的定义（用WebFetch打开arXiv的HTML版）。
- 公式、符号、步骤顺序以原始论文为准。和站内讲解有出入时，以论文为准，并在报告里指出。
- 例子里的数值如果是编的，图注里必须写“示意数值”。
- 不确定某个细节就不画那个细节。**宁可少一张图，也不要一张有错的图。**

## 目检（必须做）

```
# 在仓库根目录下运行
python3 scripts/figshot.py <key> <你的scratchpad目录>/figs
```

它会输出四张PNG（手机宽度和桌面宽度，各浅色、深色）。用Read工具打开**手机浅色**和**桌面深色**两张，逐项检查：有没有文字重叠或出框、箭头方向对不对、深色下是否都看得清、编号和图注是否对应。有问题就改SVG再渲染，直到没有问题。

然后跑校验：

```
python3 scripts/build.py --check 2>&1 | grep -E "figures/"
```

## 不要做的事

只能新建 `data/figures/<key>.svg` 和 `<key>.json`。不要改别的文件，不要运行git命令。联网只用论文标题这类关键词。

## 报告

每张图一行：key、挂在哪些概念和节点上、依据的出处、目检时改过什么。没画成的说明原因。发现站内讲解与论文不一致的地方单独列出。
